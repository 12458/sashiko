# X86 PLATFORM DRIVERS — drivers/platform

This component contains x86 and OLPC platform-specific drivers across vendor and architecture subdirectories (including OLPC EC, AMD ISP4 and WBRF, Apple gmux, Dell SMBIOS/WMI/UART backlight, HP and Huawei WMI, Inspur platform profiles, and Intel IFS/TPMI/SoC power and GPIO drivers). These drivers bridge vendor firmware (ACPI, WMI, SMBIOS, EC, TPMI, MSRs) with standard Linux kernel subsystems such as backlight, hwmon, rfkill, input, power_supply, leds, regulator, platform_profile, and vga_switcheroo.

## Architecture & Data Flow

- In `drivers/platform/x86/intel/ifs/`, `union ifs_scan` and `union ifs_status` overlay 8-bit `gen0` chunk fields (with 16-bit `rsvd`/`rsvd1`) and 16-bit `gen2` chunk fields, so `doscan()` and `ifs_test_core()` must select `.gen2` when `ifsd->generation` is non-zero and `.gen0` when `ifsd->generation == 0` (after clearing `activate.gen0.rsvd = 0`). [F51]
- In `ifs_devices[]`, `IFS_TYPE_ARRAY_BIST` has `.test_msrs = NULL` (unlike `IFS_TYPE_SAF` and `IFS_TYPE_SBAF`) and uses `plat_ifs_array_groups` (which omits `current_batch`), so `ifs_get_test_msrs(dev)` returns `NULL` for array BIST devices and must never be dereferenced in code paths reachable by `IFS_TYPE_ARRAY_BIST`. [F52]
- During suspend in `olpc_ec_suspend` and `olpc_xo175_ec_suspend`, pre-suspend EC commands (`olpc_ec_mask_write` and `CMD_SUSPEND_HINT`) must execute before setting `ec->suspended` or `priv->suspended` to `true`, and resume must clear `suspended` before sending resume EC commands. [F61]
- In `ec_dbgfs_cmd_write`, if `sscanf` parses fewer than 2 items or `ec_dbgfs_resp_bytes > EC_MAX_CMD_REPLY`, `ec_dbgfs_resp_bytes` must be reset to `0` under `ec_dbgfs_lock` before returning `-EINVAL`. [F62]
- `build_tokens_sysfs` must only be called after `dmi_walk(find_tokens, NULL)` has completed all `krealloc` calls on `da_tokens` in `parse_da_table`, because `token_entries[i].token` caches interior pointers (`&da_tokens[i]`) into the `da_tokens` array. [F65]
- When `current_batch_store` updates `ifsd->cur_batch`, `ifs_load_firmware` must update `ifsd->loaded = (ret == 0)` on every exit path so that failed loads mark `ifsd->loaded` false and prevent `do_core_test`, `current_batch_show`, and `image_version_show` from using stale batch state. [F66]
- On Omen and Victus boards, `platform_profile_omen_set`, `platform_profile_victus_set`, and `platform_profile_victus_s_set` must update `active_platform_profile` under `active_platform_profile_lock`, and `platform_profile_omen_get` must return `active_platform_profile` rather than reading the EC directly. [F68]
- On Omen boards matched by `has_omen_thermal_profile_ec_timer`, `platform_profile_omen_set_ec` must clear the EC countdown timer (`omen_thermal_profile_ec_timer_set(0)`) and set the EC thermal profile flags (`omen_thermal_profile_ec_flags_set`) immediately after `omen_thermal_profile_set`. [F69]
- `victus_s_gpu_thermal_profile_set` must first read `current_gpu_slowdown_temp` via `victus_s_gpu_thermal_profile_get` and copy it into `gpu_power_modes.gpu_slowdown_temp` before issuing `HPWMI_SET_GPU_THERMAL_MODES_QUERY`. [F70]

## Synchronization

- In `do_core_test()` and `scan_chunks_sanity_check()`, once `cpus_read_lock()` is acquired, every error and switch exit path must jump to the `out:` label to call `cpus_read_unlock()` before returning. [F5]
- In `drivers/platform/olpc/olpc-ec.c`, `ec->cmd_q_lock` must be acquired with `spin_lock_irqsave()` when adding or removing `ec_cmd_desc` entries on `ec->cmd_q`, and must be released before `olpc_ec_worker()` acquires `ec->cmd_lock` to invoke `ec_driver->ec_cmd()`. [F23]
- In `olpc_xo175_ec_probe()`, `priv->cmd_state_lock`, `priv->cmd_done`, `priv->xfer`, and `olpc_ec_driver_register(&olpc_xo175_ec_driver, priv)` must all be initialized before registering the `olpc-ec` platform device and calling `olpc_xo175_ec_set_event_mask()`. [F25]
- In `drivers/platform/x86/apple-gmux.c`, all indexed and MMIO port accessors (`gmux_index_read8`, `gmux_index_write8`, `gmux_index_read32`, `gmux_index_write32`, `gmux_mmio_read8`, `gmux_mmio_write8`, `gmux_mmio_read32`, `gmux_mmio_write32`) must hold `gmux_data->index_lock` across the entire multi-register transaction and wait sequence. [F26]
- In `gmux_set_discrete_state()`, `reinit_completion(&gmux_data->powerchange_done)` must be called before writing `GMUX_PORT_DISCRETE_POWER`, and in `gmux_probe()`, `init_completion(&gmux_data->powerchange_done)` must precede `gmux_enable_interrupts(gmux_data)`. [F27]
- In `gmux_remove()`, `gmux_fini_debugfs()`, `vga_switcheroo_unregister_handler()`, `gmux_disable_interrupts()`, `acpi_disable_gpe()`, `acpi_remove_notify_handler()`, and `backlight_device_unregister()` must all complete before unmapping `gmux_data->iomem_base`, releasing I/O regions, clearing `apple_gmux_data`, and freeing `gmux_data`. [F28]
- In `drivers/platform/x86/intel/ifs/`, the semaphore `ifs_sem` must be held across all calls to `do_core_test()` and `ifs_load_firmware()`, and before `do_core_test()` or `scan_chunks_sanity_check()` acquires `cpus_read_lock()`. [F31]
- In `drivers/platform/x86/intel/tpmi_power_domains.c`, `tpmi_lock` protects `tpmi_cpu_hash` and `tpmi_power_domain_mask` in `tpmi_cpu_online()`, `tpmi_get_linux_cpu_number()`, and `tpmi_get_power_domain_mask()`, and `tpmi_exit()` must call `cpuhp_remove_state(tpmi_hp_state)` before freeing `tpmi_power_domain_mask` and `domain_die_map`. [F33]
- In `drivers/platform/x86/intel/turbo_max_3.c`, `itmt_legacy_cpu_online()` must not call `sched_set_itmt_support()` directly from the `CPUHP_AP_ONLINE_DYN` callback and must instead defer it via `schedule_work(&sched_itmt_work)`. [F35]

## Object Lifetimes

- `olpc_ec_cmd()` allocates `struct ec_cmd_desc desc` on the caller's stack and queues it onto `ec->cmd_q` for `olpc_ec_worker()`, so `olpc_ec_cmd()` must wait uninterruptibly via `wait_for_completion(&desc.finished)` until the worker dequeues `desc` and completes `desc.finished`. [F7]
- In `amd_isp4.c`, `isp_i2c_bus_notify()` must clear `isp4_platform->i2c_dev = NULL` under `isp4_platform->lock` when `BUS_NOTIFY_REMOVED_DEVICE` matches `isp4_platform->i2c_dev`, and `amd_isp_remove()` must unregister `i2c_nb` before calling `i2c_unregister_device(isp4_platform->i2c_dev)` and `software_node_unregister_node_group()`. [F12]
- In `dell_uart_bl_pdev_probe()`, `put_device(ctrl_dev)` must release the `get_serdev_controller()` reference after `serdev_device_alloc()`, and once `serdev_device_add(serdev)` succeeds, rollback and `dell_uart_bl_pdev_remove()` must call `serdev_device_driver_unregister()` then `serdev_device_remove(serdev)`. [F15]
- In `crystal_cove_charger_probe()`, `crystal_cove_charger_rm_irq_domain` is registered via `devm_add_action_or_reset()` immediately after `irq_domain_create_linear()` and before `devm_request_threaded_irq()`, ensuring devres tears down the threaded IRQ before removing `charger->irq_domain`. [F21]

## API Contracts

- `dell_smbios_find_token()` returns a borrowed pointer into the module-global `da_tokens` array without taking a reference, so callers must not free the returned `struct calling_interface_token *` or dereference it after `dell_smbios_exit()` frees `da_tokens`. [F3]
- `hp_wmi_perform_query()` returns `0` on success, a negative errno on transport/buffer failure, or a positive `bios_return->return_code` (such as `HPWMI_RET_UNKNOWN_CMDTYPE`) on BIOS command failure, so callers returning standard kernel status codes must check `if (ret)` and map positive values to a negative errno (e.g. `ret < 0 ? ret : -EINVAL`). [F44]
- `dell_smbios_call()` only returns the backend transport status (`0` or a negative errno) without checking the SMBIOS result in `buffer->output[0]`, so callers must either use `dell_send_request()` or pass `buffer->output[0]` to `dell_smbios_error()` to convert firmware errors (`-1`, `-2`) into negative errnos (`-EIO`, `-ENXIO`, `-EINVAL`). [F46]
- `huawei_wmi_cmd()` copies the WMI response buffer into `buf` (when non-NULL) even when the firmware status byte at `buf[0]` (`*obj->buffer.pointer`) is non-zero and causes `huawei_wmi_cmd()` to return `-ENODEV`, and callers must both check the return value and skip `buf[0]` when reading payload bytes. [F47]
- In `validate_ifs_metadata()`, `ifs_test_image_ptr` (`(u64)ifs_meta + sizeof(union meta_data)`) must be aligned to `IFS_CHUNK_ALIGNMENT` (256 bytes) and `ifs_meta->starting_chunk` must be a multiple of non-zero `ifs_meta->chunks_per_stride`, or validation fails with `-EINVAL`. [F53]
- Backend drivers registering with `dell_smbios_register_device` must pass their priority via the `priority` parameter (stored in `struct smbios_device.priority`) rather than overwriting `struct device.id` on the backend's `struct device`. [F64]
- Both `dell_smbios_call_filter()` and `dell_smbios_class_is_supported()` must reject `cmd_class > 30` (or `class > 30`) before evaluating `da_supported_commands & (1 << class)`. [F80]
- In `huawei_wmi_battery_set()`, both `start` and `end` charge thresholds must be validated against both lower (`< 0`) and upper (`> 100`) bounds before being stored into `u8` fields `arg.args[2]` and `arg.args[3]` of `union hwmi_arg`. [F81]
- Callers of `hp_wmi_perform_query()` must pass a `buffer` of at least `max(insize, outsize)` bytes with `outsize <= 4096`, while `hp_wmi_perform_query()` allocates `struct_size(args, data, max(insize, 128))` for `struct bios_args` and copies `min(outsize, (int)(obj->buffer.length - sizeof(*bios_return)))` bytes from after `struct bios_return`. [F84]
- In `dell_smbios_call_filter()`, token-specific filtering against `token_blacklist` and `token_whitelist` must execute before `call_whitelist` is checked. [F100]

## Error Handling

- Because `build_tokens_sysfs()` frees all of its own partial allocations (`location_attr.attr.name`, `value_attr.attr.name`, `token_attrs`, and `token_entries`) before returning an error, `dell_smbios_init()`'s `fail_sysfs` error path must not call `free_group()` and must only unwind the WMI/SMM backends, platform device/driver, and `da_tokens`. [F2]
- In `ifs_load_firmware()`, once `request_firmware_direct(&fw, ...)` succeeds, every subsequent validation or chunk-authentication failure path must jump to `release:` so `release_firmware(fw)` is called before updating `ifsd->loaded`. [F4]
- When creating multiple sysfs attributes sequentially with `device_create_file()` in `huawei_wmi_battery_add()` or `irst_add()`, failure of the second `device_create_file()` call must roll back the first attribute with `device_remove_file()` before returning the error. [F8]
- In `hp_wmi_perform_query()`, `args` is allocated with `kmalloc()` and `output` is initialized with `ACPI_ALLOCATE_BUFFER` for `wmi_evaluate_method()`, so every exit path after `kmalloc()` must jump to `out_free:` to call `kfree(obj)` and `kfree(args)`. [F17]
- In `ifs_test_core()` and `ifs_sbaf_test_core()`, the local `status` union (`union ifs_status` or `union ifs_sbaf_status`) must be zero-initialized (`= {}`) before the retry loop because an early timeout sets only `status.error_code = IFS_SW_TIMEOUT` and breaks before `stop_core_cpuslocked()` populates `status`. [F40]
- In `gmux_selected_port_data_write()`, `copy_from_user()` returns the positive count of uncopied bytes rather than a negative errno, so any non-zero return must be translated to `-EFAULT` instead of propagated. [F41]
- In `huawei-wmi.c` (`huawei_wmi_input_setup()`, `huawei_wmi_call()`, `huawei_wmi_micmute_led_set()`), calls returning `acpi_status` (`wmi_install_notify_handler()`, `wmi_evaluate_method()`, `acpi_evaluate_object()`) must be checked with `ACPI_FAILURE()` and mapped to a negative errno, never returned directly or combined with `||`. [F42]
- In `ec_dbgfs_cmd_write()`, the stack buffer `cmdbuf` populated by `simple_write_to_buffer()` must be zero-initialized (`char cmdbuf[64] = ""`) because `simple_write_to_buffer()` does not NUL-terminate the copied user data before `sscanf()` parses `cmdbuf`. [F43]

## External Contracts

- In `huawei_wmi_cmd()`, the WMI response from `HWMI_METHOD_GUID` must be either an `ACPI_TYPE_BUFFER` of exact length `0x104` (advancing `obj->buffer.pointer` by 4 to a `0x100`-byte payload) or an `ACPI_TYPE_PACKAGE` with `count == 2` whose `elements[1]` is an `ACPI_TYPE_BUFFER`, and copying into `buf` must be bounded by `min(buflen, len)`. [F82]
- In `hp_wmi_notify()`, the WMI event `ACPI_TYPE_BUFFER` must have `obj->buffer.length` equal to either `8` (reading `event_id` at `location[0]` and `event_data` at `location[1]`) or `16` (reading `event_id` at `location[0]` and `event_data` at `location[2]`), and any other buffer length must be rejected. [F86]
- `amd_wbrf_retrieve_freq_band()` must check `4 <= obj->buffer.length <= sizeof(struct amd_wbrf_ranges_out)` before copying the DSM buffer into `__packed` `struct amd_wbrf_ranges_out` (`u32 num_of_ranges`) and then copying `num_of_ranges` and `band_list` separately into `struct wbrf_ranges_in_out` (`u64 num_of_ranges`). [F88]
- dell_led_blink() must convert millisecond delays (*delay_on and *delay_off) into 125ms intervals using DIV_ROUND_UP(..., 125) and clamp the result to [1, 255] before writing back the rounded millisecond values and calling led_blink(). [F111]
- In dell_smbios_call_filter, commands with cmd_class > 30, unsupported classes in da_supported_commands, entries in call_blacklist, and tokens in token_blacklist are rejected with -EINVAL before any capability check, while non-whitelisted calls require capable(CAP_SYS_RAWIO) and return -EACCES otherwise. [F166]
- In dell-smbios-base.c, although the token sysfs attributes under the "tokens" group are created with mode 0444 in build_tokens_sysfs, their show callbacks (location_show and value_show) must check capable(CAP_SYS_ADMIN) and return -EPERM if the caller lacks it. [F167]
- In gmux_selected_port_data_write (drivers/platform/x86/apple-gmux.c), writes to the selected_port_data debugfs file must reject non-zero file offsets (*ppos != 0) and any write size other than 1 byte (gmux_write8) or 4 bytes (gmux_write32) with -EINVAL. [F177]

## Known Pitfalls

- Because `build_tokens_sysfs()` skips `da_tokens[i]` entries with `tokenID == 0` while compacting `token_attrs[j]`, `location_show()` and `value_show()` must obtain their `calling_interface_token` via `container_of(attr, struct token_sysfs_data, ...)->token` rather than indexing `da_tokens` by the attribute's position in `token_attrs`. [F78]
- In `drivers/platform/x86/hp/hp-wmi.c`, `IS_HWBLOCKED(x)` must test `((x & HPWMI_POWER_FW_OR_HW) != HPWMI_POWER_FW_OR_HW)` so that a radio is reported hardware-blocked when either `HPWMI_POWER_BIOS` or `HPWMI_POWER_HARD` is cleared. [F99]
- In `olpc_xo175_ec_complete()`, the `CHAN_NONE` and `CHAN_SWITCH` cases of `switch (channel)` must return early after submitting their own SPI transfer rather than breaking to the trailing `olpc_xo175_ec_read_packet(priv)` call. [F102]
- In hp_wmi_get_fan_speed(), the high and low bytes in char fan_data[4] must be copied to unsigned u8 variables (fsh, fsl) before computing (fsh << 8) | fsl. [F108]
- In get_oc_core_priority(), the mailbox command and busy bit for 64-bit MSR_OC_MAILBOX must be shifted using 64-bit unsigned types (u64 cmd << MSR_OC_MAILBOX_CMD_OFFSET and BIT_ULL(MSR_OC_MAILBOX_BUSY_BIT)). [F113]
- In `drivers/platform/x86/hp/hp-wmi.c`, the macro `zero_if_sup(tmp)` expands to `(zero_insize_support?0:sizeof(tmp))`, so its argument `tmp` must be a value or non-decayed array variable rather than a pointer or decayed array parameter. [F117]
- In `drivers/platform/x86/intel/ifs/load.c`, `ifs_header_ptr`, `meta_header`, and `ifs_meta` are typed pointers, so byte offsets like `meta_header->blk_size` or `sizeof(union meta_data)` require casting the pointer to `void *` or `u64` before addition, whereas `ifs_header_ptr + 1` steps by `sizeof(*ifs_header_ptr)`. [F119]
- When formatting length-bounded byte buffers such as `ACPI_TYPE_STRING` (`obj->string.length`, `obj->string.pointer`) in `huawei_wmi_debugfs_call_dump()` or UART payload slices (`resp[RESP_LEN] - 3`, `resp + RESP_DATA`) in `dell_uart_bl_serdev_probe()`, format strings must use precision `"%.*s"` rather than `"%s"` or width `"%*s"`. [F123]
