# RUST — (top level) (part 1)

Core Rust-for-Linux kernel crate (`rust/kernel/*`), C FFI bindings (`rust/bindings/*`), and C helper wrappers (`rust/helpers/*.c`) providing foundational types for memory safety, reference counting (`Arc`, `ARef`), intrusive collections (`List`, `RBTree`), synchronization (`CondVar`, `Completion`, `Revocable`, barriers), workqueues, user-space memory access (`UserSlice`), I/O vectors (`IovIterSource`/`IovIterDest`), strings, tasks, error handling, and USB driver abstractions.

## Architecture & Data Flow
- In `ListLinks<ID>`, `prev` and `next` are null iff the item is not in a `List`, and `ListItem::view_links` must return two null pointers outside `prepare_to_insert`..`post_remove`. In `List::remove_internal_inner`, after relinking `(*next).prev` and `(*prev).next`, both `(*item).prev` and `(*item).next` must be set to `ptr::null_mut()` before setting `self.first = (*prev).next` and calling `T::post_remove` and `ListArc::from_raw`. [F7, F41]
- `ListLinksSelfPtr<T, ID>` must remain `#[repr(C)]` with `inner: ListLinks<ID>` as its first field, and `ListItem::prepare_to_insert` for `ListLinksSelfPtr` must write `me` into `self_ptr` before returning `links_field` so `view_value` and `post_remove` can recover the (potentially unsized) `*const Self`. [F100]
- `ListArc` lifecycle transitions must keep `T`'s `ListArcSafe<ID>` tracker synchronized: `From<Pin<UniqueArc<T>>>` and `pair_from_pin_unique` must call `on_create_list_arc_from_unique`, `into_arc` and `Drop::drop` must call `on_drop_list_arc`, and `into_raw` must use `transmute_to_arc` so tracking stays active while raw. [F48]
- `List::push_all_back` must reset `other.first` to `ptr::null_mut()` after splicing `other`'s circular node chain into `self`, so dropping `other` does not pop and double-remove elements now owned by `self`. [F46]
- In `list::Cursor::prev_ptr`, the `next == first` check must execute before the `next.is_null()` check that substitutes `next = first` before dereferencing `(*next).prev`. When advancing forward in `list::Iter::next` or `list::Cursor::move_next`, the pointer must be set to `ptr::null_mut()` whenever `(*current).next` equals `first` (`stop`). [F74, F75]
- Implementations of `HasWork<T, ID>` and `HasDelayedWork<T, ID>` must ensure `raw_get_work` and `work_container_of` are exact inverses for the field matching `ID`, and for `HasDelayedWork<T, ID>` the returned `Work<T, ID>` pointer must point to the `work` field of a `bindings::delayed_work`. [F99]
- `UserSliceReader::read_raw` and `IovIterSource::copy_from_iter_raw` must never write uninitialized bytes into `out: &mut [MaybeUninit<u8>]` even on failure or partial copy, because `UserSliceReader::read_slice` and `IovIterSource::copy_from_iter` cast `&mut [u8]` directly to `&mut [MaybeUninit<u8>]`. [F33]
- `UserSliceReader` (`skip`, `read_raw`, `read`) and `UserSliceWriter` (`write_slice`, `write`) must check `len <= self.length` and verify that the underlying `copy_from_user`/`copy_to_user` call returned `0` before advancing `self.ptr` and decrementing `self.length`. [F51]
- Types implementing `unsafe trait AsBytes` must not contain any uninitialized padding bytes or interior mutability, and should not contain kernel pointers, whereas `unsafe trait FromBytes` permits padding bytes only if every possible bit pattern is valid for the type and it has no interior mutability. [F60]
- `RawFormatter::write_str` must advance `self.pos` using `saturating_add(s.len())` while clamping the copied length to `min(pos_new, self.end).saturating_sub(self.pos)` so writes never overrun `self.end` and `self.pos` still reflects the total formatted byte length for `rust_fmt_argument` (`%pA`) and `CString::try_from_fmt`. [F65]
- `Error` wraps a `NonZeroI32` restricted to `>= -(bindings::MAX_ERRNO as i32) && < 0`, so `Error::from_errno` and `to_result` treat any negative value `< -MAX_ERRNO` (and `from_errno` treats `>= 0`) as a bug by logging a warning and returning `EINVAL`, and `from_result` safely casts `e.to_errno() as i16` without truncation. Broken by: calling `Error::from_errno_unchecked` on unvalidated C returns or passing positive errno constants to `Error::from_errno`. [F69]
- In `rust/kernel/ptr.rs`, `Alignable::align_down` and `Alignable::align_up` must convert `alignment` (`Alignment`) into `Self` via `try_from` rather than truncating `alignment.mask()` with `as Self`, returning `0` in `align_down` and `None` (for non-zero `self`) in `align_up` when the alignment exceeds `Self::MAX`. [F87]

## Synchronization
- `CondVar::wait_internal` must enqueue the stack `wait_queue_entry` via `prepare_to_wait_exclusive` before releasing `guard` via `guard.do_unlocked`, and must call `finish_wait` after `do_unlocked` reacquires the lock and before `wait` goes out of scope. [F11]
- When calling `CondVar::wait_interruptible_freezable`, no lock other than the lock represented by the passed `guard` argument may be held, because freezing a task that holds another lock can deadlock against a task needing that lock to freeze. [F129]
- Callers holding a `RevocableGuard` returned by `Revocable::try_access` or a reference from `Revocable::try_access_with_guard` must not sleep, because `RevocableGuard` holds an RCU read-side lock (`rcu::Guard`) while `Revocable::revoke` waits on `bindings::synchronize_rcu()`. [F120]
- `IovIterSource` and `IovIterDest` must remain `!Send` because the underlying `struct iov_iter` may reference memory mapped in a thread-local manner via `kmap_local_page()`, requiring reads and writes to occur in the same task context. [F133]
- Calling `bindings::task_active_pid_ns` without RCU protection or refcount elevation (as in `CurrentTask::active_pid_ns`) is only sound when the target task is `current`; obtaining the `PidNamespace` of any arbitrary `Task` must go through `Task::get_pid_ns` (`rust_helper_task_get_pid_ns`), which holds `guard(rcu)()` and calls `get_pid_ns`. [F146]

## Object Lifetimes
- `ForeignOwnable` implementations must guarantee `into_foreign` returns a non-null pointer aligned to at least `Self::FOREIGN_ALIGN`, and `borrow_mut` must never allow changing the address of the foreign-owned allocation (e.g. yielding `&mut Self` on a pointer wrapper). `ForeignOwnable::from_foreign` must be called at most once per `into_foreign` call and only after all borrows from `borrow` or `borrow_mut` on that pointer have ended. [F2, F107]
- `unsafe impl AlwaysRefCounted` may only be implemented for types where every instance is reference-counted and `inc_ref` keeps the allocation alive at least until a matching `dec_ref`, because `From<&T> for ARef<T>` upgrades any `&T`. `ARef::from_raw` takes ownership of an existing refcount increment without calling `inc_ref`, whereas `ARef::from(&T)` and `ARef::clone` call `inc_ref` before `ARef::from_raw`. [F4, F109]
- In `RBTree::drop`, the next postorder node must be fetched via `bindings::rb_next_postorder(next)` before the current node is freed with `drop(KBox::from_raw(this))`, and in `rbtree::Cursor::remove_current`, neighbor pointers must be read via `get_neighbor_raw` before `bindings::rb_erase` unlinks the node. [F9]
- `print_macro!` must bind `fmt!($($arg)+)` as the scrutinee of a `match` expression around `call_printk` rather than a `let` binding, and `call_printk`'s `module_name` (`__LOG_PREFIX`) must be NUL-terminated for `_printk`'s `%s` specifier. [F92]
- When deriving a related or parent device reference from a child wrapper (such as obtaining `&usb::Device` from `&usb::Interface<Ctx>` via `AsRef`), the child's `device::DeviceContext` parameter `Ctx` must not be propagated to the returned target type unless the target device is guaranteed to share that bound and lock state. [F110]
- `CurrentTask` references obtained via `current!()` or `Task::current()` must never escape the active task context—including across `kthread_use_mm()`/`kthread_unuse_mm()` boundaries, `begin_new_exec()`, `release_task()`, or return to userspace—so any closure entering a new mm/task sub-context must require `Send` to be blocked by `NotThreadSafe`. [F113]

## API Contracts
- `DelayedWork::new` must initialize both `(*slot).work` via `bindings::init_work_with_key` and `(*slot).timer` via `bindings::timer_init_key` with `Some(bindings::delayed_work_timer_fn)` and `bindings::TIMER_IRQSAFE` before the `DelayedWork` can be enqueued. [F23]
- Work items queued to `workqueue::system_bh()` or `workqueue::system_bh_highpri()` execute their `WorkItem::run` callback in softirq (bottom-half) context rather than process context, so they must not sleep or perform blocking allocations. [F132]
- `ListArc::pair_from_unique` and `ListArc::pair_from_pin_unique` require the two const generic list IDs `ID` and `ID2` to be distinct (`build_assert!(ID != ID2)`). [F40]
- Callers reading and validating userspace memory through `UserSlice` must construct a single `UserSlice` per userspace memory region and validate the kernel copy rather than calling `UserSlice::new` or `UserSliceReader::clone_reader` to read the same userspace address twice (preventing TOCTOU). [F56]
- `IovIterSource::from_raw` and `IovIterDest::from_raw` require that the C `struct iov_iter` has `data_source` equal to `ITER_SOURCE` or `ITER_DEST` respectively (panicking via `assert_eq!` otherwise) and that the underlying buffers remain valid for reading or writing for `'data` and exclusively accessed via the returned reference for `'iov`. [F112]
- Before advancing the length of a `Vec<u8, A>` via `unsafe { buf.inc_len(len) }` after an FFI read into `spare_capacity_mut()`, callers must bound `len` to the actual number of bytes initialized by the C helper (such as the return value of `_copy_from_iter` in `IovIterSource::copy_from_iter_vec` or `Ok(())` from `UserSliceReader::read_raw`). [F116]
- Closures passed to `Opaque::ffi_init` and `Opaque::try_ffi_init` receive a `*mut T` pointing to uninitialized memory and must not read from that pointer before initializing it, and callers dereferencing `Opaque::get` must ensure the inner `T` was initialized by C or Rust. [F105]
- In `rust/kernel/ioctl.rs`, `_IOC` (and `_IO`, `_IOR`, `_IOW`, `_IOWR`) requires `dir <= uapi::_IOC_DIRMASK`, `ty <= uapi::_IOC_TYPEMASK`, `nr <= uapi::_IOC_NRMASK`, and `size_of::<T>() <= (uapi::_IOC_SIZEMASK as usize)` at compile time before casting `size as u32` and shifting each field into the `u32` ioctl number. [F86]
- Kernel logging macros (`pr_emerg!`, `pr_alert!`, `pr_crit!`, `pr_err!`, `pr_warn!`, `pr_notice!`, `pr_info!`, `pr_debug!`) do not append a newline automatically; callers must terminate format strings with `\n` unless continuing the line with `pr_cont!`. [F91]
- In `rust/kernel/lib.rs`, subsystem module declarations must be gated with `#[cfg(...)]` only on the core Kconfig symbol required by the module (such as `CONFIG_PCI`, `CONFIG_BLOCK`, or `CONFIG_NET`) rather than optional sub-feature symbols like `CONFIG_PCI_MSI`. [F138]

## Error Handling
- In `<Arc<T> as RawWorkItem<ID>>::__enqueue`, `Arc::into_raw(self)` transfers one refcount to the workqueue before calling `queue_work_on(work_ptr)`, and if `queue_work_on` returns `false`, ownership must be immediately reclaimed via `Err(unsafe { Arc::from_raw(ptr) })`. [F12]
- `to_result` treats any non-negative `c_int` (`err >= 0`) as `Ok(())` and only converts negative values via `Error::from_errno`, so it must not be used for C functions that signal failure with positive return values or return a positive value needed by the caller. [F28]
- `from_err_ptr` only checks `bindings::IS_ERR` and returns `Ok(ptr)` when `ptr` is null, so callers of C functions that can return `NULL` on failure must check for null separately after calling `from_err_ptr`. [F29]
- In `UserSliceReader` and `UserSliceWriter`, `copy_from_user`, `_copy_from_user`, `copy_to_user`, and `_copy_to_user` return the number of uncopied bytes (`res != 0` on failure, mapped to `Err(EFAULT)` without advancing `ptr` or `length`), whereas `strncpy_from_user` returns a negative errno on failure or the copied byte count on success. [F34]
- `UserSliceReader::strcpy_into_buf` must reject an empty `buf` with `Err(EINVAL)`, cap the `raw_strncpy_from_user` slice to `self.length`, return `Err(EFAULT)` if `len == dst.len() < buf.len()` (hitting `self.length` before a NUL or filling `buf`), and overwrite the last byte of `buf` with `0` when `len == buf.len()`. [F59]
- `IovIterDest::simple_read_from_buffer` must reject negative file offsets (`*ppos < 0`) with `Err(EINVAL)`, return `Ok(0)` without modifying `*ppos` when `*ppos` exceeds `usize::MAX` or `contents.len()`, and otherwise advance `*ppos` by the number of bytes copied from `&contents[pos..]`. [F63]
- `CondVar::wait_interruptible_timeout` checks `crate::current!().signal_pending()` before checking whether the remaining jiffies from `schedule_timeout` is `0`, returning `CondVarTimeoutResult::Signal { jiffies }` whenever a signal is pending even if the timeout also expired. [F42]

## External Contracts
- C macro constants that use expressions or bit macros such as `BIT()` (e.g., `VM_MERGEABLE`, `BLK_FEAT_ROTATIONAL`, `FOP_UNSIGNED_OFFSET`, `GFP_*`) must be bound via `const <type> RUST_CONST_HELPER_<NAME> = <NAME>;` in `rust/bindings/bindings_helper.h` with their exact C typedef. [F82]
- Rust functions invoked directly from C (such as `rust_fmt_argument` called by `vsprintf` for `%pA`, `WorkItemPointer::run`, and `usb::Adapter` callbacks) must be declared `extern "C"`, and FFI signatures and `#[export]` functions must use `crate::ffi::c_char` (`u8` under `-funsigned-char`) and `crate::ffi::c_long`/`c_ulong` (`isize`/`usize`) rather than `core::ffi` integer types. [F90, F134]
- In `rust/helpers/io.c`, the 64-bit MMIO helper functions (`rust_helper_readq`, `rust_helper_writeq`, `rust_helper_readq_relaxed`, and `rust_helper_writeq_relaxed`) must be guarded by `#ifdef CONFIG_64BIT`. [F122]
- Kernel inline assembly templates generated from C headers (such as `generated_arch_static_branch_asm.rs` in `jump_label.rs` and `generated_arch_warn_asm.rs` in `bug.rs`) must be invoked through `$crate::asm!` rather than `core::arch::asm!` directly so `options(att_syntax)` is applied on `x86` and `x86_64`. [F135]
- Panicking compiler intrinsics in `rust/compiler_builtins.rs` (for `f32`, `f64`, `i128`, `u128`, and 32-bit ARM `u64` division) are exported with a `__rust` prefix (`#[export_name = concat!("__rust", ...)]`), and any new intrinsic added there must also be listed in `redirect-intrinsics` in `rust/Makefile`. [F137]

## Known Pitfalls
- In `impl_list_arc_safe!`, the `tracked_by` arm must invoke `::pin_init::assert_pinned!($t, $field, $fty, inline)` rather than `$crate::assert_pinned!` before projecting `self` with `Pin::map_unchecked_mut`, because `assert_pinned!` is exported by the `pin_init` crate. [F49]
- In `list::CursorPeek::remove`, `self.cursor.move_next()` must be called before `self.cursor.list.remove_internal(self.ptr)` when `ISNEXT` is true, and callers iterating with `while let Some(next) = cursor.peek_next()` must not call `cursor.move_next()` in the branch that calls `next.remove()`. [F76]
- In `static_branch_unlikely!`, the `#[cfg(not(CONFIG_JUMP_LABEL))]` fallback branch must pass `_key.cast_mut()` to `$crate::bindings::static_key_count` so its pointer mutability matches `rust_helper_static_key_count(struct static_key *key)` when `CONFIG_JUMP_LABEL` is disabled. [F54]
- `rust/helpers/atomic.c` is auto-generated by `scripts/atomic/gen-rust-atomic-helpers.sh` and must not be modified directly without updating the generator script in lockstep. [F55]
- In `rust/bindings/bindings_helper.h`, headers that define C `enum` types (such as `<linux/hrtimer_types.h>`) must be included before headers that only forward-declare those enums so `bindgen` does not generate `i32` instead of the actual unsigned C type (`c_uint`). [F81]
- In `rust/kernel/uaccess.rs`, advancing a userspace pointer in `UserSliceReader` and `UserSliceWriter` must use `UserPtr::wrapping_byte_add` (after checking `self.length`) rather than non-wrapping pointer offset arithmetic so that untrusted userspace addresses near `usize::MAX` do not panic under `CONFIG_RUST_OVERFLOW_CHECKS`. [F88]
