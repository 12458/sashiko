# DRM DRIVERS AND MISC GPU PATCHES — drivers/gpu/drm (part 5)

This component provides core DRM infrastructure for framebuffer management, GEM buffer objects and backing-store helpers (shmem, DMA/CMA, TTM, VRAM, and atomic shadow planes), GPU Shared Virtual Memory (GPUSVM) via HMM/MMU interval notifiers, DRM device-managed resources (`drmm_*`), DRM master resource leasing, core/32-bit compat IOCTL dispatch, and MIPI DBI/DSI display bus and peripheral helpers.

## Architecture & Data Flow

- In `drm_gem_vram_helper.c`, `ttm_device_funcs` callbacks (`bo_driver_evict_flags`, `bo_driver_delete_mem_notify`) must verify `drm_is_gem_vram(bo)` (`bo->destroy == ttm_buffer_object_destroy`) before downcasting `bo` with `drm_gem_vram_of_bo(bo)`. [F49]
- In drm_gem_shmem_mmap(), vma->vm_pgoff must retain the fake VMA offset from obj->vma_node so drm_vma_node_unmap() in drm_gem_shmem_purge_locked() can find and unmap active VMAs, while drm_gem_shmem_fault() must compute page_offset from (vmf->address - vma->vm_start) >> PAGE_SHIFT rather than vmf->pgoff. [F65]
- Every mutation of a struct drm_gem_lru list in drm_gem_lru_remove_locked(), drm_gem_lru_move_tail_locked(), and drm_gem_lru_scan() must update obj->lru, obj->lru_node, and lru->count (by obj->size >> PAGE_SHIFT) in lockstep under lru->lock, and a shrink() callback returning true must have removed obj from still_in_lru. [F67]
- In drm_gpusvm.c, drm_gpusvm_notifier_insert() and drm_gpusvm_notifier_remove() (for gpusvm->root and gpusvm->notifier_list) and drm_gpusvm_range_insert() and __drm_gpusvm_range_remove() (for notifier->root and notifier->range_list) must keep the interval tree and doubly-linked list synchronized in ascending address order via rb_prev(). [F70]
- Because _drm_lease_revoke() revokes a lease by emptying master->leases without removing the lessee from lessor->lessees, drm_mode_list_lessees_ioctl() must check !idr_is_empty(&lessee->leases) under dev->mode_config.idr_mutex so revoked lessees are excluded from the returned list. [F80]
- In fill_object_idr(), when lessor_priv->universal_planes is false, leasing a DRM_MODE_OBJECT_CRTC must also insert crtc->primary->base.id and (if non-NULL) crtc->cursor->base.id into the leases IDR, whereas when universal_planes is true, validate_lease() requires at least one DRM_MODE_OBJECT_PLANE in the request. [F81]
- In drm_ioctl() and drm_ioctl_flags(), the untrusted ioctl number nr (or index = nr - DRM_COMMAND_BASE for driver ioctls) must be bounds-checked against DRM_CORE_IOCTL_COUNT (or dev->driver->num_ioctls) and clamped with array_index_nospec() before indexing drm_ioctls[] or dev->driver->ioctls[]. [F89]
- drm_set_client_name() must reject name->name_len > DRM_CLIENT_NAME_MAX_LEN, copy the user buffer with memdup_user_nul(), and reject strings where strlen(new_name) != len or drm_validate_value_string() finds any byte failing isascii() or isgraph(). [F92]

## Synchronization

- When drm_gem_lock_reservations() fails after calling ww_acquire_init(acquire_ctx, &reservation_ww_class), it must unlock all already-locked reservations (objs[0..i-1] and objs[contended] if contended >= i) and tear down acquire_ctx with ww_acquire_fini(acquire_ctx) rather than ww_acquire_done(acquire_ctx). [F12]
- Drivers must fully initialize a struct drm_gem_object before calling drm_gem_handle_create() (or drm_gem_handle_create_tail()) as the final step of buffer creation, because creating the handle publishes the object to userspace. [F23]
- drm_gem_handle_create_tail() must reserve the handle slot in file_priv->object_idr with NULL under file_priv->table_lock and only replace it with obj via idr_replace() after drm_vma_node_allow() and obj->funcs->open() succeed, while drm_gem_handle_delete() must replace the slot with NULL before running drm_gem_object_release_handle(). [F24]
- All attributes of a struct drm_framebuffer (such as format, pitches, offsets, modifier, width, height, and obj[]) must be fully initialized before calling drm_framebuffer_init() and treated as invariant afterward, because drm_framebuffer_init() publishes the framebuffer for lockless concurrent reads. [F25]
- dev->object_name_lock protects obj->handle_count, obj->name, and dev->object_name_idr: all handle_count transitions and flink name insertions/removals must hold dev->object_name_lock, and drm_gem_flink_ioctl() must verify obj->handle_count != 0 under dev->object_name_lock before allocating obj->name. [F28]
- For a non-imported struct drm_gem_shmem_object, the reservation lock shmem->base.resv protects shmem->pages, shmem->sgt, shmem->vaddr, shmem->madv, and their refcounts; functions such as drm_gem_shmem_get_pages_sgt(), drm_gem_shmem_fault(), and drm_gem_shmem_purge_locked() must hold shmem->base.resv across check-and-update sequences. [F29]
- drm_gem_vmap() and drm_gem_vunmap() hold obj->resv across drm_gem_vmap_locked() and drm_gem_vunmap_locked(), so drm_gem_object_funcs.vmap and .vunmap callbacks (including drm_gem_vram_vmap(), drm_gem_vram_vunmap(), drm_gem_shmem_vmap_locked(), and drm_gem_ttm_vmap()) are entered with obj->resv held and must not re-acquire it. [F30]
- gpusvm->notifier_lock protects notifier->root, notifier->range_list, svm_pages->dma_addr, svm_pages->dpagemap, and svm_pages->flags: MMU invalidation paths (drm_gpusvm_notifier_invalidate(), drm_gpusvm_range_set_unmapped(), and drm_gpusvm_unmap_pages() with ctx->in_notifier) must hold it in write mode, while non-notifier paths hold it in read mode. [F31]

## Object Lifetimes

- In drm_framebuffer_init(), each non-NULL fb->obj[i] with an existing GEM handle must have a handle reference acquired via drm_gem_object_handle_get_if_exists_unlocked(), recorded in fb->internal_flags with DRM_FRAMEBUFFER_HAS_HANDLE_REF(i), and released via drm_gem_object_handle_put_unlocked() on init failure and in drm_framebuffer_cleanup(). [F1]
- In drm_mode_getfb2_ioctl(), if creating a GEM handle for any plane fails, the error path must delete all handles already created during that ioctl call via drm_gem_handle_delete() and zero out duplicate entries in r->handles[] so the same handle is not deleted twice. [F3]
- drm_gem_handle_create_tail() requires the caller to hold obj->dev->object_name_lock on entry, always unlocks object_name_lock before returning, and on error rolls back in reverse order: drm_vma_node_revoke(), idr_remove() under file_priv->table_lock, and drm_gem_object_handle_put_unlocked(). [F4]
- In drm_gem_object_handle_put_unlocked(), when --obj->handle_count reaches zero under dev->object_name_lock, drm_gem_object_handle_free() and drm_gem_object_exported_dma_buf_free() must run while object_name_lock is still held and before drm_gem_object_put(obj) drops the object reference. [F5]
- drm_gem_shmem_vm_open() must acquire shmem->base.resv uninterruptibly via dma_resv_lock() and unconditionally increment shmem->pages_use_count via refcount_inc_not_zero() alongside drm_gem_vm_open(vma), so that every subsequent drm_gem_shmem_vm_close() has a matching page and object reference to drop. [F8]
- For non-imported shmem objects, drm_gem_shmem_vunmap_locked() must only call vunmap(shmem->vaddr), clear shmem->vaddr = NULL, and call drm_gem_shmem_unpin_locked(shmem) inside the refcount_dec_and_test(&shmem->vmap_use_count) block when the final vmap reference is dropped. [F9]
- When refcount_dec_and_test(&shmem->pages_use_count) reaches zero in drm_gem_shmem_put_pages_locked(), it must restore write-back page caching via set_pages_array_wb() (on x86 when shmem->map_wc is true) before calling drm_gem_put_pages() and clearing shmem->pages = NULL. [F11]
- drm_gem_fb_init_with_funcs() acquires a drm_gem_object reference via drm_gem_object_lookup() for each plane and transfers ownership of those references to fb->obj[] on success (to be dropped by drm_gem_fb_destroy()), while putting all already-acquired objs[0..i-1] on failure. [F14]

## API Contracts

- Low-level MIPI DSI transfer helpers (`mipi_dsi_generic_write`, `mipi_dsi_dcs_write_buffer`, `mipi_dsi_dcs_read`) return `ssize_t` byte counts or negative errno, whereas higher-level command helpers (`mipi_dsi_compression_mode`, `mipi_dsi_picture_parameter_set`, `mipi_dsi_dcs_write_buffer_chatty`) return `int` (`0` or negative errno). [F43]
- In `drm_gpusvm.c`, `drm_gpusvm_range_chunk_size()` signals failure by returning `LONG_MAX` (checked before calling `drm_gpusvm_range_alloc()`), and `drm_gpusvm_find_vma_start()` signals failure (no intersecting VMA or dead `mm`) by returning `ULONG_MAX`. [F46]
- `drm_gem_object_lookup()` and `drm_framebuffer_lookup()` return `NULL` when the handle or ID is not found, whereas GEM/FB creation and page/sg-table acquisition helpers (`drm_gem_get_pages`, `drm_gem_shmem_get_pages_sgt`, `drm_gem_dma_get_sg_table`, `drm_gem_fb_create_with_funcs`) return `ERR_PTR`-encoded negative errnos. [F47]
- `mipi_dbi_poweron_conditional_reset()` returns `0` when the controller was reset, `1` when the display was already on (`mipi_dbi_display_is_on()` returned true), or a negative errno on regulator or command failure. [F48]
- In `drm_gem_shmem_helper.c`, imported DMA-BUF objects (`drm_gem_is_imported(&shmem->base)`) do not use shmem page arrays (`shmem->pages`); `drm_gem_shmem_pin()`, `drm_gem_shmem_pin_locked()`, `drm_gem_shmem_unpin()`, and `drm_gem_shmem_get_sg_table()` must not be called on imported objects and assert `drm_WARN_ON(..., drm_gem_is_imported(...))`. [F51]
- In `drm_gpusvm_get_pages()`, `hmm_range.dev_private_owner` must be initialized from the per-call `ctx->device_private_page_owner` parameter, and when `ctx->devmem_only` is true, encountering any page that is neither device-private nor device-coherent must abort with `err = -EFAULT` and jump to `err_unmap`. [F59]
- In `__drm_gem_duplicate_shadow_plane_state()`, `drm_format_conv_state_copy()` must be called with `&new_shadow_plane_state->fmtcnv_state` (destination) as the first argument and `&shadow_plane_state->fmtcnv_state` (source) as the second argument. [F60]
- `drm_gem_private_object_init()` and `drm_gem_object_init_with_mnt()` require `size` in `PAGE_SIZE`-aligned bytes (`BUG_ON((size & (PAGE_SIZE - 1)) != 0)`), whereas `drm_vma_offset_add()` takes page count (`size / PAGE_SIZE`) and `drm_gem_mmap_obj()` takes `obj_size` in bytes (`drm_vma_node_size(node) << PAGE_SHIFT`). [F63]

## Error Handling

- MIPI DCS status/getter helpers (`mipi_dsi_dcs_get_power_mode`, `mipi_dsi_dcs_get_pixel_format`, `mipi_dsi_dcs_get_display_brightness`, `mipi_dsi_dcs_get_display_brightness_large`) must treat a `0` return from `mipi_dsi_dcs_read()` as `-ENODATA` rather than success before reading the output buffer. [F44]
- In `bo_driver_move()`, `bo->resource` can be `NULL` (during initial BO validation); `bo_driver_move()` must check `!bo->resource` before calling `drm_gem_vram_bo_driver_move()`, using `ttm_bo_move_null()` when `new_mem->mem_type == TTM_PL_SYSTEM` or returning `-EMULTIHOP` with a `TTM_PL_SYSTEM` hop otherwise. [F50]
- In `drm_gem_shmem_get_pages_locked()` and `drm_gem_shmem_get_pages_sgt_locked()`, the result of `drm_gem_get_pages()` or `drm_gem_shmem_get_sg_table()` must be held in a local variable and only assigned to `shmem->pages` or `shmem->sgt` after all `IS_ERR()` and `dma_map_sgtable()` checks succeed. [F53]
- `drm_gem_vmap_locked()` must check both `if (ret)` and `else if (iosys_map_is_null(map))` after calling `obj->funcs->vmap(obj, map)`, converting an unpopulated `map` into `-ENOMEM`, and `drm_gem_vunmap_locked()` must always call `iosys_map_clear(map)` after unmapping. [F54]

## External Contracts

- In drm_version(), the deprecated version->date field must be populated with "0" via drm_copy_field() rather than an empty string, and drm_copy_field() must clamp the copy length to *buf_len while setting *buf_len to the full strlen(value). [F90]
- In framebuffer_check(), unused planes (indices info->num_planes through 3) must always have r->modifier[i] == 0, but non-zero r->handles[i], r->pitches[i], or r->offsets[i] on unused planes must only be rejected when r->flags & DRM_MODE_FB_MODIFIERS is set. [F94]
- On __BIG_ENDIAN architectures, drm_mode_addfb2_ioctl() must reject the ioctl with -EOPNOTSUPP unless dev->mode_config.quirk_addfb_prefer_host_byte_order is set, so userspace falls back to ADDFB on drivers that interpret pixel_format with legacy big-endian quirks. [F97]
- In drm_ioctl(), in_size and out_size must be forced to 0 unless IOC_IN or IOC_OUT is set in both the caller's cmd and the descriptor's ioctl->cmd, and any bytes in kdata between in_size and ksize must be zero-filled with memset() before calling drm_ioctl_kernel(). [F125]
- In drm_getcap(), capabilities supported on render-only or UMS drivers (DRM_CAP_TIMESTAMP_MONOTONIC, DRM_CAP_PRIME, DRM_CAP_SYNCOBJ, DRM_CAP_SYNCOBJ_TIMELINE) must be handled and return 0 before the !drm_core_check_feature(dev, DRIVER_MODESET) check that rejects KMS-only capabilities with -EOPNOTSUPP. [F126]
- In `mipi_dsi_device_transfer()`, when `dsi->mode_flags` has `MIPI_DSI_MODE_LPM` set, `MIPI_DSI_MSG_USE_LPM` must be set in `msg->flags` before invoking `dsi->host->ops->transfer(dsi->host, msg)`. [F166]
- `mipi_dsi_dcs_set_display_brightness()` encodes the 16-bit brightness parameter in little-endian order (`brightness & 0xff`, `brightness >> 8`), whereas `mipi_dsi_dcs_set_display_brightness_large()` and `mipi_dsi_dcs_get_display_brightness_large()` encode and decode 16-bit brightness in big-endian order (`brightness >> 8`, `brightness & 0xff`). [F167]
- DRM ioctl handlers that take structures with reserved padding or flag fields (drm_mode_closefb_ioctl(), drm_mode_list_lessees_ioctl(), drm_mode_get_lease_ioctl(), drm_mode_create_lease_ioctl(), and drm_internal_framebuffer_create()) must reject non-zero pad fields and unsupported flag bits with -EINVAL. [F210]

## Known Pitfalls

- In mipi_dbi_fb_dirty(), passing src->vaddr directly to mipi_dbi_command_buf() without copying through dbidev->tx_buf via mipi_dbi_buf_copy() is only valid when dbi->dc is non-NULL, the dirty rect covers the full framebuffer (width == fb->width && height == fb->height), !dbi->swap_bytes, and fb->format->format != DRM_FORMAT_XRGB8888. [F85]
- On x86, drm_mode_fb_cmd232_t is __packed because 32-bit x86 places u64 modifier[4] at byte offset 68 without the 4-byte alignment padding present in 64-bit struct drm_mode_fb_cmd2, so compat_drm_mode_addfb2() must copy fields up to offsetof(drm_mode_fb_cmd232_t, modifier) and modifier[] in two separate copy_from_user() calls. [F93]
- In drm_gem_vram_placement(), translating DRM_GEM_VRAM_PL_FLAG_TOPDOWN into TTM_PL_FLAG_TOPDOWN must write to invariant_flags rather than overwriting pl_flag, because pl_flag is subsequently tested against DRM_GEM_VRAM_PL_FLAG_VRAM and DRM_GEM_VRAM_PL_FLAG_SYSTEM. [F113]
- In drm_gem_put_pages(), the for (i = 0; i < npages; i++) loop must advance i by folio_nr_pages(folio) - 1 at the end of the body (whereas drm_gem_get_pages() failure cleanup in a while (j < i) loop advances j += folio_nr_pages(f)) so each multi-page folio is released only once. [F117]
- In drmm_release_action() and drmm_kfree(), the resource lookup loop must store a matched entry into a separate dr_match pointer (initialized to NULL) before breaking and test !dr_match after unlocking dev->managed.lock, rather than inspecting the list_for_each_entry cursor dr outside the loop. [F127]
- When fb->format->format is DRM_FORMAT_XRGB8888, mipi_dbi_buf_copy() must dispatch pixel conversion based on dbidev->pixel_format and mipi_dbi_fb_dirty() must compute the transfer byte length len from drm_format_info(dbidev->pixel_format) rather than fb->format. [F130]
- In `drm_gem_vram_offset()`, the page offset `gbo->bo.resource->start` (`unsigned long`) must be widened to `u64` via `drm_gem_vram_pg_offset()` before shifting left by `PAGE_SHIFT` so that VRAM byte offsets above 4 GiB do not truncate on 32-bit architectures. [F135]
- In `mipi_dbi_spi_transfer()`, `max_chunk = spi_max_transfer_size(spi)` must be rounded down to an even byte count with `ALIGN_DOWN(max_chunk, 2)` before chunking transfers, so 16-bit-per-word (`bpw == 16`) SPI transfers never fail `__spi_validate()` with an odd `xfer->len`. [F139]
