# MELLANOX MLX5 core VPI driver — drivers/net/ethernet/mellanox/mlx5/core (part 1)

Implements foundational mlx5 services: firmware commands (`cmd.c`), DMA/doorbells (`alloc.c`), CQs (`cq.c`), auxiliary devices and devlink (`dev.c`, `devlink.c`), DPLL (`dpll.c`), diagnostics (`diag/`), and Ethernet (`en/`) queue parameters, HTB QoS, header modification, ID mapping, port config, and health recovery.

## Architecture & Data Flow

- Slot `cmd->vars.max_reg_cmds` is reserved for `page_queue` (`MLX5_CMD_OP_MANAGE_PAGES`); `cmd_alloc_index()` searches `[0, cmd->vars.max_reg_cmds)`. Since `cmd->vars.bitmask` is one `unsigned long` and `cmd->ent_arr` has `MLX5_MAX_COMMANDS` (32) entries, `1 << cmd->vars.log_sz` in `mlx5_cmd_enable` must not exceed 32. `alloc_token()` must skip 0 on `u8` wraparound. `free_cmd_page` must pass unaligned `cmd->cmd_alloc_buf`, `cmd->alloc_dma`, and `cmd->alloc_size` to `dma_free_coherent`. [F943, F984, F990, F991]
- When `alloc_msg` reuses a cached `mlx5_cmd_msg`, it sets `msg->len = in_size`; per-command walks (`calc_chain_sig`, `verify_signature`, `dump_command`) must bound iteration to `mlx5_calc_cmd_blocks(msg)`, whereas `mlx5_free_cmd_msg` walks `msg->next` until `NULL`, and `free_msg` returns any message with `msg->parent` to `msg->parent->head` under `msg->parent->lock`. [F875, F962]
- `mlx5_frag_buf_alloc_node()` fragments must align to `1 << buf->page_shift`; `perm` in `mlx5_fill_page_frag_array_perm()` must satisfy `!(perm & 0xfc)`. [F948]
- In `dev.c`, `is_mp_supported` must exclude `is_ib_rep_supported(dev)` and `mlx5_rdma_supported` must exclude both `is_ib_rep_supported(dev)` and `is_mp_supported(dev)`. In `mlx5_detach_device()`, when `suspend` is true, an adev is suspended in place only if `is_enabled()` (if present) is true, `adev->dev.driver` is bound, and `adrv->suspend` is set; else `del_adev()` must delete it and set `priv->adev[i] = NULL`. In `devlink.c`, `mlx5_devlink_{eth,pcie_cong,vnet,max_uc_list}_params_{register,unregister}()` must share identical capability guards. [F965, F1010, F1011]
- In `mlx5_fw_tracer_start`, `mlx5_fw_tracer_set_mtrc_conf` resets `tracer->buff.consumer_index = 0` and `mlx5_fw_tracer_set_mtrc_ctrl` (when `status` is non-zero and `mlx5_core_access_reg` succeeds) resets `tracer->last_timestamp = 0`. `mlx5_tracer_get_num_of_params()` rewrites `"%llx"` to `"%x%x"` in-place, and `mlx5_tracer_handle_string_trace()` must reject `cur_string->last_param_num > TRACER_MAX_PARAMS` (7) before writing `cur_string->params[...]`. In `mlx5_tracer_handle_timestamp_trace()`, when 7-bit `str_frmt->timestamp >= (timestamp_event.timestamp & MASK_6_0)`, decrement `timestamp_event.timestamp` by 1 before masking with `MASK_52_7`. [F939, F952, F983]
- In `mlx5_rsc_dump_trigger`, `cmd->cmd` is both in and out buffer to `mlx5_core_access_reg`; read `in_seq_num` before the call and check `in_seq_num + 1 == out_seq_num` when `out_seq_num != 0`. In `mlx5_rsc_dump_read_menu_sgmt()`, `MLX5_RSC_DUMP_MENU_HEADER_SIZE` is only on page 0 (`start_idx == 0`), and the loop must stop when `size += MLX5_ST_SZ_BYTES(resource_dump_menu_record)` reaches `>= read_size`. [F941, F953]
- In `en/htb.c`, `mlx5e_htb_convert_rate` must check `parent->classid != MLX5E_HTB_CLASSID_ROOT` before `parent = parent->parent` (`max_average_bw == 0`, `parent == NULL` on root). Changing `node->max_average_bw` in `mlx5e_htb_node_modify` requires `mlx5e_htb_update_children`. `mlx5e_htb_leaf_del` must keep `htb->qos_used_qids` contiguous (for `find_last_bit` in `mlx5e_htb_cur_leaf_nodes`) by moving `moved_qid` into the freed `qid` and writing its `classid` to `*classid`. Before reassigning a `qid` or deleting a node after `qid` transfer (`mlx5e_htb_leaf_to_inner` rollback, `mlx5e_htb_leaf_del`, `mlx5e_htb_leaf_del_last`), set the old/deleted node's `qid` to `MLX5E_QOS_QID_INNER`, deactivate/close its SQ if opened, and call `mlx5e_reset_qdisc` before opening the new SQ. [F882, F926, F927, F929, F971]
- In `en/params.c`, `mlx5e_mpwrq_pages_per_wqe()` must return `>= 2` for `MLX5E_MPWRQ_UMR_MODE_ALIGNED`, and `mlx5e_mpwrq_mtts_per_wqe()` must add 1 guard page to `pages_per_wqe` before aligning up. `mlx5e_build_icosq_log_wq_sz()` must use `DIV_ROUND_UP(wqebbs * MLX5_SEND_WQE_BB, useful_space)` deducting page-boundary NOP padding. In `mlx5e_build_rq_frags_info()` and `mlx5e_rx_compute_wqe_bulk_params()`, `info->wqe_index_mask` is `(WQEs per page) - 1` and `info->wqe_bulk >= info->wqe_index_mask + 1`; for non-linear cyclic RQs, `frag_stride` is `PAGE_SIZE` when `params->xdp_prog` is set, else fragment 0 includes headroom and `SKB_DATA_ALIGN(sizeof(struct skb_shared_info))` before `roundup_pow_of_two`. [F955, F956, F982, F1050]
- In `en/port.c`, `enum mlx5e_fec_supported_link_mode` must stay ordered by ascending per-lane speed (`<=25G`, `50G`, `100G`, `200G`) and new modes added to `mlx5e_fec_admin_field` and `mlx5e_get_fec_cap_field`. Accessing `MLX5_REG_PPLM` requires both `MLX5_CAP_GEN(dev, pcam_reg)` and `MLX5_CAP_PCAM_REG(dev, pplm)`, stopping loops when `mlx5e_is_fec_supported_link_mode()` is false. `mlx5e_remap_fec_conf_mode` must check `>= MLX5E_FEC_FIRST_200G_PER_LANE_MODE` before `>= MLX5E_FEC_FIRST_50G_PER_LANE_MODE`, and `mlx5e_set_fec_mode` must reset `conf_fec = fec_policy` each iteration. Modifying `MLX5_REG_SBCM` (`mlx5e_port_set_sbcm`) or `MLX5_REG_PPTB` (`mlx5e_port_set_priority2buffer`) requires querying the register first to preserve unmodified fields. [F936, F942, F975, F1017]
- In `mlx5e_fs_tt_redirect_{udp,any}_destroy`, restore TTC entries via `mlx5_ttc_fwd_default_dest` (`fs_{udp,any}_disable`) before destroying the redirect tables. [F932]

## Synchronization

- `mlx5_dma_zalloc_coherent_node` must hold `dev->priv.alloc_mutex` around `set_dev_node` and `dma_alloc_coherent`. `mlx5_crdump_collect` must acquire `mlx5_vsc_gw_lock(dev)` before locking `MLX5_SEMAPHORE_SW_RESET` (`mlx5_vsc_sem_set_space`), and unlock `MLX5_SEMAPHORE_SW_RESET` before `mlx5_vsc_gw_unlock(dev)` on all exits. [F870, F880]
- In `cmd_work_handler`, `poll_timeout` must read `ent->lay->status_own` with `READ_ONCE` until `CMD_OWNER_HW` clears, followed by `rmb()` before `mlx5_cmd_comp_handler` copies `ent->lay->out`. `mlx5_cmd_trigger_completions` must take `cmd_ent_get(cmd->ent_arr[i])` under `dev->cmd.alloc_lock` before unlocking to call `mlx5_cmd_comp_handler`, and call `cmd_ent_put` afterwards. [F874, F889]
- Modifying `cmd->mode` (`mlx5_cmd_change_mod`) or `cmd->allowed_opcode` (`mlx5_cmd_allowed_opcode`) requires acquiring all `cmd->vars.max_reg_cmds` counts of `cmd->vars.sem` and `cmd->vars.pages_sem` (`mlx5_cmd_use_polling` must switch to `CMD_MODE_POLLING` before unregistering `dev->cmd.nb`). Conversely, `mlx5_cmd_flush` must acquire all `sem` and `pages_sem` slots via `while (down_trylock(...))` loops calling `mlx5_cmd_trigger_completions(dev)` and `cond_resched()`, never blocking `down()`. [F894, F963]
- In `cmd.c`, when `callback` is non-NULL, `cmd_alloc_ent` and `cmd_exec` must use `GFP_ATOMIC` and `mlx5_cmd_exec_cb` must use `down_trylock` on `unprivileged_sem` and `throttle_sem`. When `in_to_uid(in)` is non-zero and `mlx5_has_privileged_uid(dev)` is true, UIDs not in `privileged_uids` must acquire `unprivileged_sem` and release it on completion. All acquisitions of `struct mlx5_cmd_stats::lock` (`stats->lock`) must disable local IRQs (`spin_lock_irq` / `spin_lock_irqsave`). [F1021, F1024, F1056]
- `mlx5_{attach,detach,register,unregister}_device` require `devl_assert_locked` and must acquire `mlx5_devcom_comp_lock(dev->priv.hca_devcom_comp)` before modifying `dev->priv.flags` or `dev->priv.adev`. In `en/htb.c`, mutations of `htb->qos_used_qids` and `htb->qos_tc2node` require `htb->priv->state_lock`, and live `node->qid` updates must set `WRITE_ONCE(node->qid, MLX5E_QOS_QID_INNER)` before deactivating/closing the old SQ and use `WRITE_ONCE` when assigning a new `qid` (paired with `READ_ONCE(node->qid)` under `rcu_read_lock()` in `mlx5e_htb_get_txq_by_classid`). [F898, F903, F1036]

## Object Lifetimes

- In `cmd_exec`, when `callback` is non-NULL, `inb`/`outb` transfer to the async path only when `mlx5_cmd_invoke` returns 0; on error, `cmd_exec` must free both. In `cmd_work_handler`, after `iowrite32be` rings `&dev->iseg->cmd_dbell`, `ent` must not be dereferenced unless `cmd_mode == CMD_MODE_POLLING || poll_cmd` (using local copies saved before ringing). In `mlx5_cmd_comp_handler`, drop the completion ref via `cmd_ent_put(ent)` only when `!forced`, `mlx5_cmd_is_down(dev)`, or `!opcode_allowed(cmd, ent->op)`, keeping timed-out slots reserved until real completion. `mlx5_cmd_exec_cb_handler` must copy `work->{ctx,throttle_locked,unpriv_locked}` to locals before `work->user_callback(status, work)` and never dereference `work` after. [F871, F872, F873, F876]
- Because `tracer_string_format->string` points into `tracer->str_db.buffer[i]` and completed items are on both `tracer->hash` and `tracer->ready_strings_list`, `mlx5_tracer_handle_timestamp_trace` and `mlx5_fw_tracer_clean_ready_list` must only `list_del(&str_frmt->list)` (leaving `mlx5_tracer_clean_message` to `hlist_del` and `kfree`), and `mlx5_fw_tracer_destroy` / `mlx5_fw_tracer_recreate_strings_db` must cancel `read_fw_strings_work` and call both clean helpers before `mlx5_fw_tracer_free_strings_db`. [F934, F969]
- In `mlx5e_mod_hdr_attach`, after inserting `mh` into `tbl->hlist` and unlocking `tbl->lock`, set `mh->compl_result` and call `complete_all(&mh->res_ready)` on both success and failure of `mlx5_modify_header_alloc`; `mlx5e_mod_hdr_detach` must call `mlx5_modify_header_dealloc` only when `mh->compl_result > 0`. `mlx5e_mod_hdr_alloc` and `mlx5e_mod_hdr_dealloc` must check `mod_hdr_acts->is_static`: transitioning from static via `kzalloc` + `memcpy` + `is_static = false`, zeroing `[old_sz, new_sz)` on `krealloc`, and skipping `kfree(mod_hdr_acts->actions)` in `mlx5e_mod_hdr_dealloc` when `is_static` is true (while clearing `actions`, `num_actions`, `max_actions`). Callers of `mlx5e_mod_hdr_alloc` must increment `mod_hdr_acts->num_actions` after populating a slot and re-fetch action pointers via `mlx5e_mod_hdr_get_item` after subsequent `mlx5e_mod_hdr_alloc` calls. [F883, F884, F920, F933, F999]
- In `mapping_remove`, when `--mi->cnt` reaches 0, `mi->node` is removed from `ctx->ht` under `ctx->lock`, while `xa_erase(&ctx->xarray, mi->id)` and `kfree_rcu(mi, rcu)` are deferred via `ctx->dwork` when `ctx->delayed_removal` is true, and flushed by `mapping_flush_work(ctx)` in `mapping_destroy` before `xa_destroy`. `mlx5e_pcie_cong_event_init` must initialize `cong_event->{work,priv,obj_id}` before `mlx5_eq_notifier_register`, and `mlx5e_pcie_cong_event_cleanup` must call `mlx5_eq_notifier_unregister` and `cancel_work_sync(&cong_event->work)` before destroying `obj_id` and freeing `cong_event`. [F885, F907]

## API Contracts

- In synchronous mode (`!callback`), `mlx5_cmd_invoke` returns `< 0` on submission/timeout error, `> 0` (`ent->status`) on delivery failure (converted via `deliv_status_to_err` in `cmd_exec`), and 0 when executed by FW. `mlx5_cmd_invoke` rejects `page_queue` commands with a callback (`-EINVAL`). Callbacks (`mlx5_cmd_cbk_t`, `mlx5_async_cbk_t`) must not sleep. Callers of `mlx5_cmd_cleanup_async_ctx` must stop new `mlx5_cmd_exec_cb` submissions first. Every `MLX5_CMD_OP_*` opcode executed via `mlx5_cmd_check` needs a case in `mlx5_internal_err_ret_value` (for `-ENXIO`) and in `mlx5_command_str` (for `dev->cmd.stats`). [F893, F909, F924, F960, F961, F1022]
- `mlx5_rsc_dump_next` returns `< 0` on error, 1 when `more_dump`, and 0 when done (writing `*size` on `>= 0`); store in a signed `int`. `mlx5_cmd_pcie_cong_event_query` only ORs flags into `*state`, so callers must zero-initialize `state`. Check the `bool` return of `mlx5e_channels_get_ptp_rqn` before reading `*rqn`, and check `mlx5e_channels_is_xsk(chs, ix)` before `mlx5e_channels_get_xsk_rqn`. `mapping_add()` allocates IDs in `[1, ctx->max_id]` (`XA_LIMIT(1, ctx->max_id)`), `mapping_{add,find}` require `data` >= `ctx->data_size`, and `mapping_create_for_id` callers sharing `(id, type)` must pass identical `data_size`. `mlx5e_create_devlink` must use `devlink_alloc_ns(..., devlink_net(priv_to_devlink(mdev)), dev)` and `devl_nested_devlink_set` before `devlink_register`. [F910, F918, F925, F959, F997, F1047]

## Error Handling

- `mlx5_cmd_do` returns `-EREMOTEIO` when FW executes a command with `outbox.status != MLX5_CMD_STAT_OK` (`cmd_status_err` maps transport `-EREMOTEIO` to `-EIO`), whereas `mlx5_cmd_exec`/`mlx5_cmd_check` translate it via `cmd_status_to_err`; `mlx5_cmd_do` callers (`mlx5_create_cq`) must inspect `outbox.status` or call `mlx5_cmd_check`. `cmd_status_print` must skip `mlx5_cmd_out_err` when `in_to_uid(in) != 0`, or for `MLX5_CMD_OP_DESTROY_MKEY`, `MLX5_CMD_OP_CREATE_UCTX`, or `MLX5_CMD_STAT_NOT_READY`. [F908, F1057]
- `mlx5_reporter_vnic_create` stores `ERR_PTR` into `health.vnic_reporter`, so consumers (`mlx5_reporter_vnic_destroy`) must check `!IS_ERR_OR_NULL`. In `dev.c`, if `add_adev(dev, i)` returns `ERR_PTR`, reset `priv->adev[i] = NULL`. In `mlx5_devlink_trap_action_set`, restore `dl_trap->trap.action = action_orig` if `mlx5_blocking_notifier_call_chain` returns `NOTIFY_BAD`. In `mlx5e_htb_leaf_del_last`, when `force` is true and `mlx5_qos_create_leaf_node` fails, preserve `saved_err` across `mlx5_qos_destroy_node` and return it after transferring `qid` to `parent` before updating `node->hw_id` or opening an SQ. [F913, F914, F917, F931]

## External Contracts

- In `mlx5_alloc_cmd_msg()`, `mlx5_cmd_prot_block` chains must have `block_num` in ascending big-endian order `0..n-1` from `msg->next` to tail and `block->next = cpu_to_be64(next->dma)`, and `calc_block_sig()`/`verify_block_sig()` must compute `block->ctrl_sig` before `block->sig`. `mlx5e_htb_convert_ceil` must clamp `*max_average_bw` to `>= 1` (`max_t(u32, ..., 1)`) because FW treats 0 as unlimited, and `mlx5e_htb_convert_{rate,ceil}` must use `div_u64`/`div64_u64` (checking `parent->max_average_bw != 0`), never `/`. [F923, F945, F946, F980]
- In `mlx5_devlink_reload_up`, `DEVLINK_RELOAD_ACTION_FW_ACTIVATE` without `DEVLINK_RELOAD_LIMIT_NO_RESET` must OR `BIT(DEVLINK_RELOAD_ACTION_DRIVER_REINIT)` into `*actions_performed`. In `mlx5_dpll_clock_quality_level_get`, populate `qls` via `__set_bit`, not scalar assignment. In `mlx5e_health_rsc_fmsg_dump`, pass binary data through `mlx5e_health_rsc_fmsg_binary` to cap chunks at `MLX5_HEALTH_DEVLINK_MAX_SIZE` (1024). [F1044, F1046, F1055]

## Known Pitfalls

- Single-slot completion vectors passed to `mlx5_cmd_comp_handler()` must use `1ULL << ent->idx` because `1 << 31` sign-extends into bit 32 (`MLX5_TRIGGERED_CMD_COMP`) of `u64 vec`, aborting the command with `-ENXIO`. `mlx5_fw_tracer_cleanup` must use non-blocking `cancel_work(&tracer->update_db_work)`, never `cancel_work_sync`, because `mlx5_fw_tracer_update_db` calls `mlx5_fw_tracer_reload` -> `mlx5_fw_tracer_cleanup` on itself. In `mlx5_fw_tracer_handle_traces`, copy each trace block from `tracer->buff.log_buf` to `tmp_trace_block` and verify the previous block's timestamp still equals `tracer->last_timestamp` before parsing; in `poll_trace()`, cast `timestamp_high` and `timestamp_mid` to `u64` before shifting by 40 and 8. [F879, F940, F976, F977]
- In `mlx5_devlink_serial_numbers_put`, VPD slices from `pci_vpd_find_ro_info_keyword` must be copied via `kstrndup(vpd_data + start, kw_len, GFP_KERNEL)` before string operations. EQ notifiers (`mlx5_eq_notifier_register`) must downcast `nb` via `mlx5_nb_cof(nb, type, member)`, whereas blocking notifiers (`mlx5_blocking_notifier_register`) use `container_of`. [F993, F1002]
