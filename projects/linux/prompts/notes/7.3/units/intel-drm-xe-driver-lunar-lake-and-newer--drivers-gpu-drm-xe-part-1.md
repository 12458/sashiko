# INTEL DRM XE DRIVER (Lunar Lake and newer) — drivers/gpu/drm/xe (part 1)

This component defines the hardware and firmware ABI headers (GuC CTB/MMIO/SLPC/SR-IOV/relay/capture and GSC MKHI/PXP/proxy protocols), GPU command instruction encodings, MMIO register definitions (`struct xe_reg` and `struct xe_reg_mcr`), i915 display compatibility wrapper headers, batchbuffer suballocation helpers (`xe_bb`), and the KUnit test suite for the Xe driver.

## Architecture & Data Flow
- `struct xe_reg` stores the MMIO byte offset in a 22-bit bitfield (`addr:const_ilog2(XE_REG_ADDR_MAX)` with `XE_REG_ADDR_MAX` = `SZ_4M`) and `xe_reg_is_valid()` tests `r.addr != 0`, so every valid register offset in `XE_REG()` or `XE_REG_MCR()` must lie in `[1, SZ_4M)`. Broken by: defining a register at offset `>= SZ_4M` (truncating `addr`) or `0`. [F1005]
- KCR registers in `regs/xe_pxp_regs.h` (`KCR_INIT`, `KCR_SIP`, `KCR_GLOBAL_TERMINATE`) are only valid on platforms with a media GT and must be accessed through the media GT's `xe_mmio` instance. [F1051]
- In `blt_copy`, each iteration of `while (size)` must clamp `src_L0 = min(src_L0, dst_L0)`, pass `&src_L0` to both `pte_update_size` calls, advance both `src_it` and `dst_it` by `src_L0` (via `xe_res_next` for VRAM or `emit_pte` for system memory), and decrement `size -= src_L0`. [F1024]
- `read_l3cc_table` must read the 32-bit `LNCFCMOCS(i >> 1)` register into `reg_val` only on even indices (`!(i & 1)`) and right-shift `reg_val >>= 16` on odd indices so `reg_val & 0xffff` extracts the lower 16-bit L3CC entry on even `i` and upper 16-bit entry on odd `i`. [F1025]
- Any test-private struct retrieved via `xe_cur_kunit_priv` and downcast with `container_of` (e.g., `struct dma_buf_test_params`, `struct migrate_test_params`) must keep `struct xe_test_priv base` at offset 0, as callers apply `container_of` before null-checking the pointer. [F1037]
- In `tests/xe_guc_g2g_test.c`, `struct g2g_test_payload` must remain `u32`-aligned and a multiple of `sizeof(u32)` in size, because `g2g_test_send` sizes the GuC CT message in dwords as `sizeof(*payload) / sizeof(u32)` and `xe_guc_g2g_test_notification` casts `msg + 3` (`u32 *`, 4-byte aligned) directly to `struct g2g_test_payload *`. [F1041]

## Synchronization
- In `xe_bo.c`, `bo->ttm.bdev->lru_lock` nests inside `xe_bo_lock(bo, false)` when updating `xe_tt->purgeable` and moving `&bo->ttm` to the LRU tail via `ttm_bo_move_to_lru_tail`. [F978]
- When validating a VM-bound buffer object (`bo->vm != NULL`) in `evict_test_run_tile`, `down_read(&vm->lock)` must be acquired outer to `xe_vm_lock(vm, false)` before calling `xe_bo_validate(bo, bo->vm, false, exec)`. [F979]
- When submitting a migration job on `m->q` in `blt_copy`, `m->job_mutex` must be held continuously across `xe_sched_job_arm(job)`, acquiring `job->drm.s_fence->finished`, calling `xe_sched_job_push(job)`, and replacing `m->fence`. [F972]
- `intel_uncore_read64_2x32` must prime `upper` from `upper_reg` before its retry loop, copy `old_upper = upper` at the start of each pass before reading `lower_reg` and re-reading `upper_reg`, and bound the loop with `upper != old_upper && loop++ < 2`. [F1016]
- In `xe_guc_g2g_test.c`, `g2g_test_send` must increment `xe->g2g_test_count` before calling `xe_guc_ct_send`, and `xe_guc_g2g_test_notification` must never invoke `KUNIT_ASSERT*` macros and must decrement `xe->g2g_test_count` on every exit path. [F980]

## Object Lifetimes
- `xe_bb_create_job()` and `xe_bb_create_migration_job()` do not take ownership of `struct xe_bb *bb` on success or failure; callers must always release `bb` via `xe_bb_free(bb, fence)` (passing `NULL` if job creation failed or after synchronous completion). `xe_bb_free(bb, fence)` borrows `fence` without consuming the caller's reference (`drm_suballoc_free()` takes its own via `dma_fence_get()`), so callers that obtained `fence` via `dma_fence_get(&job->drm.s_fence->finished)` must still call `dma_fence_put(fence)`. [F959, F961]
- Before changing `xe_tt->purgeable` on an allocated `struct xe_ttm_tt` (e.g., in `shrink_test_run_device()`), the caller must hold `xe_bo_lock(bo, ...)` and bracket the mutation with `xe_ttm_tt_account_subtract(xe, &xe_tt->ttm)` before and `xe_ttm_tt_account_add(xe, &xe_tt->ttm)` after. [F965]
- `g2g_free()` must release `gt->uc.guc.g2g.bo` via `xe_managed_bo_unpin_map_no_vm(bo)` when `g2g.owned` is true and via `xe_bo_put(bo)` when `g2g.owned` is false (matching `g2g_distribute()`), and then clear `gt->uc.guc.g2g.bo = NULL`. [F968]
- When `xe_test_dmabuf_import_same_driver()` manually assigns `bo->ttm.base.dma_buf = dmabuf` after calling `xe_gem_prime_export()` directly, it must clear `bo->ttm.base.dma_buf = NULL` before calling `dma_buf_put(dmabuf)` and `drm_gem_object_put(&bo->ttm.base)`. [F963]
- `xe_kunit_helper_xe_device_test_init()` reads optional `struct xe_pci_fake_data *` input from `test->priv` inside `xe_pci_fake_device_init(xe)` before overwriting `test->priv = xe`, and must register `kunit_action_restore_priv` via `kunit_add_action_or_reset()`. `xe_kunit_helper_xe_device_live_test_init()` must verify the device is not wedged via `xe_device_wedged(xe)`, acquire a runtime PM ref with `xe_pm_runtime_get(xe)`, and register `put_xe_pm_runtime` via `kunit_add_action_or_reset()`. [F967, F1047]
- `xe_pci_live_device_gen_param` must pass the previous `dev` (`xe ? xe->drm.dev : NULL`) into `driver_find_next_device` before calling `put_device(dev)`, and must return `NULL` when `!next` before calling `dev_name(next)` or `to_pci_dev(next)`. [F1020]
- In `shrink_test_run_device`, the readback pass must re-seed `prng` with `prandom_seed_state(&prng, rand_seed)` before iterating `bos` with `list_for_each_entry_safe(link, next, &bos, link)`, and must execute `xe_bo_put(link->bo)`, `list_del(&link->link)`, and `kfree(link)` on every iteration even when `failed` or `signal_pending(current)` is true (without mutating `prng` on purgeable BOs). [F1023]

## API Contracts
- `xe_bb_new`, `xe_bb_ccs_new`, `xe_bb_create_job`, and `xe_bb_create_migration_job` return an `ERR_PTR` on failure (never `NULL`); callers must check `IS_ERR` before passing the pointer to `xe_bb_free` or storing it in a nullable field like `oa_bo->bb` or `bo->bb_ccs[ctx_id]`. [F981]
- `xe_bb_new` must allocate `4 * (dwords + 1) + bb_prefetch(gt)` bytes (reserving `SZ_1K` on `GRAPHICS_VERx100(xe) >= 1250` main GTs and `SZ_512` otherwise), and `__xe_bb_create_job` must append `MI_BATCH_BUFFER_END`, assert `bb->len * 4 + bb_prefetch(q->gt) <= size`, and call `xe_sa_bo_flush_write(bb->bo)` before `xe_sched_job_create`. [F1046]
- In `xe_bb_create_migration_job`, `batch_base_ofs` is a byte GPU offset whereas `second_idx` is a dword index (`second_idx <= bb->len`) within `bb->cs`, scaled by 4 (`batch_base_ofs + drm_suballoc_soffset(bb->bo) + 4 * second_idx`) to form the second batch address. [F984]
- `XE_INSTR_NUM_DW(x)` and `GFX_OP_PIPE_CONTROL(len)` take the total dword length (`>= 2`) of the GPU instruction and encode `(x) - 2` into the header's length field, whereas `MI_SDI_NUM_DW(x)` and `MI_SDI_NUM_QW(x)` take the number of payload data dwords/qwords and add the 3-dword header before subtracting 2. [F988]
- `xe_assert`, `xe_tile_assert`, and `xe_gt_assert` compile out to `typecheck` and `BUILD_BUG_ON_INVALID(condition)` when `CONFIG_DRM_XE_DEBUG` is disabled; never use them as branch conditions, with side-effecting expressions, or in place of `drm_WARN`/`drm_err` on runtime failure paths. [F1014]
- Every `struct intel_uncore *` passed to helpers in `compat-i915-headers/intel_uncore.h` must be `&xe->uncore` embedded in `struct xe_device` (as returned by `to_intel_uncore`), because `__compat_uncore_to_mmio` unconditionally downcasts via `container_of(uncore, struct xe_device, uncore)`. [F1038]
- `COUNT_ARGS` does not expand macro arguments before counting them; callers passing a macro whose expansion contains comma-separated arguments (e.g., `DROP_FIRST_ARG(...)`) must invoke it through `CALL_ARGS(COUNT_ARGS, ...)`. [F1018]
- KUnit parameter description and generator callbacks (`xe_pci_fake_data_desc`, `xe_pci_live_device_gen_param`, `rtp_to_sr_desc`, `rtp_desc`, `lmtt_ops_param_get_desc`, `uint_param_get_desc`) must bound writes to `char *desc` by `KUNIT_PARAM_DESC_SIZE`. [F1042]
- Live KUnit test suites compiled into `xe.ko` (e.g., `xe_dma_buf_test_suite`, `xe_bo_test_suite`) must be marked `VISIBLE_IF_KUNIT`, exported with `EXPORT_SYMBOL_IF_KUNIT()`, and registered via `kunit_test_suite()` in `drivers/gpu/drm/xe/tests/xe_live_test_mod.c` with `MODULE_IMPORT_NS("EXPORTED_FOR_KUNIT_TESTING")`. [F1064]

## External Contracts
- In `struct guc_ct_buffer_desc`, each Command Transport Buffer is one-directional: `head` must only be updated by the receiver and `tail` must only be updated by the sender. Broken by: host writing `desc->head` on H2G or `desc->tail` on G2H during normal operation. [F975]
- In `struct guc_log_buffer_state`, `write_ptr` is read-only for the host and `read_ptr` is read-only for GuC; on a flush interrupt, the host must read up to `sampled_write_ptr`, update `read_ptr` to `sampled_write_ptr`, and clear `GUC_LOG_BUFFER_STATE_FLUSH_TO_FILE` in `flags` before acknowledging the flush to GuC. [F976]
- `XE_GUC_TLB_INVAL_MODE_LITE` must only be used when address translations for in-flight engine transactions remain invariant across the invalidation; `XE_GUC_TLB_INVAL_MODE_HEAVY` is required when in-flight transactions must be Globally Observed before completion (e.g., when unmapping or changing active page table translations). [F977]
- In GuC SR-IOV and error-capture ABIs (`abi/guc_capture_abi.h`, `abi/guc_actions_sriov_abi.h`), `VFID = 0` identifies the PF while VFs use 1-based IDs (`1..63`), and in `GUC_ACTION_GUC2PF_VF_STATE_NOTIFY` event `1` means `GUC_PF_NOTIFY_VF_ENABLE` when `VFID == 0` but `GUC_PF_NOTIFY_VF_FLR` when `VFID != 0`. [F1009]

## Known Pitfalls
- `struct guc_ct_buffer_desc` `head` and `tail` are dword offsets and `GUC_CTB_MSG_0_NUM_DWORDS` is the payload length in dwords excluding `GUC_CTB_HDR_LEN` (1 dword), whereas `struct guc_log_buffer_state` offsets (`read_ptr`, `write_ptr`, `sampled_write_ptr`, `wrap_offset`, `size`) are in bytes. [F1007]
- In `abi/guc_capture_abi.h`, `struct guc_state_capture_group_t::capture_entries` cannot be indexed via C subscripting (`capture_entries[i]`) because its element type `struct guc_state_capture_t` ends with a variable-length flexible array `struct guc_mmio_reg mmio_entries[]` sized at runtime by `header.num_mmio_entries`. [F1040]
- Context register macros in `regs/xe_lrc_layout.h` (e.g., `CTX_CONTEXT_CONTROL`, `CTX_RING_HEAD`, `CTX_RING_TAIL`, `INDIRECT_CTX_RING_HEAD`) are 32-bit dword indices pointing directly to the register value slot (`offset_dw + 1`) within the LRC image, not byte offsets. [F1012]
- Because `ttm_bo_validate` clears `xe_tt->purgeable` when repopulating a BO, any caller that needs to know whether `bo` was purgeable prior to validation must sample `xe_tt->purgeable` before calling `ttm_bo_validate`. [F995]
- `xe_cur_kunit_priv(id)` dereferences `kunit_get_current_test()->priv` as `struct xe_test_priv *` to check `priv->id == id`; KUnit tests invoking paths that call `xe_cur_kunit_priv` must ensure `test->priv` is non-NULL with `base.id` initialized, and callers of `xe_cur_kunit_priv` must NULL-check the return value. [F986]
- When chaining KUnit array parameter generators in `xe_pci_graphics_ip_gen_param` and `xe_pci_media_ip_gen_param`, `prev` must be reset to `NULL` if `is_insidevar(prev, pre_gmdid_*_ips)` is true after the first generator returns `NULL` before calling the second generator. In `xe_pci_id_gen_param`, the entry from `pci_id_gen_params` must be filtered with `pci->driver_data ? pci : NULL` to exclude the trailing zero sentinel in `pciidlist`. [F1021, F1022]
- In `shrink_test_run_device()`, 64-bit division of `u64 purgeable` must use `div64_u64()` rather than `/` to avoid undefined `__udivdi3` link errors on 32-bit builds. [F1032]
