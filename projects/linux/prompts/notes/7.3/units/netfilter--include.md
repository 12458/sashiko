# NETFILTER — include

Provides the core kernel-internal headers, data structures, and inline helpers for the Netfilter subsystem, covering hook dispatch (`linux/netfilter.h`), `nf_tables` (`net/netfilter/nf_tables.h`), connection tracking (`net/netfilter/nf_conntrack*.h`), flow tables (`net/netfilter/nf_flow_table.h`), IP sets (`linux/netfilter/ipset/*.h`), and Xtables (`linux/netfilter/x_tables.h`).

## Architecture & Data Flow
- In `struct nft_regs` and `struct nft_data`, `verdict` (`struct nft_verdict`) unions with `data[0..3]`, so mutating `regs->verdict` clobbers `regs->data[0..3]` and vice versa. Because `nf_tables` allocates registers in 32-bit (`NFT_REG32_SIZE`) units, writes to `regs->data` not a multiple of 4 bytes must zero the trailing bytes of the last 32-bit slot (via `nft_reg_store8`, `nft_reg_store16`, or `nft_data_copy`), and 64-bit accesses must use `nft_reg_load64()`/`nft_reg_store64()` (`get_unaligned`/`put_unaligned`) since `u32` slots are only 4-byte aligned. [F36, F49, F67]
- In `nf_tables` objects and `struct nft_set_ext`, a set bit in `genmask` marks the entry *inactive* in that generation; active checks (`nft_is_active`, `nft_is_active_next`, `nft_active_genmask`, `nft_set_elem_active`) must test `!(genmask & mask)`. [F79]
- `struct nft_set_ext` must be aligned to `BITS_PER_LONG / 8` with `genmask` at offset 0 (and `set->ops->elemsize` in `nft_set_elem_ext()` must be a multiple of `sizeof(unsigned long)`) because `nft_set_elem_dead()`/`nft_set_elem_is_dead()` cast `struct nft_set_ext *` to `unsigned long *` for atomic bitops. `nft_set_ext_add_length` must check `tmpl->len > U8_MAX` after aligning `tmpl->len` (`u16`) before assigning `tmpl->offset[id] = tmpl->len` because `offset` is a `u8` array where `0` means absent. [F92, F114]
- `__nft_set_elem_expired` must check both `nft_set_ext_exists(ext, NFT_SET_EXT_TIMEOUT)` and `nft_set_ext_timeout(ext)->timeout != 0` before comparing `tstamp` against `expiration` with `time_after_eq64`, because `timeout == 0` marks a permanent element even when the extension exists. [F93]
- `nft_setelem_expr_foreach(__expr, __elem_expr, __size)` bounds iteration by `(__elem_expr)->size` and advances by `(__expr)->ops->size`; `elem_expr->size` must only be incremented as each expression in `elem_expr->data` is initialized, and `(__expr)->ops` must not be cleared inside the loop body. [F82]
- In `struct nft_rule`, `rule->dlen` is a 12-bit bitfield (< 4096 bytes) holding the packed expression length in `rule->data[]`. When `rule->udata` is non-zero, `struct nft_userdata` sits at `&rule->data[rule->dlen]` (`nft_expr_last(rule)` / `nft_userdata(rule)`) and encodes a non-zero payload length `ulen` as `len = ulen - 1`; callers must check `rule->udata` first and use `udata->len + 1` as the byte length. [F77, F96]
- In `struct nft_rule_blob`, rules advance by `sizeof(struct nft_rule_dp) + rule->dlen` via `nft_rule_next` (never `rule++`) and end at `(void *)blob + sizeof(*blob) + blob->size`, where a `struct nft_rule_dp_last` trailer (with `struct nft_rule_dp end` having `is_last = 1` at offset 0) is allocated past `blob->size`. [F99]
- `struct nft_trans` must be the first member of every transaction subtype (and `struct nft_trans_binding` first in binding subtypes like `struct nft_trans_set` and `struct nft_trans_chain`), and `trans->msg_type` must be checked before downcasting via `nft_trans_container_*`. Pending `NFT_MSG_NEWSET` transactions must be linked via `nft_trans_set::list_trans_newset` on `nftables_pernet::commit_set_list` and unlinked on commit/abort rather than scanning `commit_list`. [F40, F84]
- In `struct nf_conn`, `nf_conntrack_alloc` only zeroes fields after `struct { } __nfct_init_offset` via `memset_after`, so fields before it require explicit initialization, and `union nf_conntrack_proto proto` must remain the last member. `nf_ct_tuplehash_to_ctrack(hash)` uses `container_of(hash, struct nf_conn, tuplehash[hash->tuple.dst.dir])`, requiring `hash` to be embedded in `ct->tuplehash[]` with `tuple.dst.dir` initialized (`IP_CT_DIR_ORIGINAL`/`IP_CT_DIR_REPLY`) and placed after `dst.__nfct_hash_offsetend`. [F43, F102]
- `ct->timeout` in `struct nf_conn` holds a relative jiffies duration while unconfirmed (`!nf_ct_is_confirmed(ct)`) and an absolute `nfct_time_stamp` expiration once confirmed (`__nf_ct_set_timeout()`, `nf_ct_should_gc()`). Broken by: writing `nfct_time_stamp + timeout` or calling `nf_ct_expires()`/`nf_ct_is_expired()` on an unconfirmed `ct`. [F55]
- In `ip_set`, `opt->ext.timeout` uses `IPSET_NO_TIMEOUT` (`UINT_MAX`) as the sentinel to fall back to `set->timeout` via `ip_set_adt_opt_timeout`, whereas `IPSET_ELEM_PERMANENT` (`0`) in an element's timeout slot means never expires in `ip_set_timeout_expired()`. In `ip_set_timeout_set()`, if `msecs_to_jiffies(value * MSEC_PER_SEC) + jiffies` wraps to `0` (`IPSET_ELEM_PERMANENT`) for a non-zero `value`, it must be decremented (`t--`). [F33, F61]
- `IP_SET_INIT_UEXT` initializes `ext.bytes` and `ext.packets` to `ULLONG_MAX`, and `ip_set_init_counter` only writes `counter->bytes` or `counter->packets` when the corresponding `ext` field is not `ULLONG_MAX`. Broken by: passing `0` instead of `ULLONG_MAX` for unspecified counters on update, or not zero-allocating counter storage. [F32]

## Synchronization
- `nf_hook_ingress` must be called under `rcu_read_lock()` and must recheck that `rcu_dereference(skb->dev->nf_hooks_ingress)` is non-NULL even after `nf_hook_ingress_active(skb)` returned true. In `nf_hook_egress`, even when `rcu_read_lock_bh()` is held, `nf_hook_slow(skb, &state, e, 0)` must be wrapped in `rcu_read_lock()`/`rcu_read_unlock()` because Netfilter hooks require standard RCU read-side protection. [F17, F18]
- `xt_write_recseq_begin()` must be called with preemption and softirqs disabled, and its returned `addend` (`0` or `1`) must be passed unchanged to `xt_write_recseq_end(addend)` on the same CPU on all paths. [F10]
- `NF_CT_STAT_INC()` and `NF_FLOW_TABLE_STAT_INC()`/`DEC()` use non-atomic `__this_cpu_inc()`/`__this_cpu_dec()` and require softirqs/preemption disabled; preemptible process or workqueue contexts must use `NF_CT_STAT_INC_ATOMIC()` or `NF_FLOW_TABLE_STAT_INC_ATOMIC()`/`DEC_ATOMIC()`. [F113]
- `nf_conntrack_get_ht()` must be called under `rcu_read_lock()` so the `nf_conntrack_hash` table pointer read under `nf_conntrack_generation` seqcount is not freed by a concurrent `nf_conntrack_hash_resize()`. Callers of `nf_ct_should_gc(ct)` must first hold a reference on `ct` (`refcount_inc_not_zero(&ct->ct_general.use)`), and `nf_ct_should_gc()` must run `smp_acquire__after_ctrl_dep()` after `nf_ct_is_confirmed(ct)` and before `nf_ct_is_expired(ct)`. [F109, F110]
- In `nf_conntrack_event_cache`, `e->timestamp` is updated only when `local64_read(&e->timestamp)` is non-zero and `READ_ONCE(e->cache) == 0` *before* `set_bit(event, &e->cache)`, recording the first cached event. [F24]
- In `nf_flow_table_offload_add_cb` and `nf_flow_table_offload_del_cb`, `flow_table->flow_block.cb_list` accesses must be protected by `down_write(&flow_table->flow_block_lock)`, and `flow_table->type->get` or `put` must be called *after* `up_write(&flow_table->flow_block_lock)`. [F19]
- Readers of the active `nf_tables` generation bitmask must use `nft_genmask_cur(net)` (which uses `READ_ONCE(net->nft.gencursor)`) rather than reading `net->nft.gencursor` directly. [F23]
- `nft_rule_expr_deactivate()` and `nf_tables_deactivate_set()` require `nft_pernet(net)->commit_mutex` held, and `nf_tables_rule_destroy()` / `nf_tables_chain_destroy()` (calling `nft_expr_ops->destroy`) must run in sleepable process/workqueue context only after `synchronize_rcu()` once unlinked (never from `call_rcu()`). [F116]
- Saving or restoring per-CPU `struct nft_inner_tun_ctx` offsets requires `local_bh_disable()` while validating `cookie == (unsigned long)pkt->skb` (with `NFT_PKTINFO_INNER_FULL` and `type`) and copying to/from a stack `struct nft_inner_tun_ctx` before calling `nft_payload_inner_eval()` or `nft_meta_inner_eval()`. [F117]

## Object Lifetimes
- `nf_ct_get()` returns a borrowed `struct nf_conn *` from `skb->_nfct` without incrementing `ct->ct_general.use`; callers must not pass it to `nf_ct_put()` without first taking a reference. [F4]
- In `nf_conntrack_confirm()`, after `__nf_conntrack_confirm(skb)` returns `NF_ACCEPT`, local `ct` (and any pointers derived from it) must be reloaded from `skb_nfct(skb)` because clash resolution can replace `skb->_nfct` and free the losing `struct nf_conn`. [F53]
- `nf_ct_expect_alloc()` initializes `exp->use` to `1`, and `nf_ct_expect_related_report()` (or `nf_ct_expect_related()`) takes two internal references only on successful insertion, so callers must call `nf_ct_expect_put()` afterwards on both success and failure. [F5]
- `nf_tproxy_sk_is_transparent(sk)` drops `sk` via `sock_gen_put(sk)` when returning `false`, and when it returns `true`, `nf_tproxy_assign_sock(skb, sk)` orphans `skb` and transfers ownership of `sk` to `skb->sk` (`sock_edemux`); callers must not call `sock_gen_put(sk)` in either case. [F9]
- When `nft_data_init()` succeeds with `desc->type == NFT_DATA_VERDICT`, it increments `chain->use` for `NFT_JUMP` and `NFT_GOTO` verdicts, so any later error in init or teardown must call `nft_data_release(data, desc.type)`. [F11]

## API Contracts
- `nf_hook()` only dispatches `NFPROTO_IPV4`, `NFPROTO_IPV6`, `NFPROTO_ARP`, and `NFPROTO_BRIDGE`, and `NF_HOOK_LIST()` only dispatches `NFPROTO_IPV4` and `NFPROTO_IPV6` (`WARN_ON_ONCE(1)` otherwise); `NFPROTO_NETDEV` must use `nf_hook_ingress()` or `nf_hook_egress()`. [F80]
- `nf_hook_egress()` returns `skb` when the packet passes (`ret == 1`), or returns `NULL` after `nf_hook_slow()` consumes `skb` and stores `NET_XMIT_DROP` (`ret < 0`) or `NET_XMIT_SUCCESS` (`ret == 0`) into `*rc`; callers must not free or dereference `skb` when it returns `NULL`. [F3]
- `NF_DROP_REASON(skb, reason, err)` requires a positive 16-bit errno (`err <= 0xffff`), frees `skb` immediately via `kfree_skb_reason`, and returns `((err << 16) | NF_STOLEN)` (which `NF_DROP_GETERR` decodes to `-err`). Broken by: passing negative `-EXXX` or freeing `skb` again. [F27]
- `nf_ct_ext_add()` and `nf_conntrack_alter_reply()` require `!nf_ct_is_confirmed(ct)`, and because `nf_ct_ext_add()` reallocates `ct->ext` via `krealloc()`, any pointers previously obtained from `nf_ct_ext_find()` (e.g. `nfct_help(ct)`, `nfct_nat(ct)`) become stale across `nf_ct_ext_add()`. [F54]
- Before a packet carrying an unconfirmed `struct nf_conn` (`!nf_ct_is_confirmed(ct)`) is cloned for concurrent processing (e.g. multicast/broadcast frames entering `LOCAL_IN` from bridge netfilter), the conntrack must be confirmed via `nf_ct_hook->confirm(skb)` / `nf_conntrack_confirm(skb)` or detached. [F131]
- `struct nf_conn_help` embeds a 32-byte `char data[32] __aligned(8)` buffer accessed via `nfct_help_data(ct)`, which dereferences `nf_ct_ext_find(ct, NF_CT_EXT_HELPER)` without a NULL check; helpers must assert `NF_CT_HELPER_BUILD_BUG_ON(sizeof(priv_type))` and callers not guaranteed to have `NF_CT_EXT_HELPER` attached must check `nfct_help(ct)` for NULL first. [F44, F104]
- Callers of `nf_ct_set_tcp_be_liberal(ct)` or `nf_conntrack_tcp_established(ct)` must first verify `nf_ct_protonum(ct) == IPPROTO_TCP` because `ct->proto` is an untagged union (`union nf_conntrack_proto`). [F129]
- `nft_set_elem_ext` computes `(void *)elem_priv + set->ops->elemsize` and `nft_set_ext(ext, id)` computes `(void *)ext + ext->offset[id]` unconditionally; set backends must set `ops.elemsize = offsetof(elem_type, ext)`, and callers of `nft_set_ext_*` accessors for optional extensions must check `nft_set_ext_exists(ext, id)` first. [F97]
- `nft_base_chain(chain)` downcasts via `container_of` unchecked; callers must verify `nft_is_base_chain(chain)` (`NFT_CHAIN_BASE`) first. [F100]
- `nft_ctx_update()` populates `ctx->chain` only for `NFT_MSG_NEWRULE`, `NFT_MSG_DELRULE`, `NFT_MSG_DESTROYRULE`, `NFT_MSG_NEWCHAIN`, `NFT_MSG_DELCHAIN`, and `NFT_MSG_DESTROYCHAIN`, resetting `ctx->chain = NULL` for all other `trans->msg_type` values. [F51]
- In `nft_fib` evaluation (`nft_fib4_eval`, `nft_fib6_eval`, `nft_fib6_eval_type`), the VRF master interface index must be resolved via `nft_fib_l3mdev_master_ifindex_rcu(pkt, dev)` so non-strict lookups (`dev == NULL`) fall back to `pkt->skb->dev` instead of `0`. [F122]
- Any `struct nft_object_type` or `struct nft_expr_type` that assumes a specific protocol family must set `.family` to that `NFPROTO_*` constant rather than `0` (`NFPROTO_UNSPEC`). [F124]
- Before calling `__nf_flow_pppoe_proto(skb)` or reading the inner PPPoE header from `skb_mac_header(skb)`, callers (like `nf_flow_pppoe_proto()`) must ensure `pskb_may_pull(skb, ETH_HLEN + PPPOE_SES_HLEN)` succeeds. [F121]
- Before destroying an `ip_set` via `set->variant->destroy(set)` (directly or via `call_rcu(&set->rcu, ...)`), `set->variant->cancel_gc(set)` must be called synchronously in process context. [F20]
- Callers of `ip_set_netmask`, `ip_set_hostmask`, `ip_set_netmask6`, `ip_set_hostmask6`, and `ip6_netmask` must validate `pfxlen` is in `0..32` (IPv4) or `0..128` (IPv6) because they index 129-entry lookup tables (`ip_set_netmask_map`/`ip_set_hostmask_map`). [F88]
- In `struct nf_sockopt_ops`, `[set_optmin, set_optmax)` and `[get_optmin, get_optmax)` are half-open (non-inclusive upper bound), and an unused direction must set `optmin = 0`, `optmax = 0`, and callback to `NULL`. [F30]
- All three buffers passed to `ifname_compare_aligned(_a, _b, _mask)` must be at least `IFNAMSIZ` (16) bytes and aligned to `sizeof(unsigned long)`. [F72]

## Error Handling
- `nf_hook` returns `1` only when the packet passes and the caller should invoke `okfn`; `0` (queued/stolen) or negative `-ERRNO` (`NF_DROP_GETERR`) means the hook consumed `skb` and the caller must not invoke `okfn` or free `skb`. By contrast, `nf_hook_ingress(skb)` converts `0` from `nf_hook_slow` into `-1`, returning `< 0` when consumed/dropped and `>= 0` (`0` if no hooks, `1` if passed) when the caller should continue processing `skb`. [F26, F29]
- `struct ip_set_type_variant` callbacks `kadt` and `uadt` return a signed `int`: `< 0` errno on failure, `0` on non-match (`IPSET_TEST`) or success (`IPSET_ADD`/`IPSET_DEL`), and `> 0` when an element matches. [F31]
- An `xt_match->match` callback returns `bool` (`true` on match, `false` on mismatch) and can only force an immediate packet drop on inspection error by setting `par->hotdrop = true` while returning `false`. [F34]

## External Contracts
- When passing a `struct nft_set`'s data type to `nft_parse_register_store()` or `nft_data_dump()`, callers must normalize `set->dtype` via `nft_set_datatype(set)` (`NFT_DATA_VERDICT` or `NFT_DATA_VALUE`) rather than passing raw `set->dtype`. [F123]
- Any `struct xt_match` or `struct xt_target` whose private struct contains kernel-only pointers or fields after the userspace layout must set `.usersize` to the offset of the first kernel-only field so `xt_data_to_user()` zeroes the trailing region with `clear_user()`. [F127]

## Known Pitfalls
- `NF_INVF(ptr, flag, boolean)` in `include/linux/netfilter/x_tables.h` applies bitwise XOR (`^`) to `boolean` without `!!`, so callers must pass a 0-or-1 boolean expression rather than an unnormalized integer or bitmask. [F78]
- `nft_rule_for_each_expr()` advances via `nft_expr_next(expr)` (`expr + expr->ops->size`) until `nft_expr_last(rule)` without checking `expr->ops`; paths that can run on a partially initialized `struct nft_rule` (e.g. `nft_rule_expr_deactivate()`, `nf_tables_rule_destroy()`) must use `while (nft_expr_more(rule, expr))` to stop at the first NULL `expr->ops`. [F81]
- Timeout values in seconds passed to `ip_set_timeout_set` must be clamped to `IPSET_MAX_TIMEOUT` (`(UINT_MAX >> 1)/MSEC_PER_SEC`) via `ip_set_timeout_uget` rather than read with raw `ip_set_get_h32`, because `ip_set_timeout_set` multiplies `u32 value * MSEC_PER_SEC` in 32-bit arithmetic. [F86]
