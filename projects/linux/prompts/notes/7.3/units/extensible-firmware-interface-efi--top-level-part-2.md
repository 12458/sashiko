# EXTENSIBLE FIRMWARE INTERFACE (EFI) — (top level) (part 2)

This component contains the pre-boot EFI Boot Stub (`drivers/firmware/efi/libstub/*`), which executes as a PE/COFF image inside the UEFI Boot Services environment prior to `ExitBootServices()` to decompress/relocate the kernel, load initrds, configure GOP graphics, seed KASLR/RNG, measure into TPM/CC, and prepare the FDT or `boot_params`. It also includes core kernel EFI runtime service wrappers (`runtime-wrappers.c`), generic EFI variable operations (`vars.c`), OP-TEE StandaloneMM variable services (`stmm/tee_stmm_efi.c`), EFI memory map and memory attributes management (`memmap.c`, `memattr.c`), confidential computing unaccepted memory management (`unaccepted_memory.c`), MOK variable/RCI2/OVMF tables, TPM event log parsing, EFI reboot handling, and EFI system framebuffer DMI quirks (`sysfb_efi.c`).

## Architecture & Data Flow

- In x86 and shared libstub code, UEFI union fields and methods must be accessed via efi_table_attr(), efi_call_proto(), efi_bs_call(), efi_rt_call(), efi_dxe_call(), or efi_fn_call(), and handle/event arrays via for_each_efi_handle(), efi_get_handle_at(), or efi_set_event_at(). [F209]
- When efi_allocate_bootparams() allocates and zeroes a fresh struct boot_params for the x86 PE entry path, it must initialize hdr->initrd_addr_max = INT_MAX so that efi_load_initrd() enforces the 2 GiB soft limit for command-line initrds. [F216]
- When CONFIG_RANDOMIZE_BASE is enabled and !efi_nokaslr in efi_decompress_kernel(), boot_params->hdr.loadflags must have KASLR_FLAG set in lockstep, and physical randomization seed[0] must be zeroed if cmdline_memmap_override (mem=, memmap=, hugepages=) or AMI UEFI v2.0 or older is detected. [F230]
- In exit_boot(), allocate_e820() must pre-allocate both e820ext (with EFI_MMAP_NR_SLACK_SLOTS headroom) and unaccepted_table before efi_exit_boot_services(), and setup_e820() then populates unaccepted_table->bitmap via process_unaccepted_memory() from the final post-EBS memory map while converting EFI_UNACCEPTED_MEMORY entries to E820_TYPE_RAM. [F234]
- When install_cfg_tbl is true in efi_get_memory_map(), install_configuration_table for LINUX_EFI_BOOT_MEMMAP_GUID must be called before the final get_memory_map call (and uninstalled with NULL if get_memory_map fails), because installing a configuration table may allocate memory and invalidate a previously fetched memory map. [F235]
- efi_random_alloc() repurposes each descriptor's virt_addr field via MD_NUM_SLOTS(md) in its local efi_boot_memmap copy to store candidate slot counts during the first pass, and when total_mirrored_slots > 0, both total_slots and the second-pass loop must filter exclusively on EFI_MEMORY_MORE_RELIABLE descriptors. [F236]
- In efi_convert_cmdline(), efi_measure_tagged_event() must measure the raw image->load_options and load_options_size into EFISTUB_EVT_LOAD_OPTIONS before efi_apply_loadoptions_quirk() mutates options and options_size in place to point to optional_data. [F237]
- Unlike efi_pe_entry(), efi_handover_entry() is entered directly by a bootloader with an existing boot_params pointer rather than through the UEFI PE/COFF loader, so it must explicitly zero [_bss, _ebss) with memset(_bss, 0, _ebss - _bss) before calling efi_stub_entry(). [F239]

## Synchronization

- efivar_lock() and efivar_trylock() must release efivars_lock via up(&efivars_lock) and return -ENODEV if !__efivars->ops, and callers of efivar_get_variable(), efivar_get_next_variable(), and efivar_set_variable_locked() must hold efivars_lock while those callees leave the lock held across all return paths. [F180]
- All runtime-wrappers.c callers using the global efi_rts_work structure must hold efi_runtime_lock across __efi_queue_work() until wait_for_completion(&efi_rts_work.efi_rts_comp) returns and efi_rts_work.efi_rts_id is reset to EFI_NONE, because efi_rts_work and its stack-allocated union efi_rts_args are shared and non-reentrant. [F187]
- Because `efivars_register()` invokes `blocking_notifier_call_chain(&efivar_ops_nh, ...)` while holding `efivars_lock`, callbacks registered on `efivar_ops_nh` must not call `efivar_lock()`, `efivar_trylock()`, `efivar_set_variable()`, `efivars_register()`, or `efivars_unregister()`. [F196]
- In `riscv_enable_runtime_services()`, `efi_virtmap_init()` and `efi_native_runtime_setup()` must complete before `set_bit(EFI_RUNTIME_SERVICES, &efi.flags)` enables runtime service calls. [F200]
- On RISC-V, `arch_efi_call_virt_setup()` / `efi_virtmap_load()` disables preemption before switching `current->active_mm` to `efi_mm`, and `arch_efi_call_virt_teardown()` / `efi_virtmap_unload()` restores `current->active_mm` before re-enabling preemption, so code executing between setup and teardown must not sleep. [F321]

## Object Lifetimes

- Before calling efi_memmap_init_late(), the caller must unmap the early mapping via efi_memmap_unmap(), which unmaps efi.memmap.map using early_memunmap() or memunmap(), sets efi.memmap.map to NULL, and clears EFI_MEMMAP in efi.flags. [F171]
- In efi_exit_boot_services(), operations that can modify the UEFI memory map such as efi_pci_disable_bridge_busmaster() must run before efi_get_memory_map(), and once exit_boot_services() has been called once, the retry path must reuse the existing map buffer without calling allocate_pool or free_pool. [F173]
- In efi_random_get_seed(), an existing LINUX_EFI_RANDOM_SEED_TABLE_GUID configuration table (prev_seed) must only be zeroed and freed via free_pool after the replacement seed buffer has been populated and successfully installed over it via install_configuration_table. [F176]
- In alloc_e820ext(), when freeing a pre-existing *e820ext buffer before reallocating, both *e820ext and *e820ext_size must be reset to NULL and 0 prior to calling allocate_pool so that a failed reallocation does not leave a dangling pointer or stale buffer size. [F179]
- In tee_stmm_efi.c, every buffer allocated by setup_mm_hdr() via alloc_pages_exact(COMM_BUF_SIZE(payload_size), ...) must be freed before returning via free_pages_exact(comm_buf, COMM_BUF_SIZE(payload_size)) with the same payload_size, and tee_mm_communicate() must free its temporary shm via tee_shm_free(shm). [F181]
- In accept_memory(), the stack-allocated struct accept_range range added to accepting_list under unaccepted_memory_lock must remain on accepting_list while unaccepted_memory_lock is dropped (with IRQs kept disabled) across arch_accept_memory(), and must be removed via list_del(&range.list) before unlocking and returning. [F183]
- In efi_rci2_sysfs_init() and ovmf_log_probe(), the initial header-sized memremap() mapping must be unmapped with memunmap() before remapping the full table size and on header validation failure, and if sysfs_create_bin_file() fails, the full mapping (and tables_kobj in efi_rci2_sysfs_init()) must be torn down in reverse order. [F185]
- Every virtual EFI runtime service invocation in efi_call_rts() and efi_call_virt_pointer() must bracket the firmware call with arch_efi_call_virt_setup() and efi_call_virt_save_flags() beforehand, and efi_call_virt_check_flags() followed by arch_efi_call_virt_teardown() afterward, so corrupted IRQ flags and page tables/MM context are restored. [F188]

## API Contracts

- Because efi_convert_cmdline() always allocates at least one byte for the NUL terminator and returns NULL only on allocation failure, callers such as efi_handle_cmdline() must check cmdline[0] == 0 to detect an empty UEFI command line. [F202]
- handle_cmdline_files() returns EFI_NOT_READY when no matching file option is present on the command line, and callers (efi_load_initrd() and allocate_new_fdt_and_exit_boot()) must treat EFI_NOT_READY as a non-error absence of the option. [F207]
- In efi_decompress_kernel() on x86, efi_random_alloc() must be passed LOAD_PHYSICAL_ADDR as alloc_min so that the kernel is never placed below LOAD_PHYSICAL_ADDR even when physical KASLR is disabled (seed[0] == 0). [F219]
- When calling boottime->set_timer in libstub, the microsecond timeout must be multiplied by EFI_100NSEC_PER_USEC (10) because set_timer takes 100ns units whereas boottime->stall and efi_wait_for_key() take microseconds. [F221]
- In efivar_set_variable_locked(), when data_size > 0, the size passed to check_var_size() must be data_size + ucs2_strsize(name, EFI_VAR_NAME_LEN) so that both the variable data and the NUL-terminated UCS-2 variable name are accounted for. [F223]
- process_unaccepted_memory(start, end) and arch_accept_memory(start, end) take [start, end) physical addresses, whereas accept_memory(start, size) and range_contains_unaccepted_memory(start, size) take a start address and byte length. [F224]
- Because efivars_register() allows only one active __efivars singleton under efivars_lock (returning -EBUSY if non-NULL), tee_stmm_efi_probe() must call efivars_generic_ops_unregister() before registering tee_efivars, and tee_stmm_efi_remove() must unregister tee_efivars before calling efivars_generic_ops_register(). [F232]
- In `drivers/firmware/efi/stmm/tee_stmm_efi.c`, `setup_mm_hdr(&comm_buf, payload_size, func)` stores the base allocation in `comm_buf` and returns the inner payload pointer `var_hdr->data`, so callers must pass `comm_buf` (not the returned payload pointer) to `mm_communicate()` and `free_pages_exact()`. [F271]

## Error Handling

- In allocate_new_fdt_and_exit_boot(), priv.runtime_map is only allocated via efi_alloc_virtmap() when !efi_novamap, so the fail: error path must guard efi_bs_call(free_pool, priv.runtime_map) with if (!efi_novamap). [F172]
- In handle_cmdline_files(), each iteration opens volume and then file (with efi_open_file() closing fh if get_info fails), closes both handles after reading, and on any mid-iteration allocation or read error unwinds in reverse order (file->close, volume->close, and efi_free(alloc_size, alloc_addr)). [F178]
- In efi_tpm_eventlog_init(), the unsigned table size (tbl_size) passed to memblock_reserve() must not be stored in the signed int variable (final_tbl_size) used to capture the negative error return of tpm2_calc_event_log_size(). [F201]
- In check_var_size(), if __efivars->ops->query_variable_store is NULL or returns EFI_UNSUPPORTED, the function must fall back to returning EFI_SUCCESS when size <= SZ_64K and EFI_OUT_OF_RESOURCES otherwise, rather than propagating EFI_UNSUPPORTED. [F203]
- In efi_adjust_memory_range_protection(), when memattr is non-NULL, errors from both set_memory_attributes and clear_memory_attributes must be returned to the caller, and efi_decompress_kernel() must propagate any non-EFI_SUCCESS status. [F205]
- In tee_stmm_efi.c, callers of tee_client_invoke_func() and tee_client_open_session() must check both the negative Linux return code (rc < 0) and the TEE result field (arg.ret != 0 or sess_arg.ret != 0) to detect communication failures. [F206]
- In get_property_int(), EFI_NOT_FOUND from mm_communicate() indicates that no read-only property is set in StandaloneMM for the variable and must be converted to EFI_SUCCESS with var_property zero-initialized. [F208]
- In allocate_new_fdt_and_exit_boot(), if set_virtual_address_map() fails after efi_exit_boot_services() has succeeded, the stub must set virt_addr = U64_MAX on every EFI_MEMORY_RUNTIME descriptor in priv.boot_memmap->map and still return EFI_SUCCESS. [F218]

## External Contracts

- In `__efi_get_smbios_string()`, the start of the unformatted string table must be computed as `(u8 *)record + record->length` (using the firmware header's `length` byte) and indexed using 1-based string numbers (`for (int i = 1; i < *offset; i++)`), returning `NULL` if an empty string terminator is encountered early. [F246]
- In arm64's `handle_kernel_image()`, the entry alignment check on `_text` must test `IS_ALIGNED((u64)_text, SEGMENT_ALIGN)` rather than `EFI_KIMG_ALIGN`. [F247]
- In `efi_rci2_sysfs_init()`, `rci2_table_global_hdr` must first be mapped to check `RCI_SIGNATURE` (`"_RC_"`) and non-zero `rci2_len`, and after remapping `rci2_table_len` bytes, the 16-bit `checksum()` (including a zero-padded final byte if `rci2_table_len` is odd) must equal 0 before creating the sysfs file. [F250]
- In `tee_stmm_efi.c`, `struct smm_variable_access` stores variable data after `name` at byte offset `(u8 *)var_acc->name + name_size` (with `name_size = (ucs2_strnlen(name, EFI_VAR_NAME_LEN) + 1) * sizeof(u16)`), and `tee_get_next_variable()` must check `out_name_size >= in_name_size` before zeroing `out_name_size - in_name_size` trailing bytes. [F253]
- In `efi_retrieve_tcg2_eventlog()` and `efi_tpm_eventlog_init()`, total TPM log size must be computed as `log_last_entry - log_location + last_entry_size`, where TCG2 `last_entry_size` and `efi_tcg2_final_events_table` entry sizes are decoded via `__calc_tpm2_event_size()` using the first entry at `log_location` (`log_tbl->log`). [F257]
- When storing 64-bit addresses or sizes into split 32-bit `boot_params` or `screen_info` fields (`cmd_line_ptr`, `ramdisk_image`, `ramdisk_size`, `efi_systab`, `efi_memmap`, `lfb_base`), `efi_set_u64_split()` must populate both 32-bit halves and `efi_setup_gop()` must set `VIDEO_CAPABILITY_64BIT_BASE` when `ext_lfb_base` is non-zero. [F259]
- In `zboot-decompress-gzip.c` and `zboot-decompress-zstd.c`, the appended uncompressed size `payload_size` must be declared `u32 __aligned(1)`, the trailing 4-byte size trailer must be excluded from the ZSTD input length (`_gzdata_end - _gzdata_start - 4`), and GZIP must skip the 10-byte header (`_gzdata_start + 10`). [F261]
- In drivers/firmware/efi/libstub/, configuration tables that must persist across kexec/crashkernel boots—such as unaccepted_table in allocate_unaccepted_bitmap() and seed in efi_random_get_seed()—must be allocated from EFI_ACPI_RECLAIM_MEMORY rather than EFI_LOADER_DATA. [F332]

## Known Pitfalls

- Because UEFI allocate_pool returns uninitialized memory, structures allocated via allocate_pool that are only partially populated (such as in __alloc_screen_info(), preserve_pci_rom_image(), efi_retrieve_tcg2_eventlog(), and allocate_unaccepted_bitmap()) must be explicitly zeroed with memset(). [F215]
- In `efi_adjust_memory_range_protection()`, `next = desc.base_address + desc.length` must be computed after `get_memory_space_descriptor` and before the `continue` filter on `desc.gcd_memory_type` and `desc.attributes`, because the `for` loop header relies on `start = next` to advance across skipped descriptors. [F265]
- In `update_fdt()`, existing FDT memory reservation entries must be deleted in reverse index order (`num_rsv = fdt_num_mem_rsv(fdt); while (num_rsv-- > 0) fdt_del_mem_rsv(fdt, num_rsv);`) rather than incrementing from 0 to `num_rsv`, because `fdt_del_mem_rsv()` shifts subsequent entries down. [F273]
- In `system_needs_vamap()`, the `default:` label in `switch (*socid & 0xffff000f)` is intentionally placed before `case 0x0a160001:` and `case 0x0a160002:` so that matching SMBIOS `processor_version` strings (`altra` or `emag`) fall through into the `return true` cases while non-matching strings `break` to `return false`. [F274]
- In `efi_random_alloc()`, `random_seed` must be masked with `U32_MAX` and cast to `u64` before multiplying by `total_slots` and shifting right by 32 (`(total_slots * (u64)(random_seed & U32_MAX)) >> 32`). [F278]
- In `drivers/firmware/efi/libstub/vsprintf.c`, `put_dec()` and `put_dec_helper4()` must format 64-bit `unsigned long long` integers by decomposing into 16-bit chunks and multiplying by the 64-bit reciprocal `0x346DC5D7ULL >> 43` instead of using 64-bit `/` or `%`. [F279]
- In `accept_memory()`, `range_contains_unaccepted_memory()`, and `process_unaccepted_memory()`, `efi_unaccepted_memory::unit_size` (`u32`) must be widened to `u64` before multiplying by bitmap sizes or bit indices to compute 64-bit physical address offsets. [F281]
- In `accept_memory()`, the start bitmap index must be rounded down (`start / unit_size`) while the end bitmap index must use ceiling division (`DIV_ROUND_UP(end, unit_size)`), matching `DIV_ROUND_UP` in `allocate_unaccepted_bitmap()`. [F284]
- In `memrange_efi_to_native()`, `*npages` must be calculated as `PFN_UP(*addr + (*npages << EFI_PAGE_SHIFT)) - PFN_DOWN(*addr)` before `*addr` is aligned down with `*addr &= PAGE_MASK`. [F285]
