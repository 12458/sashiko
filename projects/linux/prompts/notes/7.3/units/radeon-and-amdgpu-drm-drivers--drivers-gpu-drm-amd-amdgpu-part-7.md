# RADEON and AMDGPU DRM DRIVERS — drivers/gpu/drm/amd/amdgpu (part 7)

Implements the GPU Virtual Memory (VM) multi-level page table manager (`amdgpu_vm.c`), usermode queue and fence subsystems (`amdgpu_userq.c`, `amdgpu_userq_fence.c`), SR-IOV GPU virtualization and VF2PF mailbox/telemetry (`amdgpu_virt.c`, `amdgpu_vf_error.c`), multimedia engine managers for UVD, VCE, VCN, and UMSCH (`amdgpu_uvd.c`, `amdgpu_vce.c`, `amdgpu_vcn.c`, `amdgpu_umsch_mm.c`), and Virtual KMS (`amdgpu_vkms.c`).

## Architecture & Data Flow

- Before computing `saddr + (size - 1) / AMDGPU_GPU_PAGE_SIZE` or modifying `vm->va`, VM mapping functions (`amdgpu_vm_bo_map`, `amdgpu_vm_bo_replace_map`, `amdgpu_vm_bo_clear_mappings`) must call `amdgpu_vm_verify_parameters` to reject unaligned addresses, `size == 0`, addition overflow, BO overrun, and PFNs `>= max_pfn`. [F811]
- When unmapping in `amdgpu_vm_bo_unmap` or `amdgpu_vm_bo_del`, a mapping on `bo_va->valids` must have `mapping->bo_va` cleared and move to `vm->freed` for deferred PTE clearing, whereas a mapping still on `bo_va->invalids` is freed immediately via `amdgpu_vm_free_mapping`. [F795]
- `amdgpu_vm_bo_del()` requires `vm->root.bo` and `bo_va->base.bo` to be reserved and must undo `amdgpu_vm_bo_base_init()` and `amdgpu_vm_bo_add()` by clearing `ttm_bo_set_bulk_move(&bo->tbo, NULL)` for always-valid BOs, subtracting `-1` via `amdgpu_vm_update_stats()`, unlinking `bo->vm_bo`, and resetting XGMI pstate if `bo_va->is_xgmi`. [F750]
- In `amdgpu_vm_flush`, when `amdgpu_vmid_had_gpu_reset(adev, id)` is true, `gds_switch_needed`, `vm_flush_needed`, `pasid_mapping_needed`, and `spm_update_needed` must all be forced true, and emitting the VM flush must update `id->current_gpu_reset_count` to `atomic_read(&adev->gpu_reset_counter)` under `id_mgr->lock`. [F807]
- In `amdgpu_vm_generation`, the 64-bit generation token must be constructed by casting `atomic_read(&adev->vram_lost_counter)` to `u64` before shifting left by 32 and adding only `lower_32_bits(vm->generation)` (plus 1 on `drm_sched_entity_error(&vm->delayed)`), never the full 64-bit `vm->generation`. [F843]
- `amdgpu_userq_input_args_validate` must validate `args->in.ip_type < AMDGPU_HW_IP_NUM` before `amdgpu_userq_create` is called, because `amdgpu_userq_create` directly indexes the fixed-size `adev->userq_funcs[args->in.ip_type]` array without re-checking bounds. [F812]
- Usermode queue fences must be initialized with `dma_fence_init64` and compared in `amdgpu_userq_fence_create`, `amdgpu_userq_fence_driver_process`, and `amdgpu_userq_fence_signaled` using full 64-bit unsigned sequence numbers (`rptr < fence->seqno` and `rptr >= wptr`), and fence sequence numbers in `fence_drv->cpu_addr` and queue write pointers in the userq WPTR BO must be read/written as 64-bit little-endian values (`le64_to_cpu` / `cpu_to_le64`). [F816, F848]
- In `amdgpu_virt_pre_reset`, `amdgpu_virt_fini_data_exchange(adev)` must be called to cancel `adev->virt.vf2pf_work` before transitioning MP1 to `PP_MP1_STATE_FLR`. [F876]
- Before `amdgpu_vcn_put_profile` disables `PP_SMC_POWER_PROFILE_VIDEO` and clears `adev->vcn.workload_profile_active` under `adev->vcn.workload_profile_mutex`, it must verify that every VCN instance up to `adev->vcn.num_vcn_inst` has `cur_state == AMD_PG_STATE_GATE`. [F792]
- When `amdgpu_vcnfw_log` is enabled, `amdgpu_vcn_sw_init` places `fw_shared` at `bo_size - fw_shared_size - AMDGPU_VCNFW_LOG_SIZE` inside `vcpu_bo`, so the firmware log buffer is at `vcn->fw_shared.cpu_addr + vcn->fw_shared.mem_size` (and `gpu_addr + mem_size`); in `struct amdgpu_fw_shared`, `struct amdgpu_vcn4_fw_shared`, and `struct amdgpu_vcn5_fw_shared`, `uint32_t present_flag_0` must remain at offset 0 because `amdgpu_vcn_fwlog_init()` casts `vcn->fw_shared.cpu_addr` to `uint32_t *` to set `AMDGPU_VCN_FW_LOGGING_FLAG`. [F819, F860]
- In `amdgpu_vcn_fwlog` and `amdgpu_umsch_fwlog` ring buffers, the header resides in-band at offset 0, so `rptr` and `wptr` must be initialized to and wrap back to `header_size` (not 0), and reads in `amdgpu_debugfs_vcn_fwlog_read` and `amdgpu_debugfs_umsch_fwlog_read` must reject `rptr` or `wptr` exceeding `AMDGPU_*FW_LOG_SIZE` before computing `AMDGPU_*FW_LOG_SIZE - read_pos`. [F820]
- In `amdgpu_vcn_dump_ip_state` and `amdgpu_vcn_print_ip_state`, `adev->vcn.reg_list[0]` must be `mmUVD_POWER_STATUS`, and `reg_list[1 .. reg_count - 1]` must only be read when `(ip_dump[inst_off] & UVD_POWER_STATUS__UVD_POWER_STATUS_TILES_OFF) != UVD_POWER_STATUS__UVD_POWER_STATUS_TILES_OFF`. [F839]
- In `struct amdgpu_umsch_mm`, `struct amdgpu_ring ring` must remain the first member at offset 0 because `umsch_mm_ring_set_wptr()`, `umsch_mm_ring_get_rptr()`, and `umsch_mm_ring_get_wptr()` downcast `struct amdgpu_ring *ring` via `(struct amdgpu_umsch_mm *)ring`. [F859]
- In `amdgpu_uvd_ring_parse_cs` and `amdgpu_uvd_cs_pass2`, a UVD IB must execute a 64-byte-aligned (`offset & 0x3F` check in `amdgpu_uvd_cs_msg`) message command (`cmd == 0`) before any other command so that `ctx->has_msg_cmd` is set and `ctx->buf_sizes` is populated before buffer sizes are checked against `end - start`. [F817]
- In `amdgpu_vce_ring_parse_cs` and `amdgpu_vce_ring_parse_cs_vm`, session handles claimed via `amdgpu_vce_validate_handle` (`allocated` bitmask) must have a matching create command (`created` bitmask), and on exit `adev->vce.handles[i]` must be cleared for `destroyed` slots on success or `allocated` slots on error. Broken by: early `return` on error instead of jumping to `out:`. [F804]

## Synchronization

- `vm->eviction_lock` must always be acquired via `amdgpu_vm_eviction_lock` or `amdgpu_vm_eviction_trylock` and released via `amdgpu_vm_eviction_unlock` so `memalloc_noreclaim_save()` and `memalloc_noreclaim_restore(vm->saved_flags)` bracket the critical section; never call `mutex_lock`/`mutex_unlock` on `vm->eviction_lock` directly. [F767]
- In `amdgpu_vm_update_range()`, a locked update (`!unlocked`) when `vm->last_unlocked` is unsignaled must attach `vm->last_unlocked` to `vm->root.bo` via `amdgpu_bo_fence()` and replace it with a stub fence, and `amdgpu_vm_evictable()` must reject eviction while `vm->last_unlocked` is unsignaled. [F889]
- In `amdgpu_virt_rlcg_reg_rw`, `adev->virt.rlcg_reg_lock` must be held with `spin_lock_irqsave` across programming the RLCG scratch registers (`scratch_reg0`..`scratch_reg3` and `spare_int`), polling `scratch_reg1` for completion, and reading the result from `scratch_reg0`. [F771]
- In `amdgpu_virt.c`, any request that causes the host to populate `virt->fw_reserve.ras_telemetry` (`req_ras_err_count`, `req_ras_cper_dump`, `req_ras_chk_criti`) and the subsequent read/copy of `virt->fw_reserve.ras_telemetry` must be held together under `virt->ras.ras_telemetry_mutex`, while `amdgpu_virt_req_ras_err_count()` and `amdgpu_virt_req_ras_cper_dump()` must acquire `down_read_trylock(&adev->reset_domain->sem)` outside `virt->ras.ras_telemetry_mutex` and skip host telemetry requests if a GPU reset holds `reset_domain->sem`. [F772, F894]

## Object Lifetimes

- In `amdgpu_vm_update_range()`, `amdgpu_vm_tlb_flush()` takes ownership of the heap-allocated `tlb_cb` (freeing it in `amdgpu_vm_tlb_seq_cb()`), so `amdgpu_vm_update_range()` must set `tlb_cb = NULL` after calling `amdgpu_vm_tlb_flush()` before falling through to `error_free: kfree(tlb_cb)`. [F752]
- `amdgpu_virt_release_ras_err_handler_data()` must release all reserved bad-page BOs in `data->bps_bo[0 .. data->last_reserved - 1]` via `amdgpu_virt_ras_release_bp()` before freeing `data->bps_bo`, `data->bps`, and `data`, and must reset `virt->ras_init_done = false` and `virt->virt_eh_data = NULL`. [F754]
- When `adev->vcn.per_inst_fw` is false, `amdgpu_vcn_early_init()` loads firmware once into `adev->vcn.inst[0].fw` and aliases `adev->vcn.inst[i].fw = adev->vcn.inst[0].fw`, so `amdgpu_vcn_sw_fini()` must release `&adev->vcn.inst[0].fw` and assign `adev->vcn.inst[i].fw = NULL` instead of calling `amdgpu_ucode_release(&adev->vcn.inst[i].fw)`. [F744]
- In `amdgpu_vcn_resume()` and `amdgpu_uvd_resume()`, after copying `saved_bo` back to the VCPU BO and calling `kvfree()`, the `saved_bo` pointer (`adev->vcn.inst[i].saved_bo` or `adev->uvd.inst[i].saved_bo`) must be set to `NULL`. [F745]
- `amdgpu_vkms_prepare_fb()` pins `rbo`, binds GART (unpinning `rbo` at `error_unpin` if `amdgpu_ttm_alloc_gart()` fails), unreserves `rbo`, and takes a reference via `amdgpu_bo_ref(rbo)` that must be balanced in `amdgpu_vkms_cleanup_fb()` by reserving `rbo`, calling `amdgpu_bo_unpin(rbo)`, unreserving, and calling `amdgpu_bo_unref(&rbo)`. [F755]

## API Contracts

- In `amdgpu_vm`, `amdgpu_bo_va_mapping->start` and `last` store inclusive GPU page frame numbers (`addr >> AMDGPU_GPU_PAGE_SHIFT` with range size `last - start + 1` pages), and `amdgpu_vm_bo_lookup_mapping` (requiring a hole-masked GPU page number) and `amdgpu_vm_update_range` take `addr`, `start`, and `last` in GPU pages, whereas `amdgpu_vm_bo_map`, `amdgpu_vm_bo_replace_map`, `amdgpu_vm_bo_unmap`, and `amdgpu_vm_bo_clear_mappings` take `saddr`, `offset`, and `size` in bytes. [F787, F810]
- Because `amdgpu_vm_bo_add` allows `bo` to be `NULL` (for PRT or null mappings), code traversing `amdgpu_vm_bo_base` or `amdgpu_bo_va` structures must check `bo != NULL` before dereferencing `bo` (or call `amdgpu_vm_is_bo_always_valid`, which checks `bo` internally). [F789]
- `amdgpu_vm_clear_freed()` must leave the caller's `*fence` unchanged when `vm->freed` is empty or when an error occurs (putting any intermediate `f` via `dma_fence_put(f)`), and only replace `*fence` (after `dma_fence_put(*fence)`) when all freed mappings are cleared without error and `f != NULL`. [F753]
- In `amdgpu_vm_bo_update()` and `amdgpu_vm_clear_freed()`, unmapping (`clear` or freed mappings) must sync to `vm->root.bo->tbo.base.resv` with `AMDGPU_SYNC_EQ_OWNER` before clearing PTEs, whereas mapping (`!clear && bo`) must sync to `bo->tbo.base.resv` with `AMDGPU_SYNC_EXPLICIT` before populating PTEs. [F890]
- `amdgpu_vm_get_task_info_pasid` and `amdgpu_vm_get_task_info_vm` can return `NULL` (when a PASID is not in `adev->vm_manager.pasids` or `vm` is `NULL`), and `amdgpu_vm_print_task_info` dereferences `task_info` unconditionally, so callers must check `task_info != NULL` first. [F790]
- `to_amdgpu_userq_fence` returns `NULL` when `f` is `NULL` or `f->ops != &amdgpu_userq_fence_ops`, so code inspecting generic `dma_fence` pointers (such as `amdgpu_userq_wait_ioctl` on fences from `dma_resv` or `drm_syncobj`) must check for a `NULL` return before accessing `amdgpu_userq_fence` fields. [F779]
- `amdgpu_virt_get_rlcg_reg_access_flag` only writes to `*rlcg_flag` when it returns `true`, so callers must check its boolean return value before passing `rlcg_flag` to `amdgpu_virt_rlcg_reg_rw`. [F786]
- `amdgpu_vce_validate_bo` and `amdgpu_vce_cs_reloc` take the lower-32-bit IB dword index in `lo` before the upper-32-bit IB dword index in `hi`, even though VCE command packets store the upper 32 bits at the lower IB index (`idx + N`) and the lower 32 bits at `idx + N + 1`. [F783]
- In `WREG32_SOC15_DPG_MODE` and `WREG32_SOC24_DPG_MODE` when `indirect` is true, and in `WREG32_SOC15_UMSCH` when `adev->firmware.load_type == AMDGPU_FW_LOAD_PSP`, register writes append `(offset, value)` dword pairs to `dpg_sram_curr_addr` or `cmd_buf_curr_ptr` instead of performing MMIO, requiring callers to reset the pointer to the buffer base before recording and flush via `amdgpu_vcn_psp_update_sram` or `amdgpu_umsch_mm_psp_execute_cmd_buf`. [F870]
- In `DECLARE_ATTR_CAP_CLASS` (`amdgpu_utils.h`), each capability in `enum NAME##_cap_id` uses `AMDGPU_CAP_ATTR_BITS` (2) bits in `bmap` at bit offset `(unsigned int)cap * AMDGPU_CAP_ATTR_BITS`, so `LIST_MACRO` must expand to contiguous zero-based enumerators preceding `NAME##_COUNT` without explicit value gaps. [F862]

## External Contracts

- `amdgpu_userq_create` must check `amdgpu_userq_priority_permit(filp, priority)` before allocating or mapping a queue, rejecting `priority >= AMDGPU_USERQ_CREATE_FLAGS_QUEUE_PRIORITY_HIGH` with `-EACCES` unless `capable(CAP_SYS_NICE)` or `drm_is_current_master(filp)` holds. [F904]
- When computing or verifying a checksum with `amd_sriov_msg_checksum`, the entire structure buffer of `obj_size` bytes must be zero-initialized (`memset`) before populating fields, and `checksum` must pass the current value of the structure's checksum field (or `0` when the field is still `0`). [F785]
- Non-forced SR-IOV host RAS telemetry queries in `amdgpu_virt_req_ras_err_count_internal`, `amdgpu_virt_req_ras_cper_dump`, and `amdgpu_virt_check_vf_critical_region` must be gated by `__ratelimit` on the corresponding `virt->ras` `ratelimit_state` before locking `virt->ras.ras_telemetry_mutex` and calling `virt->ops`. [F907]

## Known Pitfalls

- In `amdgpu_vm_fini`, the `rbtree_postorder_for_each_entry_safe` loop over `&vm->va.rb_root` must not call `amdgpu_vm_it_remove` or `rb_erase` on `mapping` before freeing it. [F829]
- In `amdgpu_vm_bo_unmap`, after searching `bo_va->valids` and `bo_va->invalids` with `list_for_each_entry(mapping, ..., list)`, `&mapping->list == &bo_va->valids` and `&mapping->list == &bo_va->invalids` must be checked before unlinking or dereferencing `mapping`. [F830]
- In `amdgpu_vm_bo_update`, when mapping an imported XGMI BO whose backing `abo->tbo.resource->mem_type == TTM_PL_VRAM`, the local `bo` pointer is reassigned to `abo`, so subsequent resource, `bdev`/`vram_base_offset`, and PTE flag lookups must use `bo` rather than `bo_va->base.bo`. [F831]
- In `amdgpu_vm_adjust_size`, `vm_size` (in GiB) must be widened to `uint64_t` before shifting left by 18 to compute `adev->vm_manager.max_pfn`, and `fls64(tmp) - 1` must be divided using `DIV_ROUND_UP(..., 9)` when computing `adev->vm_manager.num_level`. [F844]
- In `amdgpu_virt_rlcg_reg_rw()`, `reg_access_ctrl` scratch/spare/GRBM offsets and `offset` are dword indices that must be multiplied by 4 when added to `void __iomem *adev->rmmio`, whereas `offset` must remain unscaled in dwords when combined with `flag` and written to `scratch_reg1` (`writel((offset | flag), scratch_reg1)`). [F855]
- In `amdgpu_virt_update_sriov_video_codec`, `encode[i].max_pixels_per_frame / encode[i].max_width` and `decode[i].max_pixels_per_frame / decode[i].max_width` must each be guarded by a `max_width > 0` check even after verifying `adev->virt.is_mm_bw_enabled`. [F847]
- In `amdgpu_vce_cs_reloc`, `index` must be reset to `0` when it equals the `0xffffffff` sentinel before computing the 64-bit product `((uint64_t)size) * ((uint64_t)index)`, and that byte offset must be added before `amdgpu_cs_find_mapping` and subtracted back after converting `addr` to the BO's GPU offset. [F846]
- In `WREG32_SOC15_UMSCH`, `reg_offset` is a dword offset (`adev->reg_offset[VCN_HWIP][0][reg##_BASE_IDX] + reg`), so the `AMDGPU_FW_LOAD_PSP` command-buffer path must shift `reg_offset` left by 2 (`reg_offset << 2`) when writing to `*adev->umsch_mm.cmd_buf_curr_ptr++`, whereas the `else` branch passes unshifted `reg_offset` to `WREG32()`. [F852]
- In `amdgpu_vcn_sw_init`, when `amdgpu_ip_version(adev, UVD_HWIP, 0) == IP_VERSION(3, 0, 2)` (Vangogh) and `DMI_BIOS_VERSION` matches `"F7A0113"` or `"F7A0114"`, `adev->vcn.inst[i].indirect_sram` must be forced to `false`. [F867]
- In `amdgpu_vcn_save_vcpu_bo_inst`, `amdgpu_vcn_resume`, `amdgpu_uvd_prepare_suspend`, `amdgpu_uvd_resume`, and `amdgpu_vce_resume`, `memcpy_fromio` and `memcpy_toio` accesses to the VCPU BO mapping must be guarded by `drm_dev_enter` and `drm_dev_exit`. [F871]
