# BTRFS FILE SYSTEM — fs/btrfs (part 7)

This unit implements Btrfs subvolume quota groups (qgroups and simple quotas / squota, including space reservation, extent tracing, accounting, and async rescan), the RAID stripe tree for mapping logical-to-physical extents on zoned RAID volumes, RAID5/RAID6 parity stripe RMW, recovery, scrubbing, and stripe caching (`raid56.c`), debug extent reference verification (`ref-verify.c`), and file extent cloning/deduplication (`FICLONE`/`FIDEDUPERANGE` in `reflink.c`).

## Architecture & Data Flow
- In `btrfs_qgroup_account_extents()`, if `record->old_roots` is `NULL` and `BTRFS_QGROUP_RUNTIME_FLAG_NO_ACCOUNTING` is not set, `btrfs_find_all_roots()` must be called on the commit root to populate `record->old_roots` before searching the current root and calling `btrfs_qgroup_account_extent()`. In `btrfs_qgroup_account_extent()`, `fs_info->qgroup_seq` must advance by at least `max(nr_old_roots, nr_new_roots) + 1` after `qgroup_update_counters()`, because `btrfs_qgroup_update_old_refcnt()` / `btrfs_qgroup_update_new_refcnt()` lazily reset refcnts only when strictly `< seq`. [F911, F940]
- In `__qgroup_excl_accounting()`, when propagating an exclusive-only child qgroup's counts to ancestors (`sign > 0` or `sign < 0`), each ancestor's `rfer`/`excl` must be adjusted by `src->excl`, `rfer_cmpr`/`excl_cmpr` by `src->excl_cmpr`, and reservations via `qgroup_rsv_add_by_qgroup()` or `qgroup_rsv_release_by_qgroup()`. [F844]
- `__btrfs_qgroup_free_meta()` and `btrfs_qgroup_convert_reserved_meta()` must clamp `@num_bytes` through `sub_root_meta_rsv(root, num_bytes, type)` before calling `btrfs_qgroup_free_refroot()` or `qgroup_convert_meta()`, matching bytes recorded in `root` by `add_root_meta_rsv()` during `btrfs_qgroup_reserve_meta()`. [F847]
- Parent-child qgroup relations require strictly increasing levels: `btrfs_qgroup_level(src) < btrfs_qgroup_level(dst)` in `btrfs_add_qgroup_relation()`, and `btrfs_qgroup_level(qgroupid) > 0` for inherited parents in `btrfs_qgroup_check_inherit()`. [F927]
- In `adjust_slots_upwards()`, `path->nodes[level]` must never be unlocked or freed when `level == root_level`, because the post-loop check reads `path->nodes[root_level]` to test whether `path->slots[root_level]` reached `btrfs_header_nritems()` and stop `btrfs_qgroup_trace_subtree()`. [F942]
- In `fs/btrfs/raid56.c`, `rbio->refs` counts separate references for the creator, `h->hash_list`, and `RBIO_CACHE_BIT` on `table->stripe_cache`. `__remove_rbio_from_cache()` must drop the cache ref via `free_raid_bio()` and, when `bio_list` is empty and `hash_list` is non-empty, also unlink `hash_list` and call `refcount_dec(&rbio->refs)`. Broken by: incrementing `rbio->refs` in `cache_rbio()` when `RBIO_CACHE_BIT` is already set, or unlinking without dropping the ref. [F852]
- When `merge_rbio()` splices `victim->bio_list` into `dest->bio_list` under `dest->bio_list_lock`, it must also add `victim->bio_list_bytes` to `dest->bio_list_bytes` and OR `victim->dbitmap` into `dest->dbitmap`. [F915]
- Because `rbio->error_bitmap` is shared between read recovery and write submission on a `btrfs_raid_bio`, `rmw_rbio()`, `rmw_assemble_write_bios()`, and `finish_parity_scrub()` must clear `rbio->error_bitmap` (`bitmap_clear(rbio->error_bitmap, 0, rbio->nr_sectors)`) before assembling write bios so read-phase errors do not count against write-phase `max_errors`. [F917]
- In `struct btrfs_raid_bio`, `csum_buf` and `csum_bitmap` are sized only for data sectors (`rbio->nr_data * rbio->stripe_nsectors`), unlike `rbio->nr_sectors` arrays (`stripe_sectors`, `bio_sectors`, `error_bitmap`), so callers must verify sector indices are `< rbio->nr_data * rbio->stripe_nsectors` (excluding parity stripes `>= rbio->nr_data`). Furthermore, `dbitmap` and `finish_pbitmap` are single `unsigned long` words, so bitmap/bitops helpers on them must bound `nbits` to `rbio->stripe_nsectors` (`<= BITS_PER_LONG`), never `rbio->nr_sectors`. [F958, F959]
- In `btrfs_build_ref_tree()`, `bytenr`, `num_bytes`, and `tree_block_level` must be maintained across `walk_down_tree()` and `process_leaf()` calls rather than reset per item/leaf, and `BTRFS_EXTENT_ITEM_KEY` in `process_leaf()` must update `*num_bytes` before falling through to `BTRFS_METADATA_ITEM_KEY`. [F950]

## Synchronization
- In `btrfs_quota_enable()` and `btrfs_quota_disable()`, while holding `fs_info->subvol_sem` write-locked, `fs_info->qgroup_ioctl_lock` must be unlocked before calling `btrfs_start_transaction()` or `btrfs_commit_transaction()`. In `btrfs_quota_enable()`, `fs_info->quota_root` and `BTRFS_FS_QUOTA_ENABLED` must only be published (under `fs_info->qgroup_lock`) after `btrfs_commit_transaction()` commits the new quota tree. In `btrfs_quota_disable()`, after unlocking `qgroup_ioctl_lock` and clearing `BTRFS_FS_QUOTA_ENABLED`, the caller must call `btrfs_qgroup_wait_for_completion()` and `flush_reservations()` before starting the disable transaction, restoring `BTRFS_FS_QUOTA_ENABLED` if either fails. [F842, F864, F865]
- In qgroup modification functions (`btrfs_create_qgroup()`, `btrfs_remove_qgroup()`, `btrfs_limit_qgroup()`, `btrfs_add_qgroup_relation()`, and `__del_qgroup_relation()`), `fs_info->quota_root` must be checked under `fs_info->qgroup_ioctl_lock` without short-circuiting on an unlocked `btrfs_qgroup_mode()` check beforehand. [F862]
- When `trans->transaction->state != TRANS_STATE_COMMIT_DOING`, callers of `btrfs_run_qgroups()` must hold `fs_info->qgroup_ioctl_lock`; during `TRANS_STATE_COMMIT_DOING`, `btrfs_qgroup_inherit()` must not acquire `fs_info->qgroup_ioctl_lock`. [F971]
- When destroying a `struct btrfs_qgroup` in `btrfs_remove_qgroup()` or `btrfs_free_qgroup_config()`, the qgroup must be removed from `fs_info->qgroup_tree` (`del_qgroup_rb()`) and its relation lists under `fs_info->qgroup_lock`, and `fs_info->qgroup_lock` must be unlocked before calling `btrfs_sysfs_del_one_qgroup()` and `kfree(qgroup)`. [F843]
- After `btrfs_qgroup_trace_extent_nolock()` inserts a new `btrfs_qgroup_extent_record` into `delayed_refs->dirty_extents` under `xa_lock`, the caller must invoke `btrfs_qgroup_trace_extent_post()` outside spinlock context, which must call `btrfs_find_all_roots(&ctx, true)` with `ctx.trans == NULL` and `skip_commit_root_sem == true`. [F869]
- In `btrfs_qgroup_rescan()`, after `qgroup_rescan_init()` sets `BTRFS_QGROUP_STATUS_FLAG_RESCAN`, the current transaction must be committed before calling `qgroup_rescan_zero_tracking()`, and `btrfs_qgroup_full_accounting(fs_info)` must be rechecked under `fs_info->qgroup_rescan_lock` before queuing `fs_info->qgroup_rescan_work`. [F870]
- In `qgroup_rescan_leaf()`, while holding `fs_info->qgroup_rescan_lock`, `fs_info->qgroup_rescan_progress.objectid` must be updated to one past the last item's `objectid` in `path->nodes[0]` (or `(u64)-1` when done) and `path->nodes[0]` cloned into `scratch_leaf` before releasing `path` and `qgroup_rescan_lock`. [F912]
- In `btrfs_remap_file_range()` (`fs/btrfs/reflink.c`), when `dst_inode == src_inode`, only `btrfs_inode_lock(src_inode, BTRFS_ILOCK_MMAP)` is taken; when `dst_inode != src_inode`, it must acquire `lock_two_nondirectories()` before `btrfs_double_mmap_lock()` (which locks the higher-addressed `btrfs_inode`'s `i_mmap_lock` first) and unlock in reverse order (`btrfs_double_mmap_unlock()`). [F860]

## Object Lifetimes
- In `fs/btrfs/qgroup.c`, `add_qgroup_rb()` and `__add_relation_rb()` (and its wrapper `add_relation_rb()`) unconditionally take ownership of `@prealloc`—either linking it into `fs_info->qgroup_tree` / `member->groups` or freeing it with `kfree()`—so callers must null out their local pointer immediately after the call. [F838]
- `btrfs_qgroup_account_extent()` unconditionally frees both `@old_roots` and `@new_roots` via `ulist_free()` on all exit paths (including when full accounting is disabled or `BTRFS_QGROUP_RUNTIME_FLAG_NO_ACCOUNTING` is set), so callers like `btrfs_qgroup_account_extents()` must set their pointers to `NULL` after the call and no early return in `btrfs_qgroup_account_extent()` may bypass `out_free`. [F840]
- `btrfs_qgroup_release_data()` must be used once data is written and its `FILE_EXTENT` is inserted (clearing `EXTENT_QGROUP_RESERVED` in `inode->io_tree` while keeping `BTRFS_QGROUP_RSV_DATA` until transaction commit), whereas `btrfs_qgroup_free_data()` must be used on page invalidation or error cleanup to also free `BTRFS_QGROUP_RSV_DATA`. [F846]
- When seeding a `struct btrfs_path` at `root_level` with a caller-owned `extent_buffer` in `qgroup_trace_extent_swap()`, `qgroup_trace_subtree_swap()`, or `btrfs_qgroup_trace_subtree()`, `refcount_inc(&eb->refs)` must be called and `path->locks[root_level]` set to `0` so `btrfs_free_path()` drops only the path's reference without unlocking the caller's buffer. [F848]
- In `rbio_orig_end_io()` (`fs/btrfs/raid56.c`), `rbio->csum_buf` and `rbio->csum_bitmap` must be freed and nulled and `rbio->dbitmap` cleared before calling `unlock_stripe(rbio)`, and `rbio->bio_list` must be drained a second time after `unlock_stripe(rbio)` before calling `free_raid_bio(rbio)` to handle bios merged before `unlock_stripe()` completed. [F853]

## API Contracts
- `btrfs_qgroup_trace_extent_nolock()` takes ownership of `@record` only when it returns `0` (storing `@record` into `delayed_refs->dirty_extents`); when it returns `> 0` or `< 0`, the caller retains ownership and must release the xarray slot with `xa_release(&delayed_refs->dirty_extents, index)` and free `@record`. [F839]
- Passing `num_bytes == (u64)-1` to `btrfs_qgroup_free_refroot()` to release all reserved bytes is only valid when `type == BTRFS_QGROUP_RSV_META_PERTRANS`; any other reservation type triggers a `WARN` and returns without freeing space. [F888]
- `btrfs_qgroup_reserve_meta()` (including `_pertrans` / `_prealloc`) and `__btrfs_qgroup_free_meta()` require `@num_bytes` to be a multiple of `fs_info->nodesize` when quotas are enabled on an fstree root, enforcing alignment with `BUG_ON`. [F890]
- `try_flush_qgroup()` must never be called with an open transaction (`current->journal_info != NULL`), and callers of `btrfs_qgroup_reserve_data()` or `__btrfs_qgroup_reserve_meta(..., false)` must not hold any dirty page/folio locked or an open transaction. [F972]
- Before calling `qgroup_trace_new_subtree_blocks()`, the caller must populate `dst_path->nodes[root_level]` with the root extent buffer and ensure `0 <= cur_level <= root_level < BTRFS_MAX_LEVEL - 1`, or the function returns `-EUCLEAN`. [F892]
- In `btrfs_get_raid_extent_offset()`, when the requested `[logical, logical + *length)` range extends beyond the matched `BTRFS_RAID_STRIPE_KEY` item's `found_end`, `*length` must be truncated to `found_end - logical`, and for `BTRFS_BLOCK_GROUP_DUP` profiles stride selection must match `stripe_index == i` in addition to `devid`. [F934]
- In `fs/btrfs/raid56.c`, `lock_stripe_add(rbio)` transfers ownership of `@rbio` when it returns `1` (having either merged and freed `@rbio` via `free_raid_bio()` or queued `@rbio` on `cur->plug_list`), and leaves ownership with the caller to start I/O only when it returns `0`. [F850]
- `alloc_rbio()` returns `ERR_PTR(-ENOMEM)` on allocation failure, whereas `raid56_parity_alloc_scrub_rbio()` translates `IS_ERR(rbio)` from `alloc_rbio()` into `NULL`. [F895]

## Error Handling
- In `qgroup_reserve_data()`, if `qgroup_reserve()` fails after `btrfs_set_record_extent_bits()` has recorded `EXTENT_QGROUP_RESERVED` bits in `inode->io_tree`, `qgroup_unreserve_range()` must revert those bits and subtract their lengths from `reserved->bytes_changed`, and if `*reserved_ret` was allocated by this call (rather than caller-provided), it must be freed and set to `NULL`. [F845]
- In `btrfs_qgroup_cleanup_dropped_subvolume()`, both `-EBUSY` (simple quota subvolume still holds non-zero accounting counts) and `-ENOENT` (qgroup already removed) returned by `btrfs_remove_qgroup()` must be cleared to `0` so callers do not log false cleanup warnings. [F994]
- On error in `btrfs_ref_tree_mod()` and `btrfs_build_ref_tree()` (`ref-verify.c`), `btrfs_free_ref_cache(fs_info)` must be called before `btrfs_clear_opt(fs_info->mount_opt, REF_VERIFY)`, because `btrfs_free_ref_cache()` returns immediately without freeing `fs_info->block_tree` if `REF_VERIFY` is not set. [F900]

## External Contracts
- `btrfs_qgroup_check_inherit()` must validate user-supplied `struct btrfs_qgroup_inherit` buffers by rejecting unknown flags (`-EOPNOTSUPP`), non-zero `num_ref_copies` or `num_excl_copies` (`-EINVAL`), sizes not matching `struct_size(inherit, qgroups, inherit->num_qgroups)` or outside `[sizeof(*inherit), PAGE_SIZE]`, and level-0 qgroup IDs (`-EINVAL`). [F989]
- In `btrfs_limit_qgroup()`, when a limit flag in `limit->flags` is set and the corresponding limit value (`max_rfer`, `max_excl`, `rsv_rfer`, or `rsv_excl`) equals `(u64)-1` (`CLEAR_VALUE`), the kernel must clear that flag from both `qgroup->lim_flags` and `limit->flags` and reset the limit field to `0`. [F990]
- In `qgroup_reserve()`, quota limit checks (`qgroup_check_limits()` returning `-EDQUOT`) are bypassed when `BTRFS_FS_QUOTA_OVERRIDE` is set on `fs_info->flags` and the calling task has `capable(CAP_SYS_RESOURCE)`. [F991]
- Before calling `generic_remap_file_range_prep()`, `btrfs_remap_file_range_prep()` must flush the source mapping via `filemap_flush()` and wait for ordered extents on both source and destination ranges via `btrfs_wait_ordered_range()` so that NOCOW writes reach disk and new file extent items exist in the fs tree. In `btrfs_remap_file_range()`, after unlocking the inodes on a successful non-empty remap, if either `src_file` or `dst_file` satisfies `file_sync_write()` (`__O_SYNC`, `O_DSYNC`, or `IS_SYNC`), `btrfs_sync_file()` must be called on both the source range and the destination range. [F980, F983]

## Known Pitfalls
- The `delayed_refs->dirty_extents` XArray is indexed by sector number (`bytenr >> fs_info->sectorsize_bits`): on 32-bit architectures `btrfs_qgroup_trace_extent_nolock()` must reject `bytenr >= MAX_LFS_FILESIZE` before truncating to an `unsigned long` index, and in `btrfs_qgroup_account_extents()` the `unsigned long` XArray index must be cast to `u64` before left-shifting by `fs_info->sectorsize_bits` to compute `bytenr`. [F928, F952]
- Every function that populates a list with `qgroup_iterator_add()` or `qgroup_iterator_nested_add()` must empty it with `qgroup_iterator_clean()` or `qgroup_iterator_nested_clean()` while holding `fs_info->qgroup_lock`, because the add helpers silently skip any `btrfs_qgroup` whose iterator `list_head` is non-empty. In breadth-first ancestor loops using `list_for_each_entry()` over `btrfs_qgroup.iterator` (such as `__qgroup_excl_accounting()`, `qgroup_update_refcnt()`, `qgroup_reserve()`, and `btrfs_record_squota_delta()`), the loop body must update and walk `groups` on the loop cursor variable rather than an outer pointer to the initial level-0 qgroup. [F938, F939]
- In `qgroup_unreserve_range()`, iteration over `reserved->range_changed.root` must use `rbtree_iterate_from_safe()` so `rb_next(node)` is saved before `ulist_del()` erases and frees the current `ulist_node`. Similarly, in `btrfs_free_ref_tree_range()`, the rbtree cursor `n = rb_next(n)` must be advanced at the start of the `while (n)` loop before both the `continue` branches (when `be->bytenr < start`) and the `rb_erase()` and `free_block_entry(be)` calls. [F943, F951]
- In `copy_inline_to_page()`, the inline extent payload starts at `inline_data + btrfs_file_extent_calc_inline_size(0)` with compressed byte length `size - btrfs_file_extent_calc_inline_size(0)`, and when uncompressed length `datal < fs_info->sectorsize`, the remainder `[datal, block_size)` of the folio must be zeroed via `folio_zero_range()`. [F935]
- In `btrfs_clone()`, `prev_extent_end` must be set to `key.offset + datal` before `datal` is clipped to the `[off, off + len)` clone boundaries, and any item with `key.offset + datal <= prev_extent_end` must advance `path->slots[0]` and jump to `process_slot` so subsequent iterations set `key.offset = prev_extent_end` and make forward progress. [F946]
