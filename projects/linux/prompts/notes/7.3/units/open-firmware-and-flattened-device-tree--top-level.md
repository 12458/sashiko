# OPEN FIRMWARE AND FLATTENED DEVICE TREE — (top level)

This component provides the public kernel header interfaces (`include/linux/of*.h`), Rust device-ID bindings (`rust/kernel/of.rs` and `rust/helpers/of.c`), and the built-in self-test suite (`drivers/of/unittest.c`) for the Open Firmware (OF) and Flattened Device Tree (FDT) subsystem. It defines the core in-memory representation of device tree nodes and properties, iterator macros, address/IRQ/graph/reserved-memory parsing APIs, dynamic reconfiguration changesets and overlays, and compile-time stubs when `CONFIG_OF` options are disabled.

## Architecture & Data Flow
- Under `!CONFIG_OF`, inline stubs in `include/linux/of.h` for `of_property_read_variable_u{8,16,32,64}_array()`, `of_property_read_string_helper()`, `__of_parse_phandle_with_args()`, and `of_phandle_iterator_next()` must return negative errnos rather than `0`, because unconditionally defined inline wrappers and `of_for_each_phandle()` treat `0` as a valid result or continuation. [F220]
- When `attach_node_and_children()` attaches a new `device_node` to the live tree, it must save and clear `np->child` before linking `np` into `np->parent->child` (which overwrites `np->sibling = np->parent->child`), clearing `OF_DETACHED` under `devtree_lock`, and calling `__of_attach_node_sysfs(np)` under `of_mutex`, and only then recursively attach the saved children; any loop walking a sibling list to call `attach_node_and_children()` (including `unittest_data_add()`) must save the next `sibling` pointer before the call. [F212, F239]
- In `update_node_properties()`, `prop->next` must be saved into a local variable before calling `of_add_property(dup, prop)` rather than using `for_each_property_of_node()`, because `of_add_property()` unconditionally sets `prop->next` to `NULL`. [F211]
- Before unflattening an embedded FDT blob in `drivers/of/unittest.c`, `unittest_data_add()` and `unittest_unflatten_overlay_base()` must copy the blob into a buffer aligned to at least `FDT_ALIGN_SIZE` (8 bytes) that remains allocated for the lifetime of the unflattened nodes. Broken by: passing `__dtbo_testcases_begin` or `info->dtbo_begin` directly to `of_fdt_unflatten_tree()` / `__unflatten_device_tree()` without 8-byte alignment, or freeing `unittest_data` / `new_fdt` after unflattening succeeds. [F234]
- In `drivers/of/unittest.c`, the `overlays[]` table must begin with `overlay_base` at index 0 (`expected_result == -9999`) and end with a zeroed `{}` sentinel (`name == NULL`). Overlays intended to remain active across `of_unittest_remove_tracked_overlays()` (as in `of_unittest_overlay_gpio()`) or that test notifier error injection in `of_unittest_overlay_notify()` must be applied via `overlay_data_apply()` directly rather than `of_unittest_apply_overlay()`. [F222, F235]
- Callers that untrack an overlay via `of_unittest_untrack_overlay()` after calling `of_overlay_remove(&ovcs_id)` must save `ovcs_id` beforehand and pass the saved ID in strict LIFO order matching `track_ovcs_id[]`, because `of_overlay_remove()` zeroes `*ovcs_id` on removal. [F214]
- Macros defining `_OF_DECLARE` linker table entries (`_OF_DECLARE`, `_OF_DECLARE_STUB`, `OF_DECLARE_1`, `OF_DECLARE_1_RET`, `OF_DECLARE_2`) must initialize `struct of_device_id.data` via `(fn == (fn_type)NULL) ? fn : fn` rather than assigning `fn` directly or casting to `void *` or `fn_type`, which suppresses compile-time signature verification. [F253]
- `of::DeviceId` must remain a `#[repr(transparent)]` wrapper around `bindings::of_device_id` with no additional field or bit-pattern invariants, because `RawDeviceId` and `Adapter::of_id_info` transmute and cast directly between `DeviceId` and arbitrary C `struct of_device_id` entries. [F258]

## Synchronization
- When splicing nodes or properties directly into the live tree in `attach_node_and_children()` and `of_unittest_overlay_high_level()`, `of_mutex` must be acquired before `raw_spin_lock_irqsave(&devtree_lock, flags)`, and `devtree_lock` must be released before calling `__of_attach_node_sysfs()` while `of_mutex` remains held across every exit path (and unlocked before returning on error). [F187]
- In `of_unittest_overlay_high_level()`, `overlay_base_root` must have phandles resolved via `of_resolve_phandles()` under `of_overlay_mutex_lock()`, `__local_fixups__` and `__symbols__` unlinked, and child `parent` pointers set to `of_root` before taking `of_mutex` to splice `overlay_base_root->child` into `of_root->child` and call `__of_attach_node_sysfs()`, `__of_add_property()`, and `__of_add_property_sysfs()`. [F191]
- Overlay notifier callbacks registered via `of_overlay_notifier_register()` (such as `of_notify()` in `drivers/of/unittest.c`) are invoked on a blocking notifier chain while `of_mutex` (and during apply, `of_overlay_phandle_mutex`) is already held, so they must not acquire `of_mutex` or `of_overlay_mutex_lock()`. Broken by: calling `of_add_property()`, `of_changeset_apply()`, `of_overlay_fdt_apply()`, `of_overlay_remove()`, or `mutex_lock(&of_mutex)` from within `of_notify()`. [F279]

## Object Lifetimes
- `of_find_node_by_name()`, `of_find_node_by_type()`, `of_find_compatible_node()`, `of_find_matching_node_and_match()`, and `of_find_node_with_property()` always call `of_node_put(from)` on a non-NULL `from` argument, so callers keeping `from` must call `of_node_get(from)` first. In `of_notify()`, `of_node_get(nd->overlay)` is acquired before `switch (action)` to balance `of_find_node_by_name(nd->overlay, ...)`, so any `switch` branch or early exit not calling `of_find_node_by_name(nd->overlay, ...)` must call `of_node_put(nd->overlay)`. [F174, F244]
- Scoped node iterator macros (`for_each_child_of_node_scoped`, `for_each_child_of_node_with_prefix`, `for_each_available_child_of_node_scoped`, `for_each_of_graph_port`, and `for_each_of_graph_port_endpoint`) use `__free(device_node)`, so callers must not call `of_node_put(child)` on `break` or `return` and must use `return_ptr(child)` or `no_free_ptr(child)` to keep `child`. [F176]
- Because `of_changeset_action()` takes its own reference on `np` and `of_changeset_create_node()` returns a node with both the creation reference and the changeset's attach reference held (`of_changeset_attach_node()`), callers of `of_changeset_create_node()` must still call `of_node_put(np)` in addition to `of_changeset_destroy(&chgset)`. [F181]
- Callers of `of_parse_phandle()`, `of_parse_phandle_with_args()`, `of_parse_phandle_with_fixed_args()`, `of_parse_phandle_with_optional_args()`, and `of_parse_phandle_with_args_map()` must call `of_node_put()` on the returned `device_node` (or `out_args->np`) when they return success. [F261]
- `of_find_device_by_node()` and `of_find_i2c_device_by_node()` return a `struct platform_device *` or `struct i2c_client *` with its underlying `struct device` reference count incremented, so callers must release non-NULL results with `platform_device_put()` or `put_device(&client->dev)`. [F265]

## API Contracts
- When `CONFIG_OF` is enabled, `struct device_node::_flags` and `struct property::_flags` are `unsigned long` bitmaps accessed and mutated via atomic bitops (`test_bit`, `test_and_set_bit`, `set_bit`, `clear_bit`) through `of_node_*_flag()`, `OF_IS_DYNAMIC()`, `OF_MARK_DYNAMIC()`, and `of_property_*_flag()`, where `OF_DYNAMIC` through `OF_OVERLAY_FREE_CSET` are bit indices rather than shifted masks. Broken by: non-atomic `|=`/`&=` on `_flags`, testing `node->_flags & OF_DYNAMIC`, or passing `BIT(OF_DYNAMIC)` to `of_node_*_flag()`. [F193, F256]
- `of_node_init()` must be called on a newly allocated `struct device_node` before publication so that `node->kobj` is initialized with `of_node_ktype` (setting its initial reference count to one when `CONFIG_OF_KOBJ` is enabled) and `node->fwnode` is initialized with `&of_fwnode_ops`. Downcasting a `struct fwnode_handle *` to `struct device_node *` must use `to_of_node()` (or guard `container_of()` with `is_of_node()`, which checks `!IS_ERR_OR_NULL(fwnode)` and `fwnode->ops == &of_fwnode_ops`). [F194, F251]
- `of_property_read_variable_u{8,16,32,64}_array()` return the positive element count read on success or negative errno on failure, whereas `of_property_read_u{8,16,32,64}_array()` pass `sz_min = sz` and `sz_max = 0` (requiring at least `sz` elements or returning `-EOVERFLOW`, while allowing trailing elements beyond `sz`) and convert non-negative returns to `0`. [F198, F227]
- `of_property_read_u{8,16,32,64}_array()`, `of_property_read_u{8,16,32,64}()`, `of_property_read_u{16,32,64}_index()`, `of_property_read_string()`, and `of_property_read_string_index()` must not modify their output parameter when returning a non-zero error code. [F200]
- `of_property_read_string()`, `of_property_read_string_array()`, and `of_property_read_string_index()` return borrowed `const char *` pointers directly into the property's data buffer (never `kfree()` them), validate NUL termination only up through the requested `index` or `sz` strings without writing past decoded entries of `out_strs` on error (`-ENODATA`, `-EILSEQ`), and return the positive string count for `of_property_read_string_array()` and `of_property_count_strings()` while normalizing non-negative `of_property_read_string_helper()` returns to `0` for single-string helpers. [F179, F199, F228]
- When `of_overlay_remove(&ovcs_id)` fails before or during changeset revert (such as on an `OF_OVERLAY_PRE_REMOVE` notifier error or non-topmost overlay check), the overlay remains applied and `ovcs_id` stays non-zero, whereas on an `OF_OVERLAY_POST_REMOVE` notifier error the changeset is reverted and freed and `ovcs_id` is cleared to `0`. Broken by: retrying `of_overlay_remove(&ovcs_id)` unconditionally on negative return without checking whether `ovcs_id` is `0`, or assuming removal when `ovcs_id` is non-zero. [F183]
- When `of_find_node_opts_by_path()` resolves a path or alias that does not contain a `':'` option delimiter and the caller provides a non-NULL `opts` pointer, `*opts` must be cleared to `NULL` rather than left pointing to its prior value. [F218]
- `__of_get_address()` multiplexes non-PCI and PCI lookups using `-1` as the inactive selector: `of_get_address()` passes a 0-based `index` with `bar_no = -1`, whereas `of_get_pci_address()` passes `index = -1` with a PCI `bar_no`. Broken by: passing both `index >= 0` and `bar_no >= 0`, or passing `0` instead of `-1` for the unused selector. [F226]
- `of_range_count()` computes the entry count via typed `const __be32 *` pointer subtraction `(parser->end - parser->range) / (parser->na + parser->pna + parser->ns)` and must be called before iterating with `for_each_of_range()` or `for_each_of_pci_range()` because `of_pci_range_parser_one()` advances `parser->range`. Broken by: calling `of_range_count()` inside/after a loop expecting the total count, or dividing `parser->end - parser->range` by `sizeof(__be32)`. [F250]
- Any non-NULL `struct of_dev_auxdata` lookup array passed to `of_platform_populate()` or `of_platform_default_populate()` must be terminated with an empty `{}` sentinel entry (`compatible == NULL`). [F230]
- `DeviceId::new` initializes `bindings::of_device_id` via `core::mem::zeroed()` and copies `compatible.to_bytes_with_nul()` into `of.compatible`, requiring all unused `name`, `type`, `compatible`, and `data` bytes to be zeroed and `compatible` (including its NUL terminator) to fit within `of.compatible`. [F260]
- `unittest_unflatten_overlay_base()` runs in early boot before the slab allocator is initialized, so it must allocate memory via `dt_alloc_memory` (`memblock_alloc_or_panic`) and defer `of_resolve_phandles()` (which uses `kmalloc`) until `of_unittest_overlay_high_level()`. [F278]
- Implementations of `struct of_pdt_ops` (used by `of_pdt_build_devicetree()`) must accept a 32-byte `buf` in `nextprop` (returning the first property when `prev` is `NULL` and `0` on success), return `-1` on error from `getproplen` and `getproperty`, return `0` from `getchild` and `getsibling` when no node exists, and set `*len` to the path byte length on `pkg2path` success. [F287]
- In `drivers/of/unittest.c`, `EXPECT_BEGIN()`, `EXPECT_END()`, `EXPECT_NOT_BEGIN()`, and `EXPECT_NOT_END()` must not be used for messages emitted via `pr_debug()`, and nested `EXPECT_BEGIN()` calls must be closed by `EXPECT_END()` in reverse (LIFO) order. [F288]

## Error Handling
- `of_iomap()` returns `NULL` on failure whereas `of_io_request_and_map()` returns an `IOMEM_ERR_PTR`-encoded error pointer and never `NULL`, so callers must test `of_iomap()` with `!ptr` and `of_io_request_and_map()` with `IS_ERR(ptr)`. [F196]
- In `drivers/of/unittest.c`, `overlay_data_apply()` returns `1` on test success and `0` on failure, whereas `of_unittest_apply_overlay()` and `of_unittest_apply_overlay_check()` return `0` on success and a negative errno on failure. When `of_overlay_fdt_apply()` returns a negative error in `overlay_data_apply()`, `of_overlay_remove(&info->ovcs_id)` must still be called to clean up any partially applied overlay changeset and verified against `info->expected_result_remove`. [F208, F215]
- Overlay notifier callbacks registered with `of_overlay_notifier_register()` (such as `of_notify()` in `drivers/of/unittest.c`) must encode negative errnos with `notifier_from_errno(ret)` or return `NOTIFY_DONE` / `NOTIFY_OK`, rather than returning raw negative errno values directly. [F209]
- When resolving platform device interrupts from Device Tree, a missing IRQ domain must return `-EPROBE_DEFER` without logging an error, whereas a malformed or missing DT IRQ specification must return a negative errno other than `-EPROBE_DEFER`. [F290]

## Known Pitfalls
- Converting a potentially `NULL` `struct device_node *` to `struct fwnode_handle *` must use `of_fwnode_handle(node)` rather than `&node->fwnode`, because `fwnode` is at a non-zero offset within `struct device_node` and `&node->fwnode` yields a non-NULL interior offset address when `node` is `NULL`. [F252]
- `_OF_DECLARE()` (and macros built on it such as `OF_DECLARE_1()`, `OF_DECLARE_1_RET()`, `OF_DECLARE_2()`, and `RESERVEDMEM_OF_DECLARE()`) only emits entries into the `"__<table>_of_table"` linker section when `CONFIG_OF` is enabled and `MODULE` is not defined, degrading to an unused local static struct (`_OF_DECLARE_STUB`) in loadable modules. [F270]
- `unittest_path()` and `overlay_name_from_nr()` each format into a function-local `static char buf[256]` and return a pointer to it, so callers must not invoke the same helper twice in one expression or hold its returned pointer across another call to the same helper without copying the string first. [F223]
- In `of_unittest_lifecycle()`, after `/testcase-data/refcount-node`'s refcount is driven to zero, unlinking it from `/testcase-data`'s child list before `of_unittest_check_tree_linkage()` must walk `np->child` and `sibling` pointers directly rather than using `for_each_child_of_node()` so that `of_node_get()` is never called on the zero-refcount node. [F245]
