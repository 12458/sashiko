# INTEL DRM XE DRIVER (Lunar Lake and newer) — drivers/gpu/drm/xe (part 3)

GT management, GGTT allocation, GSC firmware/MEI proxy, and GT-level SR-IOV PF provisioning, control, migration, monitoring, and policy.

## Architecture & Data Flow

- Per-VF and spare GGTT/LMEM allocations (`config->ggtt_region`, `config->lmem_obj`, `spare.ggtt_size`, `spare.lmem_size`) live only on `tile->primary_gt`; `pf_push_full_vf_config()` on a media GT asserts its `config->ggtt_region` is unallocated and reads GGTT config from `gt->tile->primary_gt`. When `xe_device_has_lmtt(xe)`, provisioning or releasing `config->lmem_obj` in `pf_provision_vf_lmem()` or `pf_release_vf_config()` must update and invalidate all tiles' LMTTs via `pf_update_vf_lmtt()` (`pf_force_lmtt_invalidate()`) or `pf_reset_vf_lmtt()`. [F256, F274]
- `gt->sriov.pf.vfs` is indexed by `PFID` (`0`) and `VFID(1..total_vfs)`. VF-only APIs (`xe_gt_sriov_pf_migration_save_guc_state()`, `xe_gt_sriov_pf_config_release()`, `xe_gt_sriov_pf_config_sanitize()`) assert `vfid != PFID`, while `xe_gt_sriov_pf_config_get/set_{ggtt,lmem,ctxs,dbs}()` route `vfid == 0` to `gt->sriov.pf.spare`. `pf_control_state_index()` and `pf_snapshot_index()` recover VFID via `container_of(...) - gt->sriov.pf.vfs`, requiring arguments embedded in `gt->sriov.pf.vfs[0..total_vfs]`. [F255, F333]
- `pf_process_vf_state_machine()` must evaluate VF state bits in priority order: FLR (`XE_GT_SRIOV_STATE_FLR_*`), STOP, PAUSE, then RESUME. Because `xe_gt_sriov_control_state::state` is one `unsigned long` (`XE_GT_SRIOV_STATE_MISMATCH = BITS_PER_LONG - 1`) and `pf_dump_vf_state()` scans `BITS_PER_LONG` bits, all prior `enum xe_gt_sriov_control_bits` values must stay strictly below `BITS_PER_LONG - 1` (`<= 30` on 32-bit). [F298, F339]
- During VF FLR in `xe_gt_sriov_pf_control.c`, before sending `GUC_PF_TRIGGER_VF_FLR_FINISH`, the PF must run `FLR_RESET_CONFIG` (`xe_gt_sriov_pf_config_sanitize()`), `FLR_RESET_DATA` (`xe_sriov_pf_service_reset_vf()` and `xe_gt_sriov_pf_monitor_flr()`), and `FLR_RESET_MMIO` (`xe_gt_sriov_pf_sanitize_hw()`). [F277]
- `do_gt_restart()` must call `xe_gt_apply_ccs_mode(gt)` to reprogram `CCS_MODE` to `gt->ccs_mode`. On SR-IOV PF, `do_gt_restart()` and `gt_init_with_all_forcewake()` must call `xe_gt_sriov_pf_init_hw()` (writing `GUEST_GTT_UPDATE_EN` to `VIRTUAL_CTRL_REG` when `GRAPHICS_VERx100(xe) == 1200`), and `pf_restart()` (from `xe_gt_sriov_pf_restart()`) must call both `xe_gt_sriov_pf_config_restart()` to re-push PF/VF KLVs and `xe_gt_sriov_pf_control_restart()` to cancel the control worker and reset all VFs to READY via `pf_enter_vf_ready()`. [F262, F278, F364]
- Under `pfc->lock`, `pf_worker_find_work()` must unlink `cs->link` with `list_del_init()` and `pf_queue_vf()` must enqueue with `list_move_tail()`, while `pf_worker_find_work()` must re-queue via `pf_queue_control_worker(gt)` whenever `more` or `!empty` holds. [F301]
- In `xe_gt_mcr.c`, `rw_with_mcr_steering()` must keep `MCR_MULTICAST` set in `steer_reg` (`MTL_MCR_SELECTOR` or `MCR_SELECTOR`) during `MCR_OP_READ` and restore `MCR_MULTICAST` after any unicast `MCR_OP_WRITE`, as `xe_gt_mcr_multicast_write()` relies on `MCR_MULTICAST` being set under `mcr_lock(gt)`. [F347]
- Every `struct xe_mmio_range` table in `gt->steering[].ranges` must end with a `{}` sentinel for `xe_gt_mcr_get_nonterminated_steering()` and `xe_gt_mcr_steering_dump()`. Because `xe_steering_types[LNCF].init` is `NULL` and `init_steering_mslice()` populates `gt->steering[LNCF]`, setting `gt->steering[LNCF].ranges` in `xe_gt_mcr_init_early()` requires also setting `gt->steering[MSLICE].ranges`. In `dss_per_group()`, both `max_slices` and `max_subslices` must be verified non-zero before returning `DIV_ROUND_UP(max_subslices, max_slices)` for `xe_gt_mcr_get_dss_steering()`. [F268, F284, F323]
- In `xe_gt_mcr_init_early()` and `pick_runtime_regs()`, `if / else if` chains comparing `GRAPHICS_VER`, `GRAPHICS_VERx100`, `MEDIA_VER`, or `MEDIA_VERx100` with `>=` must be ordered from highest version threshold to lowest. [F296]
- In `xe_ggtt_invalidate()`, an MMIO read of `VF_CAP_REG` on the root tile must precede `ggtt_invalidate_gt_tlb()` on both `ggtt->tile->primary_gt` and `ggtt->tile->media_gt` to flush posted PTE `writeq()`s. When `XE_GGTT_FLAGS_64K` is set, VRAM BOs in `__xe_ggtt_insert_bo_at()` and VF GGTT regions in `pf_get_ggtt_alignment()` must be `SZ_64K`-aligned, while `xe_ggtt_init()` must allocate `ggtt->scratch` with `XE_BO_FLAG_SYSTEM`. [F286, F369]
- GSC exists only on the root tile's media GT: in `xe_gsc_init()`, if `tile->media_gt` exists and `gt != tile->media_gt`, set `gsc->fw` status to `XE_UC_FIRMWARE_NOT_SUPPORTED` and return `0`; `xe_gsc_proxy_init()` must reject non-root tiles (`!xe_tile_is_root(tile)`). Before uploading FW in `gsc_upload()`, set `xe->needs_flr_on_fini = true` so driver unload triggers FLR before freeing `gsc->private`. When `gsc->fw` is loadable and not in error, `xe_gsc_stop_prepare()` must assert `XE_FW_GSC` forcewake and call `xe_gsc_wait_for_proxy_init_done(gsc)`. [F355, F356, F357]
- In `proxy_channel_alloc()`, `gsc->proxy.to_csme` and `gsc->proxy.from_csme` split one `GSC_PROXY_CHANNEL_SIZE` buffer into two `GSC_PROXY_BUFFER_SIZE` (32 KiB) halves (like `to_gsc`/`from_gsc` in `gsc->proxy.bo`), so `from_csme` must not be freed separately and writes to `to_csme` must not exceed `GSC_PROXY_BUFFER_SIZE`. [F334]
- In `proxy_query()`, each loop iteration must call `xe_gsc_poison_header()` on `gsc->proxy.from_gsc` before `proxy_send_to_gsc(gsc, size)`, validate GSC and CSME headers via `validate_proxy_header()` against `max_size = GSC_PROXY_BUFFER_SIZE - reply_offset` (rejecting `length + PROXY_HDR_SIZE > max_size`), break on `GSC_PROXY_MSG_TYPE_PROXY_END`, verify CSME reply `size >= PROXY_HDR_SIZE` before copying, and update `size += wr_offset`. [F249, F281, F308]
- In `xe_gsc_read_out_header()`, `size < GSC_HDR_SIZE` must be checked alongside `payload_size < min_payload_size` after verifying `validity_marker` and `status`, because `u32 payload_size = size - GSC_HDR_SIZE` wraps when `size < GSC_HDR_SIZE`. [F280]
- `pf_process_runtime_query_msg()` must clamp VF `limit` to `max_chunks = (resp_size - VF2PF_QUERY_RUNTIME_RESPONSE_MSG_MIN_LEN) / hxg_sizeof(struct reg_data)`, and `pf_service_runtime_query()` must reject `start > runtime->size` with `-ERANGE` before subtracting `runtime->size - start`. [F289]
- In `struct xe_gpu_scheduler`, `struct drm_gpu_scheduler base` must be the first member because `xe_sched_entity_init()` casts `&sched` (`struct xe_gpu_scheduler **`) to `struct drm_gpu_scheduler **`. [F335]

## Synchronization

- In `xe_gpu_scheduler`, `sched->msgs` is protected by `sched->base.job_list_lock` (`xe_sched_msg_lock()`/`xe_sched_msg_unlock()`), and `xe_sched_process_msg_work()` must drop that lock via `xe_sched_get_msg()` before calling `sched->ops->process_msg(msg)`. `xe_sched_submission_stop()` must call `drm_sched_wqueue_stop(&sched->base)` (setting `pause_submit`) before `cancel_work_sync(&sched->work_process_msg)` because `xe_sched_process_msg_work()` and `xe_sched_process_msg_queue()` re-queue `work_process_msg` whenever `!READ_ONCE(sched->base.pause_submit)`. [F231, F380]
- `gsc->lock` protects `gsc->work_actions` and is taken in IRQ handlers (`xe_gsc_hwe_irq_handler()`, `xe_gsc_proxy_irq_handler()`), so process/worker contexts (`gsc_work()`, `xe_gsc_load_start()`) must use `spin_lock_irq()`/`spin_lock_irqsave()`. In `xe_gsc_proxy_request_handler()`, after polling `gsc->proxy.component`, `gsc->proxy.mutex` must be held and `gsc->proxy.component != NULL` rechecked across `proxy_query()`. [F233, F235]
- In VF control (`pf_enter_vf_{pause,resume,stop,flr}_wip()`), `pf_enter_vf_wip()` (`reinit_completion(&cs->done)`) must be called before queuing VF work via `pf_enter_vf_*_send_*()`. In `pf_exit_vf_pause_send_pause()` and `pf_exit_vf_flr_send_start()`, the PF must enter `XE_GT_SRIOV_STATE_{PAUSE,FLR}_WAIT_GUC` before sending the H2G command (and exit on failure) because GuC G2H DONE notifications can arrive before the H2G response. [F241, F276]
- `xe_gt_sriov_pf_master_mutex(gt)` (`&xe->sriov.pf.master_lock`) nests outside `&ggtt->lock` and BO `dma_resv` locks (`xe_bo_lock()`); never acquire `master_lock` while holding `&ggtt->lock` or a BO lock. [F382]
- In `xe_gt_idle.c`, `gtidle->lock` is a `raw_spinlock_t` acquired with `raw_spin_lock_irqsave()` in `xe_gt_idle_residency_msec()`; neither `get_residency_ms()` nor `gtidle->idle_residency(pc)` may sleep or take non-raw locks. [F376]

## Object Lifetimes

- In `pf_provision_vf_{ggtt,ctxs,dbs,lmem}()`, re-provisioning an allocated VF resource must first push a zeroed config to GuC and only on success free the host resource and clear `struct xe_gt_sriov_config` fields; if pushing the new quota KLV fails, all newly reserved host resources (GGTT node, ctx/db IDs, LMTT pages, `config->lmem_obj`) must be released in reverse order and `config` cleared. [F220, F221]
- `pf_queue_restart()` gets a runtime PM ref via `xe_pm_runtime_get_noresume()` for `gt->sriov.pf.workers.restart`, dropping it if `queue_work()` fails; otherwise it must be put by `pf_restart()`, or by `pf_cancel_restart()` / `pf_fini_workers()` when `cancel_work_sync()` / `disable_work_sync()` returns true. [F219]
- In `pf_sanitize_lmem()`, `xe_bo_lock(bo, false)` and `xe_bo_unlock(bo)` must bracket `xe_migrate_clear()`, and any valid returned `struct dma_fence *` must be released with `dma_fence_put(fence)` after `dma_fence_wait_timeout()` before unlocking `bo`. [F224]
- `xe_gsc_proxy_init()` must check `IS_ENABLED(CONFIG_INTEL_MEI_GSC_PROXY)` and `xe_tile_is_root(tile)` before registering `xe_gsc_proxy_component_ops` (`I915_COMPONENT_GSC_PROXY`). `xe_gsc_proxy_remove()` must disable HECI2 IRQs (`gsc_proxy_irq_toggle(gsc, false)`) and flush `gsc->work` (`xe_gsc_wait_for_worker_completion(gsc)`) before `component_del()`, and `xe_gsc_proxy_component_unbind()` must flush `gsc->work` before clearing `gsc->proxy.component` under `gsc->proxy.mutex`. [F359, F387]
- In `xe_gt_record_default_lrcs()`, temporary queues `q` and `nop_q` from `xe_exec_queue_create()` must be released in reverse order (`xe_exec_queue_put(nop_q)` then `xe_exec_queue_put(q)`) on all paths. [F214]

## API Contracts

- MCR accessors (`xe_gt_mcr_unicast_read_any()`, `xe_gt_mcr_unicast_read()`, `xe_gt_mcr_unicast_write()`, `xe_gt_mcr_multicast_write()`) assert `!IS_SRIOV_VF(gt_to_xe(gt))` and must not be called on VFs where `gt->steering` is uninitialized. [F252]
- `xe_ggtt_set_pte()` and `xe_ggtt_read_pte()` index `ggtt->gsm` by `addr >> XE_PTE_SHIFT`, requiring a page-aligned byte offset `< ggtt->size`. [F285]
- `xe_gsc_emit_header()` requires `host_session_id` bits 63:56 (`HOST_SESSION_CLIENT_MASK`, cleared by `xe_gsc_create_host_session_id()`) to be zeroed for `heci_client_id` encoding, and returns the next byte offset (`offset + GSC_HDR_SIZE`), not a status code. [F248]
- `pf_estimate_fair_ggtt()` and `pf_estimate_fair_lmem()` must assert `num_vfs != 0` and compute quotas via `div_u64(available, num_vfs)` followed by `ALIGN_DOWN(fair, alignment)`. [F324]
- `xe_gt_sriov_pf_config_save()` and `xe_gt_sriov_pf_config_restore()` use byte sizes while `encode_config()` and `pf_restore_vf_config()` use `u32` dwords: save must multiply by `sizeof(u32)`, restore must reject `size % sizeof(u32) != 0`, and `pf_restore_vf_config()` must verify `num_dwords >= GUC_KLV_LEN_MIN` and `num_dwords >= len` before reading `value[]` or calling `make_u64_from_u32(value[1], value[0])`. [F290, F331]
- Sysfs callbacks under child kobjects of `gt->sysfs` (`freq0`, `gtidle`) must pass `kobj->parent` to `kobj_to_gt()`, whereas attributes directly on `gt->sysfs` (`xe_gt_ccs_mode.c`) must pass `&kdev->kobj`. In `xe_gt_sriov_pf_debugfs.c`, `extract_gt()` and `extract_vfid()` expect the `pf`/`vfN` directory `dentry`, so `debugfs_create_file_unsafe()` callers must pass `parent` as `data` and raw `file_operations` must pass `file_dentry(file)->d_parent`. [F336, F390]

## Error Handling

- In `xe_ggtt_init()`, if `xe_managed_bo_create_pin_map()` returns an `ERR_PTR`, `ggtt->scratch` must be reset to `NULL` because `xe_ggtt_clear()` checks `if (ggtt->scratch)`. [F246]
- `pf_send_vf_buf_klvs()` and `pf_send_policy_klvs()` return the parsed KLV count or negative errno; `pf_push_vf_buf_klvs()` and `pf_push_policy_buf_klvs()` must check `ret != num_klvs` and map `0 <= ret < num_klvs` to `-ENOKEY` and `ret > num_klvs` to `-EPROTO`. [F258]

## External Contracts

- SR-IOV PF GuC HXG handlers (`pf_process_handshake_msg()`, `xe_gt_sriov_pf_monitor_process_guc2pf()`, `xe_gt_sriov_pf_control_process_guc2pf()`) must verify message dword length and that the header MBZ field is `0` (returning `-EPFNOSUPPORT` otherwise) before reading `msg[1..2]`. [F294]
- Debugfs write handlers `config_blob_write()` and `guc_state_write()` must reject `*pos != 0`, empty payloads (`-ENODATA`), `size % sizeof(u32) != 0` (`-EINVAL`), and oversized blobs (`count > SZ_4K` for `config_blob`, `size > SZ_2M` for `guc_state`). [F392]

## Known Pitfalls

- In `xe_gt_record_default_lrcs()`, after `emit_wa_job(gt, q)`, a second queue `nop_q` on the same engine must run `emit_nop_job(gt, nop_q)` to switch context before copying `q->lrc[0]->bo->vmap` into `gt->default_lrc[hwe->class]`. [F271]
- On non-VF devices, `do_gt_reset()` must bracket writing `GRDOM_FULL` to `GDRST` and waiting for clear with `xe_gsc_wa_14015076503(gt, true)` and `xe_gsc_wa_14015076503(gt, false)`. [F345]
- In `validate_proxy_header()`, `case GSC_PROXY_MSG_TYPE_PROXY_PAYLOAD:` must only `break` when `length > 0` and otherwise fall through to `GSC_PROXY_MSG_TYPE_PROXY_INVALID` (`-EIO`). [F299]
- In `get_pagefault()`, `FIELD_GET(PFD_VIRTUAL_ADDR_HI, desc->dw3)` must be cast to `u64` before shifting left by `PFD_VIRTUAL_ADDR_HI_SHIFT` (32). In `__xe_gt_apply_ccs_mode()`, `CCS_MODE_CSLICE_0_3_MASK << 16` must be ORed into `mode` for Xe2+ hardware. [F316, F361]
