# AMD POWERPLAY AND SWSMU — drivers/gpu/drm/amd/pm (part 1)

This component provides the core Dynamic Power Management (DPM) dispatch layer, user-space telemetry/control interfaces (sysfs, hwmon, and debugfs), and the legacy DPM implementation (including Kaveri/Kabini SMU7 fusion support) for the AMDGPU driver. It mediates clock, voltage, fan, thermal, and power-gating state transitions between the DRM/display subsystems, user-space tools, VBIOS AtomBIOS tables, and underlying power management backends (legacy DPM, PowerPlay, and SWSMU).

## Architecture & Data Flow

- Before casting `adev->powerplay.pp_handle` to `struct smu_context *`, functions in `amdgpu_dpm.c` must verify `is_support_sw_smu(adev)`; before casting it to `struct pp_hwmgr *`, they must verify both `!is_support_sw_smu(adev)` and `!amdgpu_dpm_is_legacy_dpm(adev)`. [F256]
- In `amdgpu_dpm_change_power_state_locked()`, `adev->pm.dpm.state` is synced from `user_state` only when both `thermal_active` and `uvd_active` are false; when `thermal_active` is true, `adev->pm.dpm.forced_level` must be saved before calling `pp_funcs->force_performance_level(adev, AMD_DPM_FORCED_LEVEL_LOW)` and restored afterward. [F154, F188]
- In `amdgpu_dpm_pick_power_state()`, `restart_search:` must stay below the initial `POWER_STATE_TYPE_PERFORMANCE` to `POWER_STATE_TYPE_INTERNAL_3DPERF` rewrite, and the fallback `switch` must not jump to `restart_search` on `POWER_STATE_TYPE_PERFORMANCE`. [F221]
- In `amdgpu_dpm_get_display_cfg()`, `adev->pm.pm_display_cfg.displays[]` must be densely populated with only enabled CRTCs (indexed by `num_crtcs++`, with `cfg->num_display = num_crtcs`), and `amdgpu_crtc->hw_mode.clock` must be verified non-zero before dividing `vblank_in_pixels * 1000` by it. [F200, F231]
- In `amdgpu_set_pp_od_clk_voltage()` and `amdgpu_distribute_custom_od_settings()`, committing OverDrive changes (`PP_OD_COMMIT_DPM_TABLE`) via `amdgpu_dpm_odn_edit_dpm_table()` must be followed by `amdgpu_dpm_dispatch_task(adev, AMD_PP_TASK_READJUST_POWER_STATE, NULL)`. [F194]
- In `amdgpu_od_set_init()`, if no OverDrive sub-features or containers are supported (leaving `adev->pm.od_kobj_list` singular with only `top_set`), it must call `amdgpu_od_set_fini()` to remove the empty `gpu_od` directory. [F258]
- In `amdgpu_read_mask()`, each parsed clock level must be validated (`ret || level > 31` returns `-EINVAL`) before shifting `1 << level` into the `uint32_t` bitmask. [F214]
- In `amdgpu_parse_extended_power_table()`, reading sub-tables from `power_info->pplib3`, `pplib4`, or `pplib5` requires verifying `le16_to_cpu(power_info->pplib.usTableSize) >= sizeof(struct _ATOM_PPLIB_POWERPLAYTABLE3/4/5)` and a non-zero sub-table offset; `adev->pm.dpm.num_of_vce_states` must be clamped to `AMD_MAX_VCE_LEVELS`, and `amdgpu_get_vce_clock_state()` must check `idx < num_of_vce_states`. [F205, F207]
- In `struct amdgpu_cac_leakage_table`, the active variant of each `union amdgpu_cac_leakage_entry` is selected by `adev->pm.dpm.platform_caps & ATOM_PP_PLATFORM_CAP_EVV` (`vddc1`/`vddc2`/`vddc3` when set, `vddc`/`leakage` when clear). [F180]
- In `kv_dpm_init()`, `kv_construct_boot_state()` must run before `kv_parse_power_table()`, and within `kv_parse_power_table()`, `kv_parse_pplib_non_clock_info()` must run after the `kv_parse_pplib_clock_info()` loop for each state. [F225]
- `kv_update_current_ps()` and `kv_update_requested_ps()` must copy both `*rps` into `pi->current_rps`/`requested_rps` and `*kv_get_ps(rps)` into `pi->current_ps`/`requested_ps`, then rebind `ps_priv` to `&pi->current_ps`/`&pi->requested_ps` and `adev->pm.dpm.current_ps`/`requested_ps` to `&pi->current_rps`/`&pi->requested_rps`. [F243]
- In `kv_dpm_enable()`, `kv_process_firmware_header()` must run before any function that uploads DPM tables to SMU SRAM (populating `pi->dpm_table_start` and `pi->soft_regs_start`), and `kv_set_thermal_temperature_range()` must program `ixCG_THERMAL_INT_CTRL` thresholds before `amdgpu_irq_get()` unmasks `AMDGPU_THERMAL_IRQ_LOW_TO_HIGH` and `AMDGPU_THERMAL_IRQ_HIGH_TO_LOW` (guarded by `kv_is_internal_thermal_sensor()`). [F248, F249]
- `kv_dpm_suspend()` must cancel `thermal.work`, disable DPM, and reset `current_ps` and `requested_ps` to `boot_ps` (without clearing `user_state`/`forced_level`) so `kv_dpm_resume()` can re-run `kv_dpm_setup_asic()`, `kv_dpm_enable()`, and `amdgpu_legacy_dpm_compute_clocks()` to transition from `boot_ps` back to `user_state`. [F197]
- In `kv_enable_didt()`, `amdgpu_gfx_rlc_enter_safe_mode(adev, 0)` must be called before programming `didt_config_kv` or calling `kv_do_enable_didt()`, and `amdgpu_gfx_rlc_exit_safe_mode(adev, 0)` must be called on all return paths. [F196]
- In `kv_dpm.c`, `adev->pm.dpm.dyn_state.vddc_dependency_on_sclk` is optional (`count == 0` when absent), so consumers must check `table && table->count` and fall back to `pi->sys_info.sclk_voltage_mapping_table` or `pi->sys_info.vid_mapping_table`. [F182]
- In `kv_dpm.c`, `pi->lowest_valid` and `pi->highest_valid` form an inclusive 0-based index range `[lowest_valid, highest_valid]` into `pi->graphics_level`; `kv_calculate_ds_divider()`, `kv_calculate_nbps_level_settings()`, and `kv_calculate_dpm_settings()` must reject `pi->lowest_valid > pi->highest_valid` with `-EINVAL`. [F209]
- Tables passed to `kv_program_pt_config_registers()` (like `didt_config_kv`) must end with a `{ 0xFFFFFFFF }` offset sentinel, and clock-gating tables iterated by `amdgpu_parse_cg_state()` (`clocks[]`) must end with a `flag == 0` (`{ 0, NULL }`) sentinel. [F211]

## Synchronization

- `amdgpu_set_power_dpm_force_performance_level()` must hold `adev->pm.stable_pstate_ctx_lock` across `amdgpu_dpm_force_performance_level()` (enforcing lock order `stable_pstate_ctx_lock -> adev->pm.mutex`) and set `adev->pm.stable_pstate_ctx = NULL` on success. [F153]
- `amdgpu_dpm_compute_clocks()` must update display bandwidth (when `num_crtc != 0`) and wait for all ready rings via `amdgpu_fence_wait_empty()` before acquiring `adev->pm.mutex` and calling `pp_funcs->pm_compute_clocks`; `amdgpu_dpm_compute_clocks()` must be called with `adev->pm.mutex` unlocked, whereas `amdgpu_legacy_dpm_compute_clocks()` and `amdgpu_dpm_change_power_state_locked()` require `adev->pm.mutex` held. [F253, F266]
- When looking up a peer APU in `mgpu_info.gpu_ins` (e.g., `amdgpu_show_powershift_percent()`), `mgpu_info.mutex` must be held while iterating `mgpu_info.gpu_ins` and released before calling `amdgpu_pm_get_sensor_generic()` on the target `adev`. [F164]
- `kv_dpm_sw_init()` must initialize `adev->pm.dpm.thermal.work`, allocate `adev->pm.dpm.priv` and `adev->pm.dpm.ps`, and set `current_ps`, `requested_ps`, and `boot_ps` before `kv_dpm_hw_init()` enables thermal IRQs via `amdgpu_irq_get()` and sets `adev->pm.dpm_enabled = true`. [F162]
- `adev->pm.dpm.thermal.work` (`amdgpu_dpm_thermal_work_handler`) must be drained via `cancel_work_sync()` in `kv_dpm_suspend()` and `flush_work()` in `kv_dpm_sw_fini()` without holding `adev->pm.mutex`, and before `kv_dpm_fini()` frees `adev->pm.dpm.ps` and `adev->pm.dpm.priv`. [F161]
- `kv_dpm_process_interrupt()` runs in IRQ context and must only update `adev->pm.dpm.thermal.high_to_low` and schedule `adev->pm.dpm.thermal.work` without sleeping or taking `adev->pm.mutex`; `kv_dpm_set_interrupt_state()` runs in atomic context under `adev->irq.lock` and must only use IRQ-safe `RREG32_SMC`/`WREG32_SMC`. [F264, F272]

## Object Lifetimes

- Each `struct od_kobj` on `adev->pm.od_kobj_list` is freed by `od_kobj_release()` when `kobject_put(&container->kobj)` drops its last reference in `amdgpu_od_set_fini()`; teardown must call `sysfs_remove_file()` and `kfree()` on every `struct od_attribute` in `container->attribute` before `kobject_put()`, and must never `kfree(container)` directly after `kobject_init_and_add()`. [F147]
- Because `amdgpu_parse_extended_power_table()` returns on allocation failure without internal rollback, every table it allocates in `adev->pm.dpm.dyn_state` must be freed in `amdgpu_free_extended_power_table()`, and callers such as `kv_dpm_init()` / `kv_dpm_sw_init()` must invoke `kv_dpm_fini()` / `amdgpu_free_extended_power_table()` on failure. [F149]
- In `kv_dpm_powergate_uvd()` and `kv_dpm_powergate_vce()`, gating (`gate == true`) must gate the IP block via `amdgpu_device_ip_set_powergating_state()`, disable block DPM, and then send `PPSMC_MSG_UVDPowerOFF`/`PPSMC_MSG_VCEPowerOFF`; ungating (`gate == false`) must reverse the sequence by powering on via SMU, enabling block DPM, and then ungating the IP block. [F156]

## API Contracts

- Every `amdgpu_dpm_enable_*` helper delegating to `amdgpu_dpm_set_powergating_by_smu()` (and `kv_update_uvd_dpm()`, `kv_update_samu_dpm()`, `kv_update_acp_dpm()` when calling `kv_enable_*_dpm()`) must invert the boolean argument (`!enable` or `!gate`). [F220]
- Despite its declared `enum pp_smu_status` return type, `amdgpu_dpm_get_uclk_dpm_states()` returns `0` on success or a negative errno (`-EOPNOTSUPP`); callers must capture the return value in a signed `int` before translating to `PP_SMU_RESULT_*`. [F168]
- `amdgpu_dpm_is_baco_supported()` must return `0` whenever `adev->in_s3` is true, even if `pp_funcs->get_asic_baco_capability` is implemented. [F257]
- `kv_dpm_read_sensor()` requires `*size >= 4` on entry (returning `-EINVAL` otherwise) before writing `*(uint32_t *)value` and setting `*size = 4`; callers of `amdgpu_dpm_read_sensor()` or `pp_funcs->read_sensor` must initialize `*size` to the buffer capacity (`>= 4`) beforehand. [F237]
- `amdgpu_dpm_get_temp_metrics()` returns the metrics byte size when `table == NULL`; sysfs callers (`amdgpu_get_baseboard_temp_metrics()`, `amdgpu_get_gpuboard_temp_metrics()`) must first query `size` with `NULL` and verify `size > 0 && size < PAGE_SIZE` before passing `buf`. [F238]
- When an `amdgpu_device_attr` `.attr_update` callback (`pp_dpm_dcefclk_attr_update()`, `pp_dpm_clk_default_attr_update()`, `default_attr_update()`) downgrades an attribute to read-only, it must both clear write bits (`S_IWUGO`/`S_IWUSR`) in `dev_attr->attr.mode` and set `dev_attr->store = NULL`. [F284]
- `amdgpu_hwmon_show_power_cap_generic()` and `amdgpu_hwmon_set_power_cap()` convert between hwmon microWatts and DPM Watts (factor of 1,000,000), and `amdgpu_hwmon_set_power_cap()` packs `enum pp_power_type` into bits `[31:24]` (`limit_type << 24`) of the `uint32_t` passed to `amdgpu_dpm_set_power_limit()`. [F280]
- `amdgpu_kv_read_smc_sram_dword()` requires 4-byte alignment (`(smc_address & 3) == 0`) and `smc_address + 3 <= limit`, whereas `amdgpu_kv_copy_bytes_to_smc()` accepts unaligned offsets and lengths within `limit` by performing read-modify-write on 4-byte-aligned big-endian dwords at `mmSMC_IND_DATA_0` to preserve adjacent bytes in `SMU7_Fusion_DpmTable`. [F181, F198]
- In `amdgpu_kv_send_msg_to_smc_with_parameter()` and `amdgpu_kv_notify_message_to_smu()`, `mmSMC_MSG_ARG_0` must be written before `mmSMC_MESSAGE_0` triggers the command, and `mmSMC_RESP_0` must be polled with a bounded timeout of `adev->usec_timeout` microseconds. [F261]

## Error Handling

- In `amdgpu_dpm_force_performance_level()`, transitions via `amdgpu_dpm_enter_umd_state()` and `amdgpu_dpm_exit_umd_state()` must run outside `adev->pm.mutex`, and if `pp_funcs->force_performance_level()` fails, the function must unlock `adev->pm.mutex` and call the inverse helper to roll back the UMD state. [F152]

## External Contracts

- Kaveri SMU7 SRAM is big-endian: multi-byte fields in `SMU7_Fusion_DpmTable` must be byte-swapped with `cpu_to_be16()`/`cpu_to_be32()` before `amdgpu_kv_copy_bytes_to_smc()` and converted back with `be32_to_cpu()` when read by the CPU (e.g., `graphics_level[].SclkFrequency`). [F273]
- In `amdgpu_set_pp_force_state()`, user index `idx` must be bounds-checked against `ARRAY_SIZE(data.states)`, clamped with `array_index_nospec()`, and dispatched via `AMD_PP_TASK_ENABLE_USER_STATE` only when the resolved state is neither `POWER_STATE_TYPE_INTERNAL_BOOT` nor `POWER_STATE_TYPE_DEFAULT`. [F278]
- In `amdgpu_pm.c`, `AMDGPU_PP_SENSOR_GFX_SCLK`/`MCLK` return 10 kHz units (`* 10000` for Hz in hwmon `freq[1-2]_input`, `/ 100` for MHz in debugfs), and `AMDGPU_PP_SENSOR_GPU_AVG_POWER`/`INPUT_POWER` return 8-bit fixed-point Watts converted in `amdgpu_hwmon_get_power()` as `(query >> 8) * 1000000 + (query & 0xff) * 1000` microWatts. [F281]
- `amdgpu_hwmon_set_pwm1()` and `amdgpu_hwmon_set_fan1_target()` must verify via `amdgpu_dpm_get_fan_control_mode(adev, &pwm_mode)` that `pwm_mode == AMD_FAN_CTRL_MANUAL` before calling `amdgpu_dpm_set_fan_speed_pwm()` or `amdgpu_dpm_set_fan_speed_rpm()`, returning `-EINVAL` (for `pwm1`) or `-ENODATA` (for `fan1_target`) otherwise. [F282]

## Known Pitfalls

- In `amdgpu_pm.c`, sysfs callbacks on `adev->dev` (`amdgpu_device_attrs`, `board_attrs`, `pm_policy_attrs`) must convert `dev_get_drvdata(dev)` from `struct drm_device *` via `drm_to_adev()`, `hwmon_attributes` callbacks on `adev->pm.int_hwmon_dev` receive `struct amdgpu_device *` directly from `dev_get_drvdata(dev)`, and OverDrive (`gpu_od`) `struct od_feature_ops` callbacks must obtain `adev` via `container_of(kobj, struct od_kobj, kobj)->priv` rather than `kobj_to_dev(kobj)`. [F245, F246]
- In `amdgpu_set_pp_od_clk_voltage()`, any multi-character command prefix (such as `"vc"` or `"vo"`) must not start with a character matched by an earlier `*buf ==` branch and must advance `tmp_str` past all prefix characters before `while (isspace(*++tmp_str));`. [F219]
- In `amdgpu_dpm_set_sclk_od()` and `amdgpu_dpm_set_mclk_od()`, when `amdgpu_dpm_dispatch_task(adev, AMD_PP_TASK_READJUST_POWER_STATE, NULL)` returns `-EOPNOTSUPP`, `adev->pm.dpm.current_ps` must be reset to `adev->pm.dpm.boot_ps` before calling `amdgpu_dpm_compute_clocks(adev)`. [F189]
- In `amdgpu_parse_extended_power_table()`, the VBIOS VCE, UVD, SAMU, and ACP tables start with a 1-byte `revid` followed by packed variable-length sub-tables (`VCEClockInfoArray`, `UVDClockInfoArray`, and limit/state tables) whose addresses must be computed by adding `+ 1` and the byte sizes of preceding variable-length arrays. [F242]
- `kv_convert_8bit_index_to_voltage()` maps 8-bit VID indices inversely to millivolts (`6200 - (voltage * 25)`), and `kv_patch_voltage_values()` mutates the `v` field of `uvd`, `vce`, `samu`, and `acp` dependency tables in place from VID indices to mV during `kv_dpm_init()` while leaving `vddc_dependency_on_sclk` as raw VID indices. Broken by: calling `kv_convert_8bit_index_to_voltage()` on already-patched `uvd`/`vce`/`samu`/`acp` entries, re-running `kv_patch_voltage_values()` on resume, or comparing raw VID indices directly against voltage thresholds like `pi->high_voltage_t`. [F191, F235]
- In `kv_dpm.c`, reverse loops over DPM levels with an unsigned `u32` counter (`kv_program_bootup_state()`, `kv_set_valid_clock_range()`, `kv_force_dpm_highest()`, `kv_get_sleep_divider_id_from_clock()`) must use `i > 0` so unmatched searches fall back to index 0 without underflow, while loops testing `i >= 0` (`kv_get_high_voltage_limit()`, `kv_apply_state_adjust_rules()`) must use a signed `int`. [F210]
