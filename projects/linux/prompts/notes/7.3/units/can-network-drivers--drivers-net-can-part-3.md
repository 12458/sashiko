# CAN NETWORK DRIVERS — drivers/net/can (part 3)

CAN controller drivers for NXP `sja1000` (core driver plus ISA, platform, PCI, and PCMCIA bus frontends), Softing DPRAM PCMCIA/platform cards (`softing`), SPI-attached CAN controllers (`hi311x`, `mcp251x`), Allwinner `sun4i_can`, TI `ti_hecc`, and USB CAN adapters (`ems_usb` and `gs_usb`). These drivers bridge diverse bus transports (MMIO, PIO, PCMCIA, PCI, SPI transactions, and USB bulk/control URBs) to the SocketCAN `candev` and `can_rx_offload` interfaces.

## Architecture & Data Flow

- In `gs_usb.c`, `struct gs_host_frame` union members must be selected according to `hf->flags & GS_CAN_FLAG_FD` (`canfd` / `canfd_ts` vs `classic_can` / `classic_can_ts`), and `timestamp_us` must only be read when `dev->feature & GS_CAN_FEATURE_HW_TIMESTAMP` is set. [F228]
- In `gs_usb.c` and `ems_usb.c`, a TX context slot is marked free by setting its index field to the array bound (`tx_context[i].echo_id = GS_MAX_TX_URBS` or `tx_contexts[i].echo_index = MAX_TX_URBS`), and must be initialized to that sentinel at probe and reset on TX completion or close. [F231]
- In `gs_usb_receive_bulk_callback()`, when `hf->flags & GS_CAN_FLAG_OVERFLOW` is set, `stats->rx_over_errors` and `stats->rx_errors` must be incremented before calling `alloc_can_err_skb()`. [F233]
- Every `ndo_stop` path in this component (`sja1000_close()` via `set_reset_mode()`, `softing_netdev_stop()` via `softing_startstop()`, `mcp251x_stop()`, `hi3110_stop()`, `sun4ican_close()` via `sun4i_can_stop()`, `ti_hecc_close()` via `ti_hecc_stop()`, and `gs_can_close()`) must set `can.state` to `CAN_STATE_STOPPED`. [F235]
- In `mcp251x` and `hi311x`, `tx_work` moves `priv->tx_skb` to echo slot 0 via `can_put_echo_skb()`, sets `priv->tx_busy = true`, and clears `priv->tx_skb = NULL`, so `mcp251x_clean()` and `hi3110_clean()` must free `priv->tx_skb`, call `can_free_echo_skb()` if `priv->tx_busy` is set, and reset both fields. [F236]
- In `softing`, TX submission in `softing_netdev_start_xmit()` and `CMD_ACK` handling in `softing_handle_1()` must update `card->tx.pending`, `priv->tx.pending`, and `priv->tx.echo_put`/`priv->tx.echo_get` in lockstep, and `softing_startstop()` must zero all four fields and call `close_candev()` when resetting the chip. [F238]
- In `mcp251x`, `priv->reg_bfpctrl` shadows the `BFPCTRL` GPIO output enable and state bits across `mcp251x_gpio_request()`, `mcp251x_gpio_free()`, `mcp251x_gpio_set()`, and `mcp251x_gpio_set_multiple()`, and must be restored via `mcp251x_gpio_restore()` after `mcp251x_hw_reset()` when `AFTER_SUSPEND_POWER` is set. [F239]
- In `ems_usb`, `dev->active_params` caches the full `CPC_CMD_TYPE_CAN_PARAMS` SJA1000 parameter block initialized by `init_params_sja1000()`, and mode (`ems_usb_write_mode()`) or bit-timing (`ems_usb_set_bittiming()`) changes must update `dev->active_params` in place and send `&dev->active_params` via `ems_usb_command_msg()`. [F240]
- In `peak_pci` (`peak_pciec_write_pca9553()`) and `peak_pcmcia` (`pcan_write_reg()`), writes to PCA9553 register 5 and `PCC_CCR` are skipped when the new byte equals `card->led_cache` or `card->ccr`, so LED updates must modify the cached byte and `pcan_add_channels()` must set `card->ccr = ~ccr` before the initial `PCC_CCR` write. [F241]

## Synchronization

- `gs_usb_timestamp_read()` is called with `parent->tc_lock` held (`spin_lock_bh(&parent->tc_lock)`), temporarily drops `parent->tc_lock` via `spin_unlock_bh()` to perform the sleeping `gs_usb_get_timestamp()` USB control transfer, and must re-acquire `spin_lock_bh(&parent->tc_lock)` before returning on every path. [F190]
- In `gs_can_open()`, when `!parent->active_channels` and `GS_CAN_FEATURE_HW_TIMESTAMP` is supported, `gs_usb_timestamp_init(parent)` must be called before submitting any RX URBs via `usb_submit_urb()`. [F202]
- In `gs_usb.c`, allocation and lookup of `dev->tx_context` slots in `gs_alloc_tx_context()` and `gs_get_tx_context()` must hold `dev->tx_ctx_lock` with `spin_lock_irqsave()` across checking and updating `echo_id`. [F204]
- In `softing_startstop()`, `softing_enable_irq(card, 0)` must drain the IRQ before `softing_reset_chip()` and `softing_fct_cmd()` execute, and in `softing_pdev_remove()`, `softing_card_shutdown(card)` must run before unregistering netdevs and calling `iounmap(card->dpram)`. [F209]
- In `sja1000.c` and `sun4i_can.c`, all writes to the command register (`SJA1000_CMR` and `SUN4I_REG_CMD_ADDR`) must go through `sja1000_write_cmdreg()` or `sun4i_can_write_cmdreg()` under `spin_lock_irqsave(&priv->cmdreg_lock, flags)`, including the `SJA1000_SR` readback in `sja1000_write_cmdreg()`. [F211]
- In `sja1000` frontends whose `read_reg` or `write_reg` callbacks perform multi-step I/O (`sja1000_isa_port_read_reg_indirect`, `sja1000_isa_port_write_reg_indirect`, `sp_technologic_read_reg16`, `sp_technologic_write_reg16`, `f81601_pci_write_reg`), the callback must serialize access with `spin_lock_irqsave()`, nesting inside `priv->cmdreg_lock`. [F212]
- When `sja1000_err()` triggers an asynchronous controller reset via `IRQ_WAKE_THREAD` (`SJA1000_QUIRK_RESET_ON_OVERRUN`), `sja1000_reset_interrupt()` must acquire `netif_tx_lock(dev)`, free echo slot 0 via `can_free_echo_skb(dev, 0, NULL)`, and call `sja1000_set_mode(dev, CAN_MODE_START)` before releasing `netif_tx_lock(dev)`. [F234]
- In f81601_pci_write_reg(), every MMIO register write across the card's channels must be serialized under card->lock with spin_lock_irqsave() and flushed with a dummy readb(priv->reg_base) before releasing the lock. [F307]
- In `softing`, `softing_enable_irq()` and all DPRAM command helpers that sleep via `usleep_range()` (`_softing_fct_cmd()`, `softing_fct_cmd()`, `softing_bootloader_command()`, `softing_reset_chip()`, `softing_chip_poweron()`) must only be called in process context with `card->fw.lock` held. [F330]
- In `softing_startstop()`, the failure path must unlock `card->fw.lock` before calling `dev_close(netdev)` on `card->net[j]`, because `dev_close()` invokes `softing_netdev_stop()` -> `softing_startstop(ndev, 0)` which acquires `card->fw.lock`. [F332]

## Object Lifetimes

- In `hi3110_can_ist()`, `sja1000_err()`, `sun4i_can_err()`, and `ems_usb_rx_err()`, all writes to `struct can_frame *cf` (including `can_change_state(net, cf, ...)` and `cf->data[]`) must finish before calling `netif_rx(skb)`, which transfers `skb` ownership to the networking stack. [F182]
- In `gs_can_start_xmit()` and `gs_can_open()`, once `urb->transfer_flags |= URB_FREE_BUFFER` is set on `urb`, ownership of `hf` or `buf` belongs to `urb` and is freed by `usb_free_urb(urb)`, so error paths after setting `URB_FREE_BUFFER` must not call `kfree()` on the transfer buffer. [F186]
- In `gs_can_start_xmit()` and `ems_usb_start_xmit()`, `can_put_echo_skb()` is called before `usb_submit_urb()`, so if `usb_submit_urb()` fails, the `skb` must be freed via `can_free_echo_skb()` (not `dev_kfree_skb(skb)`) while rolling back `active_tx_urbs`, the URB anchor, and the TX context. [F187]
- Unlike `gs_usb`, `ems_usb_start_xmit()` allocates TX buffers with `usb_alloc_coherent()` and `URB_NO_TRANSFER_DMA_MAP`, so `usb_free_coherent()` must be called explicitly in `ems_usb_write_bulk_callback()` on URB completion and on all error paths in `ems_usb_start_xmit()` after allocation. [F188]
- In `peak_pci_probe()`, `chan->prev_dev` and `pci_set_drvdata(pdev, dev)` must be set before `peak_pciec_probe()`, which must run before `register_sja1000dev()`, and on failure `failure_free_dev` must restore `pci_set_drvdata(pdev, chan->prev_dev)` and call `free_sja1000dev(dev)` before `failure_remove_channels`. [F191]
- In `ti_hecc_probe()` and `ti_hecc_remove()`, `priv->clk` is acquired via unmanaged `clk_get()` and `priv->offload` via `can_rx_offload_add_timestamp()`, so error paths and `ti_hecc_remove()` must call `can_rx_offload_del(&priv->offload)`, `clk_disable_unprepare(priv->clk)`, and `clk_put(priv->clk)` before `free_candev(ndev)`. [F195]
- In `gs_make_candev()` and `gs_destroy_candev()`, `can_rx_offload_add_manual(netdev, &dev->offload, GS_NAPI_WEIGHT)` is called before `register_candev(dev->netdev)`, so if `register_candev()` fails (or during `gs_destroy_candev()`), `can_rx_offload_del(&dev->offload)` must be called before `free_candev(dev->netdev)`. [F196]
- In `sun4ican_open()`, setup runs `open_candev()`, `request_irq()`, `reset_control_deassert()`, `clk_prepare_enable()`, and `sun4i_can_start()` in order, and `sun4ican_open()` rollback and `sun4ican_close()` must unwind them in reverse (`sun4i_can_stop()`, `clk_disable_unprepare()`, `reset_control_assert()`, `free_irq()`, `close_candev()`). [F197]
- In `mcp251x_can_remove()` and `hi3110_can_remove()`, `unregister_candev(net)` must be called before `destroy_workqueue(priv->wq)` and `free_candev(net)`. [F201]

## API Contracts

- `register_sja1000dev()` does not free `dev` when `sja1000_probe_chip()` or `register_candev()` fails, so every caller of `alloc_sja1000dev()` must call `free_sja1000dev(dev)` on probe or registration failure. [F183]
- `alloc_sja1000dev(sizeof_priv)` sets `priv->priv` to the trailing buffer `(void *)priv + sizeof(struct sja1000_priv)` only when `sizeof_priv` is non-zero; callers passing `sizeof_priv == 0` must explicitly assign `priv->priv` before any callback dereferences it. [F219]
- In `sun4i_can` and `ti_hecc`, `sun4ican_set_bittiming()` (`SUN4I_REG_BTIME_ADDR`) and `ti_hecc_set_btc()` (`HECC_CANBTC`) must only be called while the controller is in reset/initialization mode (`set_reset_mode()` in `sun4i_can_start()` or `HECC_CANMC_CCR` in `ti_hecc_reset()`). [F251]
- Before calling register_sja1000dev(), SJA1000 frontend drivers must initialize priv->read_reg, priv->write_reg, priv->reg_base, priv->cdr, priv->ocr, and priv->flags because register_sja1000dev() immediately probes hardware and programs SJA1000_MOD, SJA1000_IER, SJA1000_CDR, and SJA1000_OCR before register_candev(). [F303]
- SJA1000 drivers that register their own card-level IRQ handler (such as ems_pcmcia and peak_pcmcia) must set SJA1000_CUSTOM_IRQ_HANDLER in priv->flags so sja1000_open() and sja1000_close() do not call request_threaded_irq() or free_irq() on dev->irq. [F305]
- In gs_make_candev(), optional USB control requests and features must be gated on bt_const.feature and dconf->sw_version: GS_USB_BREQ_BT_CONST_EXT is sent only when both GS_CAN_FEATURE_FD and GS_CAN_FEATURE_BT_CONST_EXT are set, and GS_CAN_FEATURE_IDENTIFY is enabled only when sw_version > 1. [F325]
- Drivers using `can_rx_offload` (`ti_hecc` and `gs_usb`) must register NAPI before `register_candev()`, call `can_rx_offload_enable()` in `ndo_open` and `can_rx_offload_disable()` in `ndo_stop`, call `can_rx_offload_del()` after `unregister_candev()`, and call `can_rx_offload_irq_finish()` after queueing RX/echo SKBs in IRQ/URB context. [F348]
- `ti_hecc_mailbox_read()` must always acknowledge the mailbox via `HECC_CANRMP`, return `ERR_PTR(-ENOBUFS)` or `ERR_PTR(-ENOMEM)` on drop/allocation/overrun so `can_rx_offload` updates drop statistics, and leave `rx_packets`/`rx_bytes` updates to `can_rx_offload_napi_poll()`. [F349]
- In `gs_usb`, `gs_can_eth_ioctl()` and `gs_usb_get_ts_info()` must only call `can_eth_ioctl_hwts()` and `can_ethtool_op_get_ts_info_hwts()` when `GS_CAN_FEATURE_HW_TIMESTAMP` is set, and `gs_usb_get_echo_skb()` must call `gs_usb_set_timestamp()` before `can_rx_offload_get_echo_skb_queue_timestamp()`. [F350]

## Error Handling

- `sja1000_probe_chip()` returns `0` when the controller is absent (`sja1000_is_absent(priv)` is true) and `-1` when present, so `register_sja1000dev()` treats `!sja1000_probe_chip(dev)` as failure and returns `-ENODEV`. [F217]
- In `peak_pci_probe()`, failure returns must pass `err` through `pcibios_err_to_errno(err)` because `pci_read_config_word()` and `pci_write_config_word()` return positive `PCIBIOS_*` status codes whereas PCI `.probe()` must return a negative errno. [F220]
- When per-channel registration or detection fails after storing a `net_device` pointer into `card->net_dev[i]` in `plx_pci_add_card()` or `card->net[j]` in `softing_pdev_probe()`, the slot must be reset to `NULL` after freeing the `net_device` before cleanup iterates the array. [F222]
- `_softing_fct_cmd()` returns a negative errno (`-ETIMEDOUT` or `-ECANCELED`) on handshake failure or the non-negative 16-bit `DPRAM_FCT_RESULT` on `RES_OK`, whereas `softing_fct_cmd()` treats any positive `DPRAM_FCT_RESULT` (`ret > 0`) as an error and converts it to `-EIO`. [F223]
- In `hi311x.c` and `mcp251x.c`, `priv->power` and `priv->transceiver` are obtained via `devm_regulator_get_optional()` and retain an `ERR_PTR` value when absent, so every access must use `IS_ERR_OR_NULL()` (or `hi3110_power_enable()` / `mcp251x_power_enable()`) rather than a NULL check. [F224]
- When `sja1000_err()` returns non-zero in `sja1000_interrupt()` (such as `IRQ_WAKE_THREAD` when `SJA1000_QUIRK_RESET_ON_OVERRUN` handles `IRQ_DOI` or `-ENOMEM`), `sja1000_interrupt()` must preserve `IRQ_WAKE_THREAD` in `ret` and `break` out of the `SJA1000_IR` loop immediately. [F276]

## External Contracts

- In `gs_usb.c`, per-channel USB vendor control requests pass `dev->channel` (0-based) in the `wValue` (`value`) parameter and `0` in `wIndex` (`index`), whereas `GS_USB_BREQ_HOST_FORMAT` and `GS_USB_BREQ_DEVICE_CONFIG` pass `value = 1` and `index = bInterfaceNumber`. [F230]
- `gs_usb_get_state()` must convert `struct gs_device_state::state` from little-endian with `le32_to_cpu()` and reject values `>= CAN_STATE_MAX` with `-EOPNOTSUPP` before storing into `*state`. [F261]
- In `ems_usb`, bulk transfers begin with a `CPC_HEADER_SIZE` (4-byte) header before the first `struct ems_cpc_msg`, and `ems_usb_read_bulk_callback()` must advance `start` by `CPC_MSG_HEADER_LEN + msg->length` after each message and break if `start > urb->transfer_buffer_length`. [F262]

## Known Pitfalls

- `fw_parse()` and `softing_handle_1()` decode binary streams with variable-length fields where 16-bit and 32-bit little-endian values can lie at odd byte offsets, so they must use `le16_to_cpup()` and `le32_to_cpup()` rather than direct pointer dereferences. [F264]
- In `softing_netdev_start_xmit()`, the DPRAM TX slot layout places the CAN data payload at byte offset 5 for standard frames (advancing `ptr` by 1 byte after the 2-byte ID) and at byte offset 6 for extended frames (`CAN_EFF_FLAG`, immediately after the 4-byte ID). [F266]
- In `softing_initialize_timestamp()` and `softing_raw2ktime()`, 64-bit microsecond timestamp scaling must use `do_div()` with `card->pdat->freq ?: 16` as the divisor so 64-bit division links on 32-bit targets and a zero `card->pdat->freq` defaults to 16 instead of dividing by zero. [F285]
- In `softing_load_fw()`, `addr` (`uint32_t`), `len` (`uint16_t`), and signed `int offset` (which is negative when `offs < addr`, as in `load.offs - load.addr`) must be summed in 32-bit `uint32_t` arithmetic before checking `(addr + len + offset) > size` and indexing `dpram[addr + offset]`. [F286]
- In `sp_populate_of()`, the `"nxp,clock-out-frequency"` property `prop` must be checked to be non-zero before `u32 divider = priv->can.clock.freq * 2 / prop`, and `divider > 1` must be checked before `divider / 2 - 1`. [F288]
- In `mcp251x.c`, GPIO callbacks accessing `BFPCTRL` (`mcp251x_gpio_request()`, `mcp251x_gpio_free()`, `mcp251x_gpio_get()`, and `mcp251x_gpio_set()`) must only pass `offset - MCP251X_GPIO_RX0BF` to `BFPCTRL_BFE()` or `BFPCTRL_BFS()` when `offset` is an output pin (`!mcp251x_gpio_is_input(offset)`). [F291]
- In `softing_load_fw()` and `softing_load_app_fw()`, the record payload pointer `dat` returned by `fw_parse()` points directly into the unaligned binary firmware stream without NUL termination and must be bounded by `len` (using `strncmp(..., dat, len)` and `%.*s`). [F301]
- In peak_pcmcia, pcan_free_channels() and pcan_isr() must verify that the card is still present via pcan_pccard_present(card) before accessing SJA1000 registers, LEDs, or SPI EEPROM power controls. [F310]
- In _softing_fct_cmd(), DPRAM_FCT_HOST (0x032b) sits at an unaligned odd DPRAM offset and must be accessed via pairs of 8-bit iowrite8()/ioread8() calls with wmb() after command submission and rmb() before reading DPRAM_FCT_RESULT. [F313]
