# MELLANOX MLX5 IB driver — include/linux/mlx5

`include/linux/mlx5` defines the binary protocol between the mlx5 kernel drivers (`mlx5_core`, `mlx5_ib`, `mlx5e`, `mlx5_vdpa`) and ConnectX firmware/hardware via PRM bit-level command and descriptor layouts (`mlx5_ifc.h`, `mlx5_ifc_vdpa.h`), alongside core subsystem API declarations for Queue Pairs (`qp.h`), transport objects (`transobj.h`), flow steering helpers (`fs_helpers.h`), port configuration (`port.h`), MACsec (`macsec.h`), MPFS (`mpfs.h`), and resource dump (`rsc_dump.h`).

## Architecture & Data Flow

- In `struct mlx5_ifc_*_bits` definitions (`mlx5_ifc.h`, `mlx5_ifc_vdpa.h`), each `u8` array element is 1 bit and `offsetof` is the bit offset; adding, removing, or resizing any field requires adjusting adjacent `reserved_at_*` or padding arrays by the exact opposite bit count. [F224]
- Any scalar field in `struct mlx5_ifc_*_bits` accessed via `MLX5_SET` or `MLX5_GET` must be at most 32 (`0x20`) bits wide and must not straddle a 32-bit (`0x20`) bit-offset boundary (`(bit_offset & 0x1f) + N <= 32`), because `__mlx5_dw_bit_off` operates within a single `__be32` word. [F225]
- In `mlx5_ifc.h`, capability bitmask enumerators for the 64-bit `general_obj_types` field in `struct mlx5_ifc_cmd_hca_cap_bits` (`MLX5_GENERAL_OBJ_TYPES_CAP_*` and `MLX5_HCA_CAP_GENERAL_OBJECT_TYPES_*`) must use 64-bit shifts (`1ULL << ...` or `BIT_ULL(...)`) because object type IDs up to 63 exceed 32 bits. [F236]
- In `mlx5_ifc.h`, `MLX5_HCA_CAP_2_GENERAL_OBJECT_TYPES_*` bitmask constants for `general_obj_types_127_64` in `struct mlx5_ifc_cmd_hca_cap_2_bits` must subtract `0x40` from the `MLX5_GENERAL_OBJECT_TYPES_*` ID (`0x40..0x7f`) before passing it to `BIT_ULL(...)` so the shift stays in `0..63`. [F237]
- Every `enum mlx5e_link_mode` or `enum mlx5e_ext_link_mode` value added before `MLX5E_LINK_MODES_NUMBER` or `MLX5E_EXT_LINK_MODES_NUMBER` (`port.h`) must stay strictly `< 32` (since `MLX5E_PROT_MASK` shifts `1U` to match 32-bit PTYS registers) and have matching entries in `mlx5e_link_info`/`mlx5e_ext_link_info` (`port.c`) and `mlx5e_build_ptys2ethtool_map()` (`en_ethtool.c`). [F215, F231]
- Every connector type added to `enum mlx5e_connector_type` before `MLX5E_CONNECTOR_TYPE_NUMBER` (`port.h`) must have a corresponding mapping in `ptys2connector_type` in `drivers/net/ethernet/mellanox/mlx5/core/en_ethtool.c`. [F216]
- Every dumpable segment type added to `enum mlx5_sgmt_type` (`rsc_dump.h`) must precede `MLX5_SGMT_TYPE_MENU`, `MLX5_SGMT_TYPE_TERMINATE`, and `MLX5_SGMT_TYPE_NUM`, and have a matching `MLX5_SGMT_STR_ASSING` entry in `mlx5_rsc_sgmt_name` (`rsc_dump.c`). [F217]
- In `enum mlx5_qp_state` (`qp.h`), hardware QP states must be defined before `MLX5_QP_NUM_STATE` and handled in `mlx5_qp_state_str()`, whereas software pseudo-states `MLX5_QP_STATE` and `MLX5_QP_STATE_BAD` must remain after `MLX5_QP_NUM_STATE`. [F218]
- `MLX5_VIRTIO_NET_Q_OBJECT_NONE` (`0xffffffff` in `mlx5_ifc_vdpa.h`) is a software-only sentinel distinct from hardware `MLX5_VIRTIO_NET_Q_OBJECT_STATE_*` (`0x0..0x3`) used to mark `mvq->fw_state` when the firmware virtqueue object is uncreated or destroyed. Broken by: passing `MLX5_VIRTIO_NET_Q_OBJECT_NONE` into hardware `virtio_net_q_object` `state`, or not resetting `mvq->fw_state` to it on destruction. [F222]
- Changes to `mlx5_mpfs_add_mac` and `mlx5_mpfs_del_mac` declarations in `include/linux/mlx5/mpfs.h` must update both the `#ifdef CONFIG_MLX5_MPFS` prototypes and the `#else` inline stubs in lockstep. [F223]

## Synchronization

- Callers of `mlx5_macsec_add_roce_rule`, `mlx5_macsec_del_roce_rule`, `mlx5_macsec_add_roce_sa_rules`, and `mlx5_macsec_del_roce_sa_rules` (`macsec.h`) must run in process context while holding `dev->macsec.lock`, as these helpers sleep and mutate `tx_rules_list` and `rx_rules_list` without internal locking. [F263]
- `mlx5_mpfs_add_mac` and `mlx5_mpfs_del_mac` (`mpfs.h`) must only be called from sleepable process context because with `CONFIG_MLX5_MPFS` enabled they acquire the `mpfs->lock` mutex, allocate with `GFP_KERNEL`, and execute synchronous firmware commands. [F264]

## Object Lifetimes

- `mlx5_core_hairpin_create` allocates `struct mlx5_hairpin` and its `rqn` and `sqn` arrays in a single `kzalloc` block, and on any queue creation or pairing failure destroys all created queues and frees `hp` before returning an `ERR_PTR`. Broken by: separately `kfree`ing `hp->rqn` or `hp->sqn`, or passing an `IS_ERR` return to `mlx5_core_hairpin_destroy`. [F185]
- When a hairpin peer device is torn down before `struct mlx5_hairpin`, `mlx5_core_hairpin_clear_dead_peer` must be called to unpair and destroy peer SQs on `hp->peer_mdev` and set `hp->peer_gone = true` so `mlx5_core_hairpin_destroy` does not access `hp->peer_mdev`. Broken by: accessing `hp->peer_mdev` or `hp->sqn` in `mlx5_core_hairpin_destroy` without checking `!hp->peer_gone`. [F196]
- `mlx5_debug_qp_add` and `mlx5_debug_qp_remove` manage `qp->dbg` by setting `qp->dbg = NULL` when debugfs creation fails or after `mlx5_debug_qp_remove` frees the debugfs tree, making `mlx5_debug_qp_remove` safe when `qp->dbg` is `NULL`. Broken by: leaving `qp->dbg` non-NULL after freeing it or after `add_res_tree` fails. [F189]

## API Contracts

- `mlx5_rsc_dump_next` (`rsc_dump.h`) DMA-maps `page` at offset 0 for `cmd->mem_size` (`key->size` from `mlx5_rsc_dump_cmd_create`) bytes, sleeps in `mlx5_core_access_reg`, and returns negative errno on failure, `1` when more pages remain, or `0` on the final populated page; callers must run in process context with `key->size <= page_size` and process `page` on both `0` and `1` using a signed `int`. [F199, F265]
- In `struct mlx5_hairpin_params`, `log_data_size` and `log_num_packets` must be base-2 logarithms (`ilog2`) of the hairpin buffer byte size and packet count, whereas `num_channels` is a linear queue count. [F201]
- Transport object creation and state-query functions in `transobj.h` (`mlx5_core_alloc_transport_domain`, `mlx5_core_create_rq`, `mlx5_core_create_sq`, `mlx5_core_create_tir`, `mlx5_core_create_tis`, `mlx5_core_create_rqt`, `mlx5_core_query_sq_state`) leave their output pointer untouched on error; callers must check for a `0` return before reading `*rqn`, `*sqn`, `*tirn`, `*tisn`, `*rqtn`, `*tdn`, or `*state`. [F202]
- Although `in` and `ptys` are `u32 *`, `inlen` in `mlx5_core_create_rq`, `mlx5_core_create_sq`, `mlx5_core_create_rqt`, and `mlx5_core_modify_rqt` (`transobj.h`) and `ptys_size` in `mlx5_query_port_ptys` (`port.h`) take byte counts, and un-sized `transobj.h` helpers (`mlx5_core_query_rq`, `mlx5_core_query_sq`, `mlx5_core_modify_rq`, `mlx5_core_modify_sq`) require full `MLX5_ST_SZ_BYTES`-sized buffers. [F246]
- In `port.h`, `enum mlx5e_link_mode` and `enum mlx5e_ext_link_mode` constants are bit indices (`0..31` and `0..20`), not pre-shifted bitmasks, and must be converted with `MLX5E_PROT_MASK(link_mode)` before bitwise testing or OR-ing against PTYS protocol masks. [F211]
- Callers of `_mlx5_fs_is_outer_ipv_flow`, `mlx5_fs_is_outer_ipv4_flow`, and `mlx5_fs_is_outer_ipv6_flow` (`fs_helpers.h`) must pass pointers to the base of a full `fte_match_param` buffer rather than `outer_headers`, because `_mlx5_fs_is_outer_ipv_flow` internally adds `MLX5_BYTE_OFF(fte_match_param, outer_headers)` via `MLX5_ADDR_OF`. [F247]
- `_mlx5_fs_is_outer_ipv_flow()` must check `MLX5_CAP_FLOWTABLE_NIC_RX(mdev, ft_field_support.outer_ip_version)` before inspecting `ip_version` in `fte_match_set_lyr_2_4` (falling back to `ethertype` `ETH_P_IP`/`ETH_P_IPV6` when unsupported), and must verify both the exact-match bitmask in `headers_c` (`0xffff` for `ethertype` or `0xf` for `ip_version`) and the value in `headers_v`. [F233, F249]
- When validating a flow counter object ID for `MLX5_CMD_OP_QUERY_FLOW_COUNTER` against an `MLX5_CMD_OP_ALLOC_FLOW_COUNTER` allocation (`struct mlx5_ifc_alloc_flow_counter_in_bits`), callers must allow any ID in `[base_id, base_id + bulk_size)` where `bulk_size` is `1 << flow_counter_bulk_log_size` (or `128 * flow_counter_bulk` if 0). [F227]
- `mlx5_get_qp_default_ts()` must check `mlx5_get_roce_state(dev)` before reading `MLX5_CAP_ROCE(dev, qp_ts_format)` and fall back to `MLX5_CAP_GEN(dev, sq_ts_format)` when RoCE is disabled, because `qp_ts_format` in the RoCE capability table reads as zero when RoCE is disabled. [F248]
- Probing force-loopback RC QP support when RoCE may be disabled must check `MLX5_CAP_GEN(mdev, fl_rc_qp_when_roce_disabled)` (`struct mlx5_ifc_cmd_hca_cap_bits`) in addition to `MLX5_CAP_ROCE(mdev, fl_rc_qp_when_roce_disabled)` (`struct mlx5_ifc_roce_cap_bits`). [F256]
- Before accessing the `MRTC` hardware register, the driver must verify that `MLX5_CAP_MCAM_REG(dev, mrtc)` (`struct mlx5_ifc_mcam_access_reg_bits::mrtc`) is set. [F257]
- Setting `esw_vport_context.vport_cvlan_insert` to `MLX5_VPORT_CVLAN_INSERT_ALWAYS` requires checking `MLX5_CAP_ESW(dev, vport_cvlan_insert_always)` (`struct mlx5_ifc_e_switch_cap_bits::vport_cvlan_insert_always`), falling back to `MLX5_VPORT_CVLAN_INSERT_WHEN_NO_CVLAN` when unsupported. [F259]

## Error Handling

- `mlx5_macsec_add_roce_rule` rolls back any TX or RX steering rules it added to `tx_rules_list` and `rx_rules_list` for `gid_idx` by calling `mlx5_macsec_del_roce_rule` before returning a non-zero error. Broken by: returning an error after adding TX or RX rules without calling `mlx5_macsec_del_roce_rule`. [F191]

## External Contracts

- In `struct mlx5_wqe_inline_seg`, `byte_count` must be written as `cpu_to_be32(len | MLX5_INLINE_SEG)` with `len` masked to at most `MLX5_WQE_INLINE_SEG_BYTE_COUNT_MASK` (`0x3ff`), because bit 31 (`MLX5_INLINE_SEG`) discriminates an inline data segment from a `struct mlx5_wqe_data_seg` pointer segment. [F205]
- In `struct mlx5_wqe_eth_seg`, the software parser offset fields (`swp_outer_l4_offset`, `swp_outer_l3_offset`, `swp_inner_l4_offset`, `swp_inner_l3_offset`) must be specified in units of 2-byte words (byte offset divided by 2), not in bytes. [F206]
- In `struct mlx5_wqe_umr_ctrl_seg`, `xlt_octowords`, `bsf_octowords`, and the split translation offset (`xlt_offset` for bits 15:0 and `xlt_offset_47_16` for bits 47:16) are all measured in 16-byte octowords, and `xlt_offset` shares an anonymous union with `bsf_octowords`. Broken by: writing byte or page counts, or setting both `xlt_offset` and `bsf_octowords` in the same segment. [F208]
- In `struct mlx5_bsf`, `basic.wire.copy_byte_mask` (`MLX5_CPY_GRD_MASK`, `MLX5_CPY_APP_MASK`, `MLX5_CPY_REF_MASK`) is active only when bit 4 of `basic.bsf_size_sbs` (`1 << 4`) is set (otherwise `basic.wire` is `bs_selector`), and the entire `struct mlx5_bsf` must be zeroed before use. [F209]
- In `struct mlx5_ifc_virtio_net_q_object_bits`, the 13-bit virtio queue feature mask is split across two discontiguous fields, requiring bits 12:3 to be shifted right by 3 into `queue_feature_bit_mask_12_3` and bits 2:0 to be masked into `queue_feature_bit_mask_2_0`. [F212]
- Command opcodes in `[MLX5_CMD_OP_GENERAL_START, MLX5_CMD_OP_GENERAL_END)` (`0xb00..0xd00` in `mlx5_ifc.h`) are automatically whitelisted by `devx_is_general_cmd()` for untrusted userspace execution via `MLX5_IB_METHOD_DEVX_OTHER` without DevX object-id ownership checks. Broken by: adding an object-mutating or privileged opcode in `0xb00..0xcff` without restricting it in `devx_is_general_cmd()`. [F266]

## Known Pitfalls

- In `struct mlx5_wqe_eth_seg`, `sizeof(struct mlx5_wqe_eth_seg)` includes the 2-byte `inline_hdr.start` array; WQE size calculations for an inline header of length `copysz` must subtract `sizeof(eseg->inline_hdr.start)`, and multi-byte copies into `inline_hdr` must target the flexible array `eseg->inline_hdr.data` rather than `start`. [F243]
- In `struct mlx5_wqe_eth_seg`, `__be32 trailer` (`MLX5_ETH_WQE_INSERT_TRAILER` and `MLX5_ETH_WQE_TRAILER_HDR_*` in bits 26..30) aliases the upper bits of `__be16 inline_hdr.sz` via an anonymous union, so TX paths supporting IPsec/PSP trailer offload must OR into `eseg->inline_hdr.sz` (`|=`) rather than overwrite it (`=`). [F267]
- Bulk `memset` or `memcpy` operations covering the second 8 bytes of `struct mlx5_wqe_ctrl_seg` (`signature`, `rsvd`, `fm_ce_se`, and the trailing 32-bit union) must address `&cseg->trailer` with `sizeof(cseg->trailer)` rather than `&cseg->signature`. [F244]
- In `struct mlx5_ifc_packet_reformat_context_in_bits`, the fixed structure includes the first 2 bytes of payload in `reformat_data[2][0x8]` before the flexible array `more_reformat_data[][0x8]`, so reformat data copies must start at `MLX5_ADDR_OF(packet_reformat_context_in, ..., reformat_data)` and exact command length math must subtract `MLX5_FLD_SZ_BYTES(..., reformat_data)`. [F245]
