# BLUETOOTH DRIVERS — drivers/bluetooth (part 3)

Implements the Bluetooth HCI UART line discipline (`hci_ldisc`), Serdev glue (`hci_serdev`), UART protocols (H4, BCSP, H5, Intel, TI HCILL, Marvell, Nokia H4+), virtual HCI (`hci_vhci`), and Virtio Bluetooth (`virtio_bt`).

## Architecture & Data Flow
- `struct hci_uart` runs in Serdev (`hu->serdev != NULL`) or TTY mode (`hu->tty != NULL`); shared helpers (`hci_uart_has_flow_control`, `hci_uart_set_flow_control`) and dual-mode protocols (`h5`, `ll`, `mrvl`) must test `if (hu->serdev)` before dereferencing `hu->serdev` or `hu->tty`. In `hci_serdev.c`, `hci_uart_write_wakeup()` and `hci_uart_receive_buf()` cast `serdev_device_get_drvdata(serdev)` to `struct hci_uart *` and check `serdev == hu->serdev`, so serdev drivers must embed `struct hci_uart` first in drvdata and set `hu->serdev` before registering. [F215, F286]
- In `hci_ldisc.c` and `hci_serdev.c`, `hci_uart_close()` clears `hdev->flush = NULL` after `hci_uart_flush(hdev)`, so `hci_uart_open()` must restore `hdev->flush = hci_uart_flush`. [F238]
- In `hci_bcsp.c` and `hci_h5.c`, reliable seq/ack numbers are 3-bit mod-8 (`0..7`), and `unack`, `rel`, `msgq_txseq`/`tx_seq`, and `tbcsp`/`h5->timer` update in lockstep under `unack.lock`: `bcsp_dequeue()`/`h5_dequeue()` (via `h5_prepare_pkt()`) increments `msgq_txseq`/`tx_seq`, queues to `unack`, and arms the timer; `bcsp_timed_event()`/`h5_timed_event()` moves skbs from `unack` tail (`__skb_dequeue_tail`) to `rel` head (`skb_queue_head`) while decrementing `msgq_txseq`/`tx_seq` via `(seq - 1) & 0x07`; `bcsp_pkt_cull()`/`h5_pkt_cull()` steps backward via `(seq - 1) & 0x07` at most `skb_queue_len(&unack)` times to match `rxack`/`rx_ack` and stops the timer when `unack` empties. [F230, F231, F253, F267, F276]
- `bcsp_enqueue()`/`h5_enqueue()` must reject `skb->len > 0xfff`, and `bcsp_recv()`/`h5_rx_pkt_start()` must allocate RX `sk_buff`s >= `0x1005` bytes (`H5_MAX_LEN`) since unslipping appends bytes without checking `skb_tailroom()`. On a non-delimiter byte (`!= 0xc0`) in `BCSP_W4_PKT_START` in `bcsp_recv()` or `h5_rx_pkt_start()`, `ptr`/`count` must not advance (`h5_rx_pkt_start` returns 0) so the byte is unslipped as the first header byte on the next iteration. [F250, F252, F266]
- In `hci_bcsp.c`, the 16-bit CRC must be bit-reversed via `bitrev16()` and transmitted big-endian in `bcsp_prepare_pkt()` and read via `get_unaligned_be16()` in `bscp_get_crc()`. In `bcsp_complete_rx_pkt()`, an out-of-order reliable packet must set `pass_up = 2` (skipping `rxseq_txack` increment), `txack_req = 1`, and still call `bcsp_pkt_cull()`. [F254, F270]
- In `hci_h5.c`, `h5_peer_reset()` (in `H5_ACTIVE`) must set `h5->state = H5_UNINITIALIZED`, stop `h5->timer`, purge `rel`/`unrel`/`unack`, zero `tx_seq`/`tx_ack`, and call `hci_reset_dev()`. Every RX completion/abort path must call `h5_reset_rx()` (after clearing `h5->rx_skb` if passed to `hci_recv_frame()`) to free/NULL `rx_skb`, reset `rx_func = h5_rx_delimiter`, zero `rx_pending`, and clear `H5_RX_ESC`. `h5_handle_internal_rx()` must verify `H5_HDR_LEN(hdr) >= 2` before accessing `data = &h5->rx_skb->data[4]`, and `H5_HDR_LEN(hdr) > 2` before reading `data[2]` in `conf_rsp`. [F232, F233, F255]
- In `h4_recv_buf()`, the `!skb` branch must fall through into the payload copy and `skb->len == (&pkts[i])->hlen` check in the same iteration after consuming the 1B packet type, so `hlen == 0` packets (`ll_recv_pkts`) are delivered when `count` hits 0. In `hci_intel.c`, `STATE_BOOTLOADER` in `intel->flags` must be cleared before `intel_setup()` returns success, as `intel_dequeue()` injects synthetic `BTINTEL_HCI_OP_RESET` events while set. [F243, F265]
- In `hci_mrvl.c`, `mrvl_dequeue()` prepends `bt_cb(skb)->pkt_type` to `mrvl->txq` packets, whereas raw firmware chunks in `mrvl->rawq` are sent after `txq` empties without a type byte; both queues must be purged in `mrvl_flush()` and `mrvl_close()`. `mrvl_recv_fw_req()` and `mrvl_recv_chip_ver()` must check `(pkt->lhs ^ pkt->rhs) == 0xffff` on `struct hci_mrvl_pkt` before using `le16_to_cpu(pkt->lhs)`. `mrvl_load_firmware()` must clamp `mrvl->tx_len` to `fw_max - fw_ptr` and loop while `fw_ptr <= fw_max` to wait for and ACK the terminal `tx_len == 0` request. [F245, F263, F271]
- In `hci_nokia.c`, `nokia_enqueue()` must pad odd-length TX `sk_buff`s (after prepending the 1B H4 type) with 1 zero byte via `skb_pad(skb, 1)` and `skb_put(skb, 1)`. `nokia_recv_negotiation_packet()` and `nokia_recv_alive_packet()` must verify `hdr->dlen == sizeof(*evt)` and `hdr->dlen == sizeof(*pkt)` before `skb_pull(skb, sizeof(*hdr))`. [F261, F262]
- In `hci_vhci.c`, `force_devcd_write()` must verify `count >= offsetof(struct devcoredump_test_data, data)` and `count <= sizeof(dump_data)` before `copy_from_user()`. [F259]

## Synchronization
- `hci_uart_tx_wakeup()` takes `percpu_down_read_trylock(&hu->proto_lock)`, so `percpu_down_write(&hu->proto_lock)` must only be taken in `hci_uart_tty_close()` and released after clearing `HCI_UART_PROTO_READY` and before `cancel_work_sync(&hu->write_work)` or `hci_unregister_dev()`. `hci_uart_tx_wakeup()` must set `HCI_UART_TX_WAKEUP` before `test_and_set_bit(HCI_UART_SENDING, &hu->tx_state)`, and `hci_uart_write_work()` must clear `HCI_UART_TX_WAKEUP` before dequeuing and recheck it after clearing `HCI_UART_SENDING`. [F199, F202, F303]
- In `hci_uart_unregister_device()`, `cancel_work_sync(&hu->write_work)` must precede `hu->proto->close(hu)`, and `bcsp_close()`/`h5_close()` must synchronously stop their timers (`timer_shutdown_sync(&bcsp->tbcsp)` / `timer_delete_sync(&h5->timer)`) before purging queues or freeing state. [F314]
- In `hci_bcsp.c` and `hci_h5.c`, `unack.lock` must precede `rel.lock` (`spin_lock_irqsave_nested(..., SINGLE_DEPTH_NESTING)`) and be held across window checks, `rel`/`unack` ops, seq updates, and timer updates; `bcsp_prepare_pkt()`, `h5_prepare_pkt()`, `h4_recv_buf()`, and all UART RX `recv` allocations (`mrvl_send_ack()`, `bcsp_handle_le_pkt()`, `h5_link_control()`) must use `GFP_ATOMIC` and never sleep. [F203, F307, F311]
- In `hci_ll.c`, `ll->hcill_lock` (`spin_lock_irqsave()`) must cover all `ll->hcill_state` accesses, `send_hcill_cmd()`, and `__ll_do_awake()`, and be released before `hci_uart_tx_wakeup()`. In `ll_device_want_to_wakeup()`, `HCILL_ASLEEP_TO_AWAKE` must fall through to `HCILL_ASLEEP` to queue `HCILL_WAKE_UP_ACK` via `send_hcill_cmd()` before `__ll_do_awake()` drains `ll->tx_wait_q`. [F206, F273]
- In `hci_mrvl.c`, `mrvl_load_firmware()` must set `STATE_FW_REQ_PENDING` before queuing to `mrvl->rawq` and waking TX; `mrvl_recv_fw_req()` and `mrvl_recv_chip_ver()` must store `tx_len`/`id`/`rev` before `clear_bit()` on `mrvl->flags` and issue `smp_mb__after_atomic()` before `wake_up_bit()`. [F207, F312]
- In `hci_nokia.c`, `nokia_send_alive_packet()` and `nokia_send_negotiation()` must call `init_completion(&btdev->init_completion)` and set `btdev->init_error = 0` before `nokia_enqueue()` and `hci_uart_tx_wakeup()`; RX handlers must write `btdev->init_error` and IDs before `complete()`, and senders must check `if (btdev->init_error < 0)` after `wait_for_completion_interruptible_timeout()` succeeds. [F208, F225]
- In `hci_intel.c`, matching `hu` to `idev` on `intel_device_list` requires `intel_device_list_lock`, while `idev->hu` accesses in PM/IRQ/power callbacks require `idev->hu_lock` (which nests inside `intel_device_list_lock`). Because `intel_enqueue()` calls `pm_runtime_get_sync()` under `intel_device_list_lock`, `intel_suspend_device()`/`intel_resume_device()` must only acquire `idev->hu_lock`. `intel_irq()` must be a threaded handler (`handler == NULL`, `IRQF_ONESHOT`) as it locks `idev->hu_lock` and calls `intel_lpm_host_wake()` (`tty_set_termios()`, `GFP_KERNEL`). [F242, F309, F310]
- In `hci_vhci.c`, `data->open_mutex` serializes `vhci_create_device()`/`__vhci_create_device()` (checking `!data->hdev`) between `vhci_open_timeout()` and `vhci_get_user()`. `cancel_delayed_work_sync(&data->open_timeout)` must be called outside `data->open_mutex`, and `data->open_mutex` must never be taken in `hdev` callbacks like `vhci_send_frame()`. In `virtio_bt.c`, `virtbt_rx_done()` runs in IRQ context and must defer `virtbt_add_inbuf()` (`GFP_KERNEL`) to `virtbt_rx_work()`. [F209, F246, F313, F315]

## Object Lifetimes
- Teardown in `hci_uart_tty_close()` and `hci_uart_unregister_device()` must call `cancel_work_sync(&hu->init_ready)` before checking `HCI_UART_REGISTERED` to call `hci_unregister_dev()`. In `hci_ldisc.c`, `hci_uart_register_dev()` must allocate/init `hu->hdev` before `hu->proto->open(hu)`, and if `hci_register_dev(hdev)` fails (synchronously or in `hci_uart_init_work()`), it must call `hu->proto->close(hu)` and clear `hu->hdev = NULL` before `hci_free_dev(hdev)`. In `hci_serdev.c`, `serdev_device_close(hu->serdev)` must only be called when testing and clearing `HCI_UART_PROTO_READY`. [F190, F192, F289]
- `hci_uart_send_frame()` ignores `hu->proto->enqueue(hu, skb)`'s return value, so every `enqueue` callback must queue or `kfree_skb(skb)` on all paths. Internal TX SKBs queued onto protocols that prepend the 1B H4 type via `skb_push(skb, 1)` (`h4`, `ll`, `nokia`, `intel`, `mrvl`) must use `bt_skb_alloc()`, not `alloc_skb()`. [F321, F322]
- In `bcsp_dequeue()` and `h5_dequeue()`, a reliable `skb` from `rel` must be queued to `unack` (`__skb_queue_tail`) if `bcsp_prepare_pkt()`/`h5_prepare_pkt()` succeeds or requeued at `rel` head if `NULL`; an unreliable `skb` from `unrel` is freed on success or requeued on failure. [F188]
- In `hci_h5.c`, when `H5_WAKEUP_DISABLE` is set on `h5->flags`, `h5_btrtl_open()`/`h5_btrtl_close()` must skip `pm_runtime_enable()`/`pm_runtime_disable()`, and `h5_btrtl_resume()` must take `__module_get(THIS_MODULE)` and `get_device()` before queuing `h5_btrtl_reprobe_worker`. [F293]
- In `hci_intel.c`, `intel_probe()` calls `device_wakeup_disable(&pdev->dev)`, and `intel_set_power()` requests `idev->irq` and enables wakeup/runtime PM only when `powered == true` (undoing all three when `false`). `intel_close()` must cancel `intel->busy_work` and call `intel_set_power(hu, false)` before freeing `intel->rx_skb` and `intel`. [F193, F294]
- In `hci_nokia.c`, `wakeup_handler()` and `nokia_dequeue()` must gate `pm_runtime_get()`/`pm_runtime_put()` on `btdev->rx_enabled`/`tx_enabled` transitions, and `nokia_dequeue()` must call `serdev_device_wait_until_sent()` before deasserting `wakeup_bt` and `pm_runtime_put()`. `nokia_bluetooth_serdev_probe()` must check `clk_prepare_enable(sysclk)` for error before `clk_get_rate(sysclk)` and `clk_disable_unprepare(sysclk)`, so close/remove must not disable `sysclk`. [F224, F298, F299]
- In `hci_ll.c`, `hci_ti_probe()` must call `nvmem_cell_put()` and `kfree(bdaddr)` after `nvmem_cell_get()`/`nvmem_cell_read()`, storing `BDADDR_NONE` in `lldev->bdaddr` on errors other than `-EPROBE_DEFER`, `-ENOENT`, and `-ENOSYS`. [F300]
- In `hci_vhci.c`, `vhci_read()` must requeue `skb` at `data->readq` head (`skb_queue_head`) when `vhci_put_user()` fails, only calling `kfree_skb(skb)` on success. `vhci_release()` must drain `data->open_timeout` and `data->suspend_work` and call `vhci_debugfs_remove(hdev)` (guarded with `vhci_debugfs_init()` by `!IS_ERR_OR_NULL(hdev->debugfs)`) before `hci_unregister_dev()`, `hci_free_dev()`, and `kfree(data)`. [F196, F211, F228]
- In `virtio_bt.c`, `virtbt_probe()` must init `vbt->rx` and register `vbt->hdev` before `virtio_device_ready()` and `virtbt_open_vdev()`, and `virtbt_remove()` must call `virtio_reset_device()` and `virtbt_close_vdev()` (`cancel_work_sync(&vbt->rx)`) before detaching unused buffers, freeing `hdev`, or deleting virtqueues. [F212]

## API Contracts
- `h4_recv_buf()` returns a partial `skb`, `NULL`, or an `ERR_PTR` (after freeing any partial `skb`) and ignores `pkts[i].recv(hdev, skb)`'s return value: callers storing `rx_skb` must check `IS_ERR(rx_skb)` and set `rx_skb = NULL` without `kfree_skb()`, and every `h4_recv_pkt.recv` callback must consume or free `skb`. Each `struct h4_recv_pkt` must have `lsize` in `{0, 1, 2}`, `loff + lsize <= hlen` when `lsize > 0`, and `maxlen >= hlen`. [F213, F248, F323]
- `hci_set_drvdata(hdev, hu)` is owned by `hci_ldisc`/`hci_serdev`/`h4_recv_buf()`, so `hci_uart_proto` drivers must use `hu->priv` (or `hci_get_priv(hdev)`) and never call `hci_set_drvdata()`. Serdev drivers or `struct h5_vnd` entries (`rtl_vnd`) invoking `hci_get_priv(hdev)` helpers (`btrtl_initialize()`, `btrealtek_set_flag()`) must pass `sizeof_priv` to `hci_uart_register_device_priv()`, which calls `p->open(hu)` before `hci_alloc_dev_priv()`, so serdev-capable `open` callbacks must not dereference `hu->hdev` and must set `hu->flags` or `hu->hdev_flags`. [F281, F282, F287]
- `hci_uart_set_flow_control(hu, enable)` uses inverted semantics (`enable == true` throttles/lowers RTS via `!enable`; `false` unthrottles). Any protocol calling it on a TTY ldisc (`intel_proto`, `mrvl_proto_8897`) must check `hci_uart_has_flow_control(hu)` in `open()` and fail with `-EOPNOTSUPP` if false. `hci_uart_tty_open()` must verify `capable(CAP_NET_ADMIN)` and `tty->ops->write != NULL`. [F217, F318, F326]
- `hdev->manufacturer` is set from `hu->proto->manufacturer` only when `hu->proto->setup != NULL`, whereas `HCI_UART_VND_DETECT` in `hci_uart_setup()` only runs when `hu->proto->setup == NULL`; in `hci_mrvl.c`, `mrvl_set_baudrate()` must set `HCI_UART_VND_DETECT` on `hu->hdev_flags` for `mrvl_proto_8997` (`setup == NULL`). [F301, F320]
- In `hci_intel.c`, `intel_setup()` must return early after `btintel_check_bdaddr()` when `ver.fw_variant == 0x23` (operational) without calling bootloader-only `btintel_read_boot_params()` (`0x06`). `intel_set_baudrate()` must send Intel Read Version (`0xfc05`) before speed-change (`0xfc06`), and `intel_setup()` must restore `init_speed` via `intel_set_baudrate()` before `btintel_send_intel_reset()` when `speed_change` is set. [F296, F297]

## Error Handling
- In `intel_setup()`, `btintel_download_firmware()` returning `-EALREADY` must not fail setup at `done:` (`if (err < 0 && err != -EALREADY) return err;`). In `hci_ti_probe()`, `devm_clk_get(&serdev->dev, "ext_clock")` may store `ERR_PTR(-ENOENT)` in `lldev->ext_clk`, so `ll_open()` must guard `clk_prepare_enable(lldev->ext_clk)` with `!IS_ERR(lldev->ext_clk)`. [F220, F221]

## External Contracts
- In `hci_ldisc.c`, `hci_uart_tty_ioctl()` takes `HCIUARTSETPROTO`/`HCIUARTSETFLAGS` directly from `arg` and returns `HCIUARTGET*` directly. `hci_uart_set_flags()` must validate `HCIUARTSETFLAGS` against `valid_flags` (`HCI_UART_RAW_DEVICE`, `HCI_UART_RESET_ON_INIT`, `HCI_UART_INIT_PENDING`, `HCI_UART_EXT_CONFIG`, `HCI_UART_VND_DETECT`; bit 2 unassigned) or return `-EINVAL`. [F257, F325]
- In `hci_vhci.c`, `vhci_get_user()` requires `len >= 2 && len <= HCI_MAX_FRAME_SIZE` and rejects `HCI_VENDOR_PKT` writes with trailing bytes (`skb->len > 0`). `__vhci_create_device()` must reject `opcode & 0x3c` with `-EINVAL`, and queue the 4B `HCI_VENDOR_PKT` at `data->readq` head (`skb_queue_head()`) before `atomic_inc(&data->initialized)` and `wake_up_interruptible(&data->read_wait)`, while `vhci_send_frame()` only wakes `read_wait` when `atomic_read(&data->initialized)` is non-zero. [F258, F327]
- In `virtio_bt.c`, `virtbt_probe()` must check `virtio_has_feature(vdev, VIRTIO_BT_F_CONFIG_V2)` before reading config fields beyond `type` (`struct virtio_bt_config_v2` vs `struct virtio_bt_config`). In `hci_ll.c`, `hci_ti_probe()` must verify `len == sizeof(bdaddr_t)` on the `"bd-address"` nvmem cell and `baswap()` it, and `ll_set_bdaddr()` must `baswap()` before `HCI_VS_WRITE_BD_ADDR`. [F260, F264]

## Known Pitfalls
- In `h4_recv_buf()`, post-frame padding `hu->padding` must be computed on `(skb->len + 1)` and reduced twice with `% alignment` (`(alignment - hu->padding) % alignment`). In `bcsp_recv()` and `h5_rx_3wire_hdr()`, 8-bit ones'-complement header checksum checks must mask the promoted `int` sum/negation with `& 0xff` (or cast to `u8`). [F275, F278]
