# RADEON and AMDGPU DRM DRIVERS — drivers/gpu/drm/amd/amdgpu (part 21)

Hardware backends for the Platform Security Processor (`psp_v3_1`, `psp_v13_0`, `psp_v13_0_4`, `psp_v14_0`) and System DMA engines (`sdma_v2_4`..`sdma_v5_0`), covering PSP mailbox/ring/memory-training protocols and SDMA ring emission, VM PTE updates, engine resets, and RAS reporting.

## Architecture & Data Flow
- In `sdma_v4_4_2`, logical instance indices (`0..adev->sdma.num_instances - 1`) must be mapped via `GET_INST(SDMA0, instance)` before indexing `adev->reg_offset[SDMA0_HWIP]`, computing `aid_id`, querying/resetting RAS registers, or passing a bitmask to `amdgpu_dpm_reset_sdma`; `sdma_v4_4_2_ring_emit_hdp_flush` (`ring->me % num_inst_per_aid`) and `sdma_v4_4_2_set_ring_funcs` (`dev_inst / num_inst_per_aid`) require `adev->sdma.num_inst_per_aid` to be non-zero first. [F1845, F1887]
- Before resetting an SDMA v4.4.2 engine, `sdma_v4_4_2_stop_queue` must snapshot `gfx_guilty`/`page_guilty` and `cached_rptr` so `sdma_v4_4_2_gfx_resume` and `sdma_v4_4_2_page_resume` (`restore = true`) advance guilty queues to `ring->wptr` (without zeroing it) while resuming innocent queues at `cached_rptr`. [F1844]
- In `sdma_v4_0.c` and `sdma_v4_4_2.c`, `adev->sdma.instance[i].page` is only initialized when `adev->sdma.has_page_queue` is true, so all start, stop, resume, ring-test, queue-stop, and teardown paths must guard on `adev->sdma.has_page_queue`. [F1826]
- Register aperture selection: `sdma_v4_0_get_reg_offset` uses segment 0 (`reg_offset[SDMA0..1_HWIP][0][0]`) for instances 0..1 and segment 1 (`reg_offset[SDMA2..7_HWIP][0][1]`) for instances 2..7; `sdma_v5_0_get_reg_offset` uses `reg_offset[GC_HWIP][0][1]` with instance 1 stride `SDMA1_HYP_DEC_REG_OFFSET` (`0x20`) for `0x5880..0x5893` and `reg_offset[GC_HWIP][0][0]` with stride `SDMA1_REG_OFFSET` (`0x600`) otherwise; `sdma_v4_4_get_reg_offset` requires an `SDMA0` (`regSDMA0_*`) offset and `instance` in `0..4` (returning `0` for `> 4`). [F1839, F1864, F1865]
- When computing GPU writeback addresses from DWord slot indices (`ring->rptr_offs`, `ring->wptr_offs`, or `index` from `amdgpu_device_wb_get`) in `sdma_v4_4_2_gfx_resume`, `sdma_v4_4_2_page_resume`, and `sdma_v*_ring_test_*`, multiply the slot index by 4 before adding to `adev->wb.gpu_addr`, unlike `adev->wb.wb[index]`. [F1892]
- In `psp_v13_0_memory_training` and `psp_v14_0_memory_training`, the `ops` bitmask expansion must remain a non-exclusive chain (`SEND_SHORT_MSG` -> `RESTORE` -> `SAVE` -> `SEND_LONG_MSG` -> clear `SEND_SHORT_MSG`, set `SAVE`) followed by execution in order `SEND_LONG_MSG`, `SAVE`, `RESTORE`, `SEND_SHORT_MSG`; `SEND_LONG_MSG` must back up `BIST_MEM_TRAINING_ENCROACHED_SIZE` bytes from `adev->mman.aper_base_kaddr` before `PSP_BL__DRAM_LONG_TRAIN` and restore them via `memcpy_toio` and `amdgpu_device_flush_hdp` afterward. [F1850, F1866]
- In `sdma_v4_0_start`, `sdma_v4_4_2_inst_start`, and bare-metal `sdma_v5_0_gfx_resume_instance`, `UTC_L1_ENABLE` in `mmSDMA0_CNTL` / `regSDMA_CNTL` must be set to 1; in `sdma_v2_4_ring_emit_vm_flush` and `sdma_v3_0_ring_emit_vm_flush`, `amdgpu_gmc_emit_flush_gpu_tlb` must be followed by a 6-dword `SDMA_OP_POLL_REGMEM` on `mmVM_INVALIDATE_REQUEST << 2`. [F1921, F1922]
- When encoding `amdgpu_sdma_phase_quantum` into `PHASE*_QUANTUM` in `sdma_v3_0`, `sdma_v4_0`, `sdma_v4_4_2`, and `sdma_v5_0` `ctx_switch_enable`, each `unit` increment must halve `value` with ceiling rounding (`(value + 1) >> 1`) and clamp both fields to their mask limits. [F1886]

## Synchronization
- In `sdma_v4_4_2_inst_enable`, when disabling SDMA (`enable=false`) on bare metal during reset (`!amdgpu_sriov_vf(adev) && amdgpu_in_reset(adev)`), stop the GFX, RLC, and page queues but return before setting `SDMA_F32_CNTL.HALT=1` so SDMA firmware stays running to respond to FREEZE requests. [F1814]
- In `sdma_v4_0_gfx_resume`, `sdma_v4_0_page_resume`, `sdma_v4_4_2_gfx_resume`, `sdma_v4_4_2_page_resume`, and `sdma_v5_0_gfx_resume_instance`, set `MINOR_PTR_UPDATE=1` before programming ring WPTR/doorbell and clear `MINOR_PTR_UPDATE=0` afterward, prior to setting `RB_ENABLE=1`. [F1817]
- When `ring->use_doorbell` is true in SDMA `*_ring_set_wptr` callbacks (`sdma_v3_0`, `sdma_v4_0`, `sdma_v4_4_2`, `sdma_v5_0`), store `ring->wptr << 2` to the writeback slot via `WRITE_ONCE` or `atomic64_set` before ringing `WDOORBELL32`/`WDOORBELL64`. [F1818]
- In `sdma_v2_4_gfx_resume` and `sdma_v3_0_gfx_resume`, while holding `adev->srbm_mutex` for `vi_srbm_select(adev, 0, 0, 0, j)`, reset the selector via `vi_srbm_select(adev, 0, 0, 0, 0)` before `mutex_unlock(&adev->srbm_mutex)`. [F1800]
- `sdma_v4_4_2_update_reset_mask(adev)` must be called in `sdma_v4_4_2_late_init` (not `sw_init`/`early_init`) after SMU init and `adev->gfx.mec_fw_version` setup complete. [F1813]

## Object Lifetimes
- `psp_v3_1_ring_destroy`, `psp_v13_0_ring_destroy`, `psp_v13_0_4_ring_destroy`, and `psp_v14_0_ring_destroy` must call `psp_v*_ring_stop` before `amdgpu_bo_free_kernel(&adev->firmware.rbuf, &ring->ring_mem_mc_addr, (void **)&ring->ring_mem)`, and must still free the BO and clear `ring->ring_mem` if `ring_stop` fails. [F1793]
- In `psp_v13_0_memory_training` and `psp_v14_0_memory_training` (`PSP_MEM_TRAIN_SEND_LONG_MSG`), `buf` from `vmalloc` must be freed with `vfree(buf)` on all exit paths, and `drm_dev_exit(idx)` must be called on both success and `memory_training_send_msg` error whenever `drm_dev_enter` succeeds. [F1794]
- The `duplicate` flag passed to `amdgpu_sdma_destroy_inst_ctx` in `sdma_v4_0_sw_fini` and `sdma_v4_4_2_sw_fini` must match `sdma_v4_0_init_microcode` (`IP_VERSION(4, 2, 2)`, `(4, 4, 0)`) and `sdma_v4_4_2_init_microcode` (`IP_VERSION(4, 4, 2)`, `(4, 4, 4)`, `(4, 4, 5)`). [F1796]
- In `sdma_v4_4_2_reset_queue` and `sdma_v5_0_reset_queue`, `amdgpu_amdkfd_suspend(adev, true)` must be unconditionally paired with `amdgpu_amdkfd_resume(adev, true)` after `amdgpu_sdma_reset_engine`, even on error; `sdma_v5_0_reset_queue` must pass `caller_handles_kernel_queues = true` to `amdgpu_sdma_reset_engine` (because it calls `amdgpu_ring_reset_helper_begin`/`end`), whereas `sdma_v4_4_2_reset_queue` passes `false`. [F1805, F1807]
- In `sdma_v5_0_ring_preempt_ib`, `amdgpu_ring_set_preempt_cond_exec(ring, false)` and `WREG32(sdma_gfx_preempt, 1)` must be restored via `WREG32(sdma_gfx_preempt, 0)` and `amdgpu_ring_set_preempt_cond_exec(ring, true)` even when polling `ring->trail_fence_cpu_addr` times out. [F1806]
- In `sdma_v4_0_hw_fini`, `sdma_v4_4_2_hw_fini`, and `sdma_v4_4_2_xcp_suspend`, when `!amdgpu_sriov_vf(adev)` and `amdgpu_ras_is_supported(adev, AMDGPU_RAS_BLOCK__SDMA)`, call `amdgpu_irq_put(adev, &adev->sdma.ecc_irq, AMDGPU_SDMA_IRQ_INSTANCE0 + i)` for each target instance before halting. [F1802]
- Pair `amdgpu_vm_get_task_info_pasid` with `amdgpu_vm_put_task_info(task_info)` in `sdma_v4_0_print_iv_entry` and `sdma_v4_4_2_print_iv_entry`, and pair `amdgpu_gfx_off_ctrl(adev, false)` with `amdgpu_gfx_off_ctrl(adev, true)` around the register read loop in `sdma_v5_0_dump_ip_state`. [F1801, F1804]

## API Contracts
- `sdma_v4_0_query_ras_error_count_by_instance` and `sdma_v4_4_query_ras_error_count_by_instance` must initialize `sec_count = 0` before calling `get_ras_error_count`, add `sec_count` into the supported counter, and zero the unsupported counter (`err_data->ue_count` on v4.0, `err_data->ce_count` on v4.4); in `sdma_v4_4_query_ras_error_count_by_instance`, pass the unadjusted `regSDMA0_EDC_COUNTER` / `regSDMA0_EDC_COUNTER2` constant (not the local `reg_offset` variable) to `sdma_v4_4_get_ras_error_count`. [F1832, F1874]
- Under SR-IOV (`amdgpu_sriov_vf(adev)`), `psp_funcs.ring_set_wptr` (`psp_v3_1`, `psp_v13_0`, `psp_v13_0_4`, `psp_v14_0`) must write the DWord wptr to `C2PMSG_102` and `GFX_CTRL_CMD_ID_CONSUME_CMD` to `C2PMSG_101` (and in `psp_v3_1` set `psp->km_ring.ring_wptr = value`), whereas bare-metal writes `C2PMSG_67`. [F1924]
- In `psp_v13_0_update_spirom` and `psp_v14_0_update_spirom`, set `psp->vbflash_done = true` before issuing `C2PMSG_CMD_SPI_UPDATE_FLASH_IMAGE` so `amdgpu_psp_vbflash_status` tracks completion. [F1925]
- In `sdma_v5_0_ring_emit_fence`, emit `SDMA_OP_TRAP` only when `flags & AMDGPU_FENCE_FLAG_INT` is set, because `sdma_v5_0_ring_preempt_ib` calls it with `flags == 0` for a polled trailing fence. [F1931]

## Error Handling
- Callers of `sdma_v4_0_irq_id_to_seq` (`sdma_v4_0_process_trap_irq`, `sdma_v4_0_process_ras_data_cb`, `sdma_v4_0_process_illegal_inst_irq`, `sdma_v4_0_print_iv_entry`) must store its return value in a signed `int` and check `instance < 0` before indexing `adev->sdma.instance[instance]`. [F1824]
- In `sdma_v2_4_init_microcode` and `sdma_v3_0_init_microcode`, if `amdgpu_ucode_request` fails for any instance, jump to `out:` to call `amdgpu_ucode_release(&adev->sdma.instance[i].fw)` across all `adev->sdma.num_instances`. [F1795]
- In `sdma_v4_0`, `sdma_v4_4_2`, and `sdma_v5_0`, `dump_ip_state` and `print_ip_state` must check `if (!adev->sdma.ip_dump) return;` before dereferencing `ip_dump`; in `sdma_v2_4`, `sdma_v3_0`, `sdma_v4_0`, `sdma_v4_4_2`, and `sdma_v5_0`, `ring_insert_nop` and `ring_pad_ib` must null-check `sdma = amdgpu_sdma_get_instance_from_ring(ring)` before reading `sdma->burst_nop`. [F1827, F1828]
- Callers of `psp_v13_0_read_usbc_pd_fw` and `psp_v14_0_read_usbc_pd_fw` must check for a `0` return before reading `*fw_ver`; in `sdma_v4_0_process_ras_data_cb`, return `AMDGPU_RAS_SUCCESS` without calling `amdgpu_sdma_process_ras_data_cb` when `amdgpu_ras_is_supported(adev, AMDGPU_RAS_BLOCK__GFX)` is true. [F1825, F1935]

## External Contracts
- In `psp_v13_0_exec_spi_cmd`, `psp_v14_0_exec_spi_cmd`, `psp_v13_0_load_usbc_pd_fw`, and `psp_v14_0_load_usbc_pd_fw`, after polling bit 31 (`MBOX_READY_FLAG` / `0x80000000`) of the C2PMSG register, read the register and check `(reg_status & 0xFFFF) != 0` to detect PSP command errors. [F1869]
- In `psp_v3_1`, `psp_v13_0`, `psp_v13_0_4`, and `psp_v14_0`, 64-bit LFB/MC addresses written to `C2PMSG_36` (`psp->fw_pri_mc_addr`, `c2p_train_data_offset`, and `fw_pri_mc_addr` in `load_usbc_pd_fw`) must be 1 MB-aligned and right-shifted by 20 bits (`>> 20`); in `ring_create` under `amdgpu_sriov_vf(adev)`, stop any existing GPCOM ring via `ring_stop` before programming `C2PMSG_101`–`C2PMSG_103`. [F1833, F1911]
- Packet encodings across SDMA versions: `SDMA_OP_COPY`, `SDMA_OP_CONST_FILL`, `SDMA_OP_WRITE`, and `SDMA_OP_PTEPDE` use 0-based counts (`count - 1`, `byte_count - 1`, `ndw - 1`) in `sdma_v4_0`/`sdma_v4_4_2`/`sdma_v5_0` vs 1-based counts in `sdma_v2_4`/`sdma_v3_0`; across all five, `ring_insert_nop` and `ring_pad_ib` encode `SDMA_PKT_NOP_HEADER_COUNT(count - 1)` in the first NOP when `sdma->burst_nop` is true while still emitting `count` total dwords, and `ring_emit_ib` pads with `(2 - lower_32_bits(ring->wptr)) & 7` NOPs to 8-dword-align the 6-dword `SDMA_OP_INDIRECT` packet and masks `ib->gpu_addr` with `0xffffffe0`. [F1835, F1836, F1858]
- In `sdma_v4_0_wait_reg_mem` and `sdma_v4_4_2_wait_reg_mem`, DWord register offsets (`mem_space == 0`) are shifted left by 2 (`addr0 << 2`, `addr1 << 2`) for `SDMA_OP_POLL_REGMEM`, whereas memory addresses (`mem_space == 1`) are unshifted. [F1837]
- SDMA `*_RB_BASE`/`*_RB_BASE_HI` registers take 256-byte-aligned addresses (`gpu_addr >> 8`) and `RB_SIZE` takes `order_base_2(ring_size / 4)`; in `sdma_v4_0_load_microcode`, `sdma_v4_4_2_inst_load_microcode`, and `sdma_v5_0_load_microcode`, offset `fw->data` (`const u8 *`) by `le32_to_cpu(hdr->header.ucode_array_offset_bytes)` before casting to `const __le32 *` and iterate `le32_to_cpu(hdr->header.ucode_size_bytes) / 4` times. [F1884, F1888]
- Clearing EDC counters is a read-to-clear (`RREG32_SDMA(i, mmSDMA0_EDC_COUNTER)`) in `sdma_v4_0_reset_ras_error_count`, but requires writing `0` to both `regSDMA0_EDC_COUNTER` and `regSDMA0_EDC_COUNTER2` in `sdma_v4_4_reset_ras_error_count`; in `sdma_v4_0_process_trap_irq`, `page` ring traps use `entry->ring_id == 1` on `IP_VERSION(4, 2, 0)` and `entry->ring_id == 3` on other `sdma_v4_0` versions. [F1873, F1910]

## Known Pitfalls
- Across `sdma_v2_4`..`sdma_v5_0`, software ring pointers (`ring->wptr`, `get_rptr`, `get_wptr`) are in dwords while `RB_RPTR`/`RB_WPTR` registers, writeback slots, and doorbells use byte offsets (`<< 2` on write, `>> 2` on read); in `sdma_v4_0`, `sdma_v4_4_2`, and `sdma_v5_0` (`.support_64bit_ptrs = true`), shift the 64-bit dword pointer left by 2 before extracting `lower_32_bits`/`upper_32_bits` (not `upper_32_bits(ring->wptr) << 2`), and cast `u32 *` pointers (`ring->rptr_cpu_addr`, `ring->wptr_cpu_addr`, `&adev->wb.wb[...]`) to `u64 *` or `atomic64_t *` before dereferencing. [F1861, F1879, F1891]
- In `sdma_v4_4_2_process_trap_irq`, `sdma_v4_4_2_irq_id_to_seq(adev, entry->client_id)` returns only the intra-AID offset; step by `adev->sdma.num_inst_per_aid` until `adev->sdma.instance[i].aid_id == node_id_to_phys_map[entry->node_id]`. [F1846]
- Because `psp_v13_0_init_sos_version(psp)` overwrites `psp->sos.fw_version` with `RREG32_SOC15(MP0, 0, regMP0_SMN_C2PMSG_58)`, `psp_v13_0_is_reload_needed` must sample `psp->sos.fw_version` before calling `psp_v13_0_init_sos_version(psp)`. [F1851]
- In `sdma_v4_0_suspend` and `sdma_v4_0_resume`, when `adev->in_s0ix` is true, SMU saves/restores SDMA state, so `suspend` must only call `sdma_v4_0_gfx_enable(adev, false)` (not `hw_fini`) and `resume` must only unhalt and re-enable GFX RB/IB (not `hw_init`). [F1909]
- In `sdma_v4_0_print_iv_entry` and `sdma_v4_4_2_print_iv_entry`, cast `entry->src_data[0]` and `entry->src_data[1]` to `u64` before shifting left by 12 and 44. [F1881]
