# CRYPTO API — crypto (part 2)

This component provides the software async crypto daemon (`cryptd`), hardware crypto engine (`crypto_engine`), netlink configuration (`crypto_user`), FIPS management (`fips`), key-agreement primitives (`dh`, `ecdh`), and standard cipher modes, AEADs, MACs, KDFs, and compression/checksum algorithms (CBC, CTR, CTS, ECB, CCM, GCM, ChaCha, ChaCha20-Poly1305, CMAC, HMAC, HKDF, HCTR2, ESSIV, Echainiv, Geniv, Deflate, CRC32/CRC32C, CAST6, DES, FCrypt).

## Architecture & Data Flow
- `cryptd_skcipher_ctx`, `cryptd_hash_ctx`, and `cryptd_aead_ctx` must keep `refcount_t refcnt` as their first member so `cryptd_enqueue_request()` can cast `crypto_tfm_ctx(request->tfm)` to `refcount_t *` under `bh_lock`. `cryptd_*_init_tfm()` must size the parent request context to include both `cryptd_*_request_ctx` and the child's `reqsize`/`descsize` instead of using stack sub-requests in workers. [F193, F301]
- In `crypto/hmac.c`, `__hmac_create_shash()` and `hmac_create_ahash()` must set `cra_ctxsize` to `sizeof(struct hmac_ctx) + (ss * 2)` (or `ahash_hmac_ctx`) and enforce `ds <= cra_blocksize && ss >= cra_blocksize`. Both shash (`hmac_setkey`, `hmac_init`, `hmac_finup`) and ahash (`hmac_setkey_ahash`, `hmac_init_ahash`, `hmac_finup_finish`) store exported states of XORed `ipad` at `&tctx->pads[0]` and `opad` at `&tctx->pads[ss]` (`ss = statesize`) and must stay in lockstep. [F242, F303]
- In `essiv_aead_request_ctx` (`crypto/essiv.c`) and `hctr2_request_ctx` (`crypto/hctr2.c`), the variable-length subrequest (`aead_req` / union `u`) must be the last struct member and `reqsize` must include the child's `reqsize`/`descsize` so trailing data at `tctx->ivoffset` or `tctx->hashed_tweak_offset` never overlaps it. In `essiv_create()`, the `switch (type)` spawn setup (`crypto_spawn_skcipher_alg_common`), registration branch, and `out_drop_skcipher` error path on `ictx->u` must all test `CRYPTO_ALG_TYPE_LSKCIPHER` vs `CRYPTO_ALG_TYPE_AEAD` in lockstep. [F251, F274]
- In `crypto/ccm.c`, `crypto_ccm_init_crypt()` must validate `req->iv[0]` (`1..7`) via `crypto_ccm_check_iv()` before zeroing `iv + 15 - iv[0]` or calling `format_input()`. In `set_msg_len()`, `csize` must be clamped to `4` when `csize >= 4` before evaluating `1 << (8 * csize)`. In `crypto_rfc4309_encrypt()`/`decrypt()` (`ccm.c`) and `crypto_rfc4106_encrypt()`/`decrypt()` (`gcm.c`), `req->assoclen` must be validated as 16 or 20 before `crypto_rfc4309_crypt()` / `crypto_rfc4106_crypt()` copies `req->assoclen - 8` bytes past `iv`. [F264, F267, F293]
- In `essiv_aead_crypt()`, `int ssize = req->assoclen - crypto_aead_ivsize(tfm)` must be checked for `ssize < 0` at function start before passing `ssize` to `scatterwalk_map_and_copy()` or `sg_nents_for_len()`. In `echainiv_aead_create()`, reject `inst->alg.ivsize` if 0 or not a multiple of 8, and in `echainiv_encrypt()`/`decrypt()`, reject `req->cryptlen < ivsize` so `while ((ivsize -= 8))` and `req->cryptlen - ivsize` never underflow. [F265, F271]
- In `crypto/chacha20poly1305.c`, `chachapoly_create()` must reject `ivsize > CHACHAPOLY_IV_SIZE` so `ctx->saltlen` and `chacha_iv()` never underflow. `poly_genkey()` must verify `rctx->assoclen >= 8` before subtracting 8 when `ivsize == 8`. In `poly_hash()`, use `rctx->cryptlen` and `rctx->assoclen` (which exclude the 16-byte decrypt tag and 8-byte ESP IV), use `rctx->cryptlen == req->cryptlen` to distinguish encrypt from decrypt, and advance `scatterwalk_skip()` by `req->assoclen - rctx->assoclen`. [F266, F288]
- In `crypto_cts_encrypt()`/`decrypt()` (`cts.c`) and `hctr2_crypt()` (`hctr2.c`), verify `req->cryptlen` is at least one block (`nbytes < bsize` / `req->cryptlen < BLOCKCIPHER_BLOCK_SIZE`) before subtracting block size or computing `rounddown(nbytes - 1, bsize)`. In `crypto_cbc_decrypt_inplace()` (`cbc.c`), return early when `nbytes < bsize` (relying on `is_power_of_2(cra_blocksize)` in `crypto_cbc_create()`), and break from the reverse loop when `(nbytes -= bsize) < bsize` before reading `src - bsize`. [F268, F269]
- In `crypto/dh.c`, `__add_u64_to_be()` iterates with 1-based `for (i = n; val && i > 0; --i)` on `dst[i - 1]`, computing `u64` carry via `val = tmp >= val ? 0 : 1`. `dh_safe_prime_gen_privkey()` must allocate `n + 1` `__be64` words, call `h = __add_u64_to_be(key + 1, n, h)` twice during `2^N - 1` reduction, set `key[n] = cpu_to_be64(1)` if `__add_u64_to_be(key + 1, n, 1)` returns carry `o != 0`, and strip `key[0]` via `memmove(key, &key[1], *key_size)`. [F270, F295, F296]
- In `ecdh_set_secret()`, verify `params.key_size <= sizeof(u64) * ctx->ndigits` before `ecc_digits_from_bytes()`. In `ecdh_compute_value()`, shared-secret computation (`req->src != NULL`) must require `req->src_len == public_key_sz` (`2 * nbytes`) before copying into `public_key`, and output copying to `req->dst` must clamp `nbytes` to `min_t(size_t, nbytes, req->dst_len)`. [F255, F256]
- In `crypto/crypto_user.c`, `crypto_user_rcv_msg()` must verify `type <= CRYPTO_MSG_MAX` before subtracting `CRYPTO_MSG_BASE` to index `crypto_msg_min` or `crypto_dispatch`. Handlers reading `struct crypto_user_alg` (`crypto_report`, `crypto_update_alg`, `crypto_del_alg`, `crypto_add_alg`) must check `null_terminated(p->cru_name)` and `null_terminated(p->cru_driver_name)` before string calls or `crypto_alg_mod_lookup()`. In `crypto_dump_report()`, increment `pos` only after `crypto_report_alg()` succeeds; on `-EMSGSIZE`, break without incrementing `pos`, save `cb->args[0] = pos`, and return `skb->len`. [F260, F263, F290]
- `crypto/cast6_generic.c`, `crypto/chacha.c`, `crypto/crc32.c`, and `crypto/crc32c.c` register with `cra_alignmask = 0` and must use `get_unaligned_be32`/`put_unaligned_be32` or `get_unaligned_le32`/`put_unaligned_le32` on caller buffers. Subsystem helpers such as `crypto_engine` must not define private `cra_flags` bits outside `include/linux/crypto.h` (low bits like `CRYPTO_ALG_DUP_FIRST` at `0x200` are shared). [F275, F332]

## Synchronization
- In `crypto/cryptd.c`, `cryptd_enqueue_request()` and `cryptd_queue_worker()` must wrap `cpu_queue->queue` access in `local_bh_disable()` and `spin_lock(&cpu_queue->bh_lock)`, releasing `bh_lock` and re-enabling BH before `crypto_request_complete()`. Worker completions in `cryptd_skcipher_complete()`, `cryptd_hash_complete()`, and `cryptd_aead_crypt()` must wrap `*_request_complete()` in `local_bh_disable()` / `local_bh_enable()`. [F192, F321]
- In `crypto/crypto_engine.c`, `engine->queue_lock` must use `spin_lock_irqsave()` / `spin_unlock_irqrestore()` around `engine->queue`, `running`, `busy`, and `cur_req`, and be released before `op->do_one_request()`, `crypto_request_complete()`, or `msleep()`. In `crypto_pump_requests()`, re-acquire `engine->queue_lock` after `op->do_one_request()` before jumping to `start_request` or `out` (on `-ENOSPC` requeue), and skip backlog `-EINPROGRESS` completion when requeuing on `-ENOSPC`. [F281, F323]
- When `!engine->retry_support`, `crypto_pump_requests()` sets `engine->cur_req` and stops dequeuing while `cur_req != NULL`, so `crypto_finalize_request()` must clear `engine->cur_req = NULL` under `engine->queue_lock` before queuing `pump_requests`. `engine->busy` is only cleared in `crypto_pump_requests()` when `in_kthread` is true and the queue is empty or `!engine->running`. `crypto_engine_stop()` must re-verify `!crypto_queue_len(&engine->queue) && !engine->busy` under `queue_lock` after its `msleep(20)` loop before clearing `engine->running`; `crypto_engine_exit()` must not destroy `engine->kworker` if `crypto_engine_stop()` fails. [F232, F233, F282]
- In `crypto/crypto_user.c`, `crypto_netlink_rcv()` serializes on `crypto_cfg_mutex` and replies via `sock_net(skb->sk)->crypto_nlsk`. `crypto_alg_match()` must pin `alg` with `crypto_mod_get(q)` under `down_read(&crypto_alg_sem)`, and callers must release it with `crypto_mod_put(alg)`. `crypto_update_alg()` must call `crypto_remove_spawns(alg, &list, NULL)` and update `alg->cra_priority` under `down_write(&crypto_alg_sem)`, then unlock and `crypto_mod_put(alg)` before `crypto_remove_final(&list)`. [F201, F252, F343]
- In `crypto/deflate.c`, `deflate_init()` must hold `deflate_stream_lock` around `crypto_acomp_alloc_streams(&deflate_streams)`, `deflate_compress()`/`decompress()` must bracket stream access with `crypto_acomp_lock_stream_bh()` / `unlock_stream_bh()`, and `deflate_mod_fini()` must unregister `acomp` before freeing `deflate_streams`. [F205]
- In async continuation callbacks (`async_done_continue` in `chacha20poly1305.c`, `hmac_finup_done` in `hmac.c`, `crypto_ccm_decrypt_done` in `ccm.c`, `gcm_*_done` in `gcm.c`), clear `CRYPTO_TFM_REQ_MAY_SLEEP` from flags passed to the next subrequest. In `crypto/fips.c`, `fips_fail_notif_chain` is an `ATOMIC_NOTIFIER_HEAD`, so callbacks must not sleep. [F248, F330]

## Object Lifetimes
- In `cryptd_enqueue_request()`, `cryptd_skcipher_complete()`, `cryptd_hash_complete()`, and `cryptd_aead_crypt()`, `ctx->refcnt` is only adjusted when non-zero; read `ctx->refcnt` before `*_request_complete()` (which may free a zero-refcnt `tfm`) and do not decrement on `err == -EINPROGRESS`. In `cryptd_exit()`, call `destroy_workqueue(cryptd_wq)` before `cryptd_fini_queue(&queue)`. [F176, F195]
- `dh_set_secret()` must call `dh_clear_ctx(ctx)` both before decoding a new key and on its `err_clear_ctx` path so `ctx->p`, `ctx->g`, and `ctx->xa` are freed and zeroed. Multi-transform `init_tfm` callbacks (`crypto_ccm_init_tfm`, `crypto_gcm_init_tfm`, `hctr2_init_tfm`, `essiv_*_init_tfm`) must free already-spawned child transforms in reverse order on error because `exit_tfm` is not called when `init_tfm` fails. [F178, F188]

## API Contracts
- `cryptd_skcipher_child()`, `cryptd_ahash_child()`, and `cryptd_aead_child()` return a borrowed pointer to `ctx->child` freed in `cryptd_*_exit_tfm()`; callers must not `crypto_free_*()` it. `crypto_finalize_request()` and `crypto_finalize_*_request()` must be called in softirq (BH-disabled) context. Every algorithm queued onto `crypto_engine` must be embedded in `struct *_engine_alg` registered via `crypto_engine_register_*()` with non-NULL `op.do_one_request`. [F177, F322, F331]
- Template `.setkey` callbacks (`essiv_skcipher_setkey`, `hctr2_setkey`, `crypto_cts_setkey`, `crypto_rfc3686_setkey`, `chachapoly_setkey`, `cryptd_skcipher_setkey`) must sync `CRYPTO_TFM_REQ_MASK` from parent to child before calling child `setkey`. When a template looks up an auxiliary alg via `crypto_alg_mod_lookup()` (like `essiv_create()` for `shash_name`), it must pass `crypto_algt_inherited_mask(algt)` and OR `alg->cra_flags & CRYPTO_ALG_INHERITED_FLAGS` into `inst->alg.base.cra_flags`. [F335, F338]
- In `crypto/hmac.c` (`hmac_import*`) and `crypto/cryptd.c` (`cryptd_hash_import`), explicitly bind the child transform (`desc->tfm` or `ahash_request_set_tfm`) before calling child import. `hmac_setkey()` and `hmac_setkey_ahash()` must reject `keylen < 14` with `-EINVAL` when `fips_enabled` is true. [F243, F350]
- In `crypto/cbc.c` and `crypto/ecb.c`, lskcipher `encrypt`/`decrypt` return residual bytes `rem` (`< bsize`) when `!(flags & CRYPTO_LSKCIPHER_FLAG_FINAL)`, and `-EINVAL` for non-zero residual when `CRYPTO_LSKCIPHER_FLAG_FINAL` is set. Templates using `lskcipher_alloc_instance_simple()` that pass `NULL` state to `crypto_lskcipher_encrypt()`/`decrypt()` (`crypto_cbc_create()`) must reject non-zero `inst->alg.co.statesize`. `CRYPTO_AHASH_ALG_BLOCK_ONLY` shashes (`cbcmac`, `cmac`, `ghash`) must return unconsumed trailing bytes (`< bs`) from `.update`. [F225, F226, F333]
- In `crypto/cipher.c`, `crypto_cipher_setkey()` and `cipher_crypt_one()` must bounce `key`, `dst`, or `src` through an `(alignmask + 1)`-aligned buffer when misaligned against `crypto_cipher_alignmask(tfm)`. [F272]
- `__crypto_dh_decode_key()`, `crypto_dh_decode_key()`, and `crypto_ecdh_decode_key()` point `params` fields directly into caller's `buf` (do not `kfree()`). `crypto_dh_encode_key()` must pack all fields via `dh_pack_data(ptr, end, ...)` and verify `ptr == end`. `crypto_dh_decode_key()` must reject `key_size > p_size`, `g_size > p_size`, or all-zero `params->p`, while `dh_safe_prime_set_secret()` uses `__crypto_dh_decode_key()` and requires `p_size == 0 && g_size == 0`. `dh_check_params_length()` takes bit length (`params->p_size << 3`) and requires `>= 2048` bits in FIPS mode or `>= 1536` otherwise. [F213, F258, F345, F346]
- In `crypto_ecdh_decode_key()`, check `len` against both `ECDH_KPP_SECRET_MIN_SIZE` and `secret.len`, and verify `secret.len == crypto_ecdh_key_len(params)`. Each curve `struct kpp_alg` in `crypto/ecdh.c` must have a unique `base.cra_driver_name`. In `dh_compute_value()` and `ecdh_compute_value()`, `req->src == NULL` selects public-key generation vs shared-secret computation; in `dh_compute_value()`, `base` aliases `ctx->g` when `req->src == NULL` and must only be `mpi_free(base)`d when `req->src != NULL`. [F211, F254, F334]

## Error Handling
- In `crypto/dh.c`, check the return value of every `mpi_rshift()` and `mpi_sub_ui()` before `mpi_powm()` or `mpi_cmp()`, and in `dh_compute_value()`, convert `sign < 0` from `mpi_write_to_sgl()` to `-EBADMSG`. In `crypto/ecdh.c`, `ecdh_init()` must tolerate `crypto_register_kpp(&ecdh_nist_p192)` failing (rejected in FIPS mode) and only unregister it in `ecdh_exit()` if `ecdh_nist_p192_registered` is true. [F209, F210, F349]
- In `essiv_aead_crypt()`, initialize `rctx->assoc = NULL` before branching on `req->src == req->dst || !enc`, freeing it synchronously only when `err != -EINPROGRESS && err != -EBUSY` and in `essiv_aead_done()` when `err != -EINPROGRESS`. In async continuation callbacks preserving `CRYPTO_TFM_REQ_MAY_BACKLOG` (`hmac_finup_done`, `crypto_cts_encrypt_done`, `crypto_cts_decrypt_done`, `async_done_continue`), do not complete the parent request when the continuation returns `-EINPROGRESS` or `-EBUSY`. [F224, F284]
- In `des_setkey()` and `des3_ede_setkey()`, map `-ENOKEY` from `des*_expand_key()` to `-EINVAL` if `CRYPTO_TFM_REQ_FORBID_WEAK_KEYS` is set and `0` otherwise, zeroing `dctx` on error. In `hmac_update_ahash()` and `hmac_finup_ahash()`, check `ahash_request_isvirt(preq)` to choose `ahash_request_set_virt(req, preq->svirt, ...)` vs `ahash_request_set_crypt(req, preq->src, ...)`. [F227, F228]

## External Contracts
- In `crypto/crypto_user.c`, every mutating `NETLINK_CRYPTO` handler (`crypto_update_alg`, `crypto_del_alg`, `crypto_add_alg`, `crypto_del_rng`) must check `netlink_capable(skb, CAP_NET_ADMIN)` and return `-EPERM` before any lookup or state change. [F339]

## Known Pitfalls
- In `crypto_ccm_req_priv_ctx`, `crypto_gcm_req_priv_ctx`, and `hctr2_request_ctx`, the hash and cipher subrequests share union `u` and must be strictly serialized and re-initialized before each stage. In `crypto_rfc4106_crypt()`, `crypto_rfc4543_crypt()`, `crypto_rfc4309_crypt()`, and `crypto_cts_reqctx_space()`, offset trailing scratch space past `subreq` by the child's `reqsize` (`crypto_aead_reqsize(child)` / `crypto_skcipher_reqsize(child)`), never the parent's. [F229, F287]
- In `crypto/cts.c`, when `nbytes > bsize`, `crypto_cts_decrypt()` must copy the IV for the final two blocks into `crypto_cts_reqctx_space(req)` (`req->iv` if `offset <= bsize`, else `req->src` at `offset - 2 * bsize`) before `crypto_skcipher_decrypt(subreq)` runs. In `crypto/ccm.c`, `crypto_ccm_decrypt()` must copy `req->iv` into `pctx->idata` for `skcipher_request_set_crypt()`, preserving `req->iv` for `crypto_ccm_auth()`. In `echainiv_encrypt()`, read the 64-bit sequence number from `info + ivsize - 8` (`info = req->iv`) before zeroing `info`, copying it to `req->dst`, and overwriting `info` with salt words. [F245, F246, F247]
- In `hmac_setkey_ahash()`, bind `HASH_REQUEST_ON_STACK(req, fb)` to the synchronous fallback `fb = crypto_ahash_fb(tctx->hash)`, not `tctx->hash` or `parent`. In `crypto_cmac_digest_setkey()`, cast `_const[1]` or `_const[0]` to signed `s64` before `>> 63` for `msb_mask`, while keeping `_const[0] >> 63` unsigned in `(_const[1] << 1) | (_const[0] >> 63)`. In `crypto/deflate.c`, `deflate_streams.free_ctx` must use wrapper `deflate_free_stream(void *)` rather than casting `kvfree`. [F292, F297, F302]
