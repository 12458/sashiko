# INTEL DRM XE DRIVER (Lunar Lake and newer) — drivers/gpu/drm/xe (part 8)

This unit implements GPU Virtual Memory (`xe_vm`, `xe_vm_madvise`), userptr mappings (`xe_userptr`), BO residency validation (`xe_validation`), TTM managers (`xe_ttm_vram_mgr`, `xe_ttm_stolen_mgr`, `xe_ttm_sys_mgr`), VRAM BAR probing (`xe_vram`), TLB invalidation and dependency jobs (`xe_tlb_inval`, `xe_tlb_inval_job`), microcontroller firmware loading (`xe_uc`, `xe_uc_fw`), tile sysfs/debugfs/SR-IOV VF support, performance tunings (`xe_tuning`), Intel VSEC telemetry (`xe_vsec`), and tracepoints.

## Architecture & Data Flow

- `xe_vma_is_userptr()` identifies `struct xe_userptr_vma` by `!xe_vma_bo(vma) && !xe_vma_is_null(vma) && !xe_vma_is_cpu_addr_mirror(vma)`: `xe_vma_create()` must set `DRM_GPUVA_SPARSE`, `XE_VMA_SYSTEM_ALLOCATOR`, or `gpuva.gem.obj` before any error calls `xe_vma_free()`, and callers must check `xe_vma_is_userptr()` (not just `xe_vma_has_no_bo()`) before `to_userptr_vma()`. [F1285]
- Every `DRM_GPUVA_OP_REMAP` handler (`vm_bind_ioctl_ops_parse`, `xe_vma_op_commit`, `xe_vma_op_unwind`, `op_lock_and_prep`, `op_trace`, `op_add_ufence`) must check `op->remap.prev` and `op->remap.next` with independent `if` statements (never `else if`), and when `skip_prev` or `skip_next` is true in `vm_bind_ioctl_ops_parse`, the split VMA must inherit `xe_vma_max_pte_size(old)` via `xe_vma_set_pte_size()` while shrinking `op->remap.start` and `op->remap.range`. [F1308, F1344]
- In `madvise_atomic`, changing atomic access on a BO-backed VMA must update both `vmas[i]->attr.atomic_access` and `bo->attr.atomic_access`, set `vmas[i]->skip_invalidation = false`, and call `ttm_bo_unmap_virtual(&bo->ttm)` if the BO is in VRAM and the new policy is `DRM_XE_ATOMIC_CPU` or `DRM_XE_ATOMIC_GLOBAL`. [F1310]
- `vm->preempt.num_exec_queues` must match the queue count on `vm->preempt.exec_queues`; `xe_vm_remove_compute_exec_queue` must only decrement `num_exec_queues` when `!list_empty(&q->lr.link)` and unlink with `list_del_init(&q->lr.link)`. [F1313]
- During GT reset, `xe_tlb_inval_reset` must under `seqno_lock` and `pending_lock` cancel `fence_tdr`, advance `seqno_recv` to `tlb_inval->seqno - 1` (wrapping `1` to `TLB_INVALIDATION_SEQNO_MAX - 1`), and signal all `pending_fences`. Because `xe_tlb_inval_fence_prep` appends fences in `seqno`/`inval_time` order under `seqno_lock`, `xe_tlb_inval_fence_timeout` and `xe_tlb_inval_done_handler` must iterate `pending_fences` with `list_for_each_entry_safe` and `break` at the first non-expired or future-seqno fence. [F1316, F1348]
- `struct xe_tlb_inval_fence` must keep `struct dma_fence base` at offset 0 and any non-stack (`stack == false`) instance must be a standalone slab allocation (`inval_fence_ops` omits `.release`, so `dma_fence_release()` calls `kfree_rcu(&fence->base)`). Likewise, `struct kobj_tile` must keep `struct kobject base` at offset 0 because `xe_tile_sysfs_kobj_release()` passes `kobj` directly to `kfree()`. [F1369, F1371]
- In `xe_vm_create_scratch()` and `xe_vm_free_scratch()`, `vm->scratch_pt[id][i]` is indexed by page-table level `i` in `[MAX_HUGEPTE_LEVEL, vm->pt_root[id]->level)`, leaving indices below `MAX_HUGEPTE_LEVEL` as `NULL`. [F1342]
- In `xe_vram_probe()`, `remain_io_size` must be decremented by `min_t(u64, tile->mem.vram->actual_physical_size, remain_io_size)` after each tile, and `vram_region_init()` must clamp `vram->io_size` to `min_t(u64, usable_size, remain_io_size)`. [F1340]
- Firmware tables (`XE_GUC_FIRMWARE_DEFS`, `XE_HUC_FIRMWARE_DEFS`, `XE_GSC_FIRMWARE_DEFS`) in `xe_uc_fw.c` must be ordered in descending `enum xe_platform` order with newer versions first (`uc_fw_auto_select` loops while `p <= entries[i].platform` and breaks on first match). In `xe_vsec.c`, `bmg_capabilities[]` (and any `intel_vsec_platform_info.headers` table) must end with `NULL`, and `get_platform_info()` must bounds-check `xe->info.platform` against `vsec_platforms[]`. [F1341, F1350]

## Synchronization

- Lock order across VM and validation paths is `vm->lock` -> `xe_validation_device.lock` (`val->lock`) -> `drm_exec` (`dma_resv`) locks -> `vm->svm.gpusvm.notifier_lock` -> `vm->userptr.invalidated_lock`. In `xe_validation_should_retry`, callers must run `drm_exec_fini(ctx->exec)` before unlocking and re-locking `ctx->val->lock` for exclusive mode, and run `drm_exec_init(ctx->exec, ...)` afterward even if relocking fails so `xe_validation_ctx_fini` can safely tear down `ctx`. [F1258, F1279]
- Modifying `vm->validation.validating` (`xe_vm_set_validating` / `xe_vm_clear_validating` via `WRITE_ONCE`) and calling `xe_vm_set_validation_exec(vm, &exec)` both require holding `xe_vm_resv(vm)`, and must be cleared (`xe_vm_clear_validating`, `xe_vm_set_validation_exec(vm, NULL)`) before releasing `drm_exec` or `xe_vm_resv(vm)`. [F1265, F1407]
- `xe_vm_has_valid_gpu_mapping` reads `tile_present` and `tile_invalidated` via `READ_ONCE` and is only advisory unless holding `vm->svm.gpusvm.notifier_lock` (for userptr/SVM) or the BO `dma_resv` lock (for BOs); zapping PTEs of a non-mirror VMA in `xe_zap_ptes_in_madvise_range` or `xe_vm_invalidate_vma` must update `vma->tile_invalidated` via `WRITE_ONCE`. [F1284, F1311]
- `xe_vma_userptr_check_repin` and `xe_vm_userptr_check_repin` are lockless advisory checks (`mmu_interval_check_retry` and `list_empty_careful`) and must be rechecked under `vm->svm.gpusvm.notifier_lock` (`__xe_vm_userptr_needs_repin`) or `vm->lock` (`xe_vm_userptr_pin`). [F1283]
- `xe_vm_insert_vma` and `xe_vm_remove_vma` require holding both `vm->lock` and `vm->snap_mutex` (so `xe_vm_snapshot_capture` and `xe_vm_validate_protected` can iterate `vm->gpuvm` under `vm->snap_mutex` alone), and `xe_vm_remove_vma` must clear `vm->usm.last_fault_vma` if it matches. `xe_vm_snapshot_capture` must use `GFP_NOWAIT` and only take references (`xe_bo_get` or `mmget_not_zero`) under `vm->snap_mutex`, deferring `GFP_USER` allocations, `xe_bo_read`, and `copy_from_user` (under `kthread_use_mm`/`kthread_unuse_mm` and `mmput`) to `xe_vm_snapshot_capture_delayed`. [F1275, F1397]
- In `xe_vm_create_ioctl`, publishing `vm` into `xef->vm.xa` via `xa_alloc` must be the final fallible step after `xe_vm_create`. During teardown in `xe_vm_close_and_put`, `xe_vm_close` must set `vm->size = 0` under `vm->lock` (write) and release `vm->lock` before removing `vm->preempt.pm_activate_link` under `xe->rebind_resume_lock` and calling `flush_work(&vm->preempt.rebind_work)` (which acquires `vm->lock` in write mode). [F1267, F1272]
- Because `xe_tlb_inval_done_handler` runs in IRQ context and takes `tlb_inval->pending_lock` with `spin_lock_irqsave`, all process/worker callers (`xe_tlb_inval_fence_prep`, `xe_tlb_inval_fence_timeout`, `xe_tlb_inval_reset`, `xe_tlb_inval_fence_signal_unlocked`) must disable IRQs when locking `pending_lock`. [F1398]

## Object Lifetimes

- `xe_tlb_inval_fence_init` takes a runtime PM reference via `xe_pm_runtime_get_noresume` that is only released by `xe_tlb_inval_fence_fini` when signaled, so every initialized `xe_tlb_inval_fence` must be signaled and clear `fence->tlb_inval = NULL` on finalization. In `xe_tlb_inval_job_destroy`, `job->fence` (`ifence`) is raw `kmalloc` memory until `xe_tlb_inval_job_push` sets `job->fence_armed = true` and initializes the fence, so `xe_tlb_inval_job_destroy` must call `kfree(ifence)` when `!job->fence_armed` and `dma_fence_put(job->fence)` when `job->fence_armed`. [F1251, F1252]
- When destroying a userptr VMA, `XE_VMA_DESTROYED` must be set under `xe_svm_notifier_lock` and `xe_userptr_destroy` called under `vm->lock` in `xe_vma_destroy`, while `xe_userptr_remove` (`mmu_interval_notifier_remove`) must wait until `xe_vma_destroy_late` after the unbind `fence` signals. [F1271]
- For `XE_VM_FLAG_LR_MODE` VMs, `xe_vm_create()` acquires a runtime PM reference (`xe_pm_runtime_get_noresume(xe)`) that must be released in `vm_destroy_work_func()` or `err_no_resv`. In `xe_vm_close()`, `xe_pt_clear()` and `xe_tlb_inval_vm()` must be guarded with `drm_dev_enter(&xe->drm, &idx)` / `drm_dev_exit(idx)`. [F1391, F1393]
- Because `xe_vram_region` structs use `drmm_kzalloc()` while `lmem_bar.mapping` uses `devm_ioremap_wc()`, `xe_vram_probe()` must register `vram_fini()` via `devm_add_action_or_reset()` to clear `xe->mem.vram->mapping` and each `tile->mem.vram->mapping` to `NULL` on unbind. [F1381]

## API Contracts

- Before calling `xe_tlb_inval_job_push` with an unsignaled `@fence`, the caller must call `xe_tlb_inval_job_alloc_dep` once to preallocate dependency xarray slot 0 with `dma_fence_get_stub()`, and `xe_tlb_inval_job_push` must take the caller's reference on `&job->dep.drm.s_fence->finished` before `drm_sched_entity_push_job`. [F1253]
- `ops_execute()` returns `ERR_PTR(-ENODATA)` when committed VMA ops need no PT updates (`number_tiles == 0`): `vm_bind_ioctl_ops_execute()` must call `vm_bind_ioctl_ops_fini(vm, vops, NULL)` on `-ENODATA`, and `xe_vm_bind_ioctl()` must skip `vm_bind_ioctl_ops_unwind()` and call `vm_bind_ioctl_signal_fences()`. [F1288]
- `xe_vma_end()` and `drm_gpuva` ops use exclusive end addresses (`start + range`), whereas `xe_vma_create()` requires an inclusive `end` (`start + range - 1`, asserting `end < vm->size`). `xe_vma_need_vram_for_atomic()` returns a tri-state `int` (`1` for VRAM, `0` when not needed, `-EACCES` when `DRM_XE_ATOMIC_CPU` forbids GPU atomics) that must be checked for `< 0` before boolean use. [F1289, F1290]
- Non-leaf PDEs encode only two PAT bits (`BIT(0)` and `BIT(1)` in `pde_encode_pat_index()`), so `pde_pat_index()` asserts `pat_index <= 3`; `xelp_pte_encode_addr()` asserts `!(flags & ~XE_PTE_PS64)`. [F1304]
- `uc_fw_request()` returns `0` with `*firmware_p == NULL` on SR-IOV VFs or when uC firmware is unsupported/disabled, so `xe_uc_fw_init()` must initialize `fw = NULL` and return `0` if `!fw` before `uc_fw_copy()`. `xe_uc_fw_copy_rsa()` requires `xe_uc_fw_is_available(uc_fw)` and `min_t(u32, uc_fw->rsa_size, max_len)` to be 4-byte aligned. [F1300, F1327]
- On integrated platforms with `GRAPHICS_VERx100(xe) < 1270` (`xe_ttm_stolen_cpu_access_needs_ggtt(xe)`), `xe_ttm_stolen_mgr_init()` must leave `io_size = 0` and skip `devm_ioremap_wc()`, and CPU access in `__xe_ttm_stolen_io_mem_reserve_stolen()` requires `XE_BO_FLAG_GGTT` on the BO. [F1390]

## Error Handling

- In `xe_vm_userptr_pin`, a userptr VMA failing `xe_vma_userptr_pin_pages` with `-EFAULT` must be removed from `vm->rebind_list`, and on any error all remaining entries on `vm->userptr.repin_list` must be spliced back to `vm->userptr.invalidated` under `notifier_lock` and `invalidated_lock`. [F1256]
- If `xe_pt_create` returns an `ERR_PTR` for `vm->pt_root[id]` or `vm->scratch_pt[id][i]` in `xe_vm_create` / `xe_vm_create_scratch`, that slot must be reset to `NULL` before `xe_vm_free_scratch` or `xe_vm_pt_destroy`. Similarly, in `xe_vm_bind_ioctl`, if `vm_bind_ioctl_ops_create` returns an `ERR_PTR` for `ops[i]`, reset `ops[i] = NULL` before `unwind_ops`, and `vm_bind_ioctl_ops_unwind` must unwind in reverse (`num_ops_list - 1` down to `0` and `drm_gpuva_for_each_op_reverse`) whenever `err && err != -ENODATA`. [F1261, F1264]
- In `xe_vm_madvise.c`, `get_vmas()` frees `madvise_range->vmas` without clearing the pointer when `krealloc()` fails or `madvise_range->num_vmas == 0`, so `xe_vm_madvise_ioctl()` must jump past `err_fini` (`kfree(madvise_range.vmas)`) whenever `err || !madvise_range.num_vmas`. [F1302]
- In `parse_headers` (`xe_uc_fw.c`), `XE_UC_FW_TYPE_HUC` must only fall through to `XE_UC_FW_TYPE_GUC` (`parse_css_header`) when `parse_cpd_header` returns `-ENOENT`; `0` or any other negative error must return immediately. [F1351]

## External Contracts

- In `parse_css_header()`, validate `fw_size` against `sizeof(struct uc_css_header) + uc_fw->ucode_size + uc_fw->rsa_size` (where `ucode_size = (css->size_dw - css->header_size_dw) * sizeof(u32)`) rather than `css->size_dw * sizeof(u32)`, because `header_size_dw` and `size_dw` include `modulus_size_dw` and `exponent_size_dw` even when truncated. In `struct gsc_cpd_entry`, mask `entry->offset` with `GSC_CPD_ENTRY_OFFSET_MASK` (`GENMASK(24, 0)`) and bounds-check against remaining blob size. [F1325, F1326]
- In `xe_vm_bind_ioctl_validate_bo()`, when a BO has `XE_BO_FLAG_INTERNAL_64K` on a platform with `XE_VRAM_FLAGS_NEED64K`, `obj_offset`, `addr`, and `range` must all be 64KiB-aligned (`!(val & XE_64K_PAGE_MASK)`). [F1330]
- Userspace `pat_index` in `vm_bind_ioctl_check_args()` (rejecting `xe_pat_index_get_coh_mode() == 0` with `-EINVAL`) and `args->type` in `xe_vm_madvise_ioctl()` must be bounds-checked and clamped with `array_index_nospec()`. In `xe_vm_query_vmas_attrs_ioctl()`, require `vector_of_mem_attr == 0` and `sizeof_mem_range_attr == 0` when `num_mem_ranges == 0`, require `sizeof_mem_range_attr == sizeof(struct drm_xe_mem_range_attr)` when `num_mem_ranges > 0`, and return `-ENOSPC` from `get_mem_attrs()` if VMA count exceeds `*num_vmas`. [F1333, F1335]

## Known Pitfalls

- Union aliasing across VM types: in `struct xe_vma`, `combined_links.rebind` and `combined_links.destroy` alias, so `xe_vm_close_and_put` must `list_del_init` on `rebind` (or `destroy` when draining `contested`) before calling `xe_vma_destroy` / `xe_vma_destroy_unlocked`; `destroy_cb` and `destroy_work` also alias, so `INIT_WORK(&vma->destroy_work, ...)` must wait until `vma_destroy_cb()` runs (or when no fence callback is registered). In `struct xe_vma_op`, `prefetch` and `prefetch_range` alias, and `op->prefetch_range.range` is only initialized when `op->base.op == DRM_GPUVA_OP_PREFETCH` and `xe_vma_is_cpu_addr_mirror(vma)`. [F1352, F1374, F1375]
- In `vm_bind_ioctl_check_args()` and `xe_vm_bind_ioctl()`, `bind_ops` is heap-allocated only when `args->num_binds > 1` and aliases inline `&args->bind` otherwise, so guard `kvfree(bind_ops)` with `if (args->num_binds > 1)`. In `madvise_args_are_sane()`, cast `args->preferred_mem_loc.devmem_fd` (`__u32`) to `s32` before comparing against `DRM_XE_PREFERRED_LOC_DEFAULT_SYSTEM` (`-1`). [F1331, F1334]
- Overflow and shift pitfalls: VA space sizes in `xe_vm_create()` and `xe_tlb_inval_vm()` must use `1ull << xe->info.va_bits`; range checks in `xe_vm_bind_ioctl()`, `xe_vm_bind_ioctl_validate_bo()`, and `xe_tile_sriov_vf_balloon_ggtt_locked()` must verify `range <= limit` before comparing against `limit - range`; and `xe_ttm_sys_mgr_init()` must cast `si.totalram` to `u64` before multiplying by `si.mem_unit`. [F1362, F1365, F1366]
- Unit mismatches in TTM and uC firmware: in `xe_ttm_sys_mgr.c`, `man->size` is in pages (`gtt_size >> PAGE_SHIFT`, so shift left by `PAGE_SHIFT` against byte `ttm_resource_manager_usage(man)`) and `xe_ttm_sys_mgr_new()` must set `mm_nodes[0].size = PFN_UP(node->base.base.size)`, whereas in `xe_ttm_vram_mgr.c`, `man->size` is in bytes (shift right by `PAGE_SHIFT` against PFNs). In `xe_uc_fw.c`, CSS `*_dw` fields are in dwords (multiply by `sizeof(u32)` for bytes) while `gsc_cpd_header_v2.header_length` and `gsc_cpd_entry.offset` are in bytes, and offsets into `uc_fw->bo` for CSS headers (`uc_fw_xfer()`) or RSA keys (`xe_uc_fw_rsa_offset()`) must add `uc_fw->css_offset`. [F1367, F1376, F1377, F1379]
