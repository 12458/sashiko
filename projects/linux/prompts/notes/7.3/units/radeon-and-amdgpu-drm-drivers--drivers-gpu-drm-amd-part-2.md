# RADEON and AMDGPU DRM DRIVERS — drivers/gpu/drm/amd (part 2)

This unit comprises the Vega20 Interrupt Handler (`vega20_ih.c`), Volcanic Islands SoC common driver (`vi.c`), Video Processing Engine v6.1 backend (`vpe_v6_1.c`, `vpe_6_1_fw_if.h`), the standalone `amdxcp` platform DRM device allocator (`amdgpu_xcp_drv.c`), and shared AMD headers for ACPI ATIF/ATCS (`amd_acpi.h`), UEFI CPER error records (`amd_cper.h`), PCIe helpers (`amd_pcie*.h`), sysfs register state dumps (`amdgpu_reg_state.h`), IP blocks (`amd_shared.h`), and Aldebaran/Arcturus IP register base offsets.

## Architecture & Data Flow

- In `vega20_ih_toggle_ring_interrupts()` and `vega20_ih_get_wptr()`, clearing an IH ring overflow via `IH_RB_CNTL__WPTR_OVERFLOW_CLEAR` requires transitioning `WPTR_OVERFLOW_CLEAR` from 0 to 1 and immediately clearing it back to 0; `vega20_ih_get_wptr()` must also advance `ih->rptr` to `(wptr + 32) & ih->ptr_mask`. [F2085]
- In `vega20_ih.c`, `vega20_ih_rb_cntl` sets `IH_RB_CNTL.MC_SPACE` to `1` (GPA/bus address) when `ih->use_bus_addr` is true and `4` (GPU VM/GART) when false; on non-VF devices (for OSSSYS 4.2.1 direct load, 4.4.0, 4.4.2, and 4.4.5), `vega20_ih_irq_init` must set `IH_CHICKEN.MC_SPACE_GPA_ENABLE = 1` in `mmIH_CHICKEN` / `mmIH_CHICKEN_ALDEBARAN` when `adev->irq.ih.use_bus_addr` is true. [F2143]
- In `vega20_ih_irq_rearm`, the loop polling `ih_regs->ih_rb_rptr` and re-writing `WDOORBELL32(ih->doorbell_index, ih->rptr)` while `(v < ih->ring_size) && (v != ih->rptr)` must remain bounded to `MAX_REARM_RETRY` (10) iterations and break immediately once `ih_rb_rptr` matches `ih->rptr` or is out of range. [F2107]
- In `vpe_v6_1_load_microcode()`, when `adev->firmware.load_type == AMDGPU_FW_LOAD_PSP`, only master instance 0's `regVPEC_F32_CNTL` offset and value may be placed in `adev->vpe.cmdbuf_cpu_addr[0..1]` because PSP updates slave instances. When `load_type != AMDGPU_FW_LOAD_PSP` (direct load), the driver must iterate across all `vpe->num_instances` and convert `vpe_firmware_header_v1_0` ucode offsets/sizes and each dword written to `regVPEC_UCODE_DATA` from little-endian via `le32_to_cpu` and `le32_to_cpup`. [F2087, F2095]
- `vi_get_register_value` must only be called with a `reg_offset` matched against `vi_allowed_read_registers[]` in `vi_read_register`. When `indexed` is true, it must map the broadcast sentinel `0xffffffff` for `se_num` or `sh_num` to index `0` before indexing `adev->gfx.config.rb_config[se_idx][sh_idx]`, and any `mmGB_TILE_MODE*` / `mmGB_MACROTILE_MODE*` offsets must stay within `tile_mode_array` (32) and `macrotile_mode_array` (16) bounds. [F2097]
- In `vi.c`, when `adev->flags & AMD_IS_APU` is set, `vi_common_early_init` binds `adev->smc_rreg`/`smc_wreg` to `cz_smc_rreg`/`cz_smc_wreg`, and `vi_read_bios_from_rom`, `vi_asic_reset`, `vi_enable_doorbell_aperture`, `vi_get_pcie_usage`, and `vi_need_reset_on_init` must return early. [F2134]
- In `vi_asic_pci_config_reset`, PCI bus mastering must be cleared via `pci_clear_master(adev->pdev)` before `amdgpu_device_pci_config_reset(adev)`, and only re-enabled via `pci_set_master(adev->pdev)` once `RREG32(mmCONFIG_MEMSIZE) != 0xffffffff` within `adev->usec_timeout`. [F2133]
- In `vi_get_pcie_usage()`, after starting and resetting the counters via `ixPCIE_PERF_COUNT_CNTL = 0x5`, the driver must stop the counters and latch the shadow registers by writing `0x2` to `ixPCIE_PERF_COUNT_CNTL` before reading `COUNTER0_UPPER`/`COUNTER1_UPPER` and `ixPCIE_PERF_COUNT0/1_TXCLK`. [F2091]
- In `drivers/gpu/drm/amd/include/amd_shared.h`, `AMD_CG_SUPPORT_*` bitmask constants are stored in `u64 cg_flags` and extend beyond bit 31 (`AMD_CG_SUPPORT_REPEATER_FGCG` at bit 32, `AMD_CG_SUPPORT_GFX_PERF_CLK` at bit 33); every `AMD_CG_SUPPORT_*` definition must shift an explicit 64-bit unsigned literal (`1ULL << n` or `BIT_ULL(n)`) and `cg_flags` must not be stored in a `u32`. [F2114]

## Synchronization

- `vega20_ih_get_wptr` and `vega20_ih_irq_rearm` execute in hardirq context during `amdgpu_ih_process` and must use `RREG32_NO_KIQ` and `WREG32_NO_KIQ` rather than KIQ-routed `RREG32`/`WREG32` when accessing IH registers (`ih_rb_wptr`, `ih_rb_cntl`, `ih_rb_rptr`). Furthermore, `vega20_ih_get_wptr` may only read `*ih->wptr_cpu` on `&adev->irq.ih` (ring0) and `&adev->irq.ih_soft`; on `ih1` and `ih2` (or when `RB_OVERFLOW` is set in `*ih->wptr_cpu` on ring0), it must read `ih_regs->ih_rb_wptr` via `RREG32_NO_KIQ` and clear overflow using `RREG32_NO_KIQ`/`WREG32_NO_KIQ`. [F2070, F2137]
- `vega20_ih_self_irq` (`vega20_ih_self_irq_funcs`) runs in hardirq context when ring 0 dispatches a self-interrupt and must defer processing of `adev->irq.ih1` and `adev->irq.ih2` to workqueue context via `schedule_work(&adev->irq.ih1_work)` and `schedule_work(&adev->irq.ih2_work)`. Broken by: calling `amdgpu_ih_process` on `ih1`/`ih2` or doing blocking page-fault/RAS work directly in `vega20_ih_self_irq`. [F2138]
- `vpe_v6_1_set_trap_irq_state` (`vpe_v6_1_trap_irq_funcs.set`) runs under `spin_lock_irqsave(&adev->irq.lock, irqflags)` and `vpe_v6_1_process_trap_irq` (`vpe_v6_1_trap_irq_funcs.process`) runs in hardirq context; neither callback may sleep, acquire `mutex_lock`, or perform `GFP_KERNEL` allocations. [F2142]
- In `vi_get_register_value`, when reading a non-cached GRBM-indexed register with `se_num != 0xffffffff` or `sh_num != 0xffffffff`, `adev->grbm_idx_mutex` must be held while selecting the target SE/SH via `amdgpu_gfx_select_se_sh`, reading `RREG32(reg_offset)`, and restoring `amdgpu_gfx_select_se_sh(adev, 0xffffffff, 0xffffffff, 0xffffffff, 0)` before `mutex_unlock(&adev->grbm_idx_mutex)`. [F2063]
- `vi_srbm_select` writes `mmSRBM_GFX_CNTL` without internal locking; callers must hold `adev->srbm_mutex` across selecting an `me`/`pipe`/`queue`/`vmid` instance with `vi_srbm_select`, accessing the instanced registers, and resetting `vi_srbm_select(adev, 0, 0, 0, 0)`. [F2068]
- In `vpe_v6_1_ring_start`, resetting `regVPEC_QUEUE0_RB_WPTR` and `regVPEC_QUEUE0_RB_WPTR_HI` to a smaller value requires writing `1` to `regVPEC_QUEUE0_MINOR_PTR_UPDATE` before programming the WPTR registers and writing `0` to `regVPEC_QUEUE0_MINOR_PTR_UPDATE` afterward, before setting `RB_ENABLE` in `regVPEC_QUEUE0_RB_CNTL`. [F2071]
- `vpe_v_6_1_ring_stop` must synchronously poll `regVPEC_QUEUE_RESET_REQ` (or `regVPEC_QUEUE_RESET_REQ_6_1_1` on VPE 6.1.1) via `SOC15_WAIT_ON_RREG` until `VPEC_QUEUE_RESET_REQ__QUEUE0_RESET_MASK` clears to 0 on every VPE instance and mark `vpe->ring.sched.ready = false`. [F2072]
- In `vi.c`, direct MMIO HDP cache operations in `vi_flush_hdp` and `vi_invalidate_hdp` (when `!ring || !ring->funcs->emit_wreg`) and PCIe indirect index/data writes in `vi_pcie_rreg` and `vi_pcie_wreg` must read back the written MMIO register (`mmHDP_MEM_COHERENCY_FLUSH_CNTL`, `mmHDP_DEBUG0`, `mmPCIE_INDEX`, `mmPCIE_DATA`) to flush posted PCIe writes. [F2145]

## Object Lifetimes

- In `vega20_ih_sw_init`, `vega20_ih_init_register_offset(adev)` must be called after `amdgpu_ih_ring_init` has initialized `adev->irq.ih`, `adev->irq.ih1`, and (when supported) `adev->irq.ih2`, because `vega20_ih_init_register_offset` only populates `ih_regs` for rings whose `ring_size` is non-zero. [F2061]
- `vi_read_disabled_bios` must save `mmBUS_CNTL`, `ixROM_CNTL`, and (when `adev->mode_info.num_crtc` is non-zero) `mmD1VGA_CONTROL`, `mmD2VGA_CONTROL`, and `mmVGA_RENDER_CONTROL` before enabling the ROM, and restore all of them after `amdgpu_read_bios(adev)` returns without returning early beforehand. [F2062]

## API Contracts

- In `vega20_ih.c`, `adev->irq.ih2` is not initialized on OSSSYS v4.4.2 and v4.4.5, leaving `ih2.ring_size == 0` and `ih2.ih_regs` unpopulated; any code operating on `adev->irq.ih`, `ih1`, or `ih2` (such as `vega20_ih_enable_ring` or `vega20_ih_toggle_ring_interrupts`) must check `ih->ring_size != 0` before accessing `ih->ih_regs` or programming the ring. [F2075]
- `vpe_v6_1_set_regs` and `vpe_v6_1_irq_init` must obtain `struct amdgpu_device *` via `container_of(vpe, struct amdgpu_device, vpe)` rather than `vpe->ring.adev`, because both callbacks run before `vpe_ring_init` populates `vpe->ring.adev`. [F2078]
- `vi_flush_hdp` and `vi_invalidate_hdp` must check both `ring` and `ring->funcs->emit_wreg` for non-NULL before calling `amdgpu_ring_emit_wreg`, falling back to direct MMIO `WREG32`/`RREG32` when either is `NULL`. [F2079]

## Error Handling

- In `amdgpu_xcp_drm_dev_alloc`, `platform_device_register_simple` and `devm_drm_dev_alloc` return `ERR_PTR` values checked with `IS_ERR`/`PTR_ERR`, whereas `devres_open_group` returns `NULL` on allocation failure and must be checked for `NULL` and translated to `-ENOMEM` before jumping to `out_unregister`. [F2073]

## External Contracts

- All UEFI CPER header and section structures in `amd_cper.h` (`struct cper_hdr`, `struct cper_sec_desc`, `struct cper_sec_nonstd_err*`, `struct cper_sec_crashdump*`, `struct cper_timestamp`) must remain inside `#pragma pack(push, 1)` ... `#pragma pack(pop)` so section offsets and record lengths match the byte-packed UEFI CPER binary layout. [F2100]
- Each `struct amdgpu_reg_state_*_v1_0` payload (`xgmi`, `wafl`, `pcie`, `usr`) in `amdgpu_reg_state.h` must set `common_header.state_type` to its matching `enum amdgpu_reg_state` constant (`AMDGPU_REG_STATE_TYPE_XGMI`, `WAFL`, `PCIE`, or `USR`) and preserve the explicit `pad` fields in `amdgpu_reg_state_header`, `amdgpu_reg_inst_header`, and `amdgpu_smn_reg_data`. [F2103]

## Known Pitfalls

- In `drivers/gpu/drm/amd/amdgpu/vpe_v6_1.c`, VPE `IP_VERSION(6, 1, 1)` uses shifted register offsets `regVPEC_CNTL_6_1_1`, `regVPEC_QUEUE_RESET_REQ_6_1_1`, and `regVPEC_PUB_DUMMY2_6_1_1` instead of `regVPEC_CNTL`, `regVPEC_QUEUE_RESET_REQ`, and `regVPEC_PUB_DUMMY2`; accesses to these registers must branch on `amdgpu_ip_version(adev, VPE_HWIP, 0) == IP_VERSION(6, 1, 1)`. [F2088]
- In `vega20_ih_enable_ring` and `vpe_v6_1_ring_start`, ring base registers (`ih_rb_base`/`ih_rb_base_hi` and `regVPEC_QUEUE0_RB_BASE`/`_HI`) take `gpu_addr >> 8` and `gpu_addr >> 40`, whereas writeback pointer registers (`ih_rb_wptr_addr_lo`/`hi` and `regVPEC_QUEUE0_RB_RPTR_ADDR_LO`/`_HI`) take `lower_32_bits` and `upper_32_bits`. [F2115]
- In `vega20_ih_sw_init`, `vega20_ih_irq_init`, and `vega20_doorbell_index_init`, QWORD doorbell assignments from `enum AMDGPU_VEGA20_DOORBELL_ASSIGNMENT` (`adev->doorbell_index.ih`, `AMDGPU_VEGA20_DOORBELL_MAX_ASSIGNMENT`) must be shifted left by 1 (`<< 1`) when computing `doorbell_index`, `retry_cam_doorbell_index`, and `max_assignment`. [F2117]
- In `vi_get_pcie_usage`, the upper counter overflow fields read from `ixPCIE_PERF_CNTL_TXCLK` via `REG_GET_FIELD` (`COUNTER0_UPPER`, `COUNTER1_UPPER`) must be stored in 64-bit variables (`uint64_t cnt0_of, cnt1_of`) before shifting left by 32 (`cnt0_of << 32`, `cnt1_of << 32`) to combine with the 32-bit `ixPCIE_PERF_COUNT0_TXCLK` and `ixPCIE_PERF_COUNT1_TXCLK` values. [F2112]
- In `vi_get_pcie_replay_count`, the 32-bit register reads `RREG32_PCIE(ixPCIE_RX_NUM_NAK)` and `RREG32_PCIE(ixPCIE_RX_NUM_NAK_GENERATED)` must be widened to `uint64_t` (`nak_r`, `nak_g`) before addition so their sum does not wrap at 32 bits before being returned as `uint64_t`. [F2113]
- In `struct cper_hdr` (`amd_cper.h`), `signature[4]` (`"CPER"`), `platform_id[16]`, `creator_id[16]`, and `record_id[8]`, as well as `fru_id[16]` and `fru_text[20]` in `struct cper_sec_desc`, are fixed-width byte arrays in a `#pragma pack(1)` layout without space for a trailing NUL terminator. Broken by: writing a 5-byte NUL-terminated `"CPER"` string into `hdr->signature` (overwriting `hdr->revision`) or passing these fields to unbounded string functions expecting NUL termination. [F2101]
