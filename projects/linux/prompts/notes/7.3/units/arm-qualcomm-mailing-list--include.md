# ARM/QUALCOMM MAILING LIST — include

This unit provides public C headers for Qualcomm SoC subsystems (`include/linux/soc/qcom/`, `include/linux/dma/`, `include/linux/rpmsg/`, `include/linux/remoteproc/`, `include/linux/mfd/`) and Device Tree binding constant headers (`include/dt-bindings/`). It defines wire protocols (QMI, APR/GPR, SOCINFO SMEM), driver structures and inline helpers (GENI SE, LLCC, UBWC, MDT loader, GPI/BAM/ADM DMA), and compile-time `!CONFIG_*` fallback stubs.

## Architecture & Data Flow

- Every valid protocol enumerator in `enum geni_se_protocol_type` (before `GENI_SE_INVALID_PROTO`) must have a matching entry at the same index in `protocol_name[]` in `drivers/soc/qcom/qcom-geni-se.c`, as `geni_load_se_firmware()` bounds-checks `protocol >= ARRAY_SIZE(protocol_name)` and indexes `protocol_name[protocol]`. Similarly, `enum geni_icc_path_index` (`GENI_TO_CORE`, `CPU_TO_GENI`, `GENI_TO_DDR`) and `struct geni_se::icc_paths[3]` must stay synchronized in order and count with `icc_path_names[]` and `icc_names[]` in `geni_icc_get()`. [F518, F519]
- In `geni_se_get_tx_fifo_depth()` and `geni_se_get_rx_fifo_depth()`, the 8-bit 256-byte FIFO depth mask (`TX_FIFO_DEPTH_MSK_256_BYTES` / `RX_FIFO_DEPTH_MSK_256_BYTES`) must be selected when `(hw_major == 3 && hw_minor >= 10) || hw_major > 3`, and `TX_FIFO_DEPTH_MSK` / `RX_FIFO_DEPTH_MSK` otherwise. Broken by: simplifying to `hw_major >= 3 && hw_minor >= 10` (which breaks `hw_major > 3` with `hw_minor < 10`) or dropping parentheses around `hw_major == 3 && hw_minor >= 10`. [F536]
- In `include/linux/soc/qcom/geni-se.h`, `RX_GENI_CANCEL_IRQ` in the `SE_DMA_RX_IRQ_STAT` register is `BIT(14)` (above `RX_GENI_GP_IRQ_EXT` at `GENMASK(13, 12)`), never `BIT(11)`. [F557]

## Synchronization

- Callers of `devm_pmic_glink_client_alloc()` must store the returned `struct pmic_glink_client *` into the private driver structure (`priv`) before calling `pmic_glink_client_register()`, because registration immediately invokes `pdr_notify(priv, state)`, which can schedule work that dereferences the client pointer. [F494]
- The `cb` and `pdr` callbacks registered via `devm_pmic_glink_client_alloc()` run under `pg->client_lock` with interrupts disabled (`spin_lock_irqsave`), and `pdr` also runs under `pg->state_lock`; neither callback may sleep or call `pmic_glink_send()` synchronously instead of deferring to a workqueue. [F495]
- For `struct qmi_handle` and `struct qmi_txn`, `qmi->txn_lock` nests outside `txn->lock`. A `qmi_msg_handler.fn` callback for a `QMI_RESPONSE` (when `txn->dest` or `txn->ei` is `NULL`) runs with `txn->lock` held and must not acquire `qmi->txn_lock` by calling `qmi_txn_init()`, `qmi_txn_wait()`, `qmi_txn_cancel()`, or `qmi_send_indication()` on `qmi`. [F569]
- `geni_se_setup_m_cmd()` and `geni_se_setup_s_cmd()` must use ordered `writel()` (not `writel_relaxed()`) when writing `SE_GENI_M_CMD0` and `SE_GENI_S_CMD0`. Callers of `geni_se_setup_s_cmd()` must externally serialize calls on the same `struct geni_se` (e.g., holding the port lock) because it performs an unlocked read-modify-write of `SE_GENI_S_CMD0`. [F498]

## Object Lifetimes

- In `struct qmi_ops`, `new_server` receives a borrowed `struct qmi_service *svc` that the QMI core frees with `kfree()` immediately if `new_server` returns a negative error, or retains on `qmi->lookup_results` and frees immediately after invoking `del_server`. Broken by: `new_server` or `del_server` calling `kfree(svc)` or dereferencing `svc` after `del_server` returns. [F479]
- `qmi_encode_message()` returns a `kzalloc()`-allocated buffer and `qcom_mdt_read_metadata()` returns a `kmalloc()`-allocated buffer (or an `ERR_PTR()` on failure, including `ERR_PTR(-ENODEV)` when `!IS_ENABLED(CONFIG_QCOM_MDT_LOADER)`). Both transfer ownership to the caller, which must check `!IS_ERR()` (never `NULL`) and release the buffer with `kfree()`. [F481, F483]
- `pdr_add_lookup()` returns a borrowed `struct pdr_service *` (or `ERR_PTR()`) owned by `pdr->lookups` and freed internally by `pdr_handle_release()` or `pdr_notify_lookup_failure()`. `qcom_smem_get()` and `qcom_ubwc_config_get_data()` likewise return borrowed pointers to mapped SMEM memory and static `const struct qcom_ubwc_cfg_data` tables (or `ERR_PTR()`). Callers of these functions must check for errors with `IS_ERR()` (not `NULL`) and must never pass the returned pointer to `kfree()`. [F485, F493]
- `get_pbs_client_device()` acquires the supplier PBS device and binds its lifetime to `client_dev` via `device_link_add(..., DL_FLAG_AUTOREMOVE_SUPPLIER)`, returning an `ERR_PTR()` on failure; callers must check `IS_ERR()` (not `NULL`) and must not manually call `put_device()` on `pbs->dev`. [F488]
- `qmp_get()` returns a `struct qmp *` (or `ERR_PTR()`) holding a reference on `qmp->dev` via `of_find_device_by_node()` that the caller must release with `qmp_put()` on teardown or error rollback. [F489]
- `qcom_smem_state_get()` and `qcom_smem_state_register()` return a kref-counted `struct qcom_smem_state *` (or `ERR_PTR()`) that must be balanced by `qcom_smem_state_put()` and `qcom_smem_state_unregister()` respectively; neither release function accepts `NULL` or an `ERR_PTR()` when `CONFIG_QCOM_SMEM_STATE` is enabled. [F490]
- `geni_se_clk_tbl_get()` lazily allocates `se->clk_perf_tbl` via `devm_kcalloc(se->dev, ...)` and stores a borrowed pointer in `*tbl` that callers must not `kfree()`. `geni_se_tx_dma_prep()` and `geni_se_rx_dma_prep()` map `buf` on `se->wrapper->dev` and require a matching `geni_se_tx_dma_unprep()` or `geni_se_rx_dma_unprep()` when they return 0 (never unmapping directly on `se->dev`). [F492]
- Implementations of `apr_driver.callback`, `apr_driver.gpr_callback`, and `gpr_port_cb` must check `payload_size > 0` before dereferencing `apr_resp_pkt.payload` or `gpr_resp_pkt.payload` (which is otherwise an uninitialized stack pointer), and must not retain `resp` or `payload` after returning (without `kmemdup()`) because `resp` is stack-allocated and `apr_rxwq()` frees the backing buffer. [F553]

## API Contracts

- `qcom_register_ssr_notifier()`, `qcom_glink_smem_register()`, and `qcom_smd_register_edge()` return `ERR_PTR()` on failure when their `CONFIG_*` symbol is enabled, but their `#else` inline stubs in `qcom_rproc.h`, `qcom_glink.h`, and `qcom_smd.h` return `NULL` so `PTR_ERR_OR_ZERO()` treats disabled support as non-fatal. Broken by: changing those stubs to return `ERR_PTR()`, or passing `NULL` to `qcom_smd_unregister_edge()` or `qcom_glink_smem_unregister()`. [F491]
- Every `struct qmi_elem_info` descriptor array (including nested `ei_array` tables for `QMI_STRUCT` elements) must end with a `{ .data_type = QMI_EOTI }` sentinel, every `struct qmi_msg_handler` array passed to `qmi_handle_init()` must end with a `.fn = NULL` sentinel, and any populated `struct apr_driver.id_table` (`struct apr_device_id[]`) must end with a sentinel where `domain_id` and `svc_id` are 0. [F512, F531]
- For a `struct qmi_elem_info` entry with `data_type = QMI_STRING` decoded by `qmi_decode_message()`, `elem_len` must include space for the trailing NUL terminator (`max_wire_chars + 1`) and must not exceed the destination `char` array size, because `qmi_decode_string_elem()` rejects `string_len >= elem_len` with `-ETOOSMALL` and writes `'\0'` at `buf_dst + string_len`. [F549]
- In `include/linux/soc/qcom/apr.h`, `APR_HDR_FIELD(msg_type, hdr_len, ver)` and `struct gpr_hdr.hdr_size` encode header lengths in 32-bit words (`APR_HDR_LEN(APR_HDR_SIZE)` and `GPR_PKT_HEADER_WORD_SIZE`), whereas `apr_hdr.pkt_size` and `gpr_hdr.pkt_size` are in bytes (`APR_HDR_SIZE` and `GPR_PKT_HEADER_BYTE_SIZE`). [F508]
- In `struct apr_driver`, APR bus drivers must populate `.callback` (invoked by `apr_do_rx_callback()`), whereas GPR static service drivers (`gpr_driver_t`) must populate `.gpr_callback` (copied to `adev->svc.callback` on probe). [F572]
- `se->wrapper` in `struct geni_se` must be populated (e.g., `dev_get_drvdata(dev->parent)`) before calling `geni_se_get_qup_hw_version()`, `geni_se_get_tx_fifo_depth()`, `geni_se_get_rx_fifo_depth()`, `geni_se_resources_on()`, `geni_se_resources_off()`, `geni_se_tx_dma_unprep()`, `geni_se_rx_dma_unprep()`, or `geni_load_se_firmware()`, all of which dereference `se->wrapper` without a NULL check. [F516]
- `geni_se_setup_m_cmd()` and `geni_se_setup_s_cmd()` take an unshifted 5-bit opcode in `@cmd` (which they shift left by `M_OPCODE_SHFT` / `S_OPCODE_SHFT`) and pre-positioned command parameters in `@params` (masked with `M_PARAMS_MSK` / `S_PARAMS_MSK`). Broken by: passing a pre-shifted `opcode << M_OPCODE_SHFT` as `@cmd`. [F513]
- `geni_se_get_tx_fifo_depth()`, `geni_se_get_rx_fifo_depth()`, and the `@rx_wm` and `@rx_rfr` arguments to `geni_se_init()` are in FIFO words (not bytes), whereas `geni_se_get_tx_fifo_width()` returns the FIFO word width in bits (requiring division by `BITS_PER_BYTE` for bytes). [F514]
- `qcom_rpm_write()` (`include/linux/mfd/qcom_rpm.h`) takes `count` in 32-bit words (`u32`) and requires `count == res->size`, whereas `qcom_rpm_smd_write()` (`include/linux/soc/qcom/smd-rpm.h`) takes `count` in bytes. `struct llcc_slice_desc.slice_size` and `llcc_get_slice_size()` are in kilobytes (KB), not bytes. [F573, F575]
- Callers of `qmp_send()` must ensure the formatted string length is strictly less than 64 bytes (`QMP_MSG_LEN`) so it fits with a NUL terminator in the 64-byte stack buffer; otherwise `qmp_send()` triggers `WARN_ON(len >= sizeof(buf))` and returns `-EINVAL`. [F554]
- In `include/linux/soc/qcom/irq.h`, `irq_domain_qcom_handle_wakeup()` returns true only when `d->flags` has `IRQ_DOMAIN_FLAG_QCOM_PDC_WAKEUP` set, meaning wakeup configuration is handled at the parent PDC and the line must be masked at the child TLMM controller (unlike `IRQ_DOMAIN_FLAG_QCOM_MPM_WAKEUP`). [F560]
- In `include/linux/dma/qcom_bam_dma.h`, `bam_prep_ce_le32()` and `bam_prep_ce()` encode `struct bam_cmd_element` in `__le32` with `addr` masked to 24 bits (`addr & 0xffffff`) and `cmd` in bits 31:24 of `cmd_and_addr`; `bam_prep_ce_le32()` requires pre-converted `__le32` `data` while `bam_prep_ce()` takes host-endian `u32` `data`. [F562]

## Error Handling

- `qmi_txn_init()` returns a non-negative transaction ID on success and a negative errno on failure; once it succeeds (`ret >= 0`), the caller must call either `qmi_txn_wait()` (which removes `txn->id` from `qmi->txns` even on timeout) or `qmi_txn_cancel()` (when aborting before `qmi_txn_wait()`, e.g., if `qmi_send_request()` fails), but never both. [F509]
- When `qmi_txn_init()` is given non-NULL `@ei` and `@c_struct`, `qmi_txn_wait()` returns the decoded byte count (`>= 0`) from `qmi_decode_message()` without checking the QMI payload status; callers must also check `resp.result != QMI_RESULT_SUCCESS_V01` in `struct qmi_response_type_v01` to detect remote QMI failures. [F510]
- `qcom_mdt_get_size()` returns a signed `ssize_t` (negative errno `-EINVAL` or `-ENODEV` on failure, positive firmware memory size on success) and must not be stored in an unsigned `size_t` before error checking. `qcom_mdt_load()` and `qcom_mdt_load_no_init()` require non-zero `fw`, `mem_region`, `mem_phys`, and `mem_size`, but accept a `NULL` `reloc_base` out-parameter. [F503]
- `apr_send_pkt()`, `gpr_send_pkt()`, and `gpr_send_port_pkt()` return the positive packet byte size (`hdr->pkt_size`) on success and a negative errno on failure, and `geni_se_clk_tbl_get()` returns the positive number of clock levels (`se->num_clk_levels`, or `0` if none) on success and a negative errno on failure; callers must check `ret < 0` (or `ret <= 0` for empty clock tables) rather than `if (ret)`. [F506, F515]
- When `!IS_ENABLED(CONFIG_QCOM_WCNSS_CTRL)`, the inline stub for `qcom_wcnss_open_channel()` in `include/linux/soc/qcom/wcnss_ctrl.h` unconditionally triggers `WARN_ON(1)` before returning `ERR_PTR(-ENXIO)`, so callers must depend on `CONFIG_QCOM_WCNSS_CTRL` or guard calls at runtime. [F580]

## External Contracts

- Multi-byte fields in packed QMI/GLINK wire headers such as `struct qmi_header` (`txn_id`, `msg_id`, `msg_len`) and `struct pmic_glink_hdr` (`owner`, `type`, `opcode`) must use explicit little-endian types (`__le16`, `__le32`) rather than host-native `u16` or `u32`. [F526]
- In `include/linux/soc/qcom/socinfo.h`, `struct socinfo` defines the versioned SMEM binary layout for `SMEM_HW_SW_BUILD_ID` (`137`); existing fields must never be reordered or inserted into the middle, and readers must check `le32_to_cpu(info->fmt)` (via `SOCINFO_VERSION`) or the SMEM item size before accessing versioned fields. [F563]
- In `include/dt-bindings/power/qcom-rpmpd.h` and `qcom,rpmhpd.h`, new platform-specific power domain index macro blocks (`<SOC>_CX`, `<SOC>_VDDCX`, etc.) must not be added; new bindings must use generic `RPMPD_*` or `RPMHPD_*` constants. Also, `RPMPD_VDDCX_VFC` and `RPMPD_VDDCX_VFL` both alias index `2` and must never both be used on the same platform. [F524, F534]
- `include/dt-bindings/sound/qcom,q6afe.h` must not be deleted even though it only includes `<dt-bindings/sound/qcom,q6dsp-lpass-ports.h>`, because external device trees depend on the header path. [F535]

## Known Pitfalls

- In `struct qmi_msg_handler`, `decoded_size` must be at least the size of the C struct described by `ei`, and `fn()` must not retain the `decoded` or `txn` pointers after returning because `qmi_invoke_handler()` frees `decoded` immediately and `qmi_handle_message()` passes a stack-allocated `struct qmi_txn` for `QMI_REQUEST` and `QMI_INDICATION` messages in which only `txn->id` is initialized (`qmi`, `lock`, `completion`, `ei`, and `dest` are zeroed). [F511, F550]
- In `struct qmi_elem_info`, an entry with `data_type = QMI_DATA_LEN` uses `elem_size` (`sizeof(u8)` or `sizeof(u16)`) only for the wire length field, whereas `qmi_decode_message()` unconditionally writes a 4-byte `u32` to `out_c_struct + temp_ei->offset`; the target field in any decoded C struct must therefore be declared as `u32` (never `u8` or `u16`). [F548]
- `svc_to_apr_device()` must only be called on a `struct pkt_router_svc` embedded in a bus-registered `struct apr_device` (never on a dynamic `gpr_port_t` from `gpr_alloc_port()`), and `to_apr_device()` must never be called on `pkt_router_svc.dev` because `svc->dev` points to the parent or client device rather than `apr_device.dev`. [F551]
- Although `apr_driver.gpr_callback` and `gpr_port_cb` share the same signature, `apr_driver.gpr_callback` always receives the bus-registered `gpr_device_t *` (`struct apr_device *`) as its `void *data` argument (because `apr_add_device()` sets `adev->svc.priv = adev`), whereas a `gpr_port_cb` registered with `gpr_alloc_port()` receives the caller's `priv` pointer. Broken by: an `apr_driver.gpr_callback` casting `data` directly to driver private state instead of `gpr_device_t *` and calling `dev_get_drvdata(&gdev->dev)`. [F552]
