# DRM DRIVER FOR NVIDIA GEFORCE/QUADRO GPUS — drivers/gpu/drm/nouveau/include

This component provides the internal headers for the Nouveau driver across three layers: `nvhw` (hardware register/class definitions and DRF bitfield macros), `nvif` (the client/object/pushbuffer/ioctl interface between DRM and the backend), and `nvkm` (the core hardware abstraction for devices, subdevices, engines, VBIOS, MMU/VMM, and GSP).

## Architecture & Data Flow

- `NVKM_LAYOUT_ONCE` and `NVKM_LAYOUT_INST(type, data, ptr, cnt)` in `nvkm/core/layout.h` define the forward construction/`preinit`/`init` order of `struct nvkm_device::subdev` and the reverse `fini`/dtor order. `cnt` in `NVKM_LAYOUT_INST` must exceed the highest bit index in any chip's `nvkm_device_chip.<ptr>.inst` mask; `NVKM_LAYOUT_ONCE` subdevices must only set `.inst = 1` (`BIT(0)`). [F49, F85]
- `struct nvkm_gsp_object.client` tracks whether a GSP-RM handle is live: `nvkm_gsp_rm_alloc_get()` sets `object->client` (clearing it on failure, as does `nvkm_gsp_rm_alloc_push()`), and `nvkm_gsp_rm_free()`, `nvkm_gsp_device_dtor()`, and `nvkm_gsp_client_dtor()` gate teardown on `object->client != NULL` and clear it. Never manually assign `object->client` or call `rm->api->alloc->free(object)` without clearing `object->client = NULL`. [F6]
- `PUSH_WAIT(push, size)` sets `push->seg = push->cur + size` (with `CONFIG_NOUVEAU_DEBUG_PUSH`) and may call `push->wait` to wrap the ring and reset `push->bgn`/`cur`/`end`, while `PUSH_KICK(push)` calls `push->kick(push)` when `push->cur != push->bgn` and sets `push->bgn = push->cur`. Callers must reserve the exact `u32` word count via `PUSH_WAIT` before `PUSH_DATA__`/`PUSH_DATAp` (`_p->cur < _p->seg` and `< _p->end`) and must not cache `push->cur` or `push->bgn` across `PUSH_WAIT`. [F35, F37]
- Sentinel rules: `struct nvkm_intr_data` arrays for `nvkm_intr_add()` must end with `mask == 0`; `struct nvkm_enum` (`nvkm_enum_find()`) and `struct nvkm_bitfield` (`nvkm_snprintbf()`) arrays must end with `name == NULL`. [F46, F47]

## Synchronization

- On `struct nvkm_vmm` and `struct nvkm_mmu`, lock order is `vmm->mutex.vmm` -> `vmm->mutex.ref` / `vmm->mutex.map` -> `vmm->mmu->mutex`. Callers that look up or split a non-raw `struct nvkm_vma` under `vmm->mutex.vmm` before `nvkm_memory_map()` (`nvkm_vmm_map()`) must set `vma->busy = true` and unlock `vmm->mutex.vmm` first, and on error relock `vmm->mutex.vmm` to clear `vma->busy = false`. [F20, F95]
- Non-NULL returns from `nvkm_chan_get_chid()` or `nvkm_chan_get_inst()` hold spinlock `chan->cgrp->lock` with IRQs disabled in `*irqflags`; callers must not sleep and must release via `nvkm_chan_put(&chan, irqflags)` on all paths. Similarly, `nvkm_fifo_pause(fifo, &flags)` acquires `spin_lock_irqsave(&fifo->lock, flags)` and must be paired with `nvkm_fifo_start(fifo, &flags)` without sleeping. [F16, F17]
- `nvkm_event_func` (`nvkm_event_ntfy::func`) and `struct nvkm_event_func::init`/`fini` run in atomic context under `read_lock_irqsave(&event->list_lock)` and `spin_lock_irqsave(&event->refs_lock)` respectively, and must not sleep or call `nvkm_event_ntfy_add()`/`del()` on the same `nvkm_event`. When registered with `wait == true`, `nvkm_event_ntfy_allow()`, `block()`, and `del()` (and `nvif_event_allow()`/`block()`) acquire `write_lock_irq(&event->list_lock)` and must never be called inside `nvkm_event_func`. [F18, F93]
- GSP callbacks (`nvkm_gsp_msg_ntfy_func`, `nvkm_gsp_event_func`) run under `gsp->cmdq.mutex` (and `gsp->client_id.mutex` for events), so they must not synchronously issue GSP RPCs (`nvkm_gsp_rpc_*`, `nvkm_gsp_rm_ctrl_*`, `nvkm_gsp_rm_alloc_*`, `nvkm_gsp_rm_free`) or mutate `client->events` (`nvkm_gsp_event_dtor()`). [F19]
- Every `nvkm_inth_func` callback (including `nvkm_subdev_func::intr` via `nvkm_intr_subdev`) runs in hardirq context under `device->intr.lock`; it must not sleep or call `nvkm_inth_allow()` or `nvkm_intr_allow()`/`block()`/`rearm()`/`unarm()` on the same `struct nvkm_device`. [F92]
- Keep `nvkm_event_init()` (initializes `refs_lock` and `list_lock` before `__nvkm_event_init()`) and `nvkm_subdev_ctor()` (initializes `subdev->use.mutex` before `__nvkm_subdev_ctor()`) as inline header wrappers so each call site gets a distinct lockdep class; never call the `__`-prefixed functions directly. [F13, F14]
- `nvkm_mask` and `nvif_mask` perform unserialized 32-bit MMIO read-modify-writes (`nvkm_rd32`/`wr32`, `nvif_rd32`/`wr32`) without locking; concurrent callers on shared registers must serialize externally. [F88]

## Object Lifetimes

- `nvkm_kmap()` and `nvkm_done()` must bracket all `nvkm_ro32()`, `nvkm_wo32()`, `nvkm_mo32()`, `nvkm_wo64()`, `nvkm_robj()`, and `nvkm_wobj()` calls on a `struct nvkm_memory` or `struct nvkm_gpuobj`, as `acquire` sets up `ptrs`/`func` and `release` flushes writes and resets `ptrs`. [F1]
- Every `struct nvkm_gsp_mem` initialized by `nvkm_gsp_mem_ctor()` holds a coherent DMA buffer and `get_device()` reference in `mem->dev`, and must be freed via `nvkm_gsp_mem_dtor()` rather than freeing `mem->data` directly. [F2]
- When `nvkm_gsp_rpc_push()` or `nvkm_gsp_rpc_rd()` succeeds with `NVKM_GSP_RPC_REPLY_RECV` and `repc > 0`, the caller must free the returned buffer with `nvkm_gsp_rpc_done()`. `NVKM_GSP_RPC_REPLY_NOWAIT`, `NVKM_GSP_RPC_REPLY_POLL`, and `nvkm_gsp_rpc_wr()` consume the reply internally; RPCs returning only an empty header in the message queue (e.g., `NV_VGPU_MSG_FUNCTION_ALLOC_MEMORY`) must use `NVKM_GSP_RPC_REPLY_POLL`, not `RECV`. [F3, F80]
- `struct nvif_log.shutdown` callbacks on `struct nvif_logs` must free all debugfs dentries, buffers, and the `struct nvif_log` itself. In `struct nvkm_gsp`, `blob_init`/`intr`/`rm`/`pmu` and their backing buffers must remain valid until `debugfs_remove()` is called on `gsp->debugfs.init`/`intr`/`rm`/`pmu`. [F7, F8]
- When `nvif_object_sclass_get()` returns `>= 0` (including `0`), it allocates `*psclass` via `kcalloc()`, which the caller must free with `nvif_object_sclass_put()`. [F10]
- `nvkm_engine_ref()` can return an `ERR_PTR()` if lazy `nvkm_subdev_init_()` fails on the `0 -> 1` transition (unlike `nvkm_memory_ref()` and `nvkm_vmm_ref()`, which return the input pointer or `NULL`); always check `IS_ERR()` before dereferencing or passing to `nvkm_engine_unref()`. [F12]
- Falcon firmware needed during preinit, teardown, or shutdown (e.g., `struct nvkm_fb::vpr_scrubber` in `nvkm_fb_mem_unlock`) must be cached during `nvkm_subdev_func::oneinit` in a persistent `struct nvkm_falcon_fw` and freed in `dtor`, not loaded on demand during shutdown. Instance memory allocated via `nvkm_memory_new` with `NVKM_MEM_TARGET_INST_SR_LOST` is lost across suspend/resume, whereas `NVKM_MEM_TARGET_INST` is saved in host memory. [F79, F84]

## API Contracts

- `.dtor` callbacks in `nvkm_object_func`, `nvkm_subdev_func`, `nvkm_engine_func`, `nvkm_device_func`, and `nvkm_memory_func` must return the outer heap pointer for the core to `kfree()` (or `NULL` if embedded) and must not `kfree()` it themselves while returning non-NULL or return a non-zero-offset embedded member. [F11]
- `nvif_unpack(r, d, s, m, vl, vh, x)` and `nvif_unvers(r, d, s, m)` only inspect the payload when `r == -ENOSYS`, so callers must initialize `ret = -ENOSYS`. In `nvif_unpack`, `x = false` requires `*s == sizeof(m)` (returning `-E2BIG` on trailing bytes) and clears `*d = NULL`/`*s = 0`, whereas `x = true` advances `*d` and decrements `*s` by `sizeof(m)`. Pass the dereferenced member (e.g., `args->vn`) to `nvif_unvers`, never the pointer `args`. [F25, F43, F74]
- `nvkm_mask`, `nvif_mask`, and `DRF_MR`/`NVIF_MR32` take pre-shifted masks and values and return the old 32-bit register value, whereas `DRF_MV`/`NVIF_MV32` take an unshifted field value and return the old unshifted field value. `DRF_WV`/`NVIF_WV32` and `DRF_WD`/`NVIF_WD32` overwrite the entire register (zeroing all other bits), unlike read-modify-write `DRF_MV`/`NVIF_MV32` and `DRF_MD`/`NVIF_MD32`. [F32, F33]
- DRF bitfield macros in `nvhw/drf.h` must be unparenthesized `HI:LO` pairs with `HI >= LO` (`DRF_HI`/`DRF_LO` use `(1 ? drf)` / `(0 ? drf)`), and single-word macros (`DRF_MASK`, `DRF_SMASK`, `NVVAL*`, `NVDEF*`) require `0 <= LO <= HI < 64`. Multi-word fields for `NVVAL_MW_GET`/`NVVAL_MW_SET`/`NVDEF_MW_SET` must use `MW(hi:lo)`, span at most two adjacent elements of `o`, and pass `o` with the exact hardware word element type (`sizeof((o)[0]) * 8` bits). [F50, F53, F63, F75]
- In `nvif/push.h`, emitting a pre-reserved word at the end of a segment (e.g., wrap-around `PUSH_JUMP` inside `push->wait`) must be wrapped in `PUSH_RSVD(p, d)` so `__p->seg` and `__p->end` advance before `PUSH_DATA__` checks bounds. Addressing modes `o` used with `PUSH_1`..`PUSH_10` and `PUSH_DATAp` must define `PUSH_<o>_INC` as an unparenthesized `first_inc:subsequent_inc` colon pair. [F36, F54]
- In `nvkm/core/memory.h`, `nvkm_mo32`, `nvkm_robj(o, a, p, s)`, and `nvkm_wobj(o, a, p, s)` store byte offset `a` in a `u32` (`a + s` must fit in `u32`) and `nvkm_robj`/`wobj` take a 4-byte-multiple byte size `s` (`_size = (s) >> 2`), whereas `nvkm_fo32(o, a, d, c)` and `nvkm_fo64(o, a, d, c)` take a 4/8-byte-aligned byte offset `a` but a 32/64-bit word count `c`. [F67, F73]
- `nvkm_memory_page(p)` returns a log2 page shift and `nvkm_vmm_get()`/`nvif_vmm_get()` take `page` and `align` as log2 shifts (`size` in bytes), whereas `struct nvkm_vma::page` and `refd` store 3-bit indices into `vmm->func->page[]` (or `NVKM_VMA_PAGE_NONE`). `nvkm_mm_addr(node)` requires `nvkm_mm_contiguous(node)` (`!node->next`), otherwise it triggers `WARN_ON` and returns `0`. [F34, F100]
- Pass the target subtype's `const struct nvkm_object_func *` (not `NULL`) to `nvkm_object_search(client, handle, func)` before downcasting with `container_of`. Size `struct nvif_outp_dp_train_v0::dpcd` and the `dpcd` parameter of `nvif_outp_dp_train()` as `DP_RECEIVER_CAP_SIZE` (15 bytes, not 16). In `struct nvkm_device_tegra_func`, set `iommu_bit` to the IOMMU translation bit (or `0` if unused) and hold `tdev->iommu.mutex` when accessing `tdev->iommu.mm`. [F70, F77, F89]
- Before `NV507D_GET_CAPABILITIES`, clear the generation-specific notifier completion bit (`NV_DISP_CORE_NOTIFIER_1_CAPABILITIES_1_DONE` pre-GF110 or `NV907D_CORE_NOTIFIER_3_CAPABILITIES_4_DONE` on GF110+), enable `NV507D_SET_NOTIFIER_CONTROL` before `GET_CAPABILITIES`, disable it after, and poll for `DONE_TRUE`. [F83]

## Error Handling

- Pass `&ctrl` (pointer address) as `argv` to `nvkm_gsp_rm_ctrl_push(obj, argv, repc)` because `rm->api->ctrl->push` updates `*params` in-place to the reply buffer (whereas `nvkm_gsp_rm_ctrl_wr` and `nvkm_gsp_rm_ctrl_done` take `ctrl` by value). When `repc > 0`, `r535_gsp_rpc_rm_ctrl_push()` stores the reply in `*argv` without freeing the RPC even on non-zero `rpc->status`, so callers must call `nvkm_gsp_rm_ctrl_done(obj, ctrl)` on both success and error paths. [F4, F71]
- `nvkm_nsec`/`usec`/`msec`, `nvkm_wait_nsec`/`usec`/`msec`, and `nvif_nsec`/`usec`/`msec` return signed `s64` elapsed ns on `break` or `-ETIMEDOUT` on timeout: exit polling loops via `break` (or pass `NVKM_DELAY` in `nvkm_nsec` for pure delays) and test failure with `< 0`. `nvif_usec`/`msec` and `nvkm_wait_usec`/`msec` multiply by signed `int` `1000`, so pass timeouts >= 2148 ms (or >= 2,147,484 us) as `u64` to avoid 32-bit overflow. [F27, F59, F66]
- `nvkm_firmware_load(s, l, o, p...)` requires descriptor array `l` to end with `.load == NULL` and returns an `ERR_PTR` on failure (never `NULL` when `_ret != 0`), so check `IS_ERR()`. `nvkm_rdi2cr` and `nv_rd16i2cr` return the 8/16-bit register value in an `int` or `-EIO` on error; store the result in a signed `int` and check `< 0` before narrowing. [F28, F30]

## External Contracts

- In a channel pushbuffer, `NVC36F_MEM_OP_D` (e.g., `MMU_TLB_INVALIDATE` or `MEMBAR`) must always be preceded by `NVC36F_MEM_OP_A`, `NVC36F_MEM_OP_B`, and `NVC36F_MEM_OP_C`. [F21]
- `struct nvif_ioctl_v0`, `nvif_ioctl_new_v0`, `nvif_ioctl_mthd_v0`, and `nvif_ioctl_sclass_v0` in `nvif/ioctl.h` are copied from userspace in `nouveau_abi16_ioctl`; new header fields in `nvif_ioctl_v0` or `nvif_ioctl_mthd_v0` must go inside `struct_group_tagged` before `data[]` without breaking ABI16 layout. [F99]

## Known Pitfalls

- `NVVAL_GET_X(o, drf)` (and `NVVAL_GET`, `NVVAL_TEST`, `NVDEF_TEST`) shifts `(o) >> DRF_LO(drf)` before masking, so `o` must be a 64-bit type when `DRF_LO(drf) >= 32`. `NVVAL_MW_SET_X(o, drf, v)` (`NVVAL_MW_SET`, `NVDEF_MW_SET`) overwrites `(o)[DRF_LW_IDX((o), drf)]` before evaluating `DRF_HW_SET((o), drf, (v))` and always compiles `((long long)(v) >> DRF_LW_BITS((o), drf))`, so `v` must not have side effects or read from `(o)[DRF_LW_IDX]` and `o` must have elements narrower than 64 bits (e.g., `u32[]`) if `DRF_LW_BITS` can reach 64. [F41, F64, F65]
- Always assign the return value of `nvkm_list_find` and `nvkm_list_find_next` (`p = nvkm_list_find(p, ...)`), because on no match they return `NULL` while leaving `p` at `container_of(h, ...)`. Never unlink or free `p` inside `nvkm_list_foreach` (or `nvkm_runl_foreach_cond`/`engn_cond`) without breaking, as the step expression dereferences `p->m.next`. [F55, F56]
- In `nvif/object.h`, the `m` table passed to `nvif_mclass(o, m)` and `nvif_sclass(o, m, u)` must be ordered most-preferred first and end with `.oclass == 0`, and callers must not pass identifiers named `object`, `sclass`, or `mclass` to `nvif_mclass(o, m)`. Keep distinct local variable names across nested macros in `nvif/push.h` (`__p`/`__d`, `_pp`/`_dd`, `_p`/`_d`, `_ppp`/`__o`) and `nvkm/core/memory.h` (`_a`/`_d` in `nvkm_fill`, `__a`/`__d` in `nvkm_wo64`) to avoid variable shadowing. [F61, F62]
- On GK104-GP10x (`NV917D`), format `HEAD_SET_CONTROL_CURSOR` using `NV917D_HEAD_SET_CONTROL_CURSOR_SIZE` (`27:26`) from `cl917d.h`, not `NV907D_HEAD_SET_CONTROL_CURSOR_SIZE` (`26:26`) from `cl907d.h` (which masks out bit 1 for 128x128 and 256x256 cursors). [F82]
