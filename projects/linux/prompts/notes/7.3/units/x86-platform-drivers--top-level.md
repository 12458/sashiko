# X86 PLATFORM DRIVERS — (top level)

This component comprises standalone top-level x86 platform drivers in `drivers/platform/x86/` (including Intel IPS thermal/power sharing, P2SB BAR caching, Intel Atom PMC, Silicom MEC170x appliances, Cisco Meraki MX100, SEL-3350, MeeGoPad ANX7428, Samsung Q10, OLPC XO-1/XO-1.5, and WMI hotkey/MXM drivers) and shared platform_data headers in `include/linux/platform_data/x86/`. They provide PCI/LPC/MMIO bridge access, CPU/GPU thermal and turbo coordination, and board-specific GPIO, LED, hwmon, input, power_supply, and clock registrations.

## Architecture & Data Flow
- In `p2sb.c`, `p2sb_read_bar0()` must zero `@mem` and copy only value fields (`start`, `end`, `flags`, `desc`) from BAR0, never pointer fields (`name`, `parent`, `sibling`, `child`), because `p2sb_scan_and_cache_devfn()` immediately removes the scanned `pci_dev`. Broken by: copying BAR0 via `*mem = *bar0` or `memcpy()`. [F202]
- `p2sb_scan_and_cache_devfn()` must store `bus->dev.id` in `cache->bus_dev_id` alongside `cache->res` in `p2sb_resources[PCI_FUNC(devfn)]`, and `p2sb_read_from_cache()` must verify both `cache->bus_dev_id == bus->dev.id` and `p2sb_valid_resource(&cache->res)` before returning the cached BAR. [F222]
- In `p2sb_cache_resources()`, the `PCI_CLASS_DEVICE` check must only reject when `!PCI_POSSIBLE_ERROR(class) && class != PCI_CLASS_MEMORY_OTHER`, because a BIOS-hidden P2SB reads as `0xffff` (`PCI_POSSIBLE_ERROR(class) == true`) before `p2sb_scan_and_cache()` unhides it. [F244]
- `p2sb_get_devfn()` defaults to `P2SB_DEVFN_DEFAULT` (`PCI_DEVFN(31, 1)`) when `x86_match_cpu(p2sb_cpu_ids)` returns NULL and overrides to `P2SB_DEVFN_GOLDMONT` (`PCI_DEVFN(13, 0)`) on `INTEL_ATOM_GOLDMONT` and `INTEL_ATOM_GOLDMONT_PLUS`, where `p2sb_scan_and_cache()` scans only `devfn` and `SPI_DEVFN_GOLDMONT`. Broken by: returning `-ENODEV` on non-match, omitting `INTEL_ATOM_GOLDMONT_PLUS`, or scanning all 8 PCI functions. [F261]
- In `intel_ips.c`, `ips_probe()` must snapshot `TURBO_POWER_CURRENT_LIMIT` into `ips->orig_turbo_limit` before thermal adjustment starts, and `ips_remove()` must clear `TURBO_TDC_OVR_EN | TURBO_TDP_OVR_EN` before restoring `ips->orig_turbo_limit`. During adjustments, `ips_cpu_raise()` and `ips_cpu_lower()` must update `THM_MPCPC` MMIO and `TURBO_POWER_CURRENT_LIMIT` MSR in lockstep, writing `TURBO_TDC_OVR_EN | TURBO_TDP_OVR_EN` before writing the new `TURBO_TDP_MASK` limit. [F215, F216]
- In `intel_ips.c`, `ips->gpu_turbo_enabled` must only be set true when all i915 callbacks are acquired via `ips_get_i915_syms()` (checked via `ips->gpu_busy`), and must be cleared if `ips->gpu_raise()` or `ips->gpu_lower()` returns false. In `ips_monitor()`, `ips->read_mch_val` must be NULL-checked before calling, and `mchp_samples` must be zero-initialized with `kcalloc()` so `calc_avg_power()` never reads uninitialized memory when i915 is unloaded. [F207, F219]
- In `ips_monitor()`, `last_sample_period` must be clamped to at least 1 when `jiffies_to_msecs(jiffies) - last_msecs` is 0, because `get_cpu_power()` divides by `period` on the next iteration. [F246]
- In `struct ips_driver`, `ctv1_avg_temp`, `ctv2_avg_temp`, `mch_avg_temp`, and `mcp_avg_temp` are in 0.01 °C units while `mcp_temp_limit` and `struct ips_mcp_limits` temp limits are in whole °C, so `mcp_exceeded()`, `cpu_exceeded()`, and `mch_exceeded()` must multiply the °C limit by 100. [F251]
- In `pmc_atom.c`, paired `d3_sts_*` and `func_dis*` arrays in `struct pmc_reg_map` (such as `cht_d3_sts_1_map` and `cht_func_dis_2_map`) must keep identical length and ordering, because `pmc_dev_state_print()` and `pmc_dev_state_check()` index `fd_map[index]` using `sts_map[index].name` as the loop bound. [F223]
- In `sel3350-platform.c`, `GPIO_LOOKUP_IDX` entries in `sel3350_leds_table` must match `sel3350_leds` indices, and each registered `power_supply` (`ps_a`, `ps_b`) must set `ps_cfg.drv_data` to its own `struct sel3350_power_cfg_data` before `devm_power_supply_register()`. [F228]
- Every `struct led_classdev_mc` array passed to `silicom_mc_leds_register()` via `struct silicom_platform_info::led_info` must end with a `{ }` sentinel where `led_cdev.name == NULL`. [F237]
- In `fm07keys_poll()`, loop counter `i` must be reset to 0 before each of the four `PORT_CMD` status-polling `while` loops and bounded by `LOOP_TIMEOUT` so a stuck EC status bit jumps to `timeout` without hanging the poll workqueue or reporting stale keys. [F245]

## Synchronization
- In `p2sb_cache_resources()`, clearing `P2SBC_HIDE` in `P2SBC`, calling `p2sb_scan_and_cache()`, and restoring `P2SBC_HIDE` must be serialized under `pci_lock_rescan_remove()`. Conversely, `p2sb_bar()` must read hidden P2SB resources from `p2sb_resources` (populated at `fs_initcall_sync(p2sb_fs_init)` after `pcibios_assign_resources()`) and never acquire `pci_lock_rescan_remove()`, because `p2sb_bar()` runs from driver probe paths during sysfs PCI rescans that already hold `pci_rescan_remove_lock`. [F190, F191]
- In `ips_probe()`, `ips->adjust` must be created dormant with `kthread_create()` before starting `ips->monitor` with `kthread_run()`, because `ips_monitor()` wakes `ips->adjust` via `wake_up_process()` only after collecting the initial 5-second averages. [F194]
- In `intel_ips.c`, runtime updates to `ips->mcp_temp_limit` or `ips->mcp_power_limit` from hardware registers (in `update_turbo_limits()` or `ips_irq_handler()`) must hold `ips->turbo_status_lock` and call `verify_limits(ips)` before unlocking. [F218]
- In `xiaomi_wmi_notify()`, reporting key press, release, and `input_sync()` on `data->input_dev` must be serialized under `data->key_lock` because concurrent WMI `.notify` callbacks share `input_dev`. [F189]
- In `silicom-platform.c`, all runtime indexed I/O port sequences selecting an address at `MEC_ADDR` (`EC_ADDR_LSB`/`EC_ADDR_MSB`) and accessing `MEC_DATA_OFFSET(...)` must hold `mec_io_mutex`, and `silicom_gpio_chip.can_sleep` must remain `true`. [F268]

## Object Lifetimes
- When `p2sb_hidden_by_bios` is false, `p2sb_cache_resources()` must not call `p2sb_scan_and_cache()`, and `p2sb_bar()` must read BAR0 from the live device via `p2sb_read_from_dev()` (`pci_get_slot()` / `pci_dev_put()`) instead of scanning and removing it. [F258]
- `ips_get_i915_syms()` acquires `i915_read_mch_val`, `i915_gpu_raise`, `i915_gpu_lower`, `i915_gpu_busy`, and `i915_gpu_turbo_disable` via `symbol_get()`, unwinding in reverse with `symbol_put()` on lookup failure, and `ips_remove()` releases each non-NULL symbol with `symbol_put()`. [F183]
- Before `ips_monitor()` exits its periodic sampling loop, it must call `timer_delete_sync(&ips->timer)` so `monitor_timeout()` cannot fire and call `wake_up_process(ips->monitor)` after the kthread exits. [F195]
- In `mxm_wmi_call_mxds()` and `mxm_wmi_call_mxmx()`, pass NULL for the `wmi_evaluate_method()` output `struct acpi_buffer *` unless `output.pointer` is explicitly freed with `kfree()`. [F181]
- In `tink_board_init()` and `tink_board_exit()`, `tink_swnodes` must be registered with `software_node_register_node_group()` before creating `tink_leds_pdev` and `tink_keys_pdev`, and unregistered after `platform_device_unregister()` of both devices (including on init error). [F184]
- `silicom_mc_leds_register()` must deep-copy each `struct led_classdev_mc` and its `subled_info` array (`led->num_colors * sizeof(struct mc_subled)`) into `devm_kzalloc()` memory because board templates (`plat_0222_mc_led_info`, `cordoba_mc_led_info`, `*_mc_subled_info`) are `__initdata`. Broken by: passing `__initdata` pointers directly or sizing `subled_info` as `sizeof(led->subled_info)`. [F255]
- `get_serdev_controller()` must take a strong reference via `get_device(acpi_get_first_physical_node(adev))` before `acpi_dev_put(adev)`, and `get_serdev_controller_from_parent()` must call `put_device(ctrl_dev)` on each intermediate parent while walking `host -> :0 -> .N -> serdev_ctrl_name`. [F262]

## API Contracts
- `get_serdev_controller_from_parent()` and `get_serdev_controller()` convert NULL lookups from `device_find_child_by_name()`, `acpi_dev_get_first_match_dev()`, and `get_device()` into `ERR_PTR(-ENODEV)`, so callers must check `IS_ERR()`, not NULL. [F200]
- `p2sb_bar()` requires a non-NULL `@mem` out-parameter, while `@bus` may be NULL (resolved to domain 0, bus 0 by `p2sb_get_bus()`) and `@devfn` may be 0 (resolved by `p2sb_get_devfn()`). [F201]
- `mxm_wmi_call_mxds()` and `mxm_wmi_call_mxmx()` return 0 on success or a positive `acpi_status` on failure from `wmi_evaluate_method()`. Broken by: checking return values with `ret < 0` instead of `ret != 0`. [F214]
- Every `struct wmi_device_id` in `xiaomi_wmi_id_table` must set `.context` to a valid `const unsigned int *` pointing to a keycode `< KEY_CNT` (via `XIAOMI_DEVICE()`), because `xiaomi_wmi_probe()` dereferences `*(const unsigned int *)context` for `set_bit(..., data->input_dev->keybit)`. Broken by: casting an integer keycode directly to `void *` or pointing to a narrower integer type. [F257]
- In `silicom-platform.c`, `temp_get()` must multiply `FIELD_GET(MEC_TEMP_LOC, reg)` by 100 to convert decicelsius (0.1 °C) to millidegrees Celsius for `hwmon_temp_input`. [F291]

## Error Handling
- In `get_serdev_controller()`, `serial_ctrl_uid` may be NULL to match any ACPI UID, so print/error paths must guard it with `serial_ctrl_uid ?: "*"` before passing to `%s`. [F199]
- In `anx7428_probe()`, the `read_poll_timeout()` condition polling `i2c_smbus_read_byte_data()` on `TX_STATUS` must check `val >= 0` before testing `val & OCM_STARTUP`, because negative errno values set `BIT(7)` (`OCM_STARTUP`). [F243]
- In `pmc_atom.c`, `pmc_s2idle_check()` passes blocks that permanently report D0 on lower-featured Bay Trail/Cherry Trail SKUs via `false_pos_sts_0` and `false_pos_sts_1` so `pmc_dev_state_check()` logs them with `pm_pr_dbg()` rather than `pr_err()`. [F288]

## External Contracts
- On Broxton, Apollo Lake, and Gemini Lake LPSS PWM controllers (`struct pwm_lpss_boardinfo` in `pwm-lpss.h`), software must verify the `PWMCTRL` `sw_update` bit is 0 both before programming base unit/divisor values and before a read-modify-write of `PWMCTRL` to set PWM Enable. [F229]
- In `asus-wmi.h`, `ASUS_WMI_DEVID_SCREENPAD_POWER` (`0x00050031`) can only disable the screenpad; re-enabling it requires writing a brightness value to `ASUS_WMI_DEVID_SCREENPAD_LIGHT` (`0x00050032`). [F297]

## Known Pitfalls
- In `intel_ips.c`, `ips_enable_cpu_turbo()` and `ips_disable_cpu_turbo()` must check both `ips->__cpu_turbo_on` and `ips->turbo_toggle_allowed` (set in `ips_detect_cpu()` only if `IA32_MISC_ENABLE` has `IA32_MISC_TURBO_EN`) before calling `on_each_cpu()` to write `IA32_PERF_CTL`. [F217]
- In `intel_ips.c`, `calc_avg_temp()` and `calc_avg_power()` must divide `u64` accumulators using `do_div()` rather than `/` so 32-bit x86 builds succeed. [F250]
- In `intel_ips.c`, `ips_probe()` must request only legacy INTx (`pci_alloc_irq_vectors(dev, 1, 1, PCI_IRQ_INTX)`) with `IRQF_SHARED` (never MSI), and `ips_irq_handler()` must return `IRQ_NONE` when both `THM_TSES` and `THM_TES` are 0 and write back the read values (`thm_writeb`) to clear active status bits. [F263]
- In `pmc_atom.c`, `pmc_s2idle_check()` distinguishes Bay Trail from Cherry Trail via pointer equality `m->d3_sts_1 == byt_d3_sts_1_map`, so changing `byt_reg_map.d3_sts_1` or adding a `pmc_reg_map` requires updating `pmc_s2idle_check()`. [F224]
- In `pmc_power_off()`, `SLEEP_TYPE_MASK` is a positive `GENMASK(12, 10)` and must be bitwise-negated (`pm1_cnt_value &= ~SLEEP_TYPE_MASK`) before ORing `SLEEP_TYPE_S5`. In `pmc_sleep_tmr_show()`, the `u32` return of `pmc_reg_read()` must be cast to `u64` before shifting left by `PMC_TMR_SHIFT` (5) to avoid truncating the top 5 bits. [F240, F248]
- In `silicom-platform.c`, `u8` GPIO channel descriptors (`plat_0222_gpio_channels`) encoded with `OFFSET_BIT_TO_CHANNEL(off, bit)` require `off <= 0x0b` and `bit <= 7` so `(((off) + 0x014) << 3) | (bit)` fits in `u8` for `CHANNEL_TO_OFFSET()`. Also, `silicom_mec_port_set()` is active-low (clears the bit when `@on != 0`), whereas `silicom_mec_port_get()` returns the raw bit, so `silicom_gpio_set()` must pass `!value` to `silicom_mec_port_set()`. [F236, F242]

## Other
- In `meegopad_anx7428.c`, `anx7428_probe()` must sequence power-on by driving `enable` high (`GPIOD_OUT_HIGH`), sleeping 10 ms (`fsleep(10000)`), deasserting active-low `reset` (`GPIOD_OUT_LOW`), and polling `TX_STATUS` for `OCM_STARTUP` before reading `VENDOR_ID` or `DEVICE_ID`. [F271]
- In `pmc_atom.c`, `dmi_callback_siemens()` in `critclk_systems` must walk OEM DMI entries via `dmi_walk(simatic_ipc_find_dmi_entry_helper, &st_id)` and set `pmc_clk_is_critical = false` unless `st_id` is `SIMATIC_IPC_IPC227E` or `SIMATIC_IPC_IPC277E`. [F273]
