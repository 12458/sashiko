# RADEON and AMDGPU DRM DRIVERS — drivers/gpu/drm/amd/amdgpu (part 14)

Hardware IP block driver for GFX v8.0 (`gfx_v8_0.c`, Volcanic Islands / GCN 1.2 family including Tonga, Carrizo, Stoney, Fiji, and Polaris10/11/12), managing GFX and compute rings, CP/RLC microcode loading, MQD setup, KIQ, golden registers, clockgating/powergating, and GFX interrupts.

## Architecture & Data Flow

- In `gfx_v8_0_hw_init`, `gfx_v8_0_constants_init` (which runs `gfx_v8_0_setup_rb` and `gfx_v8_0_get_cu_info`) must execute before `adev->gfx.rlc.funcs->resume` and `gfx_v8_0_cp_resume`, because both consume `adev->gfx.config.rb_config[0][0]` and `gfx_v8_0_init_pg` consumes `adev->gfx.cu_info.ao_cu_mask`. [F1569]
- In `gfx_v8_0_cp_resume` and `gfx_v8_0_post_soft_reset`, `gfx_v8_0_kiq_resume` must run before `gfx_v8_0_kcq_resume`, because `gfx_v8_0_kcq_resume` calls `gfx_v8_0_kiq_kcq_enable` to emit `PACKET3_SET_RESOURCES` and `PACKET3_MAP_QUEUES` onto `adev->gfx.kiq[0].ring`. [F1630]
- When `gfx_v8_0_cp_compute_enable(adev, false)` halts the MEC engines via `mmCP_MEC_CNTL`, it must also set `adev->gfx.kiq[0].ring.sched.ready = false` so callers do not submit commands to the halted KIQ ring. [F1578]
- In `gfx_v8_0_mqd_init`, `mqd->cp_hqd_active` must only be set to `1` when `ring->funcs->type == AMDGPU_RING_TYPE_KIQ`, because KIQ is activated directly via MMIO in `gfx_v8_0_mqd_commit` whereas compute queues are mapped and activated via `PACKET3_MAP_QUEUES`. [F1572]
- `gfx_v8_0_get_csb_size`, `gfx_v8_0_get_csb_buffer`, and `gfx_v8_0_cp_gfx_start` must be updated in lockstep whenever the clear-state packet sequence or `vi_cs_data` changes, because both the RLC CSB allocation and `amdgpu_ring_alloc` in `gfx_v8_0_cp_gfx_start` rely on `gfx_v8_0_get_csb_size`. [F1575]
- `gfx_v8_0_ring_funcs_gfx`, `gfx_v8_0_ring_funcs_compute`, and `gfx_v8_0_ring_funcs_kiq` `.emit_frame_size` and `.emit_ib_size` must be `>=` the maximum DWords emitted per frame or IB, including the 14-DWord `CE_META` and 31-DWord `DE_META` chained-IB payloads (`vi_ce_ib_state_chained_ib` / `vi_de_ib_state_chained_ib`). [F1590]
- In `gfx_v8_0_ring_emit_ce_meta` and `gfx_v8_0_ring_emit_de_meta`, `ring->adev->virt.chained_ib_support` selects between the `chained` and `regular` variants of the `ce_payload`/`de_payload` unions and between `struct vi_gfx_meta_data_chained_ib` and `struct vi_gfx_meta_data` CSA offsets. [F1554]
- In `gfx_v8_0_ring_emit_vm_flush`, after emitting `amdgpu_gmc_emit_flush_gpu_tlb` and `PACKET3_WAIT_REG_MEM` on `mmVM_INVALIDATE_REQUEST`, `PACKET3_PFP_SYNC_ME` must be emitted when and only when `ring->funcs->type == AMDGPU_RING_TYPE_GFX` (compute/KIQ rings lack a PFP). [F1643]
- `CHIP_TOPAZ` does not support GFX ring doorbells: `gfx_v8_0_sw_init` must leave `ring->use_doorbell` false on `CHIP_TOPAZ`, `gfx_v8_0_set_cpg_door_bell` must return without touching `mmCP_RB_DOORBELL_CONTROL`, and `gfx_v8_0_ring_set_wptr_gfx` must write `mmCP_RB0_WPTR` followed by a `RREG32(mmCP_RB0_WPTR)` readback flush when `!ring->use_doorbell`. [F1625]
- `gfx_v8_0_set_compute_eop_interrupt_state` and `gfx_v8_0_emit_wave_limit` must only modify MEC1 (`me == 1`, pipes 0..3) registers (`mmCP_ME1_PIPE*_INT_CNTL` and `mmSPI_WCL_PIPE_PERCENT_CS0..3`; MEC2 is managed by `amdkfd`), and `gfx_v8_0_emit_wave_limit` must skip `i == ring->pipe` so a high-priority compute ring does not throttle its own pipe. [F1574]
- In `gfx_v8_0_eop_irq` and `gfx_v8_0_fault`, when `me_id` is `1` or `2`, the scan over `adev->gfx.compute_ring` must check all three of `ring->me == me_id`, `ring->pipe == pipe_id`, and `ring->queue == queue_id` before calling `amdgpu_fence_process` or `drm_sched_fault`. [F1599]
- `gfx_v8_0_init_gds_vmid` must only zero `amdgpu_gds_reg_offset[vmid]` for `vmid >= 1` and leave VMID 0 untouched, because `adev->gds.gds_size` is initialized from `mmGDS_VMID0_SIZE` and HWS firmware requires VMID 0 GDS access to save and restore entries. [F1573]
- In `gfx_v8_0_parse_ind_reg_list`, each non-`0xFFFFFFFF` entry in `register_list_format` is a 3-dword tuple: on `0xFFFFFFFF` the loop sets `new_entry = true` and `continue`s so `ind_offset++` advances by 1, whereas on valid entries it must advance `ind_offset += 2` to index and overwrite the 3rd dword before `ind_offset++` moves to the next tuple. [F1592]
- In `gfx_v8_0_tiling_mode_table_init`, `reg_offset == 7` in `macrotile_mode_array` (`mmGB_MACROTILE_MODE0 + 7`) must be skipped on all VI ASICs, and `reg_offset` values `7, 12, 17, 23` in `tile_mode_array` (`mmGB_TILE_MODE0 + reg_offset`) must also be skipped on 2-pipe ASICs (`CHIP_TOPAZ`, `CHIP_STONEY`, `CHIP_CARRIZO`). [F1587]
- In `gfx_v8_0_write_harvested_raster_configs`, `sh_per_se` and `num_se` must be clamped to at least 1 with `max_t(unsigned, ..., 1)` before dividing `num_rb` to compute `rb_per_pkr` and `rb_per_se`. [F1608]
- In `gfx_v8_0_do_edc_gpr_workarounds`, `vgpr_offset` and `sgpr_offset` within the IB must be 256-byte aligned (`ALIGN(..., 256)`) because `mmCOMPUTE_PGM_LO` and `mmCOMPUTE_PGM_HI` take the shader GPU address shifted right by 8 bits (`(ib.gpu_addr + offset) >> 8`). [F1589]

## Synchronization

- Every function in `gfx_v8_0.c` that selects a specific shader engine, shader array, or instance via `gfx_v8_0_select_se_sh` must hold `adev->grbm_idx_mutex` and restore broadcast indexing with `gfx_v8_0_select_se_sh(adev, 0xffffffff, 0xffffffff, 0xffffffff, 0)` before unlocking on every exit path. [F1537]
- Accesses to per-VMID or per-queue SRBM-indexed registers (including calls to `gfx_v8_0_mqd_init`, `gfx_v8_0_mqd_commit`, and `gfx_v8_0_deactivate_hqd`) must hold `adev->srbm_mutex`, select the target `(me, pipe, queue, vmid)` via `vi_srbm_select`, and reset `vi_srbm_select(adev, 0, 0, 0, 0)` before unlocking. [F1538]
- `gfx_v8_0_get_gpu_clock_counter` must hold `adev->gfx.gpu_clock_mutex` across both the capture trigger write to `mmRLC_CAPTURE_GPU_CLOCK_COUNT` and the subsequent reads of `mmRLC_GPU_CLOCK_COUNT_LSB` and `mmRLC_GPU_CLOCK_COUNT_MSB`. [F1547]
- In `gfx_v8_0_late_init`, `gfx_v8_0_do_edc_gpr_workarounds` must synchronously complete its IB execution and read `sec_ded_counter_registers` to clear initial ECC/EDC counts before `amdgpu_irq_get` enables `adev->gfx.cp_ecc_error_irq` and `adev->gfx.sq_irq`. [F1549]
- During teardown in `gfx_v8_0_hw_fini`, `gfx_v8_0_kcq_disable` must submit `PACKET3_UNMAP_QUEUES` on `adev->gfx.kiq[0].ring` and synchronously wait for completion via `amdgpu_ring_test_helper(kiq_ring)` before halting the CP or stopping the RLC. [F1550]

## Object Lifetimes

- In `gfx_v8_0_init_microcode`, `adev->gfx.rlc.register_restore` is an interior pointer into the buffer allocated for `adev->gfx.rlc.register_list_format`, so teardown in `gfx_v8_0_free_microcode` must only call `kfree(adev->gfx.rlc.register_list_format)` and never free `adev->gfx.rlc.register_restore` separately. [F1533]
- `gfx_v8_0_init_save_restore_list` must operate on a temporary `kmemdup` copy of `adev->gfx.rlc.register_list_format` and `kfree` that copy before returning because `gfx_v8_0_parse_ind_reg_list` overwrites register offset entries in place with unique-index table slots. [F1534]
- `gfx_v8_0_mec_init` must unmap and unreserve `adev->gfx.mec.hpd_eop_obj` via `amdgpu_bo_kunmap` and `amdgpu_bo_unreserve` after zeroing the HPD buffer created by `amdgpu_bo_create_reserved`, while keeping the BO allocated until `gfx_v8_0_mec_fini` frees it with `amdgpu_bo_free_kernel`. [F1536]
- In `gfx_v8_0_sw_init`, `amdgpu_gfx_kiq_init` must be called before `amdgpu_gfx_kiq_init_ring` and `amdgpu_gfx_mqd_sw_init`, and `gfx_v8_0_sw_fini` must tear them down in reverse order (`amdgpu_gfx_mqd_sw_fini`, `amdgpu_gfx_kiq_free_ring`, `amdgpu_gfx_kiq_fini`) along with all GFX/compute rings, MEC, RLC, and microcode. [F1539]
- Every call to `amdgpu_gfx_rlc_enter_safe_mode(adev, 0)` in `gfx_v8_0_hw_fini`, `gfx_v8_0_set_powergating_state`, and `gfx_v8_0_update_gfx_clock_gating` must be paired with a matching `amdgpu_gfx_rlc_exit_safe_mode(adev, 0)` under the same condition before returning. [F1540]
- IRQ references acquired with `amdgpu_irq_get` in `gfx_v8_0_late_init` (`priv_reg_irq`, `priv_inst_irq`, `cp_ecc_error_irq`, and `sq_irq`) must each be balanced by `amdgpu_irq_put` in `gfx_v8_0_hw_fini`, and `gfx_v8_0_hw_fini` must disable KCQs via `gfx_v8_0_kcq_disable` before returning (including on SR-IOV VFs). [F1541]

## API Contracts

- Callers of `gfx_v8_0_raster_config` (such as `gfx_v8_0_setup_rb`) must initialize `*rconf` and `*rconf1` to `0` before calling it, because `gfx_v8_0_raster_config` updates both out-parameters using bitwise OR-assignment (`|=`). [F1556]
- In `gfx_v8_0_get_clockgating_state`, when `amdgpu_sriov_vf(adev)` is false, the function only ORs (`|=`) clockgating capability bits into `*flags`, so callers must initialize `*flags = 0` beforehand; under SR-IOV VF it sets `*flags = 0` but still falls through to OR hardware register bits unless it returns. [F1559]
- Callers of `gfx_v8_0_read_wave_data` must initialize `*no_fields = 0` before invocation, because `gfx_v8_0_read_wave_data` appends wave status words to `dst[(*no_fields)++]` without resetting `*no_fields`. [F1558]
- In `gfx_v8_0_kiq_init_queue` and `gfx_v8_0_kcq_init_queue`, `ring->mqd_ptr` points to a `struct vi_mqd_allocation` (allocated via `amdgpu_gfx_mqd_sw_init`), and before calling `gfx_v8_0_mqd_init` on initial setup it must be zeroed over `sizeof(struct vi_mqd_allocation)` with `dynamic_cu_mask` and `dynamic_rb_mask` set to `0xFFFFFFFF`. [F1557]
- In `gfx_v8_0_kcq_init_queue`, the backup slot index `mqd_idx` into `adev->gfx.mec.mqd_backup[mqd_idx]` is computed via pointer subtraction `ring - &adev->gfx.compute_ring[0]`, so `ring` must always point to an element of `adev->gfx.compute_ring[]`. [F1618]
- In `gfx_v8_0_mqd_commit`, `mqd` is indexed as a flat `uint32_t` array starting at `&mqd->cp_mqd_base_addr_lo` via `mqd_data[mqd_reg - mmCP_MQD_BASE_ADDR]`, requiring `struct vi_mqd` fields from `cp_mqd_base_addr_lo` through `cp_hqd_error` to match the exact MMIO register offset order `mmCP_MQD_BASE_ADDR`..`mmCP_HQD_ERROR`. [F1564]
- `ring->me` for compute rings is 1-based (`mec + 1`, where `1` is MEC1 and `2` is MEC2), so `gfx_v8_0_compute_ring_init` must subtract 1 when computing `irq_type` (`(ring->me - 1) * adev->gfx.mec.num_pipe_per_mec + ring->pipe`), and `gfx_v8_0_kiq_kcq_enable` must map `ring->me` to 0-based `PACKET3_MAP_QUEUES_ME(ring->me == 1 ? 0 : 1)`. [F1560]
- In `gfx_v8_0_ring_emit_rreg`, `reg_val_offs` is a 32-bit DWord index into `adev->wb`, not a byte offset, because `gfx_v8_0_ring_emit_rreg` computes the destination GPU address as `adev->wb.gpu_addr + reg_val_offs * 4`. [F1563]
- `gfx_v8_0_ring_emit_init_cond_exec` must capture `ring->wptr & ring->buf_mask` immediately before writing a `0` placeholder DWord at the end of `PACKET3_COND_EXEC` and return that masked index, because `amdgpu_ring_patch_cond_exec` warns if `offset > ring->buf_mask` or `ring->ring[offset] != 0`. [F1646]

## Error Handling

- In `gfx_v8_0_init_microcode`, optional `_2.bin` firmware requests on `CHIP_POLARIS10`..`CHIP_POLARIS12` fall back to the required `.bin` firmware only when `amdgpu_ucode_request` returns `-ENODEV`, while any failure loading `mec2_fw` must reset `err = 0` and set `adev->gfx.mec2_fw = NULL` rather than failing init. [F1552]
- When a command stream triggers a privileged register or privileged instruction fault interrupt, `gfx_v8_0_priv_reg_irq` and `gfx_v8_0_priv_inst_irq` must report the fault to the DRM scheduler via `gfx_v8_0_fault` (`drm_sched_fault`) rather than invoking `WARN` or `BUG`. [F1652]

## External Contracts

- In `gfx_v8_0_mqd_init`, the `EOP_SIZE`, `QUEUE_SIZE`, and `RPTR_BLOCK_SIZE` fields in `mmCP_HQD_EOP_CONTROL` and `mmCP_HQD_PQ_CONTROL` encode `2^(field + 1)` DWords (`order_base_2(size_in_bytes / 4) - 1`), whereas `RB_BUFSZ` in `mmCP_RB0_CNTL` in `gfx_v8_0_cp_gfx_resume` encodes `order_base_2(ring->ring_size / 8)` QWords. [F1609]
- In `gfx_v8_0_mqd_commit`, `CP_PQ_WPTR_POLL_CNTL.EN` must be cleared before programming HQD registers, `mmCP_MQD_BASE_ADDR`..`mmCP_HQD_ACTIVE` must be written last to activate the HQD, and on `CHIP_TONGA` (`adev->asic_type == CHIP_TONGA`), `mmCP_HQD_EOP_RPTR`, `mmCP_HQD_EOP_WPTR`, and `mmCP_HQD_EOP_WPTR_MEM` must not be written. [F1623]

## Known Pitfalls

- In `gfx_v8_0_sw_init`, the compute queue setup loop nests `j` (`num_queue_per_pipe`) outside `k` (`num_pipe_per_mec`) to allocate horizontally across pipes, so `amdgpu_gfx_is_mec_queue_enabled` and `gfx_v8_0_compute_ring_init` must be passed `(i, k, j)` for `(mec, pipe, queue)` and `ring_id` must increment only for enabled queues. [F1591]
- In `gfx_v8_0_cp_gfx_resume`, `gfx_v8_0_mqd_init`, and `gfx_v8_0_do_edc_gpr_workarounds`, 256-byte-aligned 48-bit GPU addresses (`ring->gpu_addr`, `ring->eop_gpu_addr`, shader address) must be right-shifted by 8 in a 64-bit variable before extracting low 32 bits and `upper_32_bits` for `*_LO`/`_BASE` and `*_HI` register pairs. Broken by: `lower_32_bits(addr) >> 8` and `upper_32_bits(addr)`, which drops bits [39:32]. [F1604]
- In `gfx_v8_0_kiq_kcq_enable`, `queue_mask` is a 64-bit mask across `AMDGPU_MAX_COMPUTE_QUEUES`, so `i` must be checked against `sizeof(queue_mask) * 8` and shifted using a 64-bit literal (`1ull << i`) before splitting into `lower_32_bits(queue_mask)` and `upper_32_bits(queue_mask)`. [F1605]
- In `gfx_v8_0_init_microcode`, `rlc_hdr->reg_list_format_array_offset_bytes` and `rlc_hdr->reg_list_array_offset_bytes` are byte offsets from `rlc_hdr` (`const struct rlc_firmware_header_v2_0 *`), so `rlc_hdr` must be cast to `uintptr_t` (or a byte pointer) before adding the offset. [F1613]
- In `gfx_v8_0_init_microcode`, `header->ucode_size_bytes` in `struct common_firmware_header` is in bytes whereas `cp_hdr->jt_size` in `struct gfx_firmware_header_v1_0` is in DWords, so `cp_hdr->jt_size` must be converted to bytes via `<< 2` before `ALIGN(..., PAGE_SIZE)` when adding to `adev->firmware.fw_size`. [F1614]
- In `gfx_v8_0_ring_emit_ce_meta` and `gfx_v8_0_ring_emit_de_meta`, `cnt_ce` and `cnt_de` are `PACKET3_WRITE_DATA` DWord counts (`(sizeof(payload.*) >> 2) + 4 - 2`), and `amdgpu_ring_write_multiple` takes the DWord count `cnt_ce - 2` / `cnt_de - 2` (`sizeof(payload.*) >> 2`) rather than a byte size. [F1617]
- In `gfx_v8_0_set_sq_int_state`, `SQ_INTERRUPT_MSG_CTRL`'s `STALL` field has inverted polarity relative to `enum amdgpu_interrupt_state` (`AMDGPU_IRQ_STATE_DISABLE` sets `enable_flag = 1`, `AMDGPU_IRQ_STATE_ENABLE` sets `enable_flag = 0`), and `cz_enable_cp_power_gating` similarly writes `enable ? 0 : 1` to `RLC_PG_CNTL.CP_PG_DISABLE`. [F1596]
- In `gfx_v8_0_get_clockgating_state`, `AMD_CG_SUPPORT_GFX_MGCG`, `AMD_CG_SUPPORT_GFX_CGTS`, and `AMD_CG_SUPPORT_GFX_CGTS_LS` are active-low override bits (reported enabled when `!(data & *_OVERRIDE_MASK)`), whereas `AMD_CG_SUPPORT_GFX_CGCG`, `CGLS`, `RLC_LS`, and `CP_LS` are active-high enable bits (reported enabled when `data & *_EN_MASK`). [F1597]
