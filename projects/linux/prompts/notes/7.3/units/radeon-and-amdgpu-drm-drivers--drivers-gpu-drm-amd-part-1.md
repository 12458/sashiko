# RADEON and AMDGPU DRM DRIVERS — drivers/gpu/drm/amd (part 1)

This unit defines the core `amdgpu.h` header and `struct amdgpu_device`, Audio Co-Processor (ACP) power/device management, ACPI integration (ATIF, ATCS, XCC `_DSM`, S0ix), AMD Error Check Architecture (ACA), Aldebaran mode-2 reset handling, and the KGD-to-KFD compute interface (`amdgpu_amdkfd*`) across GFX v7 through v12 and MI-series GPUs.

## Architecture & Data Flow

- `struct dev_pagemap pgmap` (which ends in a flexible array) must remain the final member of `struct amdgpu_kfd_dev`, and `struct amdgpu_kfd_dev kfd` must remain the final member of `struct amdgpu_device`. Similarly, `struct dma_fence base` must remain the first member (offset 0) of `struct amdgpu_amdkfd_fence` because `amdkfd_fence_release` passes `struct dma_fence *f` directly to `kfree_rcu(f, rcu)`. [F108, F109]
- In `hqd_load` across GFX7–GFX11, `mqd_hqd = &m->cp_mqd_base_addr_lo` is indexed as a flat `uint32_t` array by `reg - hqd_base` over `[hqd_base, hqd_end]`, requiring MQD fields from `cp_mqd_base_addr_lo` to match hardware HQD register offsets 1-to-1. On GFX9.4.3, GFX10, GFX10.3, and GFX11, when `wptr` is non-NULL, `guessed_wptr` written to `CP_HQD_PQ_WPTR_LO/HI` must reconstruct the 64-bit RPTR from `cp_hqd_pq_rptr` and `cp_hqd_pq_wptr_lo/hi`, adding `queue_size` when `(cp_hqd_pq_wptr_lo & (queue_size - 1)) < (cp_hqd_pq_rptr & (queue_size - 1))`. [F81, F85]
- In `kgd_hqd_destroy` (GFX8, GFX10), `hqd_destroy_v10_3`, and `hqd_destroy_v11`, when `m->cp_hqd_vmid == 0` (the HIQ), `RLC_CP_SCHEDULERS.scheduler1` must be cleared to `0` while holding `acquire_queue` before writing `CP_HQD_DEQUEUE_REQUEST`. [F64]
- In SDMA HQD load and destroy functions (`kgd_arcturus_hqd_sdma_*`, `kgd_gfx_v9_4_3_hqd_sdma_*`, `kgd_hqd_sdma_*`, `hqd_sdma_*_v10_3`/`v11`), `RB_ENABLE` in `RB_CNTL` must be cleared and `CONTEXT_STATUS__IDLE_MASK` polled until set before mutating queue registers, and destroy must save hardware `RB_RPTR`/`RB_RPTR_HI` back into the MQD. [F63]
- In `kgd_set_pasid_vmid_mapping` (GFX7, GFX8) and `kgd_gfx_v9_4_3_set_pasid_vmid_mapping` (GC 9.4.3), after writing `ATC_VMID0_PASID_MAPPING + vmid`, software must wait for bit `1U << vmid` in `ATC_VMID_PASID_MAPPING_UPDATE_STATUS`, write `1U << vmid` to clear it, and mirror `pasid_mapping` into `IH_VMID_0_LUT + vmid`. On GC 9.4.3, `regIH_VMID_LUT_INDEX` must also be saved before selecting the XCC (`aid * 4 + (phy_inst % 2) + 1`) and AID (`aid * 4`) indices to write `regIH_VMID_0_LUT` and `regIH_VMID_0_LUT_MM`, and restored afterward. [F58, F62]
- On GFX10, because `mmSPI_GDBG_TRAP_MASK` is global across all processes, `kgd_gfx_v10_validate_trap_override_request` must restrict `*trap_mask_supported` to `KFD_DBG_TRAP_MASK_DBG_ADDRESS_WATCH` and require `trap_override == KFD_DBG_TRAP_OVERRIDE_OR`. In `kgd_gfx_v10_set_wave_launch_trap_override`, `mmSPI_GDBG_WAVE_CNTL` must be sampled into `wave_cntl_prev` before calling `kgd_gfx_v10_set_wave_launch_stall(adev, vmid, true)` and restored by writing `wave_cntl_prev` back after updating `mmSPI_GDBG_TRAP_MASK` (never by calling `set_wave_launch_stall(..., false)`). [F59, F60]
- In `kgd_gfx_v9_4_3_set_wave_launch_trap_override`, `kgd_gfx_v11_set_wave_launch_trap_override`, and `kgd_gfx_v12_set_wave_launch_trap_override`, `kfd_dbg_trap_cntl_prev` must be decoded via `trap_mask_map_hw_to_sw` before applying `trap_mask_request` and re-encoded via `trap_mask_map_sw_to_hw` so `TRAP_ON_START` and `TRAP_ON_END` are preserved. [F100]
- In `kgd_gfx_v10_set_address_watch`, `mmTCP_WATCH0_CNTL` and `mmSQ_WATCH0_CNTL` for `watch_id` must be written with `VALID = 0` before programming `mmTCP_WATCH0_ADDR_H`/`L` and `mmSQ_WATCH0_ADDR_H`/`L`, and written with `VALID = 1` only after both address pairs are programmed. When setting `MASK`, `watch_address_mask` must be shifted right by 7 for `TCP_WATCH0_CNTL` versus right by 6 for `SQ_WATCH0_CNTL`. [F61, F84]
- In `amdgpu_amdkfd_device_init`, after `bitmap_complement` populates `gpu_resources.cp_queue_bitmap` up to `AMDGPU_MAX_QUEUES`, all bits from `last_valid_bit` (`num_pipe_per_mec * num_queue_per_pipe`) through `AMDGPU_MAX_QUEUES - 1` must be explicitly cleared with `clear_bit`. [F78]
- In `aldebaran_mode2_prepare_hwcontext`, `aldebaran_mode2_suspend_ip` must only be called when `!amdgpu_sriov_vf(adev)`. In `aldebaran_mode2_restore_ip`, RLC must be resumed via `adev->gfx.rlc.funcs->resume(adev)` after reloading firmware with `psp_load_fw_list` and before calling `amdgpu_dpm_wait_for_event(adev, SMU_EVENT_RESET_COMPLETE, 0)`. [F118, F119]
- When `amd_acp_hw_init` returns `-ENODEV` (Azalia board), `acp_hw_init` powergates ACP via `amdgpu_dpm_set_powergating_by_smu` without allocating `acp_genpd` or `acp_cell`; `acp_suspend`, `acp_resume`, and `acp_hw_fini` must check `!adev->acp.acp_cell` / `!adev->acp.acp_genpd` to ungate ACP on suspend/fini and re-gate it on resume without dereferencing NULL. [F135]
- `amdgpu_acpi_is_s0ix_active` must return `false` unless `adev` is a `CHIP_RAVEN` or newer APU (`adev->flags & AMD_IS_APU`), `pm_suspend_target_state == PM_SUSPEND_TO_IDLE`, both `adev->pm.pp_feature & PP_GFXOFF_MASK` and `acpi_gbl_FADT.flags & ACPI_FADT_LOW_POWER_S0` are set, and `CONFIG_AMD_PMC` is enabled. In `amdgpu_amdkfd_suspend` and `amdgpu_amdkfd_resume`, when `adev->in_s0ix` is true, the driver must call `kgd2kfd_stop_sched_all_nodes` / `kgd2kfd_start_sched_all_nodes` rather than `kgd2kfd_suspend` / `kgd2kfd_resume`. [F136, F137]

## Synchronization

- Every `acquire_queue` or `lock_srbm` call in `amdgpu_amdkfd_gfx_v7.c`, `v8.c`, `v10.c`, `v10_3.c`, `v11.c`, and `v12.c` locks `adev->srbm_mutex` and selects an SRBM/GRBM pipe/queue/VMID, and must be paired with `release_queue` or `unlock_srbm` (which resets the selection to 0 and unlocks `srbm_mutex`) on all paths, including `-ETIME` timeouts. [F8]
- In GFX v7 and GFX v8 `kgd_hqd_load`, `release_queue(adev)` (unlocking `adev->srbm_mutex`) must be called before `read_user_wptr(mm, wptr, wptr_val)`, and `acquire_queue(adev, pipe_id, queue_id)` must be re-acquired afterward before writing `mmCP_HQD_PQ_WPTR` and `mmCP_HQD_ACTIVE`. [F23]
- In `kgd_gfx_v9_4_3_hqd_load`, `kgd_hqd_load` (GFX v10), `hqd_load_v10_3`, and `hqd_load_v11`, user `wptr` must not be read on the CPU with `get_user`; instead, doorbell logic (`DOORBELL_EN`) must be enabled first and a hardware one-shot poll triggered via `CP_PQ_WPTR_POLL_CNTL1` before setting `CP_HQD_ACTIVE`. [F24]
- `read_user_wptr` must wrap `get_user` inside `pagefault_disable()` and `pagefault_enable()`, and only access `wptr` when `mmptr == current->mm` or `current->flags & PF_KTHREAD` (via `kthread_use_mm`/`kthread_unuse_mm`), so reading pinned user queue write pointers never faults or takes `mmap_lock` under DQM locks. [F154]
- In GFX v7 and GFX v8 `kgd_hqd_destroy`, polling `mmCP_HQD_IQ_TIMER` and `mmCP_HQD_DEQUEUE_REQUEST` (`IQ_REQ_PEND`) before issuing a dequeue request must run with local interrupts and preemption disabled (`local_irq_save`/`preempt_disable`), which must be restored before the sleeping `usleep_range` poll on `mmCP_HQD_ACTIVE`. [F29]
- When `kgd_hiq_mqd_load` (GFX v10), `hiq_mqd_load_v10_3`, `hiq_mqd_load_v11`, or `amdgpu_amdkfd_unmap_hiq` submits packets on `kiq_ring`, `kiq->ring_lock` (`adev->gfx.kiq[inst].ring_lock`) must be held across `amdgpu_ring_alloc`, packet writes, and `amdgpu_ring_commit`, nesting inside `adev->srbm_mutex` when `acquire_queue` is used and avoiding `GFP_KERNEL` allocations inside `ring_lock`. [F31]
- In `kgd_wave_control_execute` (GFX v7, v8, v10) and `wave_control_execute_v10_3`/`v11`/`v12`, `adev->grbm_idx_mutex` must be held across writing `gfx_index_val` to `GRBM_GFX_INDEX`, issuing `SQ_CMD`, and restoring `GRBM_GFX_INDEX` to broadcast writes (`INSTANCE_BROADCAST_WRITES`, `SH`/`SA_BROADCAST_WRITES`, `SE_BROADCAST_WRITES`). [F26]
- In `set_barrier_auto_waitcnt` (called under `adev->grbm_idx_mutex` from `kgd_arcturus_enable_debug_trap` and `kgd_arcturus_disable_debug_trap`), after updating `adev->barrier_has_auto_waitcnt` with `WRITE_ONCE`, `adev->reset_domain->sem` must be acquired with `down_read_trylock` (never blocking `down_read`). Once acquired and `amdgpu_amdkfd_suspend(adev, true)` is called, every exit path must restart the compute scheduler via `suspend_resume_compute_scheduler(adev, false)`, call `amdgpu_amdkfd_resume(adev, true)`, and `up_read` `reset_domain->sem`. [F12, F27]
- On GFX v10, before modifying `mmSPI_GDBG_TRAP_CONFIG`, `mmSPI_GDBG_TRAP_MASK`, or `mmSPI_GDBG_WAVE_CNTL2`, callers must hold `adev->grbm_idx_mutex` and call `kgd_gfx_v10_set_wave_launch_stall(adev, vmid, true)`, which sets `STALL_VMID` and performs `KGD_GFX_V10_WAVE_LAUNCH_SPI_DRAIN_LATENCY` (110) reads of `mmSPI_GDBG_WAVE_CNTL` to drain SPI. [F28]
- In `amdgpu_amdkfd_send_close_event_drain_irq`, `amdgpu_ih_wait_on_checkpoint_process_ts(adev, &adev->irq.ih)` must succeed before `amdgpu_amdkfd_interrupt(adev, payload)` is called to deliver the close event payload. [F32]
- In `aldebaran_mode2_perform_reset`, `tmp_adev->reset_cntl->reset_lock` is held across queueing and `flush_work(&tmp_adev->reset_cntl->reset_work)` for all devices in `reset_device_list`, so `aldebaran_async_reset` (and `aldebaran_mode2_reset`) must never acquire `reset_cntl->reset_lock`. [F148]

## Object Lifetimes

- When `adev->kfd.dev` is non-NULL, `amdgpu_amdkfd_device_fini_sw` must call `kgd2kfd_device_exit(adev->kfd.dev)`, clear `adev->kfd.dev = NULL`, and subtract `adev->gmc.real_vram_size` from `amdgpu_amdkfd_total_mem_size` to balance `amdgpu_amdkfd_device_init`. [F3]
- In `amdgpu_amdkfd_fence_create` and `amdkfd_fence_release`, the fence's `mm_struct` reference is pinned with `mmgrab(mm)` before `dma_fence_init` and released with `mmdrop(fence->mm)` followed by `kfree_rcu(f, rcu)` upon fence release (never `mmget`/`mmput` or synchronous `kfree`). [F33]
- `amdgpu_atif_call` and `amdgpu_atcs_call` free the `ACPI_ALLOCATE_BUFFER` output buffer on evaluation or type-validation failure and return `NULL`, but transfer ownership of the allocated `union acpi_object *` to the caller on success, requiring every caller to `kfree` the returned pointer on all paths. [F17]
- In `amdgpu_atif_pci_probe_handle` and `amdgpu_atcs_pci_probe_handle`, if `amdgpu_atif_verify_interface` or `amdgpu_atcs_verify_interface` fails after setting `amdgpu_acpi_priv.atif.handle` or `amdgpu_acpi_priv.atcs.handle`, the handle must be reset to `0` before returning `false`. [F20]
- `amdgpu_acpi_get_numa_info` owns `struct amdgpu_numa_info` allocations in the global `numa_info_xa` xarray and lends borrowed pointers to `xcc_info->numa_info`. In `amdgpu_acpi_release`, `amdgpu_acpi_dev_list` and each `dev_info->xcc_list` must be torn down with nested `list_for_each_entry_safe` loops that unlink and `kfree` every child `xcc_info` before its parent `dev_info`, while `numa_info` entries must only be freed via `numa_info_xa` iteration and never via `kfree(xcc_info->numa_info)`. [F19, F94]
- In `acp_hw_fini`, child devices must be detached from the generic PM domain via `device_for_each_child(adev->acp.parent, NULL, acp_genpd_remove_device)` and removed via `mfd_remove_devices(adev->acp.parent)` before freeing `adev->acp.acp_res`, `adev->acp.acp_genpd`, and `adev->acp.acp_cell`. [F21]

## API Contracts

- `read_user_wptr(mmptr, wptr, dst)` in `amdgpu_amdkfd.h` only writes `dst` when it returns `true`, so callers in `hqd_load` and `hqd_sdma_load` must check its boolean return before reading `dst` and, in `hqd_sdma_load`, fall back to writing the saved `rb_rptr` into `RB_WPTR` when it returns `false`. Although `kfd2kgd_calls.hqd_sdma_load` takes `uint32_t __user *wptr`, on GFX9, GFX10, and GFX11 SDMA uses a 64-bit write pointer, so `hqd_sdma_load` must cast `wptr` to `uint64_t __user *` and pass a `uint64_t` destination to `read_user_wptr` before writing `RB_WPTR` and `RB_WPTR_HI`. [F51, F80]
- In `amdgpu_amdkfd_gfx_v10.c`, `amdgpu_amdkfd_gfx_v10_3.c`, and `amdgpu_amdkfd_gfx_v11.c`, `lock_srbm` and `RLC_CP_SCHEDULERS` use a 1-based MEC index (`mec = (pipe_id / adev->gfx.mec.num_pipe_per_mec) + 1`, where `0` is GFX ME0), whereas `PACKET3_MAP_QUEUES_ME` in `hiq_mqd_load` requires the 0-based compute ME index `mec - 1`. [F53]
- In `kfd2kgd_calls`, `queue_address` in `hqd_is_occupied` and `tba_addr`/`tma_addr` in `program_trap_handler_settings` are byte GPU virtual addresses that must be right-shifted by 8 bits (`>> 8`) before comparing with `CP_HQD_PQ_BASE`/`CP_HQD_PQ_BASE_HI` or writing to `SQ_SHADER_TBA_LO`/`HI` and `SQ_SHADER_TMA_LO`/`HI`. [F54]
- When a callback in `struct kfd2kgd_calls` (such as `hqd_sdma_get_doorbell`) is called unconditionally by KFD without a NULL check, every hardware generation's `kfd2kgd_calls` table (`gfx_v7_kfd2kgd` through `gfx_v12_kfd2kgd`, `arcturus_kfd2kgd`, `aldebaran_kfd2kgd`, and `gc_9_4_3_kfd2kgd`) must wire up a handler or a stub. [F55]
- In `amdgpu_amdkfd_gfx_v7.c` and `amdgpu_amdkfd_gfx_v8.c`, `set_vm_context_page_table_base` computes the register address as `mmVM_CONTEXT8_PAGE_TABLE_BASE_ADDR + vmid - 8`, so it must verify `amdgpu_amdkfd_is_kfd_vmid(adev, vmid)` first to ensure `vmid >= 8`. [F83]
- `amdgpu_ip_version(adev, ip, inst)` masks off the lower 8 bits (`& ~0xFFU`) containing the 4-bit variant and 4-bit subrevision fields; code matching a non-zero variant or subrevision from `IP_VERSION_FULL` must call `amdgpu_ip_version_full` instead. [F76]
- `KFD_XCP_MEM_ID(adev, xcp_id)` returns `-1` when `adev->xcp_mgr` is NULL or `xcp_id < 0`, so callers such as `amdgpu_amdkfd_xcp_memory_size` must verify `mem_id >= 0` (and `xcp_id >= 0`) before indexing `adev->gmc.mem_partitions[mem_id]`. [F77]
- `amdgpu_atif_get_sbios_requests` returns a negative errno (`-EIO` or `-EINVAL`) on failure, `0` when no requests are pending, or the positive bit count `hweight32(req->pending)` on success, so callers such as `amdgpu_atif_handler` must check `count <= 0` before reading `*req`. [F40]

## Error Handling

- In `amdgpu_acpi_dev_init` and `amdgpu_acpi_get_xcc_info`, `*dev_info` must be initialized to `NULL` before fallible `_DSM` evaluations, and `obj` must be reset to `NULL` after `ACPI_FREE(obj)` whenever subsequent code can still reach the `out:` label that executes `if (obj) ACPI_FREE(obj)`. [F42]

## Known Pitfalls

- In `amdgpu_amdkfd_gfx_v8.c:kgd_hqd_load`, registers `mmCP_HQD_EOP_RPTR`, `mmCP_HQD_EOP_WPTR`, and `mmCP_HQD_EOP_WPTR_MEM` must be skipped when `adev->asic_type == CHIP_TONGA` due to a Tonga hardware erratum. [F126]
- Timeout polling loops in `amdgpu_amdkfd_*` (such as `kgd_arcturus_hqd_sdma_load`, `kgd_gfx_v9_4_3_set_pasid_vmid_mapping`, `kgd_hqd_destroy`, and `kgd_hqd_sdma_destroy`) must check `jiffies` expiration via `time_after(jiffies, end_jiffies)` rather than direct relational operators. [F107]
- `amdgpu_amdkfd_xcp_memory_size` must use `do_div` to divide the `u64` partition size `tmp` by `adev->xcp_mgr->num_xcp_per_mem_partition` and `ALIGN_DOWN` the result to `PAGE_SIZE`. [F104]
- In `amdgpu_afmt_calc_cts`, the factor `mul` scaling the GCD-reduced `(n, cts)` pair up to `128 * freq / 1000` must use ceiling division `((128 * freq / 1000) + (n - 1)) / n` rather than truncating division. [F105]
