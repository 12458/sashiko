# SOUND — sound/hda/codecs (part 3)

This unit implements HD-Audio codec drivers for Realtek ALC series codecs (ALC260, ALC262, ALC268, ALC269/2xx/7xx, ALC662, ALC680, ALC861, ALC861-VD, ALC880, ALC882/1220, and shared Realtek helpers) and the Silicon Labs Si3054 modem codec, handling vendor COEF registers, GPIO and mute LEDs, CTIA/OMTP headset jack detection, board quirk tables, and ACPI binding to companion smart amplifiers.

## Architecture & Data Flow
- `struct alc_spec` must keep `struct hda_gen_spec gen` as its first member at offset 0 because generic `hda_codec_ops` callbacks and helpers (such as `snd_hda_gen_remove`, `snd_hda_gen_init`, and `snd_hda_gen_build_pcms`) cast `codec->spec` directly to `struct hda_gen_spec *`. [F229]
- In `alc_update_headset_mode()`, transitioning to `ALC_HEADSET_MODE_UNPLUGGED` must reset `spec->current_headset_type` to `ALC_HEADSET_TYPE_UNKNOWN` alongside updating `spec->current_headset_mode` and `spec->gen.hp_jack_present` (as `ALC_HEADSET_MODE_HEADSET` only calls `alc_determine_headset_type()` when `current_headset_type` is `UNKNOWN`), and when `new_headset_mode == ALC_HEADSET_MODE_MIC` the post-switch `snd_hda_set_pin_ctl_cache` block must be skipped so it does not undo `alc_headset_mode_mic_in()` disabling `hp_pin` output and enabling `PIN_VREF50` on `spec->headphone_mic_pin`. [F184, F214]
- Across suspend/resume, `alc269_resume()` must re-write `spec->gpio_data` via `alc_write_gpio_data(codec)` when non-zero, and `alc_fixup_headset_mode()` on `HDA_FIXUP_ACT_INIT` must reset `spec->current_headset_mode` and `spec->current_headset_type` to `UNKNOWN` when `is_s3_resume(codec) || is_s4_resume(codec)`. In `alc225_init()` and `alc294_init()`, manual headphone depop calibration (`alc285_hp_init()` / `alc294_hp_init()`) must only run when `!spec->done_hp_init` or on S3/S4 resume and must set `spec->done_hp_init = true`. [F193, F261]
- In `alc256_shutup()`, when `spec->en_3kpull_low` is true, `alc_update_coef_idx(codec, 0x46, 0, 3 << 12)` must run unconditionally before checking `snd_hda_jack_detect()` or clearing `AC_VERB_SET_PIN_WIDGET_CONTROL` on `hp_pin` to avoid warm-reboot stalls. In `alc225_shutup()`, when `hp1_pin_sense || hp2_pin_sense` is true, setting `3 << 10` in COEF `0x4a` and muting/disabling the headphone pins must be preceded by `alc_disable_headset_jack_key(codec)` and followed (after clearing `3 << 10` in COEF `0x4a`) by `alc_enable_headset_jack_key(codec)`. [F238, F239]
- Quirk and ID table ordering: in `alc269.c`, `SND_PCI_QUIRK_VENDOR` entries belong in `alc269_fixup_vendor_tbl` (not `alc269_fixup_tbl`, since `snd_hda_pick_pin_fixup` runs between them and is a no-op once `codec->fixup_id` is set), and `alc269_fallback_pin_fixup_tbl` may have at most one `SND_HDA_PIN_QUIRK` per `(codec, subvendor)` pair (`match_all_pins = false`). In `alc861_fixup_tbl`, `alc880_fixup_tbl`, and `alc882_fixup_tbl`, `SND_PCI_QUIRK` must precede `SND_PCI_QUIRK_VENDOR` for the same subvendor; in `snd_hda_id_alc861`/`alc662`/`alc882`, `HDA_CODEC_ID_REV` must precede `HDA_CODEC_ID` for the same `vendor_id`; and in `rename_tbl`, narrower `coef_mask` entries must precede broader subset masks for the same `vendor_id`. [F207, F208, F209, F210, F223]
- In `alc269.c`, fixups registering VREF LEDs via `vref_mute_led_set` (`spec->mute_led_nid`) or `vref_micmute_led_set` (`spec->cap_mute_led_nid`) must set the corresponding NID field and `codec->power_filter = led_power_filter` to keep VREF powered in `AC_PWRST_D3`. In `alc269_fixup_hp_mute_led()`, the hex `pin` parsed from `"HP_Mute_LED_%d_%x"` must be bounds-checked to `[0x0a, 0x10)` before computing `spec->mute_led_nid = pin - 0x0a + 0x18`. [F203, F222]
- When a fixup enables VREF on an output or amplifier pin at `HDA_FIXUP_ACT_INIT` via `snd_hda_set_pin_ctl()` (e.g., `alc889_fixup_mbp_vref()`, `alc889_fixup_mac_pins()`, `alc861_fixup_asus_amp_vref_0f()`), it must also set `spec->gen.keep_vref_in_automute = 1`. In `alc260_fixup_gpio1_toggle()`, enabling headphone automute on a single-output-pin machine at `HDA_FIXUP_ACT_PROBE` must populate `spec->gen.autocfg.hp_pins[0]` alongside setting `detect_hp = 1`, `automute_speaker = 1`, and `automute_hook`. [F188, F197]
- In `alc_write_gpio()`, `AC_VERB_SET_GPIO_MASK` and `AC_VERB_SET_GPIO_DIRECTION` must be written to `codec->core.afg` before `alc_write_gpio_data(codec)` writes `AC_VERB_SET_GPIO_DATA`, with an `msleep(1)` in between when `spec->gpio_write_delay` is true. In `alc_fixup_no_depop_delay()`, disabling depop delays must set both `spec->no_depop_delay = 1` (used by `alc_eapd_shutup()` and `alc_resume()`) and `codec->depop_delay = 0` together. [F195, F255]
- When `alc_auto_parse_customize_define()` or `alc_subsystem_id()` falls back to reading the 32-bit BIOS SKU word from pin NID `0x1d` (or `0x17` on ALC260), it must verify bit 0 (`ass & 1`) is set and bits `19:16` equal the popcount of bits `15:1` before unpacking SKU fields. [F200]
- In `alc298_samsung_v2_init_amps()`, `spec->num_speaker_amps` must be initialized before calling `alc298_samsung_v2_disable_amps(codec)`, which must run before programming `alc298_samsung_v2_amp_desc_tbl` or setting `spec->gen.pcm_playback_hook`. ALC5505 DSP helpers (`alc5505_dsp_init`, `alc5505_dsp_suspend`, `alc5505_dsp_resume`) access NID `0x51` and must only be called when `snd_hda_codec_read(codec, 0x51, 0, AC_VERB_PARAMETERS, 0) == 0x10ec5505` (`spec->has_alc5505_dsp`). [F240, F246]
- `alc_set_beep_amp()` must keep `alc_beep_mixer` `static const` and only write `beep_amp` into `knew->private_value` on the `struct snd_kcontrol_new *knew` copy returned by `snd_hda_gen_add_kctl()`. Because `struct alc_spec` defines `u8 alc_mute_keycode_map[1]` and `alc_register_micmute_input_device()` sets `kb_dev->keycodesize` to `sizeof(spec->alc_mute_keycode_map[0])`, any keycode stored in `alc_mute_keycode_map` must fit in `u8` (`<= 255`) unless the array element type is widened. [F236, F248]
- In `si3054_pcm_prepare()`, `stream_tag & 0xf` must be placed into bits `15:12` (`SI3054_DTAG_MASK`) of `SI3054_LINE_LEVEL` for playback while preserving the low byte, and into bits `7:4` (`SI3054_ATAG_MASK`) for capture while preserving the high byte. [F206]

## Synchronization
- `coef_mutex_lock()` must call `snd_hda_power_up_pm(codec)` before acquiring `spec->coef_mutex`, and `coef_mutex_unlock()` must release `spec->coef_mutex` before calling `snd_hda_power_down_pm(codec)`. Callers already holding `guard(coef_mutex)(codec)` (such as `alc_process_coef_fw()`) must use the unlocked `__alc_*_coefex_idx()` helpers rather than re-entering `alc_*_coefex_idx()`. [F153]
- In `alc268_beep_switch_put()`, `codec->control_mutex` must be held while temporarily mutating `kcontrol->private_value` to update NIDs `0x0f` and `0x10`, and `kcontrol->private_value` must be restored before releasing the lock. [F165]

## Object Lifetimes
- In `alc_alloc_spec()`, `codec->spec` and `mutex_init(&spec->coef_mutex)` must be initialized before calling `alc_codec_rename_from_preset(codec)` (which reads COEF registers via `alc_get_coef0()`). In every Realtek `.probe` function, any error path after `alc_alloc_spec()` succeeds must call `snd_hda_gen_remove(codec)` (or `alc269_remove(codec)` in `alc269_probe()`) before returning a negative errno, because `hda_codec_driver_probe()` does not call `ops->remove` when `ops->probe` fails. [F160, F269]
- In `comp_master_ops`, `comp_bind()` must call `hda_component_manager_bind()` before `hda_component_manager_bind_acpi_notifications()`, and `comp_unbind()` must call `hda_component_manager_unbind_acpi_notifications()` before `hda_component_manager_unbind()`. `alc269_remove()` must call `hda_component_manager_free(&spec->comps, &comp_master_ops)` before `snd_hda_gen_remove(codec)` so component masters initialized by `find_cirrus_companion_amps()` outside the HDA fixup table are unregistered before `codec->spec` is freed. [F155, F156]
- `spec->kb_dev` is allocated with non-devres `input_allocate_device()` in `alc_register_micmute_input_device()`, so registration failure must call `input_free_device(spec->kb_dev)` and clear `spec->kb_dev = NULL`, while `HDA_FIXUP_ACT_FREE` must call `input_unregister_device(spec->kb_dev)` and clear `spec->kb_dev = NULL`. In `alc280_fixup_hp_gpio2_mic_hotkey()` and `alc233_fixup_lenovo_line2_mic_hotkey()`, `alc_register_micmute_input_device(codec)` must succeed before `snd_hda_jack_detect_enable_callback()` registers `gpio2_mic_hotkey_event`. [F164, F243]
- Any `struct hda_verb` array passed to `snd_hda_add_verbs()` and any `hda_nid_t` pair list assigned to `spec->gen.preferred_dacs` must be `static` (and `const` for `preferred_dacs`) with a zero sentinel terminator, because both store only the raw pointer for later traversal during init/resume or `alc_parse_auto_config()`. [F230, F231]
- `alc_update_vref_led()` must hold a runtime PM reference via `CLASS(snd_hda_power_pm, pm)(codec)` while calling `snd_hda_set_pin_ctl_cache()`. [F266]

## API Contracts
- In `alc_update_coefex_idx()`, `alc_update_coef_idx()`, and `UPDATE_COEF` / `UPDATE_COEFEX`, `mask` specifies bits to clear and `bits_set` is ORed directly without masking (`(val & ~mask) | bits_set`), whereas in `alc_fix_pll_init()` `coef_bit` is a 0-based bit shift index. Every `struct coef_fw` table passed to `alc_process_coef_fw()` must end with a zero-initialized sentinel (`nid == 0`), where active entries have non-zero `nid` and `mask == (unsigned short)-1` (`0xffff`) performs an uncached direct write. [F177, F198, F271]
- `alc5505_coef_set()` and `alc5505_coef_get()` take an even byte-addressed DSP register offset `index_reg` (which they shift via `index_reg >> 1` for `AC_VERB_SET_COEF_INDEX` on NID `0x51`) and transfer a 32-bit value across two consecutive 16-bit `AC_VERB_SET_PROC_COEF` / `AC_VERB_GET_PROC_COEF` verbs (LSB first, then MSB). Broken by: passing a pre-halved word index or using 16-bit `alc_*_coefex_idx(codec, 0x51, ...)`. [F183]
- `alc_subsystem_id()` returns `1` on valid SKU/SSID and `0` on invalid SKU, whereas `alc_auto_parse_customize_define()` returns `0` on success and `-1` on failure. Any non-NULL `ssid_nids` (`ports`) array passed to `alc_parse_auto_config()`, `alc_ssid_check()`, or `alc_subsystem_id()` must have at least 4 `hda_nid_t` elements ordered `{ port-A, port-E, port-D, port-I }` (`0` for unsupported), because `alc_subsystem_id()` indexes `ports[(ass >> 11) & 0x3]` without bounds checking. [F168, F181]
- Fixup stage contracts: mute/mic-mute LED registration via `snd_hda_gen_add_mute_led_cdev()` or `snd_hda_gen_add_micmute_led_cdev()` must run at `HDA_FIXUP_ACT_PRE_PROBE` before `alc_parse_auto_config()`; custom `automute_hook` or `hp_automute_hook` combined with `alc_fixup_headset_mode()` must be installed at `HDA_FIXUP_ACT_PROBE` after `alc_fixup_headset_mode()` runs and must never pre-populate `spec->gen.cap_sync_hook`; and renaming controls via `rename_ctl()` or modifying `spec->gen.pcm_rec` must run at `HDA_FIXUP_ACT_BUILD`. On dual-codec boards (`alc_fixup_dual_codecs()`, `alc1220_fixup_gb_dual_codecs()`, `alc233_alc662_fixup_lenovo_dual_codecs()`), fixups must set `suppress_vmaster`, `suppress_auto_mute`, `suppress_auto_mic`, `mixer_nid = 0`, and `codec->force_pin_prefix = 1` at `HDA_FIXUP_ACT_PRE_PROBE` and rename Capture controls by `codec->addr` at `HDA_FIXUP_ACT_BUILD`. [F191, F275, F276, F277]
- `match_str` passed to `comp_generic_fixup()` is formatted by `hda_comp_match_dev_name()` via `snprintf(tmp, sizeof(tmp), match_str, hid, index)` into a 32-byte buffer (`<= 31` chars), so `find_cirrus_companion_amps()` must escape `%%s` and `%%d` in `devm_kasprintf()`. In `comp_bind()`, the `void *data` passed to `hda_component_manager_bind_acpi_notifications()` must be the `struct hda_codec *` pointer (`cdc`) because `comp_acpi_device_notify()` casts `data` directly to `struct hda_codec *`. [F232, F233]
- `set_eapd()` must verify `get_wcaps_type(get_wcaps(codec, nid)) == AC_WID_PIN` and `snd_hda_query_pin_caps(codec, nid) & AC_PINCAP_EAPD` before sending `AC_VERB_SET_EAPD_BTLENABLE`. Callers of `snd_hda_override_conn_list()` and `alc889_fixup_mac_pins()` must pass `ARRAY_SIZE(...)` rather than `sizeof(...)` because `hda_nid_t` is `u16` (2 bytes). [F235, F245]

## Error Handling
- `alc_parse_auto_config()` returns `1` on success and a negative errno on failure, so codec `.probe` functions must check `err < 0` (never `if (err)`) and must explicitly `return 0` at the end of `.probe` rather than returning `err`. [F167]
- `codec->bus->pci` can be `NULL` on non-PCI HD-Audio buses, so any direct dereference of `codec->bus->pci` (e.g., reading `subsystem_vendor`, `subsystem_device`, or `vendor`) must first check `codec->bus->pci != NULL`. [F169]
- `alc_get_hp_pin()` and `alc_find_ext_mic_pin()` return `0` when no matching pin exists in `spec->gen.autocfg`, so callers must check for `0` before issuing verbs or registering jack callbacks, and `alc271_hp_gate_mic_jack()` (`ALC271_FIXUP_HP_GATE_MIC_JACK`) must only be used on machines guaranteed to have both pins at `HDA_FIXUP_ACT_PROBE` because missing either triggers `snd_BUG_ON`. [F170, F278]
- In `alc269_probe()`, `set_beep_amp()` must only be called when `spec->gen.mixer_nid` is non-zero in addition to `!spec->gen.no_analog && spec->gen.beep_nid`, because many ALC269 variants and fixups clear `spec->gen.mixer_nid = 0`. `snd_hda_find_mixer_ctl()` returns `NULL` when a control is absent, so callers like `rename_ctl()` and `alc_update_knob_master()` must NULL-check `kctl` before dereferencing or renaming it. [F171, F172]

## Known Pitfalls
- The suffix in `alc_fixup_gpio1()`, `alc_fixup_gpio2()`, `alc_fixup_gpio3()`, and `alc_fixup_gpio4()` is the hex GPIO bitmask (`0x01`, `0x02`, `0x03`, `0x04`), not a 1-based GPIO line number: `alc_fixup_gpio3()` enables both GPIO0 and GPIO1 (`0x03`), and `alc_fixup_gpio4()` enables GPIO2 (`0x04`). [F180]
- `alc_update_gpio_led()` passes `!enabled` (after applying `polarity`) to `alc_update_gpio_data(codec, mask, !enabled)` because `micmute_led_set()` and `gpio_mute_led_set()` pass `!brightness` as `enabled`, whereas `alc_update_vref_led()` and `alc_update_coef_led()` receive `brightness` directly as `on` without inverting when `polarity == 0`. [F252]
- In `struct hda_fixup` tables, setting `.chain_id` has no effect unless `.chained = true` (run target after this entry) or `.chained_before = true` (run target before this entry) is also set. On laptops with external I2C/SPI companion amplifiers (e.g., `tas2781_fixup_tias_i2c` or `cs35l41_fixup_i2c_two`) that also need non-default speaker DAC routing or headset mic pins, the board quirk must chain those fixups (such as `ALC289_FIXUP_DUAL_SPK` or `ALC294_FIXUP_ASUS_I2C_HEADSET_MIC`). [F211, F250]
- In `alc_fill_eapd_coef()`, the `0x10ec0225`/`0295`/`0299` cases intentionally fall through `0x10ec0215`..`0289` and into `0x10ec0230`..`0300` (and `0x10ec0234`/`0274` fall through `0x10ec0294`..`0711`) to apply multi-register COEF updates in sequence; do not insert a `case` with `break` or reorder cases inside these fallthrough chains. When an OEM reuses a PCI SSID across boards with different Realtek chips in `alc269_fixup_tbl`, chip-specific COEF writes, pin overrides, or DMIC inversions must be gated on `codec->core.vendor_id` (as in `alc285_fixup_asus_ga403u` and `alc256_fixup_mic_no_presence_and_resume`). [F213, F247]
- Setting or clearing pin-NID bits in `spec->gen.mute_bits` (such as in `asus_tx300_automute()`) must use a 64-bit shift (`1ULL << nid` or `BIT_ULL(nid)`) because `mute_bits` is `u64` and pin NIDs can reach or exceed 32 (e.g., `0x21`). When parsing OEM string NID values with `sscanf()` in `alc269_fixup_hp_mute_led()`, `%x` must target an `int` (or `unsigned int`) temporary before assigning to `spec->mute_led_nid` because `hda_nid_t` is `u16` (2 bytes). [F224, F234]
