# VIRTIO CORE — (top level)

This unit contains the kernel internal and UAPI headers defining Virtio, vring, vringh, Virtio-PCI, Virtio-MMIO, and vDPA protocols, data structures, and inline helpers, along with userspace testing, benchmarking, and tracing tools under `tools/virtio/`.

## Architecture & Data Flow

- Helpers consuming a `struct vringh_iov` or `struct vringh_kiov` in place (such as `vringh_kiov_advance`) must track bytes consumed from `iov->iov[iov->i]` in `iov->consumed` and restore `iov_len += iov->consumed` and `iov_base -= iov->consumed` before advancing `iov->i` or resetting `iov->i` to 0 in `vringh_iov_reset` / `vringh_kiov_reset`. [F432]
- `vringh_kiov_length` must start its summation loop at `i = kiov->i` rather than `0`, because remaining unconsumed data in `struct vringh_kiov` spans `kiov->iov + kiov->i` through `kiov->used - 1`. [F458]
- Feature bit helpers in `include/linux/virtio_features.h` (such as `virtio_features_test_bit`) must validate `bit < VIRTIO_FEATURES_BITS` via `virtio_features_chk_bit(bit)` and pair word index `VIRTIO_U64(bit)` with 64-bit mask `VIRTIO_BIT(bit)` (which masks the shift exponent with `0x3f` and shifts `1ULL`). Broken by: shifting a 32-bit `1` or `1UL` for bits `>= 32`, or applying `VIRTIO_BIT(bit)` to a single `u64` without indexing `features[VIRTIO_U64(bit)]`. [F464]
- In `include/uapi/linux/virtio_pci.h`, `MAX_CAP_ID` must be computed using ceiling division `__KERNEL_DIV_ROUND_UP(VIRTIO_DEV_PARTS_CAP + 1, 64)` to size `virtio_admin_cmd_query_cap_id_result::supported_caps`. Broken by: using truncating division or omitting `+ 1` when converting the highest 0-based capability ID to `__le64` words. [F469]

## Synchronization

- Multi-part or `>4`-byte configuration space reads (`__virtio_cread_many`, `virtio_cread_bytes`, `virtio_cread64`, and `>4`-byte `virtio_cread` / `virtio_cread_le`) must retry reading around `vdev->config->generation(vdev)` until consecutive generation counts match. Broken by: reading a 64-bit or multi-byte config field directly with `vdev->config->get()` without the generation-counter retry loop. [F399]
- In `struct vdpa_device`, `cf_lock` (`struct rw_semaphore`) protects configuration space access, `features_valid`, and reset/status transitions; `vdpa_set_features_unlocked()`, `vdev->config->reset()`, and `vdev->config->set_config()` must only be called while holding `vdev->cf_lock`, whereas unlocked callers must use `vdpa_set_features()` or `vdpa_reset()`. [F403]
- `struct vdpa_device` must not store a custom `driver_override` pointer read without locking in bus match callbacks; driver override matching must use the driver core's locked `bus_type.driver_override` and `device_match_driver_override()` infrastructure. [F406]
- `virtio_synchronize_cbs()` calls `dev->config->synchronize_cbs(dev)` or falls back to `synchronize_rcu()`, so it may sleep and must only be called from sleepable process context. Broken by: calling `virtio_synchronize_cbs()` or `virtio_device_ready()` (when `CONFIG_VIRTIO_HARDEN_NOTIFICATION` is enabled) from atomic or RCU read-side context. [F503]
- In `struct virtio_device`, `config_lock` protects `config_core_enabled`, `config_driver_disabled`, and `config_change_pending`, while `vqs_list_lock` protects the `vqs` list; userspace tests in `tools/virtio/` calling `vring_new_virtqueue()` or `vring_del_virtqueue()` on a standalone `struct virtio_device` must first call `INIT_LIST_HEAD(&vdev.vqs)` and `spin_lock_init(&vdev.vqs_list_lock)`. [F402]
- When reading available descriptors from a split vring (such as `vringh_get_head()` in `tools/virtio/vringh_test.c`), the consumer must execute `virtio_rmb(vrh->weak_barriers)` after observing `vrh->last_avail_idx != avail_idx` and before reading `vrh->vring.avail->ring[i]`. [F408]
- In `tools/virtio/ringtest/ring.c`, descriptor handoff between guest and host in `add_inbuf()`, `get_buf()`, and `use_buf()` is ordered by pairing `smp_release()` before writing `ring[head].flags` with `smp_acquire()` after polling `ring[head].flags` (`DESC_HW` set by `add_inbuf()` and cleared by `use_buf()`). [F409]
- In `tools/virtio/ringtest/` (`ring.c` and `virtio_ring_0_9.c`), event-index notification suppression requires `smp_mb()` between writing the event index in `enable_kick()` / `enable_call()` and testing ring emptiness, paired with `smp_mb()` after publishing descriptors before reading the peer's event index in `kick_available()` / `call_used()`. [F410]
- In `wait_order` (`tools/virtio/virtio-trace/trace-agent-ctl.c`), when `global_signal_val` is set and `!global_run_operation`, `pthread_cond_broadcast(&cond_wakeup)` must be called before breaking out of the poll loop so sleeping `rw_thread_main` threads wake and exit on `global_sig_receive`. [F462]

## Object Lifetimes

- `struct vringh_iov::max_num` and `struct vringh_kiov::max_num` store the `VRINGH_IOV_ALLOCATED` (`0x8000000`) flag in bit 27 alongside capacity, so capacity checks must mask out `~VRINGH_IOV_ALLOCATED`, and any instance used with `vringh_getdesc_*` must be passed to `vringh_iov_cleanup` / `vringh_kiov_cleanup` when done or before calling `vringh_iov_init` / `vringh_kiov_init` again (which overwrite `iov` and `max_num` without freeing). [F388, F447]
- `vringh_iov_reset` and `vringh_kiov_reset` must not be called on a `struct vringh_iov` or `struct vringh_kiov` after `vringh_iov_cleanup` or `vringh_kiov_cleanup` (unless re-initialized), because cleanup sets `iov->iov` to `NULL` while reset unconditionally dereferences `iov->iov[iov->i]`. [F389]
- `vring_del_virtqueue` frees the descriptor ring only if the virtqueue was created with `vring_create_virtqueue` or `vring_create_virtqueue_map`; when created with `vring_new_virtqueue`, the caller retains ownership of the `pages` ring buffer and must free or reuse it only after `vring_del_virtqueue` returns. [F390]

## API Contracts

- `virtio_config_ops.reset` (and `virtio_reset_device()`) must never be called from a `vq_callback_t` or `virtio_driver.config_changed` callback, nor concurrently with device addition or removal. [F396]
- When invoking `virtio_config_ops.disable_vq_and_reset`, the caller must guarantee that no virtqueue function other than the virtqueue callback concurrently accesses the vring (e.g., `virtqueue_add_*()`, `virtqueue_kick()`, or `virtqueue_get_buf()`). [F397]
- The `virtio_config_ops` callbacks `@get`, `@set`, `@get_status`, `@set_status`, `@get_features`, and `@finalize_features`, as well as `virtio_cread*` and `virtio_cwrite*` helpers, may sleep and must not be called from atomic context or while holding a spinlock. [F398]
- A `struct virtio_driver` that uses virtqueues inside its `probe` callback before `probe` returns must first call `virtio_device_ready(dev)` to unbreak virtqueues and set `VIRTIO_CONFIG_S_DRIVER_OK`; calling `virtio_device_ready(dev)` when `VIRTIO_CONFIG_S_DRIVER_OK` is already set triggers `WARN_ON`. [F481]
- `dev_to_virtio()` performs an unchecked `container_of_const(_dev, struct virtio_device, dev)` downcast; callers holding a generic `struct device *` not already guaranteed to belong to `virtio_bus` must verify `is_virtio_device(_dev)` first. [F478]
- `virtio_cread_feature()` and `virtio_cread_le_feature()` return `0` and populate `*ptr` only when `virtio_has_feature(vdev, fbit)` is true; when absent they return `-ENOENT` without modifying `*ptr`, so callers must check the return value or pre-initialize `*ptr`. [F412]
- `virtio_get_shm_region()` treats `region_out` (`struct virtio_shm_region *`) strictly as an out-parameter populated by `vdev->config->get_shm_region()` and returns `false` if the callback is `NULL` or the region is absent; it must not reject a zero-initialized `region_out->len` before invoking the callback. [F413]
- Feature array helpers in `include/linux/virtio_features.h` (`virtio_features_zero`, `virtio_features_copy`, `virtio_features_from_u64`, `virtio_features_equal`, `virtio_features_andnot`) and `virtio_get_features()` take a decayed `u64 *` and unconditionally access `VIRTIO_FEATURES_U64S` (2) `u64` words (16 bytes). Broken by: passing the address of a single `u64` instead of a `u64[VIRTIO_FEATURES_U64S]` array or `VIRTIO_DECLARE_FEATURES` union. [F473]
- `vp_modern_get_driver_features` in `include/linux/virtio_pci_modern.h` only returns the lower 64 feature bits (`features_array[0]`) and triggers `WARN_ON_ONCE` if any feature bit `>= 64` is set; callers on devices with extended features must use `vp_modern_get_driver_extended_features`. [F454]
- `vring_need_event(event_idx, new_idx, old)` takes the peer's published event threshold first (`event_idx`), the newly incremented ring index second (`new_idx`), and the previous ring index third (`old`), all as 0-based `__u16` indices. [F426]
- `vringh_init_iotlb()` and `vringh_init_iotlb_va()` do not initialize `vrh->iotlb` or `vrh->iotlb_lock`; callers must invoke `vringh_set_iotlb(vrh, iotlb, iotlb_lock)` before calling any `*_iotlb()` ring operation because `iotlb_translate()` unconditionally locks `vrh->iotlb_lock` and dereferences `vrh->iotlb`. [F423]
- In `include/linux/vringh.h`, IOTLB helpers (`vringh_set_iotlb`, `vringh_init_iotlb`, `vringh_init_iotlb_va`, `vringh_getdesc_iotlb`, `vringh_iov_pull_iotlb`, `vringh_iov_push_iotlb`, `vringh_complete_iotlb`, `vringh_need_notify_iotlb`) are only declared when `IS_REACHABLE(CONFIG_VHOST_IOTLB)` is true. [F525]
- `struct vringh_range::end_incl` in `include/linux/vringh.h` is an inclusive upper bound (`[start, end_incl]`), so `getrange` callbacks (such as `getrange_iov`) passed to `vringh_getdesc_user` must set `end_incl` to the last valid byte address (`start + size - 1`), not `start + size`. [F448]
- Callers of `vdpa_config_ops.set_group_asid` must serialize it against concurrent `vdpa_config_ops.set_status` calls on the same `struct vdpa_device`. [F405]
- In `vdpa_reset`, `ops->compat_reset(vdev, flags)` in `struct vdpa_config_ops` is called only when both `ops->compat_reset` is non-NULL and `flags` is non-zero; when `flags == 0` or `ops->compat_reset == NULL`, `ops->reset(vdev)` must be called. [F461]
- When a non-NULL `trigger` eventfd is provided in `struct vdpa_callback` to `set_vq_cb` or `set_config_cb`, the vDPA driver must ensure that signaling `trigger` is functionally equivalent to invoking `callback(private)`. [F526]
- In `tools/virtio/`, when `__kmalloc_fake` redirects `kmalloc` into a non-heap buffer, `[__kfree_ignore_start, __kfree_ignore_end)` must cover that address before `kfree` is called on it (e.g., via `virtqueue_get_buf` or `vring_del_virtqueue`), and `__kmalloc_fake` must be reset to `NULL` before subsequent real heap allocations (such as in `vringh_getdesc_user`). [F393]

## Error Handling

- `virtio_find_single_vq()` returns `ERR_PTR(err)` when `virtio_find_vqs()` returns a negative status, never `NULL` on failure, so callers must check the returned `struct virtqueue *` with `IS_ERR()` rather than `!vq`. [F411]
- `vringh_need_notify_user()`, `vringh_need_notify_kern()`, and `vringh_need_notify_iotlb()` return a tri-state `int` (`< 0` on error, `0` if no notification is needed, `1` if notification is needed), so callers must check for `< 0` rather than treating any non-zero return as true. [F422]

## External Contracts

- Structure definitions in UAPI virtio headers (such as `struct virtio_admin_cmd_hdr` and `struct virtio_admin_cmd_status` in `include/uapi/linux/virtio_pci.h`) must use explicit padding fields and natural alignment rather than the kernel-internal `__packed` macro. [F441]
- Modern Virtio-PCI MMIO registers in `struct virtio_pci_common_cfg` and `struct virtio_pci_modern_common_cfg` must be accessed at their exact natural width using `vp_ioread8`/`16`/`32` and `vp_iowrite8`/`16`/`32`, with 64-bit split registers written via `vp_iowrite64_twopart(val, lo, hi)`. Broken by: using byte-wise `ioread8`/`memcpy_fromio` or a single 64-bit `writeq`. [F491]
- In `struct virtio_pcidev_msg` (`include/uapi/linux/virtio_pcidev.h`), header fields (`op`, `bar`, `size`, `addr`) are in CPU-native endianness while `data[]` is little-endian, and for `VIRTIO_PCIDEV_OP_MMIO_MEMSET`, `data[]` is only 1 byte long even though `size` specifies the multi-byte memset length. [F453]

## Known Pitfalls

- Unlike split-ring descriptor flags (`VRING_DESC_F_NEXT`, `VRING_DESC_F_WRITE`, `VRING_DESC_F_INDIRECT`) which are shifted bitmasks (`1`, `2`, `4`), `VRING_PACKED_DESC_F_AVAIL` (`7`), `VRING_PACKED_DESC_F_USED` (`15`), and `VRING_PACKED_EVENT_F_WRAP_CTR` (`15`) are bit shifts that must be shifted (`1 << ...`) when masking. [F425]
- `VIRTIO_F_ACCESS_PLATFORM` (bit 33) has inverted quirk polarity: `virtio_has_dma_quirk(vdev)` returns `true` when `VIRTIO_F_ACCESS_PLATFORM` is NOT negotiated (device bypasses platform DMA/IOMMU and uses physical addresses) and `false` when platform DMA must be used. [F484]
- `virtio_cread` and `virtio_cwrite` require the config struct member type to use bitwise `__virtio16`/`__virtio32`/`__virtio64` (endianness depends on `VIRTIO_F_VERSION_1` via `virtio_is_little_endian`), whereas config structs defined with `__le16`/`__le32`/`__le64` must be accessed with `virtio_cread_le` and `virtio_cwrite_le`. [F489]
- In `vring_init` (and `vring_size`), the `align` parameter used in `& ~(align - 1)` to align the pointer `&vr->avail->ring[num]` must be an `unsigned long` (pointer-width) integer rather than a 32-bit `unsigned int` or `u32`. [F466]
- In `include/uapi/linux/virtio_ring.h`, the explicit alignment attributes for `vring_desc_t`, `vring_avail_t`, `vring_used_t`, and `vring_used_elem_t` must be attached to the `typedef` declarations rather than the underlying `struct` definitions, because GCC ignores `aligned` attributes on a non-packed `struct` when they decrease alignment. [F475]
- In the `tools/virtio/` userspace test environment, `mb()`, `dma_rmb()`, and `dma_wmb()` in `tools/virtio/asm/barrier.h` call `abort()`, and `synchronize_rcu()` in `tools/virtio/linux/kernel.h` calls `assert(0)`, so userspace test virtqueues and `vringh` instances must always be initialized with `weak_barriers = true` and provide a custom `synchronize_cbs` op if calling `virtio_synchronize_cbs()`. [F508]

## Other

- When `drivers/virtio/virtio_ring.c`, `drivers/vhost/vringh.c`, or `include/linux/virtio*.h` introduces a use of a kernel macro, type, or helper (such as `VIRTIO_DECLARE_FEATURES`, `virtio_features_chk_bit`, `DMA_MAPPING_ERROR`, `sg_dma_len`, or `MODULE_DESCRIPTION`), a matching userspace stub must be added to `tools/virtio/linux/` in lockstep. [F438]
