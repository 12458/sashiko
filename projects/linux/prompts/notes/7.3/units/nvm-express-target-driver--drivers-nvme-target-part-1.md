# NVM EXPRESS TARGET DRIVER — drivers/nvme/target (part 1)

Core framework, command engines, configuration interfaces, and local/PCI endpoint transports for the Linux NVMe Target (nvmet) subsystem. It manages target subsystems, controllers, submission/completion queues, namespaces, Asymmetric Namespace Access (ANA) groups, discovery services, and persistent reservations via configfs and debugfs. It implements Admin, Fabrics, and I/O command execution over block devices, files, or passthrough NVMe controllers, along with the in-kernel loopback (`nvme-loop`) and PCI Endpoint Function (`nvmet-pci-epf`) transports.

## Architecture & Data Flow

- In `struct nvmet_ns`, `ns->bdev` is `NULL` when the namespace is file-backed or `ns->buffered_io` is enabled (`ns->file != NULL`), so shared namespace code must check `ns->bdev` (or `ns->file`) before dereferencing `ns->bdev` or `nvmet_ns_dev(ns)`. [F48]
- In `struct nvmet_pci_epf_iod`, single-segment commands point `iod->data_segs` at inline `&iod->data_seg` and `iod->data_sgt.sgl` at inline `&iod->data_sgl` (`nents == 1`), so `nvmet_pci_epf_free_iod()` must check `iod->data_segs != &iod->data_seg` before `kfree()` and `iod->data_sgt.nents > 1` before `sg_free_table()`. [F49]
- Before a Fabrics Connect command installs the queue on a controller, `req->sq->ctrl` is `NULL`, so any code reachable during `nvmet_req_init()`, `nvmet_req_transfer_len()`, or `nvmet_set_error()` must check `req->sq->ctrl` for `NULL` before dereferencing it. [F50]
- When disabling a PCI EPF controller on link-down in `nvmet_pci_epf_stop_ctrl()` or rolling back a failed enable in `nvmet_pci_epf_enable_ctrl()`, `nvmet_pci_epf_clear_ctrl_config()` must zero `ctrl->cc`, `tctrl->cc`, `ctrl->csts`, and `tctrl->csts` and write `0` to `NVME_REG_CC` and `NVME_REG_CSTS` in the BAR. [F63]
- When shutting down a PCI EPF controller (`shutdown == true`) in `nvmet_pci_epf_disable_ctrl()`, `NVME_CC_ENABLE` must be cleared in both `ctrl->cc` and the `NVME_REG_CC` BAR register alongside setting `NVME_CSTS_SHST_CMPLT` in `ctrl->csts` so `nvmet_pci_epf_poll_cc_work()` can detect a subsequent `CC.EN` transition. [F64]
- `nvmet_pci_epf_poll_cc_work()` must only call `nvmet_update_cc()` and write `ctrl->csts` to `NVME_REG_CSTS` when `NVME_REG_CC` has changed from `ctrl->cc` and `nvmet_pci_epf_enable_ctrl()` succeeds, while still rescheduling `ctrl->poll_cc` if `nvmet_pci_epf_enable_ctrl()` fails. [F65]
- Both `nvmet_pci_epf_delete_cq()` and the error path of `nvmet_pci_epf_create_cq()` must atomically test and clear `NVMET_PCI_EPF_Q_IRQ_ENABLED` in `cq->flags` via `test_and_clear_bit()` before calling `nvmet_pci_epf_remove_irq_vector()`. [F66]
- Every change to `ns->anagrpid` in `nvmet_ns_alloc()`, `nvmet_ns_free()`, and `nvmet_ns_ana_grpid_store()` must update `nvmet_ana_group_enabled[]` under `nvmet_ana_sem`, and `nvmet_ns_ana_grpid_store()` and `nvmet_ana_group_ana_state_store()` must also increment `nvmet_ana_chgcnt` under `nvmet_ana_sem` and send an ANA AEN. [F69]

## Synchronization

- In nvmet_pci_epf_create_cq() and nvmet_pci_epf_create_sq(), NVMET_PCI_EPF_Q_LIVE in cq->flags or sq->flags must only be tested on entry and set via set_bit() after all queue fields, PCI mappings, nvmet_cq_create()/nvmet_sq_create(), and sq->iod_wq are initialized. [F19]
- nvmet_config_sem protects nvmet_transports, nvmet_genctr, nvmet_disc_subsys->subsysnqn, port->subsystems, port->referrals, subsys->hosts, and subsys->allow_any_host; writers must hold down_write(&nvmet_config_sem) and readers (such as nvmet_host_allowed() and nvmet_execute_disc_get_log_page()) must hold down_read(&nvmet_config_sem). [F29]
- nvmet_ana_sem protects nvmet_ana_group_enabled[], nvmet_ana_chgcnt, and updates to port->ana_state[] and ns->anagrpid; updates must hold down_write(&nvmet_ana_sem) and ANA log page generation in nvmet_execute_get_log_page_ana() must hold down_read(&nvmet_ana_sem). [F31]
- In drivers/nvme/target/pr.c, all mutations to ns->pr.registrant_list and ns->pr.holder must hold ns->pr.pr_sem, and when nvmet_execute_pr_acquire() queues req->r.abort_work for NVME_PR_ACQUIRE_ACT_PREEMPT_AND_ABORT, pr_sem must remain held across work queueing and be released by nvmet_pr_do_abort() after per-controller refs drain and resurrect. [F33]
- The lock acquisition hierarchy in nvmet is nvmet_config_sem -> subsys->lock -> ctrl->lock (and ns->pr.pr_sem -> subsys->lock -> ctrl->pr_log_mgr.lock / ctrl->lock); subsys->lock must never be acquired while holding ctrl->lock, and nvmet_config_sem must never be acquired while holding subsys->lock or ctrl->lock. [F35]
- In nvmet_async_events_process() and nvmet_async_events_failall(), ctrl->lock must be released before calling nvmet_req_complete() on a dequeued async_event_cmds request and re-acquired before the next loop iteration. [F36]
- In nvmet_enable_port(), if nvmet_transports[port->disc_addr.trtype] is NULL, nvmet_config_sem must be released before calling request_module(), re-acquired via down_write(&nvmet_config_sem), and nvmet_transports[port->disc_addr.trtype] must be re-read and re-checked under the lock. [F38]
- In nvmet_update_sq_head(), req->sq->sqhd must be updated using READ_ONCE() and a try_cmpxchg() loop to advance (old_sqhd + 1) % req->sq->size. [F39]

## Object Lifetimes

- `nvmet_req_complete()` must save `req->sq` into a local pointer before calling `__nvmet_req_complete(req, status)` and pass that saved pointer to `percpu_ref_put(&sq->ref)`, because `req->ops->queue_response(req)` inside `__nvmet_req_complete()` may free `req`. [F3]
- In `nvmet_init()` and `nvmet_exit()`, `nvmet_init_debugfs()` must precede `nvmet_init_discovery()` during setup and `nvmet_exit_discovery()` must precede `nvmet_exit_debugfs()` during teardown and error rollback, because `nvmet_disc_subsys` creates its debugfs directory under `nvmet_debugfs`. [F6]
- `nvmet_req_bio_put()` must call `bio_uninit(bio)` when `bio == &req->b.inline_bio` (or the union-aliased `&req->p.inline_bio` or `&req->z.inline_bio`) and `bio_put(bio)` otherwise, so that resources attached to an inline bio such as `bio->bi_integrity` are freed. [F7]
- In `nvmet_file_execute_rw()` and `nvmet_file_io_done()`, `req->f.bvec` must only be freed when `req->f.bvec != req->inline_bvec`, using `mempool_free(req->f.bvec, req->ns->bvec_pool)` when `req->f.mpool_alloc` is `true` and `kfree(req->f.bvec)` when `req->f.mpool_alloc` is `false`. [F13]
- `nvmet_copy_to_sgl()` copies data from the caller's buffer into `req->sg` without taking ownership of the buffer, so command handlers that `kzalloc()` a temporary response structure (such as in `admin-cmd.c`, `discovery.c`, `passthru.c`, or `pr.c`) must `kfree()` it before calling `nvmet_req_complete()`. [F16]
- In `nvmet_host_release()`, all dynamically allocated authentication secret buffers on `struct nvmet_host` (`host->dhchap_secret` and `host->dhchap_ctrl_secret`) must be freed with `kfree()` before freeing `host`. [F17]
- `nvmet_passthru_ctrl_enable()` closes the `filp_open()` handle via `filp_close(file, NULL)` before returning and pins `subsys->passthru_ctrl` via `passthru_subsystems`, `nvme_get_ctrl()`, and `__module_get()`, which `__nvmet_passthru_ctrl_disable()` must release and clear to `NULL`. [F18]
- In nvmet_sq_destroy(), if the queue being destroyed is the admin queue (ctrl->sqs[0] == sq), nvmet_async_events_failall(ctrl) must be called before killing sq->ref and waiting on sq->confirm_done and sq->free_done. [F23]
- In nvmet_file_ns_disable(), when ns->buffered_io is enabled, flush_workqueue(buffered_io_wq) must be called before destroying ns->bvec_pool and closing ns->file. [F25]

## API Contracts

- `nvmet_check_transfer_len()` and `nvmet_check_data_len_lte()` call `nvmet_req_complete()` before returning `false`, so callers must return immediately on `false` without completing `req` again and must invoke them before allocating per-command resources that are only freed on the normal completion path. [F4]
- When `nvmet_req_init()` returns `false`, it has already invoked `__nvmet_req_complete()` without acquiring `sq->ref`, so callers must return without calling `nvmet_req_complete()` or `nvmet_req_uninit()`, whereas failures after `nvmet_req_init()` returns `true` must call `nvmet_req_uninit()` or `nvmet_req_complete()`. [F42]
- `nvmet_bdev_ns_enable()` must return `-ENOTBLK` whenever `ns->buffered_io` is set or `bdev_file_open_by_path()` rejects a regular file, because `nvmet_ns_enable()` falls back to `nvmet_file_ns_enable()` only when `nvmet_bdev_ns_enable()` returns `-ENOTBLK`. [F46]
- Internal NVMe status codes (`u16 status`) are unshifted values where bit 0 is the low status bit, so writing to a CQE or error log slot (`nvmet_set_error()`, `nvmet_pci_epf_cq_work()`) must shift left by 1 (`status << 1`) to reserve bit 0 for the Phase Tag, and reading from `cqe->status` (`nvmet_pci_epf_queue_response()`) must shift right by 1. [F57]
- Keep-Alive Timeout values on the NVMe wire (`c->kato`, `NVMET_DISC_KATO_MS`, and `NVME_FEAT_KATO` cdw11/result) are in milliseconds, whereas `ctrl->kato` is stored in seconds via `DIV_ROUND_UP(kato, 1000)` and must be multiplied by `1000` in `nvmet_get_feat_kato()` and by `HZ` when scheduling `ctrl->ka_work`. [F59]
- In `nvmet_bdev_alloc_bip()`, the starting sector passed to `bip_set_seed()` must be converted from 512-byte sectors (`SECTOR_SHIFT`) to block-integrity interval units by right-shifting `bio->bi_iter.bi_sector` by `(bi->interval_exp - SECTOR_SHIFT)`. [F60]
- In `nvmet_pci_epf_raise_irq()`, the 0-based NVMe completion queue interrupt vector `cq->vector` must be converted to a 1-based interrupt number (`cq->vector + 1`) when calling `pci_epc_raise_irq()` for `PCI_IRQ_MSI` or `PCI_IRQ_MSIX`, and `0` must be passed for `PCI_IRQ_INTX`. [F61]
- Wire queue sizes (`c->sqsize`, `create_sq.qsize`, `create_cq.qsize`) and `NVME_CAP_MQES(ctrl->cap)` are 0-based while `nvmet_sq.size` and `nvmet_cq.size` are 1-based, so queue setup paths must check non-zero wire size against `NVME_CAP_MQES(ctrl->cap)` before passing `size + 1` to `nvmet_sq_setup()` or `nvmet_cq_setup()`. [F84]

## Error Handling

- In `nvmet_passthru_execute_cmd_work()`, when `nvme_execute_rq()` succeeds on `nvme_admin_identify`, the `u16` status returned by `nvmet_passthru_override_id_ctrl()`, `nvmet_passthru_override_id_ns()`, or `nvmet_passthru_override_id_descs()` must be captured in `status` and passed to `nvmet_req_complete()`. [F44]
- When `nvmet_req_find_ns()` finds a namespace in `subsys->namespaces` whose `ns->enabled` flag is `false`, it must reset `req->ns = NULL` before returning `NVME_SC_INTERNAL_PATH_ERROR` without calling `percpu_ref_get(&req->ns->ref)`. [F51]
- When `bdev_file_open_by_path()` in `nvmet_bdev_ns_enable()`, `filp_open()` in `nvmet_file_ns_enable()`, or `key_lookup()` in `nvmet_ports_make()` returns an `IS_ERR()` pointer, the field (`ns->bdev_file`, `ns->file`, or `port->keyring`) must be reset to `NULL` after extracting `PTR_ERR()`. [F52]
- In `nvmet_pci_epf_cq_work()`, `cqe->sq_head`, `cqe->sq_id`, `cqe->command_id`, and `cqe->status` must always be explicitly initialized before `memcpy_toio()` because an IOD that fails before `req->execute()` in `nvmet_pci_epf_exec_iod_work()` bypasses `__nvmet_req_complete()`. [F53]
- In `nvmet_req_init()`, `req->cqe->result.u64`, `req->cqe->status`, `req->cqe->sq_head`, `req->ns`, `req->pc_ref`, `req->error_loc` (`NVMET_NO_ERROR_LOC`), and `req->error_slba` must be initialized before any check that can `goto fail`, because transports reuse `nvmet_req` and `nvme_completion` structures across commands. [F54]
- In `nvmet_set_feat_write_protect()`, when setting `NVME_NS_WRITE_PROTECT`, `req->ns->readonly` must be set to `true` under `subsys->lock` before calling `nvmet_write_protect_flush_sync()`, and if the flush fails, `req->ns->readonly` must be restored to `false` without calling `nvmet_ns_changed()`. [F79]
- In errno_to_nvme_status() and blk_to_nvme_status(), -EOPNOTSUPP and BLK_STS_NOTSUPP must map unconditionally to NVME_SC_INVALID_OPCODE | NVME_STATUS_DNR without overriding the status code for nvme_cmd_dsm or nvme_cmd_write_zeroes. [F107]
- In nvmet_bdev_discard_range() and nvmet_file_execute_discard(), -EOPNOTSUPP returned by __blkdev_issue_discard() or vfs_fallocate() must be ignored so the discard range loop continues and completes with NVME_SC_SUCCESS rather than failing the DSM command. [F108]

## External Contracts

- In `nvmet_execute_identify_ns()`, if `nvmet_req_find_ns()` fails to find an enabled namespace for a non-broadcast NSID, `status` must be cleared to `0` and the zero-initialized `struct nvme_id_ns` buffer copied to the host SGL. [F55]
- In `nvmet_execute_identify_ctrl()`, `nvmet_execute_disc_identify()`, and `nvmet_subsys_attr_serial_store_locked()`, the `sn`, `mn`, and `fr` fields of `struct nvme_id_ctrl` and `subsys->serial` must be padded with ASCII spaces (`' '`) via `memcpy_and_pad()` rather than NUL-terminated. [F56]
- `nvmet_execute_identify_nslist()` must reject reserved `min_nsid` values `0xFFFFFFFE` and `NVME_NSID_ALL` with `NVME_SC_INVALID_NS | NVME_STATUS_DNR` before allocating and populating the active namespace ID list. [F90]
- In `nvmet_pci_epf_iod_parse_prps()`, `prp1`'s page offset (`nvmet_pci_epf_prp_ofst()`) must be 4-byte aligned (`!(ofst & 0x3)`), while `nvmet_pci_epf_iod_parse_prp_simple()` and `nvmet_pci_epf_iod_parse_prp_list()` must reject any non-zero offset on `prp2` or data PRP list entries with `NVME_SC_PRP_INVALID_OFFSET`. [F92]
- `nvmet_start_ctrl()` must only enforce `nvmet_cc_iosqes(ctrl->cc) == NVME_NVM_IOSQES` and `nvmet_cc_iocqes(ctrl->cc) == NVME_NVM_IOCQES` when `!nvmet_is_disc_subsys(ctrl->subsys)` so discovery controllers remain backward-compatible with hosts that do not set `iosqes` or `iocqes`. [F98]
- Configfs port attribute handlers `nvmet_addr_tsas_show()` and `nvmet_addr_tsas_store()` must output an empty line `"\n"` when TSAS is unset and accept idempotent writes matching the current RDMA `port->disc_addr.tsas.rdma.qptype` so userspace tools can save and restore port configurations. [F99]
- In nvmet_execute_identify(), command-set-independent CNS values (such as NVME_ID_CNS_NS, NVME_ID_CNS_CTRL, and NVME_ID_CNS_NS_ACTIVE_LIST) must dispatch directly without filtering on req->cmd->identify.csi, while NVME_ID_CNS_CS_NS and NVME_ID_CNS_CS_CTRL must handle both NVME_CSI_NVM and NVME_CSI_ZNS. [F106]

## Known Pitfalls

- `nvmet_execute_admin_connect()` and `nvmet_execute_io_connect()` must explicitly NUL-terminate `d->subsysnqn[NVMF_NQN_FIELD_LEN - 1]` and `d->hostnqn[NVMF_NQN_FIELD_LEN - 1]` after `nvmet_copy_from_sgl()` before passing `d->subsysnqn` or `d->hostnqn` to `nvmet_alloc_ctrl()`, `nvmet_ctrl_find_get()`, or string functions. [F85]
- Unaligned or 24-bit wire byte-array fields—specifically `id->ieee` in `nvmet_execute_identify_ctrl()`, 128-bit counters in `nvme_smart_log` and `nvme_endurance_group_log`, and `data->regctl` in `nvmet_execute_pr_report()`—must be written via `put_unaligned_le24()`, `put_unaligned_le64()`, or `put_unaligned_le16()`. [F95]
- In nvmet_ctrl_find_get(), the list_for_each_entry(ctrl, &subsys->ctrls, subsys_entry) search must explicitly reset ctrl = NULL when the loop finishes without jumping to found, because the loop cursor ctrl otherwise points to the list head container. [F110]
- In nvmet_execute_disc_get_log_page(), subsystem entries must be formatted using req->port and the transport-resolved traddr, whereas referral entries must be formatted using the referral struct nvmet_port *r and r->disc_addr.traddr (skipping referrals with NVMF_TRTYPE_PCI). [F119]
- In nvmet_referral_enable_store() and nvmet_referral_notify(), the referral nvmet_port is obtained via to_nvmet_port(item) while the parent nvmet_port owning referrals_group is obtained via to_nvmet_port(item->ci_parent->ci_parent). [F120]
- In `nvmet_file_execute_discard()`, `le32_to_cpu(range.nlb)` must be assigned to the 64-bit `loff_t len` before left-shifting by `req->ns->blksize_shift` so that discard lengths exceeding 4 GiB are not truncated to 32 bits. [F121]
- When converting block-device byte-limit ratios to 16-bit 0-based NVMe Identify Namespace fields in `nvmet_bdev_set_limits()`, the ratio must be passed through `to0based()`, which clamps the input to `[1U, 1U << 16]` before subtracting 1. [F126]
