# GPIO SUBSYSTEM — include

Core Linux GPIO framework (`gpiolib.c`, `gpiolib.h`), DT, swnode, devres, legacy, and sysfs frontends, public GPIO consumer/driver/DT headers, and controller drivers (`gpio-xlp.c` through `gpio-zynqmp-modepin.c`).

## Architecture & Data Flow

- `gpio_chip_hwgpio()` and `desc_to_gpio()` compute offsets via `desc - &desc->gdev->descs[0]`; every `struct gpio_desc *` passed to gpiolib must reside in its parent `gdev->descs` array, never a standalone or copied struct. [F441]
- `gpiod_get_array()` places `struct gpio_array` (`array_info`) in the `krealloc()` block right after `descs->desc[count]`, sets `array_info->desc = descs->desc` after reallocation (`gpiod_get/set_array_value_complex()` verify `(void *)array_info == desc_array + array_info->size`; `gpiod_put_array()` frees only `descs`), and sizes `invert_mask`/`get_mask`/`set_mask` to `BITS_TO_LONGS(max(gdev->ngpio, count))`. [F435, F438]
- In `gpio_chip_get_multiple()` and `gpiochip_set_multiple()`, when `gc->get_multiple` or `gc->set_multiple` is non-NULL, return its status directly (mapping `> 0` to `-EBADE`) instead of falling through to `for_each_set_bit()` on `0`. [F417]
- In `gpiod_configure_flags()`, reject multiple `GPIO_PULL_UP`/`GPIO_PULL_DOWN`/`GPIO_PULL_DISABLE` bits in `lflags` before the `if`/`else if` chain setting `GPIOD_FLAG_*`, and return early on `!(dflags & GPIOD_FLAGS_BIT_DIR_SET)` before testing `GPIOD_FLAGS_BIT_DIR_OUT` so `GPIOD_ASIS` (`0`) leaves direction unchanged. [F421, F422]
- In `gpiod_direction_output_nonotify()`, when open-drain/open-source emulation jumps to `set_output_flag` and calls `gpiod_direction_input_nonotify(desc)` (clearing `GPIOD_FLAG_IS_OUT`), `set_bit(GPIOD_FLAG_IS_OUT, &desc->flags)` must follow so `gpiod_set_raw_value_commit()` does not fail with `-EPERM`. [F423]
- `gpiochip_allocate_mask()` uses `bitmap_fill(p, gc->ngpio)` so lines start valid before `gpiochip_apply_reserved_ranges()` or `init_valid_mask()` clears bits. In `gpiochip_apply_reserved_ranges()`, `size` is even (`gpiochip_count_reserved_ranges()`) and both `ranges[--size]` decrements must precede the `start >= gc->ngpio || start + count > gc->ngpio` `continue`. [F386, F430]
- `gpiochip_set_names()` must return early when `"gpio-line-names"` count is `<= chip->offset`, and clamp `count - chip->offset` to `chip->ngpio` before indexing `names[chip->offset + i]` and `gdev->descs[i]`. [F407]
- `gpiodev_add_to_list_unlocked()` keeps `gpio_devices` sorted in ascending non-overlapping `[base, base + ngpio)` order and must check `if (&next->list == &gpio_devices) break;` before reading `next->base`. `gpiochip_find_base_unlocked()` allocates dynamic bases only in `[GPIO_DYNAMIC_BASE, GPIO_DYNAMIC_MAX - ngpio]`. [F409, F424]
- `of_gpiochip_add()` rejects `of_gpio_n_cells > MAX_PHANDLE_ARGS`, `of_xlate_and_get_gpiod_flags()` requires `gpiospec->args_count == of_gpio_n_cells`, and `of_gpiochip_add_pin_range()` parses `of_gpio_n_cells + 1` cells per `"gpio-ranges"` entry and trims linear ranges to `[chip->offset, chip->offset + chip->ngpio)`. `gpiochip_add_pin_ranges()` skips `gc->add_pin_ranges(gc)` when `"gpio-ranges"` is present on `&gc->gpiodev->dev`. For DT SPI `"cs"` -> `"gpios"` quirks in `gpiolib-of.c`, update `of_gpio_spi_cs_get_count()` and `of_find_gpio_rename()` in lockstep. [F402, F412, F457]
- In `struct gpio_irq_chip`, `per_parent_data` selects between `parent_handler_data_array` (`num_parents` entries) and `parent_handler_data` (or `gc` if `NULL`). When `gc->irq.chip->flags & IRQCHIP_IMMUTABLE` is set, `gpiochip_set_irq_hooks()` and `gpiochip_irqchip_remove()` do not mutate `irq_chip`; the driver's `irq_chip` must include `GPIOCHIP_IRQ_RESOURCE_HELPERS` and call `gpiochip_enable_irq()`/`gpiochip_disable_irq()`. [F384, F455]
- In `gpio_sysfs_set_active_low()`, changing `GPIOD_FLAG_ACTIVE_LOW` when `data->irq_flags` is `GPIO_IRQF_TRIGGER_FALLING` or `GPIO_IRQF_TRIGGER_RISING` must free and re-request the IRQ using a pre-sampled copy of `data->irq_flags`, since `gpio_sysfs_free_irq()` zeroes `data->irq_flags`. [F396]
- In `gpio-xlp.c`, registers are at byte offset `(gpio / XLP_GPIO_REGSZ) * 4` with `BIT(gpio % XLP_GPIO_REGSZ)`, `gc->ngpio <= XLP_MAX_NR_GPIO` (96, bounding `priv->gpio_enabled_mask`), and `xlp_gpio_generic_handler()` must initialize `regoff = -1` (not `0`) before `for_each_set_bit()` so bank 0 is read. [F415, F432]

## Synchronization

- Runtime `gdev->chip` access and `gpiochip_get_direction()`, `gpiochip_direction_input()`, `gpiochip_direction_output()`, `gpiochip_get()`, `gpio_chip_get_multiple()`, `gpiochip_set()`, and `gpiochip_set_multiple()` require `gdev->srcu` (`gpio_chip_guard`) and `gc != NULL`. Before registration in `gpiochip_add_data_with_key()`, call `gc->get_direction()` directly. Cross-descriptor chip comparisons must use `gpio_device_chip_cmp(gdev, gc)`. [F359, F362, F369]
- `gpio_devices` updates require `gpio_devices_lock`, RCU list ops (`list_add_rcu`, `list_add_tail_rcu`, `list_del_rcu`), and `synchronize_srcu(&gpio_devices_srcu)` after unlocking on removal before freeing/numbing `gdev`. `gpiod_find_and_request()` must hold `gpio_devices_srcu` continuously across `gpiod_fwnode_lookup()`/`gpiod_find()` and `gpiod_request()`. [F367, F476]
- `desc_set_label()` updates `desc->label` via `rcu_replace_pointer()` and frees old labels via `call_srcu(&desc->gdev->desc_srcu, &old->rh, desc_free_label)`; `gpiodev_release()` calls `synchronize_srcu(&gdev->desc_srcu)` before `cleanup_srcu_struct()`. `gpiod_get_label(desc)` callers must hold `desc->gdev->desc_srcu` across access (or copy inside it as in `gpiochip_dup_line_label()`) and handle `NULL`. [F382, F469, F470]
- `gpiod_line_state_notify()` must hold `read_lock_irqsave(&desc->gdev->line_state_lock)` around `raw_notifier_call_chain(&desc->gdev->line_state_notifier, action, desc)`. [F366]
- `gpiochip_irqchip_add_allocated_domain()` must set `gc->to_irq`, `gc->irq.domain`, and `gc->irq.domain_is_allocated_externally` and run `barrier()` before `gc->irq.initialized = true` (checked by `gpiochip_to_irq()`). [F360]
- In `gpiod_get/set_array_value_complex()`, when `guard.gc->ngpio > FASTPATH_NGPIO`, `bitmap_alloc()` must use `can_sleep ? GFP_KERNEL : GFP_ATOMIC`. `gpiochip_lock_as_irq()` must only call `gpiod_get_direction(desc)` when `!gc->can_sleep && gc->get_direction`. [F473, F475]
- In `gpiod_free_irqs()`, hold `irqd->request_mutex` only while checking `irq_desc_has_action(irqd)` and reading `irqd->action->dev_id`, releasing it before `free_irq(irq, cookie)`. [F478]
- In `gpiolib-sysfs.c`, `gpio_sysfs_request_irq()`, `gpio_sysfs_free_irq()`, and `gpio_sysfs_set_active_low()` require `data->mutex`, except `gpio_sysfs_free_irq()` in `gpiod_unexport()` after `device_unregister(desc_data->dev)`. [F479]
- In `gpio-xlp.c`, updates to `priv->gpio_intr_en`, `priv->gpio_intr_stat` (acked by writing `1`), and `priv->gpio_enabled_mask` require `spin_lock_irqsave(&priv->lock, flags)`. In `gpio-zevio.c`, all MMIO requires `controller->lock`, and `zevio_gpio_direction_output()` must write `ZEVIO_GPIO_OUTPUT` before `ZEVIO_GPIO_DIRECTION`. In `gpio-xtensa.c`, wrap `read_impwire`, `rur.expstate`, and `wrmsk_expstate` in `enable_cp()`/`disable_cp()`. [F373, F463, F465]

## Object Lifetimes

- `gpiod_request()` gets `desc->gdev->owner` (`try_module_get()`) and `desc->gdev` (`gpio_device_get()`) released by `gpiod_free()`, whereas `gpiochip_request_own_desc()` takes neither and pairs with `gpiochip_free_own_desc()`. `gpiochip_reqres_irq()` must call `try_module_get(gc->gpiodev->owner)` before `gpiochip_lock_as_irq()` and call `module_put()` on failure, matching `gpiochip_relres_irq()`. [F344, F358]
- `gpio_device_find*()` return a referenced `struct gpio_device *` requiring `gpio_device_put()`, whereas `gpio_device_get_desc()` and `gpiod_to_gpio_device()` do not take a reference. [F453]
- `devm_gpiod_put()` and `devm_gpiod_put_array()` must call `devm_release_action()` (not `devm_remove_action()`), whereas `devm_gpiod_unhinge()` calls `devm_remove_action_nowarn()` and ignores `-ENOENT`. With `GPIOD_FLAGS_BIT_NONEXCLUSIVE`, `devm_gpiod_get_index()` must check `devm_is_action_added(dev, devm_gpiod_release, desc)` before adding the action. [F349, F451]
- `gdev->label` uses `kstrdup_const()` and must be freed with `kfree_const()` in `gpiodev_release()` and `gpiochip_add_data_with_key()` error paths. `gpiochip_set_names()` must only `kfree(names)` and never free `names[i]` or `desc->name` in `gpiodev_release()`. `gpiochip_free_mask()` must set `*p = NULL` after `bitmap_free(*p)` since `gpiochip_irqchip_remove()` and `err_remove_irqchip` both call `gpiochip_irqchip_free_valid_mask(gc)`. [F348, F356, F445]
- In `of_get_named_gpiod_flags()`, every return path after `of_parse_phandle_with_args_map()` succeeds must call `of_node_put(gpiospec.np)` and `gpio_device_put(gdev)`. In `swnode_find_gpio()` and `swnode_gpio_count()`, every successful `swnode_gpio_get_reference()` requires `fwnode_handle_put(args.fwnode)`. [F353, F355]

## API Contracts

- Non-optional getters (`gpiod_get_index`, `gpiod_get_array`, `devm_*`) return `ERR_PTR(-ENOENT)` when unassigned; `_optional` variants convert only `-ENOENT` (`gpiod_not_found()`) to `NULL` and propagate other `ERR_PTR`s. `!CONFIG_GPIOLIB` stubs return `NULL` or `ERR_PTR(-ENOSYS)` and `WARN_ON(desc)` if non-NULL `desc` is passed to consumer ops. `gpiod_fwnode_lookup()` must fall back to `fwnode->secondary` on `-ENOENT`. [F374, F458, F498]
- `gpio_to_desc()` takes a global GPIO number and returns `NULL` on failure; `gpio_device_get_desc()` and `gpiochip_get_desc()` take a chip offset (`0 .. gdev->ngpio - 1`), return `ERR_PTR(-EINVAL)` when `hwnum >= gdev->ngpio`, and `gpio_device_get_desc()` clamps `hwnum` via `array_index_nospec(hwnum, gdev->ngpio)`. [F375, F486]
- `gpiod_get_direction()` and `gpiod_to_irq()` must check `validate_desc(desc, __func__) <= 0` and return `-EINVAL` instead of `VALIDATE_DESC(desc)`, since `0` is valid (`GPIO_LINE_DIRECTION_OUT` / `NO_IRQ`). [F377]
- `gpiod_direction_output()`, `gpiod_get_value*()`, and `gpiod_set_value*()` use logical values (`GPIOD_FLAG_ACTIVE_LOW` and open-drain/open-source emulation), while `*_raw*()` use physical levels. Non-sleeping accessors (`!can_sleep`) must not be called when `gdev->can_sleep` or `gc->can_sleep` is true. With `array_info` fastpath, `gpiod_set_array_value_complex()` mutates `value_bitmap` in-place via `bitmap_xor()` and passes it as `bits` to `gc->get_multiple()`/`gc->set_multiple()`, which must only access `bits` words active in `mask`. [F388, F440, F472]
- `struct gpio_chip` callbacks `.request`, `.direction_input`, `.direction_output`, `.set`, `.set_multiple`, `.get_multiple`, and `.set_config` return `0` or negative errno; `.get` and `.get_direction` return `0`, `1`, or negative errno (`> 1` becomes `-EBADE`). Setting `.direction_input` without `.get`, or output mode without `.direction_output` or `.set`, fails with `-EIO`. [F379, F490]
- `gpiod_set_config()` and `gpio_do_set_config()` take `pinconf_to_config_packed(param, arg)`, whereas `gpiod_set_debounce()` and `gpio_set_debounce_timeout()` take unpacked microseconds. `gpiod_set_transitory()` must update `GPIOD_FLAG_TRANSITORY` in `desc->flags` before calling `gpio_set_config_with_argument_optional(desc, PIN_CONFIG_PERSIST_STATE, !transitory)` (which maps `-ENOTSUPP` to `0`). [F389, F467]
- For gpiolib IRQ domains, `domain->host_data`, per-IRQ `chip_data`, and default chained `handler_data` are `struct gpio_chip *gc`. `gpiochip_add_irqchip()` rejects `gc->irq.parent_handler && gc->can_sleep` (`-EINVAL`) and warns/resets `gc->irq.default_type` to `IRQ_TYPE_NONE` when a fwnode is present. Hierarchical domains (`gc->irq.parent_domain`) require `child_to_parent_hwirq` and `fwnode`, and `gpiochip_hierarchy_setup_domain_ops()` overwrites `activate`, `deactivate`, and `alloc` in `child_irq_domain_ops`. [F444, F474, F491, F492]
- `gpiochip_dup_line_label()` returns `NULL` if out of range/unrequested, `ERR_PTR(-ENOMEM)` on alloc failure, or a `kfree()`-able string. `gpio_device_find()` visitors like `gpiofind_sysfs_register()` must return `0` so iteration continues without taking a `gpio_device_get()` reference. [F383, F431]
- `gpiod_lookup_table.table` arrays end with `.key == NULL` (`chip_hwnum == U16_MAX` when `key` is a line name) and `gpiod_hog` arrays end with `.chip_label == NULL`. `GPIOD_FLAG_*` are bit numbers (`0`..`19`) for bitops on `desc->flags`, whereas `enum gpiod_flags`, `enum gpio_lookup_flags`, and `enum of_gpio_flags` are bitmasks for `|` and `&`. [F411, F493]

## Error Handling

- Public `gpiod_*` entry points must validate `desc` with `VALIDATE_DESC()` or `VALIDATE_DESC_VOID()` before passing `desc` to `gpio_chip_guard`, `gpiod_line_state_notify()`, or `*_nonotify()` / `*_commit()` helpers. [F376]
- In `gpiod_direction_input_nonotify()` and `gpiod_direction_output_raw_commit()`, the result of `gpiochip_get_direction()` (`0` or `1`) must not remain in `ret` on success, as callers pass non-zero `ret` to `ERR_PTR(ret)`. [F378]
- Helpers taking `struct gpio_chip *gc` callable before `gpiochip_add_data_with_key()` initializes `gc->gpiodev` (`gpiochip_line_is_valid()`, `gpiochip_get_ngpios()`) must not dereference `gc->gpiodev` unconditionally or call `chip_err()`/`chip_warn()`. [F381]
- In `gpiod_get_array()`, increment `descs->ndescs` only after `gpiod_get_index()` succeeds and `descs->desc[descs->ndescs]` is set so `gpiod_put_array(descs)` never passes an `ERR_PTR` to `gpiod_put()`. In `gpiod_get/set_array_value_complex()`, zero `mask` via `bitmap_zero(mask, guard.gc->ngpio)` before setting `hwgpio` bits. [F385, F387]
- `gpiod_request_user()` (sysfs `export_gpio_desc()`) translates `-EPROBE_DEFER` to `-ENODEV`, sysfs `export_store()`/`unexport_store()`/`export_gpio_desc()` log invalid/masked GPIOs with `pr_debug_ratelimited()`, and `gpiochip_add_data_with_key()` suppresses `pr_err()` on `-EPROBE_DEFER`. [F488, F497]

## External Contracts

- Legacy sysfs `/sys/class/gpio/export` and `unexport` (`export_store()`, `unexport_store()`) resolve global GPIO numbers via `gpio_to_desc()`, whereas per-chip `/sys/class/gpio/chipN/export` and `unexport` (`do_chip_export_store()`) resolve 0-based hardware offsets via `gpio_device_get_desc()`. [F413]
- `unexport_gpio_desc()` and `gpiochip_sysfs_unregister()` must check `GPIOD_FLAG_SYSFS` before calling `gpiod_unexport()` and `gpiod_free()`, as `GPIOD_FLAG_EXPORT` is also set on kernel-owned lines exported via `gpiod_export()`. [F487]

## Known Pitfalls

- In `gpiod_set_array_value_complex()`'s slowpath loop, skip active-low inversion when `array_info && test_bit(i, array_info->invert_mask)` holds, since fastpath `bitmap_xor()` already inverted `value_bitmap` in-place for all `invert_mask` pins. [F418]
- In `of_gpio_set_polarity_by_property()`, match `compatible` on `np_compat` (`np->parent` for `atmel,hsmci`) while reading `polarity_propname` from `np_propname` (`np`). In `of_gpio_flags_quirks()`, for `"cs-gpios"` on SPI controller `np`, read `reg` and `"spi-cs-high"` from the matching `child` node. [F426, F427]
- In `gpiochip_get_ngpios()`, check `if (gc->ngpio == 0)` on 16-bit `gc->ngpio` after assigning 32-bit `ngpios` from `fwnode_property_read_u32()`, catching non-zero multiples of 65536 that truncate to `0`. [F434]
- `for_each_gpio_property_name(propname, con_id)` passes `sizeof(propname)` to `snprintf()`, so `propname` must be a fixed-size `char` array in scope (e.g. `char propname[32]`), never a `char *`. [F437]
- In `gpio_is_visible()`, downcast `dev_attr` to `struct gpiod_data` via `container_of()` only after matching `attr->name` with its specific member (`dir_attr`, `val_attr`, `edge_attr`, `active_low_attr`). [F442]
- `for_each_hwgpio_in_range()` and wrappers pass `&_label` and `&_i` to `_gpiochip_for_each_data` (`const char **label, int *i`) and `kfree(_label)` each step and on exit; declare `_i` as `int`/`unsigned int` and never reassign `_label` to a non-kmalloc pointer or free it without setting `_label = NULL`. [F446]
