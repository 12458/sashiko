# MELLANOX MLX5 core VPI driver — drivers/net/ethernet/mellanox/mlx5/core (part 5)

Implements device health monitoring and devlink health reporters, hardware thermal sensor monitoring (hwmon), IP-over-InfiniBand (IPoIB) parent and PKey child netdevices, IRQ CPU affinity management, and Link Aggregation (LAG) across dual/multi-port ConnectX functions.

## Architecture & Data Flow

- `mlx5_set_nic_state()` must update `dev->iseg->cmdq_addr_l_sz` via a read-modify-write preserving the upper 20 bits (`cur_cmdq_addr_l_sz & 0xFFFFF000`), as the command queue physical address shares the 32-bit MMIO register. [F427]
- In `mlx5_health_check_fatal_sensors()`, `sensor_pci_not_working(dev)` must precede `mlx5_get_nic_state(dev)` and `sensor_fw_synd_rfr(dev)`, because offline PCI reads return `0xffffffff`, aliasing `MLX5_INITIAL_SEG_NIC_INTERFACE_SW_RESET` (`0x7`) and setting non-zero `rfr`/`synd` bits. [F459]
- `mlx5_start_health_fw_log_up()` must check both `mlx5_core_is_pf(dev)` and `MLX5_CAP_MCAM_REG(dev, mrtc)` before queueing `update_fw_log_ts_work` to write `MLX5_REG_MRTC`. [F483]
- In `struct mlx5_hwmon`, `chip_channel_config`, `channel_info`, and `temp_channel_config` must be allocated with one extra trailing zero element (`+ 1` via `kzalloc`/`kcalloc`) to satisfy `hwmon_device_register_with_info()`'s 0-terminated array contract. [F409]
- In `hwmon.c`, `mlx5_hwmon_init_sensors_indexes()` uses `for_each_set_bit()` to pack ASIC sensor IDs into `hwmon->temp_channel_desc[0 .. i - 1]` and places the optional module sensor at `[i]`, keeping all `asic_platform_scount + module_scount` entries contiguous. Hwmon channel numbers densely index `temp_channel_desc[channel]`, whereas MTMP register queries (`mlx5_hwmon_query_mtmp()`, `mlx5_hwmon_reset_max_temp()`, `mlx5_hwmon_enable_max_temp()`) must pass `temp_channel_desc[channel].sensor_index`. [F445, F461]
- In `struct mlx5i_priv`, `struct rdma_netdev rn` must be the first member and `char *mlx5e_priv[]` the trailing flexible array allocated via `sizeof(struct mlx5i_priv) + sizeof(struct mlx5e_priv)`, so `netdev_priv(netdev)` yields `struct mlx5i_priv` and `mlx5i_epriv(netdev)` yields `struct mlx5e_priv`. `mlx5_rdma_setup_rn()` detects PKey child sub-interfaces via `mlx5_is_sub_interface(mdev)` (`mdev->mlx5e_res.hw_objs.pdn != 0`), so `mlx5e_create_mdev_resources()` and `mlx5i_pkey_qpn_ht_init()` (and teardown in `mlx5_rdma_netdev_free()`) must only run when `!ipriv->sub_interface`. [F431, F447]
- `ldev->v2p_map` and `lag_definer->rules` are indexed by `[i * ldev->buckets + j]` for PF index `i` and bucket `j` in `[0, ldev->buckets)`, and `ldev->v2p_map` (and `ports[]` in `port_sel.c`) stores 1-based PF numbers (`i + 1`) whereas `mlx5_infer_tx_enabled()` and `mlx5_infer_tx_disabled()` output 0-based PF indices. Broken by: indexing `ldev->pf[]` with a `v2p_map` value without subtracting 1, or indexing `v2p_map` by `i` instead of `i * ldev->buckets + j`. [F450]
- In `mlx5_lag_is_supported()`, `MLX5_CAP_GEN(dev, num_lag_ports)` must be bounded to `[2, MLX5_MAX_PORTS]` (`[2, 8]`) so `ldev->ports` keeps shift exponents in `GENMASK(ldev->ports - 1, 0)` within `[1, 7]` and bitmasks in `lag_active_port_bits` and `mlx5_handle_changeupper_event()` (`u8 bond_status`) fit in `u8`. [F464]
- When activating a LAG bond in `mlx5_do_bond()` or modifying it in `mlx5_modify_lag()`, if `tracker.tx_type == NETDEV_LAG_TX_TYPE_ACTIVEBACKUP`, the driver must notify `dev0->priv.lag_nh` with `MLX5_DRIVER_EVENT_ACTIVE_BACKUP_LAG_CHANGE_LOWERSTATE` passing the netdev from `mlx5_lag_active_backup_get_netdev(dev0)`, then call `dev_put()`. [F436]
- `mlx5_lag_add_netdev()` must reset `ldev->tracker.netdev_state[fn]` and set `MLX5_LAG_FLAG_NDEVS_READY` only when `mlx5_lag_num_netdevs(ldev) >= ldev->ports`, while `mlx5_lag_remove_netdev()` must clear `ldev->pf[i].netdev`, clear `MLX5_LAG_FLAG_NDEVS_READY`, and queue `ldev->bond_work` if LAG is active. [F439]

## Synchronization

- In `mlx5_start_health_poll()`, `health->fatal_error`, `health->flags` (`MLX5_DROP_HEALTH_WORK`), `health->health`, and `health->health_counter` must be initialized before `add_timer(&health->timer)` arms `poll_health`. Because `poll_health` runs in atomic timer softirq context, it must only perform MMIO reads and direct `dev->state` assignment, deferring sleeping recovery, devlink reporting, and mutex acquisitions to `health->wq` via `mlx5_trigger_health_work()` or `queue_work(health->wq, &health->report_work)`. [F389, F494]
- In `mlx5_drain_health_wq()`, `MLX5_DROP_HEALTH_WORK` must be set in `health->flags` before cancelling `update_fw_log_ts_work`, `report_work`, and `fatal_report_work`, and `mlx5_fw_fatal_reporter_err_work()` must check `MLX5_DROP_HEALTH_WORK` under `dev->intf_state_mutex` before running recovery. [F390]
- In `mlx5_enter_error_state()`, after optimistically setting `dev->state` from `MLX5_DEVICE_STATE_UP` to `MLX5_DEVICE_STATE_INTERNAL_ERROR`, `dev->intf_state_mutex` must be acquired and `dev->state` rechecked when `!err_detected` (`if (!err_detected && dev->state == MLX5_DEVICE_STATE_INTERNAL_ERROR)`) to skip duplicate `enter_error_state()` calls. [F392]
- `mlx5_health_try_recover()` must be called with `devl_lock(priv_to_devlink(dev))` held and `dev->intf_state_mutex` unlocked, because `mlx5_disable_device()` and `mlx5_recover_device()` invoke `mlx5_unload_one_devl_locked()`, `mlx5_error_sw_reset()`, and `mlx5_load_one_devl_locked()`, which assert `devl_lock` and acquire `dev->intf_state_mutex`. [F495]
- `mlx5_error_sw_reset()` must serialize reset across sibling PCI functions via `lock_sem_sw_reset(dev, true)` (`MLX5_SEMAPHORE_SW_RESET`), `reset_fw_if_needed()` must re-check `mlx5_health_check_fatal_sensors(dev)` before setting `MLX5_INITIAL_SEG_NIC_INTERFACE_SW_RESET`, and `lock_sem_sw_reset(dev, false)` must only run when `lock_sem_sw_reset(dev, true)` returned `0` (`!lock`). `lock_sem_sw_reset()` must wrap `mlx5_vsc_sem_set_space()` in `mlx5_vsc_gw_lock()`/`mlx5_vsc_gw_unlock()`, translating `-EBUSY` from `mlx5_vsc_gw_lock()` to `-EINVAL` so `-EBUSY` is reserved for non-PFs or when another PF holds `MLX5_SEMAPHORE_SW_RESET`. [F387, F408, F428, F496]
- In `ipoib_vlan.c`, insertions and removals on `ht->buckets` in `mlx5i_pkey_add_qpn()` and `mlx5i_pkey_del_qpn()` must hold `spin_lock_bh(&ht->ht_lock)` (`struct mlx5i_pkey_qpn_ht`), and `new_node->netdev` and `new_node->underlay_qpn` must be initialized before `hlist_add_head()`. [F397]
- In `ipoib.c` and `ipoib_vlan.c`, `priv->state_lock` (`epriv->state_lock`) must be held across `MLX5E_STATE_OPENED` transitions, channel open/close/parameter switches, and `WRITE_ONCE(netdev->mtu, ...)` in `mlx5i_open()`, `mlx5i_close()`, `mlx5i_change_mtu()`, `mlx5i_pkey_open()`, `mlx5i_pkey_close()`, and `mlx5i_pkey_change_mtu()`. [F398]
- In `lag.c`, no locks (such as `ldev->lock`) or sleeping calls (`blocking_notifier_call_chain()`, `mlx5_cmd_exec_inout()`, `kvzalloc(..., GFP_KERNEL)`) may be taken under `lag_lock`: `mlx5_lag_active_backup_get_netdev()` must `dev_hold(ndev)` under `lag_lock` before `blocking_notifier_call_chain()`, and `mlx5_lag_query_cong_counters()` must snapshot `ldev->pf[i].dev` under `lag_lock` before `mlx5_cmd_exec_inout()`. [F400]
- In `mlx5_handle_changeupper_event()` and `mlx5_handle_changeinfodata_event()`, iterating bond slaves with `for_each_netdev_in_bond_rcu()` and inspecting slave state via `bond_slave_get_rcu()` must be enclosed within `rcu_read_lock()` and `rcu_read_unlock()`. [F504]

## Object Lifetimes

- In `mlx5_health_cleanup()`, `health->update_fw_log_ts_work` must be cancelled and `health->wq` destroyed before calling `mlx5_reporter_vnic_destroy()` and `mlx5_fw_reporters_destroy()`. [F391]
- In `mlx5_fw_reporter_dump()` and `mlx5_fw_fatal_reporter_dump()`, `priv_ctx` is either `NULL` or a stack-allocated `struct mlx5_fw_reporter_ctx` from `mlx5_fw_reporter_err_work()` / `mlx5_fw_fatal_reporter_err_work()`, so callbacks must check `priv_ctx` for `NULL`, cast it only to `struct mlx5_fw_reporter_ctx *`, and never retain it asynchronously. [F474]
- `mlx5_hwmon_dev_register()` must only assign `mdev->hwmon = hwmon` after `hwmon_device_register_with_info()` succeeds (leaving `mdev->hwmon` `NULL` if `mtmp` is unsupported or registration fails), and `mlx5_hwmon_dev_unregister()` must check `if (!mdev->hwmon)`, call `hwmon_device_unregister(hwmon->hwmon_dev)` before `mlx5_hwmon_free(hwmon)`, and clear `mdev->hwmon = NULL`. [F388, F410]
- `mlx5i_parent_get()` (in `mlx5i_pkey_dev_init()`) acquires a parent netdev ref via `dev_get_by_index()`, inherits `parent_ipriv->qpn_htbl`, and increments `parent_ipriv->num_sub_interfaces`; any failure after `mlx5i_parent_get()` and teardown in `mlx5i_pkey_dev_cleanup()` must call `mlx5i_parent_put()`, `mlx5i_set_channels()` must reject changes while `ipriv->num_sub_interfaces > 0`, and all accesses to `num_sub_interfaces` must hold RTNL (`ASSERT_RTNL()`). [F380, F396, F432]
- In `mlx5_irq_affinity_request()` and `mlx5_irq_affinity_irq_release()`, `pci_irq_vector()` must use `pool->dev->pdev` while SF sysfs IRQ calls (`mlx5_sf_coredev_to_adev()`, `auxiliary_device_sysfs_irq_add()`/`remove()`) use the requesting `dev` after dropping `pool->lock` when `mlx5_irq_pool_is_sf_pool(pool)`. `mlx5_irq_affinity_irq_release()` must get `pool` via `mlx5_irq_get_pool(irq)` (not from `dev`), read `pool`, `cpu`, index, and irq number before `mlx5_irq_put(irq)`, and call `cpu_put(pool, cpu)` only when `mlx5_irq_put(irq)` returns non-zero. [F379, F453, F454, F515]
- `__mlx5_lag_dev_add_mdev()` initializes `ldev->ref` to 1 via `mlx5_lag_dev_alloc()` for the first PF and calls `mlx5_ldev_get(ldev)` only when attaching additional peer PFs after checking `!ldev->mode_changes_in_progress`. In `mlx5_lag_remove_mdev()`, `mlx5_ldev_remove_debugfs()` must be called before `mlx5_ldev_remove_mdev()` clears `dev->priv.lag` and before `mlx5_ldev_put(ldev)` drops the `mlx5_lag` ref. [F384, F403]
- In `mlx5_ldev_free()` and `mlx5_lag_mp_cleanup()`, `ldev->nb` and `mp->fib_nb` must be unregistered before cancelling `ldev->bond_work` and destroying `ldev->wq` and `mp->wq`; if notifier registration fails during init (`mlx5_lag_mp_init()`), `notifier_call` must be cleared to `NULL` because cleanup tests `notifier_call` before unregistering and destroying `mp->wq`. [F404, F425]
- In `mlx5_lag_fib_event()` and `mlx5_lag_fib_update()`, the union in `struct mlx5_fib_event_work` holds `fen_info` for `FIB_EVENT_ENTRY_REPLACE`/`DEL` (with `fib_info_hold(fen_info.fi)`) and `fnh_info` for `FIB_EVENT_NH_ADD`/`DEL` (with `fib_info_hold(fnh_info.fib_nh->nh_parent)`), and `mlx5_lag_fib_update()` must access and `fib_info_put()` only the matching union member before `kfree(fib_work)`. `ldev->lag_mp.fib.mfi` is an unreferenced pointer that must be cleared to `NULL` on `FIB_EVENT_ENTRY_DEL`, when replacement has `!nh_dev0`, and in `mlx5_lag_mp_reset()`/`init()`/`cleanup()`. [F382, F383, F424]

## API Contracts

- Devlink health reporter dump callbacks (`mlx5_fw_reporter_dump()`, `mlx5_fw_fatal_reporter_dump()`) must only be exposed on PFs/ECPFs (`mlx5_fw_reporter_pf_ops`, `mlx5_fw_fatal_reporter_pf_ops`, `mlx5_fw_fatal_reporter_ecpf_ops`); VFs and SFs must use `mlx5_fw_reporter_ops` and `mlx5_fw_fatal_reporter_ops` without `.dump`. [F514]
- Callers of `mlx5_hwmon_is_module_mon_cap()` (`mlx5_hwmon_alloc()`) must initialize `*mon_cap = false` before calling it (it only writes `*mon_cap = true` when temperature is non-zero). Module numbers from `mlx5_query_module_num()` must be mapped to `64 + idx` via `to_mtmp_module_sensor_idx()` in `mlx5_hwmon_get_module_sensor_index()`, raw MTMP temperatures (in 0.125 C units) must be scaled by 125 via `mtmp_temp_to_mdeg()`, and `mlx5_hwmon_enable_max_temp()` must first read current `MLX5_REG_MTMP` contents via `mlx5_hwmon_query_mtmp()` before setting `mte = 1` and writing back. [F411, F412, F430]
- `mlx5i_get_tisn()` requires both `lag_port` and `tc` to be `0` (`WARN()` and return `0` otherwise), and `mlx5i_init()` must call `mlx5i_build_nic_params()` after `mlx5e_build_nic_params()` to disable RX striding RQ (`MLX5E_PFLAG_RX_STRIDING_RQ`), packet merge (`MLX5E_PACKET_MERGE_NONE`), and RX CQE compression (`MLX5E_PFLAG_RX_CQE_COMPRESS`). [F416, F509]
- In `mlx5_lag_query_cong_counters()`, each element of `offsets[]` is a byte offset into `out`, and each counter must be read via `be64_to_cpup((__be64 *)(out + offsets[j]))` and accumulated across active LAG ports. [F452]
- `mlx5_lag_fib_event()` must check `info->family == AF_INET` before downcasting `struct fib_notifier_info *info` with `container_of()` to `struct fib_entry_notifier_info` or `struct fib_nh_notifier_info`, and must ignore `FIB_EVENT_ENTRY_REPLACE`/`DEL` events where `fi->nh != NULL` before accessing legacy `fib_nh` paths. [F473, F518]

## Error Handling

- `health->fw_reporter` and `health->fw_fatal_reporter` can be `NULL` or `ERR_PTR`, so all readers and teardown (`mlx5_fw_reporters_destroy()`, `mlx5_health_init()`) must check `IS_ERR_OR_NULL()`. In `mlx5_fw_fatal_reporter_err_work()`, if `devlink_health_report()` returns `-ECANCELED`, the driver must call `mlx5_unload_one(dev, false)`. [F407, F513]
- In `mlx5i_init_underlay_qp()`, if any step in `MLX5_CMD_OP_RST2INIT_QP` -> `INIT2RTR_QP` -> `RTR2RTS_QP` fails, the QP must be transitioned to error via `MLX5_CMD_OP_2ERR_QP` before returning. [F488]
- `mlx5_irq_affinity_request()` returns `ERR_PTR` (never `NULL`) on failure (and calls `mlx5_irq_put()` if `auxiliary_device_sysfs_irq_add()` fails), so callers must check `IS_ERR(irq)`. [F417]
- Both `mlx5_lag_port_sel_create()` on error and `mlx5_lag_port_sel_destroy()` on teardown must destroy TTC tables before definers (`outer.ttc`, `inner.ttc`, then `mlx5_lag_destroy_definers()`) and zero `ldev->port_sel` with `memset(port_sel, 0, sizeof(*port_sel))` afterwards. [F377]

## External Contracts

- LAG netdevice notifier registration (`register_netdevice_notifier_net()` / `unregister_netdevice_notifier_net()`) and HCA devcom component matching (`MLX5_DEVCOM_MATCH_FLAGS_NS` in `mlx5_lag_register_hca_devcom_comp()`) must be scoped to the device's network namespace (`mlx5_core_net(dev)` / `ldev->net`). [F516]

## Known Pitfalls

- In `mlx5_error_sw_reset()` and `mlx5_health_wait_pci_up()`, polling loops waiting on `jiffies` deadlines (`end = jiffies + msecs_to_jiffies(...)`) must use `time_after(jiffies, end)` rather than `jiffies > end`. [F467]
- In `mlx5_hwmon_init_sensors_indexes()`, `u64 sensor_map` from `MLX5_GET64(mtcap_reg, mtcap_out, sensor_map)` must be converted via `bitmap_from_u64()` before `for_each_set_bit()`. In `mlx5_hwmon_init_channels_names()`, `sensor_name` is populated via `memcpy()` of the 8-byte `sensor_name_hi`/`lo` fields without a NUL write, requiring zero-allocated `temp_channel_desc` and `sizeof(sensor_name) > 8`. [F466, F471]
- In `mlx5_lag_print_mapping()`, the non-hash branch formats `ldev->ports * ldev->buckets` entries into `char buf[MLX5_MAX_PORTS * 10 + 1]`, requiring `ldev->buckets == 1` whenever `MLX5_LAG_MODE_FLAG_HASH_BASED` is not set. [F475]
