# NETWORKING DRIVERS — drivers/net/ethernet/marvell

This unit contains the Marvell Octeon PCIe Endpoint Physical Function (`octeon_ep`) and Virtual Function (`octeon_ep_vf`) Ethernet drivers for CN9K and CN10K (CNXK) SoCs, managing host-to-Octeon communication over PCIe via Instruction Queues (IQ/TX), Output Queues (OQ/RX), PF-firmware control mailboxes, and PF-VF mailboxes.

## Architecture & Data Flow

- On PF, `oct->iq[]` and `oct->oq[]` use 0-based `q_no`, but SDP CSR accesses (`setup_iq_regs`, `setup_oq_regs`, `enable_iq`, `enable_oq`, `disable_iq`, `disable_oq`, `reset_io_queues`) must add `CFG_GET_PORTS_PF_SRN(oct->conf)` (`conf->pf_ring_cfg.srn`) to `q_no`. Similarly, `oct->msix_entries[0 .. CFG_GET_NON_IOQ_MSIX(oct->conf) - 1]` are reserved for non-IOQ IRQs, so `oct->ioq_vector[j]` pairs with `oct->msix_entries[j + CFG_GET_NON_IOQ_MSIX(oct->conf)]` in `octep_request_irqs()` and `octep_free_irqs()`. [F229, F230]
- On PF, VF `vf`'s mailbox in `oct->mbox[]`, `SDP_MBOX_PF_VF_DATA` / `SDP_MBOX_VF_PF_DATA` CSRs, and `SDP_EPF_MBOX_RINT` bit are indexed by `vf_mbox_queue = vf * rings_per_vf`, whereas `oct->vf_info[vf]` is indexed by `vf`. In `octep_poll_pfvf_mailbox`, check `vf_mbox_queue < 64` before shifting `0x1UL`: test `0x1UL << vf_mbox_queue` against `CN93_SDP_EPF_MBOX_RINT(0)` when `< 64`, and `0x1UL << (vf_mbox_queue - 64)` against `CN93_SDP_EPF_MBOX_RINT(1)` when `>= 64`. [F259, F293]
- In `__octep_[vf_]oq_process_rx()`, only a packet's first descriptor has `octep_[vf_]oq_resp_hw` and (only when `fw_info.rx_ol_flags` is non-zero) `octep_[vf_]oq_resp_hw_ext` (`OCTEP_[VF_]OQ_RESP_HW_EXT_SIZE` subtracted from `max_single_buffer_size` and `buff_info->len`, added to `data_offset`); later fragments start at offset 0 up to `oq->buffer_size`. Return values count whole packets (`pkt`, for `oq->pkts_pending` and NAPI budget), whereas `oq->refill_count` adds total descriptors consumed (`desc_used`, including fragments). [F199, F234, F235]
- In `octep_[vf_]enable_ioq_irq`, writing `iq->pkts_processed` to `iq->inst_cnt_reg` must subtract `iq->pkts_processed` from `iq->pkt_in_done` (and zero `iq->pkts_processed`), and writing `oq->last_pkt_count - pkts_pend` to `oq->pkts_sent_reg` must set `oq->last_pkt_count = pkts_pend`. In `octep_[vf_]setup_iq`, `octep_[vf_]iq_reset_indices` must zero `iq->pkt_in_done`, and `setup_iq_regs` must read `iq->inst_cnt_reg` and write it back to clear the hardware counter. [F211, F221]
- `iq->max_count` (`CFG_GET_IQ_NUM_DESC(oct->conf)`, `OCTEP_[VF_]IQ_MAX_DESCRIPTORS`) must be a power of 2 because `iq->ring_size_mask` (`iq->max_count - 1`) is bitwise-ANDed to wrap `iq->host_write_index` and compute `IQ_INSTR_PENDING(iq)`. `OCTEP_[VF_]SGLIST_ENTRIES_PER_PKT` must round up via `((MAX_SKB_FRAGS + 1 + 3) / 4)` (4 pointers per SG descriptor, slot 0 for linear SKB). In TX xmit (`octep_[vf_]tx_desc_hw`), convert `hw_desc->txm64[0]` with `cpu_to_be64()` after setting `txm` fields, and set `hw_desc->ih.tlen = skb->len + hw_desc->ih.fsz`. [F232, F236, F261]
- In `octep_set_mac`, `octep_change_mtu`, `octep_set_features`, `octep_set_link_ksettings`, and VF counterparts (`octep_vf_set_mac`, `octep_vf_change_mtu`, `octep_vf_set_features`), local shadow state (`oct->mac_addr`, `oct->link_info`, `netdev->mtu`, `netdev->features`) must only be updated after the firmware/PF mailbox call succeeds. [F213]
- When a VF MAC is queried/set (`octep_pfvf_get_mac_addr`, `octep_pfvf_set_mac_addr`, `octep_set_vf_mac`), `oct->vf_info[vf_id].mac_addr` must update in lockstep, and `octep_pfvf_dev_remove` must zero `oct->vf_info[vf_id]`. `octep_sriov_enable` and `octep_sriov_disable` must keep `CFG_GET_ACTIVE_VFS(oct->conf)` synchronized with enabled VFs, resetting it to `0` on `pci_enable_sriov` failure or SR-IOV disable. [F210, F215]
- In `octep_vf_mbox_bulk_read` and `octep_pfvf_pf_get_data`, the multi-fragment cursor and buffer (`mbox->mbox_data.data_index` and `recv_data` on VF; `mbox->config_data_index` and `config_data` on PF) must be reset to zero at the start of a non-fragment request and on VF completion or error. [F222]
- In `octep_request_irqs`, `oct->conf->msix_cfg.non_ioq_msix_names` (`cn93_non_ioq_msix_names` / `cnxk_non_ioq_msix_names`) must have at least `non_ioq_msix` entries; each is matched by prefix via `strncmp(..., strlen("<prefix>"))` into an `OCTEP_MSIX_NAME_SIZE`-byte slot in `oct->non_ioq_irq_names`. [F275]

## Synchronization

- `octep_get_stats64()` and `octep_vf_get_stats64()` run in RCU read-side critical sections via `dev_get_stats()` and must only read in-memory counters (`oct->stats_iq`, `oct->stats_oq`), never calling sleeping mailbox functions (`octep_ctrl_net_get_if_stats`, `octep_send_mbox_req`, `octep_vf_get_if_stats`, `octep_vf_mbox_bulk_read`). [F295, F296]
- `octep_[vf_]tx_timeout()` runs in atomic timer/softirq context and must defer `rtnl_lock()` / reset to `oct->tx_timeout_task`. `octep_vf_tx_timeout()` must call `netdev_hold(netdev, NULL, GFP_ATOMIC)` and release it with `netdev_put()` if `schedule_work()` returns false or after `rtnl_unlock()` in `octep_vf_tx_timeout_task()`. `cancel_work_sync(&oct->tx_timeout_task)` and `cancel_delayed_work_sync(&oct->hb_task)` in teardown (`octep_remove`, `octep_device_cleanup`, `octep_vf_remove`) must run outside `rtnl_lock()` (never inside `octep_[vf_]stop`) because those tasks acquire `rtnl_lock()`. [F297, F298, F300]
- PF-VF mailbox work (`oct->mbox[vf_mbox_queue]->wk.work`, `octep_pfvf_mbox_work`) must be scheduled on `system_wq` via `schedule_work()`, never on single-threaded `octep_wq`, because `octep_pfvf_mbox_work()` blocks in `octep_send_mbox_req()` waiting for `oct->ctrl_mbox_task` on `octep_wq`. `octep_poll_pfvf_mailbox[_cnxk_pf]()` and `octep_poll_oei_cn93/cnxk_pf()` run from both MSI-X hardirq and `octep_intr_poll_task`; they must not sleep or take mutexes, deferring work via `schedule_work()` and `queue_work(octep_wq, &oct->ctrl_mbox_task)`. [F299, F301]
- Per-VF PF mailbox state (`pf_vf_data_reg`, `vf_pf_data_reg`, `config_data`, `config_data_index`, `message_len`) in `struct octep_mbox` requires `mutex_lock(&mbox->lock)`, which nests outside `oct->ctrl_mbox.h2fq_lock`. `octep_ctrl_mbox_send` (`mbox->h2fq_lock`) and `octep_ctrl_mbox_recv` (`mbox->f2hq_lock`) must hold their mutex across index reads, copies, and hardware index updates, unlocking on `-EAGAIN` early returns as well as completion. [F181, F303]
- In `octep_ctrl_mbox_init()`, write `OCTEP_CTRL_MBOX_STATUS_INIT` to `OCTEP_CTRL_MBOX_INFO_HOST_STATUS(mbox->barmem)` before setting queue pointers and `mbox->version`, then `wmb()` before writing `OCTEP_CTRL_MBOX_STATUS_READY`. In `octep_ctrl_mbox_uninit()`, clearing `OCTEP_CTRL_MBOX_INFO_HOST_VERSION` and writing `OCTEP_CTRL_MBOX_STATUS_INVALID` must be ordered by `wmb()` before destroying `h2fq_lock` and `f2hq_lock`. [F183, F294]
- In `octep_device_setup()`, `octep_ctrl_net_init()` and `INIT_WORK(&oct->ctrl_mbox_task, ...)` must finish before queueing `oct->intr_poll_task`. In `octep_open()`, set `oct->poll_non_ioq_intr = false` before `enable_interrupts(oct)`; in `octep_stop()`, set `oct->poll_non_ioq_intr = true` and queue `oct->intr_poll_task` after `disable_interrupts(oct)` and `octep_clean_irqs(oct)`. In `octep_[vf_]open()`, call `octep_[vf_]napi_add()` and `octep_[vf_]napi_enable()` before `enable_interrupts()` and `octep_[vf_]oq_dbell_init()`. [F184, F185, F279]
- `octep_iq_full_check()` must run `smp_mb()` after `netif_stop_subqueue()` and recheck `IQ_INSTR_SPACE(iq) > OCTEP_WAKE_QUEUE_THRESHOLD` (calling `netif_start_subqueue()` if true) to order against `iq->flush_index` updates in `octep_iq_process_completions()`. Before writing doorbell or interrupt-resend MMIO registers (`iq->doorbell_reg`, `oq->pkts_credit_reg`, `oq->pkts_sent_reg`, `iq->inst_cnt_reg`), issue a write barrier (`wmb()` in PF, `smp_wmb()` in VF). [F305, F307]

## Object Lifetimes

- In `octep_[vf_]open` and `octep_[vf_]stop`, `octep_[vf_]setup_iqs` and `octep_[vf_]setup_oqs` must succeed before `octep_[vf_]setup_irqs` (which reads `oct->num_oqs`, `oct->iq[i]`, `oct->oq[i]`), `octep_[vf_]clean_irqs` must run before `octep_[vf_]free_oqs` (as `octep_[vf_]free_ioq_vectors` loops to `oct->num_oqs`, which `octep_[vf_]free_oq` decrements), and `octep_[vf_]clean_iqs` must run before `octep_[vf_]free_iqs` (as `octep_[vf_]free_iq` frees `iq->buff_info` without unmapping/freeing in-flight SKBs between `flush_index` and `host_write_index`). [F172, F173, F175]
- `octep_[vf_]free_oqs()`, `octep_[vf_]oq_free_ring_buffers()`, `octep_free_ioq_vectors()`, and `octep_delete_pfvf_mbox()` iterate the full range and skip only `NULL` slots, so setup rollback, RX page handoff (`octep_oq_next_pkt`, `__octep_vf_oq_process_rx`), and free paths must set `oct->oq[q_no]`, `oq->buff_info[i].page`, `oct->ioq_vector[i]`, and `oct->mbox[ring]` to `NULL`. [F174, F207]
- In `octep_[vf_]start_xmit`, `iq->host_write_index` and `[__]netdev_tx_sent_queue` must only advance/run after all linear and SG DMA mappings succeed; on mapping error, unmap prior segments, call `dev_kfree_skb_any(skb)`, and return `NETDEV_TX_OK`. Pending BQL bytes must be completed in `octep_[vf_]iq_process_completions` or reset via `netdev_tx_reset_queue` in `octep_[vf_]iq_free_pending`. [F176, F312]
- In `octep_remove`, `unregister_netdev` and `cancel_work_sync(&oct->tx_timeout_task)` must finish before `octep_device_cleanup` sets `poll_non_ioq_intr = false` and cancels `intr_poll_task` and `ctrl_mbox_task`, which must finish before `octep_delete_pfvf_mbox` and `octep_ctrl_net_uninit`. In `octep_vf_remove`, `octep_vf_mbox_dev_remove`, `cancel_work_sync(&oct->tx_timeout_task)`, and `unregister_netdev` must run before `octep_vf_delete_mbox`, which must precede `octep_vf_device_cleanup` unmapping `oct->mmio.hw_addr`. [F178, F179]
- Because `octep_ctrl_net_*` callers allocate `struct octep_ctrl_net_wait_data d` on the stack, `octep_send_mbox_req` must only link `d->list` onto `oct->ctrl_req_wait_list` when `wait_for_response` is true and must unconditionally `list_del(&d->list)` after `wait_event_interruptible_timeout` before returning. [F274]

## API Contracts

- Callers of `init_send_req()` in `octep_ctrl_net.c` must zero-initialize `struct octep_ctrl_net_wait_data` first (for `reserved1`, `is_vf`, `vf_idx`), and pass `sz` as the payload size in `struct octep_ctrl_net_h2f_req` excluding `union octep_ctrl_net_req_hdr` (`init_send_req` adds `req_hdr_sz`). Callers of `octep_write_mbox_data()` and `octep_read_mbox_data()` must first verify `octep_ctrl_mbox_circq_space()` or `octep_ctrl_mbox_circq_depth()` has enough bytes. [F202, F233, F268]
- `octep_ctrl_net_get_mtu()` and `octep_pfvf_get_mtu()` return max RX frame length including `ETH_HLEN + ETH_FCS_LEN` (18 bytes), whereas `netdev->max_mtu`, `octep_ctrl_net_set_mtu()`, and `octep_vf_mbox_set_mtu()` use L3 MTU excluding `ETH_HLEN + ETH_FCS_LEN`. [F209]
- `octep_[vf_]iq_process_completions()` returns `!budget` (`1` if TX work remains, `0` if done), not packet counts. In `octep_[vf_]napi_poll`, if `tx_pending` is non-zero or `rx_done >= budget`, return `budget` without completing NAPI or calling `octep_[vf_]enable_ioq_irq`. `octep_[vf_]iq_full_check` returns `1` when the subqueue is stopped; `octep_[vf_]start_xmit` must then bypass `xmit_more` and ring `iq->doorbell_reg` immediately. [F208, F246, F309]
- In PF SG TX (`octep_start_xmit`, `octep_iq_process_completions`, `octep_iq_free_pending`), `sglist[0].dma_ptr[0]` (`sglist[0].len[3]`) maps `skb->data` via `dma_map_single()` / `dma_unmap_single()`, while fragment `si >= 1` (`sglist[si >> 2].dma_ptr[si & 3]`, `len[3 - (si & 3)]`) uses `skb_frag_dma_map()` / `dma_unmap_page()`. [F306]
- PF `net_device_ops` callbacks taking a userspace VF index (`octep_get_vf_config`, `octep_set_vf_mac`) must validate it with `octep_is_vf_valid()` (`vf < CFG_GET_ACTIVE_VFS(oct->conf)`). To permanently bring down `oct->netdev` from recovery work (`octep_hb_timeout_task`) under `rtnl_lock()`, call `dev_close(oct->netdev)` rather than `octep_stop()` directly. [F227, F308]
- Only `hw_ops.ioq_intr_handler` receives `struct octep_ioq_vector *`; the 11 non-IOQ `hw_ops.*_intr_handler` callbacks receive `struct octep_device *` despite `void *ioq_vector` prototypes. Indirect 64-bit reads via `OCTEP_PCI_WIN_READ(oct, addr)` must set bit 53 (`addr |= 1ull << 53`) before writing `pci_win_rd_addr`, and windowed reset writes in `octep_soft_reset_cn93/cnxk_pf()` must first write `0xFF` to `SDP_WIN_WR_MASK_REG`. [F272, F287]

## Error Handling

- `octep_ctrl_net_get_link_status()` and `octep_ctrl_net_get_mtu()` return `-errno` on failure and non-negative values (`resp.link.state` or `resp.mtu.val`) on success; callers must store the return value in a signed `int` and test `< 0`. Conversely, `[__]octep_vf_mbox_send_cmd()` and `octep_vf_mbox_bulk_read()` can return positive `OCTEP_PFVF_MBOX_CMD_STATUS_*` (`1`..`3`) or `-EOPNOTSUPP` on failure; callers must test `if (ret)` rather than `if (ret < 0)`. [F200, F201]

## External Contracts

- In `octep_probe()`, `get_fw_ready_status(pdev)` must verify PCI VSEC `FW_STATUS_VSEC_ID` (`0xA3`) reports `FW_STATUS_READY` (`1`) at `pos + 8` before `octep_device_setup()` or `octep_ctrl_net_init()`, returning `-EPROBE_DEFER` otherwise. Before programming IQ/OQ CSRs in `octep_setup_iq/oq_regs_*`, poll `SDP_R_IN/OUT_CONTROL(q)` for `R_IN/OUT_CTL_IDLE`. In `octep_[vf_]enable_iq_cn93/cnxk[_pf]()`, write `0xFFFFFFFF` to `SDP_R_IN_INSTR_DBELL(iq_no)` and poll until 0 before setting `SDP_R_IN_ENABLE(iq_no)`. [F282, F289, F290]
- New commands in `enum octep_ctrl_net_h2f_cmd`, `octep_ctrl_net_f2h_cmd`, or `octep_pfvf_mbox_opcode` require a non-zero version entry in `octep_ctrl_net_h2f/f2h_cmd_versions[]` or `pfvf_cmd_versions[]` (PF and VF). `octep_vf_iface_rx_stats`, `octep_vf_iface_tx_stats` (with `reserved[13]`), and `octep_vf_iface_link_info` must match the exact byte layout of their PF counterparts for raw bulk copies. [F238, F239]
- Every PF-VF mailbox handler in `octep_pfvf_mbox_work()` must set `rsp->s.type` to `OCTEP_PFVF_MBOX_TYPE_RSP_ACK` or `RSP_NACK`. Once `octep_set_vf_mac` sets `OCTEON_PFVF_FLAG_MAC_SET_BY_PF` in `oct->vf_info[vf].flags`, `octep_pfvf_set_mac_addr` must reject VF `OCTEP_PFVF_MBOX_CMD_SET_MAC_ADDR` requests with `OCTEP_PFVF_MBOX_TYPE_RSP_NACK`. [F241, F314]

## Known Pitfalls

- In `octep_[vf_]setup_iq`, scale `iq->sglist` by element count `i * OCTEP_[VF_]SGLIST_ENTRIES_PER_PKT` and offset `iq->sglist_dma` by byte size `i * OCTEP_[VF_]SGLIST_SIZE_PER_PKT`. In PF mailbox work (`octep_pfvf_mbox_wk`), `wk->ctxptr` is `struct octep_mbox *`, whereas in VF mailbox work (`octep_vf_mbox_wk`), `wk->ctxptr` is `struct octep_vf_device *`. [F266, F273]
- In `CNXK_PEMX_PFX_CSX_PFCFGX`, cast `pem` to `uint64_t` before shifting left by 36. On CNXK PF, call `OCTEP_PCI_WIN_WRITE(oct, CNXK_PEMX_PFX_CSX_PFCFGX(0, 0, CNXK_PCIEEP_VSECST_CTL), FW_STATUS_RUNNING)` in `octep_device_setup_cnxk_pf()` and before `CNXK_RST_CHIP_DOMAIN_W1S` in `octep_soft_reset_cnxk_pf()`. In `octep_device_setup_cn93_pf()`, check `oct->chip_id == OCTEP_PCI_DEVICE_ID_CN98_PF` to use `CN98_SDP_MAC_PF_RING_CTL_SRN`/`RPPF` and `octep_soft_reset_cn98_pf`. [F257, F283, F284]
