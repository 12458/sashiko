# BLUETOOTH SUBSYSTEM — net/bluetooth (part 5)

This unit implements the Bluetooth Management (`mgmt`) protocol interface (`mgmt.c`, `mgmt_util.c`, `mgmt_config.c`) and the Microsoft vendor-specific HCI extension (`msft.c`) for controller-offloaded LE advertisement monitoring and RSSI filtering.

## Architecture & Data Flow
- `mgmt_get_adv_discov_flags` and `mgmt_get_connectable` must check `pending_find(MGMT_OP_SET_DISCOVERABLE, hdev)` and `pending_find(MGMT_OP_SET_CONNECTABLE, hdev)` before reading `HCI_DISCOVERABLE`, `HCI_LIMITED_DISCOVERABLE`, or `HCI_CONNECTABLE` from `hdev->dev_flags`. [F193]
- In `mgmt_connect_failed`, if `test_and_clear_bit(HCI_CONN_MGMT_CONNECTED, &conn->flags)` succeeds, call `mgmt_device_disconnected` instead of emitting `MGMT_EV_CONNECT_FAILED` so every `MGMT_EV_DEVICE_CONNECTED` pairs with `MGMT_EV_DEVICE_DISCONNECTED`. [F185]
- Before calling `hci_disable_advertising_sync` in `mesh_send_done_sync` or `remove_advertising_sync`, check `list_empty(&hdev->adv_instances)`. Whenever an `adv_info` matching `hdev->cur_adv_instance` is modified or expired in `mesh_send_sync`, `adv_expire_sync`, `add_advertising`, or `add_ext_adv_data`, call `cancel_adv_timeout(hdev)` to clear `hdev->adv_instance_timeout` and cancel `hdev->adv_instance_expire`. [F186, F200]
- Userspace MGMT advertising instances are 1-based in `1..hdev->le_num_of_adv_sets` (`0x00` is for `MGMT_OP_SET_ADVERTISING`; `hdev->le_num_of_adv_sets + 1` is for `mesh_send_sync` and hidden by `read_adv_features`). `requested_adv_flags_are_valid` must reject bits outside `get_supported_adv_flags(hdev)` or multiple secondary PHY bits in `MGMT_ADV_FLAG_SEC_MASK`. [F211, F227]
- `mgmt_mesh_foreach`, `mgmt_mesh_next`, and `mgmt_mesh_find` must iterate `&hdev->mesh_pending`, never `&hdev->mgmt_pending`. `mgmt_mesh_add` wraps `hdev->mesh_send_ref` in `1..255` (skipping `0`, the wildcard in `send_cancel`), and `send_cancel` / `mgmt_cleanup` loops rely on `mesh_send_complete` calling `mgmt_mesh_remove(mesh_tx)` on every non-NULL `mesh_tx`. [F212, F220, F225]
- `hdev->advmon_pend_notify` tracks unnotified `hdev->monitored_devices`: `msft_device_found` sets it `true`, `msft_resume_sync` / `msft_do_close` clear it when purging `monitored_devices`, and `mgmt_adv_monitor_device_found` clears it and must set it back `true` if any entry still has `!dev->notified` (do not `break` early on `bdaddr` match). `mgmt_send_adv_monitor_device_found` prepends `__le16 monitor_handle` to `skb->data` from the `MGMT_EV_DEVICE_FOUND` `skb` and must run before `mgmt_event_skb` pushes `mgmt_hdr`. [F201, F229, F235]
- Skip `HCI_QUIRK_RAW_DEVICE` controllers in `read_index_list`, `read_unconf_index_list`, `read_ext_index_list`, `mgmt_index_added`, and `mgmt_index_removed`. `is_configured` and `get_missing_options` treat `hdev` as unconfigured when `HCI_QUIRK_EXTERNAL_CONFIG` is set without `HCI_EXT_CONFIGURED`, or when `HCI_QUIRK_INVALID_BDADDR` / `HCI_QUIRK_USE_BDADDR_PROPERTY` is set with `hdev->public_addr == BDADDR_ANY`. [F252, F254]
- In `read_index_list`, `read_unconf_index_list`, `read_ext_index_list`, and `get_connections`, the second list pass must reset the counter and recompute the response count and `mgmt_cmd_complete` payload size from the filtered count. [F226]
- New `mgmt_handlers[]` entries must add their `MGMT_OP_*` to `mgmt_commands[]` (and `mgmt_untrusted_commands[]` if `HCI_MGMT_UNTRUSTED`). `exp_features[]` must end with `EXP_FEAT(NULL, NULL)`. Public signature changes in `msft.c` must update both `#if IS_ENABLED(CONFIG_BT_MSFTEXT)` declarations and `#else` stubs in `msft.h`. [F197, F202, F214]
- `msft_vendor_evt` and sub-event handlers (`msft_monitor_device_evt`) must consume bytes sequentially via `msft_skb_pull` (`msft->evt_prefix_len`, 1-byte event code, then event struct). `msft_add_monitor_sync` advances `offset += sizeof(*pattern) + entry->length` (3 + `entry->length`) while setting `pattern->length = entry->length + 2`. In `msft_suspend_sync` and `reregister_monitor`, `idr_get_next(&hdev->adv_monitors_idr, &handle)` loops must increment `handle++` each iteration. [F210, F223, F241]
- `eir_has_uuids` must check `field_len == 0` and `eir_len - parsed < field_len + 1` before reading `eir[1]`, and use additive UUID loop bounds (`i + 3/5/17 <= field_len`). `get_conn_info` must check cache expiry with `time_after(jiffies, conn->conn_info_timestamp + msecs_to_jiffies(conn_info_age)) || !conn->conn_info_timestamp`. [F215, F232]

## Synchronization
- Lock order: `hdev->req_lock` (`hci_req_sync_lock`) -> `hdev->lock` (`hci_dev_lock`) -> `msft->filter_lock`, and `hdev->lock` -> `hdev->mgmt_pending_lock`; never acquire an outer lock while holding an inner lock or hold `hdev->lock` / `msft->filter_lock` across `__hci_cmd_sync`. `mgmt_pending_foreach` callbacks run under `hdev->mgmt_pending_lock` and must not call `mgmt_pending_find/add/remove/listed/valid` or `hci_dev_lock(hdev)`. [F168, F259, F261]
- `hci_cmd_sync` work callbacks for commands on `hdev->mgmt_pending` must check `__mgmt_pending_listed` / `mgmt_pending_listed` under `hdev->mgmt_pending_lock` and copy `cmd->param` / `cmd->user_data` before unlocking (returning `-ECANCELED` if unlinked). Completion callbacks must return before `hci_dev_lock(hdev)` if `err == -ECANCELED` or `!mgmt_pending_valid(hdev, cmd)`, and then call `mgmt_pending_free(cmd)`. [F160, F161]
- Async `hci_cmd_sync` workers must read new values from `cmd->param` rather than `hdev` fields updated after `hci_cmd_sync_queue` (e.g. `set_name_sync`), and callbacks (`add_device_complete`, `disconnect_sync`, `unpair_device_sync`, `get_conn_info_sync`, `get_clock_info_sync`) must re-lookup `hci_conn_params` or `hci_conn` by address rather than caching pointers/flags across the lock drop. [F163, F188]
- Under `read_lock(&hci_dev_list_lock)`: index-list handlers must allocate with `GFP_ATOMIC` and only call `mgmt_cmd_complete` / `mgmt_cmd_status` after `read_unlock`; `mgmt_cleanup` must pass `silent = true` to `mesh_send_complete` for matching `mgmt_mesh_tx` entries so `mgmt_mesh_remove` unlinks and drops `sk` without allocating an SKB under the rwlock. [F158, F257]
- In `set_powered`, powering off (`cp->val == 0x00`) must call `hci_cmd_sync_cancel_sync(hdev, -EHOSTDOWN)` before queueing `set_powered_sync`. During MSFT suspend/resume, `msft->suspending` and `msft->resuming` must be set so `msft_add_monitor_pattern` and `msft_remove_monitor` return `-EBUSY` and `msft_le_cancel_monitor_advertisement_cb` does not free `monitor` while `msft->suspending`. [F171, F262]

## Object Lifetimes
- `mgmt_alloc_skb` reserves `sizeof(struct mgmt_hdr)` headroom and sets `bt_cb(skb)->mgmt`, required by `mgmt_send_event_skb` (and `mgmt_event_skb`), which pushes `mgmt_hdr` and unconditionally frees `skb` via `kfree_skb`. By contrast, `mgmt_send_adv_monitor_device_found` borrows `skb` and allocates a separate `advmon_skb`. [F145, F265]
- `mgmt_pending_new` commands are unlinked and freed with `mgmt_pending_free`; `mgmt_pending_add` commands are on `hdev->mgmt_pending` and must be unlinked via `mgmt_pending_remove` or `mgmt_pending_valid` before `mgmt_pending_free`. When `mgmt_pending_foreach` runs with `remove = true`, it unlinks `cmd->list` before `cb` and calls `mgmt_pending_free(cmd)` after, so `cb` and `cmd->cmd_complete` (`pairing_complete`, `addr_cmd_complete`, `generic_cmd_complete`) must not remove or free `cmd`. [F146, F148]
- `settings_rsp` and `sk_lookup` call `sock_hold(match->sk)` on the first matched command when `match->sk == NULL`; callers must initialize `match.sk = NULL` and call `sock_put(match.sk)` if non-NULL. [F149]
- In `pair_device`, drop `conn` via `hci_conn_drop(conn)` on error before `cmd->user_data = hci_conn_get(conn)`; once set, `pairing_complete` must clear `conn->connect_cfm_cb`, `security_cfm_cb`, and `disconn_cfm_cb` and call both `hci_conn_drop` and `hci_conn_put`. [F150]
- `__add_adv_patterns_monitor` must call `hci_free_adv_monitor(hdev, m)` on synchronous error, while `mgmt_add_adv_patterns_monitor_complete` increments `hdev->adv_monitors_cnt` and updates `monitor->state` only when `!status`. `msft_le_monitor_advertisement_cb` must call `hci_free_adv_monitor` under `hdev->lock` on short response, `rp->status != 0`, or `kmalloc` failure; `msft_le_cancel_monitor_advertisement_cb` must call `hci_free_adv_monitor` and `msft_monitor_device_del` only when `!msft->suspending`. [F151, F155]
- In `msft_remove_addr_filters_sync`, an `address_filter` in `AF_STATE_ADDING` must be set to `AF_STATE_REMOVING` and not freed or added to `head` (leaving `msft_add_address_filter_sync` / `msft_cancel_address_filter_sync` to free it). `msft_add_address_filter_sync` and `msft_cancel_address_filter_sync` must verify `hdev->msft_data && test_bit(HCI_UP, &hdev->flags)` before dereferencing `address_filter`. [F156, F170]
- `msft_do_open` must free any prior `msft->evt_prefix` and reset `evt_prefix`, `evt_prefix_len`, and `features` before `read_supported_features`, and clear `hdev->msft_data = NULL` and free `msft` if probing fails. `msft_do_close` must free `msft->handle_map` and `msft->address_filters` locally without sending cancel HCI commands, reset offloaded monitors to `ADV_MONITOR_STATE_REGISTERED`, and purge `hdev->monitored_devices` via `msft_monitor_device_del`. [F245, F246]
- `__mgmt_power_off` must drain `hdev->mgmt_pending` (`MGMT_STATUS_INVALID_INDEX` if `HCI_UNREGISTER`, else `MGMT_STATUS_NOT_POWERED`) before connection teardown or `mgmt_index_removed`. `mgmt_index_removed` must only call `cancel_delayed_work_sync` on `discov_off`, `service_cache`, and `rpa_expired` if `hci_dev_test_flag(hdev, HCI_MGMT)` is true. [F165, F256]

## API Contracts
- Handlers that run when powered off (`set_powered` with `cp->val == 1`, `add_uuid`, `remove_uuid`, `set_dev_class`, `remove_adv_monitor`) must use `hci_cmd_sync_submit`, not `hci_cmd_sync_queue`. [F164]
- `link_to_bdaddr` maps `CIS_LINK`, `BIS_LINK`, `PA_LINK`, and `LE_LINK` to LE address types, while `mgmt_device_disconnected` only emits `MGMT_EV_DEVICE_DISCONNECTED` for `ACL_LINK`, `LE_LINK`, and `BIS_LINK`. BR/EDR link key paths (`load_link_keys`, `mgmt_new_link_key`) use `BDADDR_BREDR`; SMP LE key paths (`load_long_term_keys`, `load_irks`, `mgmt_new_ltk`, `mgmt_new_irk`, `mgmt_new_csrk`) use `BDADDR_LE_PUBLIC` / `BDADDR_LE_RANDOM`. [F179, F270]
- `msft_find_handle_data(hdev, handle, is_mgmt)` matches `entry->mgmt_handle` when `is_mgmt == true` (`adv_monitor->handle`) and `entry->msft_handle` when `false` (`ev->monitor_handle`). `mgmt_mesh_add` callers must verify `len <= MGMT_MESH_SEND_SIZE + 31` (`sizeof(mesh_tx->param)`). Commands with `cmd->cmd_complete = addr_cmd_complete` must have `cmd->param` starting with `struct mgmt_addr_info` (`param_len >= sizeof(struct mgmt_addr_info)`). Access `HCI_QUIRK_*` and `dev_flags` via `hci_test_quirk` and `hci_dev_test/set/clear_flag`, never `test_bit` on `&hdev->flags`. [F182, F205, F242, F244]

## Error Handling
- `mgmt_status(int err)` maps `err < 0` as errnos and `err >= 0` as HCI status codes; preserve negative errnos in a signed `int`/`long`, never `u8`. [F173]
- `set_default_phy_complete`, `read_local_oob_data_complete`, and `read_local_oob_ext_data_complete` must check both `!skb` and `IS_ERR(skb)` before reading `skb->data` or calling `kfree_skb(skb)`. In `msft_add_address_filter_sync`, reset `skb = NULL` on `IS_ERR(skb)` before `goto done:` (which calls `kfree_skb(skb)`). [F174, F175]
- `mgmt_alloc_skb` and `hci_conn_params_add` return `NULL` on error (`!ptr`); `hci_connect_acl`, `hci_connect_le_scan`, and `hci_add_adv_instance` return `ERR_PTR` (`IS_ERR(ptr)`). `msft_le_set_advertisement_filter_enable_cb` must treat HCI status `0x0C` (Command Disallowed) as success alongside `0x00` and update `msft->filter_enabled = cp->enable`. [F176, F177, F251]
- In `load_link_keys`, `load_long_term_keys`, and `load_conn_param`, after header/length validation, skip invalid, blocked, or debug key entries (`MGMT_LTK_P256_DEBUG`, `HCI_LK_DEBUG_COMBINATION`) with `continue` rather than failing the batch. [F228, F269]

## External Contracts
- `HCI_MGMT_VAR_LEN` handlers must validate exact payload sizes: `__le16` count + array handlers (`load_link_keys`, `load_irks`, `load_long_term_keys`, `load_conn_param`, `set_blocked_keys`, `start_service_discovery`) must bound count by `(U16_MAX - sizeof(*cp)) / sizeof(elem)` and check `struct_size == len`; `add_advertising` / `add_ext_adv_data` must check `data_len == sizeof(*cp) + cp->adv_data_len + cp->scan_rsp_len` and `tlv_data_is_valid` on both slices. By contrast, `add_ext_adv_params` checks `data_len < MGMT_ADD_EXT_ADV_PARAMS_MIN_SIZE` and only reads optional fields when their `MGMT_ADV_PARAM_*` flag bit is set. [F203, F208, F218, F268]
- `read_ext_index_list` swaps `HCI_MGMT_INDEX_EVENTS` / `HCI_MGMT_UNCONF_INDEX_EVENTS` for `HCI_MGMT_EXT_INDEX_EVENTS` on `sk`, and `read_ext_controller_info` swaps `HCI_MGMT_DEV_CLASS_EVENTS` / `HCI_MGMT_LOCAL_NAME_EVENTS` for `HCI_MGMT_EXT_INFO_EVENTS`; thus `mgmt_index_added` / `mgmt_index_removed` must emit both legacy and extended index events, and CoD, local name, or `set_appearance` changes must also call `ext_info_changed`. [F194, F195, F272]
- `set_scan_params` and `set_mesh` must validate endian-converted interval/period and window in `0x0004..0x4000` with `window <= interval`. TLV `0x001b` (`def_le_autoconnect_timeout`) in `read_def_system_config` / `set_def_system_config` must convert between wire msecs and `hdev` jiffies, and `set_def_system_config` must validate all TLVs in a first pass before mutating `hdev` (ignoring unknown TLV types with `bt_dev_warn`). [F183, F209, F274]
- `read_exp_features_info` and `set_exp_feature` (`HCI_MGMT_HDEV_OPTIONAL`) must handle `hdev == NULL` (populating global `debug_uuid` / `iso_socket_uuid` when `NULL` and guarding controller features with `if (hdev && ...)`). In `mgmt_device_found`, normalize `ev->rssi = 0` when `rssi == HCI_RSSI_INVALID && !hdev->discovery.report_invalid_rssi && link_type == ACL_LINK`. [F219, F267]

## Known Pitfalls
- `hdev->dev_name` (248B) and `hdev->short_name` (10B) are 1B shorter than `MGMT_MAX_NAME_LENGTH` / `MGMT_MAX_SHORT_NAME_LENGTH` and may be non-NUL-terminated; bound copies by `sizeof(hdev->dev_name)` / `sizeof(hdev->short_name)` and use `strnlen`, never `strlen`. [F233]
- `eir_append_data` and `eir_append_le16` do not bounds-check, so `read_controller_cap` (`char buf[20]`) and `read_local_oob_ext_data` / `read_local_oob_ext_data_complete` must pre-allocate `2 + data_len` bytes per field; `read_exp_features_info` pre-allocates 7 entries (`sizeof(*rp) + sizeof(rp->features[0]) * 7`). [F237, F238]
- In `load_conn_param`, initialize `bool update = false` inside the `for` loop body. Helpers taking wire `__le16`/`__le32` (`mgmt_adv_monitor_removed`, `user_pairing_resp`) must type parameters as `__le16`/`__le32` without double-converting via `cpu_to_le*`. [F180, F216]
- In `msft_monitor_device_evt`, store a matched filter in `address_filter = NULL` rather than testing the `list_for_each_entry` cursor `n` after the loop, and when `HCI_QUIRK_USE_MSFT_EXT_ADDRESS_FILTER` is set, do not report found/lost on pattern monitor handles—queue `msft_add_address_filter` on found events instead. [F224, F250]
