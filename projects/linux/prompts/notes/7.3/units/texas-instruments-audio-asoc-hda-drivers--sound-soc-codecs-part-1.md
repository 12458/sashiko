# TEXAS INSTRUMENTS AUDIO (ASoC/HDA) DRIVERS — sound/soc/codecs (part 1)

This unit contains the TAS2781 firmware library (`tas2781-fmwlib.c`), TAS2781 I2C driver (`tas2781-i2c.c`), TAS2783 SoundWire SDCA driver (`tas2783-sdw.c`), and TLV320 codec/ADC drivers (`tlv320adc3xxx`, `tlv320adcx140`, `tlv320aic23`, `tlv320aic26`, `tlv320aic31xx`, `tlv320aic32x4`, `tlv320aic3x`).

## Architecture & Data Flow
- In `tasdevice_fw_ready()`, `tas_priv->fw_state` becomes `TASDEVICE_RCA_FW_OK` after `tasdevice_rca_parser()` and `TASDEVICE_DSP_FW_ALL_OK` only after `tasdevice_dsp_parser()` and `tasdevice_dsp_create_ctrls()` succeed; if still `TASDEVICE_RCA_FW_OK` at `out:`, `tasdevice_dsp_remove()` must free partial DSP state. `tasdevice_tuning_switch()` and `tasdevice_startup()` must allow playback in either state for RCA-only chips and fallback mode. [F209, F285]
- In `tasdevice_select_tuningprm_cfg()` and `tasdevice_prmg_load()`, setting `tasdevice[i].is_loading = true` must reset `tasdevice[i].cur_conf = -1` to force config/calibration reload, and `tasdev_load_calibrated_data()` must run after `tasdevice_load_data(tas_priv, &(conf->dev_data))` so config writes do not overwrite calibration. Signed indices (`prm_no`, `cfg_no`, `rca_conf_no`, `conf_no`) can be `-1` and must be checked `>= 0` (along with upper bounds) before indexing `programs`, `configs`, or `rca->cfg_info`. [F206, F220, F283]
- In `tas2781-fmwlib.c`, `tasdev_blk_data::dev_idx` and `tasdev_blk::dev_idx & 0x3F` use `0` for broadcast to all `ndev` channels and `1..ndev` as 1-based indices (decrement by 1 before indexing `tasdevice[]` or shifting `active_dev`). In `tasdevice_process_block()`, `dev_idx & 0xC0` tags RCA (`0x00`), DSP program (`0x80`), and coeff/pre (`0xC0`) blocks, so new `map_dev_idx()` table entries must set `0x80` or `0xC0`. [F221, F222]
- In `tasdevice_dspfw_ready()`, every supported non-`0x100` `fw_fixed_hdr->drv_ver` needs a `switch` case (`default` calls `dspfw_default_callback()`, which rejects `drv_ver != 0x100`). In `map_dev_idx()`, `dspbin_type_check()`, and `dspfw_default_callback()`, `ppcver >= ...` checks must be ordered from highest threshold (`PPC3_VERSION_TAS5825_BASE`, `PPC3_VERSION_TAS2781_BETA_MIN`, `PPC3_VERSION_TAS2781_BASIC_MIN`) down to `PPC3_VERSION_BASE`. [F245, F246]
- `fw_parse_variable_header_kernel()` and `fw_parse_variable_hdr()` must reject `fw_hdr->device >= TASDEVICE_DSP_TAS_MAX_DEVICE` or `== 6` before indexing `deviceNumber[]` (`6` is an unassigned gap with `deviceNumber[6] == 0`). In `tas2781-i2c.c`, `tasdevice_parse_dt()` indexes `tasdevice_id[tas_priv->chip_id]`, so `tasdevice_id[]` must match `enum audio_device` 1-to-1. [F224, F280]
- Non-kernel DSP blocks (`fw_parse_block_data()`) size `block->data` as `nr_cmds * 4` bytes and step by 4-byte words in `tasdev_load_blk()`, whereas kernel blocks (`fw_parse_block_data_kernel()`) size `block->data` as `blk_size` bytes and step by bytes in `tasdevice_load_block_kernel()`. In `tasdev_load_blk()` and `tasdev_multibytes_wr()`, multi-byte commands (`offset == 0x85`) increment `nr_cmds` once for the header and advance `*nr_cmds` by `1 + (len >= 2 ? ((len - 2) / 4) + 1 : 0)`. [F251, F270]
- `tasdevice_load_block()` must reset `block->nr_retry = 6` each channel iteration (`for (; chn < chnend; chn++)`) before `tasdev_load_blk()`, and each retry pass in `tasdev_load_blk()` must reset `TASDEVICE_CHECKSUM_REG`, `crc_chksum = 0`, and `nr_cmds = 0`. `tasdev_multibytes_chksum()` must reject `(reg + len - 1) > 127` before `check_yram()` and `dev_bulk_read()` into `nBuf1[128]`. [F228, F250]
- `sngl_calib_start()` and `tas2563_calib_start_put()` must read current registers into `tasdev[i].cali_data_backup` (and `alp_cali_bckp` for `TASDEV_ALPHA`) before writing start values so stop callbacks can restore them. `sngl_calib_start()` loops `j` up to `ARRAY_SIZE(tas2781_cali_start_reg) - 4` for 1-byte writes and indexes `p[j..j+3]` for 4-byte bulk writes, so the last 4 entries of `tas2781_cali_start_reg[]` must remain the four 4-byte registers in order. [F211, F229]
- In `tasdev_cali_data_get()`, every `continue` path in `for (j = 0, k = 0; j < priv->ndev; j++)` must advance `i` and `k` by the exact remaining bytes of the 21-byte device record (`+21`, `+20`, `+16`, `+12`, or `+8`). In `tasdevice_digital_gain_get/put()`, `mc->max` is the inclusive upper index into ascending big-endian `tas_dev->dvc_tlv_table[]`, so controls must set `mc->max = ARRAY_SIZE(table) - 1`. [F232, F253]
- In `tas2783-sdw.c`, `tas2783_validate_calibdata()` must verify `spk_count <= TAS2783_CALIB_MAX_SPK_COUNT` (8) and `size >= (spk_count * TAS2783_CALIB_PARAMS * sizeof(u32)) + TAS2783_CALIB_HDR_SZ + TAS2783_CALIB_CRC_SZ` before `tas2783_set_calib_params_to_device()` reads `cali_data[3..]` (`TAS2783_CALIB_PARAMS` = `ARRAY_SIZE(tas2783_cali_reg) + 1`). Every register in `tas2783_reg_default[]`, `tas2783_init_seq[]`, or accessed via `tas_dev->regmap` must have a case in `tas2783_sdca_mbq_size()`. [F233, F235]
- In paged regmaps (`aic32x4`, `aic31xx`, `adc3xxx`), adding a higher-paged register requires updating both `regmap_config.max_register` and `regmap_range_cfg.range_max`. Dynamic DAPM routes in `aic31xx_clock_master_routes()` (`master_dapm_route_applied`), `adc3xxx_hw_params()` (`use_pll`), and `adc3xxx_set_dai_fmt()` (`master`) must only be added when the flag is false and deleted when true, updating the flag in lockstep. [F214, F215]
- In `tlv320aic31xx.c`, when `sysclk_id == AIC31XX_PLL_CLKIN_BCLK`, `aic31xx_hw_params()` must set `sysclk = rate * width * channels` and `p_div = 1` before `aic31xx_setup_pll()`. `aic31xx_setup_pll()` must verify `sysclk` and `p_div` are non-zero before dividing, and only set `aic31xx->rate_div_line = match` after checking `match != -1` (`aic31xx_clk_on()` indexes `aic31xx_divs[rate_div_line]` unchecked). [F216, F237, F264]
- In `tlv320aic31xx.c`, `AIC31XX_HSDETECT` is volatile, so `aic31xx_power_on()` must call `aic31xx_set_jack(component, aic31xx->jack, NULL)` after `aic31xx_reset()` and `regcache_sync()`. In `aic31xx_set_dai_fmt()`, `DSP_A` sets `dsp_a_val = 0x1` and falls through to `DSP_B`, which must toggle `iface_reg2 ^= AIC31XX_BCLKINV_MASK` after the polarity switch. `aic31xx_dapm_power_event()` must poll `AIC31XX_DACFLAG1`/`ADCFLAG` via `aic31xx_wait_bits()` (7s `POST_PMU` timeout for `AIC31XX_HPDRIVER`). DAC-only variants (`codec_type & DAC31XX_BIT`) must gate off ADC controls, widgets, routes, and capture DAI. In `tlv320dac3100_fw_load()`, `size != 153` must match the exact `data++` loop sum (`4 + 1 + 124 + 24`). [F217, F236, F259, F295, F296]
- In `tlv320aic32x4.c`, `AIC32X4_TYPE_TAS2505` must not write `AIC32X4_ADCSPB`/`ADCSETUP`, must reject `r_block != 0` or `p_block > 3` in `aic32x4_set_processing_blocks()`, and uses `soc_component_dev_aic32x4_tas2505` / `aic32x4_tas2505_dai`. In `tlv320aic32x4-clk.c`, `AIC32X4_DIV_MASK` encodes `AIC32X4_DIV_MAX` (`128`) as `0`, so `clk_aic32x4_div_recalc_rate()` must map `val == 0` to `AIC32X4_DIV_MAX` before dividing. [F242, F297]
- In `tlv320adc3xxx.c`, `gpio_cfg[]` stores DT pin configs as `val + 1` (`0` = unconfigured), so `adc3xxx_gpio_request()` compares against `ADC3XXX_GPIO_GPO + 1` and `adc3xxx_init_gpio()` decrements `cfg--`. Offsets `0..1` index `adc3xxx_gpio_ctrl_reg[]`/`gpio_cfg[]`, while offsets `2..3` (`ADC3XXX_GPIO_PINS..ADC3XXX_GPIOS_MAX - 1`) must subtract `ADC3XXX_GPIO_PINS` before indexing `micbias_gpo[]`, `micbias_vg[]`, or `adc3xxx_micbias_shift[]`. In `adc3xxx_divs[]`, PLL entries (`pll_p != 0`) must precede non-PLL entries for the same `(mclk, rate)`. [F238, F239, F240]
- In `tlv320adcx140.c`, when `supply_areg` is `NULL`, `adcx140_codec_probe()` must set `ADCX140_AREG_INTERNAL | ADCX140_WAKE_DEV` in `ADCX140_SLEEP_CFG` after reset and wait >= 1 ms. `adcx140_hw_params()` and `adcx140_set_dai_fmt()` must call `adcx140_pwr_ctrl(adcx140, false)` before modifying `ASI_CFG0`, `MST_CFG0`, or `ASI_CFG1`, and `adcx140_pwr_ctrl(adcx140, true)` must write `ADCX140_PHASE_CALIB` from `phase_calib_on` before `ADCX140_PWR_CFG`. In `tlv320aic23.c`, `tlv320aic23_shutdown()` must reset the closing stream's `requested_dac` or `requested_adc` to `0`. [F218, F219, F293]

## Synchronization
- In `tas2781-fmwlib.c`, `tasdevice_rca_parser()`, `tasdevice_dsp_parser()`, `tas2781_load_calibration()`, `tasdevice_prmg_load()`, `tasdevice_select_cfg_blk()`, and `tasdevice_tuning_switch()` do not lock `tas_priv->codec_lock`; callers in `tas2781-i2c.c` must hold `codec_lock`. In `tasdevice_i2c_probe()`, `tasdevice_parse_dt()`, `tasdevice_init()`, and `tasdevice_reset()` must finish before `devm_snd_soc_register_component()`. [F177, F181]
- In `tas2783-sdw.c`, `tas_io_init()` and `tas_update_status()` must not hold `pde_lock` or `calib_lock` while waiting on `fw_wait`, because `tas2783_fw_ready()` acquires both locks before waking `fw_wait`. [F301]
- In `tlv320aic31xx.c`, `aic31xx_irq()` must be a threaded IRQ (`IRQF_ONESHOT`, NULL hardirq handler) due to sleeping I2C regmap reads and `snd_soc_jack_report()`, and must check `if (aic31xx->jack)` before `snd_soc_jack_report()` since the IRQ is registered before `aic31xx_set_jack()`. `aic31xx_codec_probe()` must set both `disable_nb[i].nb.notifier_call` and `disable_nb[i].aic31xx = aic31xx` before `devm_regulator_register_notifier()`. [F186, F187, F306]

## Object Lifetimes
- `tasdevice_fw_ready()` must `goto out` on every exit path to unlock `codec_lock` and call `release_firmware(fmw)`. `tas2781_load_calibration()` must `goto out` on every exit path to call `release_firmware(fw_entry)`, leaving `tasdev->cali_data_fmw` attached on parse failure so `tasdevice_calbin_remove()` frees the tree and clears `cali_data_fmw = NULL`. [F161, F166]
- In `tas2781-fmwlib.c`, `tasdevice_rca::cfg_info` and `tasdevice_config_info::blk_data` are `kcalloc` pointer arrays to `kzalloc` elements (`tasdevice_config_info_remove()` must `kfree()` each element before the array), whereas `tasdevice_fw::programs`, `configs`, `calibrations`, and `tasdevice_data::dev_blks` are contiguous struct arrays (teardown in `tas2781_clear_calfirmware()` / DSP removal must only `kfree()` `block->data` and the array base pointer). In `tas2781-i2c.c`, `tasdev[i].cali_data_backup` uses non-devm `kmemdup()` and must be `kfree()`d in `tasdevice_deinit()`, unlike `devm_*`-allocated kcontrols and `cali_data->data`. [F167, F268, F269]
- In `tlv320aic32x4.c`, optional supplies `supply_ldo`, `supply_dv`, and `supply_av` (`devm_regulator_get_optional()`) hold `ERR_PTR` when absent, so `aic32x4_setup_regulators()` and `aic32x4_disable_regulators()` must guard them with `!IS_ERR(...)`, disabling in reverse LIFO order (`error_av`, `error_dv`, `error_ldo`) on setup failure, and `aic32x4_probe()` must jump to `err_disable_regulators` on post-setup failure. In `tlv320aic32x4-clk.c`, `aic32x4_clkdesc_array[0..1].parent_names` are assigned stack compound literals in `aic32x4_register_clocks()` and dangle once it returns. [F170, F171, F276]
- `aic31xx_power_on()` must restore `regcache_cache_only(aic31xx->regmap, true)` and call `regulator_bulk_disable()` if `regcache_sync()` fails. In `tlv320adc3xxx.c`, error paths after `clk_prepare_enable(adc3xxx->mclk)` in `adc3xxx_i2c_probe()` must jump to `err_unprepare_mclk`, and `adc3xxx_i2c_remove()` must not be marked `__exit`. In `adcx140_i2c_probe()`, non-`-EPROBE_DEFER` errors from `devm_regulator_get_optional(..., "areg")` must reset `supply_areg = NULL`, while success must enable it and register `adcx140_disable_regulator()` via `devm_add_action_or_reset()`. [F173, F176, F290]

## API Contracts
- `tas2781-fmwlib.c` is shared by ASoC (`codec` is `snd_soc_component *`, drvdata is `tasdevice_priv *`) and HDA (`codec` is `hda_codec *`, drvdata is `tas2781_hda *`), so it must never downcast `tas_priv->codec` or `dev_get_drvdata(tas_priv->dev)`. All `tas2781-fmwlib.c` exports use `EXPORT_SYMBOL_NS_GPL(..., "SND_SOC_TAS2781_FMWLIB")`, requiring `MODULE_IMPORT_NS("SND_SOC_TAS2781_FMWLIB")`. [F275, F321]
- In `tas2781_cali_start_reg`, protected test registers (`TAS2781_PRM_TEST_57_REG`, `TAS2781_PRM_TEST_62_REG`) must set `is_locked = true` via `X2781_CL_STT_VAL` so `TAS2781_TEST_PAGE_UNLOCK` is written to `TAS2781_TEST_UNLOCK_REG`. In `tasdevice_parse_dt()`, request reset GPIO via `devm_gpiod_get_optional()` with `"reset"` (no `"-gpios"`), and never pass IRQs from `of_irq_get()`/`acpi_dev_gpio_irq_get()` to GPIO APIs. [F282, F286]
- In `tlv320aic32x4-clk.c`, `aic32x4_pll_ops`, `aic32x4_div_ops`, and `aic32x4_bdiv_ops` must use `.prepare`/`.unprepare`/`.is_prepared` (not `.enable`/`.disable`) because regmap I/O and `msleep(10)` sleep. In `tlv320adc3xxx.c`, `adc3xxx_gpio_chip` must keep `.can_sleep = 1`, and `adc3xxx_gpio_set()` must set both output mode (`ADC3XXX_GPIO_GPO`) and level via `adc3xxx_gpio_direction_out()`. In `adcx140_set_dai_tdm_slot()`, `tx_mask` must equal `GENMASK(__fls(tx_mask), 0)` unless `ADCX140_ASI_CH1..CH8` are explicitly programmed. [F241, F305, F307, F312]

## Error Handling
- `tasdevice_add_config()` never clears `*status` on success and returns a non-NULL partial `tasdevice_config_info *` on error; `tasdevice_rca_parser()` increments `rca->ncfgs` before calling it (updating `rcabin.init_profile_id = rcabin.ncfgs - 1` without breaking on `"init"` matches) and stores the pointer in `rca->cfg_info[i]`. Callers must init `*status = 0`, check `*status` (not NULL), call `tasdevice_config_info_remove()` on failure, and bound loops in `tasdevice_config_info_remove()` and `tasdevice_select_cfg_blk()` by `rca->ncfgs` and `real_nblocks` (not `fw_hdr.nconfig` or `nblocks`). [F163, F189, F247, F248]
- In `tlv320adcx140.c`, callers of `device_property_count_u32()` for optional DT properties (`"ti,gpio-config"`, `"ti,pdm-edge-select"`, `"ti,gpi-config"`) must store the result in a signed `int` and check `<= 0` (or `> 0`) rather than `== 0`. [F199]

## External Contracts
- In `fw_parse_fct_param_address()` and `fct_param_address_parser()`, the calibration parameter section is 40 reserved bytes + twenty 24-byte entries (`520` bytes; verify `offset + 520 <= fmw->size`), with `dat[23] != 1` terminating the scan. In `tasdev_cali_data_put()`, `tasdevice_create_cali_ctrls()`, and `tasdev_load_calibrated_data()`, `Speaker Calibrated Data` has a 17-byte header (`[0] == bytes_ext->max`, `[1] == 'r'`, 15 reg bytes) + `ndev` 21-byte records where `src[17 + j * 21] == j`. In `acoustic_ctl_write/read()`, `struct acoustic_data` has a 6-byte header (`len`, `id`, `addr`, `book`, `page`, `reg`) + 128-byte `data`; writes use `len = src[0] - 6`, while reads take `len = src[6]` and set `p->len = len + 6`. [F227, F230, F231]

## Known Pitfalls
- `cali_reg_update()` and `partial_cali_data_update()` must switch on the immutable `tas2781_cali_start_reg[j].reg` template rather than `p[j].reg` (overwritten across runs), and `struct bulk_reg_val::val` must be >= 4 bytes because `sngl_calib_start()` and `tas2563_calib_start_put()` cast `&p[j].val[0]` to `(int *)/(unsigned int *)` in `tasdevice_dev_read()`. Do not confuse `cali_reg_array.r0_reg` (`unsigned int` for `iks_E0` in `tasdev_r0_data_get()`) with `fct_par_addr.r0_reg` (`u8[3]` `[book, page, reg]` for `Re_Int` in `tasdev_re_data_get()`). [F210, F255, F272]
- `tasdevice_config::name`, `tasdevice_data::name`, and 64-byte profile headers in `tas2781-fmwlib.c` are not NUL-terminated; bound all string operations to 64 bytes. Optional GPIOs from `devm_gpiod_get_optional()` (`aic32x4->rstn_gpio`, `aic31xx->gpio_reset`) are `NULL` when absent, so check `if (gpio)` before toggling. In `aic32x4_setup_clocks()`, compute `madc` and `min_mdac` with `DIV_ROUND_UP((32 * resource_class), osr)`, not truncating division. [F244, F263, F279]
