# DRM DRIVERS — (top level) (part 2)

This component provides core DRM C headers (rectangle math, simple KMS pipelines, suballocation, syncobjs, vblank tracking and workers, VMA offset management, writeback connectors, lockless SPSC queues, task barriers, and VGA arbitration), core and driver UAPI headers (DRM/KMS ioctls, FourCC pixel formats and modifiers, SAREA, and OMAP/VGEM/VirtGPU ioctls), and safe Rust kernel abstractions (`kernel::drm`) wrapping `drm_device`, `drm_driver`, `drm_file`, `drm_gem_object`, and ioctl dispatch tables.

## Architecture & Data Flow

- In any `impl drm::Driver for T`, `<T::File as DriverFile>::Driver` must equal `T`, because `Device<T>::VTABLE` wires `File::<T::File>::open_callback` which casts `raw_dev` (`Device<T>`) to `&Device<<T::File as DriverFile>::Driver>` via `Device::from_raw`. Broken by: implementing `Driver` with `type File = F` where `F::Driver` is a different driver type. [F261]
- `drm_writeback_connector::encoder` is only initialized by `drm_writeback_connector_init`; when initialized via `drm_writeback_connector_init_with_encoder` or `drmm_writeback_connector_init`, the caller-supplied external `struct drm_encoder *enc` is attached and `wb_connector->encoder` is invalid. Broken by: dereferencing or cleaning up `&wb_connector->encoder` on connectors initialized with an external encoder. [F202]
- `struct drm_rect` (`include/drm/drm_rect.h`) must keep the exact field order and 32-bit signed integer layout (`x1, y1, x2, y2`) of UAPI `struct drm_mode_rect` because `drm_atomic_helper_damage_iter_init()` casts `struct drm_mode_rect *` directly to `struct drm_rect *`. [F218]
- In `struct drm_suballoc`, `soffset` is inclusive and `eoffset` is exclusive (`soffset + size`), so `drm_suballoc_eoffset()` returns one past the last byte and `drm_suballoc_size()` is `sa->eoffset - sa->soffset`. Also, `DRM_SUBALLOC_MAX_QUEUES` must be a power of two because `drm_suballoc_free()` indexes `sa_manager->flist` via `fence->context & (DRM_SUBALLOC_MAX_QUEUES - 1)`. [F220, F221]

## Synchronization

- `drm_syncobj.fence` must never be dereferenced directly: lockless readers must hold a `struct drm_syncobj` reference and acquire a fence reference in an RCU read-side critical section via `drm_syncobj_fence_get()` (`dma_fence_get_rcu_safe`), while updates to `fence`, `cb_list`, and `ev_fd_list` must hold `drm_syncobj.lock`. [F177]
- In `struct drm_vblank_crtc`, `last` is protected by `drm_device.vbl_lock`, `hwmode` is only valid while `enabled` is true, and `count` must be read via `drm_crtc_vblank_count()` or `drm_crtc_vblank_count_and_time()` (never raw `atomic64_read`) so `seqlock` barriers pair with `drm_crtc_handle_vblank()`. [F179, F213]
- While holding `drm_vma_offset_lock_lookup(mgr)` (`read_lock(&mgr->vm_lock)`), the caller is in atomic context, must only call locked lookup helpers (`drm_vma_offset_lookup_locked`, `drm_vma_offset_exact_lookup_locked`), and must pin any returned object's reference before `drm_vma_offset_unlock_lookup(mgr)`. Also, `drm_vma_node_unmap()` accesses `node->vm_node` unlocked, so callers must externally serialize it against `drm_vma_offset_remove()`. [F180, F181]
- `spsc_queue_push` must set `node->next = NULL` before `atomic_long_xchg(&queue->tail, (long)&node->next)` and keep preemption disabled across `atomic_long_xchg` and `WRITE_ONCE(*tail, node)`. In `spsc_queue_pop`, if `READ_ONCE(node->next)` is NULL and `atomic_long_cmpxchg(&queue->tail, (long)&node->next, (long)&queue->head)` fails, the consumer must spin with `smp_rmb()` until `READ_ONCE(node->next)` is non-NULL and store it into `queue->head` before returning `node`. [F175, F176]
- In `struct task_barrier`, `task_barrier_enter` increments `tb->count` to `tb->n` (`enter_turnstile`) and `task_barrier_exit` decrements it to `0` (`exit_turnstile`), sleeping via `down()`; both (and `task_barrier_full()`) require sleepable process context, every `enter` must pair with `exit`, and `tb->n` (`task_barrier_add_task`/`rem_task`) must not change while tasks are in the barrier. [F210, F281]
- In `struct drm_writeback_connector`, `job_lock` protects `job_queue` whereas `fence_lock` protects fences in `fence_context`. Broken by: modifying `job_queue` without `job_lock`, or using `job_lock` instead of `fence_lock` for writeback timeline fences. [F182]

## Object Lifetimes

- In `Device::release`, `core::ptr::drop_in_place` must only drop `Self` in place without freeing the backing memory, because the container is allocated by `bindings::__drm_dev_alloc` (sized via `Kmalloc::aligned_layout`) and freed by the C DRM core after `release` returns. Broken by: reconstructing a `KBox` via `KBox::from_raw` or calling `kfree` in `Device::release`. [F164]
- `AlwaysRefCounted::dec_ref` for `drm::Device<T>` and `IntoGEMObject` types must extract the raw C pointer and end the lifetime of any `&Self` reference before calling `drm_dev_put` or `drm_gem_object_put`, which may synchronously deallocate `Self`. Broken by: holding `&Self` across `drm_dev_put` or `drm_gem_object_put`. [F264]
- `File<T>::inner` and `File<T>::postclose_callback` assume `(*self.as_raw()).driver_priv` holds a valid `Pin<KBox<T>>` pointer created by `KBox::into_raw` in `File<T>::open_callback`; never call `File<T>::inner` before `open_callback` assigns `driver_priv`, after `postclose_callback` runs, or on a `drm_file` not opened by `File::<T>::open_callback`. [F265]

## API Contracts

- `drm_vma_offset_manager_init`, `drm_vma_offset_lookup_locked`, `drm_vma_offset_add`, `drm_vma_node_start`, and `drm_vma_node_size` use page-based addresses and page counts, whereas `drm_vma_node_offset_addr` returns a byte offset (`<< PAGE_SHIFT`). `drm_vma_offset_exact_lookup_locked()` must check `node->vm_node.start == start` because `drm_vma_offset_lookup_locked()` matches any node covering `[start, start + pages)`. `drm_vma_node_reset` `memset`s the node in place and must never be called before `drm_vma_offset_remove` or with active `vm_files`. [F191, F211, F243]
- `drm_rect_visible()` requires both `drm_rect_width(r) > 0` and `drm_rect_height(r) > 0`, and `drm_rect_overlap()` requires strict inequalities (`a->x2 > b->x1 && b->x2 > a->x1 && a->y2 > b->y1 && b->y2 > a->y1`). `drm_rect_downscale()` divides unconditionally by `horz` and `vert`, which must be non-zero. `drm_rect_clip_scaled`, `drm_rect_calc_hscale`, and `drm_rect_calc_vscale` require 16.16 fixed-point `src` and integer `dst`, returning `0` if `dst` size is `0`, `-EINVAL` if `src`/`dst` size is negative, or `-ERANGE` if out of bounds. [F199, F244, F248]
- `drm_crtc_set_max_vblank_count` must only be called when `dev->max_vblank_count == 0` and `vblank->inmodeset` is non-zero (before `drm_crtc_vblank_on`), and non-zero values require `drm_crtc_funcs.get_vblank_counter`. KMS drivers must call `drm_crtc_vblank_off` when disabling a CRTC and `drm_crtc_vblank_on` (or `drm_crtc_vblank_on_config`) when enabling it. [F201, F270]
- `drm_writeback_job::fb` must be set via `drm_writeback_set_fb(conn_state, fb)` (which allocates `conn_state->writeback_job` if NULL and takes a framebuffer reference via `drm_framebuffer_assign`), never assigned directly. Also, `drm_connector_to_writeback()` does an unchecked `container_of` downcast, so callers must verify `connector->connector_type == DRM_MODE_CONNECTOR_WRITEBACK` first. [F203, F257]
- When `vga_get`, `vga_get_interruptible`, or `vga_get_uninterruptible` returns `0`, the caller must release the VGA resources with a matching `vga_put(pdev, rsrc)`, and must never call `vga_put` when `vga_get*` returns a non-zero error. [F173]
- `drm_timeout_abs_to_jiffies(timeout_nsec)` takes an absolute `ktime_get()` (`CLOCK_MONOTONIC`) nanosecond timestamp (not a relative duration), returning `0` when `timeout_nsec <= 0` or in the past and clamping large values to `MAX_SCHEDULE_TIMEOUT - 1` (never negative or `MAX_SCHEDULE_TIMEOUT`). [F205]
- Any non-NULL `format_modifiers` array passed to `drm_simple_display_pipe_init()` must be terminated with `DRM_FORMAT_MOD_INVALID`. [F223]
- `EXPORT_SYMBOL_FOR_TESTS_ONLY(x)` in `include/drm/drm_util.h` only exports `x` when `CONFIG_DRM_EXPORT_FOR_TESTS` is enabled and must not be used for symbols needed by production DRM driver modules. [F295]

## Error Handling

- `drm_syncobj_find` and `drm_syncobj_fence_get` return `NULL` (never an `ERR_PTR`) when the handle is not found or has no fence bound, whereas `drm_syncobj_find_fence` returns `0` with a non-null `*fence` on success or a negative errno on failure. Broken by: checking `drm_syncobj_find` or `drm_syncobj_fence_get` with `IS_ERR`. [F196]
- `drm_vblank_work_schedule` returns `1` if newly scheduled or rescheduled, `0` if already scheduled at the same `count`, being cancelled (`work->cancelling`), or `vblank->inmodeset` is set, and `< 0` only when `drm_vblank_get` fails. Broken by: treating a non-zero return (`if (drm_vblank_work_schedule(...))`) as an error. [F200]
- `drm_get_panel_backlight_quirk` returns `ERR_PTR(-ENODATA)` or `ERR_PTR(-EINVAL)` (never `NULL`) when no quirk matches, `edid` is `NULL`, or `CONFIG_DMI` is disabled, whereas `drm_get_panel_orientation_quirk` returns `DRM_MODE_PANEL_ORIENTATION_UNKNOWN`. Broken by: checking `drm_get_panel_backlight_quirk` only for `NULL` without `IS_ERR`. [F204]

## External Contracts

- In `struct drm_mode_fb_cmd2`, `modifier[4]` is only valid when `flags & DRM_MODE_FB_MODIFIERS` is set, all used planes must have identical `modifier[i]`, and all unused plane slots in `handles`, `pitches`, `offsets`, and `modifier` must be zero. In `DRM_IOCTL_MODE_GETFB2`, `handles` are zeroed unless the caller is DRM master or has `CAP_SYS_ADMIN`, and fresh handles are allocated on each call—unlike `DRM_IOCTL_PRIME_FD_TO_HANDLE`, which deduplicates handles on a `drm_file`; since GEM handles are not refcounted, `DRM_IOCTL_GEM_CLOSE` must be called once per unique handle. [F174, F207, F225]
- FourCC modifiers (`include/uapi/drm/drm_fourcc.h`) pack the 8-bit `DRM_FORMAT_MOD_VENDOR_*` in bits 63:56 and 56-bit value in bits 55:0 via `fourcc_mod_code(vendor, val)`, with reserved bits (e.g., bits 55:36 of `AMD_FMT_MOD`) zeroed; modifiers must uniquely identify a layout without aliasing or encoding pitch-alignment subsets, and `DRM_FORMAT_MOD_GENERIC_*` aliases must match the original numerical value. In `struct drm_format_modifier`, bit `b` of `formats` corresponds to plane format index `offset + b`. [F228, F232, F294]
- In `include/uapi/drm/virtgpu_drm.h` and DRM UAPI ioctl structs, user pointers must be `__u64` and all fields must be naturally aligned with explicit padding (`pad`/`__pad`) for 32/64-bit compatibility. Modeset-mutating ioctls must set `drm::ioctl::MASTER` (`DRM_MASTER`), and render-only ioctls on render-node drivers must set `drm::ioctl::RENDER_ALLOW` (`DRM_RENDER_ALLOW`). [F224, F293]
- In `struct drm_mode_get_plane`, bit `N` of `possible_crtcs` is the 0-based `drm_crtc_index()` `N` (not a KMS object ID), and `pipe` in `struct drm_pending_vblank_event` and `struct drm_vblank_crtc` is also the 0-based `drm_crtc_index()`. [F227]
- In `struct drm_mode_fb_dirty_cmd`, when `DRM_MODE_FB_DIRTY_ANNOTATE_COPY` is set in `flags`, `clips_ptr` holds paired source/destination rects (`num_clips / 2` regions, even `num_clips <= DRM_MODE_FB_DIRTY_MAX_CLIPS` (256)). [F229]
- In `include/uapi/drm/drm_mode.h`, `drm_mode_modeinfo::flags` bits 0–13 (`DRM_MODE_FLAG_PHSYNC`..`DRM_MODE_FLAG_CLKDIV2`) must match XRandR `RR_*` bits and new mode flags require a `DRM_CLIENT_CAP_*` gate; `drm_color_ctm::matrix` uses 64-bit S31.32 sign-magnitude format (bit 63 sign, bits 62:0 unsigned magnitude), not two's complement. [F233, F234]

## Known Pitfalls

- `struct drm_rect` stores inclusive `(x1, y1)` and exclusive `(x2, y2)`, whereas `DRM_RECT_INIT` and `drm_rect_init` take `(x, y, width, height)` (`x2 = x + width`, `y2 = y + height`). `drm_rect_fp_to_int()` must compute `dst->x2` and `dst->y2` as `(src->x1 >> 16) + (drm_rect_width(src) >> 16)` (not `src->x2 >> 16`). `DRM_RECT_FMT` pairs with `DRM_RECT_ARG(r)` (4 ints, width/height before `x1`/`y1`) for integer rects, while `DRM_RECT_FP_FMT` pairs with `DRM_RECT_FP_ARG(r)` (8 ints) for 16.16 fixed-point rects. [F198, F249, F258]
- In `include/uapi/drm/omap_drm.h`, `drm_omap_gem_new::size` is `size.tiled` when `flags & OMAP_BO_TILED_MASK` is non-zero and `size.bytes` otherwise. Because `OMAP_BO_TILED_32` (`0x300`) equals `OMAP_BO_TILED_8 | OMAP_BO_TILED_16` and `OMAP_BO_CACHED` is `0`, always mask `flags` with `OMAP_BO_TILED_MASK` or `OMAP_BO_CACHE_MASK` and compare for equality rather than testing individual bits. [F206, F241]
- `drm_fourcc_canonicalize_nvidia_format_mod()` must check `!(modifier & 0x10) || (modifier & (0xff << 12))` (requiring bit `0x10` set and the full 8-bit page-kind field zero) before ORing `0xfe << 12`. For Broadcom modifiers, `fourcc_mod_broadcom_mod(m)` clears bits `[55:8]` and `fourcc_mod_broadcom_param(m)` casts bits `[55:8]` to `int`, so base `val` must be `<= 0xff` and `params` must fit in `int`. [F240, F247]
- In `include/uapi/drm/drm_mode.h`, extended property types (`DRM_MODE_PROP_OBJECT`, `DRM_MODE_PROP_SIGNED_RANGE`) are integer IDs shifted into `DRM_MODE_PROP_EXTENDED_TYPE` (`0x0000ffc0`), so checks must use `(flags & DRM_MODE_PROP_EXTENDED_TYPE) == DRM_MODE_PROP_OBJECT` instead of a bitwise AND. [F242]
- Never use `drm_can_sleep()` (`include/drm/drm_util.h`) in new code because its `in_atomic()` check does not reliably detect all atomic contexts. [F282]
