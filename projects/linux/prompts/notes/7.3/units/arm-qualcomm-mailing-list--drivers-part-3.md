# ARM/QUALCOMM MAILING LIST — drivers (part 3)

This component contains Qualcomm PHY drivers for USB (QMP USB-C, QUSB2, Synopsys Femto v2, 28nm HS, HSIC, SS), PCIe (28lp UniPHY), and Ethernet (SGMII), plus power reset (`msm-poweroff`, `qcom-pon`) and power supply/charger drivers (`qcom_battmgr`, `qcom_smbb`).

## Architecture & Data Flow
- In `qusb2_phy_init`, `qphy->has_se_clk_scheme` is set from `cfg->se_clk_scheme_default` and `qphy->tcsr`; `qphy->ref_clk` must be prepared/enabled in `qusb2_phy_init` and `qusb2_phy_runtime_resume` and disabled/unprepared in `qusb2_phy_exit`, `qusb2_phy_runtime_suspend`, and `qusb2_phy_init`'s `disable_ref_clk` error path iff `!qphy->has_se_clk_scheme`. `qusb2_phy_init` must unwind resources in reverse order (`disable_ref_clk`, `assert_phy_reset`, `disable_ahb_clk`, `disable_iface_clk`, `poweroff_phy`) and set `qphy->phy_initialized = true` only after `QUSB2PHY_PLL_STATUS` lock succeeds. [F201, F237]
- In `qusb2_phy_init`, when `cfg->has_pll_test` is true, sample post-reset `QUSB2PHY_PLL_TEST` into `val` before `qcom_qusb2_phy_configure` and keep it until `CLK_REF_SEL` is updated and written back after `qphy->has_se_clk_scheme` is set. Run `qcom_qusb2_phy_configure` (full writes to `QUSB2PHY_PORT_TUNE1`/`QUSB2PHY_PORT_TUNE2`) before `qusb2_phy_override_phy_params` and `qusb2_phy_set_tune2_param` (masked updates). In `qusb2_phy_set_tune2_param`, shift non-zero `hstx_trim` by `HSTX_TRIM_SHIFT` into `HSTX_TRIM_MASK` of `QUSB2PHY_PORT_TUNE1` if `cfg->update_tune1_with_efuse`, else `QUSB2PHY_PORT_TUNE2`. [F238, F239, F289]
- In `phy-qcom-qusb2.c`, `qusb2_phy_init_tbl` entries using `QUSB2_PHY_INIT_CFG_L` (`in_layout = 1`) use `offset` as an `enum qusb2phy_reg_layout` index into `cfg->regs[]` (which must be populated in the SoC's `regs` array), whereas `QUSB2_PHY_INIT_CFG` (`in_layout = 0`) uses `offset` as a raw byte offset. [F253]
- Runtime PM callbacks in `phy-qcom-qmp-usbc.c` (`!qmp->phy->init_count`), `phy-qcom-qusb2.c` (`!qphy->phy_initialized`), and `phy-qcom-snps-femto-v2.c` (`!hsphy->phy_initialized`) must return 0 immediately without touching clocks or MMIO registers when the PHY is uninitialized. [F297]
- In `phy-qcom-snps-femto-v2.c`, `qcom_snps_hsphy_probe` must set `hsphy->phy = generic_phy` and `dev_set_drvdata(dev, hsphy)` before `qcom_snps_hsphy_read_override_param_seq(dev)`. Any `override_param_map` table (e.g., `sc7280_snps_7nm_phy`) must end with a `{}` (`prop_name == NULL`) sentinel, have `<= NUM_HSPHY_TUNING_PARAMS` entries, and each entry needs `table_size >= 1`, non-zero `param_mask`, and `reg_val << __ffs(param_mask)` fitting in `u8` (`seq_entry->value`). [F240, F274, F280]
- In `qcom_snps_hsphy_por_reset` (`phy-qcom-usb-hs-28nm.c`), call `qcom_snps_hsphy_exit_retention` (clearing `SIDDQ` in `PHY_CTRL_COMMON0`) after `reset_control_assert(priv->por_reset)` and before `reset_control_deassert(priv->por_reset)`. [F241]
- `qcom_usb_hs_phy_probe()` must allocate `(size / 2) + 1` elements for `uphy->init_seq` and zero `uphy->init_seq[size / 2].addr`, as `qcom_usb_hs_phy_power_on()` loops until `seq->addr == 0` and adds `ULPI_EXT_VENDOR_SPECIFIC` to each `seq->addr`. When `uphy->vbus_edev` is set, `qcom_usb_hs_phy_power_on` must also query `EXTCON_USB` via `extcon_get_state` and seed `ULPI_MISC_A_VBUSVLDEXT` via `qcom_usb_hs_phy_vbus_notifier` alongside registering `uphy->vbus_notify`. [F243, F254]
- In `phy-qcom-usb-ss.c`, when `priv->reset_com` is non-NULL, `qcom_ssphy_init_reset` requires `priv->reset_phy` to be non-NULL too, and `qcom_ssphy_do_reset` asserts/deasserts both reset controls instead of toggling `PHY_RESET` in `PHY_CTRL1`. [F220]
- In `qcom_uniphy_pcie_init`, per-lane programming must advance a local `base` pointer by `data->lane_offset` across `phy->lanes` iterations without modifying `phy->base`, keeping `phy->base` at lane 0 for `qcom_uniphy_pcie_power_on`. [F244]
- In `qcom-pon.c`, `qcom_pon_reboot_mode_write()` updates 8-bit `PON_SOFT_RB_SPARE` with `GENMASK(7, pon->reason_shift)` and `magic << pon->reason_shift`, so `qcom_pon_id_table` match data must be in `1..7` (or `NO_REASON_SHIFT` `0` to skip reboot-mode registration). [F258]
- In `qcom_battmgr_request`, run `reinit_completion(&battmgr->ack)` and `battmgr->error = 0` before `pmic_glink_send`. In `qcom_battmgr_notification`, `NOTIF_BAT_INFO` must set `battmgr->info.valid = false` before `power_supply_changed(battmgr->bat_psy)` so `qcom_battmgr_bat_sc8280xp_update` re-fetches `BATTMGR_BAT_INFO` and refreshes `battmgr->unit` and `battmgr->info.last_full_capacity`. [F229, F232]
- In `qcom_battmgr_sc8280xp_callback`, compute `battmgr->status.percent` from unscaled `100 * le32_to_cpu(resp->status.capacity)` divided by `battmgr->info.last_full_capacity / 1000` (avoiding 32-bit overflow on `100 * battmgr->status.capacity`); first check `battmgr->info.last_full_capacity` is non-zero (and a multiple of 1000), storing `(unsigned int)-1` in `battmgr->status.percent` when zero so `qcom_battmgr_bat_get_property` returns `-ENODATA`. [F270, F271]
- In `qcom_smbb.c`, `ATTR_BAT_ISAFE`/`ATTR_BAT_VSAFE` must precede `ATTR_BAT_IMAX`/`ATTR_BAT_VMAX` in `enum smbb_attr`, and `smbb_charger_attr_parse` must fall back to `smbb_charger_attr_read` when a `.fail_ok = 1` write fails, because `smbb_charger_attr_write` clamps `IMAX`/`VMAX` against `prop->safe_reg`. Both `smbb_charger_attr_write` and `smbb_charger_attr_read` must update `chg->attr[which]` via `prop->hw_fn`, as `.get_property` callbacks serve `chg->attr` directly. [F226, F234]
- Every `hw_fn` in `smbb_charger_attrs[]` must be strictly monotonically increasing with `index`, and `smbb_charger_attr_write` must validate `val` in `[prop->min, prop->max]` (`-EINVAL` if outside) and clamp to `prop->safe_reg` before calling `smbb_hw_lookup()`, which increments `widx` from `0` unbounded until `(*fn)(widx) > val`. [F255, F308]

## Synchronization
- In `qcom_battmgr_probe()`, initialize `battmgr->enable_work`, `battmgr->lock`, `battmgr->ack`, `bat_psy`, `usb_psy`, `wls_psy`, and `battmgr->client` (`devm_pmic_glink_client_alloc()`) before `pmic_glink_client_register()`. All property request paths in `qcom_battmgr.c` must hold `battmgr->lock` across `qcom_battmgr_request()` (and its `request_property`/`update_*`/`set_charge_control` wrappers), as concurrent requests share `battmgr->ack` and hang firmware. [F207, F208]
- `qcom_battmgr_callback` and its callees (`qcom_battmgr_notification`, `qcom_battmgr_sc8280xp_callback`, `qcom_battmgr_sm8350_callback`) run under `spin_lock_irqsave(&pg->client_lock, flags)` while a requester holds `battmgr->lock` waiting on `battmgr->ack`, so they must not sleep or acquire `battmgr->lock`. `qcom_battmgr_pdr_notify` runs under `pg->state_lock` and `pg->client_lock` with IRQs disabled, so it must not sleep or call `qcom_battmgr_request`/`pmic_glink_send` directly and must schedule `battmgr->enable_work`. [F298, F299]
- In `qcom_smbb.c`, hold `chg->statlock` when modifying `chg->status` (`smbb_set_line_flag()`, `smbb_bat_temp_handler()`) and reading it in `.get_property` callbacks (`smbb_usbin_get_property()`, `smbb_dcin_get_property()`, `smbb_battery_get_property()`). All `smbb_charger_irqs` handlers lock `chg->statlock` or call sleeping `regmap_read`, so they must run in threaded IRQ (`devm_request_threaded_irq` `thread_fn`) or process context, and `smbb_charger_probe()` must initialize/register `chg->statlock`, `bat_psy`, `usb_psy`, `edev`, and `dc_psy` before invoking or registering them. [F210, F211, F301]
- `do_msm_poweroff` (`msm-poweroff.c`) runs in atomic `SYS_OFF_MODE_RESTART` / `SYS_OFF_MODE_POWER_OFF` context and must use `mdelay` rather than sleeping delays or mutexes after asserting `msm_ps_hold`. [F302]

## Object Lifetimes
- In `qusb2_phy_set_tune2_param`, the buffer from `nvmem_cell_read(qphy->cell, NULL)` is caller-owned heap memory and must be freed with `kfree(val)` on all paths, including when `hstx_trim` (`val[0]`) is zero. [F196]
- In `phy-qcom-qmp-usbc.c`, `phy_pipe_clk_register` (`of_clk_add_hw_provider`) and `qmp_usbc_typec_switch_register` (`typec_switch_register`) must immediately attach `devm_add_action_or_reset` (`phy_clk_release_provider` / `qmp_usbc_typec_unregister`) with no fallible steps in between; guard `qmp_usbc_typec_switch_register` with `#if IS_ENABLED(CONFIG_TYPEC)` and a `return 0;` stub when disabled. [F199, F309]

## API Contracts
- `qusb2_write_mask(base, offset, val, mask)` takes pre-shifted `val` third and `mask` fourth, whereas `qcom_snps_hsphy_write_mask(base, offset, mask, val)` takes `mask` third and pre-shifted `val` fourth. Both helpers, plus `qphy_setbits`/`qphy_clrbits` (`phy-qcom-qmp-usbc.c`) and `qusb2_setbits`/`qusb2_clrbits` (`phy-qcom-qusb2.c`), follow each MMIO write with a readback of the same offset to flush posted writes. [F215, F293]
- `qmp_configure_lane()` filters `qmp_phy_init_tbl` entries via `t->lane_mask & lane_mask`, so callers like `qmp_usbc_power_on()` must pass bitmasks `1` (`BIT(0)`) for lane 0 and `2` (`BIT(1)`) for lane 1, not 0-based indices. [F257]
- In `phy-qcom-qmp-usbc.c`, clearing autonomous-mode IRQs in `qmp_usbc_enable_autonomous_mode` / `qmp_usbc_disable_autonomous_mode` requires setting `IRQ_CLEAR` in `QPHY_PCS_LFPS_RXTERM_IRQ_CLEAR` via `qphy_setbits` then clearing it via `qphy_clrbits`. Similarly, in `qusb2_phy_runtime_suspend` (`phy-qcom-qusb2.c`), enable auto-resume only when `qphy->mode != PHY_MODE_INVALID` by setting `cfg->autoresume_en` in `QUSB2PHY_PORT_TEST1` via `qusb2_setbits` then clearing it via `qusb2_clrbits`. [F294, F295]
- In `qcom_battmgr_bat_get_property`, `POWER_SUPPLY_PROP_CHARGE_*` must return `-ENODATA` when `unit != QCOM_BATTMGR_UNIT_mAh` and `POWER_SUPPLY_PROP_ENERGY_*` when `unit != QCOM_BATTMGR_UNIT_mWh`. In `qcom_battmgr_sc8280xp_callback`, multiply firmware capacity, rate, and voltage fields in `resp->info` and `resp->status` (mWh/mAh, mW, mV) by `1000` to match `power_supply` micro-units (`uWh`/`uAh`, `uW`, `uV`). [F223, F305]

## Error Handling
- In `qusb2_phy_probe` and `qcom_usb_hs_phy_probe`, optional handles (`qphy->tcsr`, `qphy->cell`, `uphy->reset`, `uphy->vbus_edev`) must be cleared to `NULL` on ignored `IS_ERR` returns so runtime NULL checks do not dereference an `ERR_PTR`. [F202]
- In `qcom_snps_hsphy_probe` (`phy-qcom-usb-hs-28nm.c`), if `regulator_set_load` on `priv->vregs[VDDA_3P3]` fails, jump to `unset_1p8_load` to reset `priv->vregs[VDDA_1P8]` load to `0`. In `phy-qcom-usb-hs.c`, `qcom_usb_hs_phy_power_on` (`ref_clk`, `sleep_clk`, `v1p8`, `v3p3`, `vbus_notify`) and `qcom_usb_hs_phy_power_off` / `err_ulpi`..`err_sleep` must tear down resources in symmetric reverse order. [F203, F204]
- In `qmp_usbc_parse_vls_clamp`, a missing `"qcom,tcsr-reg"` (`-ENOENT`) leaves `qmp->tcsr_map` NULL and `qmp->vls_clamp_reg` 0, so `qmp_usbc_enable_autonomous_mode` and `qmp_usbc_disable_autonomous_mode` must check `if (qmp->tcsr_map && qmp->vls_clamp_reg)` before calling `regmap_write`. [F214]
- In `qcom_battmgr.c`, every `power_supply` `get_property`/`set_property` callback must return `-EAGAIN` when `!battmgr->service_up` before sending any GLINK request. In `qcom_battmgr_sm8350_callback()`, integer property responses (`BATTMGR_*_PROPERTY_GET`) must check `resp->intval.result` and jump to `out_complete` (`complete(&battmgr->ack)`) before `switch (property)` when `battmgr->error` is non-zero. [F222, F261]
- In `qcom_battmgr_charge_control_thresholds_init()`, reject `delta_soc >= end_soc` before computing `u8` `start_soc = end_soc - delta_soc`, and clamp both thresholds to `[CHARGE_CTRL_START_THR_MIN, CHARGE_CTRL_START_THR_MAX]` and `[CHARGE_CTRL_END_THR_MIN, CHARGE_CTRL_END_THR_MAX]`. [F250]
- In `qcom_smbb.c`, `chg->dc_psy` is NULL when `chg->dc_disabled` (`"qcom,disable-dc"`), so `smbb_dc_valid_handler` and `smbb_chg_gone_handler` must check `if (!chg->dc_disabled)` before calling `power_supply_changed(chg->dc_psy)`. [F227]

## External Contracts
- In `struct qcom_battmgr_message`, `strval` places `model[BATTMGR_STRING_LEN]` at `intval.value` and omits `intval.result`, so `qcom_battmgr_sm8350_callback()` must check `payload_len == sizeof(resp->strval)` and skip `resp->intval.result` for string properties like `BATT_MODEL_NAME`. [F245]
- In `qcom_battmgr_sc8280xp_callback()`, `BATTMGR_BAT_INFO` length validation must accept both `sizeof(resp->info)` and `sizeof(resp->info) + sizeof(__le32)`. Copy `resp->info` strings (`model_number`, `serial_number`, `oem_info`) via `qcom_battmgr_sc8280xp_strcpy()`, which handles Pascal strings and copies up to `BATTMGR_STRING_LEN` (128) bytes without a size argument (both `qcom_battmgr_info` and `qcom_battmgr_message` string buffers must be `>= BATTMGR_STRING_LEN` bytes). [F246, F247, F276]

## Known Pitfalls
- In `qmp_usbc_power_on()`, `readl_poll_timeout()` on `QPHY_PCS_STATUS` must poll for `!(val & PHYSTATUS)` (active-low busy bit cleared), unlike `qcom_dwmac_sgmii_phy_poll_status()` and `qusb2_phy_init()` which poll active-high ready bits. [F263]
- In `qcom_battmgr_probe`, `QCOM_BATTMGR_SC8280XP` has enum value `0` (`NULL` in `qcom_battmgr_of_variants[].data`) while unmatched parents default to `QCOM_BATTMGR_SM8350` (`1`), so use `of_match_device(qcom_battmgr_of_variants, dev->parent)` rather than `of_device_get_match_data` / `device_get_match_data`. [F221]
- Every property in `sm8350_bat_props`, `sm8550_bat_props`, `sm8350_usb_props`, or `sm8350_wls_props` must have a matching entry in `sm8350_*_prop_map` and a case in `qcom_battmgr_sm8350_callback`, because unmapped slots zero-initialize to `0` (`BATT_STATUS`, `USB_ONLINE`, `WLS_ONLINE`). [F231]
- In `qcom_smbb.c`, `smbb_charger_probe()` sets `chg->revision` (`1..3`) to `SMBB_MISC_REV2 + 1` and skips `smbb_charger_setup[]` entries when `r->rev_mask & BIT(chg->revision)` is non-zero (`rev_mask` uses 1-based revision bits to skip). In `smbb_battery_get_property()`, `POWER_SUPPLY_PROP_HEALTH` must check `status & STATUS_BAT_OK` before `status & STATUS_BAT_HOT`, as `smbb_bat_temp_handler()` never clears `STATUS_BAT_HOT` when `TEMP_STATUS_OK` is restored. [F256, F268]
