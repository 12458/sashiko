# MELLANOX MLX5 core VPI driver — drivers/net/ethernet/mellanox/mlx5/core/lib

`drivers/net/ethernet/mellanox/mlx5/core/lib` provides shared hardware abstractions across the mlx5 core, Ethernet (`mlx5e`), E-Switch, and RDMA (`mlx5_ib`) drivers: PTP clock/PPS (`clock.c`), cross-function communication (`devcom.c`), Socket-Direct (`sd.c`), flow steering chains and TTC (`fs_chains.c`, `fs_ttc.c`, `smfs.c`), MACsec and RoCE IPsec steering (`macsec_fs.c`, `ipsec_fs_roce.c`), bulk DEK pools (`crypto.c`), ASO WQEs (`aso.c`), device memory ICM (`dm.c`), L2 MPFS (`mpfs.c`), tunnel ports/entropy (`vxlan.c`, `geneve.c`, `port_tun.c`), PCI VSC (`pci_vsc.c`), and NVRAM parameters (`nv_param.c`).

## Architecture & Data Flow

- Every mutation of `struct mlx5_crypto_dek_bulk` key counts (`num_deks`, `avail_deks`, `in_use_deks`) must update `struct mlx5_crypto_dek_pool` counters by the same delta under `pool->lock`. In `bulk`, a DEK bit in `need_sync` must stay set when `mlx5_crypto_dek_free_locked` clears `in_use` and only clear after `mlx5_crypto_cmd_sync_crypto` succeeds in `mlx5_crypto_dek_sync_work_fn`, and bits at indices `>= bulk->num_deks` in `need_sync` and `in_use` must remain zero for `hweight_long((*need_sync) ^ (*in_use))` in `mlx5_crypto_dek_bulk_reset_synced`. [F1478, F1479, F1542]
- When `struct mlx5_crypto_dek_bulk` moves between `avail_list`, `partial_list`, `full_list`, and `sync_list` or is revalidated in `mlx5_crypto_dek_bulk_reset_synced` / `mlx5_crypto_dek_pool_reset_synced`, `bulk->avail_start` must be updated to `<=` the lowest zero bit in `bulk->need_sync`. `mlx5_crypto_dek_pool_reset_synced` must iterate `partial_list`, `full_list`, and `sync_list` with `list_for_each_entry_safe` before calling `mlx5_crypto_dek_pool_free_wait_keys(pool)`. [F1481, F1521]
- In `mlx5_crypto_dek_fill_key`, a 128-bit key (`sz_bytes == 16`) must be copied to `MLX5_ADDR_OF(encryption_key_obj, key_obj, key[1])` because the upper 128 bits (`key[0]`) are reserved. [F1503]
- In `port_tun.c`, `mlx5_set_port_tun_entropy_calc` and `mlx5_set_port_gre_tun_entropy_calc` must query `MLX5_REG_PCMR` via `mlx5_query_ports_check` before modifying bits. In `mlx5_set_entropy`, disabling global `entropy_calc` must be rejected when `tun_entropy->num_enabling_entries != 0`, and `entropy_flags.gre_calc_supported && reformat_type == MLX5_REFORMAT_TYPE_L2_TO_NVGRE` must be checked before `entropy_flags.calc_supported`. [F1489, F1525]
- In `gid.c`, `mlx5_core_reserve_gids` and `mlx5_core_unreserve_gids` must adjust `dev->roce.reserved_gids.start` and `count` in opposite directions by the same delta so `start + count == MLX5_CAP_ROCE(dev, roce_address_table_size)`. [F1497]
- In `set_l2table_entry_cmd` (`mpfs.c`), the 6-byte MAC address must be copied to `&in_mac_addr[2]` past the 2-byte reserved prefix in `struct mlx5_ifc_mac_address_layout_bits`. [F1507]
- In `clock.c`/`clock.h`, hardware real-time timestamps pack 32-bit seconds above 32-bit nsec: `mlx5_ptp_settime_real_time` and `mlx5_perout_configure` (real-time mode) must reject `seconds > U32_MAX`, and `mlx5_ptp_freq_adj_real_time` must fall back to PPB when `scaled_ppm` is outside `[S32_MIN, S32_MAX]`. Combining 32-bit words (`timer_h1`/`timer_l` or `sec`/`nsec`) in `mlx5_read_time`, `perout_conf_real_time`, and `REAL_TIME_TO_NS` requires casting both operands to `u64` before `<< 32` or `* NSEC_PER_SEC`. [F1510, F1531]
- 64-bit divisions in `clock.c` (`find_target_cycles`, `mlx5_init_overflow_period`) and `dm.c` (`mlx5_dm_sw_icm_alloc`, `mlx5_dm_sw_icm_dealloc`) must use `div64_u64`/`div_u64`/`do_div`/`DIV_ROUND_UP_ULL`, not `/`. In `mlx5_dm_sw_icm_alloc`, `block_idx` must be `u64` before `block_idx << MLX5_LOG_SW_ICM_BLOCK_SIZE(dev)`. [F1533, F1538]
- In `macsec_fs.h`, `MLX5_MACEC_RX_FS_ID_MAX` (`0xffff`) is both the inclusive max RX `fs_id` and `MLX5_MACSEC_RX_FS_ID_MASK` in `MLX5_MACSEC_RX_METADAT_HANDLE`, so it must be `2^N - 1`. In `macsec_fs_rx_setup_fte`, big-endian `attrs->sci` requires `be32_to_cpu()` on its 32-bit words when `sci_present` is true, or copying its first `ETH_ALEN` bytes directly to `outer_headers.smac_47_16` when false. [F1512, F1513]
- In `fs_ttc.c`, `ttc_rules[]` is sized only up to `MLX5_TT_ANY`, so `0 <= tt < MLX5_NUM_TT` loops in `mlx5_generate_ttc_table_rules` and `mlx5_generate_inner_ttc_table_rules` must skip `mlx5_ttc_is_decrypted_esp_tt(tt)` before indexing `ttc_rules[tt]`. [F1514]

## Synchronization

- Updates to `clock->timer.tc`, `clock->timer.cycles.mult`, `clock->pps_info.start`, and calls to `mlx5_update_clock_info_page` must hold `write_seqlock_irqsave(&clock->lock, flags)` (never IRQ-enabled `write_seqlock`), while `mlx5_timecounter_cyc2time` uses `read_seqbegin`/`read_seqretry`. `mlx5_update_clock_info_page` must bracket `mdev->clock_info` writes by setting `MLX5_IB_CLOCK_INFO_KERNEL_UPDATING` on `clock_info->sign` with `smp_store_mb` and advancing `sign` with `smp_store_release`. [F1444, F1445]
- When `clock->shared` is true, `mlx5_clock_mdev_get(clock)` and accesses to `clock_priv(clock)->mdev` and `event_mdev` require `mlx5_clock_lock(clock)` (`clock_priv(clock)->lock`), which nests inside `mlx5_devcom_comp_lock(mdev->clock_state->compdev)` and outside `clock->lock`. [F1446]
- `mlx5_devcom_get_next_peer_data` and `mlx5_devcom_for_each_peer_entry` require holding `devcom->comp->sem` (`mlx5_devcom_for_each_peer_begin` or `mlx5_devcom_comp_lock`), whereas `_rcu` variants require `rcu_read_lock()`. When `attr->flags & MLX5_DEVCOM_MATCH_FLAGS_NS` is set in `mlx5_devcom_register_component`, `devcom_component_equal` only pairs devices with matching `net_eq(attr->net, read_pnet(&devcom->key.net))`. [F1449, F1596]
- Access to `pool->destroy_list` between `mlx5_crypto_dek_pool_reset_synced` (under `pool->lock`) and `mlx5_crypto_dek_destroy_work_fn` (without `pool->lock`) must be serialized by `pool->destroy_lock` via `mlx5_crypto_dek_pool_splice_destroy_list`. [F1453]
- `mlx5_vsc_gw_lock` must take `pci_cfg_access_lock(dev->pdev)` before polling/locking `VSC_SEMAPHORE_OFFSET` (unlocking on every error path), and `mlx5_vsc_gw_unlock` must write `MLX5_VSC_UNLOCK` to `VSC_SEMAPHORE_OFFSET` before `pci_cfg_access_unlock(dev->pdev)`. [F1461]
- In `mlx5_aso_post_wqe`, `dma_wmb()` must precede `*aso->wq.db = cpu_to_be32(aso->pc)` and `wmb()` must precede `mlx5_write64((__be32 *)doorbell_cseg, aso->uar_map)`. In `eq_update_ci`, `__raw_writel` to `eq->doorbell + (arm ? 0 : 2)` must be followed by `wmb()`. [F1549, F1552]

## Object Lifetimes

- In `mlx5_chains_get_table`, when `level > 0`, references to levels `0 .. level - 1` must be acquired recursively before taking `chains_lock(chains)` for `level` and released in reverse via `mlx5_chains_put_table` on failure, matching `mlx5_chains_put_table` which decrements `level` first and puts `level - 1 .. 0`. [F1418]
- `mlx5_chains_create_prio` gets `chain_s` via `mlx5_chains_get_chain`, creates `ft`, `miss_group`, and `miss_rule`, inserts `prio_s` into `prios_ht` and `chain_s->prios_list`, and calls `mlx5_chains_update_prio_prevs`; its error paths and `mlx5_chains_destroy_prio` must tear these down in reverse order ending with `mlx5_chains_put_chain`. [F1420]
- `destroy_chain_restore` gates all cleanup (`restore_rule`, `miss_modify_hdr`, `chains_mapping`) on `if (!chain->miss_modify_hdr) return;`, so `create_chain_restore` must roll back `chain->restore_rule` and `chain->id` if `mlx5_modify_header_alloc` fails. [F1421]
- `mlx5_dm_sw_icm_alloc` reserves `num_blocks` in `block_map` under `dm->lock` before `mlx5_cmd_exec` and clears them on failure; `mlx5_dm_sw_icm_dealloc` must run `MLX5_CMD_OP_DESTROY_GENERAL_OBJECT` first and only clear `block_map` if `mlx5_cmd_exec` succeeds. [F1427]
- `macsec_fs_tx_add_rule` and `macsec_fs_rx_add_rule` must balance `macsec_fs_tx_ft_get` / `macsec_fs_rx_ft_get` on every error path via `ft_put` or `del_rule` because `macsec_fs_tx_cleanup` / `rx_cleanup` abort if `tables->refcnt != 0`. [F1430]
- When `refcount_dec_and_test(&fs_id_found->refcnt)` holds in `macsec_fs_id_del`, `fs_id_found->hash` must be removed from `hash_table` and `fs_id_found->id` zeroed under `xa_lock(fs_id_xa)` before unlocking, calling `xa_erase`, freeing `fs_id_found`, and freeing `macsec_device` if `macsec_fs_is_macsec_device_empty` holds. [F1431]
- `mlx5_macsec_fs_add_rule` fires `MLX5_DRIVER_EVENT_MACSEC_SA_ADDED` on `mdev->macsec_nh` only after `macsec_fs_tx/rx_add_rule` succeeds, whereas `mlx5_macsec_fs_del_rule` fires `MLX5_DRIVER_EVENT_MACSEC_SA_DELETED` before `macsec_fs_tx/rx_del_rule`. Callbacks on `mdev->macsec_nh` must not retain the stack-allocated `struct mlx5_macsec_event_data *` after returning. [F1460, F1547]
- When `!MLX5_CAP_GEN(mdev, device_frequency_khz)`, `mlx5_init_clock` sets `mdev->clock = &null_clock` and `mdev->clock_state = NULL`, so `mlx5_clock_load`, `mlx5_clock_unload`, and `mlx5_cleanup_clock` must return early on `!MLX5_CAP_GEN(mdev, device_frequency_khz)`. In `mlx5_clock_unload` and `mlx5_shared_clock_unregister`, PPS-in events must be disarmed (or, if `clock->shared`, `cpriv->event_mdev` and `cpriv->mdev` migrated to a surviving peer under `compdev` and `clock` locks, calling `mlx5_clock_free` only when no peer remains) and `pps_nb` unregistered via `mlx5_eq_notifier_unregister` before `cancel_work_sync(&clock_state->out_work)`. [F1436, F1437, F1557]
- `mlx5_vxlan_del_port` must call `hash_del_rcu(&vxlanp->hlist)` and `synchronize_rcu()` before freeing `vxlanp` under `vxlan->sync_lock`, and `mlx5_vxlan_reset_to_default` must skip `IANA_VXLAN_UDP_PORT` (only removed by `mlx5_vxlan_destroy`). [F1438]
- In `mlx5_crypto_dek_pool_destroy`, `cancel_work_sync(&pool->sync_work)` must precede `cancel_work_sync(&pool->destroy_work)`, and both must finish before draining `wait_for_free`, removing bulks, or freeing `destroy_list`. [F1452]
- `mlx5_hv_vhca_agent_create` must initialize all `struct mlx5_hv_vhca_agent` fields/callbacks before setting `hv_vhca->agents[type] = agent` under `agents_lock`, and `mlx5_hv_vhca_agent_destroy` must clear `hv_vhca->agents[agent->type]` under `agents_lock` before `agent->cleanup(agent)` and `kfree(agent)`. [F1455]
- `mlx5_uplink_netdev_get(mdev)` takes a tracked reference on `mdev->mlx5e_res.uplink_netdev` via `netdev_hold` under `uplink_netdev_lock` that must be released via `mlx5_uplink_netdev_put(mdev, netdev)`, not `dev_put`. [F1597]

## API Contracts

- `mlx5_crypto_dek_pool_push` takes ownership of `dek` on every path (deferring on `pool->wait_for_free` or freeing via `mlx5_crypto_dek_free_locked`), so callers like `mlx5_crypto_dek_create` must never `kfree(dek)` after calling it. `mlx5_crypto_dek_init` returns `NULL` when `!MLX5_CAP_CRYPTO(mdev, log_dek_max_alloc)` (fallback mode tested via `!dek_priv` in `mlx5_crypto_dek_create`/`destroy`) and `ERR_PTR` on error, so callers must check `IS_ERR` and reset `dek_priv` to `NULL` on failure. [F1422, F1463]
- `mlx5_aso_get_wqe`, `mlx5_aso_build_wqe`, `mlx5_aso_post_wqe`, and `mlx5_aso_poll_cq` have no internal locking on `struct mlx5_aso`; callers sharing an instance must externally lock the full post-and-poll cycle. `mlx5_aso_get_wqe` only zeroes `sizeof(struct mlx5_aso_wqe)` (64B), so `with_data == true` callers must zero the trailing `aso_data` segment and call `mlx5_aso_build_wqe` before `mlx5_aso_post_wqe`. In `mlx5_aso_poll_cq`, `aso->cc` must be updated only after `mlx5_cqwq_pop(&cq->wq)`, `mlx5_cqwq_update_db_record(&cq->wq)`, and `wmb()`, using the same `with_data` increment (`MLX5_ASO_WQEBBS_DATA` vs `MLX5_ASO_WQEBBS`) passed to `mlx5_aso_post_wqe`. [F1443, F1473, F1484]
- In `pci_vsc.c`, `mlx5_vsc_gw_write` must write `VSC_DATA_OFFSET` before writing `VSC_ADDR_OFFSET` with bit 31 (`VSC_FLAG_BIT_OFFS`) set and polling `mlx5_vsc_wait_on_flag(dev, 0)`, whereas `mlx5_vsc_gw_read` writes `VSC_ADDR_OFFSET` with bit 31 cleared, waits via `mlx5_vsc_wait_on_flag(dev, 1)`, then reads `VSC_DATA_OFFSET`. `mlx5_vsc_gw_read_block_fast` returns the non-negative byte offset `read_addr` read so far (`< length` on failure, `length` on full success), so callers must check `ret != length`, not `ret < 0`. [F1464, F1506, F1554]
- `mlx5_macsec_fs_add_rule` and `mlx5_macsec_fs_del_rule` select `tx_rule` vs `rx_rule` in `union mlx5_macsec_rule` and whether `sa_fs_id` is dereferenced solely via `action == MLX5_ACCEL_MACSEC_ACTION_ENCRYPT`; callers must pass non-NULL `sa_fs_id` for decrypt rules and the same `action` on delete. [F1466]
- `mlx5_dm_sw_icm_alloc` requires `length` to be a non-zero power-of-two byte count and multiple of `MLX5_SW_ICM_BLOCK_SIZE(dev)`, while `log_alignment` is `ilog2` of byte alignment. `mlx5_hv_read_config` and `mlx5_hv_write_config` require `len == HV_CONFIG_BLOCK_SIZE_MAX` and `offset` a multiple of `HV_CONFIG_BLOCK_SIZE_MAX`. [F1474, F1477]

## Error Handling

- `mlx5_chains_update_prio_prevs` must allocate all replacement `miss_rules[n]` via `mlx5_chains_add_miss_rule` across the reverse walk of `chain->prios_list` before deleting any existing `pos->miss_rule`, so `err_prev_rule` can delete only the new rules and leave prior steering intact. [F1419]
- `mlx5_macsec_add_roce_rule` must call `mlx5_macsec_del_roce_rule(gid_idx, macsec_fs, tx_rules_list, rx_rules_list)` on any error to roll back TX/RX rules already added for `gid_idx`. Teardown helpers in `macsec_fs.c` (`macsec_fs_tx/rx_destroy`, `macsec_fs_tx/rx_del_rule`) only check for non-`NULL`, so creation functions must check `IS_ERR` before storing pointers into struct fields. [F1432, F1470]
- `mlx5_geneve_tlv_option_create` returns `< 0` on error and a non-negative 16-bit `obj_id` on success; callers must store it in a signed `int` and test `< 0`. [F1465]
- `mlx5_crypto_modify_dek_key` and `mlx5_crypto_create_dek_key` must call `memzero_explicit(in, sizeof(in))` on their stack command buffers after `mlx5_cmd_exec` before returning. [F1471]
- `mlx5_nv_param_read` and `mlx5_nv_param_write` use `WARN_ON` only for caller bugs (`len > MLX5_ST_SZ_BYTES(mnvda_reg)` or `MLX5_GET_CFG_HDR_LEN(mnvda) == 0`); register access failures in `mlx5_nv_param_read` log `mlx5_core_warn` and return `-EOPNOTSUPP`. [F1598]

## External Contracts

- In `mlx5_devlink_enable_sriov_set` and `mlx5_devlink_total_vfs_set`, modifying PF SR-IOV NVRAM parameters must verify `per_pf_total_vf_supported` in `nv_global_pci_cap` (returning `-EOPNOTSUPP` if false) before setting `per_pf_total_vf = 1` in `nv_global_pci_conf` and writing `nv_pf_pci_conf`. [F1492]
- `mlx5_extts_configure` must reject simultaneous edges via `(rq->extts.flags & PTP_EXTTS_EDGES) == PTP_EXTTS_EDGES`, and `mlx5_ptp_verify` must invert the capability bit test (`!(clock->pps_info.pin_caps[pin] & ...)`). [F1528]

## Known Pitfalls

- `mlx5_nv_param_read` passes `mnvda` as both input and output to `mlx5_core_access_reg`, so reusing `mnvda` for a subsequent `mlx5_nv_param_read_*` call on a different item requires `memset(mnvda, 0, sizeof(mnvda))` first. [F1472]
- `mlx5_create_ttc_table_groups`, `mlx5_create_ttc_table_ipsec_groups`, and `mlx5_create_inner_ttc_table_groups` reuse one `create_flow_group_in` buffer across `mlx5_create_flow_group` calls, so any match criterion set in `mc` must be zeroed before the next call. [F1487]
- In `mlx5_devcom_get_next_peer_data` and `mlx5_devcom_get_next_peer_data_rcu`, after `list_for_each_entry_continue(tmp, &comp->comp_dev_list_head, list)`, `list_entry_is_head(tmp, &comp->comp_dev_list_head, list)` must be checked to return `NULL` before setting `*pos = tmp`. [F1516]
- In `mlx5_vsc_gw_lock`, the `if (lock_val)` branch that sleeps and executes `continue` must increment `retries` first so the loop stays bounded by `VSC_MAX_RETRIES`. [F1520]

## Other

- In `mlx5_read_time`, reading the 64-bit timer across 32-bit MMIO registers (`real_time_h`/`l` or `internal_timer_h`/`l`) via `ioread32be` must read high, low, then high again (`timer_h1`), re-reading low if `timer_h != timer_h1`. [F1555]
