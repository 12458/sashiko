# MELLANOX ETHERNET DRIVER (mlx5e) — drivers/net/ethernet/mellanox/mlx5/core (part 3)

This component implements fast-path packet transmission (`en_tx.c`) and unified NAPI polling and completion handling (`en_txrx.c`) for `mlx5e`, translating `sk_buff` packets into standard WQEs or Enhanced Multi-Packet Send WQEs (MPWQEs) with inline headers, VLAN insertion, GSO/TSO, checksum, hardware timestamping, and crypto offloads, while polling TX, RX, XDP, AF_XDP (XSK), and ICOSQ completion queues.

## Architecture & Data Flow
- In `mlx5e_xmit`, `priv->txq2sq[skb_get_queue_mapping(skb)]` can be `NULL` (e.g., if an HTB queue ID is selected before its `mlx5e_txqsq` is created or after creation failed); `mlx5e_xmit` must check `!sq`, free `skb` via `dev_kfree_skb_any`, and return `NETDEV_TX_OK`. [F417]
- An `sk_buff` with `SKBTX_HW_TSTAMP` set can be transmitted and completed on a regular `mlx5e_txqsq` where `sq->ptpsq` is `NULL`; `mlx5e_txwqe_build_eseg`, `mlx5e_txwqe_complete`, and `mlx5e_consume_skb` must check `sq->ptpsq != NULL` before dereferencing PTP queue state. [F416]
- In `mlx5e_xmit`, `struct mlx5e_accel_tx_state accel` must be zero-initialized (`= {}`) before `mlx5e_accel_tx_begin`, which only populates sub-structs for active offloads while `mlx5e_tx_wqe_inline_mode`, `mlx5e_txwqe_build_eseg_csum`, `mlx5e_accel_tx_ids_len`, and `mlx5e_accel_tx_finish` inspect its fields unconditionally. [F413]
- Because `mlx5e_poll_tx_cq` and `mlx5e_free_txqsq_descs` branch on `wi->skb`, `wi->resync_dump_frag_page`, and `wi->num_fifo_pkts` without clearing `sq->db.wqe_info[ci]`, every WQE producer (`mlx5e_txwqe_complete`, `mlx5e_tx_mpwqe_session_complete`, `mlx5e_tx_flush`) must overwrite `sq->db.wqe_info[pi]` with a full `(struct mlx5e_tx_wqe_info){ ... }` initializer rather than partial field assignments. [F414]
- Both `mlx5e_poll_tx_cq` and `mlx5e_free_txqsq_descs` must be updated in lockstep for any `struct mlx5e_tx_wqe_info` completion type or resource to unmap DMA, release SKBs or pages, and accumulate `npkts` (`1` per `wi->skb` or `wi->num_fifo_pkts` per MPWQE) and `nbytes` (`wi->num_bytes`) for `netdev_tx_completed_queue(sq->txq, npkts, nbytes)` to match `__netdev_tx_sent_queue`. [F396, F431]
- Before posting any non-MPWQE descriptor to an MPWQE-capable `mlx5e_txqsq` (`MLX5E_SQ_STATE_MPWQE`), callers such as `mlx5e_xmit` or `mlx5e_tx_flush` must call `mlx5e_tx_mpwqe_ensure_complete(sq)` before `mlx5e_txqsq_get_next_pi` or `mlx5e_post_nop`, because an active MPWQE session occupies the WQE slot at `sq->pc` without having incremented `sq->pc`. [F468]
- `mlx5e_sq_xmit_mpwqe` must map `txd.dma_addr` and check `dma_mapping_error` before calling `mlx5e_tx_mpwqe_session_start(sq, eseg)`, because `mlx5e_tx_flush(sq)` on the `err_unmap` path must not be called when an MPWQE session is active (`sq->mpwqe.wqe != NULL`) with zero packets. [F392]
- `mlx5e_tx_mpwqe_session_start` and `mlx5e_tx_mpwqe_same_eseg` only copy and compare the first `MLX5E_ACCEL_ESEG_LEN` (`offsetof(struct mlx5_wqe_eth_seg, mss)`, 6 bytes) of `eseg`, so `mlx5e_tx_skb_supports_mpwqe` must reject any packet needing `eseg` fields at or after `mss` (such as `inline_hdr`, `trailer`, or `flow_table_metadata`). [F440]
- `sq->pc`, `sq->cc`, and hardware `be16_to_cpu(cqe->wqe_counter)` are 16-bit cyclic WQEBB counters that advance by `wi->num_wqebbs` per WQE and must be converted via `mlx5_wq_cyc_ctr2ix(&sq->wq, ...)` before indexing `sq->db.wqe_info`. In `mlx5e_txwqe_complete` and `mlx5e_tx_mpwqe_session_complete`, `cseg->opmod_idx_opcode` must be packed with `sq->pc << 8` before `sq->pc += wi->num_wqebbs`, and `mlx5e_poll_tx_cq` must check `u16 sqcc == wqe_counter` (never `<` or `<=`) before advancing `sqcc += wi->num_wqebbs`. [F442, F454]
- In `mlx5e_sq_calc_wqe_attr` and `mlx5i_sq_calc_wqe_attr`, `INL_HDR_START_SZ` must be subtracted from `attr->ihs` (plus `VLAN_HLEN` if `skb_vlan_tag_present(skb)` in `mlx5e_sq_calc_wqe_attr`) before computing `ds_cnt_inl`, and `ds_cnt_inl`, `ds_cnt_ids`, and `num_wqebbs` (including in `mlx5e_tx_mpwqe_session_complete`) must use `DIV_ROUND_UP` and stay synced with `MLX5E_MAX_TX_WQEBBS`. [F435, F453]
- In `mlx5e_sq_xmit_wqe`, `attr->ihs` holds the untagged header length in `skb->data` (at least `2 * ETH_ALEN` when `mlx5e_insert_vlan` is called), while the local `ihs` written to `eseg->inline_hdr.sz` is incremented by `VLAN_HLEN` when `skb_vlan_tag_present(skb)` is true without modifying `attr->ihs`. [F437]
- In `mlx5e_txwqe_build_dsegs`, `num_dma` must be incremented only after each segment's DMA mapping succeeds and is pushed to `sq->db.dma_fifo` via `sq->dma_fifo_pc++`, so `mlx5e_dma_unmap_wqe_err` can unwind exact pushed mappings by pre-decrementing `--sq->dma_fifo_pc` `num_dma` times. [F448]
- In `mlx5e_napi_poll`, `xskrq->cq` and `rq->cq` share the single NAPI `budget`: `rq->cq` must only be polled when `budget - work_done` is non-zero after polling `xskrq->cq`, and must be passed `budget - work_done` so total RX `work_done` never exceeds `budget`. [F452]
- In `mlx5e_napi_poll`, `MLX5E_SQ_STATE_PENDING_XSK_TX` on `c->async_icosq.state` must be cleared only when `mlx5e_poll_ico_cq(&c->async_icosq.cq)` returns a non-zero completion count, and `mlx5e_ktls_rx_pending_resync_list` must be evaluated only after polling `&c->async_icosq.cq`. [F469]

## Synchronization
- In `mlx5e_poll_tx_cq`, `sq->cc` and `sq->dma_fifo_cc` must be updated only after calling `mlx5_cqwq_update_db_record(&cq->wq)` followed by `wmb()`, so new WQEs cannot be posted before CQ space is freed to hardware (which can cause a CQ overrun). [F464]
- On a `MLX5_CQE_REQ_ERR` completion in atomic NAPI context, `mlx5e_poll_tx_cq` must defer recovery via `test_and_set_bit(MLX5E_SQ_STATE_RECOVERING, &sq->state)` and `queue_work(cq->workqueue, &sq->recover_work)`. Neither `mlx5e_txqsq_wake` nor `mlx5e_poll_tx_cq` may wake `sq->txq` unless `MLX5E_SQ_STATE_ENABLED` is set, `MLX5E_SQ_STATE_RECOVERING` is clear, `mlx5e_wqc_has_room_for` is true, and `!mlx5e_ptpsq_metadata_freelist_empty(sq->ptpsq)` holds. [F408, F477]
- When hardware timestamping is active on `sq->ptpsq` in `mlx5e_txwqe_complete`, `mlx5e_skb_cb_hwtstamp_init(skb)` and `mlx5e_ptp_metadata_map_put(&sq->ptpsq->metadata_map, skb, metadata_index)` must be executed followed by `wmb()` before `mlx5e_ptpsq_track_metadata(sq->ptpsq, metadata_index)`. [F401]
- `mlx5e_napi_poll` must hold `rcu_read_lock()` across its entire execution until `out:`, dereference `c->qos_sqs` and each `qos_sqs[i]` with `rcu_dereference()`, and read `c->qos_sqs_size` with `READ_ONCE()` only after `smp_rmb()` when `qos_sqs` is non-NULL. [F473]
- In `mlx5e_napi_xsk_post`, when `need_wakeup` is enabled, `xsk_set_tx_need_wakeup` (when `xsksq->pc == xsksq->cc`) and `xsk_set_rx_need_wakeup` (when `!mlx5e_rqwq_get_cur_sz(xskrq)`) must be set before calling `mlx5e_xsk_tx` and `xskrq->post_wqes` respectively. [F407]

## Object Lifetimes
- `mlx5e_tx_mpwqe_session_complete` must clear `sq->mpwqe.wqe = NULL` after recording `sq->db.wqe_info[pi]` and advancing `sq->pc`, so `mlx5e_tx_mpwqe_session_is_active(sq)` returns `false` and prevents double-completing the session. [F393]
- For PTP hardware-timestamped packets (`sq->ptpsq && (skb_shinfo(skb)->tx_flags & SKBTX_HW_TSTAMP)`), `mlx5e_cqe_ts_id_eseg` must only peek `sq->ptpsq->metadata_freelist`, whereas `mlx5e_txwqe_complete` pops the freelist, inserts `skb` into `sq->ptpsq->metadata_map`, and calls `skb_get(skb)` only after DMA mapping in `mlx5e_txwqe_build_dsegs` succeeds. [F394]
- In both `mlx5e_poll_tx_cq` and `mlx5e_free_txqsq_descs`, all DMA mappings for a WQE must be unmapped via `mlx5e_tx_wi_dma_unmap(sq, wi, &dma_fifo_cc)` before consuming or freeing `wi->skb` or the FIFO SKBs (`mlx5e_tx_wi_consume_fifo_skbs` / `mlx5e_tx_wi_kfree_fifo_skbs`). [F479]

## API Contracts
- When `mlx5e_accel_tx_begin` returns `false`, the failing offload handler has already consumed and freed `skb`, so `mlx5e_xmit` must return `NETDEV_TX_OK` immediately without freeing `skb` again. [F412]
- In `mlx5e_xmit`, any offload preparation that may post auxiliary WQEs to `sq` must run in `mlx5e_accel_tx_begin` before `pi` and `wqe` are fetched via `mlx5e_txqsq_get_next_pi`; `mlx5e_accel_tx_finish` must only mutate `wqe` and never post WQEs. [F427]
- TX error-drop and queue teardown paths (`mlx5e_xmit`, `mlx5e_sq_xmit_wqe`, `mlx5e_sq_xmit_mpwqe`, `mlx5i_sq_xmit`, `mlx5e_free_txqsq_descs`, `mlx5e_tx_wi_kfree_fifo_skbs`) must free SKBs via `dev_kfree_skb_any()`, while `mlx5e_poll_tx_cq` must pass `napi_budget` through `mlx5e_consume_skb` to `napi_consume_skb()`. [F476]
- `mlx5e_poll_tx_cq` unconditionally downcasts its `struct mlx5e_cq *` parameter via `container_of(cq, struct mlx5e_txqsq, cq)`, so it must only be called on CQs embedded in `struct mlx5e_txqsq` and never on CQs in `mlx5e_xdpsq`, `mlx5e_rq`, or `mlx5e_icosq`. [F463]
- When `mlx5e_napi_poll` is called with `budget == 0` (e.g., from IRQ/netpoll context), it must only poll TX CQs (`c->sq[i].cq` and `qos_sqs[i]->cq`) and immediately jump to `out:` without polling RX/XDP/ICO CQs, posting WQEs, completing NAPI, or re-arming CQs. [F475]
- `rq->post_wqes` (`mlx5e_post_rx_mpwqes` or `mlx5e_post_rx_wqes`) returns `true` on RX buffer allocation failure; `mlx5e_napi_xsk_post` must OR this result into `busy_xsk` only when `!need_wakeup`, and otherwise use it to select between `xsk_set_rx_need_wakeup` and `xsk_clear_rx_need_wakeup`. [F420]

## Error Handling
- When `mlx5e_sq_xmit_wqe`, `mlx5e_sq_xmit_mpwqe`, or `mlx5i_sq_xmit` drops `skb` on a DMA mapping error, it must free `skb` with `dev_kfree_skb_any(skb)` and call `mlx5e_tx_flush(sq)` so any open MPWQE session, edge-padding NOPs, or prior `xmit_more` WQEs are completed and notified to hardware. [F391]
- `mlx5e_txwqe_build_dsegs` returns the non-negative mapped segment count on success or `-ENOMEM` after unwinding already-pushed mappings via `mlx5e_dma_unmap_wqe_err`, so callers (`mlx5e_sq_xmit_wqe`, `mlx5i_sq_xmit`) must store the result in a signed `int` and check `< 0` before narrowing it to `u8` for `mlx5e_txwqe_complete`. [F409]

## External Contracts
- In `mlx5e_napi_poll`, when `busy` is true, if `mlx5e_channel_no_affinity_change(c)` holds it must return `budget` without calling `napi_complete_done` or arming CQs; if affinity changed, it must clamp `work_done` below `budget` (`work_done--` if `work_done == budget`) before calling `napi_complete_done`, arming CQs, and triggering an ICOSQ IRQ via `mlx5e_trigger_irq` when `busy_xsk` is true. [F451]
- When `ipv6_has_hopopt_jumbo(skb)` is true on a non-encapsulated TCP GSO SKB, `mlx5e_tx_get_gso_ihs` and `mlx5e_sq_xmit_prepare` must subtract `sizeof(struct hop_jumbo_hdr)` from `ihs` and `headlen`, and `mlx5e_sq_xmit_wqe` and `mlx5i_sq_xmit` must strip that header from `inline_hdr.start` and map DMA from `skb->data + attr->ihs + attr->hopbyhop`. [F490]

## Known Pitfalls
- In `mlx5e_sq_xmit_wqe`, `eseg->inline_hdr.sz` must be updated with bitwise OR (`|= cpu_to_be16(ihs)`) after `MLX5E_TX_FETCH_WQE` zeroes the WQE, because `eseg->inline_hdr.sz` shares a union with the upper 16 bits of `eseg->trailer` in `struct mlx5_wqe_eth_seg`, which `mlx5e_txwqe_build_eseg` populates beforehand for IPsec and PSP offloads. [F439]
- In `mlx5e_sq_xmit_wqe`, when `ihs` is non-zero, `attr->hopbyhop` must be tested before `skb_vlan_tag_present(skb)` because the `attr->hopbyhop` branch handles both VLAN-tagged and untagged IPv6 jumbogram packets while stripping `sizeof(struct hop_jumbo_hdr)`. [F449]
- In `mlx5e_tx_mpwqe_add_dseg`, `session->ds_count` starts at `MLX5E_TX_WQE_EMPTY_DS_COUNT` (counting `wqe->ctrl` and `wqe->eth` in 16-byte `MLX5_SEND_WQE_DS` units), so `session->wqe` (`struct mlx5e_tx_wqe *`, 32 bytes) must be cast to `struct mlx5_wqe_data_seg *` (16 bytes) before adding `session->ds_count`. [F461]
- In `mlx5e_txwqe_complete` and `mlx5e_sq_xmit_mpwqe` (when full), `sq->pc` advancement and queue-stop checks (`mlx5e_tx_check_stop` and PTP freelist stop) must precede `__netdev_tx_sent_queue`, so stopping `sq->txq` forces `__netdev_tx_sent_queue` to return `true` and ring the doorbell via `mlx5e_notify_hw` even when `xmit_more` is set. [F467]
