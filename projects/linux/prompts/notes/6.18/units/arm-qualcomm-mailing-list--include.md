# ARM/QUALCOMM MAILING LIST — include

This unit contains public C headers for Qualcomm SoC subsystems (`include/linux/soc/qcom/`, `include/linux/dma/`, `include/linux/rpmsg/`, `include/linux/remoteproc/`, `include/linux/mfd/`) and Device Tree binding constant headers (`include/dt-bindings/`). It defines wire protocols (QMI, APR/GPR, SOCINFO SMEM), driver structures and inline helpers (GENI SE, LLCC, UBWC, MDT loader, BAM DMA), and compile-time `!CONFIG_*` fallback stubs.

## Architecture & Data Flow

- Every valid protocol in `enum geni_se_protocol_type` (before `GENI_SE_INVALID_PROTO`) must have a matching entry at the same index in `protocol_name[]` in `drivers/soc/qcom/qcom-geni-se.c`, and `enum geni_icc_path_index` (`GENI_TO_CORE`, `CPU_TO_GENI`, `GENI_TO_DDR`) plus `struct geni_se::icc_paths[3]` must stay synchronized in order and count with `icc_path_names[]` and `icc_names[]` in `geni_icc_get()`. [F518, F519]
- In `geni_se_get_tx_fifo_depth()` and `geni_se_get_rx_fifo_depth()`, the 8-bit 256-byte FIFO depth mask (`TX_FIFO_DEPTH_MSK_256_BYTES` / `RX_FIFO_DEPTH_MSK_256_BYTES`) must be selected when `(hw_major == 3 && hw_minor >= 10) || hw_major > 3`, and `TX_FIFO_DEPTH_MSK` / `RX_FIFO_DEPTH_MSK` otherwise. Broken by: simplifying to `hw_major >= 3 && hw_minor >= 10` or dropping parentheses. [F536]
- In `include/linux/soc/qcom/geni-se.h`, `RX_GENI_CANCEL_IRQ` in the `SE_DMA_RX_IRQ_STAT` register is `BIT(14)` (above `RX_GENI_GP_IRQ_EXT` at `GENMASK(13, 12)`). [F557]
- In `struct qcom_ubwc_cfg_data`, any configuration with `ubwc_enc_version == UBWC_1_0` must also set `UBWC_SWIZZLE_ENABLE_LVL1` in `ubwc_swizzle` because UBWC 1.0 always enables level 1 bank swizzling, while `qcom_ubwc_get_ubwc_mode()` returns `true` if and only if `cfg->ubwc_enc_version == UBWC_1_0` (only logging via `pr_err()` if `UBWC_SWIZZLE_ENABLE_LVL1` is cleared). [F521, F537]

## Synchronization

- Callers of `devm_pmic_glink_client_alloc()` must store the returned `struct pmic_glink_client *` into `priv` before calling `pmic_glink_client_register()`, which immediately invokes `pdr_notify(priv, state)`. Both `cb` and `pdr` callbacks run under `spin_lock_irqsave(&pg->client_lock)` (and `pdr` under `pg->state_lock`), so neither may sleep or call `pmic_glink_send()` synchronously. [F494, F495]
- For `struct qmi_handle` and `struct qmi_txn`, `qmi->txn_lock` nests outside `txn->lock`. A `qmi_msg_handler.fn` callback for a `QMI_RESPONSE` (when `txn->dest` or `txn->ei` is `NULL`) runs with `txn->lock` held and must not call `qmi_txn_init()`, `qmi_txn_wait()`, `qmi_txn_cancel()`, or `qmi_send_indication()` on `qmi`. [F569]
- In `struct llcc_drv_data`, `drv_data->lock` must be held across the entire `test_bit()`, hardware activation/deactivation (`llcc_update_act_ctrl()`), and non-atomic `__set_bit()` / `__clear_bit()` sequence on `drv_data->bitmap` in `llcc_slice_activate()` and `llcc_slice_deactivate()`. [F497]
- `geni_se_setup_m_cmd()` and `geni_se_setup_s_cmd()` must use `writel()` (not `writel_relaxed()`) when writing `SE_GENI_M_CMD0` and `SE_GENI_S_CMD0`, and callers of `geni_se_setup_s_cmd()` must externally serialize calls on the same `struct geni_se` because it performs an unlocked read-modify-write of `SE_GENI_S_CMD0`. [F498]
- In `include/linux/soc/qcom/apr.h`, `pkt_router_svc.lock` is acquired with `spin_lock_irqsave` in `apr_send_pkt()`, `gpr_send_pkt()`, and `gpr_send_port_pkt()` around `rpmsg_trysend()`, whereas `apr_driver.callback`, `apr_driver.gpr_callback`, and `gpr_port_cb` execute in workqueue process context without `svc.lock` held. [F570]

## Object Lifetimes

- In `struct qmi_ops`, `new_server` receives a borrowed `struct qmi_service *svc` that the QMI core frees with `kfree()` immediately if `new_server` returns a negative error, or retains on `qmi->lookup_results` and frees immediately after invoking `del_server`. Callers must never `kfree(svc)` or dereference it after `del_server` returns. [F479]
- `qmi_encode_message()` returns a `kzalloc()`-allocated buffer and `qcom_mdt_read_metadata()` returns a `kmalloc()`-allocated buffer (or an `ERR_PTR()` on failure, including `ERR_PTR(-ENODEV)` when `!IS_ENABLED(CONFIG_QCOM_MDT_LOADER)`). In both cases ownership transfers to the caller, which must check `IS_ERR()` (not `NULL`) and free the buffer with `kfree()`. [F481, F483]
- `pdr_add_lookup()` returns a borrowed `struct pdr_service *` (or `ERR_PTR()`) owned by `pdr->lookups` and freed internally by `pdr_handle_release()` or `pdr_notify_lookup_failure()`, whereas `qcom_smem_get()` and `qcom_ubwc_config_get_data()` return borrowed pointers to mapped SMEM memory and static `const struct qcom_ubwc_cfg_data` tables (or `ERR_PTR()`). Callers must check `IS_ERR()` and never `kfree()` these pointers. [F485, F493]
- `gpr_alloc_port()` returns an `ERR_PTR()` on failure and a caller-owned `gpr_port_t *` on success that must be freed with `gpr_free_port()`, which unconditionally dereferences `port` to remove `port->id` from `gpr->svcs_idr` before calling `kfree(port)`. Broken by: checking `gpr_alloc_port()` for `NULL` instead of `IS_ERR()`, leaking the port, or passing `NULL` or `ERR_PTR()` to `gpr_free_port()`. [F486]
- `get_pbs_client_device()` binds the supplier PBS device lifetime to `client_dev` via `device_link_add(..., DL_FLAG_AUTOREMOVE_SUPPLIER)` (returning `ERR_PTR()` on failure), so callers must not manually `put_device(pbs->dev)`. Conversely, `qmp_get()` returns a `struct qmp *` (or `ERR_PTR()`) holding a `qmp->dev` reference from `of_find_device_by_node()` that callers must release with `qmp_put()`. [F488, F489]
- `qcom_smem_state_get()` and `qcom_smem_state_register()` return a kref-counted `struct qcom_smem_state *` (or `ERR_PTR()` on failure) that must be balanced by `qcom_smem_state_put()` and `qcom_smem_state_unregister()` respectively; neither release function accepts `NULL` or an `ERR_PTR()` when `CONFIG_QCOM_SMEM_STATE` is enabled. [F490]
- `geni_se_clk_tbl_get()` lazily allocates `se->clk_perf_tbl` via `devm_kcalloc(se->dev, ...)` and stores a borrowed pointer in `*tbl` (must not be `kfree()`d). `geni_se_tx_dma_prep()` and `geni_se_rx_dma_prep()` map `buf` on `se->wrapper->dev` and require a matching `geni_se_tx_dma_unprep()` or `geni_se_rx_dma_unprep()` call when they return 0. [F492]
- Implementations of `apr_driver.callback`, `apr_driver.gpr_callback`, and `gpr_port_cb` must check `payload_size > 0` before dereferencing `apr_resp_pkt.payload` or `gpr_resp_pkt.payload`, and must not retain `resp` or `payload` after returning because `resp` is stack-allocated and `apr_rxwq()` frees the backing buffer. [F553]

## API Contracts

- `llcc_slice_getd()` returns `ERR_PTR()` on failure when `CONFIG_QCOM_LLCC` is enabled but returns `NULL` from its `!IS_ENABLED(CONFIG_QCOM_LLCC)` stub in `llcc-qcom.h` (so callers must check `IS_ERR_OR_NULL()` or `PTR_ERR_OR_ZERO()`), while `llcc_slice_putd()` only frees `struct llcc_slice_desc` without deactivating the slice in hardware (`llcc_slice_deactivate()` must be called first). [F482]
- `qcom_register_ssr_notifier()`, `qcom_glink_smem_register()`, and `qcom_smd_register_edge()` return `ERR_PTR()` on failure when enabled, but their `#else` stubs in `qcom_rproc.h`, `qcom_glink.h`, and `qcom_smd.h` return `NULL` so `PTR_ERR_OR_ZERO()` treats disabled support as non-fatal. Furthermore, any prototype change under `#if IS_ENABLED(CONFIG_*)` or `#ifdef CONFIG_*` across Qualcomm headers must update the `#else` stub in lockstep. [F491, F520]
- In `include/linux/soc/qcom/apr.h`, `APR_HDR_FIELD(msg_type, hdr_len, ver)` and `struct gpr_hdr.hdr_size` encode header lengths in 32-bit words (`APR_HDR_LEN(APR_HDR_SIZE)` and `GPR_PKT_HEADER_WORD_SIZE`), whereas `apr_hdr.pkt_size` and `gpr_hdr.pkt_size` are in bytes (`APR_HDR_SIZE` and `GPR_PKT_HEADER_BYTE_SIZE`). [F508]
- In `struct apr_driver`, APR bus drivers must set `.callback` whereas GPR static service drivers must set `.gpr_callback`, and any populated `apr_driver.id_table` (`struct apr_device_id[]`) must be terminated by a sentinel entry with `domain_id == 0` and `svc_id == 0`. [F531, F572]
- Every `struct qmi_elem_info` array (including nested `ei_array` tables for `QMI_STRUCT`) must end with a `.data_type = QMI_EOTI` sentinel, and every `struct qmi_msg_handler` array passed to `qmi_handle_init()` must end with a `.fn = NULL` sentinel. For `QMI_STRING` elements decoded by `qmi_decode_message()`, `elem_len` must include the trailing NUL (`max_wire_chars + 1`) and not exceed the destination `char` array size. [F512, F549]
- In `geni-se.h`, `se->wrapper` must be populated before calling `geni_se_get_qup_hw_version()`, `geni_se_get_tx_fifo_depth()`, `geni_se_get_rx_fifo_depth()`, `geni_se_resources_on()`, `geni_se_resources_off()`, `geni_se_tx_dma_unprep()`, `geni_se_rx_dma_unprep()`, or `geni_load_se_firmware()`. `geni_se_setup_m_cmd()` and `geni_se_setup_s_cmd()` take an unshifted 5-bit opcode in `@cmd` and pre-positioned parameters in `@params`. [F513, F516]
- `geni_se_get_tx_fifo_depth()`, `geni_se_get_rx_fifo_depth()`, and `@rx_wm` / `@rx_rfr` in `geni_se_init()` are in FIFO words, whereas `geni_se_get_tx_fifo_width()` is in bits; `llcc_slice_desc.slice_size` and `llcc_get_slice_size()` are in kilobytes (KB); `qcom_rpm_write()` takes `count` in 32-bit words (matching `res->size`) whereas `qcom_rpm_smd_write()` takes `count` in bytes. [F514, F573, F575]
- Callers of `qmp_send()` must ensure the formatted string length is strictly less than 64 bytes (`QMP_MSG_LEN`) to fit in the 64-byte stack buffer including the NUL terminator, or `qmp_send()` triggers `WARN_ON(len >= sizeof(buf))` and returns `-EINVAL`. [F554]
- In `llcc-qcom.h`, when `llcc_drv_data.ecc_irq_configured` is true, firmware has already configured LLCC ECC interrupt propagation and consumers (such as `qcom_llcc_edac_probe()`) must not write to the LLCC interrupt enable/configuration registers. [F558]
- In `include/linux/soc/qcom/irq.h`, `irq_domain_qcom_handle_wakeup()` returns `true` only when `d->flags` has `IRQ_DOMAIN_FLAG_QCOM_PDC_WAKEUP` set, indicating wakeup configuration is handled at the parent PDC and the line must be masked at the child TLMM interrupt controller. [F560]
- In `include/linux/dma/qcom_bam_dma.h`, `bam_prep_ce_le32()` and `bam_prep_ce()` encode `struct bam_cmd_element` in `__le32` with `addr` masked to 24 bits (`addr & 0xffffff`) and `cmd` in bits 31:24 of `cmd_and_addr`, requiring pre-converted `__le32` data for `bam_prep_ce_le32()` and host-endian `u32` data for `bam_prep_ce()`. [F562]

## Error Handling

- `qcom_ubwc_config_get_data()` returns an `ERR_PTR` (`-ENODEV`, `-EINVAL`, or `-EOPNOTSUPP` when `!IS_ENABLED(CONFIG_QCOM_UBWC_CONFIG)`), and `qcom_ubwc_get_ubwc_mode()` unconditionally dereferences `cfg`, so callers must validate `cfg` with `IS_ERR()` (not `!cfg`) before calling `qcom_ubwc_get_ubwc_mode(cfg)` or reading `struct qcom_ubwc_cfg_data`. [F501]
- `qcom_mdt_get_size()` returns a negative errno on failure and positive firmware memory size on success as a signed `ssize_t` (must not be stored in unsigned `size_t` before checking errors), whereas `qcom_mdt_load()` and `qcom_mdt_load_no_init()` require non-zero `fw`, `mem_region`, `mem_phys`, and `mem_size` but accept a `NULL` `reloc_base` out-parameter. [F503]
- `apr_send_pkt()`, `gpr_send_pkt()`, and `gpr_send_port_pkt()` return the positive packet byte size (`hdr->pkt_size`) on success, and `geni_se_clk_tbl_get()` returns the positive number of clock performance levels (`se->num_clk_levels`) on success (or `0` if none found) and negative errno on failure. Callers must check `ret < 0` (or `ret <= 0` for `geni_se_clk_tbl_get()`) rather than `if (ret)`. [F506, F515]
- `qmi_txn_init()` returns a non-negative transaction ID on success and negative errno on failure; once it succeeds, the caller must call either `qmi_txn_wait()` (which removes `txn->id` from `qmi->txns` even on timeout) or `qmi_txn_cancel()` (when aborting before `qmi_txn_wait()`), never both. When initialized with non-NULL `@ei` and `@c_struct`, `qmi_txn_wait()` returns the decoded byte count (`>= 0`) without checking payload status, so callers must also check `resp.result != QMI_RESULT_SUCCESS_V01`. [F509, F510]
- When `!IS_ENABLED(CONFIG_QCOM_WCNSS_CTRL)`, the fallback stub for `qcom_wcnss_open_channel()` in `include/linux/soc/qcom/wcnss_ctrl.h` unconditionally triggers `WARN_ON(1)` before returning `ERR_PTR(-ENXIO)`, so callers must depend on `CONFIG_QCOM_WCNSS_CTRL` or guard calls at runtime. [F580]

## External Contracts

- In `include/dt-bindings/power/qcom-rpmpd.h` and `qcom,rpmhpd.h`, `RPMPD_VDDCX_VFC` and `RPMPD_VDDCX_VFL` both alias power domain index `2` and must never be used on the same platform, and new platform-specific power domain index macros (`<SOC>_CX`, `<SOC>_MX`, `<SOC>_VDDCX`) must not be added—use generic `RPMHPD_*` or `RPMPD_*` constants instead. [F524, F534]
- `include/dt-bindings/sound/qcom,q6afe.h` must not be removed even though it only includes `<dt-bindings/sound/qcom,q6dsp-lpass-ports.h>`, because external device trees depend on the header path for backward compatibility. [F535]
- Multi-byte fields in packed QMI/GLINK wire headers (`struct qmi_header`, `struct pmic_glink_hdr`) must use explicit `__le16` / `__le32` annotations rather than host-native types. In `include/linux/soc/qcom/socinfo.h`, `struct socinfo` defines the versioned SMEM binary layout for `SMEM_HW_SW_BUILD_ID` (`137`), so existing fields must never be reordered and readers must check `info->fmt` (`SOCINFO_VERSION`) or item size before accessing versioned fields. [F526, F563]

## Known Pitfalls

- In `struct qmi_msg_handler`, `decoded_size` must be at least the size of the C struct described by `ei`, and `fn()` must not retain `decoded` or `txn` after returning because `qmi_invoke_handler()` frees `decoded` immediately and `qmi_handle_message()` passes a stack-allocated `struct qmi_txn` for `QMI_REQUEST` and `QMI_INDICATION` messages in which only `txn->id` is initialized (all other fields are zeroed). [F511, F550]
- In `struct qmi_elem_info`, an entry with `data_type = QMI_DATA_LEN` uses `elem_size` (`sizeof(u8)` or `sizeof(u16)`) only for the wire length field, whereas `qmi_decode_message()` unconditionally writes a 4-byte `u32` to `out_c_struct + temp_ei->offset`, so the target member in any decoded C struct must be a `u32`. [F548]
- `svc_to_apr_device()` must only be called on a `struct pkt_router_svc` embedded in a bus-registered `struct apr_device` (never on a dynamic `gpr_port_t` from `gpr_alloc_port()`), and `to_apr_device()` must never be called on `pkt_router_svc.dev`. Furthermore, `apr_driver.gpr_callback` always receives the bus-registered `gpr_device_t *` (`struct apr_device *`) as its `void *data` argument, whereas `gpr_port_cb` registered with `gpr_alloc_port()` receives the caller's `priv` pointer. [F551, F552]
- In `struct llcc_drv_data` (`include/linux/soc/qcom/llcc-qcom.h`), all fields consumed by `qcom_edac.c` (`regmaps`, `bcast_regmap`, `edac_reg_offset`, `num_banks`, `ecc_irq`, `ecc_irq_configured`) must be populated in `qcom_llcc_probe()` before `platform_device_register_data()` shallow-copies `*drv_data` by value into `pdev->dev.platform_data`. [F523]
