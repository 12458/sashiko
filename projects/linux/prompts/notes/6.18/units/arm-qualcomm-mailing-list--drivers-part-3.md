# ARM/QUALCOMM MAILING LIST — drivers (part 3)

Qualcomm PHY drivers for USB (QMP USB-C, QUSB2, Synopsys Femto v2, 28nm HS, HSIC, SS), PCIe (28lp UniPHY), and Ethernet (SGMII), plus power reset (`msm-poweroff`, `qcom-pon`) and power supply/charger drivers (`qcom_battmgr`, `qcom_smbb`).

## Architecture & Data Flow

- In `qusb2_phy_init`, when `cfg->has_pll_test` is true, sample post-reset `QUSB2PHY_PLL_TEST` into `val` before `qcom_qusb2_phy_configure` and keep `val` until `CLK_REF_SEL` is updated after `qphy->has_se_clk_scheme` is set. Run `qcom_qusb2_phy_configure` before `qusb2_phy_override_phy_params` and `qusb2_phy_set_tune2_param` (full writes to `QUSB2PHY_PORT_TUNE1`/`TUNE2` vs masked updates). In `qusb2_phy_set_tune2_param`, shift non-zero `hstx_trim` from `qphy->cell` by `HSTX_TRIM_SHIFT` into `HSTX_TRIM_MASK` of `QUSB2PHY_PORT_TUNE1` if `cfg->update_tune1_with_efuse`, else `QUSB2PHY_PORT_TUNE2`. [F238, F239, F289]
- In `phy-qcom-qusb2.c`, `QUSB2_PHY_INIT_CFG_L` (`in_layout = 1`) uses `offset` as an `enum qusb2phy_reg_layout` index into `cfg->regs[]` (which must be populated in the SoC's `regs` layout array, e.g., `QUSB2PHY_PORT_TUNE5` on `msm8998_regs_layout`), whereas `QUSB2_PHY_INIT_CFG` (`in_layout = 0`) uses a raw byte offset. [F253]
- Runtime PM callbacks in `phy-qcom-qmp-usbc.c` (`!qmp->phy->init_count`), `phy-qcom-qusb2.c` (`!qphy->phy_initialized`), and `phy-qcom-snps-femto-v2.c` (`!hsphy->phy_initialized`) must return 0 immediately without touching clocks or MMIO when uninitialized. Prepare/enable `qphy->ref_clk` in `qusb2_phy_init`/`qusb2_phy_runtime_resume` and disable/unprepare it in `qusb2_phy_exit`/`qusb2_phy_runtime_suspend` iff `!qphy->has_se_clk_scheme`. [F237, F297]
- Set `dev_set_drvdata(dev, qmp)` before `devm_pm_runtime_enable(dev)` in `qmp_usbc_probe` (used by `qmp_usbc_runtime_suspend`/`resume`), and set `hsphy->phy = generic_phy` and `dev_set_drvdata(dev, hsphy)` before `qcom_snps_hsphy_read_override_param_seq(dev)` in `qcom_snps_hsphy_probe`. [F279, F280]
- In `phy-qcom-snps-femto-v2.c`, non-sentinel `override_param_map` entries must have `table_size >= 1`, non-zero `param_mask`, and `reg_val << __ffs(param_mask)` fitting in `u8` (`seq_entry->value`). In `qcom_snps_hsphy_por_reset`, call `qcom_snps_hsphy_exit_retention` (clearing `SIDDQ` in `PHY_CTRL_COMMON0`) between `reset_control_assert` and `reset_control_deassert` of `priv->por_reset`. [F241, F274]
- In `qcom_usb_hs_phy_probe()`, allocate `(size / 2) + 1` elements for `uphy->init_seq` and zero `uphy->init_seq[size / 2].addr` (`qcom_usb_hs_phy_power_on()` loops until `seq->addr == 0`, adding `ULPI_EXT_VENDOR_SPECIFIC` to non-zero `addr`). In `qcom_usb_hs_phy_power_on`, when `uphy->vbus_edev` is set, seed initial `extcon_get_state` (`EXTCON_USB`) into `ULPI_MISC_A_VBUSVLDEXT` via `qcom_usb_hs_phy_vbus_notifier` alongside registering `uphy->vbus_notify`. [F243, F254]
- In `phy-qcom-usb-ss.c`, when `priv->reset_com` is non-NULL, `qcom_ssphy_init_reset` requires `priv->reset_phy` to be non-NULL too, and `qcom_ssphy_do_reset` toggles both resets instead of `PHY_RESET` in `PHY_CTRL1`. In `qcom_uniphy_pcie_init`, advance a local `base` cursor by `data->lane_offset` across `phy->lanes` without mutating `phy->base` (needed at lane 0 by `qcom_uniphy_pcie_power_on`). [F220, F244]
- In `qcom-pon.c`, `qcom_pon_reboot_mode_write()` updates 8-bit `PON_SOFT_RB_SPARE` with `GENMASK(7, pon->reason_shift)` and `magic << pon->reason_shift`, so `qcom_pon_id_table` match data must be in `1..7` (or `NO_REASON_SHIFT` `0` to skip registering reboot-mode). [F258]
- In `qcom_battmgr_request`, call `reinit_completion(&battmgr->ack)` and `battmgr->error = 0` before `pmic_glink_send`. In `qcom_battmgr_notification`, `NOTIF_BAT_INFO` must set `battmgr->info.valid = false` before `power_supply_changed(battmgr->bat_psy)` so `qcom_battmgr_bat_sc8280xp_update` re-fetches `BATTMGR_BAT_INFO`. [F229, F232]
- In `qcom_smbb.c`, `ATTR_BAT_ISAFE`/`ATTR_BAT_VSAFE` must precede `ATTR_BAT_IMAX`/`ATTR_BAT_VMAX` in `enum smbb_attr`, and `smbb_charger_attr_parse` must fall back to `smbb_charger_attr_read` when a `.fail_ok = 1` write fails (`smbb_charger_attr_write` clamps `IMAX`/`VMAX` against `prop->safe_reg`). Both `smbb_charger_attr_write` and `smbb_charger_attr_read` must update `chg->attr[which]` via `prop->hw_fn`, as `.get_property` callbacks serve `chg->attr` directly. [F226, F234]

## Synchronization

- In `phy-qcom-qmp-usbc.c`, `qmp->phy_mutex` serializes `qmp_usbc_enable()` and `qmp_usbc_typec_switch_set()`. When `qmp->orientation` changes in `qmp_usbc_typec_switch_set` while `qmp->usb_init_count` is non-zero, power-cycle the PHY (`qmp_usbc_power_off`, `qmp_usbc_exit`, `qmp_usbc_init`, `qmp_usbc_power_on`) under `qmp->phy_mutex` without altering `qmp->usb_init_count`. [F212, F236]
- In `qcom_battmgr_probe()`, initialize `battmgr->enable_work`, `battmgr->lock`, `battmgr->ack`, `bat_psy`/`usb_psy`/`wls_psy`, and `battmgr->client` (`devm_pmic_glink_client_alloc()`) before `pmic_glink_client_register()`. All property request paths in `qcom_battmgr.c` must hold `battmgr->lock` across `qcom_battmgr_request()` and its wrappers (`qcom_battmgr_request_property()`, `qcom_battmgr_update_*()`, `qcom_battmgr_set_charge_control()`). [F207, F208]
- `qcom_battmgr_callback` (and `qcom_battmgr_notification`, `qcom_battmgr_sc8280xp_callback`, `qcom_battmgr_sm8350_callback`) runs under `spin_lock_irqsave(&pg->client_lock, flags)` while a requester holds `battmgr->lock`, so it must not sleep or take `battmgr->lock`. `qcom_battmgr_pdr_notify` runs under mutex `pg->state_lock` and spinlock `pg->client_lock` with IRQs disabled, so it must not sleep or call `qcom_battmgr_request`/`pmic_glink_send` directly and must defer to `battmgr->enable_work`. [F298, F299]
- In `qcom_smbb.c`, hold `chg->statlock` when accessing `chg->status` in IRQ handlers (`smbb_set_line_flag()`, `smbb_bat_temp_handler()`) and `.get_property` callbacks. Because `smbb_charger_irqs` handlers take mutex `chg->statlock` or call sleeping `regmap_read`, register them only as threaded IRQs (`devm_request_threaded_irq`), and only after `chg->statlock`, `bat_psy`, `usb_psy`, `edev`, and `dc_psy` are initialized in `smbb_charger_probe()`. [F210, F211, F301]
- In `msm-poweroff.c`, `do_msm_poweroff` runs in atomic `SYS_OFF_MODE_RESTART`/`SYS_OFF_MODE_POWER_OFF` context and must use `mdelay` rather than sleeping delays or mutexes after asserting `msm_ps_hold`. [F302]

## Object Lifetimes

- In `qusb2_phy_set_tune2_param`, `kfree(val)` the `nvmem_cell_read(qphy->cell, NULL)` buffer on all return paths, including when `hstx_trim` (`val[0]`) is zero. In `qusb2_phy_probe`, any error path after unmanaged `pm_runtime_enable(dev)` must call `pm_runtime_disable(dev)`. [F196, F286]
- `qmp_usbc_probe` must release `np` (`of_get_child_by_name` or `of_node_get`) via `of_node_put(np)` before `devm_of_phy_provider_register` on success and at `err_node_put` on all failures. `qmp_usbc_parse_vls_clamp` must call `of_node_put(tcsr_args.np)` after `syscon_node_to_regmap(tcsr_args.np)` and before returning on `IS_ERR(qmp->tcsr_map)`. [F197, F198]
- In `phy-qcom-qmp-usbc.c`, `phy_pipe_clk_register` (`of_clk_add_hw_provider` on `np`, which may be a child DT node rather than `qmp->dev`) and `qmp_usbc_typec_switch_register` (`typec_switch_register`, guarded by `#if IS_ENABLED(CONFIG_TYPEC)` with a `0` stub) must immediately attach `devm_add_action_or_reset` (`phy_clk_release_provider` and `qmp_usbc_typec_unregister`) with no fallible steps in between. [F199, F284, F309]

## API Contracts

- `qusb2_write_mask(base, offset, val, mask)` takes pre-shifted `val` 3rd and `mask` 4th, whereas `qcom_snps_hsphy_write_mask(base, offset, mask, val)` takes `mask` 3rd and pre-shifted `val` 4th. Both helpers and `qphy_setbits`/`qphy_clrbits`/`qusb2_setbits`/`qusb2_clrbits` follow each MMIO write with a same-offset readback to flush posted writes; do not remove the readback or bypass them before delays or clock gates. [F215, F293]
- `qmp_configure_lane()` tests `t->lane_mask & lane_mask`, so callers (`qmp_usbc_power_on()`) and `QMP_PHY_INIT_CFG_LANE` must use bitmasks `1` (`BIT(0)`) and `2` (`BIT(1)`), not 0-based indices. Clearing autonomous-mode IRQs in `qmp_usbc_enable_autonomous_mode`/`qmp_usbc_disable_autonomous_mode` requires `qphy_setbits` then `qphy_clrbits` of `IRQ_CLEAR` in `QPHY_PCS_LFPS_RXTERM_IRQ_CLEAR`. In `qusb2_phy_runtime_suspend`, only enable auto-resume when `qphy->mode != PHY_MODE_INVALID`, using `qusb2_setbits` then `qusb2_clrbits` of `cfg->autoresume_en` in `QUSB2PHY_PORT_TEST1`. [F257, F294, F295]
- In `qcom_battmgr_bat_get_property`, `POWER_SUPPLY_PROP_CHARGE_*` must return `-ENODATA` when `unit != QCOM_BATTMGR_UNIT_mAh` and `POWER_SUPPLY_PROP_ENERGY_*` when `unit != QCOM_BATTMGR_UNIT_mWh`. In `qcom_battmgr_sc8280xp_callback`, multiply firmware mWh/mAh, mW, and mV fields in `resp->info` and `resp->status` by `1000` for micro-units. [F223, F305]
- In `qcom_smbb.c`, `hw_fn` callbacks in `smbb_charger_attrs[]` must be strictly monotonic with `index`, and `smbb_charger_attr_write()` must reject `val` outside `[prop->min, prop->max]` with `-EINVAL` (and clamp against `prop->safe_reg`) before calling `smbb_hw_lookup()`, which loops `widx` upward without bound until `(*fn)(widx) > val`. [F255, F308]

## Error Handling

- In `qmp_usbc_enable`, if `qmp_usbc_power_on(phy)` fails after `qmp_usbc_init(phy)`, call `qmp_usbc_exit(phy)` before unlocking `qmp->phy_mutex` and do not increment `qmp->usb_init_count`. In `qmp_usbc_enable_autonomous_mode`/`qmp_usbc_disable_autonomous_mode`, guard `regmap_write` with `if (qmp->tcsr_map && qmp->vls_clamp_reg)` since `"qcom,tcsr-reg"` is optional. [F200, F214]
- `qusb2_phy_init` must unwind in reverse order (`disable_ref_clk` gated by `!qphy->has_se_clk_scheme`, `assert_phy_reset`, `disable_ahb_clk`, `disable_iface_clk`, `poweroff_phy`) and set `qphy->phy_initialized = true` only after `QUSB2PHY_PLL_STATUS` lock succeeds. In `qusb2_phy_probe` and `qcom_usb_hs_phy_probe`, clear optional `qphy->tcsr`, `qphy->cell`, `uphy->reset`, and `uphy->vbus_edev` to `NULL` on ignored `IS_ERR` returns. [F201, F202]
- In `qcom_snps_hsphy_probe` (`phy-qcom-usb-hs-28nm.c`), jump to `unset_1p8_load` to reset `VDDA_1P8` load to `0` if setting `VDDA_3P3` load fails. In `phy-qcom-usb-hs.c`, `qcom_usb_hs_phy_power_on` (`ref_clk`, `sleep_clk`, `v1p8`, `v3p3`, `vbus_notify`), its `err_*` labels, and `qcom_usb_hs_phy_power_off` must stay symmetric in reverse order. [F203, F204]
- In `qcom_battmgr.c`, all `.get_property`/`.set_property` callbacks must return `-EAGAIN` when `!battmgr->service_up`. In `qcom_battmgr_sm8350_callback()`, integer property responses (`BATTMGR_*_PROPERTY_GET`) must check `resp->intval.result` and jump to `out_complete` (signaling `battmgr->ack`) before `switch (property)` on error. In `qcom_smbb.c`, check `if (!chg->dc_disabled)` before `power_supply_changed(chg->dc_psy)` in `smbb_dc_valid_handler` and `smbb_chg_gone_handler`. [F222, F227, F261]

## External Contracts

- `qcom_battmgr_set_charge_control` and NVMEM cells in `qcom_battmgr_charge_control_thresholds_init` use `(target_soc, delta_soc)` where `target_soc = end_soc` and `delta_soc = end_soc - start_soc`. In `qcom_battmgr_charge_control_thresholds_init()`, reject `delta_soc >= end_soc` before `u8` subtraction `end_soc - delta_soc`, and clamp to `[CHARGE_CTRL_START_THR_MIN, MAX]` (`[50, 95]`) and `[CHARGE_CTRL_END_THR_MIN, MAX]` (`[55, 100]`). In `qcom_battmgr_set_charge_start_threshold`/`end_threshold`, reject sysfs values outside those bounds with `-EINVAL` and update both `charge_ctrl_start` and `charge_ctrl_end` on success. [F225, F230, F250, F307]
- In `struct qcom_battmgr_message`, `strval.model` aliases `intval.value` and omits `intval.result`, so `qcom_battmgr_sm8350_callback()` must check `payload_len == sizeof(resp->strval)` and skip `resp->intval.result` for `BATT_MODEL_NAME`. In `qcom_battmgr_sc8280xp_callback()`, `BATTMGR_BAT_INFO` must accept `sizeof(resp->info)` or `sizeof(resp->info) + sizeof(__le32)`, and copy `resp->info` strings via `qcom_battmgr_sc8280xp_strcpy()` (handles Pascal strings and copies up to `BATTMGR_STRING_LEN` = 128 bytes; caller buffers must be `>= BATTMGR_STRING_LEN`). [F245, F246, F247, F276]

## Known Pitfalls

- In `qmp_usbc_power_on()`, `readl_poll_timeout()` on `QPHY_PCS_STATUS` must poll for `!(val & PHYSTATUS)` (active-low busy bit), unlike `qcom_dwmac_sgmii_phy_poll_status()` and `qusb2_phy_init()`. Any `override_param_map` array in `phy-qcom-snps-femto-v2.c` must end with a `{}` sentinel (`prop_name == NULL`) and have at most `NUM_HSPHY_TUNING_PARAMS` entries. [F240, F263]
- In `qcom_battmgr_probe`, `QCOM_BATTMGR_SC8280XP` is `0` (`NULL` in `qcom_battmgr_of_variants[].data`) while unmatched parents default to `QCOM_BATTMGR_SM8350` (`1`), so use `of_match_device(qcom_battmgr_of_variants, dev->parent)`, not `of_device_get_match_data`. Every property in `sm8350_*_props`/`sm8550_bat_props` must have an entry in `sm8350_*_prop_map` and `qcom_battmgr_sm8350_callback` (unmapped slots zero-init to `BATT_STATUS`/`USB_ONLINE`/`WLS_ONLINE`). [F221, F231]
- In `qcom_battmgr_sc8280xp_callback`, check `battmgr->info.last_full_capacity != 0` (and a multiple of 1000) before dividing, setting `battmgr->status.percent = (unsigned int)-1` when zero (`-ENODATA`), and compute `percent` from unscaled `100 * le32_to_cpu(resp->status.capacity)` divided by `last_full_capacity / 1000` to avoid 32-bit overflow on micro-unit `battmgr->status.capacity`. [F270, F271]
- In `qcom_smbb.c`, `smbb_charger_probe()` sets `chg->revision` to `SMBB_MISC_REV2 + 1` (`1..3`) and skips `smbb_charger_setup[]` entries when `r->rev_mask & BIT(chg->revision)`, so `rev_mask` uses 1-based skip bits. In `smbb_battery_get_property()`, check `STATUS_BAT_OK` before `STATUS_BAT_HOT` for `POWER_SUPPLY_PROP_HEALTH` because `smbb_bat_temp_handler()` never clears `STATUS_BAT_HOT`. [F256, F268]
