# OPEN FIRMWARE AND FLATTENED DEVICE TREE — (top level)

This component provides the public kernel header interfaces (`include/linux/of*.h`), Rust device-ID bindings (`rust/kernel/of.rs` and `rust/helpers/of.c`), and the built-in self-test suite (`drivers/of/unittest.c`) for the Open Firmware (OF) and Flattened Device Tree (FDT) subsystem, defining core representations of device tree nodes and properties, iterator macros, address/IRQ/graph/reserved-memory parsing APIs, dynamic changesets/overlays, and `!CONFIG_OF` stubs.

## Architecture & Data Flow
- Under `!CONFIG_OF`, inline stubs for `of_property_read_variable_u{8,16,32,64}_array()`, `of_property_read_string_helper()`, `__of_parse_phandle_with_args()`, and `of_phandle_iterator_next()` must return negative errnos rather than `0`, because unconditionally defined inline wrappers and `of_for_each_phandle()` treat `0` as a valid result or continuation. [F220]
- In `rust/kernel/of.rs`, `of::DeviceId` must remain a `#[repr(transparent)]` wrapper around `bindings::of_device_id` with no extra invariants because `RawDeviceId` and `Adapter::of_id_info` transmute/cast directly between them. Its `RawDeviceIdIndex` implementation must keep `DRIVER_DATA_OFFSET` as `offset_of!(bindings::of_device_id, data)` and `index()` reading `self.0.data as usize`, and constructors must leave `self.0.data` available for `IdArray::new` to overwrite with the table index. [F221, F258]
- `_OF_DECLARE` and `_OF_DECLARE_STUB` macros must initialize `struct of_device_id.data` via `(fn == (fn_type)NULL) ? fn : fn` rather than assigning `fn` directly or casting to `void *`/`fn_type`, preserving compile-time signature checks. [F253]
- In `update_node_properties()`, `prop->next` must be saved into a local variable before calling `of_add_property(dup, prop)` rather than using `for_each_property_of_node()`, because `of_add_property()` unconditionally sets `prop->next = NULL`. [F211]
- When `attach_node_and_children()` attaches a `device_node` to the live tree, it must save and clear `np->child` before linking `np` into `np->parent->child`, clearing `OF_DETACHED` under `devtree_lock`, and calling `__of_attach_node_sysfs(np)` under `of_mutex`, only then recursively attaching the saved children. Because it also overwrites `np->sibling = np->parent->child`, any loop walking a sibling list to call `attach_node_and_children()` (including `unittest_data_add()`) must cache `np->sibling` before the call. [F212, F239]
- Before unflattening an embedded FDT blob in `drivers/of/unittest.c`, `unittest_data_add()` and `unittest_unflatten_overlay_base()` must copy the blob into a buffer aligned to at least `FDT_ALIGN_SIZE` (8 bytes) that stays allocated for the lifetime of the unflattened nodes. In `unittest_data_add()`, `unittest_data` is allocated with `kmalloc(size + FDT_ALIGN_SIZE, GFP_KERNEL)` and aligned via `PTR_ALIGN` into `unittest_data_align`, so error paths must pass `unittest_data` (not `unittest_data_align`) to `kfree()`. [F234, F254]
- In `drivers/of/unittest.c`, the `overlays[]` table must start with `overlay_base` at index 0 (`expected_result == -9999`) and end with a zeroed `{}` sentinel (`name == NULL`). [F235]
- Callers that untrack an overlay via `of_unittest_untrack_overlay()` after `of_overlay_remove(&ovcs_id)` must save `ovcs_id` before `of_overlay_remove()` (which zeroes `*ovcs_id`) and untrack in strict LIFO order matching `track_ovcs_id[]`. Overlays intended to remain active across `of_unittest_remove_tracked_overlays()` (as in `of_unittest_overlay_gpio()`) or testing notifier error injection in `of_unittest_overlay_notify()` must be applied via `overlay_data_apply()` directly rather than `of_unittest_apply_overlay()`. [F214, F222]

## Synchronization
- When splicing nodes or properties into the live tree in `attach_node_and_children()` and `of_unittest_overlay_high_level()`, `of_mutex` must be acquired before `raw_spin_lock_irqsave(&devtree_lock, flags)`, `devtree_lock` must be released before calling `__of_attach_node_sysfs()`, and `of_mutex` must be held and unlocked across every exit path. [F187]
- In `unittest_data_add()`, `of_overlay_mutex_lock()` must be held across `of_resolve_phandles(unittest_data_node)` and the `attach_node_and_children()` loop attaching the subtree to `of_root`, nesting `of_mutex` and `devtree_lock` inside `of_overlay_mutex_lock()`. [F190]
- In `of_unittest_overlay_high_level()`, `overlay_base_root` must have phandles resolved under `of_overlay_mutex_lock()`, `__local_fixups__` and `__symbols__` unlinked, and child `parent` pointers set to `of_root` before taking `of_mutex` to splice `overlay_base_root->child` into `of_root` and attach sysfs entries (`__of_attach_node_sysfs()`, `__of_add_property()`, `__of_add_property_sysfs()`). [F191]
- Overlay notifier callbacks registered via `of_overlay_notifier_register()` (such as `of_notify()`) run while `of_mutex` (and during apply, `of_overlay_phandle_mutex`) is already held, so they must not acquire `of_mutex` or `of_overlay_mutex_lock()`. Broken by: calling `of_add_property()`, `of_changeset_apply()`, `of_overlay_fdt_apply()`, or `of_overlay_remove()` inside `of_notify()`. [F279]

## Object Lifetimes
- `of_find_node_by_name()`, `of_find_node_by_type()`, `of_find_compatible_node()`, `of_find_matching_node_and_match()`, and `of_find_node_with_property()` always call `of_node_put(from)` on a non-NULL `from` argument, so callers not surrendering their reference must call `of_node_get(from)` first. In `of_notify()`, `of_node_get(nd->overlay)` is taken before `switch (action)` to balance `of_find_node_by_name(nd->overlay, ...)`, so any branch or early exit not calling `of_find_node_by_name(nd->overlay, ...)` must call `of_node_put(nd->overlay)`. [F174, F244]
- Scoped node iterators (`for_each_child_of_node_scoped`, `for_each_child_of_node_with_prefix`, `for_each_available_child_of_node_scoped`, `for_each_of_graph_port`, `for_each_of_graph_port_endpoint`) use `__free(device_node)`, so callers must not call `of_node_put(child)` on `break`/`return` and must use `return_ptr` or `no_free_ptr` to keep `child`. [F176]
- Callers of `of_parse_phandle()`, `of_parse_phandle_with_args()`, `of_parse_phandle_with_fixed_args()`, `of_parse_phandle_with_optional_args()`, and `of_parse_phandle_with_args_map()` must call `of_node_put()` on the returned `device_node` (or `out_args->np`) on success. [F261]
- Because `of_changeset_action()` takes its own reference on `np` and `of_changeset_create_node()` returns a node with both the creation reference and the changeset's attach reference held, callers of `of_changeset_create_node()` must call `of_node_put(np)` in addition to `of_changeset_destroy(&chgset)`. [F181]
- `of_find_device_by_node()` and `of_find_i2c_device_by_node()` increment the underlying `struct device` refcount, so callers must release non-NULL results with `platform_device_put()` or `put_device(&client->dev)`. [F265]
- When a driver applies an overlay and populates child platform devices via `of_platform_default_populate()` or `of_platform_populate()` (as in `testdrv_probe()`), teardown (such as `testdrv_remove()`) must call `of_platform_depopulate()` before `of_overlay_remove()`. [F185]

## API Contracts
- `of_node_init()` must be called on any newly allocated `struct device_node` before publication to initialize `node->kobj` with `of_node_ktype` (refcount 1 under `CONFIG_OF_KOBJ`) and `node->fwnode` with `&of_fwnode_ops`. Downcasting `struct fwnode_handle *` to `struct device_node *` must use `to_of_node()` or guard `container_of()` with `is_of_node()` (which checks `!IS_ERR_OR_NULL(fwnode)` and `fwnode->ops == &of_fwnode_ops`). [F194, F251]
- Under `CONFIG_OF`, `struct device_node._flags` and `struct property._flags` are `unsigned long` bitmaps accessed via atomic bitops (`test_bit`, `set_bit`, `clear_bit`, `test_and_set_bit`) in `of_node_*_flag()`, `OF_IS_DYNAMIC()`, `OF_MARK_DYNAMIC()`, and `of_property_*_flag()`, and flag constants (`OF_DYNAMIC` through `OF_OVERLAY_FREE_CSET`) are bit indices, not shifted masks. Broken by: non-atomic `|=`/`&=` updates or passing `BIT(OF_DYNAMIC)` to flag helpers. [F193, F256]
- `of_property_read_variable_u{8,16,32,64}_array()` return the positive element count on success or negative errno on failure, whereas `of_property_read_u{8,16,32,64}_array()` pass `sz_min = sz` and `sz_max = 0` (requiring at least `sz` elements without modifying `out_values` if shorter, while allowing trailing elements) and convert non-negative returns to `0`. [F198, F227]
- `of_property_read_u{8,16,32,64}{,_array,_index}()` and `of_property_read_string{,_index}()` must never modify their output parameter on a non-zero error return. `of_property_read_string{,_array,_index}()` return borrowed `const char *` pointers into the property buffer (never `kfree()`d) and validate NUL termination only up through the requested `index`/`sz` without writing past decoded entries. `of_property_read_string_array()` and `of_property_count_strings()` return the positive string count or negative errno, while `of_property_read_string_index()` normalizes non-negative returns to `0`. [F179, F199, F200, F228]
- When `of_find_node_opts_by_path()` resolves a path or alias without a `:` option delimiter and `opts` is non-NULL, `*opts` must be cleared to `NULL`. [F218]
- `__of_get_address()` multiplexes non-PCI and PCI lookups using `-1` as the inactive selector: `of_get_address()` passes 0-based `index` with `bar_no = -1`, while `of_get_pci_address()` passes `index = -1` with a PCI `bar_no`. [F226]
- `of_range_count()` computes entry count via typed `const __be32 *` pointer subtraction `(parser->end - parser->range) / (parser->na + parser->pna + parser->ns)` and must be called before iterating with `for_each_of_range()` or `for_each_of_pci_range()` because `of_pci_range_parser_one()` advances `parser->range`. [F250]
- When `of_overlay_remove(&ovcs_id)` fails before or during changeset revert (e.g., `OF_OVERLAY_PRE_REMOVE` notifier error or non-topmost overlay), the overlay remains applied and `ovcs_id` stays non-zero; on an `OF_OVERLAY_POST_REMOVE` notifier error, the changeset is reverted/freed and `ovcs_id` is cleared to `0`. [F183]
- Any non-NULL `struct of_dev_auxdata` array passed to `of_platform_populate()` or `of_platform_default_populate()` must end with an empty sentinel entry (`compatible == NULL`). [F230]
- `DeviceId::new` in `rust/kernel/of.rs` initializes `bindings::of_device_id` via `core::mem::zeroed()` and copies `compatible.to_bytes_with_nul()` into `of.compatible`, requiring all fields to be valid when zeroed and `compatible` (with NUL) to fit. [F260]
- `struct of_pdt_ops` implementations must accept a 32-byte `buf` in `nextprop` (returning the first property when `prev == NULL` and `0` on success), return `-1` on error from `getproplen`/`getproperty`, return `0` from `getchild`/`getsibling` when no node exists, and set `*len` to path byte length on `pkg2path` success. [F287]
- `unittest_unflatten_overlay_base()` runs in early boot before slab initialization, so it must allocate via `dt_alloc_memory` (`memblock_alloc_or_panic`) and defer `of_resolve_phandles()` (which uses `kmalloc`) until `of_unittest_overlay_high_level()`. [F278]
- In `drivers/of/unittest.c`, `EXPECT_BEGIN()`, `EXPECT_END()`, `EXPECT_NOT_BEGIN()`, and `EXPECT_NOT_END()` must not be used for `pr_debug()` messages, and nested `EXPECT_BEGIN()` calls must be closed by `EXPECT_END()` in LIFO order. [F288]

## Error Handling
- `of_iomap()` returns `NULL` on failure whereas `of_io_request_and_map()` returns an `IOMEM_ERR_PTR`-encoded error pointer and never `NULL`, so callers must test `of_iomap()` with `!ptr` and `of_io_request_and_map()` with `IS_ERR(ptr)`. [F196]
- When resolving platform device interrupts from DT, a missing IRQ domain must return `-EPROBE_DEFER` without logging an error, whereas a malformed or missing DT IRQ specification must return a negative errno other than `-EPROBE_DEFER`. [F290]
- Overlay notifier callbacks registered with `of_overlay_notifier_register()` (such as `of_notify()`) must wrap negative errnos with `notifier_from_errno(ret)` or return `NOTIFY_DONE`/`NOTIFY_OK`, never raw negative errnos. [F209]
- In `drivers/of/unittest.c`, `overlay_data_apply()` returns `1` on success and `0` on failure, whereas `of_unittest_apply_overlay()` and `of_unittest_apply_overlay_check()` return `0` on success and a negative errno on failure. When `of_overlay_fdt_apply()` returns a negative error in `overlay_data_apply()`, `of_overlay_remove(&info->ovcs_id)` must still be called to clean up any partial changeset and checked against `info->expected_result_remove`. [F208, F215]

## Known Pitfalls
- Converting a potentially `NULL` `struct device_node *` to `struct fwnode_handle *` must use `of_fwnode_handle(node)` rather than `&node->fwnode` because `fwnode` is at a non-zero offset within `struct device_node`. [F252]
- `_OF_DECLARE()` (and `OF_DECLARE_1()`, `OF_DECLARE_2()`, `RESERVEDMEM_OF_DECLARE()`) only emits entries into the `"__<table>_of_table"` linker section when `CONFIG_OF` is enabled and `MODULE` is not defined, degrading to an unused local static struct in loadable modules. [F270]
- `unittest_path()` and `overlay_name_from_nr()` each format into a function-local `static char buf[256]`, so callers must not hold or compare pointers across two calls to the same helper without copying first. [F223]
- In `of_unittest_lifecycle()`, after `/testcase-data/refcount-node`'s refcount reaches zero, unlinking it from `/testcase-data`'s child list before `of_unittest_check_tree_linkage()` must walk raw `np->child` and `sibling` pointers rather than `for_each_child_of_node()` so `of_node_get()` is never called on the zero-refcount node. [F245]
- In `of_unittest_parse_dma_ranges()`, test cases passing an `expect_dma_addr` above `U32_MAX` to `of_unittest_dma_ranges_one()` must be guarded by `IS_ENABLED(CONFIG_ARCH_DMA_ADDR_T_64BIT)` because `of_unittest_dma_ranges_one()` converts addresses using `dma_addr_t`. [F248]
