# MELLANOX MLX5 core VPI driver — drivers/net/ethernet/mellanox/mlx5/core/en

Implements the mlx5e Ethernet NIC and switchdev representor subsystems for RX/TX resource management, PTP hardware timestamping, QoS, health reporting, and TC flower/action hardware offloads. It manages Receive Queue Tables (RQT), RSS contexts (`rx_res.c`, `rss.c`), TX queue selection (`selq.c`), PTP channels (`ptp.c`), representor neigh/bridge/bond/TC plumbing (`rep/`), and the modular TC action parsing, connection tracking (CT), policing/metering, and packet sampling engines (`tc/`).

## Architecture & Data Flow

- In `struct mlx5e_flow_meter_handle`, `meter->meters_obj` is `NULL` when `meter->params.mtu` is non-zero (`alloc_aso == false`), so `meter->meters_obj` (including via `mlx5e_flow_meter_get_base_id`) must only be dereferenced when `!meter->params.mtu`. [F1107]
- A `struct mlx5e_ptp` channel can be opened with only `MLX5E_PTP_STATE_TX` or only `MLX5E_PTP_STATE_RX` set in `c->state` (or `priv->channels.ptp` can be `NULL`), so any access to `c->ptpsq` must be gated by `test_bit(MLX5E_PTP_STATE_TX, c->state)` and any access to `c->rq` must be gated by `test_bit(MLX5E_PTP_STATE_RX, c->state)`. [F1108]
- In `struct mlx5e_rq` and `struct mlx5e_txqsq`, `rq->channel`, `rq->icosq`, and `sq->channel` are `NULL` for PTP queues, so health reporter callbacks must null-check `rq->icosq` before accessing ICOSQ state and null-check `rq->channel` / `sq->channel` before calling `mlx5e_trigger_napi_icosq`. [F1109]
- In `struct mlx5e_rss`, `rss->tir[tt]` and `rss->inner_tir[tt]` are `NULL` when initialized with `MLX5E_RSS_INIT_NO_TIRS` until lazily created by `mlx5e_rss_obtain_tirn`, so callers of `mlx5e_rss_get_tirn` on non-default RSS contexts must first verify `mlx5e_rss_valid_tir(rss, tt, inner)`. [F1110]
- In mlx5e_selq_prepare_params and mlx5e_selq_prepare_htb, selq->standby must first be initialized by copying *selq->active before mutating only the subset of fields (channel/TC/PTP params or HTB maj_id/defcls) relevant to that update. [F1122]
- When updating a channel's XSK state in mlx5e_rx_res_xsk_update, after updating res->rss_rqns[ix] (and vhca_id), both all active RSS contexts (via mlx5e_rx_res_rss_enable) and the channel's direct RQT (via mlx5e_rx_res_channel_activate_direct) must be redirected. [F1123]
- In mlx5e_rx_res_packet_merge_set_param, changes to res->pkt_merge_param must be synchronized under res->pkt_merge_param_sem and propagated to all non-NULL res->rss[ix] contexts and all res->max_nch direct_tir objects, while res->ptp.tir does not share packet-merge state. [F1124]
- In mlx5e_rss_set_hash_fields, when rss->params.inner_ft_support is enabled, rss->rx_hash_fields[tt] must be applied to both the outer TIR (inner=false) and inner TIR (inner=true), reverting rss->rx_hash_fields[tt] and the outer TIR on failure. [F1127]
- In ptp.c, a metadata_id removed from ptpsq->ts_cqe_pending_list due to timeout in mlx5e_ptpsq_mark_ts_cqes_undelivered has pos->inuse cleared and ptpsq->metadata_map.undelivered_counter incremented, so mlx5e_ptp_handle_ts_cqe must check pending_cqe_list->nodes[metadata_id].inuse and decrement undelivered_counter if false. [F1131]
- In mlx5e_rep_changelowerstate_event, only one rx_rule per bond_metadata may exist: when a slave representor becomes active, every passive lower representor must delete its rx_rule via mlx5e_rep_bond_update(priv, true) and bond its egress ACL before mlx5e_rep_bond_update(netdev_priv(netdev), false) adds the active slave's rx_rule. [F1133]

## Synchronization

- In `mlx5e_selq_init`, `init_params` must be populated with non-zero default queue counts (`num_regular_queues = 1`, `num_channels = 1`, `num_tcs = 1`) before `rcu_assign_pointer(selq->active, init_params)` publishes it, so concurrent `mlx5e_select_queue` calls before channel open do not crash or loop infinitely in `mlx5e_txq_to_ch_ix`. [F1077]
- On the TX datapath, `mlx5e_qid_from_qos` may read `chs->params` without locking only after the caller has verified `selq->htb_maj_id != 0` inside an RCU read-side critical section, and channel parameter changes (`num_channels` or PTP TX state) must be rejected whenever `mlx5e_selq_is_htb_enabled(&priv->selq)` is true. [F1079]
- In `mlx5e_open_qos_sq`, `priv->htb_qos_sq_stats[node_qid]` must be stored via `WRITE_ONCE` before `priv->htb_max_qos_sqs` is incremented using `smp_store_release`, pairing with `smp_load_acquire(&priv->htb_max_qos_sqs)` in statistics readers. [F1080]
- In `mlx5e_qos_alloc_queues`, `chs->c[i]->qos_sqs_size` must be written with `WRITE_ONCE` followed by `smp_wmb()` before publishing `chs->c[i]->qos_sqs` via `rcu_assign_pointer`, pairing with `smp_rmb()` in `mlx5e_napi_poll`. [F1081]
- `mlx5e_rep_bond_enslave` and `mlx5e_rep_bond_unslave` must be called with `rtnl_lock` held (`ASSERT_RTNL()`), which serializes all access to `uplink_priv->bond->metadata_list` and `mdata->slaves_list`. [F1084]
- In `mlx5e_rep_neigh_update`, `n->ha`, `n->nud_state`, `n->dead`, and `READ_ONCE(nhe->neigh_dev) == n->dev` must be snapshotted together under `read_lock_bh(&n->lock)` before dropping `n->lock` to call the sleeping `mlx5e_rep_update_flows` under `rtnl_lock()` and `esw->offloads.encap_tbl_lock`. [F1087]
- When `mlx5_esw_bridge_switchdev_event` handles `SWITCHDEV_FDB_DEL_TO_BRIDGE` for a peer device, it must call `mlx5_esw_bridge_fdb_mark_deleted` synchronously before queuing the asynchronous `mlx5_bridge_switchdev_fdb_work` on `br_offloads->wq`, preventing `mlx5_esw_bridge_update_work` from refreshing the entry in the interim. [F1089]
- In `mlx5e_tc_act_stats_del_flow`, `handle->ht_lock` must be held across `rhashtable_lookup_fast` and `rhashtable_remove_fast`, and removed `struct mlx5e_tc_act_stats` entries must be freed via `kvfree_rcu(act_stats, rcu_head)` to synchronize with `rcu_read_lock()` readers in `mlx5e_tc_act_stats_fill_stats`. [F1092]
- In `tc/meter.c`, `flow_meters->sync_lock` must be held for all meter hashtable, bitmap, and refcount operations (`mlx5e_tc_meter_get`, `mlx5e_tc_meter_put`, `mlx5e_tc_meter_update`, `mlx5e_tc_meter_replace`), and `flow_meters->aso_lock` must be held in `mlx5e_tc_meter_modify` across WQE build, post, and CQ poll. [F1093]

## Object Lifetimes

- In `sample_modify_hdr_get`, `mod_acts` (`struct mlx5e_tc_mod_hdr_acts *`) is deallocated via `mlx5e_mod_hdr_dealloc(mod_acts)` once `mlx5e_tc_match_to_reg_set` succeeds, on both the success path and the `mlx5_modify_header_alloc` failure path. [F1060]
- `mlx5e_tc_sample_unoffload` and the error rollback of `mlx5e_tc_sample_offload` must delete resources in strict reverse order (`pre_rule`, `sample_restore_put`, `mapping_remove`, `sampler_put`, and finally `del_post_rule` if `post_rule` exists) so that firmware syndromes are not triggered. [F1061]
- `mlx5e_post_meter_add_rule` borrows `act_counter` or `drop_counter` into `attr->counter` for `mlx5_eswitch_add_offloaded_rule` and must clear `MLX5_FLOW_CONTEXT_ACTION_COUNT` from `attr->action` before returning so that `free_branching_attr` does not destroy the meter-owned counter. [F1062]
- `mlx5_ct_fs_hmfs_fill_rule_actions` acquires a reference on `attr->counter`'s HWS action via `mlx5_fc_get_hws_action`, so `mlx5_ct_fs_hmfs_ct_rule_update` must release `attr->counter` on `mlx5hws_bwc_rule_action_update` failure and release the previous `hmfs_rule->counter` on success. [F1063]
- An offloaded police action holds one base reference on its `struct mlx5e_flow_meter_handle`, so `tc_act_police_offload` must call `mlx5e_tc_meter_put` after `mlx5e_tc_meter_update` when `mlx5e_tc_meter_get` succeeds, and `tc_act_police_destroy` must call `mlx5e_tc_meter_put` twice after `mlx5e_tc_meter_get`. [F1064]
- `mlx5e_tc_int_port_cleanup_rep_rx` must set `int_port->rx_rule = NULL` after deleting `int_port->rx_rule` under `ppriv->int_ports_lock`, because `mlx5e_int_port_remove` later checks `if (int_port->rx_rule)` when the last reference on `int_port` is dropped via `mlx5e_tc_int_port_put`. [F1065]
- `mlx5e_tc_post_act_unoffload` must clear `handle->rule = NULL` after calling `mlx5e_tc_rule_unoffload`, because `mlx5e_tc_post_act_del` checks `!IS_ERR_OR_NULL(handle->rule)` and invokes `mlx5e_tc_post_act_unoffload` if `handle->rule` is still non-NULL. [F1066]
- `mlx5e_rep_neigh_entry_lookup` must be called under `rpriv->neigh_update.encap_lock` or `rcu_read_lock()` and increments `nhe->refcnt` on a match, requiring the caller to release the returned entry via `mlx5e_rep_neigh_entry_release` in non-atomic context (since `mlx5e_rep_neigh_entry_remove` locks `encap_lock`). [F1067]
- `mlx5e_rep_neigh_cleanup` must unregister `neigh_update->netevent_nb` before calling `flush_workqueue(priv->wq)` and `cancel_delayed_work_sync(&rpriv->neigh_update.neigh_stats_work)`, and must flush both work items before destroying `neigh_update->encap_lock` and `neigh_update->neigh_ht`. [F1068]

## API Contracts

- `mlx5e_selq_prepare_params` and `mlx5e_selq_prepare_htb` must be called with `selq->state_lock` held while `!selq->is_prepared`, and every prepare call must be paired with either `mlx5e_selq_apply` (which swaps `selq->active` and `selq->standby` and runs `synchronize_net()`) or `mlx5e_selq_cancel`. [F1071]
- Unlike `mlx5e_tc_post_act_init`, `mlx5e_tc_int_port_init` returns `NULL` (converting any `IS_ERR` from `mapping_create_for_id` to `NULL`), whereas `mlx5e_tc_int_port_get` always returns `ERR_PTR` on failure (including `-EOPNOTSUPP` when `priv` is `NULL`). [F1102]
- `mlx5e_reporter_tx_timeout` (via `mlx5e_tx_reporter_timeout_recover` and `mlx5e_tx_timeout_ctx.status`) returns `0` when a single SQ's EQ was recovered, `1` when all channels were reopened via `mlx5e_safe_reopen_channels`, or a negative errno if both recovery steps failed. [F1105]
- `fill_meter_params_from_act` converts `rate_bytes_ps` to bits/s (`<< 3`) for `MLX5_RATE_LIMIT_BPS` while leaving `rate_pkt_ps` and `burst_pkt` unscaled for `MLX5_RATE_LIMIT_PPS`, because `mlx5e_tc_meter_modify` scales PPS `rate` (`<< 10`) and `burst` (`<< 7`) before `mlx5e_flow_meter_cir_calc`. [F1116]
- `mlx5e_int_port_metadata_alloc` sets `0xf << ESW_VPORT_BITS` in `*id`, so `mlx5e_int_port_metadata_free` must mask `id` with `(1 << ESW_VPORT_BITS) - 1` before `mapping_remove`, and `metadata_reg_c_0` matches must use `mlx5e_tc_int_port_get_metadata_for_match` rather than `mlx5e_tc_int_port_get_metadata`. [F1119]
- `mlx5e_tc_act_pedit_parse_action` requires `act->mangle.mask` (inverted, where 0-bits select modified bits) and `act->mangle.val` to hold network-byte-order bytes cast to `u32`, inverting `~mask` before `set_pedit_val` ORs active-high masks and masked values into `hdrs[cmd].masks` and `hdrs[cmd].vals`. [F1145]
- In `reporter_tx.c`, `err_ctx.ctx` passed to `mlx5e_health_report()` must match the pointer type expected by both `err_ctx.recover` and `err_ctx.dump` (`struct mlx5e_txqsq *` for CQE errors, `struct mlx5e_tx_timeout_ctx *` for TX timeouts via `mlx5e_tx_reporter_timeout_dump()`, and `struct mlx5e_ptpsq *` for unhealthy PTP SQs). [F1194]
- Netdevice and switchdev notifier handlers in `rep/bond.c` and `rep/bridge.c` must verify that a `struct net_device *` is an mlx5 eswitch representor (`mlx5e_eswitch_rep()` or `mlx5e_eswitch_vf_rep()`) before casting `netdev_priv(dev)` to `struct mlx5e_priv *` and dereferencing `priv->ppriv` as `struct mlx5e_rep_priv *`. [F1195]
- Shared buffer pool configuration and queries (`mlx5e_port_query_pool`, `mlx5e_port_set_sbpr`, `mlx5e_port_set_sbcm`) in `port_buffer.c` must be guarded by `MLX5_CAP_GEN(mdev, sbcam_reg)`. [F1212]

## Error Handling

- In `ct_fs_smfs.c` and `ct_fs_hmfs.c`, the underlying `mlx5_smfs_*` and `mlx5hws_*` object creation APIs return `NULL` on failure, so `mlx5_ct_fs_ops` implementations must check `!ptr` on those calls and translate failures to `-EINVAL` or `ERR_PTR(-EINVAL)` rather than using `IS_ERR` / `ERR_CAST`. [F1103]
- `mlx5e_htb_get_txq_by_classid`, `mlx5e_htb_leaf_alloc_queue`, and `mlx5e_select_htb_queue` return a signed `int` that is either a negative errno (or `0` when no default class exists in `mlx5e_select_htb_queue`) or a positive `u16` TXQ index, and callers must store the result in a signed `int` and check `< 0` or `> 0` before narrowing to `u16`. [F1104]
- In `mlx5e_rx_res`, `res->rss[i]` slots are nullable pointers (never `ERR_PTR`), so `mlx5e_rx_res_rss_init_def` and `mlx5e_rx_res_rss_init` must validate `IS_ERR(rss)` on `mlx5e_rss_init` before storing `rss` into `res->rss[i]`. [F1111]
- In `mlx5e_ptp_open_tx_cqs` and `mlx5e_rx_res_channels_init`, where two sequential init loops share one loop variable (`tc` or `ix`), the first error-unwind loop must reset it (`tc = num_tc` or `ix = res->max_nch`) before falling through to the second unwind loop. [F1168]
- When `tc_act_can_offload_mirred` rejects a forwarding action because `out_dev` is not on the same switch hardware, it must not set `parse_state->extack` if `parse_attr->filter_dev != priv->netdev`. [F1255]

## External Contracts

- `mlx5e_rep_setup_ft_cb` and `mlx5e_rep_indr_setup_ft_cb` only accept `TC_SETUP_FT` rules on `chain_index == 0` with `prio < mlx5_chains_get_prio_range(esw_chains(esw))`, and must remap `chain_index` to `mlx5_chains_get_nf_ft_chain(esw_chains(esw))` and increment `prio` by 1 on a local `flow_cls_offload` copy. [F1120]
- In `mlx5_esw_bridge_port_obj_add`, `mlx5_esw_bridge_port_obj_del`, and `mlx5_esw_bridge_port_obj_attr_set`, `handled` must be set to `true` only after verifying `dev` belongs to `br_offloads->esw` via `mlx5_esw_bridge_rep_vport_num_vhca_id_get` (or its lower-dev variant), returning `0` otherwise. [F1253]

## Known Pitfalls

- `mlx5e_ptp_close_txqsq` must only call `cancel_work_sync(&ptpsq->report_unhealthy_work)` when `current_work() != &ptpsq->report_unhealthy_work`, because `mlx5e_ptpsq_unhealthy_work` itself invokes `mlx5e_tx_reporter_ptpsq_unhealthy_recover`, which calls `mlx5e_ptp_close`. [F1072]
- In `mlx5e_alloc_neigh_update_work` (invoked from atomic netevent notifier context), `mlx5e_rep_neigh_entry_lookup` must be called only after all fallible allocations succeed so `mlx5e_rep_neigh_entry_release`—which acquires the sleeping `rpriv->neigh_update.encap_lock` mutex on last reference—is never called in atomic context. [F1086]
- Any `struct mlx5e_neigh` key passed to `mlx5e_rep_neigh_entry_lookup` or `mlx5e_rep_neigh_entry_create` must be zero-initialized (`= {}`) before copying an IPv4 address into `dst_ip`, because `mlx5e_neigh_ht_params` hashes the entire `sizeof(struct mlx5e_neigh)` including the unused bytes of the `in6_addr` union. [F1113]
- Any `struct mlx5_mapped_obj` passed to `mapping_add` on `esw->offloads.reg_c0_obj_pool` (as in `mlx5e_tc_sample_offload` and `mlx5e_int_port_add`) must be zero-initialized (`= {}`) so that alignment padding and unused union bytes do not corrupt the fixed-size `sizeof(struct mlx5_mapped_obj)` mapping key. [F1114]
- In mlx5e_rss_set_rxfh, changing rss->hash.hfunc must set both changed_hash and changed_indir so that mlx5e_rss_apply recomputes the RQT indirection table (which bit-inverts indices when hfunc is ETH_RSS_HASH_XOR), and if mlx5e_rss_apply fails, rss must be restored from old_rss via mlx5e_rss_copy. [F1125]
- When copying struct mlx5e_rss in mlx5e_rss_copy, the destination's preallocated to->indir.table pointer must be saved before struct assignment (*to = *from), restored afterward, and populated via memcpy. [F1126]
- In `mlx5_esw_bridge_switchdev_event`, `SWITCHDEV_FDB_DEL_TO_BRIDGE` for peer devices falls through to `SWITCHDEV_FDB_ADD_TO_DEVICE` and `SWITCHDEV_FDB_DEL_TO_DEVICE`, so the `add` flag passed to `mlx5_esw_bridge_init_switchdev_fdb_work` must be computed as `event == SWITCHDEV_FDB_ADD_TO_DEVICE`. [F1163]
- In `verify_uplink_forwarding`, the input representor netdev must be retrieved from `mlx5e_rep_to_rep_priv(attr->esw_attr->in_rep)->netdev` rather than `priv->netdev`, because in LAG mode `priv` is the master uplink's private data and may not match the input vport. [F1172]
- In `parse_mirred`, `is_duplicated_output_device` and `parse_state->ifindexes` must record `out_dev->ifindex` before `out_dev` is unwrapped via `macvlan_dev_real_dev`, `get_fdb_out_dev`, or `mlx5e_tc_act_vlan_add_push_action`, while destination vport and `mdev` are read from `netdev_priv(out_dev)` after unwrapping. [F1173]
