# BLUETOOTH SUBSYSTEM — net/bluetooth (part 5)

This unit implements the Bluetooth Management (`mgmt`) protocol (`mgmt.c`, `mgmt_util.c`, `mgmt_config.c`) and the Microsoft vendor HCI extension (`msft.c`) for controller-offloaded LE advertisement monitoring and RSSI filtering.

## Architecture & Data Flow
- `HCI_MGMT_VAR_LEN` handlers must verify exact payload length (`hci_mgmt_cmd` only checks `len >= handler->data_len`): `__le16`-count array handlers (`load_link_keys`, `load_irks`, `load_long_term_keys`, `load_conn_param`, `set_blocked_keys`, `start_service_discovery`) must bound count by `(U16_MAX - sizeof(*cp)) / sizeof(elem)` and require `struct_size == len`, while `mgmt_hci_cmd_sync` requires `len == offsetof(struct mgmt_cp_hci_cmd_sync, params) + le16_to_cpu(cp->params_len)`. [F203, F204, F268]
- `add_adv_patterns_monitor*` require `len == sizeof(*cp) + cp->pattern_count * sizeof(struct mgmt_adv_pattern)` (`len > sizeof(*cp)`), and `parse_adv_monitor_pattern` must check `offset < HCI_MAX_EXT_AD_LENGTH` and `offset + length <= HCI_MAX_EXT_AD_LENGTH`. `add_advertising` and `add_ext_adv_data` require `data_len == sizeof(*cp) + cp->adv_data_len + cp->scan_rsp_len` with both `cp->data` and `cp->data + cp->adv_data_len` passing `tlv_data_is_valid`. [F206, F208]
- `set_scan_params` and `set_mesh` must verify endian-converted LE scan interval/period and window are in `0x0004..0x4000` with `window <= interval`/`period`. In `eir_has_uuids`, each field must check `field_len == 0` and `eir_len - parsed < field_len + 1` before reading `eir[1]`, and UUID loops must use additive bounds (`i + 3/5/17 <= field_len`). [F209, F215]
- `msft_vendor_evt` and sub-handlers like `msft_monitor_device_evt` must pull bytes sequentially via `msft_skb_pull` (`msft->evt_prefix_len`, 1-byte event code, then event struct) and check for `NULL`. `msft_add_monitor_sync` packs `struct msft_le_monitor_advertisement_pattern` by advancing `offset += sizeof(*pattern) + entry->length` (`3 + entry->length`) while setting `pattern->length = entry->length + 2`. [F210, F241]
- `read_ext_index_list` replaces `HCI_MGMT_INDEX_EVENTS`/`HCI_MGMT_UNCONF_INDEX_EVENTS` with `HCI_MGMT_EXT_INDEX_EVENTS` on `sk`, and `read_ext_controller_info` replaces `HCI_MGMT_DEV_CLASS_EVENTS`/`HCI_MGMT_LOCAL_NAME_EVENTS` with `HCI_MGMT_EXT_INFO_EVENTS`; thus `mgmt_index_added`/`mgmt_index_removed` must emit both legacy and `MGMT_EV_EXT_INDEX_*` events, and every path emitting CoD/name events or updating `dev_class`, `dev_name`, `short_name`, or `appearance` (`set_appearance`) must call `ext_info_changed`. [F194, F195, F272]
- In `mgmt_connect_failed`, if `test_and_clear_bit(HCI_CONN_MGMT_CONNECTED, &conn->flags)` succeeds, call `mgmt_device_disconnected` instead of emitting `MGMT_EV_CONNECT_FAILED`. Before `hci_disable_advertising_sync` in `mesh_send_done_sync` or `remove_advertising_sync`, check `list_empty(&hdev->adv_instances)`; when modifying or expiring `hdev->cur_adv_instance` in `mesh_send_sync`, `adv_expire_sync`, `add_advertising`, or `add_ext_adv_data`, call `cancel_adv_timeout(hdev)`. [F185, F186, F200]
- Userspace advertising instance IDs in `mgmt.c` are `1..hdev->le_num_of_adv_sets` (`0x00` is `MGMT_OP_SET_ADVERTISING`; `hdev->le_num_of_adv_sets + 1` is reserved for `mesh_send_sync` and hidden by `read_adv_features`). `requested_adv_flags_are_valid` must reject bits outside `get_supported_adv_flags(hdev)` and multiple secondary PHY bits in `MGMT_ADV_FLAG_SEC_MASK` (`phy_flags && (phy_flags ^ (phy_flags & -phy_flags))`). [F211, F227]
- `mgmt_get_adv_discov_flags` and `mgmt_get_connectable` must check `pending_find(MGMT_OP_SET_DISCOVERABLE/CONNECTABLE, hdev)` before reading `hdev->dev_flags`. In `get_conn_info`, test expiration with `time_after(jiffies, conn->conn_info_timestamp + msecs_to_jiffies(conn_info_age)) || !conn->conn_info_timestamp`. [F193, F232]
- `hdev->advmon_pend_notify` tracks unnotified entries in `hdev->monitored_devices`: `msft_device_found` sets it `true`, `msft_resume_sync`/`msft_do_close` clear it when purging `hdev->monitored_devices`, and `mgmt_adv_monitor_device_found` clears it before iterating `hdev->monitored_devices` and must set it back to `true` if any remaining entry has `!dev->notified` (no early `break`). [F201, F229]
- `mgmt_mesh_foreach/next/find` must iterate `&hdev->mesh_pending` (never `&hdev->mgmt_pending`). `mgmt_mesh_add` must skip `0` on `hdev->mesh_send_ref` wrap (`1..255`) so `cancel->handle == 0` in `send_cancel` remains the wildcard; in `send_cancel` and `mgmt_cleanup`, `mgmt_mesh_next` loops rely on `mesh_send_complete` calling `mgmt_mesh_remove(mesh_tx)` on every non-NULL `mesh_tx`. [F212, F220, F225]
- Skip `HCI_QUIRK_RAW_DEVICE` controllers in `read_*index_list` and `mgmt_index_added`/`mgmt_index_removed`. `is_configured` and `get_missing_options` treat `hdev` as unconfigured when `HCI_QUIRK_EXTERNAL_CONFIG` lacks `HCI_EXT_CONFIGURED`, or when `HCI_QUIRK_INVALID_BDADDR`/`HCI_QUIRK_USE_BDADDR_PROPERTY` has `hdev->public_addr == BDADDR_ANY`. In `read_*index_list` and `get_connections`, the second pass must reset the counter and recompute the response count and `mgmt_cmd_complete` size. [F226, F252, F254]
- New `mgmt_handlers[]` entries must add their `MGMT_OP_*` to `mgmt_commands[]` (and `mgmt_untrusted_commands[]` if `HCI_MGMT_UNTRUSTED`). `exp_features[]` must end with `EXP_FEAT(NULL, NULL)`. Exported `msft.c` signature changes must update both `#if IS_ENABLED(CONFIG_BT_MSFTEXT)` and `#else` stubs in `msft.h`. In `msft_suspend_sync` and `reregister_monitor`, the `idr_get_next(&hdev->adv_monitors_idr, &handle)` loop must increment `handle++` every iteration. [F197, F202, F214, F223]

## Synchronization
- Lock order is `hdev->req_lock` -> `hdev->lock` -> `msft->filter_lock`, and `hdev->lock` -> `hdev->mgmt_pending_lock`; neither `hdev->lock` nor `msft->filter_lock` may be held across `__hci_cmd_sync`, and `mgmt_pending_foreach` callbacks (under `hdev->mgmt_pending_lock`) must never call `mgmt_pending_find/add/remove/listed/valid` or `hci_dev_lock` on `hdev`. [F168, F259, F261]
- For `hdev->mgmt_pending` commands, `hci_cmd_sync` workers (`set_powered_sync`, `set_discoverable_sync`, `mgmt_add_adv_patterns_monitor_sync`, `set_name_sync`) must check `__mgmt_pending_listed` under `hdev->mgmt_pending_lock` (returning `-ECANCELED` if unlinked) and read parameters from `cmd->param`/`cmd->user_data` before unlocking (not `hdev` fields like `hdev->dev_name` updated after queueing); completion callbacks (`mgmt_set_discoverable/connectable/powered_complete`) must return before `hci_dev_lock(hdev)` if `err == -ECANCELED` or `!mgmt_pending_valid(hdev, cmd)`, then call `mgmt_pending_free(cmd)`. [F160, F161, F163]
- Asynchronous `hci_cmd_sync_queue` callbacks (`add_device_complete`, `disconnect_sync`, `unpair_device_sync`, `get_conn_info_sync`, `get_clock_info_sync`) must re-lookup `struct hci_conn_params` or `struct hci_conn` by address when running rather than caching pointers or flags across the lock drop. [F188]
- Under `read_lock(&hci_dev_list_lock)`: in `read_*index_list`, use `GFP_ATOMIC` and call `mgmt_cmd_complete`/`mgmt_cmd_status` only after `read_unlock`; in `mgmt_cleanup`, call `mesh_send_complete` with `silent = true` so `mgmt_mesh_remove` unlinks `mesh_tx` and drops `mesh_tx->sk` without allocating an SKB under the rwlock. [F158, F257]
- During MSFT suspend/resume, `msft->suspending` and `msft->resuming` must be set so `msft_add_monitor_pattern`/`msft_remove_monitor` return `-EBUSY` and `msft_le_cancel_monitor_advertisement_cb` skips `hci_free_adv_monitor` and `msft_monitor_device_del` while `msft->suspending`; `msft_le_monitor_advertisement_cb` must call `hci_free_adv_monitor(hdev, monitor)` under `hdev->lock` on short response, non-zero `rp->status`, or `kmalloc` failure. [F155, F171]
- Powering off in `set_powered` (`cp->val == 0x00`) must call `hci_cmd_sync_cancel_sync(hdev, -EHOSTDOWN)` before queueing `set_powered_sync`. In `set_blocked_keys`, mutations to `hdev->blocked_keys` must hold `hci_dev_lock(hdev)`, use `hci_blocked_keys_clear(hdev)` (`list_del_rcu` + `kfree_rcu`), and initialize each `struct blocked_key` before `list_add_rcu`. [F262, F263]

## Object Lifetimes
- `mgmt_alloc_skb` reserves `sizeof(struct mgmt_hdr)` headroom and sets `bt_cb(skb)->mgmt`, which `mgmt_send_event_skb` / `mgmt_event_skb` requires before pushing `struct mgmt_hdr` and consuming `skb` via `kfree_skb(skb)`; `mgmt_send_adv_monitor_device_found` borrows `skb` and prepends `__le16 monitor_handle` to `skb->data` (`skb->len` bytes), so it must run before `mgmt_event_skb` pushes `struct mgmt_hdr`. [F145, F235, F265]
- `mgmt_pending_new` commands are unlinked and freed with `mgmt_pending_free`, whereas `mgmt_pending_add` commands must be unlinked via `mgmt_pending_remove`/`mgmt_pending_valid` before `mgmt_pending_free`; `mgmt_pending_foreach(..., remove = true, ...)` unlinks `cmd->list` before `cb` and calls `mgmt_pending_free(cmd)` after `cb`, so `cb` and `cmd->cmd_complete` (`pairing_complete`, `addr_cmd_complete`, `generic_cmd_complete`) must not call `mgmt_pending_remove` or `mgmt_pending_free`. [F146, F148]
- `__mgmt_power_off` must drain `hdev->mgmt_pending` via `mgmt_pending_foreach(0, hdev, true, cmd_complete_rsp, &match)` (`MGMT_STATUS_INVALID_INDEX` if `HCI_UNREGISTER`, else `MGMT_STATUS_NOT_POWERED`) before connection teardown or `mgmt_index_removed`, and `cmd_complete_rsp` must call `hci_cmd_sync_dequeue(match->hdev, NULL, cmd, NULL)` before completing and freeing `cmd`. In `mgmt_index_removed`, `cancel_delayed_work_sync` on `discov_off`, `service_cache`, and `rpa_expired` must only run if `hci_dev_test_flag(hdev, HCI_MGMT)`. [F162, F165, F256]
- `settings_rsp` and `sk_lookup` call `sock_hold(match->sk)` on the first match when `match->sk == NULL`, so `struct cmd_lookup` callers must initialize `match.sk = NULL` and call `sock_put(match.sk)` when non-NULL. `__add_adv_patterns_monitor` must call `hci_free_adv_monitor(hdev, m)` on synchronous error, while `mgmt_add_adv_patterns_monitor_complete` increments `hdev->adv_monitors_cnt` and updates `monitor->state` only when `!status`. [F149, F151]
- In `pair_device`, drop `conn` with `hci_conn_drop(conn)` on error before `cmd->user_data = hci_conn_get(conn)`; afterward, `pairing_complete` must clear `conn->connect_cfm_cb`, `conn->security_cfm_cb`, and `conn->disconn_cfm_cb` and call both `hci_conn_drop` and `hci_conn_put`. [F150]
- `msft_do_open` must free any existing `msft->evt_prefix` and reset `evt_prefix`, `evt_prefix_len`, and `features` before `read_supported_features`, and clear `hdev->msft_data = NULL` and free `msft` on failure. `msft_do_close` must free `msft->handle_map` and `msft->address_filters` locally without cancel HCI commands, reset each offloaded monitor's `state` to `ADV_MONITOR_STATE_REGISTERED`, and purge `hdev->monitored_devices` via `msft_monitor_device_del`. [F245, F246]
- `msft_add_address_filter_sync` and `msft_cancel_address_filter_sync` must check `hdev->msft_data` and `test_bit(HCI_UP, &hdev->flags)` before dereferencing `address_filter`; in `msft_remove_addr_filters_sync`, an `address_filter` unlinked while in `AF_STATE_ADDING` must be set to `AF_STATE_REMOVING` and not freed or moved to `head`. [F156, F170]

## API Contracts
- Handlers that can run while `hdev` is powered off (`set_powered` with `cp->val == 1`, `add_uuid`, `remove_uuid`, `set_dev_class`, `remove_adv_monitor`) must use `hci_cmd_sync_submit` rather than `hci_cmd_sync_queue`. `link_to_bdaddr` maps `CIS_LINK`, `BIS_LINK`, `PA_LINK`, and `LE_LINK` to LE address types, whereas `mgmt_device_disconnected` only emits `MGMT_EV_DEVICE_DISCONNECTED` for `ACL_LINK`, `LE_LINK`, and `BIS_LINK`. [F164, F179]
- `msft_find_handle_data(hdev, handle, is_mgmt)` matches `entry->mgmt_handle` when `is_mgmt == true` and `entry->msft_handle` when `is_mgmt == false`. In `read_def_system_config` and `set_def_system_config`, TLV `0x001b` (`def_le_autoconnect_timeout`) must be converted between wire milliseconds and `hdev->def_le_autoconnect_timeout` jiffies. [F182, F183]
- Callers of `mgmt_mesh_add` (`mesh_send`) must verify `len <= MGMT_MESH_SEND_SIZE + 31` (`sizeof(mesh_tx->param)`). Any `mgmt_pending_cmd` using `addr_cmd_complete` must have `cmd->param` starting with `struct mgmt_addr_info` and `cmd->param_len >= sizeof(struct mgmt_addr_info)`. `HCI_QUIRK_*` and `dev_flags` on `hdev` must be accessed via `hci_test_quirk` and `hci_dev_test/set/clear_flag`, never `test_bit` on `&hdev->flags`. [F205, F242, F244]

## Error Handling
- `mgmt_status(int err)` maps `err < 0` via `mgmt_errno_status()` and `0 <= err < ARRAY_SIZE(mgmt_status_table)` via `mgmt_status_table`, so negative errnos must not be truncated to `u8`. `mgmt_alloc_skb` and `hci_conn_params_add` return `NULL` (`!ptr`), whereas `hci_connect_acl`, `hci_connect_le_scan`, and `hci_add_adv_instance` return `ERR_PTR` (`IS_ERR(ptr)`). [F173, F176, F177]
- `set_default_phy_complete` and `read_local_oob*_complete` must check both `!skb` and `IS_ERR(skb)` on `cmd->skb` before reading `skb->data` or calling `kfree_skb(skb)`; in `msft_add_address_filter_sync`, if `IS_ERR(skb)`, set `skb = NULL` before `goto done;`. `msft_le_set_advertisement_filter_enable_cb` must treat HCI status `0x0C` as success alongside `0x00` and update `msft->filter_enabled = cp->enable`. In `load_link_keys`, `load_long_term_keys`, and `load_conn_param`, invalid or blocked entries must be skipped with `continue`. [F174, F175, F251, F269]

## External Contracts
- In `add_ext_adv_params`, check `data_len < MGMT_ADD_EXT_ADV_PARAMS_MIN_SIZE` and read optional fields (`timeout`, `duration`, `min_interval`, `max_interval`, `tx_power`) only when their `MGMT_ADV_PARAM_*` flag bit is set. In `mgmt_device_found`, when `rssi == HCI_RSSI_INVALID`, `!hdev->discovery.report_invalid_rssi`, and `link_type == ACL_LINK`, set `ev->rssi = 0`. [F218, F219]
- BR/EDR link key paths (`load_link_keys`, `mgmt_new_link_key`) must use `BDADDR_BREDR`, whereas SMP LE key paths (`load_long_term_keys`, `load_irks`, `mgmt_new_ltk/irk/csrk`) must use `BDADDR_LE_PUBLIC`/`BDADDR_LE_RANDOM`; `load_long_term_keys` and `load_link_keys` must skip debug keys (`MGMT_LTK_P256_DEBUG` and `HCI_LK_DEBUG_COMBINATION`). [F228, F270]
- In `read_exp_features_info` and `set_exp_feature` (`HCI_MGMT_HDEV_OPTIONAL`), `read_exp_features_info` must include global features (`debug_uuid`, `iso_socket_uuid`) when `hdev == NULL` and guard controller features with `if (hdev && ...)`, while `set_exp_feature` callbacks must validate `hdev`. `set_def_system_config` must validate all TLV entries in a first pass before mutating `hdev` in the second pass, ignoring unknown TLV types with `bt_dev_warn`. [F267, F274]

## Known Pitfalls
- In `load_conn_param`, initialize `bool update = false;` inside the `for` loop before `if (!i && param_count == 1)`. Helpers taking wire-format little-endian values (`mgmt_adv_monitor_removed` `__le16 handle`, `user_pairing_resp` `__le32 passkey`) must type the parameter as `__le16`/`__le32` without a second `cpu_to_le*`. [F180, F216]
- In `msft_monitor_device_evt`, searching `&msft->address_filters` must record a match in a separate `address_filter = NULL` pointer (not loop cursor `n`); when `HCI_QUIRK_USE_MSFT_EXT_ADDRESS_FILTER` is set, pattern monitor events in `msft->handle_map` must not fall through to `report_state`, and a found event on `MSFT_MONITOR_ADVERTISEMENT_TYPE_PATTERN` must call `msft_add_address_filter`. [F224, F250]
- `hdev->dev_name` (248 bytes) and `hdev->short_name` (10 bytes) are 1 byte shorter than `MGMT_MAX_NAME_LENGTH`/`MGMT_MAX_SHORT_NAME_LENGTH` and may be non-NUL-terminated when full, so bound copies by `sizeof(hdev->dev_name)`/`sizeof(hdev->short_name)` and use `strnlen`. `read_exp_features_info` allocates `rp` for at most 7 entries; `eir_append_data`/`eir_append_le16` do not bounds-check, so `read_controller_cap` (`char buf[20]`) and `read_local_oob_ext_data*` must pre-allocate `2 + data_len` bytes per item. [F233, F237, F238]
