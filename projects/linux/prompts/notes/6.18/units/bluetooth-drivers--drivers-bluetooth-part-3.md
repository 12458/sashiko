# BLUETOOTH DRIVERS — drivers/bluetooth (part 3)

Implements the Bluetooth HCI UART line discipline (`hci_ldisc`), Serdev controller glue (`hci_serdev`), UART transport protocols (H4, BCSP, Three-wire H5, Intel, TI HCILL, Marvell, Nokia H4+), virtual HCI (`hci_vhci`), and Virtio Bluetooth (`virtio_bt`).

## Architecture & Data Flow
- `struct hci_uart` runs in Serdev (`hu->serdev != NULL`) or TTY (`hu->tty != NULL`) mode; shared helpers (`hci_uart_has_flow_control()`, `hci_uart_set_flow_control()`) and dual-mode protocols (`h5`, `ll`, `mrvl`) must test `hu->serdev` before dereferencing either. `hci_uart_write_wakeup()`/`hci_uart_receive_buf()` cast `serdev_device_get_drvdata(serdev)` to `struct hci_uart *` and check `serdev == hu->serdev`, so Serdev drivers must embed `struct hci_uart` first in drvdata and set `hu->serdev` before registering. [F215, F286]
- `hci_uart_close()` clears `hdev->flush = NULL` after `hci_uart_flush(hdev)`, so `hci_uart_open()` must restore `hdev->flush = hci_uart_flush`. [F238]
- In `h4_recv_buf()`, the `!skb` packet-start branch must fall through into the payload copy and `skb->len == (&pkts[i])->hlen` check in the same iteration so zero-header packets (`hlen == 0`, e.g. `ll_recv_pkts`) complete when `count` hits 0. [F265]
- In `hci_bcsp.c` and `hci_h5.c`, `unack`, `rel`, 3-bit `msgq_txseq`/`tx_seq`, and `tbcsp`/`h5->timer` update in lockstep under `unack.lock`: `bcsp_dequeue()`/`h5_dequeue()` increment seq, queue to `unack`, and arm the timer; `bcsp_timed_event()`/`h5_timed_event()` move skbs from `unack` tail (`__skb_dequeue_tail`) to `rel` head (`skb_queue_head`) while decrementing `(seq - 1) & 0x07`; `bcsp_pkt_cull()`/`h5_pkt_cull()` step backward via `(seq - 1) & 0x07` at most `skb_queue_len(&unack)` times to match `rxack`/`rx_ack` and stop the timer when `unack` empties. [F230, F231, F253, F267, F276]
- `bcsp_enqueue()`/`h5_enqueue()` must reject `skb->len > 0xfff` (12-bit header length), and `bcsp_recv()`/`h5_rx_pkt_start()` must allocate RX SKBs of at least `0x1005` bytes (`H5_MAX_LEN`) since unslipping appends wire bytes without checking `skb_tailroom()`. When a non-`0xc0` byte starts a packet in `BCSP_W4_PKT_START` or `h5_rx_pkt_start()`, `ptr`/`count` must not advance (`h5_rx_pkt_start()` returns 0) so that byte is unslipped as header byte 0. [F250, F252, F266]
- In `hci_bcsp.c`, the 16-bit CRC (`bcsp_txmsg_crc`, `bcsp->message_crc`) is bit-reversed via `bitrev16()` and big-endian (`bcsp_prepare_pkt()`, `bscp_get_crc()`). In `bcsp_complete_rx_pkt()`, an out-of-order reliable packet sets `pass_up = 2` (skipping payload delivery and `rxseq_txack` increment) but must still set `txack_req = 1` and call `bcsp_pkt_cull()`. [F254, F270]
- In `hci_h5.c`, all RX completion/abort paths must call `h5_reset_rx()` (freeing/NULLing `rx_skb`, resetting `rx_func = h5_rx_delimiter`, `rx_pending = 0`, and clearing `H5_RX_ESC`). `h5_handle_internal_rx()` must check `H5_HDR_LEN(hdr) >= 2` before reading `data = &h5->rx_skb->data[4]` and `> 2` before reading `data[2]`. In `H5_ACTIVE`, `h5_peer_reset()` must set `H5_UNINITIALIZED`, stop `h5->timer`, purge `rel`/`unrel`/`unack`, zero `tx_seq`/`tx_ack`, and call `hci_reset_dev()`. [F232, F233, F255]
- In `hci_intel.c`, `STATE_BOOTLOADER` in `intel->flags` must be cleared before `intel_setup()` returns success (both for running `0x23` firmware and after firmware boot), because `intel_dequeue()` injects synthetic `BTINTEL_HCI_OP_RESET` events while `STATE_BOOTLOADER` is set. [F243]
- In `hci_mrvl.c`, `mrvl_dequeue()` prepends `bt_cb(skb)->pkt_type` to `mrvl->txq` packets, whereas `mrvl->rawq` firmware chunks are sent raw after `txq` empties; both queues must be purged in `mrvl_flush()`/`mrvl_close()`. `mrvl_recv_fw_req()`/`mrvl_recv_chip_ver()` must check `(pkt->lhs ^ pkt->rhs) == 0xffff`. `mrvl_load_firmware()` must clamp `mrvl->tx_len` to `fw_max - fw_ptr` and loop while `fw_ptr <= fw_max` to wait for and ACK the final `tx_len == 0` request. [F245, F263, F271]
- In `hci_nokia.c`, `nokia_enqueue()` must pad odd-length TX SKBs (after prepending the 1-byte H4 type) via `skb_pad(skb, 1)` and `skb_put(skb, 1)` for 2-byte alignment. `nokia_recv_negotiation_packet()` and `nokia_recv_alive_packet()` must verify `hdr->dlen == sizeof(*evt)` / `sizeof(*pkt)` before `skb_pull(skb, sizeof(*hdr))` and dereferencing the payload. [F261, F262]
- In `hci_vhci.c`, `force_devcd_write()` must verify `count >= offsetof(struct devcoredump_test_data, data)` and `count <= sizeof(dump_data)` before `copy_from_user()`. [F259]

## Synchronization
- `hci_uart_set_proto()` must set `HCI_UART_PROTO_INIT` before `hci_uart_register_dev()` and only set `HCI_UART_PROTO_READY` after it succeeds, preventing concurrent `hci_uart_tty_close()` teardown mid-registration. [F200]
- `hci_uart_tx_wakeup()` runs in atomic context and uses `percpu_down_read_trylock(&hu->proto_lock)`, so `percpu_down_write(&hu->proto_lock)` is only allowed in `hci_uart_tty_close()`, which must release it after clearing `HCI_UART_PROTO_READY` and before `cancel_work_sync(&hu->write_work)` or `hci_unregister_dev()` (since `hci_uart_dequeue()` and `hci_uart_flush()` take `percpu_down_read()`). [F199, F303]
- `hci_uart_tx_wakeup()` must set `HCI_UART_TX_WAKEUP` before `test_and_set_bit(HCI_UART_SENDING, &hu->tx_state)`, and `hci_uart_write_work()` must clear `HCI_UART_TX_WAKEUP` before dequeuing and recheck it after clearing `HCI_UART_SENDING`. [F202]
- `h4_recv_buf()`, `h4_recv_pkt.recv` callbacks, `bcsp_recv()`, `h5_recv()`, and `bcsp_prepare_pkt()`/`h5_prepare_pkt()` (called under `unack.lock` with IRQs off) must allocate SKBs with `GFP_ATOMIC` and never sleep. [F307, F311]
- In `hci_bcsp.c` and `hci_h5.c`, `unack.lock` must be acquired before `rel.lock` (`spin_lock_irqsave_nested(..., SINGLE_DEPTH_NESTING)`) and held across window checks, `rel` dequeue/requeue, seq updates, `unack` changes, and timer updates. [F203]
- In `hci_intel.c`, iterating `intel_device_list` requires `intel_device_list_lock`, while accessing `idev->hu` in PM/IRQ/power paths requires `idev->hu_lock` (which nests inside `intel_device_list_lock`). Because `intel_enqueue()` calls `pm_runtime_get_sync()` under `intel_device_list_lock`, `intel_suspend_device()`/`intel_resume_device()` must only take `idev->hu_lock`. `intel_irq()` must be a `IRQF_ONESHOT` threaded handler (`handler == NULL`) because it takes `idev->hu_lock` and calls `intel_lpm_host_wake()` (`GFP_KERNEL`). [F242, F309, F310]
- In `hci_ll.c`, `ll->hcill_lock` (`spin_lock_irqsave()`) protects `ll->hcill_state`, `send_hcill_cmd()`, and `__ll_do_awake()`, and must be dropped before `hci_uart_tx_wakeup()`. In `ll_device_want_to_wakeup()`, `HCILL_ASLEEP_TO_AWAKE` must fall through to `HCILL_ASLEEP` to queue `HCILL_WAKE_UP_ACK` before `__ll_do_awake()` drains `ll->tx_wait_q` to `ll->txq`. [F206, F273]
- In `hci_mrvl.c`, `mrvl_load_firmware()` must set `STATE_FW_REQ_PENDING` before queuing to `mrvl->rawq` and waking TX; `mrvl_recv_fw_req()`/`mrvl_recv_chip_ver()` must write `tx_len`/`id`/`rev`, `clear_bit()` on `mrvl->flags`, and run `smp_mb__after_atomic()` before `wake_up_bit()`. [F207, F312]
- In `hci_nokia.c`, `nokia_send_alive_packet()`/`nokia_send_negotiation()` must call `init_completion(&btdev->init_completion)` and set `btdev->init_error = 0` before `nokia_enqueue()`, and RX handlers must write `btdev->init_error` before `complete()`; callers must check `btdev->init_error < 0` after `wait_for_completion_interruptible_timeout()` succeeds. [F208, F225]
- In `hci_vhci.c`, `data->open_mutex` serializes `__vhci_create_device()` (`vhci_create_device()`) and must never be taken in `hdev` callbacks (`vhci_send_frame()`, `vhci_open_dev()`, `vhci_close_dev()`, `vhci_flush()`) or held across `cancel_delayed_work_sync(&data->open_timeout)` (called before locking in `vhci_get_user()` and `vhci_release()`). [F209, F246, F313]
- In `virtio_bt.c`, `virtbt_rx_done()` runs in IRQ context and must defer RX processing and `virtbt_add_inbuf()` (`GFP_KERNEL`) to `virtbt_rx_work()`. [F315]

## Object Lifetimes
- `hci_uart_send_frame()` ignores `hu->proto->enqueue(hu, skb)`'s return value and returns 0, so `enqueue` owns `skb` and must queue or `kfree_skb()` it. Internal TX SKBs queued where `skb_push(skb, 1)` prepends the H4 type (`h4`, `ll`, `nokia`, `intel`, `mrvl`) must use `bt_skb_alloc()`. [F321, F322]
- In `bcsp_dequeue()`/`h5_dequeue()`, reliable SKBs from `rel` move to `unack` on `prepare_pkt` success or back to `rel` head on failure; unreliable SKBs from `unrel` are freed on success or requeued to `unrel` head on failure. [F188]
- In `hci_ldisc.c`, `hci_uart_register_dev()` must initialize `hu->hdev` before `hu->proto->open(hu)`; if `hci_register_dev()` fails (synchronously or in `hci_uart_init_work()`), it must call `hu->proto->close(hu)` and set `hu->hdev = NULL` before `hci_free_dev(hdev)`. [F190]
- Teardown in `hci_uart_tty_close()` (after clearing `HCI_UART_PROTO_READY` under `proto_lock`) and `hci_uart_unregister_device()` must call `cancel_work_sync(&hu->init_ready)` and `cancel_work_sync(&hu->write_work)` before checking `HCI_UART_REGISTERED` to unregister/free `hu->hdev` and calling `hu->proto->close(hu)`. `bcsp_close()`/`h5_close()` must stop timers (`timer_shutdown_sync(&bcsp->tbcsp)` / `timer_delete_sync(&h5->timer)`) before purging queues or freeing state. [F191, F289, F314]
- In `hci_serdev.c`, `serdev_device_open()`/`close()` on `hu->serdev` are gated by `HCI_UART_PROTO_READY` across `hci_uart_register_device_priv()`, `hci_uart_open()`, `hci_uart_close()` (with `HCI_QUIRK_NON_PERSISTENT_SETUP`), and `hci_uart_unregister_device()`; `serdev_device_close()` must only be called when clearing `HCI_UART_PROTO_READY`. [F192]
- `h5_close()` must only `kfree(h5)` when `!hu->serdev` (Serdev allocates `h5` via `devm_kzalloc()`). When `H5_WAKEUP_DISABLE` is set, `h5_btrtl_open()`/`close()` skip `pm_runtime_enable()`/`disable()`, and `h5_btrtl_resume()` must take `__module_get(THIS_MODULE)` and `get_device()` before scheduling `h5_btrtl_reprobe_worker`. [F189, F293]
- In `hci_intel.c`, `intel_probe()` disables wakeup, and `intel_set_power()` requests/frees `idev->irq`, toggles wakeup/runtime PM, and sets/clears `idev->hu` under `idev->hu_lock`. `intel_close()` must cancel `intel->busy_work` and call `intel_set_power(hu, false)` before freeing `intel->rx_skb` and `intel`. [F193, F294]
- In `hci_nokia.c`, `nokia_bluetooth_serdev_probe()` checks `clk_prepare_enable(sysclk)`, reads `btdev->sysclk_speed`, and immediately calls `clk_disable_unprepare(sysclk)`, so close/remove must not disable `sysclk`. `wakeup_handler()` and `nokia_dequeue()` gate `pm_runtime_get()`/`put()` on `btdev->rx_enabled`/`tx_enabled` transitions, and `nokia_dequeue()` must call `serdev_device_wait_until_sent()` before dropping `wakeup_bt` and calling `pm_runtime_put()`. [F224, F298, F299]
- In `hci_ll.c`, `hci_ti_probe()` must call `nvmem_cell_put()` and `kfree(bdaddr)` after `nvmem_cell_get()`/`read()`, storing `BDADDR_NONE` on errors other than `-EPROBE_DEFER`, `-ENOENT`, and `-ENOSYS` so `ll_setup()` sets `HCI_QUIRK_INVALID_BDADDR`. [F300]
- In `hci_vhci.c`, `vhci_read()` must requeue `skb` at `data->readq` head (`skb_queue_head()`) if `vhci_put_user()` fails. `vhci_release()` must drain `data->open_timeout` and `data->suspend_work` and call `vhci_debugfs_remove(hdev)` (when `!IS_ERR_OR_NULL(hdev->debugfs)`) before `hci_unregister_dev()`, `hci_free_dev()`, and `kfree(data)`. [F196, F211, F228]
- `virtbt_probe()` must init `vbt->rx` and register `vbt->hdev` before `virtio_device_ready()` and `virtbt_open_vdev()`; `virtbt_remove()` must call `virtio_reset_device()` and `virtbt_close_vdev()` (`cancel_work_sync(&vbt->rx)`) before detaching buffers, freeing `hdev`, or deleting virtqueues. [F212]

## API Contracts
- `h4_recv_buf()` frees any partial `skb` before returning `ERR_PTR()` and ignores `pkts[i].recv()`'s return value; callers must reset `rx_skb = NULL` on `IS_ERR(rx_skb)` without calling `kfree_skb()`, and `pkts[i].recv()` must consume/free `skb`. Each `struct h4_recv_pkt` requires `lsize <= 2`, `loff + lsize <= hlen` (when `lsize > 0`), and `maxlen >= hlen`. [F213, F248, F323]
- `hci_set_drvdata(hdev, hu)` is owned by `hci_ldisc`/`hci_serdev`/`h4_recv_buf()`, so protocols must use `hu->priv` or `hci_get_priv(hdev)`. Serdev drivers and `struct h5_vnd` entries using vendor helpers that call `hci_get_priv(hdev)` (e.g. `btrtl_initialize()`) must pass the vendor priv size via `sizeof_priv` to `hci_uart_register_device_priv()`. [F281, F282]
- `hci_uart_register_device_priv()` calls `p->open(hu)` before allocating `hu->hdev`, so Serdev-capable `open` callbacks must not dereference `hu->hdev` (use `hu->flags`/`hu->hdev_flags`). [F287]
- `hci_uart_set_flow_control(hu, enable)` is inverted: `enable == true` throttles the peer (lowers RTS / disables flow control) and `false` unthrottles. Protocols calling it on a TTY (`intel_proto`, `mrvl_proto_8897`) must require `hci_uart_has_flow_control(hu)` in `open()` (`-EOPNOTSUPP`). [F217, F318]
- `hu->proto->manufacturer` is applied only when `hu->proto->setup` is non-NULL, while `HCI_UART_VND_DETECT` in `hci_uart_setup()` runs only when `setup` is NULL (`mrvl_set_baudrate()` sets `HCI_UART_VND_DETECT` for `mrvl_proto_8997`). [F301, F320]
- `hci_uart_tty_open()` must check `capable(CAP_NET_ADMIN)` and `tty->ops->write != NULL` before allocating `struct hci_uart`. [F326]
- In `hci_intel.c`, `intel_setup()` must return early after `btintel_check_bdaddr()` when `ver.fw_variant == 0x23` (operational) without calling bootloader-only `btintel_read_boot_params()`, and must restore `init_speed` via `intel_set_baudrate()` (which sends `0xfc05` Read Version before `0xfc06`) before `btintel_send_intel_reset()`. [F296, F297]

## Error Handling
- In `intel_setup()`, `btintel_download_firmware()` returning `-EALREADY` must not fail setup at `done:` (`if (err < 0 && err != -EALREADY) return err;`). [F220]
- In `hci_ti_probe()`, `lldev->ext_clk` may hold `ERR_PTR(-ENOENT)`, so `ll_open()` must guard `clk_prepare_enable(lldev->ext_clk)` with `!IS_ERR(lldev->ext_clk)`. [F221]

## External Contracts
- `hci_uart_tty_ioctl()` takes `HCIUARTSETPROTO`/`HCIUARTSETFLAGS` directly from `arg` (not `get_user()`) and returns `HCIUARTGET*` directly as the return value (not `put_user()`). `hci_uart_set_flags()` must reject any bit outside `valid_flags` (`RAW_DEVICE`, `RESET_ON_INIT`, `INIT_PENDING`, `EXT_CONFIG`, `VND_DETECT`; bit 2 is unassigned) with `-EINVAL`. [F257, F325]
- In `hci_ll.c`, `hci_ti_probe()` must check `len == sizeof(bdaddr_t)` on the `"bd-address"` nvmem cell and `baswap()` it, and `ll_set_bdaddr()` must also `baswap()` before `HCI_VS_WRITE_BD_ADDR`. [F264]
- In `hci_vhci.c`, `vhci_get_user()` requires `len >= 2 && len <= HCI_MAX_FRAME_SIZE` and `skb->len == 0` after the 2-byte `HCI_VENDOR_PKT` header. `__vhci_create_device()` must reject `opcode & 0x3c` with `-EINVAL`, and queue the initial `HCI_VENDOR_PKT` with `skb_queue_head(&data->readq, skb)` before `atomic_inc(&data->initialized)` and waking `read_wait`, while `vhci_send_frame()` only wakes `read_wait` when `data->initialized` is non-zero. [F258, F327]
- In `virtio_bt.c`, `virtbt_probe()` must check `VIRTIO_BT_F_CONFIG_V2` to select `struct virtio_bt_config_v2` vs `struct virtio_bt_config` before reading `vendor` or `msft_opcode`. [F260]

## Known Pitfalls
- In `h4_recv_buf()`, post-frame padding `hu->padding` must use `(skb->len + 1)` (including the H4 type byte) and a second modulo `((alignment - hu->padding) % alignment)`. [F275]
- In `bcsp_recv()` and `h5_rx_3wire_hdr()`, the 8-bit header checksum comparison must mask the promoted `int` sum/negation with `& 0xff` (or cast to `u8`). [F278]
