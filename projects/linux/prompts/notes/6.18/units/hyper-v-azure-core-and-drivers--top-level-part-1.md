# Hyper-V/Azure CORE AND DRIVERS — (top level) (part 1)

Core Hyper-V guest and root-partition infrastructure, including architecture-specific hypervisor detection and MSR/hypercall access (`mshyperv`), synthetic timers (`hyperv_timer`), VMBus connection/channel/ring-buffer management (`drivers/hv/channel*.c`, `connection.c`, `hv.c`), and MSHV root-partition virtualization support (`mshv_*`). It also includes built-in Hyper-V integration services and utility drivers for dynamic memory ballooning and hot-add (`hv_balloon`), key-value pair exchange (`hv_kvp`), volume shadow copy snapshots (`hv_snapshot`), heartbeat/shutdown/timesync (`hv_util`), and synthetic HID input (`hid-hyperv`).

## Architecture & Data Flow

- Every path through `vmbus_onoffer()` and `vmbus_process_offer()` must decrement `vmbus_connection.offer_in_progress` exactly once, and when inserting a channel into `chn_list`, `sc_list`, or `vmbus_connection.channels[]`, the decrement must occur while holding `vmbus_connection.channel_mutex`. [F8]
- Pages allocated in `alloc_balloon_pages()` are split into order-0 pages (if `alloc_unit != 1`), marked `PageOffline`, and accounted in `dm->num_pages_ballooned`, `NR_BALLOON_PAGES`, and `adjust_managed_page_count()`, so `balloon_up()` error paths and `balloon_down()` must release them via `free_balloon_pages()`. [F16]
- Because the Hyper-V reference counter resets across hibernation while `hv_sched_clock_offset` is cached at boot, `hv_save_sched_clock_state()` must record `hv_ref_counter_at_suspend` and `hv_restore_sched_clock_state()` must call `hv_adj_sched_clock_offset()` with the delta before `old_restore_sched_clock_state()` runs. [F65]
- Before calling `hv_clear_allocated_cpu()` or `hv_update_allocated_cpus()` under `vmbus_connection.channel_mutex`, the caller must have already unlinked the channel from `chn_list`/`sc_list` (in `hv_process_channel_removal()`) or updated `channel->target_cpu` (in `vmbus_channel_set_cpu()`). [F66]
- During hibernation suspend (`vmbus_bus_suspend`), every channel in `vmbus_connection.chn_list` must be unmapped via `vmbus_channel_unmap_relid()` and have `offermsg.child_relid` set to `INVALID_RELID`, and `hv_process_channel_removal()` must skip both `vmbus_channel_unmap_relid()` and `vmbus_release_relid()` when `child_relid == INVALID_RELID`. [F67]
- When `vmbus_onoffer()` matches an existing primary channel across hibernation resume (`oldchannel != NULL`), it must update `oldchannel->offermsg.child_relid`, call `vmbus_setup_channel_state(oldchannel, offer)` if any other `offer` fields changed, and remap the channel via `vmbus_channel_map_relid(oldchannel)` under `channel_mutex`. [F68]
- In `hv_mem_hot_add()`, `has->ha_end_pfn` and `has->covered_end_pfn` must be advanced under `dm_device.ha_lock` before calling `add_memory()`, and if `add_memory()` returns an error, both `has->ha_end_pfn` and `has->covered_end_pfn` must be rolled back under `dm_device.ha_lock`. [F73]
- When `pfn_covered()` matches a hot-add request `[start_pfn, start_pfn + pfn_cnt)` to an existing `hv_hotadd_state` where `has->covered_end_pfn != start_pfn`, it must insert a `struct hv_hotadd_gap` for `[has->covered_end_pfn, start_pfn)` into `has->gap_list` and set `has->covered_end_pfn = start_pfn` under `dm_device.ha_lock`. [F74]

## Synchronization

- `send_modifychannel_with_ack()` is called with `vmbus_connection.channel_mutex` held and must unlock `channel_mutex` around `wait_for_completion(&info->waitevent)` and re-acquire it before returning so `vmbus_onoffer_rescind()` can acquire `channel_mutex` and signal the completion. [F7]
- In __vmbus_establish_gpadl(), __vmbus_open(), and vmbus_teardown_gpadl(), channel->rescind must be checked after msginfo is added to vmbus_connection.chn_msg_list under vmbus_connection.channelmsg_lock and before blocking on wait_for_completion(&msginfo->waitevent). [F21]
- vmbus_add_channel_work() must set newchannel->probe_done = true on both success and failure paths, and vmbus_onoffer_rescind() must wait until READ_ONCE(channel->probe_done) is true after calling vmbus_rescind_cleanup() before unregistering or removing the channel. [F28]
- Callers of __vmbus_request_addr_match() must hold channel->requestor.req_lock via lock_requestor(channel, flags), whereas callers without the lock must call vmbus_request_addr_match() or vmbus_request_addr(). [F30]
- mshv_vp_irq_try_set_vector() must update vp->vp_register_page->interrupt_vectors.as_uint64 using cmpxchg() in a retry loop (mshv_vp_irq_set_vector()). [F37]
- Modifications to pt->ioeventfds_list in mshv_assign_ioeventfd() and mshv_deassign_ioeventfd() require pt->pt_mutex to be held, and removals in mshv_deassign_ioeventfd() and mshv_eventfd_release() must call synchronize_rcu() before calling ioeventfd_release(). [F38]
- In hv_kvp.c and hv_snapshot.c, completion, error, and reset paths (kvp_on_msg, kvp_send_key, kvp_on_reset, vss_on_msg, vss_send_op, vss_on_reset) must only call kvp_respond_to_host() or vss_respond_to_host() if cancel_delayed_work_sync() on kvp_timeout_work or vss_timeout_work returns true. [F41]
- dm_device.ha_lock protects dm_device.ha_region_list, dm_device.num_pages_onlined, and each hv_hotadd_state entry, and must be released before calling hv_mem_hot_add() in handle_pg_range(). [F42]

## Object Lifetimes

- Before `vmbus_add_channel_work()` initializes `newchannel->kobj` (via `vmbus_add_channel_kobj()` or `vmbus_device_register()`), early-exit paths such as `vmbus_process_offer()` must release `newchannel` with `kfree(newchannel)` rather than `free_channel()`, because `free_channel()` calls `kobject_put(&channel->kobj)`. [F2]
- `vmbus_close_internal()` must first call `vmbus_reset_channel_cb()` to disable `channel->callback_event` and clear `channel->onchannel_callback` under `channel->sched_lock`, and must only call `vmbus_free_requestor()` and allow `vmbus_free_ring()` when both `CHANNELMSG_CLOSECHANNEL` and `vmbus_teardown_gpadl()` succeed. [F5]
- `vmbus_disconnect_ring()` must close and free all sub-channels on `channel->sc_list` (waiting on `cur_channel->rescind_event` if `cur_channel->rescind` is set and calling `hv_process_channel_removal()` under `vmbus_connection.channel_mutex`) before closing the primary channel. [F6]
- In `hv_common_cpu_init()`, the per-CPU hypercall pages allocated into `hyperv_pcpu_input_arg` and `hyperv_pcpu_output_arg` must not be freed in `hv_common_cpu_die()` when a CPU goes offline, and are instead reused if that CPU is brought back online. [F10]
- In `hv_synic_enable_regs()` and `hv_synic_disable_regs()`, when `ms_hyperv.paravisor_present || hv_root_partition()` is true, `synic_message_page` and `synic_event_page` are mapped with `ioremap_cache()` and must be unmapped with `iounmap()` and set to `NULL` without clearing `base_simp_gpa` or `base_siefp_gpa`. [F11]
- mshv_irqfd_shutdown() must call remove_wait_queue(irqfd->irqfd_wqh, &irqfd->irqfd_wait) before tearing down the resampler, dropping eventfd references, and freeing irqfd, and mshv_irqfd_deassign() and mshv_irqfd_release() must call flush_workqueue(irqfd_cleanup_wq) after deactivating irqfds. [F35]
- In mshv_irqfd_resampler_shutdown(), while holding pt->irqfds_resampler_lock, irqfd->irqfd_resampler_hnode must be removed with hlist_del_rcu() and synchronize_srcu(&pt->pt_irq_srcu) must complete before unregistering rp->rsmplr_notifier and freeing rp if rp->rsmplr_irqfd_list is empty. [F36]
- hvutil_transport_destroy() must set hvt->mode = HVUTIL_TRANSPORT_DESTROY and wake hvt->outmsg_q under hvt->lock, remove hvt from hvt_list and netlink, and if mode_old == HVUTIL_TRANSPORT_CHARDEV, wait for hvt->release completion before calling hvt_transport_free(). [F40]

## API Contracts

- `vmbus_device_register()` consumes ownership of `newchannel->device_obj` and frees it via `device_unregister()` -> `vmbus_device_release()` when registration fails, so callers such as `vmbus_add_channel_work()` must not call `kfree(newchannel->device_obj)` on error. [F1]
- `hv_call_deposit_pages()` splits each high-order allocation with `split_page(pages[i], order)` and transfers ownership of the pages to the hypervisor when `HVCALL_DEPOSIT_MEMORY` succeeds, so it must free the individual order-0 pages (`__free_page(pfn_to_page(base_pfn + j))`) only when allocation or `HVCALL_DEPOSIT_MEMORY` fails. [F18]
- `hyperv_pcpu_input_arg` and `hyperv_pcpu_output_arg` are `void * __percpu *` variables holding per-CPU page pointers; callers must dereference `*this_cpu_ptr(...)` and pass that page pointer directly to `hv_do_hypercall()` (never `&output`), and must only access `hyperv_pcpu_output_arg` when `hv_output_page_exists()` holds. [F46]
- `hv_do_hypercall()` converts non-NULL `input` and `output` pointers to guest physical addresses via `virt_to_phys()`, so every buffer passed to it must reside in directly mapped memory (never stack-allocated or `vmalloc` memory) and be 8-byte aligned (`HV_HYPERCALL_PARAM_ALIGN`). [F47]
- In `balloon_onchannelcallback()`, a `DM_MEM_HOT_ADD_REQUEST` message contains a second `union dm_mem_page_range` (`&ha_pg_range[1]`) only when `ha_msg->hdr.size != sizeof(struct dm_hot_add)`; when `ha_msg->hdr.size == sizeof(struct dm_hot_add)`, only `ha_msg->range` is present and `dm->ha_wrk.ha_region_range.page_range` must be set to `0`. [F63]
- Callers of `vmbus_alloc_ring()` and `vmbus_open()` must pass `send_size` and `recv_size` values that are multiples of the guest `PAGE_SIZE`, and `__vmbus_open()` must reject `userdatalen > MAX_USER_DEFINED_BYTES` before copying into `open_msg->userdata`. [F93]
- `hv_call_deposit_pages()` must reject `num_pages > HV_DEPOSIT_MAX` (`HV_HYP_PAGE_SIZE / sizeof(u64) - 1`) before allocating or populating `input_page->gpa_page_list[]` on `hyperv_pcpu_input_arg`. [F105]

## Error Handling

- Hypercall helpers (`hv_do_hypercall`, `hv_do_rep_hypercall`, `hv_ghcb_hypercall`, `hv_tdx_hypercall`) return a 64-bit Hyper-V status whose low 16 bits (`hv_result`) hold the status code and bits [43:32] (`hv_repcomp`) hold completed reps; callers must check `hv_result_success(status)` and convert failures via `hv_result_to_errno(status)`. [F44]
- `hv_post_message()` returns `-EMSGSIZE` when `payload_size > HV_MESSAGE_PAYLOAD_BYTE_COUNT` but otherwise returns the non-negative 16-bit Hyper-V status `hv_result(status)`; callers requiring negative Linux error codes and retry handling on transient resource exhaustion must call `vmbus_post_msg()` or translate `HV_STATUS_*` explicitly. [F45]
- In `hv_common_cpu_init()`, `*inputarg` (`*this_cpu_ptr(hyperv_pcpu_input_arg)`) must remain `NULL` until after `set_memory_decrypted()` and `memset()` complete, and callers of `hyperv_pcpu_input_arg` that can run before or during decryption (such as `hv_free_page_report()`) must check that the dereferenced pointer is non-NULL. [F48]
- `hv_synic_eventring_tail` is allocated only when `hv_parent_partition()` is true, so per-CPU init and teardown paths (`hv_common_cpu_init()` and `hv_common_cpu_die()`) must guard `this_cpu_ptr(hv_synic_eventring_tail)` accesses behind `if (hv_parent_partition())`. [F49]
- `relid2channel()` must check that `vmbus_connection.channels` is non-NULL and `relid < MAX_CHANNEL_RELIDS` before indexing `vmbus_connection.channels[relid]`, and callers must handle a `NULL` return value. [F50]
- Pages decrypted with `set_memory_decrypted()` in `vmbus_connect()`, `hv_common_cpu_init()`, and `hv_synic_alloc()` must be explicitly zeroed with `memset()` after `set_memory_decrypted()` succeeds, even if originally allocated with `__GFP_ZERO` or `get_zeroed_page()`. [F52]
- Because `cpuhp_setup_state()` returns `0` (not a positive state ID) on success for static hotplug states (`CPUHP_AP_HYPERV_ONLINE` and `CPUHP_AP_HYPERV_TIMER_STARTING`), setup must check `ret < 0` and teardown (`hv_machine_shutdown()`, `hv_stimer_global_cleanup()`) must pass the `CPUHP_*` constant directly to `cpuhp_remove_state()`. [F58]

## External Contracts

- Outbound VMBus ring packets constructed by `vmbus_sendpacket_getid()` and `vmbus_sendpacket_mpb_desc()` must pad the total packet length to an 8-byte (`sizeof(u64)`) boundary and encode descriptor offset and length fields (`offset8`/`dataoffset8` and `len8`/`length8`) in 8-byte units (`>> 3`). [F94]
- `create_gpadl_header()` must split GPADL PFN arrays across one `CHANNELMSG_GPADL_HEADER` message and subsequent `CHANNELMSG_GPADL_BODY` messages so that no individual message exceeds `MAX_SIZE_CHANNEL_MESSAGE` (`HV_MESSAGE_PAYLOAD_BYTE_COUNT`, 240 bytes), because `hv_post_message()` rejects payloads larger than `HV_MESSAGE_PAYLOAD_BYTE_COUNT`. [F95]
- In `hvt_op_read()`, a userspace read with `count < hvt->outmsg_len` must be rejected with `-EINVAL` before freeing `hvt->outmsg` or invoking `hvt->on_read`, because utility transport messages are delivered atomically in a single read. [F100]
- In `post_status()` in `drivers/hv/hv_balloon.c`, guest page counts (`num_pages_avail` and `num_pages_committed`) must be multiplied by `NR_HV_HYP_PAGES_IN_PAGE` before being written to `status.num_avail` and `status.num_committed`, because the Dynamic Memory protocol reports memory in `HV_HYP_PAGE_SIZE` (4 KiB) units. [F102]
- In `hv_free_page_report()`, each `union hv_gpa_page_range` entry in `hint->ranges[i]` must set `page.additional_pages` to the number of 2 MiB or 4 KiB pages in the scatterlist entry minus 1 (`(sg->length / unit_size) - 1`), and must check `sgl->length >= (HV_HYP_PAGE_SIZE << page_reporting_order)`. [F103]
- `vss_handle_handshake()` must preserve the distinction between `VSS_OP_REGISTER` (which completes registration without sending a reply to userspace) and `VSS_OP_REGISTER1` (which sends a 4-byte `u32` containing `VSS_OP_REGISTER1` back to the daemon via `hvutil_transport_send()`). [F110]
- In `vmbus_post_msg()`, when `hv_post_message()` returns `HV_STATUS_INVALID_CONNECTION_ID`, `hdr->msgtype == CHANNELMSG_INITIATE_CONTACT` must return `-EINVAL` immediately without retrying, whereas other message types treat it as `-EAGAIN` and retry up to 100 times. [F112]

## Known Pitfalls

- Because `kvp_transaction.kvp_msg` and `vss_transaction.msg` point directly into the shared `recv_buffer` which `kvp_respond_to_host()` and `vss_respond_to_host()` mutate in place and send back to the host, `kvp_transaction.state` and `vss_transaction.state` must not be reset to `HVUTIL_READY` until after `*_respond_to_host()` has completed. [F78]
- In `hv_call_add_logical_proc()` and `hv_call_create_vp()`, when retrying after `HV_STATUS_INSUFFICIENT_MEMORY` and calling `hv_call_deposit_pages()`, the loop must re-disable interrupts, re-fetch `input = *this_cpu_ptr(hyperv_pcpu_input_arg)`, and re-populate all `input` fields on every iteration. [F79]
- Because `vmbus_prep_negotiate_resp()` mutates the incoming `struct icmsg_negotiate` buffer in place, it must finish reading `negop->icframe_vercnt`, `negop->icmsg_vercnt`, and `negop->icversion_data[]` in both version loops before overwriting `icframe_vercnt`, `icmsg_vercnt`, and `icversion_data[0..1]`. [F84]
- In `hv_synic_event_pending()`, each pass at `retry:` must reset `pending = false`, skip `relid == 0` in `for_each_set_bit(relid, recv_int_page, HV_EVENT_FLAGS_COUNT)` because bit 0 is for VMBus channel protocol messages, and retry at most `HV_MAX_TRIES` times with `usleep_range()` when a non-zero bit is set. [F114]
- In `vmbus_prep_negotiate_resp()`, after matching a framework version in `negop->icversion_data[0 .. negop->icframe_vercnt - 1]`, `found_match` must be reset to `false` before scanning service versions in `negop->icversion_data[negop->icframe_vercnt .. negop->icframe_vercnt + negop->icmsg_vercnt - 1]`. [F117]
- In `hv_call_deposit_pages()`, when the inner `alloc_pages_node()` order-fallback loop fails at `order == 0`, it must record `num_allocations = i` before jumping to `err_free_allocations` so the cleanup loop only frees the `0 .. num_allocations - 1` allocations that succeeded. [F123]
- In `hv_page_offline_check()`, each iteration of `while (pfn < start_pfn + nr_pages)` must reset `found = false`, advance `pfn++` inside the inner `while` loop when `pfn` falls within a `hv_hotadd_state` (`has`), and increment `pfn++` after scanning `dm_device.ha_region_list` when `!found`. [F124]
