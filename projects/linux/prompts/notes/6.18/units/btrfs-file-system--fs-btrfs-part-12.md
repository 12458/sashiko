# BTRFS FILE SYSTEM — fs/btrfs (part 12)

Manages Btrfs multi-device volumes, chunk allocation, and logical-to-physical block mapping across SINGLE, DUP, RAID0, RAID1*, RAID10, and RAID56 profiles (volumes.c), extended attributes (xattr.c), zlib and zstd compression/decompression backends (zlib.c, zstd.c), and zoned block device (HMZBD/ZNS) sequential write pointer, active zone, and superblock log zone management (zoned.c).

## Architecture & Data Flow

- Even on a zoned filesystem (`btrfs_is_zoned(fs_info)`), a missing `struct btrfs_device` (`device->bdev == NULL`) has `device->zone_info == NULL`, so zoned code iterating over `fs_devices->devices`, `fs_devices->alloc_list`, or `map->stripes[i].dev` must check `device->bdev` before dereferencing `device->zone_info`. [F1207]
- `device->zone_info->zone_cache` is only allocated when `populate_cache` is true and `bdev_is_zoned(device->bdev)` holds, is not copied by `btrfs_clone_dev_zone_info()`, and is freed and set to `NULL` by `btrfs_free_zone_cache()`, so `zinfo->zone_cache` must be null-checked before access. [F1208]
- Whenever a transaction mutates `btrfs_device::bytes_used` or `btrfs_device::disk_total_bytes` (in `create_chunk`, `btrfs_remove_chunk`, `btrfs_grow_device`, or `btrfs_shrink_device`), it must link `device->post_commit_list` onto `trans->transaction->dev_update_list` under `fs_info->chunk_mutex` if `list_empty(&device->post_commit_list)` is true. [F1221]
- Inserting a `btrfs_chunk_map` into `fs_info->mapping_tree` (`btrfs_add_chunk_map`) must set `CHUNK_ALLOCATED` and clear `CHUNK_TRIMMED` in each stripe device's `alloc_state` tree under `mapping_tree_lock`, and removing it (`btrfs_remove_chunk_map`, `btrfs_mapping_tree_free`) must clear `CHUNK_ALLOCATED` and call `RB_CLEAR_NODE(&map->rb_node)`. [F1222]
- When inserting or removing a chunk item with `BTRFS_BLOCK_GROUP_SYSTEM` set in `fs_info->chunk_root` (`btrfs_chunk_alloc_add_chunk_item` and `btrfs_remove_chunk`), the superblock copy's `sys_chunk_array` and `sys_array_size` must be updated in lockstep via `btrfs_add_system_chunk()` or `btrfs_del_sys_chunk()` under `fs_info->chunk_mutex`. [F1223]
- Before detaching an active `btrfs_device` from `fs_devices->devices` on a mounted filesystem (`btrfs_rm_device`, `btrfs_destroy_dev_replace_tgtdev`) or sprouting a seed device (`btrfs_init_new_device`), `btrfs_assign_next_active_device()` must be called under `device_list_mutex` to repoint `fs_info->sb->s_bdev` and `fs_devices->latest_dev`. [F1224]
- Because `btrfs_close_devices()` retains `btrfs_fs_devices` across unmount when `num_devices > 1`, `btrfs_close_one_device()` must reset per-mount state on each `btrfs_device` (`dev_alloc_list`, `dev_state` flags, `bdev`, `zone_info`, `fs_info`, `alloc_state`, and `last_flush_error`) while updating `fs_devices` counters. [F1225]
- Because `btrfs_xattr_handler_get_security()` caches `-ENODATA` for `XATTR_NAME_CAPS` by setting `BTRFS_INODE_NO_CAP_XATTR` on `BTRFS_I(inode)->runtime_flags`, any path that writes `XATTR_NAME_CAPS` (`btrfs_xattr_handler_set_security()` and `btrfs_initxattrs()`) must clear `BTRFS_INODE_NO_CAP_XATTR`. [F1230]
- In `btrfs_clone_dev_zone_info()`, after `kmemdup()` of `orig_dev->zone_info`, the `seq_zones`, `empty_zones`, and `active_zones` bitmaps must be freshly allocated and copied, and `zone_info->zone_cache` must be set to `NULL`. [F1231]

## Synchronization

- In btrfs_map_block(), dev_replace->rwsem is read-locked only when dev_replace->replace_task != current, released immediately if !dev_replace_is_ongoing, and otherwise held across stripe mapping until the out: label. [F1170]
- Device and volume management locks must be acquired in the nesting order `uuid_mutex` -> `fs_devices->device_list_mutex` -> `fs_info->chunk_mutex`, or `uuid_mutex` -> `fs_info->balance_mutex`. [F1186]
- Callers of `btrfs_relocate_chunk` must acquire `fs_info->reclaim_bgs_lock` before searching the chunk or device trees for the target chunk and hold it across `btrfs_relocate_chunk`. [F1189]
- Replacing `device->name` on a live `struct btrfs_device` must be performed under `fs_devices->device_list_mutex` (and `uuid_mutex`) using `rcu_assign_pointer` and freeing the previous string via `kfree_rcu_mightsleep`. [F1191]
- Updates to `btrfs_device::total_bytes`, `disk_total_bytes`, and `bytes_used` on a live device, and unlocked reads of those fields, must use the `btrfs_device_set_*` and `btrfs_device_get_*` accessors so 32-bit platforms prevent torn 64-bit accesses via `data_seqcount` and preemption disabling. [F1192]
- Modifying `fs_devices->devices` or updating the device count in `fs_info->super_copy` via `btrfs_set_super_num_devices` on a mounted filesystem must be done while holding `fs_devices->device_list_mutex`. [F1194]
- In `fs/btrfs/zstd.c`, process-context functions accessing `struct zstd_workspace_manager` (`zstd_find_workspace`, `zstd_put_workspace`, `zstd_free_workspace_manager`) must acquire `zwsm->lock` using `spin_lock_bh`/`spin_unlock_bh` because `zstd_reclaim_timer_fn` acquires `zwsm->lock` in softirq timer context. [F1196]
- In `calculate_alloc_pointer` (`fs/btrfs/zoned.c`), when `new` is true, the function must return immediately without searching the extent tree because the caller (`btrfs_make_block_group`) holds `fs_info->chunk_mutex` and the lock hierarchy is extent buffer lock -> `fs_info->chunk_mutex`. [F1198]
- In `do_zone_finish`, after dropping `block_group->lock` to set the block group read-only and wait for writes, callers must re-acquire `block_group->lock` and reverify `BLOCK_GROUP_FLAG_ZONE_IS_ACTIVE`, `!block_group->reserved`, and `!BLOCK_GROUP_FLAG_ZONED_DATA_RELOC` before deactivating the zone. [F1200]

## Object Lifetimes

- btrfs_add_chunk_map() transfers the initial reference of a btrfs_alloc_chunk_map() allocation to fs_info->mapping_tree; callers must call btrfs_free_chunk_map() if failing before or during btrfs_add_chunk_map(), and btrfs_remove_chunk_map() if rolling back after btrfs_add_chunk_map() succeeds. [F1165]
- btrfs_rm_device() must not call btrfs_close_bdev() or bdev_fput() on the removed device while the caller holds the superblock write lock; instead it returns device->bdev_file via *bdev_file before freeing device so the caller can release it after mnt_drop_write_file(). [F1172]
- btrfs_read_disk_super() returns a pointer into a pagecache page whose reference is held; callers must release it with btrfs_release_disk_super(), and btrfs_get_bdev_and_sb() must close *bdev_file and reset *disk_super = NULL and *bdev_file = NULL if reading the superblock fails. [F1175]
- When removing a struct btrfs_device from a mounted filesystem's fs_devices->devices list (in btrfs_rm_device(), btrfs_rm_dev_replace_free_srcdev(), or btrfs_destroy_dev_replace_tgtdev()), list_del_rcu(&device->dev_list) and synchronize_rcu() must complete before calling btrfs_free_device(). [F1177]
- In zstd_find_workspace(), a higher-level workspace borrowed for a lower-level request (clip_level(level) != workspace->level) stays on zwsm->lru_list with workspace->req_level set to non-zero; zstd_reclaim_timer_fn() must skip entries with victim->req_level != 0, and zstd_put_workspace() must reset req_level = 0. [F1179]
- zstd_free_workspace_manager() must unlock zwsm->lock before calling timer_delete_sync(&zwsm->timer), and must complete timer_delete_sync(&zwsm->timer) before calling kfree(zwsm). [F1180]
- btrfs_schedule_zone_finish_bg() increments both bg's refcount (btrfs_get_block_group(bg)) and eb->refs (storing eb in bg->last_eb) before queueing bg->zone_finish_work, and btrfs_zone_finish_endio_workfn() must release both via free_extent_buffer(bg->last_eb) and btrfs_put_block_group(bg). [F1182]
- In `btrfs_finish_ordered_zoned()`, if `inode->flags & BTRFS_INODE_NODATASUM` or `BTRFS_FS_STATE_NO_DATA_CSUMS` is set, all `btrfs_ordered_sum` entries on `ordered->list` must be unlinked and freed after updating logical addresses so dummy zone-append sums are not logged as checksums. [F1329]

## API Contracts

- btrfs_map_block() sets *bioc_ret to NULL when satisfied by the single-device smap optimization or when failing after alloc_btrfs_io_context() (after freeing bioc via btrfs_put_bioc()); otherwise it returns a refcounted btrfs_io_context that the caller must release with btrfs_put_bioc(). [F1169]
- btrfs_balance() must be entered and exited with fs_info->balance_mutex held and consumes ownership of both bctl and the exclusive operation: unless balance pauses, it frees bctl (via reset_balance_state() or kfree(bctl)) and calls btrfs_exclop_finish(fs_info) on every exit path. [F1174]
- When `mount_arg_dev` is `false`, `btrfs_scan_one_device()` returns `NULL` (not an `ERR_PTR`) when `btrfs_skip_registration()` skips a single non-seeding device, whereas errors are returned as `ERR_PTR()`, so callers passing `false` must check `IS_ERR_OR_NULL()` before dereferencing the returned `struct btrfs_device *`. [F1202]
- `btrfs_find_chunk_map()` and `btrfs_find_chunk_map_nolock()` return `NULL` when no chunk map is found and may return a chunk map starting after `logical` if `[logical, logical + length)` overlaps it, whereas `btrfs_get_chunk_map()` returns `ERR_PTR(-EINVAL)` (never `NULL`) if no chunk map contains `logical`. [F1203]
- `find_free_dev_extent()` always writes `*start` (`max_hole_start`) and, if non-NULL, `*len` (`max_hole_size`) on exit, storing the largest free hole found even when returning `-ENOSPC` because no hole of size `num_bytes` exists. [F1204]
- `struct btrfs_dev_lookup_args` must be initialized with `BTRFS_DEV_LOOKUP_ARGS_INIT` (or `BTRFS_DEV_LOOKUP_ARGS()`, setting `.devid = (u64)-1`) when `devid` is not explicitly specified, and `btrfs_put_dev_args_from_path()` must only be called on `args` populated by `btrfs_get_dev_args_from_path()`. [F1206]
- In `zlib_decompress()` and `zstd_decompress()`, if decompression fails or produces fewer than `destlen` bytes (`to_copy < destlen`), the function must zero the unwritten tail of `dest_folio` via `folio_zero_range(dest_folio, dest_pgoff + to_copy, destlen - to_copy)` and return `-EIO`. [F1212]
- In `fs/btrfs/zstd.c`, compression `level` can be negative (`ZSTD_BTRFS_MIN_LEVEL` `-15` to `ZSTD_BTRFS_MAX_LEVEL` `15`), so any index into `zstd_ws_mem_sizes[]`, `zwsm->idle_ws[]`, or `zwsm->active_map` must be converted with `clip_level(level)` (`max(0, level - 1)`), while keeping the signed `level` in `workspace->req_level`. [F1213]
- Lookups and iterations on `fs_info->buffer_tree` in `wait_eb_writebacks()` must convert byte offsets to xarray indices by shifting right by `fs_info->nodesize_bits` (`block_group->start >> fs_info->nodesize_bits`), never `fs_info->sectorsize_bits`. [F1214]

## Error Handling

- In btrfs_rm_device(), after unlinking a writable device from dev_alloc_list and decrementing device->fs_devices->rw_devices under chunk_mutex, any failure in btrfs_shrink_device() or btrfs_start_transaction() must jump to error_undo to re-add dev_alloc_list and increment rw_devices under chunk_mutex. [F1173]
- In zlib_compress_folios() and zstd_compress_folios(), advancing to the next input folio must kunmap_local(), clear data_in or workspace->in_buf.src to NULL, and folio_put(in_folio) before calling btrfs_compress_filemap_get_folio(), and every exit path must set *out_folios = nr_folios. [F1181]
- `sb_write_pointer()` sets `*wp_ret = zones[0].start << SECTOR_SHIFT` and returns `-ENOENT` when both superblock log zones are empty, so callers `btrfs_get_dev_zone_info()` and `sb_log_location()` must treat `-ENOENT` as a valid empty-log state rather than a corruption error. [F1210]
- In `btrfs_setxattr()`, when `btrfs_insert_xattr_item()` returns `-EOVERFLOW` (leaf item full) or `-EEXIST` (matching xattr name exists), `ret` must be reset to `0` and `btrfs_match_dir_item_name()` used to locate `di` for in-place replacement (or returning `-ENOSPC` if `!di && !(flags & XATTR_REPLACE)`). [F1217]
- In `insert_balance_item()` and `del_balance_item()`, the status of `btrfs_commit_transaction(trans)` at `out:` must be captured in a separate variable `err` and only assigned to `ret` if `err && !ret`, so a successful commit (`0`) never overwrites a prior tree operation error in `ret`. [F1219]
- Per-I/O device error logging in `btrfs_dev_stat_inc_and_print()` and unknown `read_policy` warnings in `find_live_mirror()` must use ratelimited logging helpers (`btrfs_err_rl` / `btrfs_warn_rl`), and `btrfs_dev_stat_inc_and_print()` must suppress printing until `dev->dev_stats_valid` is set. [F1341]

## External Contracts

- When loading a BTRFS_DEV_STATS_OBJECTID item in btrfs_device_init_dev_stats(), each stat index i (0..BTRFS_DEV_STAT_VALUES_MAX-1) may only be read from the leaf if item_size >= (1 + i) * sizeof(__le64) (defaulting to 0 otherwise), and btrfs_get_dev_stats() must only write stats->values[i] when stats->nr_items > i. [F1254]
- In btrfs_listxattr(), packed btrfs_dir_item records within a single BTRFS_XATTR_ITEM_KEY leaf item must be walked until cur == item_size by advancing cur and di by sizeof(*di) + name_len + data_len, and when size > 0, each attribute must verify name_len + 1 <= size_left before copying and NUL-terminating. [F1258]
- In `btrfs_get_dev_zone_info()`, if the number of open/closed zones (`nactive`) exceeds `max_active_zones` and `bdev_max_active_zones(bdev)` is 0, `max_active_zones` and `zone_info->max_active_zones` must be cleared to 0 instead of failing with `-EIO`. [F1325]
- In `btrfs_check_zoned_mode()`, `blk_stack_limits(&fs_info->limits, bdev_limits(device->bdev), 0)` must only be called for devices where `bdev_is_zoned(device->bdev)` is true, because regular devices using zoned emulation do not have a valid `max_zone_append_sectors` limit. [F1326]

## Known Pitfalls

- When `btrfs_init_sprout()` copies `fs_devices` into `seed_devices` via `memcpy()`, it must re-initialize `seed_devices->devices`, `seed_devices->alloc_list`, and `seed_devices->device_list_mutex`, and `btrfs_setup_sprout()` must repoint every spliced device's `device->fs_devices = seed_devices` and zero the device counters on `fs_devices`. [F1226]
- In `__btrfs_balance()`, `should_balance_chunk()` decrements `bctl->{data,meta,sys}.limit` (and `limit_max`, which shares the same union storage) during the `counting = true` pass, so `__btrfs_balance()` must save those limits before the loop and restore `bctl->{data,meta,sys}.limit` when restarting at `again:` with `counting = false`. [F1227]
- In `btrfs_shrink_device()`, `device->total_bytes`, `fs_devices->total_rw_bytes`, and `fs_info->free_chunk_space` are reduced before relocating device extents so new allocations avoid the shrunk range; if relocation or the final device update fails (`ret != 0`), all three must be restored under `fs_info->chunk_mutex` at label `done:`. [F1228]
- When replacing an existing xattr (`di != NULL`) in `btrfs_setxattr()`, `btrfs_leaf_free_space(leaf) < (size - old_data_len)` must be checked before calling `btrfs_delete_one_dir_name()`, `btrfs_extend_item()`, or `btrfs_truncate_item()`, and `di` must then be recomputed from `btrfs_item_ptr(leaf, slot, char)` before writing the new value. [F1229]
- Reverse B-tree walks starting at key.offset = (u64)-1 in __btrfs_balance() and btrfs_relocate_sys_chunks() must break when found_key.offset == 0 before setting key.offset = found_key.offset - 1 (and btrfs_shrink_device() must guard with key.offset-- > 0) so key.offset does not underflow back to (u64)-1. [F1250]
- In btrfs_read_sys_array(), chunk passed to btrfs_chunk_* accessors and read_one_chunk() must be the extent_buffer-relative offset cast to a pointer ((struct btrfs_chunk *)sb_array_offset), whereas btrfs_del_sys_chunk() operates directly on super_copy->sys_chunk_array memory and must use btrfs_stack_chunk_* accessors. [F1252]
- In `zlib_compress_folios()`, the `workspace->strm.avail_out == 0` check that allocates a new output folio must execute before `if (workspace->strm.total_in >= len) break;` in the `Z_SYNC_FLUSH` loop. [F1271]
- In `btrfs_rm_device()`, per-device list counters (`num_devices`, `missing_devices`, `open_devices`) must be decremented on `cur_devices = device->fs_devices`, whereas `total_devices` must be decremented on `cur_devices` and also on `fs_devices` (`fs_info->fs_devices`) when `cur_devices != fs_devices`. [F1274]
