# PIN CONTROLLER - QUALCOMM — drivers/pinctrl/qcom (part 5)

This component contains Qualcomm SoC-specific TLMM (Top-Level Mode Multiplexer) pin controller drivers for SM6115, SM6125, SM6350, SM6375, SM7150, SM8150, SM8250, SM8350, and SM8450, as well as LPASS LPI (Low Power Island) pin controller variant drivers for SM8250, SM8350, SM8450, and SM8550. Each TLMM driver defines static pin descriptors, mux function tables, pingroup register/bit layouts, and MPM/PDC wakeup IRQ maps registered via `msm_pinctrl_probe()`, while each LPASS LPI driver binds static `lpi_pinctrl_variant_data` tables to `lpi_pinctrl_probe()` and `lpi_pinctrl_remove()`.

## Architecture & Data Flow

- In TLMM drivers (`pinctrl-sm6115.c` through `pinctrl-sm8450.c`), `<soc>_groups[]` must use dense 0-based indexing synchronized 1-to-1 with `<soc>_pins[]`, retaining dummy `PINGROUP` entries for missing pins because `pinctrl-msm.c` (e.g. `msm_gpio_direction_input()`) indexes `pctrl->soc->groups[offset]` directly by GPIO offset and `hwirq`. Broken by: omitting a missing pin's dummy `PINGROUP` or reordering `<soc>_groups[]` relative to `<soc>_pins[]`. [F97]
- Every constant in `enum <soc>_functions` or `enum lpass_lpi_functions` with value `< ARRAY_SIZE(<soc>_functions)` must have a designated initializer (`MSM_PIN_FUNCTION`, `MSM_GPIO_PIN_FUNCTION`, or `LPI_FUNCTION`) in `<soc>_functions[]`, and unindexed placeholders (`msm_mux__`, `LPI_MUX__`) must be last in the enum. Broken by: adding `msm_mux_<foo>` or `LPI_MUX_<foo>` before the end of the enum without a matching entry in `<soc>_functions[]`. [F91]
- In multi-tile TLMM drivers (`pinctrl-sm6115.c`, `pinctrl-sm6125.c`, `pinctrl-sm7150.c`, `pinctrl-sm8150.c`, `pinctrl-sm8250.c`), tile enum values (`NORTH`, `SOUTH`, `EAST`, `WEST`) must match the 0-based order of `<soc>_tiles[]` and stay `< ntiles` (and `< MAX_NR_TILES`, `4`), and `PINGROUP`, `SDC_PINGROUP`, `SDC_QDSD_PINGROUP`, and `UFS_RESET` must set `struct msm_pingroup.tile` to the specific tile containing each pin's register offset. Broken by: misordering tile enums relative to `<soc>_tiles[]`, using a tile `>= ntiles`, or hardcoding the wrong tile in special pin macros. [F99, F121]
- Register offsets passed to `PINGROUP`, `SDC_PINGROUP`, `SDC_QDSD_PINGROUP`, and `UFS_RESET` must be relative to the OS-accessible TLMM or tile base address mapped from Device Tree, and all pins of the same SDC controller (`clk`, `cmd`, `data`) sharing a control register must specify the identical `ctl` offset. Broken by: passing unadjusted wrapper-block offsets (e.g. `0x1d8000` instead of `0xd8000` in `sm8350_groups`) or a mismatched `ctl` offset on one pin of an SDC group (e.g. `0x7000` instead of `0xb7000` for `sdc2_clk` in `sm8250_groups`). [F122]
- In all TLMM drivers, `PINGROUP` must set `.intr_detection_width` to `1` or `2` and non-interrupt macros (`UFS_RESET`, `SDC_PINGROUP`, `SDC_QDSD_PINGROUP`) must set `.intr_detection_width = -1`, because `msm_gpio_irq_init_valid_mask()` only masks out `0..ngpios-1` entries where `intr_detection_width` is neither `1` nor `2`. Broken by: giving a non-interrupt pingroup within `0..ngpios-1` an `intr_detection_width` of `1` or `2`, or an interrupt-capable `PINGROUP` a value other than `1` or `2`. [F111]
- In `PINGROUP` definitions across all nine TLMM drivers, `.nfuncs` must be between `2` and `16` because `msm_pinmux_set_mux()` computes the mux field mask as `GENMASK(g->mux_bit + order_base_2(g->nfuncs) - 1, g->mux_bit)` with `.mux_bit = 2` and `.drv_bit = 6`. Broken by: increasing `.nfuncs` above `16` without relocating `.drv_bit` above `g->mux_bit + order_base_2(g->nfuncs) - 1`. [F115]

## Object Lifetimes

- SoC descriptor tables (`struct msm_pinctrl_soc_data`, `struct lpi_pinctrl_variant_data`, and their nested arrays) must remain non-`__initconst` static storage because `msm_pinctrl_probe()` and `lpi_pinctrl_probe()` store borrowed pointers to them in `pctrl->soc` and `pctrl->data` for runtime and remove use. Broken by: annotating `sm*_tlmm`, `sm*_pinctrl`, `sm*_lpi_data`, or any nested pin, group, function, tile, or wakeirq arrays with `__initconst` or `__initdata`. [F78]
- Every LPASS LPI driver (`pinctrl-sm8250-lpass-lpi.c` through `pinctrl-sm8550-lpass-lpi.c`) must set `.data` to its `struct lpi_pinctrl_variant_data` (`sm8250_lpi_data`..`sm8550_lpi_data`) in `lpi_pinctrl_of_match[]` and wire both `.probe = lpi_pinctrl_probe` and `.remove = lpi_pinctrl_remove` on `lpi_pinctrl_driver`. [F128]

## API Contracts

- In all TLMM drivers in this component, the `gpio` entry in `<soc>_functions[]` (and `egpio` in `sm8450_functions[]`) must use `MSM_GPIO_PIN_FUNCTION()` rather than `MSM_PIN_FUNCTION()` so `PINFUNCTION_FLAG_GPIO` is set when `pin_request()` evaluates `ops->function_is_gpio()` under `msm_pinmux_ops.strict = true`. [F107]
- In TLMM drivers supporting eGPIO (`pinctrl-sm8250.c`, `pinctrl-sm8450.c`), `msm_pinctrl_soc_data.egpio_func` must equal the slot index (`9`, for parameter `f9`) where `msm_mux_egpio` resides in `msm_pingroup.funcs[]`, every eGPIO-capable `PINGROUP` must pass `egpio` in that `f9` slot, and `PINGROUP` must set `.egpio_present` and `.egpio_enable`. Broken by: passing `egpio` in `f1..f8` instead of `f9`, setting `egpio_func` to `msm_mux_egpio` or `0`, or omitting `.egpio_present`/`.egpio_enable` in `PINGROUP`. [F81]

## External Contracts

- In all TLMM drivers (`pinctrl-sm6115.c` through `pinctrl-sm8450.c`), `struct msm_pinctrl_soc_data` must populate `.wakeirq_map` and `.nwakeirq_map` with the SoC's exact `{ gpio, wakeirq }` MPM or PDC interrupt mappings (`sm6115_mpm_map`, `sm6125_mpm_map`, `sm6350_pdc_map`, `sm6375_mpm_map`, `sm7150_pdc_map`, `sm8150_pdc_map`, `sm8250_pdc_map`, `sm8350_pdc_map`, `sm8450_pdc_map`), every entry's `.gpio` field must be `< ngpios` (and `< MAX_NR_GPIO`, `300`) for `msm_gpio_init()`, and `.wakeirq_dual_edge_errata = true` must be set when the parent wakeup controller cannot detect both edges in hardware. Broken by: swapping `.gpio` and `.wakeirq`, adding `.gpio >= MAX_NR_GPIO`, mapping a GPIO to the wrong PDC/MPM IRQ, or omitting `.wakeirq_map` or `.wakeirq_dual_edge_errata = true` when required. [F102, F125]

## Known Pitfalls

- In `SDC_PINGROUP` and `SDC_QDSD_PINGROUP` invocations across the SM6xxx/SM7xxx/SM8xxx TLMM drivers, `pull` must be in `[0, 30]` and `drv` must be in `[0, 29]` (never `-1`), because `pull_bit` and `drv_bit` are 5-bit unsigned bitfields shifted as `3 << bit` and `7 << bit` into a 32-bit `u32` register value. Broken by: passing `-1` or a bit offset `> 30` (for `pull`) or `> 29` (for `drv`). [F113]
