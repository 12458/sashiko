# MELLANOX MLX5 IB driver — (top level)

This component implements core Queue Pair (QP), Shared Receive Queue (SRQ), User-Mode Memory Registration (UMR), Work Request (WR) posting, resource tracking (restrack), and standard uverbs ioctl operations for the Mellanox ConnectX-4/ConnectX-5+ (`mlx5_ib`) InfiniBand/RDMA driver, alongside shared `include/linux/mlx5/` core headers for device capabilities, doorbells, completion/event queues, e-switch, and flow steering. It translates RDMA verbs and uverbs requests into hardware firmware commands (`CREATE_QP`, `CREATE_SRQ`, `QUERY_ESW_VPORT_CONTEXT`, etc.) and constructs hardware Work Queue Elements (WQEs) and doorbell rings.

## Architecture & Data Flow

- In `__mlx5_ib_qp_set_counter()`, when `mqp->type == IB_QPT_RAW_PACKET`, the counter must be bound on `qp->raw_packet_qp.rq` via `__mlx5_ib_qp_set_raw_qp_counter()` and `mlx5_core_modify_rq()` rather than modifying `mqp->trans_qp.base` with `MLX5_CMD_OP_RTS2RTS_QP`. [F46]
- When `qp->type == IB_QPT_RAW_PACKET` or `qp->flags & IB_QP_CREATE_SOURCE_QPN` is set, `create_user_qp()` and `destroy_qp_common()` must select `&qp->raw_packet_qp.rq.base` as the `struct mlx5_ib_qp_base *` rather than `&qp->trans_qp.base`. [F47]
- When `__mlx5_ib_modify_qp` transitions a kernel non-`IB_QPT_XRC_TGT` QP to `IB_QPS_RESET`, it must clean `recv_cq` and `send_cq` via `mlx5_ib_cq_clean`, zero `rq.head`, `rq.tail`, `sq.head`, `sq.tail`, `sq.cur_post`, `sq.last_poll`, and `db.db`, and reset `qp->sq.cur_edge` to `get_sq_edge(&qp->sq, 0)`. [F61]
- When `mlx5_ib_qp_set_counter` is called on a QP in a state other than `IB_QPS_RESET` or `IB_QPS_RTS`, it sets `mqp->counter_pending = 1` with `qp->counter`, and `__mlx5_ib_modify_qp` must apply `__mlx5_ib_qp_set_counter` and clear `qp->counter_pending = 0` upon transitioning to `IB_QPS_RTS`. [F62]
- `set_qpc_atomic_flags` derives hardware `rre`, `rae`, and `rwe` from both `IB_QP_ACCESS_FLAGS` and `IB_QP_MAX_DEST_RD_ATOMIC` using cached `qp->trans_qp.atomic_rd_en` and `qp->trans_qp.resp_depth` for whichever attribute is omitted, so `__mlx5_ib_modify_qp` must update those shadow fields only after the firmware modify succeeds. [F63]
- In `mlx5_ib_modify_dct`, when LAG is active (`mlx5_lag_is_active(dev->mdev)`), `dctc` `port` is programmed with `get_tx_affinity_rr(dev, udata)` while `qp->port` stores `attr->port_num`, so `mlx5_ib_dct_query_qp` must return `mqp->port` for `IB_QP_PORT` rather than reading `port` from `dctc`. [F64]
- `__mlx5_ib_modify_qp` caches `attr->alt_port_num` in `qp->trans_qp.alt_port` when `IB_QP_ALT_PATH` is set, and `mlx5_ib_qp_event` updates `to_mibqp(qp)->port` from `to_mibqp(qp)->trans_qp.alt_port` when `MLX5_EVENT_TYPE_PATH_MIG` is received. [F65]
- `set_pi_umr_wr` requires `sig_mr->sig->sig_status_checked` to be true before building a protection-information UMR WQE and must reset `sig_mr->sig->sig_status_checked = false` once `set_sig_data_segment` succeeds. [F71]

## Synchronization

- When linking or unlinking a QP in dev->qp_list, send_cq->list_send_qp, and recv_cq->list_recv_qp (in create_dci(), create_user_qp(), create_kernel_qp(), and destroy_qp_common()), dev->reset_flow_resource_lock must be acquired before mlx5_ib_lock_cqs(send_cq, recv_cq), which orders distinct CQ locks by ascending mcq.cqn. [F12]
- In mlx5r_umr_post_send_wait(), down(&umrc->sem) must be paired with up(&umrc->sem) across all exit paths of the submission/recovery loop, and umrc->lock must be released before sleeping in wait_for_completion(&umr_context.done), usleep_range(), or mlx5r_umr_recover(). [F21]
- In `mlx5_core_destroy_rq_tracked()`, `modify_resource_common_state(dev, rq, true)` must set `rq->common.invalid` under `qp_table.lock` before `destroy_rq_tracked()`, revert it to `false` if the firmware command fails, and call `destroy_resource_common()` only after `destroy_rq_tracked()` succeeds. [F24]
- In `mlx5_core_destroy_dct()`, unless `dev->mdev->state == MLX5_DEVICE_STATE_INTERNAL_ERROR`, `mlx5_core_drain_dct()` and `wait_for_completion(&dct->drained)` must complete while `dct` is still in `qp_table.dct_xa`, before `xa_cmpxchg_irq()` replaces it with `XA_ZERO_ENTRY` and `_mlx5_core_destroy_dct()` runs. [F25]
- `srq->lock` protects the kernel SRQ WQE ring and free-list (`srq->head`, `srq->tail`, `srq->wqe_ctr`, and `next->next_wqe_index`) in `mlx5_ib_post_srq_recv()` and `mlx5_ib_free_srq_wqe()` (which requires interrupts to be disabled by its caller), while `srq->mutex` serializes `mlx5_cmd_arm_srq()` in `mlx5_ib_modify_srq()`. [F27]
- When locking two `mlx5_ib_cq` instances simultaneously, `mlx5_ib_lock_cqs()` must be used so that distinct `send_cq->lock` and `recv_cq->lock` are acquired in ascending `mcq.cqn` order with `spin_lock_nested(..., SINGLE_DEPTH_NESTING)` and a shared CQ (`send_cq->mcq.cqn == recv_cq->mcq.cqn`) is locked only once. [F29]
- `mlx5r_wq_overflow()` is called with `qp->sq.lock` or `qp->rq.lock` held with interrupts disabled (in `mlx5_ib_post_send()`, `mlx5r_umr_post_send()`, and `mlx5_ib_post_recv()`) and, when `wq->head - wq->tail + nreq >= wq->max_post`, acquires `cq->lock` to re-read `wq->tail` updated by CQ polling. [F30]
- In `mlx5_ib_post_recv()` and `mlx5_ib_post_srq_recv()`, a `wmb()` must separate writing the receive WQE scatter segments in host memory from updating the doorbell record `*qp->db.db` or `*srq->db.db` while holding `qp->rq.lock` or `srq->lock`. [F32]

## Object Lifetimes

- In modify_raw_packet_qp(), the new vport SQ flow rule from create_flow_rule_vport_sq() must be deleted with mlx5_del_flow_rules() if modify_raw_packet_qp_sq() fails, and the existing sq->flow_rule must only be destroyed and replaced after modify_raw_packet_qp_sq() succeeds. [F11]
- In _create_user_qp() and destroy_qp(), mlx5_ib_free_bfreg() must only be called when bfregn != MLX5_IB_INVALID_BFREG, because QPs created with MLX5_QP_FLAG_UAR_PAGE_INDEX or MLX5_QP_FLAG_BFREG_INDEX do not allocate a kernel-managed bfreg from context->bfregi. [F13]
- In create_rq() and destroy_user_rq(), MLX5_IB_WQ_FLAGS_DELAY_DROP must be set in rwq->create_flags only after set_delay_drop() succeeds and increments dev->delay_drop.rqs_cnt, so destroy_user_rq() decrements dev->delay_drop.rqs_cnt if and only if it was incremented. [F14]
- In create_raw_packet_qp() and destroy_raw_packet_qp(), SQ sub-resources must be created in order TIS then SQ (and torn down SQ then TIS), and RQ sub-resources must be created in order RQ then TIR (and torn down TIR then RQ). [F15]
- For MLX5_IB_QPT_DCT QPs, create_dct() only allocates qp->dct.in while the hardware DCT is created in mlx5_ib_modify_dct() on transition to IB_QPS_RTR, so mlx5_ib_destroy_dct() must call mlx5_core_destroy_dct() only when mqp->state == IB_QPS_RTR and only free mqp->dct.in after mlx5_core_destroy_dct() succeeds. [F17]
- In mlx5_ib_create_srq(), in.pas allocated by create_srq_kernel() is only used to populate the CREATE_SRQ firmware command input and must be freed via kvfree(in.pas) immediately after mlx5_cmd_create_srq(), whereas srq->wrid, srq->buf, and srq->db are freed in destroy_srq_kernel(). [F18]
- In dump_rsc(), the dump command returned by mlx5_rsc_dump_cmd_create() must be destroyed with mlx5_rsc_dump_cmd_destroy(cmd) and the page from alloc_page() freed with __free_page(page) on both normal completion and when mlx5_rsc_dump_next() fails or exceeds MAX_DUMP_SIZE. [F20]
- When `rsc_event_notifier()` dispatches `qp->event(qp, event_type)` for `MLX5_RES_QP`, `MLX5_RES_RQ`, or `MLX5_RES_SQ`, it transfers the `common.refcount` reference acquired by `mlx5_get_rsc()` to the callback, which must release it via `mlx5_core_res_put()` (as `mlx5_ib_qp_event()` does on early exit or in `mlx5_ib_handle_qp_event()`). [F22]

## API Contracts

- Unlike qp->event(), srq->event() (mlx5_ib_srq_event) borrows the SRQ reference held by srq_event_notifier() and must not call mlx5_core_res_put(&srq->common), because srq_event_notifier() releases the reference after srq->event() returns. [F5]
- mlx5_core_res_hold() and mlx5_cmd_get_srq() increment common.refcount on the returned resource and transfer that reference to the caller, which must release it via mlx5_core_res_put(). [F6]
- In fill_multiport_info(), the struct mlx5_core_dev pointer returned by mlx5_ib_get_native_port_mdev(dev, port_num, NULL) holds an active reference on the port's multiport info and must be released by calling mlx5_ib_put_native_port_mdev(dev, port_num) before returning. [F19]
- `_mlx5r_umr_zap_mkey()` must return a signed `int` status (`0` on success or a negative errno on failure) and pass the zapped block count through its `size_t *nblocks` out-parameter so callers can detect failures before continuing multi-step UMR page-size updates. [F43]
- IB static rate attributes (`enum ib_rate`) must be converted via `mlx5r_ib_rate()` into a signed `int` and checked for `< 0` before writing the hardware `stat_rate` field, because `mlx5r_ib_rate()` maps `IB_RATE_PORT_CURRENT` and `IB_RATE_800_GBPS` to `0` and returns `-EINVAL` for invalid rates. [F44]
- In `modify_raw_packet_qp()`, `create_flow_rule_vport_sq()` returns `NULL` when no rule is needed, an `ERR_PTR` on failure, or a valid `struct mlx5_flow_handle *`, so callers must check `IS_ERR(flow_rule)` for errors and then check `if (flow_rule)` before deleting or storing the rule. [F49]
- `get_ts_format()`, `get_rq_ts_format()`, `get_sq_ts_format()`, and `get_qp_ts_format()` return either a non-negative `MLX5_TIMESTAMP_FORMAT_*` value or `-EOPNOTSUPP`, so callers must store the result in a signed `int` and check `< 0` before writing `ts_format` into hardware context structures. [F50]

## Error Handling

- `mlx5r_umr_cleanup()` must check that `dev->umrc.pd` is non-NULL and `mlx5r_umr_resource_cleanup()` must check that `dev->umrc.state != MLX5_UMR_STATE_UNINIT` before destroying UMR mutexes, QPs, CQs, or PDs. [F45]
- In `mlx5_ib_post_send()`, `mlx5_ib_post_recv()`, and `mlx5_ib_post_srq_recv()`, every error path—including the early `MLX5_DEVICE_STATE_INTERNAL_ERROR` check and per-WR validation or overflow failures—must assign `*bad_wr = wr` before returning a negative error code. [F54]
- In `mlx5r_begin_wqe()`, the 32-bit word at `*seg + 8` (covering `signature` and `rsvd` in `struct mlx5_wqe_ctrl_seg`) must be explicitly zeroed before populating `general_id` and `fm_ce_se` because SQ ring buffer entries are reused across wrap-arounds without full zeroing. [F55]
- `modify_raw_packet_qp_sq` must add the new rate limit via `mlx5_rl_add_rate` before `mlx5_core_modify_sq`, roll back the new rate on firmware error, and only remove `old_rl` via `mlx5_rl_remove_rate` (and zero `ibqp->rl` if `new_state != MLX5_SQC_STATE_RDY`) after `mlx5_core_modify_sq` succeeds. [F66]
- `_mlx5r_umr_zap_mkey` and `mlx5r_umr_dmabuf_update_pgsz` temporarily mutate `mr->page_shift` so `_mlx5r_dmabuf_umr_update_pas` iterates blocks at the target granularity while `MLX5_IB_UPD_XLT_KEEP_PGSZ` suppresses hardware page-size changes, and must restore `mr->page_shift = old_page_shift` if any UMR step fails. [F75]
- `mlx5_core_destroy_dct` and `mlx5_cmd_destroy_srq` must replace the object pointer in `qp_table.dct_xa` or `srq_table.array` with `XA_ZERO_ENTRY` via `xa_cmpxchg_irq` before the firmware destroy command, restore the pointer via `xa_cmpxchg_irq` if the command fails, and call `xa_erase_irq` only on success. [F78]
- In `fill_stat_mr_entry` and `fill_res_mr_entry` (`drivers/infiniband/hw/mlx5/restrack.c`), if any nested netlink attribute helper (`rdma_nl_stat_hwcounter_entry` or `rdma_nl_put_driver_string`) fails after `nla_nest_start`, the function must call `nla_nest_cancel(msg, table_attr)` before returning `-EMSGSIZE`. [F171]

## External Contracts

- In `process_udata_size` and `check_ucmd_data` for non-RSS QPs, `udata->inlen` is accepted down to `offsetof(struct mlx5_ib_create_qp, ece_options)` for older `rdma-core` compatibility, and any bytes from `offsetof(struct mlx5_ib_create_qp, reserved)` up to `udata->inlen` must be verified zero via `ib_is_udata_cleared`. [F88]
- In `mlx5_ib_modify_dct` and `mlx5_ib_modify_qp` (`drivers/infiniband/hw/mlx5/qp.c`), `resp.response_length` must be set to the number of bytes copied to userspace (`min_resp_len` if `udata->outlen < sizeof(resp)` in `mlx5_ib_modify_dct`, or `sizeof(resp)` when `udata->outlen >= resp.response_length` in `mlx5_ib_modify_qp`). [F103]
- In `process_vendor_flag` (`drivers/infiniband/hw/mlx5/qp.c`), `MLX5_QP_FLAG_SCATTER_CQE` and `MLX5_QP_FLAG_ALLOW_SCATTER_CQE` must be cleared from `*flags` without returning `-EINVAL` even when `MLX5_CAP_GEN(mdev, sctr_data_cqe)` is false, whereas any other unsupported flag must remain set in `*flags` so `process_vendor_flags` returns `-EINVAL`. [F104]
- In `fill_res_qp_entry` (`drivers/infiniband/hw/mlx5/restrack.c`), driver-specific QP types (`qp->type >= IB_QPT_DRIVER`: `MLX5_IB_QPT_REG_UMR`, `MLX5_IB_QPT_DCT`, `MLX5_IB_QPT_DCI`) must emit both `RDMA_NLDEV_ATTR_RES_SUBTYPE` with the subtype string and `RDMA_NLDEV_ATTR_RES_TYPE` set to `IB_QPT_DRIVER`. [F170]
- In `create_srq_user` (`drivers/infiniband/hw/mlx5/srq.c`), after copying `struct mlx5_ib_create_srq` from `udata`, non-zero `ucmd.reserved0` or `ucmd.reserved1` fields or non-zero trailing bytes beyond `sizeof(ucmd)` (checked via `ib_is_udata_cleared`) must be rejected with `-EINVAL` before pinning user memory with `ib_umem_get`. [F174]
- In `mlx5_ib_modify_dct` (`drivers/infiniband/hw/mlx5/qp.c`), transitioning from `IB_QPS_INIT` to `IB_QPS_RTR` must reject `udata->outlen < min_resp_len` (`offsetofend(typeof(resp), dctn)`), cap `resp.response_length` to `min_resp_len` if `udata->outlen < sizeof(resp)`, and call `mlx5_core_destroy_dct` if `ib_copy_to_udata` fails. [F176]
- In `mlx5_ib_modify_qp` (`drivers/infiniband/hw/mlx5/qp.c`), when `udata && udata->inlen` is true, `udata->inlen < offsetofend(typeof(ucmd), ece_options)` must return `-EINVAL`, whereas non-zero trailing bytes past `sizeof(ucmd)`, unknown `ucmd.comp_mask` bits, or non-zero `ucmd.burst_info.reserved` bytes must return `-EOPNOTSUPP`. [F177]

## Known Pitfalls

- Callers of mlx5r_umr_create_xlt() that shrink sg.length for the final UMR WQE (such as _mlx5r_umr_update_mr_pas() and mlx5r_umr_update_xlt()) must restore sg.length to its original allocated length before calling mlx5r_umr_unmap_free_xlt(). [F9]
- When setting or clearing bits in `wqe->ctrl_seg.mkey_mask` (`__be64`) in `umr.c` or `wr.c`, host-endian `MLX5_MKEY_MASK_*` constants must be converted with `cpu_to_be64()` before bitwise assignment, and `wqe->ctrl_seg.mkey_mask` must be converted back with `be64_to_cpu()` before passing to `umr_check_mkey_mask`. [F87]
- In `include/linux/mlx5/device.h`, `MLX5_SET`, `MLX5_GET`, `MLX5_SET64`, `MLX5_GET64`, `MLX5_SET16`, and `MLX5_GET16` cast the base pointer `p` directly to `(__be32 *)`, `(__be64 *)`, or `(__be16 *)` and dereference it without unaligned accessors, so `p` must be aligned to the access width (4, 8, or 2 bytes respectively). [F98]
- In `include/linux/mlx5/device.h`, `MLX5_SET` and `MLX5_GET` operate on a single 32-bit dword at `__mlx5_dw_off(typ, fld)` using a 32-bit mask, so 64-bit PRM fields must be accessed with `MLX5_SET64`/`MLX5_GET64` (when 64-bit aligned) or split across dwords (such as `icm_address_31_0`, `icm_address_39_32`, `icm_address_63_40` in `qp.c`). [F99]
- In `process_vendor_flags` and `process_create_flags`, each supported flag bit must be cleared from the local `flags` or `create_flags` mask (via `process_vendor_flag` or `process_create_flag`) because any residual set bit at function exit causes QP creation to fail with `-EINVAL` or `-EOPNOTSUPP`. [F106]
- In `mlx5_ib_post_send`, when `handle_qpt_rc` processes `IB_WR_REG_MR_INTEGRITY`, control must jump to `skip_psv` because `handle_reg_mr_integrity` already finishes the UMR and PSV WQEs and updates `qp->next_fence`, whereas other UMR opcodes (`IB_WR_LOCAL_INV`, `IB_WR_REG_MR`) zero `*num_sge` and rely on the loop-tail `mlx5r_finish_wqe`. [F108]
- In `_mlx5r_umr_update_mr_pas`, when `curr_entry == entry + sg.length` triggers an intermediate `mlx5r_umr_post_send_wait`, the loop must advance `offset += sg.length`, call `mlx5r_umr_update_offset`, and reset `cur_ksm` or `cur_mtt` to `entry` before writing the current DMA block. [F111]
