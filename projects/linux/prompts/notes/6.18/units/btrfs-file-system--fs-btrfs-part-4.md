# BTRFS FILE SYSTEM — fs/btrfs (part 4)

Implements Btrfs extent allocation and backref management in the extent tree (allocating/freeing data and metadata extents, running delayed refs, pinning extents, and dropping snapshots), low-level extent buffer and pagecache folio I/O operations (extent_io.c), in-memory file extent mapping cache (extent_map.c), and FIEMAP extent reporting (fiemap.c).

## Architecture & Data Flow

- In `struct extent_map`, `disk_bytenr` holds a valid on-disk byte address only when `em->disk_bytenr < EXTENT_MAP_LAST_BYTE` (`(u64)-4`); for `EXTENT_MAP_HOLE` (`(u64)-3`) and `EXTENT_MAP_INLINE` (`(u64)-2`), `offset` and `disk_num_bytes` must remain `0` and `disk_bytenr` must not have `em->offset` added to it. [F392]
- `struct extent_buffer::addr` is non-`NULL` only when `alloc_extent_buffer()` confirms all pages in `eb->folios[]` are physically contiguous (`page_contig`) and is `NULL` for discontiguous or dummy/cloned buffers, so `extent_buffer` accessors must fall back to `eb->folios[]` when `eb->addr` is `NULL`. [F393]
- Before downcasting a `struct btrfs_extent_inline_ref *iref` payload, callers must check `btrfs_get_extent_inline_ref_type(leaf, iref, ...)` for `BTRFS_REF_TYPE_INVALID` and use `&iref->offset` for `BTRFS_EXTENT_DATA_REF_KEY` or `BTRFS_EXTENT_OWNER_REF_KEY` versus `(iref + 1)` for `BTRFS_SHARED_DATA_REF_KEY`. [F394]
- For tree-block extent items, `struct btrfs_tree_block_info` follows `struct btrfs_extent_item` (`ei + 1`) only for non-skinny `BTRFS_EXTENT_ITEM_KEY` (`!skinny_metadata`), whereas for `BTRFS_METADATA_ITEM_KEY` (`skinny_metadata`) inline refs start at `ei + 1` and `extent_op` in `alloc_reserved_tree_block()` may be `NULL`. [F395]
- Adding an extent_map via add_extent_mapping() or removing one via remove_em() on a filesystem tree root (!btrfs_is_testing(fs_info) && btrfs_is_fstree(btrfs_root_id(inode->root))) must increment or decrement fs_info->evictable_extent_maps in lockstep, whereas replace_extent_mapping() must not alter the counter. [F406]
- When btrfs_remove_extent_mapping() or replace_extent_mapping() removes an extent_map from inode->extent_tree, it must call list_del_init(&em->list) only if !(em->flags & EXTENT_FLAG_LOGGING), and must call RB_CLEAR_NODE(&em->rb_node) so btrfs_extent_map_in_tree() reflects removal. [F407]
- When btrfs_scan_root() finishes scanning all inodes of a root (inode == NULL) or btrfs_extent_map_shrinker_worker() wraps around to root 0, fs_info->em_shrinker_last_ino must be reset to 0 alongside updating fs_info->em_shrinker_last_root. [F411]
- Setting, clearing, or starting writeback on EXTENT_BUFFER_DIRTY (in set_extent_buffer_dirty(), btrfs_clear_buffer_dirty(), and lock_extent_buffer_for_io()) must update fs_info->buffer_tree PAGECACHE_TAG_DIRTY/PAGECACHE_TAG_WRITEBACK marks, fs_info->dirty_metadata_bytes, and folio dirty bits in lockstep. [F416]

## Synchronization

- release_extent_buffer() requires eb->refs_lock to be held on entry and unconditionally unlocks eb->refs_lock on all return paths, so callers must acquire eb->refs_lock beforehand and never unlock eb->refs_lock after calling release_extent_buffer(). [F347]
- lock_delalloc_folios() and process_one_folio() (via __process_folios_contig(), unlock_delalloc_folio(), and extent_clear_unlock_delalloc()) must skip locking and unlocking the caller's locked_folio so that the caller retains ownership of its lock on locked_folio. [F351]
- In writepage_delalloc() and extent_writepage(), ranges for which btrfs_run_delalloc_range() returns > 0 (async compression or inline) must be cleared from bio_ctrl->submit_bitmap, and if writepage_delalloc() or extent_writepage_io() returns 1, extent_writepage() must return 0 without calling btrfs_folio_end_lock_bitmap(). [F352]
- In btrfs_cross_ref_exist(), btrfs_lookup_extent_info(), and check_ref_exists(), the extent tree leaf in path must stay locked while trylocking head->mutex; if mutex_trylock() fails, the caller must increment head->refs, unlock delayed_refs->lock, and call btrfs_release_path(path) before sleeping on mutex_lock(&head->mutex). [F357]
- In extent_fiemap(), before calling flush_fiemap_cache() or emit_last_fiemap_cache() (which write to user space via fiemap_fill_next_extent()), the file range in inode->io_tree must be unlocked and path must be released (or freed with path = NULL for BTRFS_PATH_AUTO_FREE). [F364]
- In try_release_subpage_extent_buffer(), iteration over fs_info->buffer_tree must use rcu_read_lock() and never acquire the non-IRQ-safe eb->refs_lock while holding the IRQ-safe buffer_tree XArray lock, because IRQ writeback completion (end_bbio_meta_write) acquires the buffer_tree lock. [F365]
- Page cache read operations in btrfs_read_folio() and btrfs_readahead() must hold the extent range lock on inode->io_tree via lock_extents_for_read() across the entire btrfs_do_readpage() execution before calling btrfs_unlock_extent(). [F366]
- In lock_extent_buffer_for_io(), clearing EXTENT_BUFFER_DIRTY and setting EXTENT_BUFFER_WRITEBACK on eb->bflags must be performed together while holding eb->refs_lock. [F368]

## Object Lifetimes

- When iterating over a struct eb_batch populated by buffer_tree_get_ebs_tag() (such as in btree_write_cache_pages()), each extent_buffer reference is owned by the batch and released by eb_batch_release(), so inner loop skip or error paths must never call free_extent_buffer(eb). [F345]
- In alloc_extent_buffer(), folios attached via attach_eb_folio_to_filemap() must stay locked until eb is inserted into fs_info->buffer_tree, and on the out: rollback path detach_extent_buffer_folio() must be called before folio_unlock(), followed by folio_put() and setting eb->folios[i] = NULL before btrfs_release_extent_buffer(). [F348]
- When read_extent_buffer_pages_nowait() sets EXTENT_BUFFER_READING on eb->bflags, it must either clear and wake the bit immediately if EXTENT_BUFFER_UPTODATE is already set, or increment eb->refs and submit the bbio so end_bbio_meta_read() clears EXTENT_BUFFER_READING and calls free_extent_buffer(eb). [F349]
- Once submit_one_bio() submits bio_ctrl->bbio or submit_write_bio() terminates it via btrfs_bio_end_io(), ownership of the struct btrfs_bio transfers to its end_io callback and bio_ctrl->bbio must be set to NULL to prevent duplicate submission or completion. [F350]
- In btrfs_run_delayed_refs_for_head(), clearing locked_ref->must_insert_reserved = false transfers ownership of the reserved extent and simple-quota reservation to run_one_delayed_ref(), which must pin the extent and free the squota reserve on transaction abort or error. [F356]
- When btrfs_lock_cluster() returns a cluster_bg != bg, it holds an extra reference and (if delalloc) cluster_bg->data_rwsem; find_free_extent_clustered() must call btrfs_release_block_group(cluster_bg, ffe_ctl->delalloc) if allocation from cluster_bg fails, or return it via *cluster_bg_ret so find_free_extent() releases the old block_group. [F358]
- btrfs_alloc_tree_block() acquires resources in the order btrfs_use_block_rsv(), btrfs_reserve_extent(), btrfs_init_new_buffer(), and btrfs_alloc_delayed_extent_op(), and error paths must unwind them in reverse: btrfs_free_delayed_extent_op(), btrfs_tree_unlock() + free_extent_buffer(), btrfs_free_reserved_extent(), and btrfs_unuse_block_rsv(). [F359]
- In btrfs_drop_snapshot(), when the root is completely dropped (root_dropped = true), ownership of root is either transferred to trans via btrfs_add_dropped_root() (if BTRFS_ROOT_IN_RADIX is set) or released via btrfs_put_root(); if btrfs_drop_snapshot() exits with !root_dropped and !for_reloc, it must re-queue root via btrfs_add_dead_root(root). [F362]

## API Contracts

- btrfs_remove_extent_mapping() and replace_extent_mapping() remove cur/em from inode->extent_tree.root without decrementing its refcount, so callers removing or replacing an in-tree extent_map must explicitly call btrfs_free_extent_map() to drop the tree's reference. [F354]
- When add_extent_mapping() returns -EEXIST in btrfs_add_extent_mapping(), if start is covered by the existing map it frees the caller's *em_in and replaces *em_in with a referenced existing map; if merge_extent_mapping() fails, it frees the caller's *em_in, sets *em_in = NULL, and frees existing. [F355]
- When check_next_block_uptodate() fails to read next from disk, it unlocks next and calls free_extent_buffer(next) before returning a non-zero error, so its caller do_walk_down() must return immediately on error rather than jumping to out_unlock. [F360]
- btrfs_drop_subtree() consumes the caller's write lock and reference on node (storing it in path with path->locks[level] = BTRFS_WRITE_LOCK without incrementing node->refs), whereas it preserves the caller's write lock and reference on parent by incrementing parent->refs and leaving path->locks[parent_level] == 0. [F361]
- `alloc_extent_buffer()` and `btrfs_alloc_tree_block()` return an `ERR_PTR()` on failure and never `NULL`, whereas `find_extent_buffer()`, `btrfs_clone_extent_buffer()`, and `alloc_dummy_extent_buffer()` return `NULL` on failure or miss and never an `ERR_PTR()`. [F386]
- `btrfs_alloc_extent_map()`, `btrfs_lookup_extent_mapping()`, and `btrfs_search_extent_mapping()` return `NULL` when allocation fails or no mapping is found, whereas `get_extent_map()` returns an `ERR_PTR()` on failure and never `NULL`. [F387]
- `find_free_extent_clustered()` returns `0` when an extent is allocated, `> 0` (`1`) when no free extent is found in `bg`, and `-ENOENT` to signal `do_allocation_clustered()` to fall back to `find_free_extent_unclustered()` on the same block group. [F390]
- `emit_fiemap_extent()` returns the negative sentinel `BTRFS_FIEMAP_FLUSH_CACHE` (`-(MAX_ERRNO + 1)`) when `cache->entries` is full; `extent_fiemap()` must intercept this value after unlocking the io_tree range to release `path`, call `flush_fiemap_cache()`, and restart from `cache.next_search_offset` rather than returning it to VFS. [F391]

## Error Handling

- When iterating over sectors in `extent_writepage_io()`, any negative return from `submit_one_sector()` must be latched into `found_error` (preserving the first error) and returned at the end of the function rather than returning `ret`. [F384]
- In `btrfs_finish_extent_commit()`, the first non-zero error returned by `unpin_extent_range()` must be latched into `unpin_error` and returned after all pinned ranges and `deleted_bgs` discards have been processed, rather than returning `ret`. [F396]
- In `find_free_extent()`, block-group caching errors (`btrfs_cache_block_group() < 0` or `BTRFS_CACHE_ERROR`) must be latched in `cache_block_group_error` while resetting `ret = 0`, and if the search finishes with `ret == -ENOSPC` and `cache_block_group_error != 0`, `cache_block_group_error` must be returned instead. [F397]
- In `writepage_delalloc()`, once `btrfs_run_delalloc_range()` returns a negative `ret`, subsequent iterations of the delalloc bitmap loop must not call `btrfs_run_delalloc_range()` or overwrite `ret`, and must instead unlock the remaining locked delalloc ranges and finish ordered extents up to `last_finished_delalloc_end`. [F398]
- In `find_free_extent_update_loop()`, when `btrfs_chunk_alloc()` returns `-ENOSPC` during `LOOP_ALLOC_CHUNK`, `ret` must be reset to `0` and `ffe_ctl->loop` incremented to `LOOP_WRONG_SIZE_CLASS` without aborting the transaction or returning `-ENOSPC` to `find_free_extent()`. [F447]
- When metadata writeback fails in end_bbio_meta_write(), set_btree_ioerr() must call mapping_set_error(eb->fs_info->btree_inode->i_mapping, -EIO) AND set BTRFS_FS_BTREE_ERR, BTRFS_FS_LOG1_ERR, or BTRFS_FS_LOG2_ERR on fs_info->flags according to eb->log_index. [F506]
- In btrfs_get_extent_inline_ref_type() and lookup_inline_extent_backref(), on-disk inline backref entries must validate that shared ref offsets (BTRFS_SHARED_BLOCK_REF_KEY and BTRFS_SHARED_DATA_REF_KEY) are non-zero and aligned to fs_info->sectorsize and that the inline ref cursor ptr does not exceed the item end, returning -EUCLEAN on violation. [F509]

## External Contracts

- `btrfs_trim_fs` must reject `range->start == U64_MAX` and, when `range->len != U64_MAX`, check `check_add_overflow(range->start, range->len, &range_end)` with `-EINVAL` before iterating block groups, and store the total bytes trimmed back into `range->len` on return. [F437]
- In hash_extent_data_ref(), the 32-bit high_crc and low_crc values must be cast to u64 before shifting high_crc left by 31 and XORing with low_crc so that the upper bits of high_crc are not truncated in the 64-bit BTRFS_EXTENT_DATA_REF_KEY offset. [F462]
- When FIEMAP_FLAG_SYNC is set in fieinfo->fi_flags, btrfs_fiemap() must call btrfs_wait_ordered_range(btrfs_inode, 0, LLONG_MAX) in addition to fiemap_prep() (and repeat it after taking BTRFS_ILOCK_SHARED), because filemap_write_and_wait() alone returns before async compression and ordered extent btree updates complete. [F496]
- In submit_one_sector() and extent_writepage_io(), when sector writeback fails before bio submission or all sectors are >= i_size, the code must call btrfs_folio_clear_dirty(), btrfs_folio_set_writeback(), and btrfs_folio_clear_writeback() so PAGECACHE_TAG_DIRTY is cleared and no writeback occurs without an ordered extent. [F501]
- In extent_write_cache_pages(), subpage folios (btrfs_is_subpage(inode_to_fs_info(inode), folio)) must wait for existing writeback via folio_wait_writeback(folio) even when wbc->sync_mode == WB_SYNC_NONE, because async compression on one subpage sector sets folio writeback while other dirty sectors in the same folio still require submission. [F503]
- In alloc_new_bio() and submit_extent_folio(), data write bios (bio_ctrl->wbc != NULL) must bind to fs_info->fs_devices->latest_dev->bdev, call wbc_init_bio() and wbc_account_cgroup_owner() for blk-cgroup writeback accounting, and split via submit_one_bio() at ordered extent boundaries tracked by bio_ctrl->len_to_oe_boundary. [F504]

## Known Pitfalls

- try_merge_map() must not mutate an extent_map in place unless refcount_read(&em->refs) <= 2 and can_merge_extent_map(em) holds, and merge_ondisk_extents() must compute new_disk_bytenr, new_disk_num_bytes, and new_offset into locals before writing to merged because merged aliases prev or next. [F409]
- In btrfs_do_readpage(), when reading a compressed extent (compress_type != BTRFS_COMPRESS_NONE) and bio_ctrl->last_em_start != U64_MAX && bio_ctrl->last_em_start != em->start, submit_one_bio(bio_ctrl) must be called before adding the folio to bio_ctrl->bbio. [F415]
- In btrfs_init_new_buffer(), btrfs_set_header_generation(buf, trans->transid) must be called before btrfs_clear_buffer_dirty(trans, buf), and again after memzero_extent_buffer(buf, 0, sizeof(struct btrfs_header)), while also initializing buf->log_index and clearing EXTENT_BUFFER_STALE and EXTENT_BUFFER_ZONED_ZEROOUT. [F424]
- During snapshot deletion, whenever a tree block lock is dropped and reacquired (in check_next_block_uptodate() when reading a non-uptodate block, or in walk_up_proc() when transitioning from UPDATE_BACKREF to DROP_REFERENCE on an unlocked node), wc->refs[level] and wc->flags[level] must be refreshed via btrfs_lookup_extent_info(). [F425]
- `num_extent_folios` returns `0` when `eb->folios[0]` is `NULL`, so loops that clear `eb->folios[i] = NULL` (like `cleanup_extent_buffer_folios` and `alloc_extent_buffer`) must cache `num_extent_folios(eb)` beforehand or bound the loop with `num_extent_pages(eb)` instead of re-evaluating `num_extent_folios(eb)`. [F429]
- Because `btrfs_find_first_clear_extent_bit` sets `end` to `(u64)-1` when a clear range reaches the end of `device->alloc_state`, `btrfs_trim_free_extents` must check `start > device->total_bytes` and clamp `[start, end]` to `[BTRFS_DEVICE_RANGE_RESERVED, device->total_bytes - 1]` before computing `len = end - start + 1`. [F438]
- When inspecting a `struct btrfs_file_extent_item`, callers (`fiemap_find_last_extent_offset()`, `extent_fiemap()`, `btrfs_exclude_logged_extents()`, `__btrfs_mod_ref()`) must check `btrfs_file_extent_type(leaf, ei) == BTRFS_FILE_EXTENT_INLINE` before reading `btrfs_file_extent_disk_bytenr(leaf, ei)` or treating `disk_bytenr == 0` as a hole. [F442]
