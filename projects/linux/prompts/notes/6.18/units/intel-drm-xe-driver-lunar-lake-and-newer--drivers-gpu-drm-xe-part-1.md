# INTEL DRM XE DRIVER (Lunar Lake and newer) — drivers/gpu/drm/xe (part 1)

This component defines the hardware and firmware ABI headers (GuC CTB/MMIO/SLPC/SR-IOV/relay/capture and GSC MKHI/PXP/proxy protocols), GPU command instruction encodings, MMIO register definitions (`struct xe_reg` and `struct xe_reg_mcr`), i915 display compatibility wrapper headers, batchbuffer suballocation helpers (`xe_bb`), and the KUnit test suite for the Xe driver.

## Architecture & Data Flow

- `struct xe_reg` stores the MMIO byte offset in a 22-bit bitfield (`addr:const_ilog2(XE_REG_ADDR_MAX)`, `XE_REG_ADDR_MAX == SZ_4M`) and `xe_reg_is_valid()` tests `r.addr != 0`, so every valid register offset in `XE_REG()` or `XE_REG_MCR()` must lie in `[1, SZ_4M)`. Broken by: defining a register at offset `>= SZ_4M` (truncating `addr`) or `0` when checked by `xe_reg_is_valid()`. [F1005]
- KCR registers in `regs/xe_pxp_regs.h` (`KCR_INIT`, `KCR_SIP`, `KCR_GLOBAL_TERMINATE`) are only valid on platforms with a media GT and must be accessed through the media GT's `xe_mmio` instance, never on a primary GT or a platform without a media GT. [F1051]
- In static IP and PCI device descriptors, `xe_graphics_desc.hw_engine_mask` must only set RCS, CCS, or BCS bits, `xe_media_desc.hw_engine_mask` must only set VCS, VECS, or GSCCS bits, and `xe_device_desc.max_gt_per_tile` must be in `[1, XE_MAX_GT_PER_TILE]`. [F1049]
- `xe_bb_ccs_new()` must suballocate `4 * (dwords + 1)` bytes from `xe->sriov.vf.ccs.contexts[ctx_id].mem.ccs_bb_pool` for a `dwords`-length command stream so the extra guard dword prevents the last suballocation chunk from overwriting the pool's trailing `MI_BATCH_BUFFER_END`. Broken by: allocating `4 * dwords` bytes or writing `dwords + 1` commands into the `bb`. [F991]
- In `blt_copy()`, each `while (size)` pass must clamp `src_L0 = min(src_L0, dst_L0)`, pass `&src_L0` to both `pte_update_size()` calls, advance both `src_it` and `dst_it` by `src_L0` (via `xe_res_next()` for VRAM or `emit_pte()` for system memory), and decrement `size -= src_L0`. Broken by: passing `&dst_L0` or advancing `dst_it` by `dst_L0`. [F1024]
- `read_l3cc_table()` must read the 32-bit `LNCFCMOCS(i >> 1)` register into `reg_val` only on even indices (`!(i & 1)`) and right-shift `reg_val >>= 16` on odd indices so `reg_val & 0xffff` extracts the lower 16-bit L3CC entry on even `i` and the upper 16-bit entry on odd `i`. [F1025]
- Any test-private struct retrieved via `xe_cur_kunit_priv()` and downcast with `container_of()` (e.g., `struct dma_buf_test_params`, `struct migrate_test_params`) must keep `struct xe_test_priv base` at offset 0, because callers apply `container_of()` directly to `xe_cur_kunit_priv(...)` before null-checking the result. [F1037]
- In `tests/xe_guc_g2g_test.c`, `struct g2g_test_payload` must remain `u32`-aligned and a multiple of `sizeof(u32)` in size, because `g2g_test_send()` sizes the GuC CT message in dwords as `sizeof(*payload) / sizeof(u32)` and `xe_guc_g2g_test_notification()` casts `msg + 3` (`u32 *`) directly to `struct g2g_test_payload *`. Broken by: adding unpadded `u8`/`u16` fields or 8-byte-aligned `u64` fields. [F1041]

## Synchronization

- When submitting a migration job on `m->q` in `blt_copy()`, `m->job_mutex` must be held continuously across `xe_sched_job_arm(job)`, acquiring `job->drm.s_fence->finished`, calling `xe_sched_job_push(job)`, and replacing `m->fence`. [F972]
- In `xe_bo.c`, `bo->ttm.bdev->lru_lock` nests inside `xe_bo_lock(bo, false)` when updating `xe_tt->purgeable` and moving `&bo->ttm` to the LRU tail via `ttm_bo_move_to_lru_tail()`. Broken by: acquiring `xe_bo_lock()` while holding `lru_lock` or calling `ttm_bo_move_to_lru_tail()` without `lru_lock`. [F978]
- When validating a VM-bound BO (`bo->vm != NULL`) in `evict_test_run_tile()`, `down_read(&vm->lock)` must be acquired outer to `xe_vm_lock(vm, false)` before calling `xe_bo_validate(bo, bo->vm, false, exec)`. [F979]
- In `xe_guc_g2g_test.c`, `g2g_test_send()` must increment `xe->g2g_test_count` before calling `xe_guc_ct_send()`, and `xe_guc_g2g_test_notification()` must never invoke `KUNIT_ASSERT*` macros and must always decrement `xe->g2g_test_count` via `atomic_dec()` on every exit path. [F980]
- `intel_uncore_read64_2x32()` must prime `upper` from `upper_reg` before its retry loop, copy `old_upper = upper` at the start of each pass before reading `lower_reg` and re-reading `upper_reg`, and bound the loop with `upper != old_upper && loop++ < 2`. [F1016]

## Object Lifetimes

- `xe_bb_create_job()` and `xe_bb_create_migration_job()` do not take ownership of `struct xe_bb *bb` on success or failure; callers must always release `bb` via `xe_bb_free(bb, fence)` (passing `NULL` for `fence` on job creation failure or after synchronous completion). Furthermore, `xe_bb_free(bb, fence)` borrows `fence` without consuming the caller's reference (`drm_suballoc_free()` takes its own via `dma_fence_get()`), so callers that obtained `fence` via `dma_fence_get(&job->drm.s_fence->finished)` must still call `dma_fence_put(fence)`. [F959, F961]
- `i915_gem_stolen_remove_node()` must both unpin/unmap `fb->bo` via `xe_bo_unpin_map_no_vm(fb->bo)` and clear `fb->bo = NULL` so `i915_gem_stolen_node_allocated(fb)` (`!!((fb)->bo)`) is accurate. Broken by: leaving `fb->bo` non-NULL on removal or overwriting `fb->bo` in `i915_gem_stolen_insert_node_in_range()` when `xe_bo_create_pin_range_novm()` returns an `ERR_PTR`. [F962]
- When `xe_test_dmabuf_import_same_driver()` manually sets `bo->ttm.base.dma_buf = dmabuf` after calling `xe_gem_prime_export()` directly, it must clear `bo->ttm.base.dma_buf = NULL` before calling `dma_buf_put(dmabuf)` and `drm_gem_object_put(&bo->ttm.base)`. [F963]
- Before changing `xe_tt->purgeable` on an allocated `struct xe_ttm_tt` (e.g., in `shrink_test_run_device()`), the caller must hold `xe_bo_lock(bo, ...)` and bracket the mutation with `xe_ttm_tt_account_subtract(xe, &xe_tt->ttm)` before and `xe_ttm_tt_account_add(xe, &xe_tt->ttm)` after. [F965]
- `xe_kunit_helper_xe_device_test_init()` must call `xe_pci_fake_device_init(xe)` (which reads optional `struct xe_pci_fake_data *` from `test->priv`) before overwriting `test->priv = xe`, and must register `kunit_action_restore_priv` via `kunit_add_action_or_reset()`. [F967]
- `xe_kunit_helper_xe_device_live_test_init()` must verify `!xe_device_wedged(xe)`, acquire a runtime PM reference via `xe_pm_runtime_get(xe)`, and register `put_xe_pm_runtime` via `kunit_add_action_or_reset()`. [F1047]
- `g2g_free()` must release `gt->uc.guc.g2g.bo` via `xe_managed_bo_unpin_map_no_vm(bo)` when `g2g.owned` is true and via `xe_bo_put(bo)` when `g2g.owned` is false (matching `g2g_distribute()`), and then clear `gt->uc.guc.g2g.bo = NULL`. [F968]
- `xe_pci_live_device_gen_param()` must pass the previous `dev` (`xe ? xe->drm.dev : NULL`) into `driver_find_next_device()` before calling `put_device(dev)`, and must return `NULL` when `!next` before calling `dev_name(next)` or `to_pci_dev(next)`. [F1020]
- In `shrink_test_run_device()`, the readback pass must re-seed `prng` via `prandom_seed_state(&prng, rand_seed)` before iterating `bos` with `list_for_each_entry_safe(link, next, &bos, link)`, and must execute `xe_bo_put(link->bo)`, `list_del(&link->link)`, and `kfree(link)` on every iteration even when `failed` or `signal_pending(current)` is true. Broken by: breaking out of the loop early or mutating `prng` on purgeable BOs. [F1023]

## API Contracts

- `xe_bb_new()`, `xe_bb_ccs_new()`, `xe_bb_create_job()`, and `xe_bb_create_migration_job()` return an `ERR_PTR` on failure (never `NULL`), and `xe_bb_new()` / `xe_bb_ccs_new()` allocate with `GFP_KERNEL` (process context only). Callers must check returns with `IS_ERR()` before storing them in nullable fields (like `oa_bo->bb` or `bo->bb_ccs[ctx_id]`) or passing them to `xe_bb_free()`. [F981, F1053]
- `xe_bb_new()` must allocate `4 * (dwords + 1) + bb_prefetch(gt)` bytes (reserving `SZ_1K` on `GRAPHICS_VERx100(xe) >= 1250` main GTs and `SZ_512` otherwise), and `__xe_bb_create_job()` must append `MI_BATCH_BUFFER_END`, assert `bb->len * 4 + bb_prefetch(q->gt) <= size`, and call `xe_sa_bo_flush_write(bb->bo)` before `xe_sched_job_create()`. [F1046]
- In `xe_bb_create_migration_job()`, `batch_base_ofs` is a byte GPU offset whereas `second_idx` is a dword index (`second_idx <= bb->len`) within `bb->cs`, scaled by 4 (`batch_base_ofs + drm_suballoc_soffset(bb->bo) + 4 * second_idx`) to form the second batch address. [F984]
- `XE_INSTR_NUM_DW(x)` and `GFX_OP_PIPE_CONTROL(len)` take the total instruction dword length (`>= 2`) and encode `(x) - 2`, whereas `MI_SDI_NUM_DW(x)` and `MI_SDI_NUM_QW(x)` take the number of data payload dwords or qwords being stored and add the 3-dword header before subtracting 2. [F988]
- `xe_assert()`, `xe_tile_assert()`, and `xe_gt_assert()` compile out to `typecheck()` and `BUILD_BUG_ON_INVALID(condition)` when `CONFIG_DRM_XE_DEBUG` is disabled; never use them as branch conditions, with side-effecting expressions, or as the sole guard on runtime failure paths (use `drm_WARN` or `drm_err` with a fallback instead). [F1014]
- `COUNT_ARGS()` does not expand macro arguments before counting them; callers passing a macro whose expansion contains comma-separated arguments (such as `DROP_FIRST_ARG(...)`) must invoke it through `CALL_ARGS(COUNT_ARGS, ...)`. [F1018]
- In `compat-i915-headers/intel_uncore.h`, every `struct intel_uncore *` passed to `intel_uncore_read*`, `intel_uncore_write*`, or `intel_wait_for_register*` must be the `&xe->uncore` member embedded in `struct xe_device` (from `to_intel_uncore()`), because `__compat_uncore_to_mmio()` unconditionally downcasts it via `container_of(uncore, struct xe_device, uncore)`. Furthermore, `intel_wait_for_register()` and `intel_wait_for_register_fw()` take `timeout` in milliseconds (scaled by `USEC_PER_MSEC`), whereas `__intel_wait_for_register()` takes `fast_timeout_us` in microseconds and `slow_timeout_ms` in milliseconds and sets `atomic = !slow_timeout_ms && fast_timeout_us > 0`. [F985, F1038]
- In `compat-i915-headers/`, `intel_pxp_key_check()` requires `assign == false` (returning `-EINVAL` if `true` because Xe assigns PXP keys at BO creation), and `i915_gem_stolen_insert_node()` unconditionally triggers `BUG_ON(1)` (display callers must use `i915_gem_stolen_insert_node_in_range()`). [F987, F1067]
- Reading MOCS (`GLOBAL_MOCS`) or L3CC (`LNCFCMOCS`) registers in `read_mocs_table()` and `read_l3cc_table()` requires holding forcewake via `xe_force_wake_get()` (calling `xe_force_wake_put()` on any partially acquired domain mask if `xe_force_wake_ref_has_domain()` fails) and using `xe_gt_mcr_unicast_read_any()` when `regs_are_mcr(gt)` is true. [F1050]
- KUnit parameter description and generator callbacks (`xe_pci_fake_data_desc`, `xe_pci_live_device_gen_param`, `rtp_to_sr_desc`, `rtp_desc`, `lmtt_ops_param_get_desc`, `uint_param_get_desc`) must bound writes to `char *desc` by `KUNIT_PARAM_DESC_SIZE`. [F1042]
- Live KUnit test suites compiled into `xe.ko` (e.g., `xe_dma_buf_test_suite`, `xe_bo_test_suite`) must be marked `VISIBLE_IF_KUNIT`, exported with `EXPORT_SYMBOL_IF_KUNIT()`, and registered via `kunit_test_suite()` in `drivers/gpu/drm/xe/tests/xe_live_test_mod.c` with `MODULE_IMPORT_NS("EXPORTED_FOR_KUNIT_TESTING")`. [F1064]

## External Contracts

- In `struct guc_ct_buffer_desc`, each CTB is unidirectional: `head` must only be updated by the receiver and `tail` must only be updated by the sender. Broken by: host code writing `desc->head` on an H2G CTB or `desc->tail` on a G2H CTB during normal operation. [F975]
- In `struct guc_log_buffer_state`, `write_ptr` is read-only for the host and `read_ptr` is read-only for GuC; on a flush interrupt, the host must read up to `sampled_write_ptr`, update `read_ptr` to `sampled_write_ptr`, and clear `GUC_LOG_BUFFER_STATE_FLUSH_TO_FILE` in `flags` before acknowledging the flush to GuC. [F976]
- `XE_GUC_TLB_INVAL_MODE_LITE` must only be used when address translations for in-flight engine transactions remain invariant across the invalidation; `XE_GUC_TLB_INVAL_MODE_HEAVY` is required when unmapping or changing active page table translations that may be accessed by in-flight GPU transactions. [F977]
- In GuC SR-IOV and error-capture ABIs (`abi/guc_capture_abi.h`, `abi/guc_actions_sriov_abi.h`), `VFID == 0` identifies the PF while VFs use 1-based IDs (`1..63`), and in `GUC_ACTION_GUC2PF_VF_STATE_NOTIFY` event value `1` means `GUC_PF_NOTIFY_VF_ENABLE` when `VFID == 0` but `GUC_PF_NOTIFY_VF_FLR` when `VFID != 0`. [F1009]

## Known Pitfalls

- `struct guc_ct_buffer_desc` `head` and `tail` are dword offsets and `GUC_CTB_MSG_0_NUM_DWORDS` is the payload length in dwords excluding the 1-dword `GUC_CTB_HDR_LEN`, whereas `struct guc_log_buffer_state` offsets (`read_ptr`, `write_ptr`, `sampled_write_ptr`, `wrap_offset`, `size`) are in bytes. [F1007]
- In `abi/guc_capture_abi.h`, `struct guc_state_capture_group_t::capture_entries` cannot be indexed via `capture_entries[i]` because `struct guc_state_capture_t` ends with a flexible array `struct guc_mmio_reg mmio_entries[]` sized at runtime by `header.num_mmio_entries`; advance a byte pointer by `sizeof(struct guc_state_capture_header_t) + num_mmio_entries * sizeof(struct guc_mmio_reg)` instead. [F1040]
- Context register macros in `regs/xe_lrc_layout.h` (`CTX_CONTEXT_CONTROL`, `CTX_RING_HEAD`, `CTX_RING_TAIL`, `INDIRECT_CTX_RING_HEAD`, etc.) are 32-bit dword indices pointing directly to the register value dword (`offset_dw + 1`) in the LRC image, not byte offsets. Broken by: using them as byte offsets without multiplying by `sizeof(u32)` or adding `+ 1` again. [F1012]
- Because `ttm_bo_validate()` clears `xe_tt->purgeable` when repopulating a BO, any caller that needs to know whether `bo` was purgeable prior to validation must sample `xe_tt->purgeable` before calling `ttm_bo_validate()`. [F995]
- In `shrink_test_run_device()`, 64-bit division of `u64 purgeable` must use `div64_u64()` rather than `/` to avoid undefined `__udivdi3` link failures on 32-bit builds. [F1032]
- `xe_cur_kunit_priv(id)` dereferences `kunit_get_current_test()->priv` as `struct xe_test_priv *` to check `priv->id == id`, so KUnit tests invoking driver paths that call `xe_cur_kunit_priv()` must ensure `test->priv` is non-NULL with `base.id` initialized, and callers of `xe_cur_kunit_priv()` must NULL-check its return value. [F986]
- In KUnit parameter generators: `xe_pci_graphics_ip_gen_param()` and `xe_pci_media_ip_gen_param()` must reset `prev = NULL` when `is_insidevar(prev, pre_gmdid_*_ips)` is true after the first generator returns `NULL` before chaining to the second generator; `xe_pci_id_gen_param()` must filter out the trailing zero sentinel in `pciidlist` via `pci->driver_data ? pci : NULL`. [F1021, F1022]
- In `tests/xe_rtp_test.c`, `xe_rtp_process_to_sr_tests()` and `xe_rtp_process_tests()` pass `&active` (a single `unsigned long`) to `xe_rtp_process_ctx_enable_active_tracking()`, so test cases in `rtp_to_sr_cases` and `rtp_cases` must not exceed `BITS_PER_LONG` entries unless `active` is widened to a multi-word bitmap. [F1039]
