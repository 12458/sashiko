# INTEL DRM XE DRIVER (Lunar Lake and newer) — drivers/gpu/drm/xe (part 5)

GuC workload submission, GuC SR-IOV relay, GuC TLB invalidation, HuC firmware, hardware engines, hardware fences, interrupts, hwmon, I2C, late-binding firmware, Local Memory Translation Table (LMTT), and Logical Ring Context (LRC) management. It bridges the DRM scheduler to GuC firmware contexts, handles top-level PCI/MSI-X interrupts and hardware error interrupts, exposes hwmon power/thermal/fan sensors, and formats per-engine LRC context images and ringbuffers.

## Architecture & Data Flow

- `xe_hw_engine_setup_groups()` leaves `hwe->hw_engine_group` as `NULL` for `XE_ENGINE_CLASS_OTHER` engines, and `xe_hw_engine_group_add_exec_queue()` and `xe_hw_engine_group_del_exec_queue()` assert `group` is non-NULL, so callers must check `hwe->hw_engine_group` before invoking them. [F443]
- `fini_lmtt()` asserts `!(!!lmtt->ops ^ !!lmtt->pd)`, so `xe_lmtt_init()` must clear `lmtt->ops = NULL` if `lmtt_init_pd()` fails. [F448]
- In `xe_lrc.c`, `__xe_lrc_wa_bb_offset()`, `__xe_lrc_indirect_ctx_offset()`, and `__xe_lrc_indirect_ring_offset()` compute offsets backward from `xe_bo_size(lrc->bo)`, so any change to tail regions of `lrc->bo` in `xe_lrc_init()` or `xe_gt_lrc_size()` must update these offset helpers in lockstep. [F455]
- When `xe_lrc_has_indirect_ring_state(lrc)` is true, ring buffer registers (`START`, `HEAD`, `TAIL`, `CTL`) reside in the indirect ring state page accessed via `xe_lrc_read_indirect_ctx_reg()`/`xe_lrc_write_indirect_ctx_reg()` rather than the main context image accessed via `xe_lrc_read_ctx_reg()`/`xe_lrc_write_ctx_reg()`. [F456]
- `xe_lrc_write_ring()` only advances the software cursor `lrc->ring.tail`, so `submit_exec_queue()` must flush `lrc->ring.tail` to hardware via `xe_lrc_set_ring_tail()` for single-LRC queues or encode `lrc->ring.tail / sizeof(u64)` into the parallel workqueue item via `wq_item_append()` for parallel queues. [F457]
- In `xe_lrc_init()`, when `gt->default_lrc[hwe->class]` is present, the first `LRC_PPHWSP_SIZE` bytes of `lrc->bo` at `__xe_lrc_pphwsp_map(lrc)` must be zeroed and only the context image at offset `LRC_PPHWSP_SIZE` copied from `gt->default_lrc[hwe->class]`, isolating per-context PPHWSP state from the class template. [F458]
- During SR-IOV VF post-migration GGTT rebase, `xe_guc_contexts_hwsp_rebase()` must update both per-LRC GGTT references via `xe_exec_queue_contexts_hwsp_rebase()` and, for parallel queues, rewrite `XE_GUC_CONTEXT_WQ_EL_INFO_DATA_1_CTX_DESC_LOW` in all unconsumed `WQ_TYPE_MULTI_LRC` workqueue items via `wq_items_rebase()`. [F460]
- Because `alloc_guc_id()` stores a parallel `xe_exec_queue` pointer in `guc->submission_state.exec_queue_lookup` at every contiguous GuC ID in `q->guc->id .. q->guc->id + q->width - 1`, per-queue state transition loops over `exec_queue_lookup` such as `xe_guc_submit_stop()` and `xe_guc_submit_start()` must skip entries where `q->guc->id != index`. [F461]

## Synchronization

- On success, `xe_hw_engine_group_get_mode()` returns with `group->mode_sem` held as a read lock (upgrading to write and calling `downgrade_write(&group->mode_sem)` if a mode switch was required) that the caller must release via `xe_hw_engine_group_put()`, whereas on error it releases any acquired lock before returning. [F393]
- `switch_mode()`, `xe_hw_engine_group_suspend_faulting_lr_jobs()`, and `xe_hw_engine_group_wait_for_dma_fence_jobs()` are called with `group->mode_sem` write-locked by `xe_hw_engine_group_get_mode()` and must not release `group->mode_sem` on any path, leaving unlock on failure to the caller. [F394]
- Because `xe_guc.submission_state.lock` is primed under `fs_reclaim_acquire(GFP_KERNEL)` and held in the dma-fence signaling path, code holding `guc->submission_state.lock` (such as `alloc_guc_id`) must not perform `GFP_KERNEL` allocations or wait for GFX hardware responses. [F411]
- `xe_guc_submit_reset_prepare` must use atomic operations on `guc->submission_state.stopped` rather than acquiring `guc->submission_state.lock`, because it can be invoked from a G2H handler holding the CT lock while `submission_state.lock` holders acquire the CT lock to resubmit jobs. [F412]
- In `guc_exec_queue_timedout_job` and `xe_guc_exec_queue_lr_cleanup`, the driver must call `xe_sched_submission_stop(sched)` before sampling queue state or disabling scheduling, and must wait for `!exec_queue_pending_disable(q) || xe_guc_read_stopped(guc)` before signaling job fences or completing cleanup. [F414]
- In `guc_exec_queue_timedout_job`, hardware fence IRQ signaling must be stopped via `xe_hw_fence_irq_stop(q->fence_irq)` before re-adding the timed-out job to `pending_list`, restarting the scheduler, and setting error status on pending jobs under `sched->base.job_list_lock`, and then restarted via `xe_hw_fence_irq_start(q->fence_irq)`. [F415]
- Enqueuing a preallocated static `xe_sched_msg` (`STATIC_MSG_SUSPEND` or `STATIC_MSG_RESUME`) via `guc_exec_queue_try_add_msg` and setting `q->guc->suspend_pending = true` must be serialized under `xe_sched_msg_lock(sched)` (`sched->base.job_list_lock`), checking `list_empty(&msg->link)` before adding the message. [F418]
- In `xe_hw_engine_group_get_mode`, when upgrading `group->mode_sem` from read to write by dropping the read lock and calling `down_write_killable(&group->mode_sem)`, the caller must recheck `new_mode != group->cur_mode` before calling `switch_mode(group)` and then call `downgrade_write(&group->mode_sem)`. [F426]

## Object Lifetimes

- In `xe_guc_submit.c`, `guc_exec_queue_init()` and `guc_exec_queue_fini()` must strictly pair the GuC submission backend resources (`ge`, `ge->sched`, `ge->entity`, and `alloc_guc_id()` / `release_guc_id()`), while `guc_exec_queue_destroy()` and `__guc_exec_queue_destroy_async()` handle asynchronous TDR cancellation and call `xe_exec_queue_fini(q)`. [F395]
- When `alloc_guc_id()` reserves `q->width` contiguous GuC IDs via `xe_guc_id_mgr_reserve_locked()` and stores `q` into `guc->submission_state.exec_queue_lookup` at indices `q->guc->id + i`, a failure at index `i` must call `__release_guc_id(guc, q, i)` to erase only the `i` populated xarray entries while releasing all `q->width` IDs. [F396]
- An exec queue that takes an extra `xe_exec_queue_get(q)` reference when registered in `register_exec_queue()` (for `xe_exec_queue_is_lr(q)`) or when setting `EXEC_QUEUE_STATE_EXTRA_REF` in `guc_exec_queue_timedout_job()` must drop that reference via `xe_exec_queue_put(q)` in `handle_deregister_done()` or `guc_exec_queue_stop()`. [F397]
- Every `xe_sched_msg` queued by `guc_exec_queue_add_msg()` takes a runtime PM reference via `xe_pm_runtime_get_noresume()` released in `guc_exec_queue_process_msg()`, where `SET_SCHED_PROPS` messages must be freed via `kfree(msg)` while `CLEANUP`, `SUSPEND`, and `RESUME` use `q->guc->static_msgs`. [F399]
- `xe_hw_fence_enable_signaling()` acquires a `dma_fence_get(dma_fence)` reference when linking `fence->irq_link` onto `irq->pending`, and both `hw_fence_irq_run_cb()` and `xe_hw_fence_irq_finish()` must remove the fence with `list_del_init(&fence->irq_link)` before dropping that reference with `dma_fence_put()`. [F401]
- `xe_lrc_snapshot_capture()` takes a buffer object reference `snapshot->lrc_bo = xe_bo_get(lrc->bo)` that is consumed and cleared (`snapshot->lrc_bo = NULL`) by `xe_lrc_snapshot_capture_delayed()`, and `xe_lrc_snapshot_free()` must still check `if (snapshot->lrc_bo) xe_bo_put(snapshot->lrc_bo)` in case the delayed capture never ran. [F402]
- All VF LMTT page tables allocated for a VF via `xe_lmtt_prepare_pages()` must be released via `xe_lmtt_drop_pages()` (which clears `pd->entries[vfid]` and recursively frees child page tables) before driver teardown, because `lmtt_fini_pd()` asserts `!pd->entries[n]` for every root page directory entry. [F406]
- In `xe_hw_engine.c`, `xe_hw_engine_snapshot_capture()` may lock a matched GuC error-capture node via `xe_guc_capture_get_matching_and_lock(q)` and store it in `coredump->snapshot.matched_node`, which `xe_hw_engine_snapshot_free()` must release by calling `xe_guc_capture_put_matched_nodes(&gt->uc.guc)` before freeing `snapshot->name` and `snapshot`. [F407]

## API Contracts

- `send_tlb_inval_ggtt()` and `send_tlb_inval_ppgtt()` in `xe_guc_tlb_inval.c` must return `-ECANCELED` whenever they complete or skip invalidation without sending an asynchronous GuC CT request, because `xe_tlb_inval_issue()` only signals the prepared fence immediately on `< 0` and squashes `-ECANCELED` to `0`. [F439]
- Callers of `xe_guc_relay_send_to_pf()`, `xe_guc_relay_send_to_vf()`, and `__relay_get_transaction()` must pass `buf` (`resp`) and `buf_size` (`resp_size`, in dwords) either both as `NULL`/`0` or both non-zero with `GUC_RELAY_MSG_MIN_LEN <= resp_size <= GUC_RELAY_MSG_MAX_LEN`. [F441]
- `xe_hw_fence_alloc()` (and `xe_lrc_alloc_seqno_fence()`) returns an uninitialized `struct dma_fence *` (or `ERR_PTR(-ENOMEM)`), so before `xe_hw_fence_init()` sets `fence->ops = &xe_hw_fence_ops`, callers must release it with `xe_hw_fence_free()` rather than `dma_fence_put()` and must not call `to_xe_hw_fence()`. [F442]
- `xe_hw_engine_mmio_write32()` and `xe_hw_engine_mmio_read32()` add `hwe->mmio_base` to `reg.addr` and assert `!(reg.addr & hwe->mmio_base)` and `xe_force_wake_assert_held(gt_to_fw(hwe->gt), hwe->domain)`, so callers must hold forcewake for `hwe->domain` and pass a 0-based engine register offset rather than one parameterized with `hwe->mmio_base`. [F445]
- `xe_lmtt_prepare_pages()`, `xe_lmtt_populate_pages()`, and `xe_lmtt_drop_pages()` require an initialized `lmtt->pd`, a 1-based `vfid` (`1 <= vfid <= lmtt->ops->lmtt_pte_num(pd->level)`), and `range`, `offset`, and `xe_bo_size(bo)` aligned to `lmtt_page_size(lmtt)` (2 MiB). [F447]
- In `xe_irq_msix_request_irq()`, `u16 *msix` is an in-parameter when `dynamic_msix` is `false` (reserving the exact vector `*msix` via `XA_LIMIT(*msix, *msix)`) and an out-parameter when `dynamic_msix` is `true` (allocating a vector in `[NUM_OF_STATIC_MSIX, xe->irq.msix.nvec - 1]` and storing it in `*msix`). [F449]
- Each `struct bo_setup::setup` callback in `xe_lrc.c` takes `max_len` in `u32` dwords and must return the number of `u32` dwords written (or a negative errno), and `setup_bo()` fails with `-ENOSPC` if any callback returns `< 0` or leaves fewer than `state->reserve_dw` dwords remaining. [F451]
- `xe_hwmon_power_curr_crit_read()` and `xe_hwmon_power_curr_crit_write()` scale the U10.6 PCODE `I1` value by `scale_factor`, so callers must pass `SF_POWER` (`1000000`, microwatts) for `hwmon_power_crit` (when `POWER_SETUP_I1_WATTS` is set) and `SF_CURR` (`1000`, milliamperes) for `hwmon_curr_crit` (when clear). [F454]

## Error Handling

- In `parse_cpd_header()` and `parse_lb_layout()`, the local `offset` variable is only assigned inside a loop when an entry name matches `manifest_entry` or `fpt_entry`, so `offset` must be initialized to `0` before the loop prior to checking `if (!offset)`. [F436]
- `xe_late_bind_fw_num_fans()` returns the negative error code from `xe_pcode_read()` and writes the fan count via the `u32 *num_fans` out-parameter, so `__xe_late_bind_fw_init()` must check its return status before inspecting `num_fans`. [F437]
- In `xe_late_bind_work()`, `late_bind->component.ops->push_payload()` returns `0` on success, a negative errno (with `-EBUSY` retried up to `LB_FW_LOAD_RETRY_MAXCOUNT`), or a positive `INTEL_LB_STATUS_*` failure code decoded by `xe_late_bind_parse_status()`, and any non-zero final result must free and clear `lbfw->payload`. [F438]
- In `xe_guc_relay.c`, `relay_send_transaction()` converts any positive return from `xe_guc_ct_send_block()` into `-EPROTO`, whereas `relay_send_message_and_wait()` returns the positive `txn->response_len` (in dwords) on success and converts positive remote `txn->reply` error codes into negative errnos via `from_relay_error()`. [F440]
- In `heci_gsc_add_device()`, if `auxiliary_device_init()` fails, `adev` must be freed with `kfree(adev)`, whereas if `auxiliary_device_add()` fails after `auxiliary_device_init()` succeeds, `heci_gsc->adev` must be reset to `NULL` and `auxiliary_device_uninit()` called without `kfree(adev)` because `heci_gsc_release_dev()` frees `adev`. [F453]
- In relay_handle_reply(), when reply == 0, the incoming message dword length len must be checked against pending->response_len before copying 4 * len bytes into pending->response, setting reply and err to -ENOBUFS if len > pending->response_len. [F477]
- In `xe_hwmon_fan_input_read()`, `time` (`jiffies_delta_to_msecs(time_now - fi->time_prev)`) must be verified non-zero (returning `-EAGAIN` before updating `fi->reg_val_prev` and `fi->time_prev`) prior to calling `DIV_ROUND_UP_ULL(rotations * (MSEC_PER_SEC * 60), time)`. [F510]
- In guc_exec_queue_timedout_job(), kernel warnings (xe_gt_WARN) must only be emitted when a timed-out job belongs to an EXEC_QUEUE_FLAG_KERNEL queue or a non-killed EXEC_QUEUE_FLAG_VM queue, whereas user queue timeouts log at xe_gt_notice() without warning. [F571]

## External Contracts

- When relay_process_incoming_action() sends an error reply to a remote VF (txn->remote != 0), it must pass the error and hint through sanitize_relay_error() and sanitize_relay_error_hint() so non-debug builds (!CONFIG_DRM_XE_DEBUG) report GUC_RELAY_ERROR_UNDISCLOSED and 0. [F478]
- In drivers/gpu/drm/xe/xe_hwmon.c, hwmon callbacks must scale register values using SF_POWER (uW), SF_CURR (mA), SF_VOLTAGE (mV), MILLIDEGREE_PER_DEGREE (mC), SF_ENERGY (uJ), and SF_TIME (ms). [F574]
- In drivers/gpu/drm/xe/xe_hwmon.c, the pcode I1 threshold (xe_hwmon_pcode_read_i1) must be exposed as hwmon_power_crit on CHANNEL_CARD only when POWER_SETUP_I1_WATTS (bit 31) is set, and as hwmon_curr_crit on CHANNEL_PKG only when POWER_SETUP_I1_WATTS is clear. [F576]
- In drivers/gpu/drm/xe/xe_lrc.c, setup_configfs_post_ctx_restore_bb() and setup_configfs_mid_ctx_restore_bb() must reject user-configured dword counts exceeding max_len with -ENOSPC and call add_taint(TAINT_TEST, LOCKDEP_STILL_OK) before copying commands into the LRC. [F581]

## Known Pitfalls

- In `relay_process_incoming_action()`, the `if (ret == -EINPROGRESS)`, `if (ret > 0)`, and `if (ret < 0)` blocks must remain sequential `if` statements (not `else if`), and the `if (ret < 0)` block must reset `again = false` before `if (again)` re-adds `txn->link` to `relay->incoming_actions`. [F495]
- In `__lmtt_alloc_range()`, the next page-directory boundary must be computed as `min(end, round_up(offset + 1, pte_addr_shift))` using `offset + 1` rather than `offset` so `next` strictly advances when `offset` is already aligned to `pte_addr_shift`. [F498]
- In `xe_hwmon_power_max_write()` and `xe_hwmon_power_curr_crit_write()`, the sysfs `value` must be clamped to the maximum field-supported scaled limit (`max_supp_power_limit` / `max_crit_power_curr`) before left-shifting in `DIV_ROUND_CLOSEST_ULL()` and packing into `PWR_LIM_VAL` or `POWER_SETUP_I1_DATA_MASK`. [F506]
- In `xe_hwmon_power_max_interval_show()` and `xe_hwmon_power_max_interval_store()`, the 2-bit mantissa `(1 << x_w) | x` must be cast to `u64` before shifting left by `y` (`tau4`), and the `x_w` (2) fixed-point offset must be added to the right shift (`hwmon->scl_shift_time + x_w`) rather than shifting by `y - x_w`. [F507]
- In `xe_hwmon_power_max_interval_store()`, `val` must be checked for zero before calling `ilog2(val)`, and the mantissa `x` must be computed as `(val - (1ul << y)) << x_w >> y` rather than shifting right by `y - x_w`. [F508]
- In `check_timeout()`, the 64-bit context timestamp from `xe_lrc_ctx_timestamp()` must be truncated with `lower_32_bits()` before subtracting the 32-bit `xe_lrc_ctx_job_timestamp()` in `u32 diff`, and `running_time_ms` must be scaled via `ADJUST_FIVE_PERCENT` (`mul_u64_u32_div(__t, 105, 100)`). [F513]
- In xe_guc_submit.c, wqi_head, wqi_tail, wq_desc.head, wq_desc.tail, and WQ_SIZE are in bytes, so indexing the u32 arrays guc_submit_parallel_scratch::wq and snapshot->parallel.wq must divide byte offsets by sizeof(u32), while WQ_RING_TAIL_MASK and child ring tails in wq_item_append() must divide lrc->ring.tail by sizeof(u64). [F519]
