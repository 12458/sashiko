# BCACHE (BLOCK LAYER CACHE) — drivers/md/bcache (part 1)

Implements the core Linux block-layer cache (bcache), enabling fast SSD devices to act as writethrough, writeback, or writearound caches for slower backing block devices, as well as providing thin-provisioned flash-only volumes. This component manages cache set and backing device registration, on-disk superblocks, bucket allocation and priority/generation tracking, a hybrid log-structured B+ tree index (`btree` and `bset`) with auxiliary floating-point search trees, metadata journaling, moving garbage collection, and block request submission/splitting.

## Architecture & Data Flow

- Because struct btree instances are recycled across c->btree_cache_freeable and c->btree_cache_freed until bch_btree_cache_free(), mca_bucket_free() must zero b->key.ptr[0] and remove b->hash via hlist_del_init_rcu(), and bch_btree_keys_free() must reset t->prev, t->tree, and t->data to NULL after freeing them. [F12]
- The btree root node c->root must be unlinked from c->btree_cache via list_del_init(&b->list) whenever it is installed (in run_cache_set() and bch_btree_set_root()) and re-added to c->btree_cache in cache_set_flush() before flushing and calling bch_btree_cache_free(). [F13]
- Every increment of c->prio_blocked in make_btree_freeing_key() must be paired either with parent node insertion (where bch_btree_ptr_insert_fixup() transfers it to btree_current_write(b)->prio_blocked for btree_complete_write() to release) or with atomic_dec(&b->c->prio_blocked) for each ZERO_KEY popped on rollback. [F16]
- The btree shrinker callbacks bch_mca_scan() and bch_mca_count() must bound the number of reclaimable btree nodes by mca_can_free(c), leaving at least mca_reserve(c) allocated nodes in c->btree_cache and c->btree_cache_freeable. [F18]
- A struct bcache_device pointer in c->devices[i] (or s->d in cache_lookup()) can be either a standalone struct bcache_device allocated by flash_dev_run() or the embedded dc->disk member of a struct cached_dev, so code must verify d is non-NULL and !UUID_FLASH_ONLY(&c->uuids[i]) before downcasting via container_of(d, struct cached_dev, disk). [F50]
- In struct cache_sb, cache-device fields (nbuckets, bucket_size, nr_in_set, nr_this_dev) share a union with backing-device data_offset, and holder is allocated as struct cached_dev or struct cache, so generic registration paths must branch on SB_IS_BDEV(sb) before accessing union fields or casting holder. [F51]
- Superblock feature masks (sb->feature_compat, sb->feature_ro_compat, sb->feature_incompat) are only populated when sb->version >= BCACHE_SB_VERSION_CDEV_WITH_FEATURES, so feature checks must use bch_has_feature_*() helpers or explicitly verify sb->version >= BCACHE_SB_VERSION_CDEV_WITH_FEATURES before reading them. [F52]
- mca_bucket_alloc() must allocate struct btree using kzalloc() (zeroed memory) because bch_btree_keys_init() relies on b->keys.set[].size and b->keys.set[].data already being zeroed at allocation time rather than clearing them on initialization. [F62]
- When `bch_extent_insert_fixup()` modifies an existing extent `k` in place via `bch_cut_back()` or `__bch_cut_back()`, it must call `bch_bset_fix_invalidated_key(b, k)` so that any written `bset_tree` (`t->end` or `bkey_float` nodes) referencing `k`'s key offset is updated. [F67]

## Synchronization

- In btree_gc_coalesce(), error paths taken after locking new_nodes[i]->write_lock must jump to out_unlock_nocoalesce to unlock new_nodes[i]->write_lock for all allocated nodes before out_nocoalesce calls btree_node_free(new_nodes[i]), which acquires write_lock internally. [F8]
- Callers of btree_node_free(b) must hold b->lock for write and call btree_node_free(b) before calling rw_unlock(true, b), because btree_node_free() places b on c->btree_cache_freeable where mca_reap() can immediately acquire b->lock via down_write_trylock(&b->lock) once b->lock is released. [F9]
- In bch_allocator_thread(), allocator_wait(ca, cond) is entered with ca->set->bucket_lock held and sets TASK_INTERRUPTIBLE; when exiting on kthread_should_stop() or CACHE_SET_IO_DISABLE, it must unlock ca->set->bucket_lock, restore task state to TASK_RUNNING, and jump to out without re-acquiring bucket_lock. [F22]
- In bch_cached_dev_attach(), bcache_device_attach() must set dc->disk.c and issue smp_wmb() before refcount_set(&dc->count, 1) publishes the cached device, pairing with smp_mb__after_atomic() in cached_dev_get(). [F25]
- Before calling bcache_device_stop(&dc->disk) due to backing-device errors, offline timeout, or a failed cache set with dirty data (atomic_read(&dc->has_dirty)), dc->io_disable must be set to true followed by smp_mb(). [F30]
- When btree_flush_write() selects dirty btree nodes from c->btree_cache to flush outside c->bucket_lock, it must set BTREE_NODE_journal_flush under both c->bucket_lock and b->write_lock, and mca_reap() and btree_node_free() must wait under b->write_lock until BTREE_NODE_journal_flush is cleared. [F33]
- c->bucket_lock must be held whenever mutating c->btree_cache, c->btree_cache_freeable, c->btree_cache_freed, c->bucket_hash, c->gc_mark_valid, or bucket allocation freelists (ca->free[], ca->free_inc, ca->heap) in mca_alloc(), mca_reap(), __bch_bucket_alloc_set(), and __bch_invalidate_one_bucket(). [F35]
- In cached_dev_write(), dc->writeback_lock must be held shared via down_read_non_owner() across bch_keybuf_check_overlapping(&dc->writeback_keys, ...), bch_writeback_add(dc), and bch_data_insert() until cached_dev_write_complete() calls up_read_non_owner(). [F36]
- Nested struct btree rw_semaphores (b->lock) must be acquired strictly in descending order of b->level (parent before child) and, for nodes at the same b->level, in ascending bkey_cmp(&a->key, &b->key) order. [F38]

## Object Lifetimes

- bch_btree_insert() consumes all keys in its keylist argument and drops one bucket pin reference via bkey_put() for each key both upon leaf insertion (in bch_btree_insert_keys()) and upon error (by popping remaining keys), while leaving the keylist's buffer allocated for the caller to free with bch_keylist_free(). [F2]
- bch_alloc_sectors() returns true with a bucket pin reference held for each pointer in k (by incrementing PTR_BUCKET(c, &b->key, i)->pin while b->sectors_free remains non-zero and transferring the open_bucket's initial pin when b->sectors_free reaches zero), which the caller must release via bch_btree_insert() or bkey_put(). [F3]
- In bcache_device_free(), any access to d->disk fields (such as disk->disk_name and disk->first_minor for ida_free(&bcache_device_idx, ...)) must occur before put_disk(disk) is called. [F6]
- In register_cache(), any log message or access referencing bdev_file or ca must execute before fput(bdev_file) (on cache_alloc() failure) or kobject_put(&ca->kobj) (at the out label, which invokes bch_cache_release() to fput(ca->bdev_file) and kfree(ca)). [F7]
- In register_bcache(), after reading the superblock via a read-only bdev_file and allocating the holder object (struct cached_dev or struct cache), the block device must be reopened with BLK_OPEN_READ | BLK_OPEN_WRITE passing holder to bdev_file_open_by_dev() and the initial read-only bdev_file immediately closed with fput(). [F10]
- In bch_cached_dev_run(), every return path after allocating buf, env[1], and env[2] at function entry must jump to out to kfree(env[1]), kfree(env[2]), and kfree(buf). [F11]
- btree_complete_write() must reset w->prio_blocked = 0 and w->journal = NULL after releasing the c->prio_blocked count and w->journal pin reference. [F14]
- Both cache_set_free() (under bch_register_lock) and bch_cache_release() must clear the cross-pointers ca->set and c->cache to NULL before releasing ca, because bch_cache_set_alloc() links c->cache = ca and ca->set = c before register_cache_set() increments ca->kobj. [F15]

## API Contracts

- When journaling is active, bch_journal() returns a pointer to the current journal entry's atomic_t pin in c->journal.pin with its reference count incremented by 1, and the caller must decrement that returned atomic_t via atomic_dec_bug() after bch_btree_insert() finishes. [F1]
- bch_btree_node_get() and __bch_btree_node_alloc() return either an ERR_PTR or a valid struct btree pointer with b->lock held (read- or write-locked per the write parameter for bch_btree_node_get(), and write-locked for __bch_btree_node_alloc()), which the caller owns and must release with rw_unlock(). [F4]
- mca_alloc(), __bch_btree_node_write(), bch_btree_insert(), and bch_journal_meta() must never be called when current->bio_list is non-NULL (such as directly from submit_bio_noacct); bch_btree_node_get() and bch_btree_insert_node() must return -EAGAIN so callers defer to bcache_wq. [F42]
- bch_btree_node_get() and __bch_btree_node_alloc() never return NULL; they return either a locked struct btree pointer or an ERR_PTR value (such as ERR_PTR(-EAGAIN), ERR_PTR(-EINTR), ERR_PTR(-ENOMEM), or ERR_PTR(-EIO)), so callers must check IS_ERR() rather than testing for NULL. [F47]
- bch_bucket_alloc() returns a non-negative bucket index on success and -1 on failure (requiring a signed long variable), whereas __bch_bucket_alloc_set() and bch_bucket_alloc_set() return 0 on success and -1 on failure, and bch_alloc_sectors() returns true on success and false on failure. [F53]
- Within bcache_btree_root() and bcache_btree() traversals, returning -EINTR restarts the operation from c->root (after releasing node locks, calling bch_cannibalize_unlock(c), and scheduling), whereas returning -EAGAIN aborts the traversal and propagates out of bcache_btree_root() when current->bio_list is non-NULL. [F54]
- Callbacks for bch_btree_map_nodes() and bch_btree_map_keys() (btree_map_nodes_fn and btree_map_keys_fn), as well as d->cache_miss(), must return MAP_CONTINUE (1) to keep iterating, MAP_DONE (0) to terminate normally, or a negative errno (such as -EINTR or -EAGAIN) to abort traversal. [F56]
- In super.c, read_super(), read_super_common(), uuid_read(), and register_cache_set() return NULL on success and a non-NULL error string on failure (and read_super() only populates *res and retains the superblock folio on NULL return), whereas run_cache_set(), register_cache(), and register_bdev() return 0 on success and a negative errno on failure. [F57]

## Error Handling

- c->root in struct cache_set can be NULL (before run_cache_set() assigns it), an ERR_PTR (when bch_btree_node_get() or __bch_btree_node_alloc() fails in run_cache_set()), or a valid struct btree pointer, so cache_set_flush() and mca_reserve() must check !IS_ERR_OR_NULL(c->root) before dereferencing c->root. [F48]
- In btree_gc_coalesce() and btree_gc_recurse(), node pointers in new_nodes[] and struct gc_merge_info r[] can hold NULL (from memset or array shifting), an ERR_PTR (such as the ERR_PTR(-EINTR) sentinel or a failed allocation/get), or a valid struct btree pointer, so loops inspecting or cleaning them up must check !IS_ERR_OR_NULL(). [F49]
- In btree_flush_write(), the journal pin reference count read via atomic_read(fifo_front_p) must be stored in a signed int (ref_nr) rather than an unsigned integer so that the non-positive check ref_nr <= 0 and loop termination check nr >= ref_nr behave as signed comparisons. [F59]
- In debugfs read handlers such as bch_dump_read(), a non-zero residual byte count returned by copy_to_user() must be translated into -EFAULT rather than returned directly as the ssize_t result. [F60]
- bch_keybuf_next() initializes w->private to ERR_PTR(-EINTR) to mark the keybuf_key as claimed, so callers such as read_moving() that jump to error cleanup before or after assigning a heap pointer to w->private must check !IS_ERR_OR_NULL(w->private) before calling kfree(w->private). [F65]
- In read_super(), when sb->version is BCACHE_SB_VERSION_CDEV_WITH_FEATURES, sb->feature_compat, sb->feature_incompat, and sb->feature_ro_compat must be converted from disk endianness and validated against supported feature masks via bch_has_unknown_*_features() before calling read_super_common(). [F90]
- In journal_read_bucket(), set_bytes(j) for an on-disk struct jset must be checked against the remaining bucket bytes (left << 9), the maximum journal buffer size (PAGE_SIZE << JSET_BITS), and the current read window (len << 9, triggering reread if larger) before calling csum_set(j) or copying j into struct journal_replay. [F93]
- In bch_btree_node_read_done(), each on-disk struct bset must be checked to ensure b->written + set_blocks(i, block_bytes(b->c->cache)) <= btree_blocks(b) before computing csum_set(i) or btree_csum_set(b, i) or pushing [i->start, bset_bkey_last(i)) onto iter. [F94]

## External Contracts

- Because csum_set() computes the CRC64 from byte 8 of a structure up to bset_bkey_last(i) ((uint64_t *)(i)->d + (i)->keys), fields in struct cache_sb_disk must never be added after d[SB_JOURNAL_BUCKETS], as they lie beyond bset_bkey_last(s) and are excluded from the superblock checksum. [F106]
- In bch_prio_write() and prio_read(), each 3-byte packed struct bucket_disk entry in struct prio_set must have its 16-bit prio converted via cpu_to_le16() / le16_to_cpu(), and the prio_set checksum must be computed with bch_crc64(&p->magic, meta_bucket_bytes(&ca->sb) - 8) rather than csum_set(). [F110]
- When attaching a cached device in bch_cached_dev_attach() or starting a flash-only volume in flash_dev_run() on a cache set where bch_has_feature_obso_large_bucket(&c->cache->sb) is true, the bcache gendisk must be marked read-only via set_disk_ro(..., 1). [F111]
- In struct cache_sb_disk and struct cache_sb, fields must not be added after data_offset in the backing-device union struct because read_super() reads block_size from the cache-device union struct even when SB_IS_BDEV(sb) is true. [F112]
- In register_bcache(), when bdev_file_open_by_dev() fails with -EBUSY and attr == &ksysfs_register_quiet, the handler must suppress error logging and return size rather than -EBUSY to userspace. [F203]

## Known Pitfalls

- When `bch_extent_insert_fixup()` splits an unwritten key (`!bkey_written(b, k)`) overlapped in the middle by `insert`, it must copy `k` into a temporary `BKEY_PADDED` buffer before calling `bch_bset_insert(b, k, &temp.key)` because `bch_bset_insert()` `memmove`s the bset at `where` before copying `insert`. [F69]
- In-memory struct cache_sb has a different binary layout, field width (notably __u32 bucket_size vs __le16 bucket_size in struct cache_sb_disk), and field ordering from on-disk struct cache_sb_disk, so read_super() and __write_super() must translate each field individually with le*_to_cpu() / cpu_to_le*(). [F107]
- In `do_bio_hook()`, `bio_init_clone()` must be passed the source bio's block device (`orig_bio->bi_bdev`) rather than the destination `s->bio.bio.bi_bdev` (`bio->bi_bdev`), which may be uninitialized. [F115]
- Inner blocks in `run_cache_set()` (such as the `CACHE_SYNC(&c->cache->sb)` branch) must use the function-scoped `LIST_HEAD(journal)` and never redeclare a shadowing `journal` list head, because the `err:` cleanup label frees remaining `struct journal_replay` entries from the outer `journal` list. [F117]
- `bch_extent_merge()` must check `KEY_SIZE(l) + KEY_SIZE(r) > USHRT_MAX` and saturate `l` at `USHRT_MAX` (cutting `r` from the front) before calling `SET_KEY_SIZE()`, because `SET_KEY_SIZE` masks its argument to 16 bits (`KEY_SIZE_BITS`) and would wrap the merged extent size. [F134]
- `bucket_to_sector()` must cast the bucket index `size_t b` to `sector_t` before shifting left by `c->bucket_bits`, because on 32-bit architectures with 64-bit `sector_t`, `size_t` is 32 bits and shifting before widening truncates sector offsets above 2 TiB (`2^32` sectors). [F136]
- In `__bch_btree_mark_key()`, adding `KEY_SIZE(k)` to `GC_SECTORS_USED(g)` must be clamped to `MAX_GC_SECTORS_USED` (`(1 << 13) - 1`) before calling `SET_GC_SECTORS_USED()`, because `GC_SECTORS_USED` is a 13-bit field in `g->gc_mark` and `SET_GC_SECTORS_USED` masks its input without saturation. [F137]
- In `bch_count_io_errors()`, `ca->io_errors` stores the error count left-shifted by `IO_ERROR_SHIFT` (20), so decaying `errors` by `127 / 128` must widen `errors` to `uint64_t` before multiplying by `127`, and threshold checks against `ca->set->error_limit` must right-shift by `IO_ERROR_SHIFT`. [F139]
