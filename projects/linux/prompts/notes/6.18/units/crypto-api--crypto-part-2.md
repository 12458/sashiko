# CRYPTO API — crypto (part 2)

This component provides the software async crypto daemon (`cryptd`), hardware crypto engine framework (`crypto_engine`), netlink configuration (`crypto_user`), FIPS mode (`fips`), DH/ECDH, NIST SP800-90A DRBG, and standard cipher modes, AEADs, MACs, KDFs, Deflate, and checksums.

## Architecture & Data Flow

- `struct cryptd_{skcipher,hash,aead}_ctx` must keep `refcount_t refcnt` first so `cryptd_enqueue_request()` can cast `crypto_tfm_ctx(request->tfm)` under `bh_lock`. `cryptd_*_init_tfm()` must size the parent request context to include `cryptd_*_request_ctx` plus the child's `reqsize`/`descsize` (never stack subrequests). [F193, F301]
- In `crypto_pump_requests()`, when `!engine->retry_support`, the active request is saved in `engine->cur_req` and further dequeues block until `crypto_finalize_request()` clears `engine->cur_req = NULL` under `queue_lock` before queuing `pump_requests`. Helpers like `crypto_engine` must never define private `cra_flags` bits on `struct crypto_alg` outside `include/linux/crypto.h`. [F232, F332]
- In `crypto/drbg.c`, `drbg_algs` needs `>= ARRAY_SIZE(drbg_cores) * 2` slots, with `drbg_cores` ordered lowest-to-highest preference. `drbg_seed()` rejects `pers->len > drbg_max_addtl(drbg)` and scales initial non-test `entropylen` to `((entropylen + 1) / 2) * 3`; `drbg_generate()` rejects `buflen > drbg_max_request_bytes(drbg)` or `addtl->len > drbg_max_addtl(drbg)`. When `d_ops->update` succeeds in `__drbg_seed()`, `seeded`, `last_seed_time`, `reseed_ctr`, and `reseed_threshold` must update in lockstep. [F234, F238, F261, F298]
- In `drbg_alloc_state()` and `drbg_init_sym_kernel()`, `Vbuf`, `Cbuf`, `scratchpadbuf`, and `outscratchpadbuf` need `+ alignmask` bytes, `PTR_ALIGN(..., alignmask + 1)` alignment, and freeing via unaligned `*buf` pointers. In `drbg_ctr_update()`, `reseed` is 4-state (0=init, 1=reseed, 2=pre-gen DF, 3=post-gen): zero `df_data` on entry only when `reseed < 3` and on exit only when `reseed != 2`. In `drbg_kcapi_sym_ctr()`, each loop iteration must call `crypto_init_wait(&drbg->ctr_wait)` and `memzero_explicit(drbg->outscratchpad, cryptlen)` after copying to `outbuf`. [F273, F279, F280]
- Buffers mapped via `sg_init_one()`/`sg_set_buf()` in `crypto_gcm_setkey()`, `gcm_zeroes`, `drbg_kcapi_sym_ctr()`, and `essiv_aead_crypt()` must be in kmalloc or request-context memory, never on the stack or in static module data. [F327]
- In `essiv_aead_request_ctx` (`aead_req`) and `hctr2_request_ctx` (`u`), the variable-length subrequest must be the last member so trailing data at `ivoffset`/`hashed_tweak_offset` never overlaps. In `essiv_create()`, the spawn setup, registration, and `out_drop_skcipher` branches on `ictx->u` must all test `CRYPTO_ALG_TYPE_LSKCIPHER` (using `crypto_spawn_skcipher_alg_common`) vs. `CRYPTO_ALG_TYPE_AEAD`. `essiv_aead_crypt()` must check `int ssize = req->assoclen - crypto_aead_ivsize(tfm) < 0` at entry. [F251, F265, F274]
- `hctr2_setkey()` must update `blockcipher` and `xctr` keys, derive `hbar = E_K(0)` and `L = E_K(1)`, key `polyval` with `hbar`, and recompute both exported tweak-length states via `hctr2_hash_tweaklen(tctx, true/false)`. In `crypto/hmac.c`, `__hmac_create_shash()` and `hmac_create_ahash()` must size `pads[]` by `statesize * 2` (`ss * 2`), enforce `ds <= cra_blocksize && ss >= cra_blocksize`, and keep shash/ahash `ipad` (`&pads[0]`) and `opad` (`&pads[ss]`) layouts in lockstep. [F241, F242, F303]
- In `crypto/crypto_user.c`, `crypto_user_rcv_msg()` must verify `type <= CRYPTO_MSG_MAX` before subtracting `CRYPTO_MSG_BASE` to index `crypto_msg_min`/`crypto_dispatch`. Handlers reading `struct crypto_user_alg` must check `null_terminated()` on `cru_name`, `cru_driver_name`, and `cru_module_name`. In `crypto_dump_report()`, increment `pos` only after `crypto_report_alg()` succeeds; on `-EMSGSIZE`, break without incrementing `pos`, save `cb->args[0] = pos`, and return `skb->len`. [F260, F263, F290]
- `ecdh_set_secret()` must check `params.key_size <= sizeof(u64) * ctx->ndigits` before `ecc_digits_from_bytes()`. `ecdh_compute_value()` (`req->src != NULL`) requires `req->src_len == public_key_sz` (`2 * nbytes`) and clamps output copy to `min_t(size_t, nbytes, req->dst_len)`. In `crypto/dh.c`, `__add_u64_to_be()` loops with 1-based `for (i = n; val && i > 0; --i)` indexing `dst[i - 1]` with carry `val = tmp >= val ? 0 : 1`; `dh_safe_prime_gen_privkey()` allocates `n + 1` `__be64` words before stripping `key[0]`, calls `h = __add_u64_to_be(key + 1, n, h)` twice for `mod 2^N - 1`, and sets `key[n] = cpu_to_be64(1)` if `__add_u64_to_be(key + 1, n, 1)` carries. [F255, F256, F270, F295, F296]
- In `ccm.c` and `gcm.c`, `pctx->dst`/`rctx->dst` is only set when `req->src != req->dst`, so stages must use `req->src == req->dst ? pctx->src : pctx->dst`. `crypto_rfc4309_{encrypt,decrypt}()` and `crypto_rfc4106_{encrypt,decrypt}()` must verify `req->assoclen` is 16 or 20 before copying `req->assoclen - 8` bytes. `crypto_ccm_init_crypt()` must validate `req->iv[0]` (`1..7`) via `crypto_ccm_check_iv()` before zeroing `iv + 15 - iv[0]` or calling `format_input()`, and `set_msg_len()` must clamp `csize` to `4` before `1 << (8 * csize)`. [F264, F267, F289, F293]
- In `chacha20poly1305.c`, `chachapoly_create()` rejects `ivsize > CHACHAPOLY_IV_SIZE`; `poly_genkey()` checks `rctx->assoclen >= 8` when `ivsize == 8`; and `poly_hash()` uses `rctx->cryptlen` and `rctx->assoclen` (`rctx->cryptlen == req->cryptlen` for encrypt vs. decrypt, skipping `req->assoclen - rctx->assoclen`). [F266, F288]
- Mode bounds: `crypto_cts_{encrypt,decrypt}()` and `hctr2_crypt()` require `req->cryptlen >= bsize` before subtracting `bsize` or calling `rounddown(nbytes - 1, bsize)`. `crypto_cbc_decrypt_inplace()` returns early if `nbytes < bsize` (requiring `is_power_of_2(cra_blocksize)` in `crypto_cbc_create()`) and breaks when `(nbytes -= bsize) < bsize`. `echainiv_aead_create()` rejects `ivsize == 0` or non-multiples of 8, and `echainiv_{encrypt,decrypt}()` reject `req->cryptlen < ivsize`. With `cra_alignmask = 0`, `cast6_generic.c`, `chacha.c`, `crc32.c`, and `crc32c.c` must use `get_unaligned_{be,le}32()` / `put_unaligned_{be,le}32()`. [F268, F269, F271, F275]

## Synchronization

- In `cryptd.c`, `cryptd_enqueue_request()` and `cryptd_queue_worker()` must disable BH and hold `cpu_queue->bh_lock` across `cpu_queue->queue` ops, unlocking and re-enabling BH before `crypto_request_complete()`. Worker completions in `cryptd_{skcipher,hash}_complete()` and `cryptd_aead_crypt()` must wrap `*_request_complete()` in `local_bh_disable()`/`local_bh_enable()`. [F192, F321]
- In `crypto_engine.c`, `engine->queue_lock` requires `spin_lock_irqsave()`/`spin_unlock_irqrestore()` around `queue`, `running`, `busy`, and `cur_req`, and must be dropped before `op->do_one_request()`, `crypto_request_complete()`, or `msleep()`. `crypto_pump_requests()` may only clear `engine->busy` when `in_kthread` is true and the queue is empty or `!engine->running`, must re-acquire `queue_lock` after `do_one_request()` before `goto start_request`/`out`, and must skip backlog `-EINPROGRESS` completion on `-ENOSPC` requeue. `crypto_engine_stop()` must re-verify `!crypto_queue_len(&engine->queue) && !engine->busy` under `queue_lock` after its `msleep(20)` loop before clearing `running = false`, and `crypto_engine_exit()` must not destroy `kworker` if `crypto_engine_stop()` fails. [F233, F281, F282, F323]
- In `crypto_user.c`, messages serialize on `crypto_cfg_mutex` in `crypto_netlink_rcv()`, and replies use `sock_net(skb->sk)->crypto_nlsk`. `crypto_alg_match()` pins matches with `crypto_mod_get(q)` under `down_read(&crypto_alg_sem)`, balanced by caller `crypto_mod_put(alg)`. `crypto_update_alg()` calls `crypto_remove_spawns()` and updates `cra_priority` under `down_write(&crypto_alg_sem)`, then unlocks and calls `crypto_mod_put(alg)` before `crypto_remove_final(&list)`. [F201, F252, F343]
- In `drbg.c`, `drbg->drbg_mutex` protects all mutable `drbg_state` fields across `drbg_generate()`, `drbg_instantiate()`, and `drbg_kcapi_set_entropy()`. `drbg_nopr_reseed_interval_elapsed()` must use `time_after(jiffies, next_reseed)`. In `deflate.c`, `deflate_init()` holds `deflate_stream_lock` around `crypto_acomp_alloc_streams()`; `deflate_{compress,decompress}()` use `crypto_acomp_{lock,unlock}_stream_bh()`; and `deflate_mod_fini()` unregisters acomp before freeing `deflate_streams`. [F203, F205, F299]
- Async callbacks (`async_done_continue`, `hmac_finup_done`, `crypto_ccm_decrypt_done`, `gcm_*_done`) must strip `CRYPTO_TFM_REQ_MAY_SLEEP` from continuation subrequest flags. `hctr2_hash_message()` requires `SG_MITER_ATOMIC`. `fips_fail_notif_chain` is an `ATOMIC_NOTIFIER_HEAD` (callbacks must not sleep). [F248, F326, F330]

## Object Lifetimes

- In `cryptd`, `ctx->refcnt` is only touched when non-zero, read before `*_request_complete()`, and unchanged on `-EINPROGRESS`. `cryptd_exit()` must call `destroy_workqueue(cryptd_wq)` before `cryptd_fini_queue(&queue)`. [F176, F195]
- `crypto_engine_alloc_init_and_set()` must init `queue`, `queue_lock`, `kworker`, and `pump_requests` with `running = false` and `busy = false` before `crypto_engine_start()`. Drivers must call `crypto_engine_exit()` before unbind completes to stop the unmanaged `kworker`. [F200, F312]
- `dh_set_secret()` must call `dh_clear_ctx(ctx)` before decoding and on `err_clear_ctx`. `drbg_uninstantiate()` must call `d_ops->crypto_fini(drbg)` before `drbg_dealloc_state()` clears `d_ops`, NULLing freed pointers while preserving `test_data`. [F178, F181]
- `essiv_create()` must call `crypto_mod_put(_hash_alg)` on both success and `out_free_hash`. Multi-transform `init_tfm` callbacks (`crypto_{ccm,gcm}_init_tfm`, `hctr2_init_tfm`, `essiv_*init_tfm`) must free earlier child transforms in reverse order on error. `crypto_gcm_module_init()` must init `gcm_zeroes` before `crypto_register_templates()`. `ghash_setkey()` must check `keylen == GHASH_BLOCK_SIZE` before `gf128mul_free_4k(ctx->gf128)`. `crypto_hkdf_module_init()` must use `late_initcall`. [F187, F188, F206, F240, F317]

## API Contracts

- `cryptd_alloc_{skcipher,ahash,aead}()` must verify `tfm->base.__crt_alg->cra_module == THIS_MODULE` before setting `ctx->refcnt` (else free `tfm` and return `ERR_PTR(-EINVAL)`). `cryptd_*_child()` return borrowed pointers freed by `cryptd_*_exit_tfm()`. [F177, F352]
- `crypto_engine_alloc_init{,_and_set}()` return `NULL` on failure (never `ERR_PTR`). Engine algorithms must use `struct *_engine_alg` via `crypto_engine_register_*()` with non-NULL `op.do_one_request`. `crypto_finalize_*_request()` requires softirq/BH-disabled context. [F207, F322, F331]
- `hkdf_extract()` re-keys `hmac_tfm` with `salt`, so callers must re-key with `prk` before `hkdf_expand()`. `hkdf_expand()` rejects `okmlen > 255 * hashlen`, bounces partial blocks through `tmp`, and zeroes `okm`, `desc`, and `tmp` on error. [F191, F262]
- `{__crypto_dh,crypto_dh,crypto_ecdh}_decode_key()` alias `buf` without allocating. `crypto_dh_encode_key()` packs via `dh_pack_data()` and checks `ptr == end`. `crypto_dh_decode_key()` rejects `key_size > p_size`, `g_size > p_size`, or all-zero `p`; `dh_safe_prime_set_secret()` requires `p_size == 0 && g_size == 0`. `dh_check_params_length(p_size << 3)` requires `>= 2048` bits in FIPS (`>= 1536` otherwise). `crypto_ecdh_decode_key()` checks `len >= ECDH_KPP_SECRET_MIN_SIZE`, `len >= secret.len`, and `secret.len == crypto_ecdh_key_len(params)`. In `{dh,ecdh}_compute_value()`, `req->src == NULL` generates a public key (`dh_compute_value()` only frees `base` when `req->src != NULL`). Each ECDH curve `kpp_alg` needs a unique `cra_driver_name`. [F211, F213, F254, F258, F334, F345, F346]
- `cbc.c`/`ecb.c` lskcipher `encrypt`/`decrypt` return residual `rem` when `!(flags & CRYPTO_LSKCIPHER_FLAG_FINAL)`, and `-EINVAL` when `FINAL` is set; `lskcipher_alloc_instance_simple()` templates passing `NULL` state must reject non-zero `inst->alg.co.statesize`. `CRYPTO_AHASH_ALG_BLOCK_ONLY` shashes (`cbcmac`, `cmac`, `ghash`) return unconsumed trailing bytes (`< bs`) from `.update`. [F225, F226, F333]
- `hmac_import*()` and `cryptd_hash_import()` must bind the child transform on the inner descriptor/request before child import. `hmac_setkey{,_ahash}()` reject `keylen < 14` (`-EINVAL`) when `fips_enabled`. `crypto_cipher_setkey()` and `cipher_crypt_one()` bounce pointers unaligned to `crypto_cipher_alignmask(tfm)` through an `(alignmask + 1)`-aligned buffer. Template `.setkey` callbacks must sync `CRYPTO_TFM_REQ_MASK` to children. Templates using `crypto_alg_mod_lookup()` (`essiv_create()`) must pass `crypto_algt_inherited_mask(algt)` and OR `CRYPTO_ALG_INHERITED_FLAGS` into `inst->alg.base.cra_flags`. [F243, F272, F335, F338, F350]

## Error Handling

- In `dh.c`, check `mpi_rshift()`/`mpi_sub_ui()` return values before `mpi_powm()`/`mpi_cmp()`, and convert `sign < 0` from `mpi_write_to_sgl()` to `-EBADMSG`. `ecdh_init()` must tolerate `crypto_register_kpp(&ecdh_nist_p192)` failing in FIPS mode (`ecdh_nist_p192_registered`). [F209, F210, F349]
- In `drbg.c`, `d_ops->crypto_init` returns `alignmask >= 0` or `< 0` error; `d_ops->generate` returns `> 0` bytes or `<= 0` error (`drbg_generate()` returns `0`). `drbg_fips_continuous_test()` runs only when `IS_ENABLED(CONFIG_CRYPTO_FIPS) && !list_empty(&drbg->test_data.list) && fips_enabled`, priming `prev` with `-EAGAIN` when `!fips_primed` and calling `panic()` on match. Jitter RNG errors are fatal only when `fips_enabled`, and `drbg_seed()` ignores `-EAGAIN` when `reseed == true`. [F215, F216, F347, F348]
- `essiv_aead_crypt()` must init `rctx->assoc = NULL` and free it synchronously when `err != -EINPROGRESS && err != -EBUSY` or in `essiv_aead_done()` when `err != -EINPROGRESS`. Callbacks preserving `CRYPTO_TFM_REQ_MAY_BACKLOG` (`hmac_finup_done`, `crypto_cts_*_done`, `async_done_continue`) must not complete the parent request on `-EINPROGRESS` or `-EBUSY`. `des{,3_ede}_setkey()` map `-ENOKEY` to `-EINVAL` if `CRYPTO_TFM_REQ_FORBID_WEAK_KEYS` (else `0`), zeroing `dctx` on error. `hmac_{update,finup}_ahash()` must branch on `ahash_request_isvirt(preq)`. [F224, F227, F228, F284]

## External Contracts

- In `crypto_user.c`, mutating handlers (`crypto_{update,del,add}_alg`, `crypto_del_rng`) require `netlink_capable(skb, CAP_NET_ADMIN)` (`-EPERM`). `crypto_del_alg()` rejects non-`CRYPTO_ALG_INSTANCE` (`-EINVAL`) and `refcount_read(&alg->cra_refcnt) > 2` (`-EBUSY`). `crypto_report_{one,cipher}()` must `memset()` UAPI structs to 0 and use `strscpy()` before `nla_put()`. [F276, F339, F342]

## Known Pitfalls

- `crypto_{ccm,gcm}_req_priv_ctx` and `hctr2_request_ctx` share union `u` between hash and skcipher subrequests (must serialize and re-init per stage). `crypto_rfc{4106,4543,4309}_crypt()` and `crypto_cts_reqctx_space()` must offset past `subreq` by the child's `reqsize`, never the parent's. [F229, F287]
- IV preservation: `crypto_cts_decrypt()` (`nbytes > bsize`) must save the final-blocks IV into `crypto_cts_reqctx_space(req)` before `crypto_skcipher_decrypt(subreq)`. `echainiv_encrypt()` must read `info + ivsize - 8` before zeroing `info`, copying to `req->dst`, and writing the multiplied salt. `crypto_ccm_decrypt()` must copy `req->iv` into `pctx->idata` for `skcipher_request_set_crypt()`, preserving `req->iv` for `crypto_ccm_auth()`. [F245, F246, F247]
- In `drbg.c`, `list_empty(&drbg->test_data.list)` is `true` in test mode and `false` in normal mode. In `deflate_decompress_one()`, when `acomp_walk_next_dst(&walk)` returns `0`, set `out_of_space = true` and `break` so `acomp_walk_done_src(&walk, scur)` runs; `deflate_streams.free_ctx` must use `deflate_free_stream`. `hmac_setkey_ahash()` must bind `HASH_REQUEST_ON_STACK` to `fb = crypto_ahash_fb(tctx->hash)`. In `crypto_cmac_digest_setkey()`, cast `_const[...]` to `s64` before `>> 63` for `msb_mask`, keeping `_const[0] >> 63` unsigned for carry. [F277, F286, F292, F297, F302]
