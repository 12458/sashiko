# X86 PLATFORM DRIVERS — (top level)

This component comprises standalone x86 platform drivers at the top level of `drivers/platform/x86/` (including Intel IPS thermal/power sharing, P2SB BAR caching, Intel Atom PMC, Silicom MEC170x appliances, Cisco Meraki MX100, SEL-3350, MeeGoPad ANX7428, Samsung Q10, OLPC XO-1/XO-1.5, and WMI hotkey/MXM drivers) along with shared x86 `platform_data` headers in `include/linux/platform_data/x86/`. It provides PCI/LPC/MMIO bridge access, CPU/GPU thermal and turbo coordination, and board-specific GPIO, LED, hwmon, input, power_supply, and clock registrations.

## Architecture & Data Flow

- In `p2sb.c`, `p2sb_get_devfn()` defaults to `P2SB_DEVFN_DEFAULT` (`PCI_DEVFN(31, 1)`) when `x86_match_cpu(p2sb_cpu_ids)` returns NULL, and uses `P2SB_DEVFN_GOLDMONT` (`PCI_DEVFN(13, 0)`) on `INTEL_ATOM_GOLDMONT` and `INTEL_ATOM_GOLDMONT_PLUS` (where `p2sb_scan_and_cache()` scans only `devfn` and `SPI_DEVFN_GOLDMONT`). In `p2sb_cache_resources()`, the `PCI_CLASS_DEVICE` check must only reject `!PCI_POSSIBLE_ERROR(class) && class != PCI_CLASS_MEMORY_OTHER` because a BIOS-hidden P2SB device returns `0xffff` before `p2sb_scan_and_cache()` unhides it. [F244, F261]
- In `p2sb.c`, `p2sb_read_bar0()` must zero the destination `struct resource` and copy only value fields (`start`, `end`, `flags`, `desc`) from BAR0—never pointer fields (`name`, `parent`, `sibling`, `child`)—because `p2sb_scan_and_cache_devfn()` immediately removes the scanned `pci_dev`. `p2sb_scan_and_cache_devfn()` must also record `bus->dev.id` in `cache->bus_dev_id` alongside `cache->res` in `p2sb_resources[PCI_FUNC(devfn)]`, and `p2sb_read_from_cache()` must verify both `cache->bus_dev_id == bus->dev.id` and `p2sb_valid_resource(&cache->res)`. [F202, F222]
- In `intel_ips.c`, `ips_probe()` must snapshot `TURBO_POWER_CURRENT_LIMIT` into `ips->orig_turbo_limit` before thermal adjustment starts, and `ips_remove()` must clear `TURBO_TDC_OVR_EN | TURBO_TDP_OVR_EN` before restoring `ips->orig_turbo_limit`. During operation, `ips_cpu_raise()` and `ips_cpu_lower()` must update both `THM_MPCPC` MMIO and `TURBO_POWER_CURRENT_LIMIT` MSR in lockstep, enabling `TURBO_TDC_OVR_EN | TURBO_TDP_OVR_EN` before writing the new `TURBO_TDP_MASK` limit. [F215, F216]
- In `intel_ips.c`, `ips->gpu_turbo_enabled` may only be set to true when all i915 symbols (`read_mch_val`, `gpu_raise`, `gpu_lower`, `gpu_busy`, `gpu_turbo_disable`) are acquired via `ips_get_i915_syms()` (checked via `ips->gpu_busy`), and must be cleared if `ips->gpu_raise()` or `ips->gpu_lower()` returns false. In `ips_monitor()`, `mchp_samples` must be zero-initialized via `kcalloc()` and `ips->read_mch_val` checked for non-NULL before calling so `calc_avg_power()` never reads uninitialized memory when i915 is unloaded. [F207, F219]
- In `intel_ips.c`, `ips_monitor()` must clamp `last_sample_period` to at least 1 when `jiffies_to_msecs(jiffies) - last_msecs` is 0 because `get_cpu_power()` divides by `period` on the next iteration. Also in `struct ips_driver`, `ctv1_avg_temp`, `ctv2_avg_temp`, `mch_avg_temp`, and `mcp_avg_temp` are in `0.01 C` units whereas `mcp_temp_limit` and `struct ips_mcp_limits` temperature limits are in whole degrees C, so `mcp_exceeded()`, `cpu_exceeded()`, and `mch_exceeded()` must multiply the degree C limit by 100. [F246, F251]
- In `pmc_atom.c`, paired `d3_sts_*` and `func_dis*` arrays in `struct pmc_reg_map` (such as `cht_d3_sts_1_map` and `cht_func_dis_2_map`, or `d3_sts_0_map`/`byt_d3_sts_1_map` and their `func_dis` counterparts) must maintain identical length and entry order because `pmc_dev_state_print()` and `pmc_dev_state_check()` index `fd_map[index]` using `sts_map[index].name` as the loop bound. [F223]
- In `sel3350-platform.c`, `GPIO_LOOKUP_IDX` entries in `sel3350_leds_table` must match the indices of `sel3350_leds`, and each registered `power_supply` (`ps_a`, `ps_b`) must set `ps_cfg.drv_data` to its own `struct sel3350_power_cfg_data` before calling `devm_power_supply_register()`. [F228]
- In `silicom-platform.c`, every `struct led_classdev_mc` array passed to `silicom_mc_leds_register()` via `struct silicom_platform_info::led_info` must be terminated by a sentinel element with `led_cdev.name == NULL`. [F237]
- In `fm07keys_poll()`, the loop counter `i` must be reset to 0 before each of the four `PORT_CMD` status-polling `while` loops and incremented against `LOOP_TIMEOUT` on every iteration so a stuck EC status bit jumps to `timeout` without hanging the poll workqueue or reporting stale key data. [F245]

## Synchronization

- In `p2sb.c`, `p2sb_cache_resources()` must hold `pci_lock_rescan_remove()` across unhiding the P2SB device in `P2SBC`, scanning and removing it in `p2sb_scan_and_cache()`, and re-hiding it with `P2SBC_HIDE`. Conversely, `p2sb_bar()` must never acquire `pci_lock_rescan_remove()` and must instead read hidden P2SB resources from `p2sb_resources` (populated at `fs_initcall_sync(p2sb_fs_init)` after `pcibios_assign_resources()`), because `p2sb_bar()` is called from driver probe paths during sysfs PCI rescans that already hold `pci_rescan_remove_lock`. [F190, F191]
- In `intel_ips.c`, `ips_probe()` must create `ips->adjust` dormant via `kthread_create()` before starting `ips->monitor` via `kthread_run()`, because `ips_monitor()` only calls `wake_up_process(ips->adjust)` after collecting the initial 5-second temperature and power averages. Any runtime update to `ips->mcp_temp_limit` or `ips->mcp_power_limit` from hardware registers (in `update_turbo_limits()` or `ips_irq_handler()`) must hold `ips->turbo_status_lock` and call `verify_limits(ips)` before releasing it. [F194, F218]
- In `xiaomi_wmi_notify()`, reporting key press, release, and `input_sync()` on `data->input_dev` must be serialized under `data->key_lock` because WMI `.notify` callbacks can run concurrently and interleave events. [F189]
- In `silicom-platform.c`, all runtime indexed I/O port sequences selecting an address at `MEC_ADDR` (`EC_ADDR_LSB` / `EC_ADDR_MSB`) and accessing `MEC_DATA_OFFSET(...)` must hold `mec_io_mutex`, and `silicom_gpio_chip.can_sleep` must remain `true`. [F268]

## Object Lifetimes

- When `p2sb_hidden_by_bios` is false, `p2sb_cache_resources()` must not call `p2sb_scan_and_cache()`, and `p2sb_bar()` must read BAR0 from the live PCI device via `p2sb_read_from_dev()` (`pci_get_slot()` / `pci_dev_put()`) rather than scanning and removing an unhidden `pci_dev`. [F258]
- In `intel_ips.c`, `ips_get_i915_syms()` acquires symbol references via `symbol_get()` for `i915_read_mch_val`, `i915_gpu_raise`, `i915_gpu_lower`, `i915_gpu_busy`, and `i915_gpu_turbo_disable`; any failure must unwind already-acquired references in reverse order with `symbol_put()`, and `ips_remove()` must release each non-NULL reference with `symbol_put()`. Also, before `ips_monitor()` exits its sampling loop, it must call `timer_delete_sync(&ips->timer)` so `monitor_timeout()` cannot fire `wake_up_process(ips->monitor)` after the kthread exits. [F183, F195]
- In `mxm_wmi_call_mxds()` and `mxm_wmi_call_mxmx()`, `wmi_evaluate_method()` must be passed `NULL` for the output `struct acpi_buffer` pointer unless the caller frees `output.pointer` with `kfree()`. Broken by: passing an `ACPI_ALLOCATE_BUFFER` output buffer without freeing `output.pointer`. [F181]
- In `tink_board_init()` and `tink_board_exit()` (`meraki-mx100.c`), `tink_swnodes` must be registered with `software_node_register_node_group()` before creating `tink_leds_pdev` and `tink_keys_pdev` with fwnode references to those nodes, and torn down in reverse order (`platform_device_unregister()` of keys and leds before `software_node_unregister_node_group()`). [F184]
- In `sel3350_probe()` and `sel3350_remove()`, `sel3350_leds_table` and `sel3350_gpios_table` must be registered via `gpiod_add_lookup_table()` before creating `sel3350->leds_pdev` or requesting GPIOs, and removed via `gpiod_remove_lookup_table()` only after `platform_device_unregister(sel3350->leds_pdev)`. [F197]
- In `pmc_setup_clks()`, the temporary `struct pmc_clk_data` buffer passed to `platform_device_register_data()` must be freed with `kfree(clk_data)` on both success and error paths because `platform_device_register_data()` copies the buffer. [F186]
- In `wireless-hotkey.c` and `xo15-ebook.c`, a non-devm `struct input_dev` allocated with `input_allocate_device()` must be freed with `input_free_device()` on failure before `input_register_device()`, and released solely via `input_unregister_device()` (without `input_free_device()`) in `wireless_input_destroy()` or `ebook_switch_remove()` before `kfree(button)`. [F187]
- In `silicom_mc_leds_register()`, each `struct led_classdev_mc` entry and its `subled_info` array (`led->num_colors * sizeof(struct mc_subled)`) must be deep-copied into `devm_kzalloc()` memory before registration because the board LED templates (`plat_0222_mc_led_info`, `cordoba_mc_led_info`, `*_mc_subled_info`) are marked `__initdata`. [F255]
- In `serdev_helpers.h`, `get_serdev_controller()` must acquire a strong reference via `get_device(acpi_get_first_physical_node(adev))` before calling `acpi_dev_put(adev)`, and `get_serdev_controller_from_parent()` must call `put_device(ctrl_dev)` on each intermediate parent as it walks `host -> :0 -> .N -> serdev_ctrl_name`. [F262]

## API Contracts

- `p2sb_bar()` requires a non-NULL `@mem` out-parameter, whereas `@bus` may be NULL (resolved to domain 0, bus 0 via `p2sb_get_bus()`) and `@devfn` may be 0 (resolved to the CPU-specific or default P2SB devfn via `p2sb_get_devfn()`). [F201]
- Both `get_serdev_controller_from_parent()` and `get_serdev_controller()` convert NULL results from `device_find_child_by_name()`, `acpi_dev_get_first_match_dev()`, and `get_device()` into `ERR_PTR(-ENODEV)`, so callers must check `IS_ERR()` rather than NULL. [F200]
- `mxm_wmi_call_mxds()` and `mxm_wmi_call_mxmx()` return 0 on success or a positive `acpi_status` code when `wmi_evaluate_method()` fails, not a negative errno. Broken by: checking return values with `ret < 0` instead of `ret != 0`. [F214]
- Every `struct wmi_device_id` entry in `xiaomi_wmi_id_table` must set `.context` to a valid `const unsigned int *` pointing to a keycode below `KEY_CNT` (as `XIAOMI_DEVICE()` does), because `xiaomi_wmi_probe()` dereferences `*(const unsigned int *)context` and passes it to `set_bit(..., data->input_dev->keybit)`. [F257]
- In `silicom-platform.c`, `temp_get()` multiplies `FIELD_GET(MEC_TEMP_LOC, reg)` by 100 to convert the MEC170x decicelsius (`0.1 C`) reading into millidegrees Celsius for `hwmon_temp_input`. [F291]

## Error Handling

- In `get_serdev_controller()`, `serial_ctrl_uid` may be NULL to match any ACPI UID, so error logging must guard it with a fallback (`serial_ctrl_uid ?: "*"`) before passing it to `%s`. [F199]
- In `anx7428_probe()`, the `read_poll_timeout()` condition polling `i2c_smbus_read_byte_data()` on `TX_STATUS` must check `val >= 0` before testing `(val & OCM_STARTUP)` because negative SMBus errno values have sign-extended upper bits set, including `BIT(7)` (`OCM_STARTUP`). [F243]
- In `pmc_atom.c`, `pmc_s2idle_check()` passes SoC blocks that permanently report D0 on lower-featured Bay Trail and Cherry Trail SKUs via `false_pos_sts_0` and `false_pos_sts_1` so `pmc_dev_state_check()` logs them with `pm_pr_dbg()` instead of `pr_err()`. [F288]

## External Contracts

- As documented on `struct pwm_lpss_boardinfo` in `include/linux/platform_data/x86/pwm-lpss.h`, on Broxton, Apollo Lake, and Gemini Lake LPSS PWM controllers, software must verify the `PWMCTRL` `sw_update` bit is 0 both before programming base unit/divisor values and before a read-modify-write of `PWMCTRL` to set PWM Enable. [F229]
- In `include/linux/platform_data/x86/asus-wmi.h`, `ASUS_WMI_DEVID_SCREENPAD_POWER` (`0x00050031`) can only disable the screenpad; re-enabling a disabled screenpad requires writing a brightness value to `ASUS_WMI_DEVID_SCREENPAD_LIGHT` (`0x00050032`). [F297]

## Known Pitfalls

- In `intel_ips.c`, `ips_enable_cpu_turbo()` and `ips_disable_cpu_turbo()` must check both `ips->__cpu_turbo_on` and `ips->turbo_toggle_allowed` (set in `ips_detect_cpu()` only when `IA32_MISC_ENABLE` has `IA32_MISC_TURBO_EN`) before calling `on_each_cpu()` to write `IA32_PERF_CTL`. Also, `calc_avg_temp()` and `calc_avg_power()` must divide 64-bit accumulators with `do_div()` rather than `/` so 32-bit x86 builds succeed. [F217, F250]
- In `intel_ips.c`, `ips_probe()` must allocate only legacy INTx vectors (`pci_alloc_irq_vectors(dev, 1, 1, PCI_IRQ_INTX)`) with `IRQF_SHARED` (not MSI), and `ips_irq_handler()` must return `IRQ_NONE` when both `THM_TSES` and `THM_TES` read as 0 and write back the read values (`thm_writeb`) to clear active status bits. [F263]
- In `pmc_atom.c`, `pmc_s2idle_check()` distinguishes Bay Trail from Cherry Trail via pointer equality `m->d3_sts_1 == byt_d3_sts_1_map`, so changing `byt_reg_map.d3_sts_1` or adding a new `pmc_reg_map` requires updating `pmc_s2idle_check()`. In `pmc_power_off()`, `SLEEP_TYPE_MASK` (`GENMASK(12, 10)`) must be bitwise-inverted (`pm1_cnt_value &= ~SLEEP_TYPE_MASK`) before ORing `SLEEP_TYPE_S5`, and in `pmc_sleep_tmr_show()`, the `u32` return of `pmc_reg_read()` must be cast to `u64` before shifting left by `PMC_TMR_SHIFT` (5). [F224, F240, F248]
- In `silicom-platform.c`, GPIO channels packed into `u8` arrays (`plat_0222_gpio_channels`) via `OFFSET_BIT_TO_CHANNEL(off, bit)` require `off <= 0x0b` and `bit <= 7` so `(((off) + 0x014) << 3) | (bit)` fits in `u8` and `CHANNEL_TO_OFFSET()` recovers `off`. Furthermore, `silicom_mec_port_set()` is active-low (clearing the port bit when `@on` is non-zero) whereas `silicom_mec_port_get()` returns the raw bit, so `silicom_gpio_set()` must pass `!value` to `silicom_mec_port_set()`. [F236, F242]

## Other

- In `meegopad_anx7428.c`, `anx7428_probe()` must sequence power-on by asserting `enable` high (`GPIOD_OUT_HIGH`), sleeping 10 ms (`fsleep(10000)`), deasserting the active-low `reset` GPIO (`GPIOD_OUT_LOW`), and polling `TX_STATUS` for `OCM_STARTUP` via `read_poll_timeout()` before reading `VENDOR_ID` or `DEVICE_ID`. [F271]
- In `pmc_atom.c`, `dmi_callback_siemens()` in `critclk_systems` must walk OEM DMI entries via `dmi_walk(simatic_ipc_find_dmi_entry_helper, &st_id)` and set `pmc_clk_is_critical = false` unless `st_id` is `SIMATIC_IPC_IPC227E` or `SIMATIC_IPC_IPC277E`. [F273]
- In `xo15-ebook.c`, `ebook_switch_add()` must enable the run-wake GPE via `acpi_enable_gpe()` and `device_set_wakeup_enable(&device->dev, true)` when `device->wakeup.flags.valid` is set, and `ebook_switch_resume()` must call `ebook_send_state()` to re-evaluate the ACPI `EBK` method and sync `SW_TABLET_MODE` on resume. [F274]
