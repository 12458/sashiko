# FILESYSTEMS (VFS and infrastructure) — fs (part 3)

Provides core VFS pathname resolution and directory entry operations (`fs/namei.c`), generic helper libraries for pseudo and in-memory filesystems (`fs/libfs.c`), internal mount data structures (`fs/mount.h`), multi-page BIO read/write submission (`fs/mpage.c`), and metadata block caching for extended attribute deduplication (`fs/mbcache.c`). It bridges userspace path-based system calls and pagecache I/O with filesystem-specific inode, dentry, and block mapping callbacks.

## Architecture & Data Flow

- In `mnt_notify_add()`, when queuing `m->to_notify` onto `notify_list` is skipped because neither `m->mnt_ns` nor `m->prev_ns` has `n_fsnotify_marks`, `m->prev_ns` must still be updated to `m->mnt_ns`. [F71]
- In `simple_offset_*` helpers, a dentry's `d_fsdata` offset (`offset_set()`/`dentry2offset()`) and its entry in the parent directory's `struct offset_ctx` maple tree (`octx->mt`) must be updated in lockstep, with `simple_offset_rename()` zeroing a positive `new_dentry`'s offset and reusing that offset in `new_ctx` for `old_dentry`. [F73]
- In `simple_rename()` and `simple_rename_exchange()`, parent directory `i_nlink` counts must be adjusted whenever a directory entry moves across parents without replacing another directory, including when `simple_rename_exchange()` swaps a directory and a non-directory between `old_dir != new_dir`. [F75]
- `mb_cache_entry_create()` must set `e_refcnt` to 2 before `c_hash` insertion and drop the extra ref after adding to `c_list`, while `mb_cache_entry_delete_or_get()` and `mb_cache_shrink()` must zero `e_refcnt`, unlink `e_list` and decrement `c_entry_count` under `c_list_lock`, then call `__mb_cache_entry_free()`. [F78]
- In `do_mpage_readpage()`, `args->map_bh` caches a multi-block extent mapping starting at `args->first_logical_block` across calls, and `clear_buffer_mapped(map_bh)` must be called once all `map_bh->b_size >> blkbits` blocks in the cached mapping have been consumed. [F80]
- In `mpage_write_folio()`, `bio_add_folio()` must succeed before `clean_buffers(folio, first_unmapped)` clears `BH_Dirty` on only the first `first_unmapped` buffers, and `clean_buffers()` must not call `try_to_free_buffers(folio)` unless `folio_test_uptodate(folio)` is true. [F81]
- `__set_nameidata()` must initialize `p->total_link_count` from `current->nameidata->total_link_count` when pushing `p` onto `current->nameidata`, and `restore_nameidata()` must copy `now->total_link_count` back to `old->total_link_count` when popping it. [F82]
- In `struct nameidata`, `terminate_walk()` must drop `nd->root` and clear `ND_ROOT_GRABBED` while preserving `ND_ROOT_PRESET` across retries, and `complete_walk()` must not clear `nd->root.mnt` before `try_to_unlazy()` when either `ND_ROOT_PRESET` or `LOOKUP_IS_SCOPED` is set. [F83]
- Because `try_to_unlazy()` and `try_to_unlazy_next()` clear `LOOKUP_RCU` via `leave_rcu()` even when legitimization fails, any ungrabbed RCU pointers in `nd->path` (`mnt` and `dentry`) must be set to `NULL` and `nd->depth` must be truncated by `legitimize_links()` to the last attempted index (`i + 1`, or `0`) before `leave_rcu()` is called. [F84]

## Synchronization

- In `__simple_recursive_removal`, the current inode's `i_rwsem` must be unlocked before descending to lock a child or ascending to lock `this->d_parent`, and when `locked` is true (`locked_recursive_removal`), the caller holds `dentry->d_parent->d_inode` with `I_MUTEX_PARENT` so it must not be relocked or unlocked when `victim == dentry`. [F31]
- In `simple_transaction_set`, `smp_mb()` must precede `ar->size = n` so that `ar->data` is populated before a concurrent `simple_transaction_read` sees a non-zero `ar->size`, while `simple_transaction_get` must check and set `file->private_data` under `simple_transaction_lock`. [F33]
- When inspecting `d_flags` on a pinned dentry without holding its parent's `i_rwsem` or `d_lock` in `traverse_mounts`, `__traverse_mounts`, `lookup_one_positive_killable`, `lookup_one_positive_unlocked`, and `lookup_noperm_positive_unlocked`, `d_flags` must be loaded with `smp_load_acquire(&dentry->d_flags)`. [F38]
- During RCU mount and parent traversal in `__follow_mount_rcu` and `follow_dotdot_rcu`, the target dentry's sequence count (`nd->next_seq` or `nd->seq`) must be sampled via `read_seqcount_begin(&dentry->d_seq)` before checking `read_seqretry(&mount_lock, nd->m_seq)` or `read_seqcount_retry(&old->d_seq, nd->seq)`. [F39]
- In `path_init`, `nd->m_seq` (`mount_lock.seqcount`) and `nd->r_seq` (`rename_lock.seqcount`) must be sampled before `smp_rmb()`, and in `handle_dots` for `LAST_DOTDOT` when `LOOKUP_IS_SCOPED` is set, `smp_rmb()` and `__read_seqcount_retry` on both `mount_lock.seqcount` and `rename_lock.seqcount` must be checked after `step_into`. [F40]
- In `lock_rename` and `lock_rename_child`, `s_vfs_rename_mutex` must be held whenever `lock_two_directories` walks `d_parent` to lock two distinct directories (`I_MUTEX_PARENT` on the ancestor first, then `I_MUTEX_PARENT2`), and must be unlocked on return if both directories are the same. [F41]
- In `vfs_rename`, with parent directories already locked via `lock_rename`, any directory `source` or `target` that requires locking must be locked before any non-directory `source` or `target` inode, and when both `source` and `target` are non-directories they must be locked via `lock_two_nondirectories(source, target)`. [F43]
- When `vfs_unlink`, `vfs_link`, or `vfs_rename` populates `*delegated_inode`, callers (`do_unlinkat`, `do_linkat`, `do_renameat2`) must release all directory `i_rwsem` locks and `s_vfs_rename_mutex` before calling `break_deleg_wait(&delegated_inode)`, and `do_unlinkat` must also defer `iput(inode)` until after `inode_unlock` on the parent directory. [F44]
- Before `scan_positives()` drops `dentry->d_lock` for `cond_resched()`, it must move `cursor->d_sib` behind the current entry `d->d_sib` and rebind the iteration pointer `p` to `&cursor->d_sib.next`, while skipping any sibling with `DCACHE_DENTRY_CURSOR` set. [F72]

## Object Lifetimes

- kern_path_parent() and __start_removing_path() must transfer ownership of parent_path to the caller's struct path via no_free_ptr() on every non-ERR_PTR return (including negative dentries in kern_path_parent()), and release parent_path (plus inode_lock and mnt_drop_write in __start_removing_path()) only when returning an ERR_PTR. [F1]
- In struct nameidata, terminate_walk() must execute drop_links() to run and clear all active saved->done delayed calls before dropping path references in ref-walk mode (nd->path, nd->stack[0..nd->depth-1].link, and nd->root only when ND_ROOT_GRABBED is set) or calling leave_rcu() in RCU mode, and must reset nd->depth to 0 and nd->path to NULL. [F4]
- __legitimize_path() must null out path->mnt only when __legitimize_mnt() returns a positive value and must always null out path->dentry on any failure, because __legitimize_mnt() returning a negative value means the mount reference was acquired and must still be released by a subsequent path_put(). [F5]
- In do_unlinkat(), the victim inode must be pinned with ihold(inode) before vfs_unlink() and released with iput(inode) only after inode_unlock(path.dentry->d_inode), and inode must be reset to NULL before any retry_deleg or retry_estale loop. [F9]
- In vfs_rename(), after take_dentry_name_snapshot(&old_name, old_dentry), dget(new_dentry), and conditional child inode locking, every exit path must jump to out so the exact locked child inodes are unlocked, dput(new_dentry) is called, and release_dentry_name_snapshot(&old_name) is executed. [F10]
- When d_alloc_parallel() returns an in-lookup dentry (d_in_lookup(dentry) is true) in __lookup_slow(), lookup_open(), or atomic_open(), the caller must invoke d_lookup_done(dentry) after calling i_op->lookup or i_op->atomic_open and before calling dput(dentry) on error or when replacing dentry with a non-NULL return value. [F13]
- simple_pin_fs() must always call mntget(*mount) and increment *count under pin_fs_lock and then call mntput(mnt) on any local vfs_kern_mount() result after unlocking, while simple_release_fs() must clear *mount = NULL under pin_fs_lock when --*count reaches 0 before calling mntput(mnt). [F17]
- In path_from_stashed() and prepare_anon_dentry(), sops->put_data(data) must be called when reusing an existing dentry or when new_inode_pseudo() fails, whereas once sops->init_inode(inode, data) is invoked, @data is owned by the inode and must be cleaned up via iput(inode) or dput(dentry). [F18]

## API Contracts

- Every successful call to filename_create(), start_creating_path(), start_creating_user_path(), start_removing_path(), or start_removing_user_path_at() returns with path pinned, mnt_want_write(path->mnt) held, and path->dentry->d_inode locked, and must be paired with end_creating_path() (or end_removing_path()) to release them in reverse order. [F2]
- Unlike vfs_create(), vfs_mknod(), and vfs_symlink(), vfs_mkdir() consumes the caller's reference to @dentry on all paths: it calls dput(dentry) and returns an ERR_PTR on failure, and calls dput(dentry) if dir->i_op->mkdir returns an alternate non-NULL dentry, returning the surviving dentry reference. [F3]
- nd_jump_link() always takes ownership of the caller-provided struct path reference: on success it calls path_put(&nd->path) and installs *path into nd->path, and on any error it calls path_put(path) before returning. [F6]
- scan_positives() and find_next_child() in fs/libfs.c always consume the caller's reference to the previous dentry argument (@last or @prev) via dput() and return a new reference to the next positive child dentry (or NULL when none remains). [F15]
- mb_cache_entry_find_next() always drops the caller's reference to @entry via mb_cache_entry_put(), whereas mb_cache_entry_delete_or_get() returns NULL if the entry was absent or deleted and returns a referenced entry (which the caller must put) when active users prevent deletion (e_refcnt > 2). [F20]
- `getname_flags()` must initialize `result->uptr` with the original `__user` `filename` pointer via `initname(result, filename)` before calling `audit_getname(result)`, whereas `getname_kernel()` must pass `NULL` (`initname(result, NULL)`). [F46]
- `lock_rename()` and `lock_rename_child()` return `ERR_PTR(-EXDEV)` with `s_vfs_rename_mutex` and directory `i_rwsem` locks already released when the directories have no common ancestor, `NULL` with locks held when neither is an ancestor of the other, or a non-error child `struct dentry *` trap with locks held when one is an ancestor. [F47]
- `dentry->d_op->d_revalidate()` and `d_weak_revalidate()` return `> 0` when the dentry is valid, `0` when the dentry is stale/invalid, and `< 0` (`-errno`, or `-ECHILD` under `LOOKUP_RCU`) on error, so callers must treat `<= 0` as failure and invalidate or translate `0` to `-ESTALE` rather than treating `0` as success. [F50]

## Error Handling

- When `mtree_alloc_cyclic()` returns `-EBUSY` in `simple_offset_add()` because the `[DIR_OFFSET_MIN, DIR_OFFSET_MAX]` directory offset range is exhausted, `simple_offset_add()` must translate that `-EBUSY` into `-ENOSPC` while returning `-EBUSY` only when `dentry2offset(dentry) != 0`. [F45]
- In `lookup_open()` and `vfs_mkdir()`, when `dir->i_op->lookup()` or `dir->i_op->mkdir()` returns a non-NULL pointer `res`/`de`, the caller must check `IS_ERR()` before replacing `dentry` and jumping to cleanup, so `dput(dentry)` drops the original dentry rather than dereferencing an `ERR_PTR`. [F48]
- In `__start_removing_path()` and `filename_create()`, the status of `mnt_want_write()` must be preserved in `error` across `lookup_one_qstr_excl()` without being overwritten, so lookup errors take precedence while `if (!error) mnt_drop_write()` only drops write access when `mnt_want_write()` succeeded. [F52]
- Because `mb_entry_cache` is created without a constructor or `__GFP_ZERO`, `mb_cache_entry_create()` must explicitly initialize `e_list`, `e_refcnt` (to 2), `e_key`, `e_value`, and `e_flags = 0` before inserting the entry, and must free `entry` and return `-EBUSY` if a matching `(key, value)` entry already exists. [F58]
- In `direct_write_fallback()`, if `buffered_written < 0` or `filemap_write_and_wait_range()` returns a negative error (in which case `iocb->ki_pos` is rewound by `buffered_written`), the function must return `direct_written` whenever `direct_written != 0` and only return the negative error when `direct_written == 0`. [F59]
- In `__generic_file_fsync()`, the return value of `sync_mapping_buffers()` in `ret` must only be overwritten by `sync_inode_metadata()` or `file_check_and_advance_wb_err()` when `ret == 0`, and `file_check_and_advance_wb_err()` must still be called on the `out:` path even when earlier steps failed or were skipped. [F60]
- In `simple_offset_rename_exchange()`, the `out_restore:` rollback path must ignore the return values of the restoring `simple_offset_replace()` calls and return the original negative `ret` that triggered the rollback. [F61]
- Because `atomic_open()` initializes `file->__f_path.dentry` to `DENTRY_NOT_SET` (`(void *)-1UL`), any `->atomic_open()` callback returning `0` without setting `FMODE_OPENED` must update `file->f_path.dentry` to `NULL` or a replacement dentry (via `finish_no_open()`) or `atomic_open()` fails with `-EIO`. [F67]

## External Contracts

- When `LOOKUP_LINKAT_EMPTY` is set (`linkat` with `AT_EMPTY_PATH` on a non-`AT_FDCWD` descriptor), `path_init()` must verify that `fd_file(f)->f_cred == current_cred()` or `ns_capable(fd_file(f)->f_cred->user_ns, CAP_DAC_READ_SEARCH)`, returning `-ENOENT` if neither holds. [F181]
- When `nd->flags & LOOKUP_IS_SCOPED` is set, `complete_walk()` must keep `nd->root.mnt` across `try_to_unlazy()` and verify `path_is_under(&nd->path, &nd->root)`, while `handle_dots()` must return `-EAGAIN` if `mount_lock` or `rename_lock` sequence counts changed during `..` traversal. [F185]

## Known Pitfalls

- `generic_ci_d_compare()` and `generic_ci_match()` have opposite non-negative return conventions: `generic_ci_d_compare()` returns `0` on match and `1` on mismatch, whereas `generic_ci_match()` returns `> 0` (`1`) on match and `0` on mismatch (or invalid UTF-8 under strict encoding). [F62]
- `simple_read_from_buffer(to, count, ppos, from, available)` and `simple_write_to_buffer(to, available, ppos, from, count)` take `count` and `available` in opposite parameter positions (2nd and 5th vs 5th and 2nd), and both return `-EFAULT` only when the residual uncopied byte count from `copy_to_user()`/`copy_from_user()` equals `count`. [F69]
- When `offset_dir_lookup()` resumes directory iteration at `offset != DIR_OFFSET_FIRST`, it must search `octx->mt` downward toward `DIR_OFFSET_MIN` with `mas_find_rev(&mas, DIR_OFFSET_MIN)` because `offset_iterate_dir()` walks `d_sib` in descending offset order. [F90]
- Despite kerneldoc comments saying `@fh_len` is in bytes, `generic_fh_to_dentry()` and `generic_fh_to_parent()` (like `generic_encode_ino32_fh()`) measure `fh_len` in 4-byte (`__u32`) words, requiring `fh_len >= 2` for dentry lookup and `fh_len > 2` for parent lookup (`fh_len > 3` for `fid->i32.parent_gen`). [F94]
- Under `CONFIG_DCACHE_WORD_ACCESS`, `hash_name()` stores the zero-masked first word of a single-word component into `*lastword` in native word byte order, so `LAST_WORD_IS_DOT` and `LAST_WORD_IS_DOTDOT` must be shifted to the most significant bytes (`0x2eul << (BITS_PER_LONG-8)` and `0x2e2eul << (BITS_PER_LONG-16)`) on `__BIG_ENDIAN`. [F100]
- In `__entry_find`, the caller's `entry` argument must be saved in `old_entry` before the `while (node)` loop overwrites `entry`, and `entry` must be reset to `NULL` if the loop finishes without jumping to `out`. [F111]
- In `__entry_find` and `mb_cache_entry_get`, `atomic_inc_not_zero(&entry->e_refcnt)` must be the final conjunct in the `&&` condition after key, value, and `MBE_REUSABLE_B` checks. [F112]
- In `mb_cache_shrink`, `test_bit(MBE_REFERENCED_B, &entry->e_flags)` must be evaluated before `atomic_cmpxchg(&entry->e_refcnt, 1, 0) != 1` in the `||` condition, and the skipped entry must be moved to the tail of `cache->c_list` via `list_move_tail` before `continue`. [F113]
