# FIREWIRE SUBSYSTEM — drivers/firewire

The FireWire (IEEE 1394) subsystem provides the core bus infrastructure, transaction management, topology tracking, isochronous streaming, character device UAPI (`/dev/fw*`), and hardware controller/protocol drivers. It includes `firewire-core` (card, node topology, device/unit discovery, CSR/Config ROM parsing, asynchronous transactions, isochronous DMA buffers/contexts, and character device interface), `firewire-ohci` (PCI 1394 Open Host Controller Interface driver), `firewire-net` (IPv4/IPv6 over IEEE 1394 per RFC 2734/3146), `nosy` (TI PCILynx packet sniffer driver), and early boot physical DMA initialization (`init_ohci1394_dma`).

## Architecture & Data Flow

- Both `struct fw_device` and `struct fw_unit` sit on `fw_bus_type` with distinct `dev->type` pointers (`&fw_device_type` vs `&fw_unit_type`), so callbacks taking `struct device *` (`fw_unit_match()`, `show_immediate()`, `show_text_leaf()`, `update_unit()`, `compare_configuration_rom()`) must check `is_fw_unit()` or `is_fw_device()` first. [F45]
- `client->resource_xa` in `drivers/firewire/core-cdev.c` stores heterogeneous `struct client_resource` objects discriminated by `resource->release`, so callers (`release_client_resource()`, `queue_bus_reset_event()`, `has_outbound_transactions()`) must verify `resource->release` before downcasting with `to_*_resource()`. [F46]
- `struct fw_transaction` stores its completion handler in `union fw_transaction_callback callback` (`without_tstamp` vs `with_tstamp`), and every completion path (`close_transaction()`, `split_transaction_timeout_callback()`, `fw_core_handle_response()`, and `__fw_send_request()`) must branch on `t->with_tstamp` to invoke the matching union member. [F47]
- In `drivers/firewire/core-cdev.c`, `outbound_transaction_event.rsp` and `outbound_phy_packet_event.phy_packet` are unions of legacy and timestamped UAPI event structs, so `complete_transaction()` and `outbound_phy_packet_callback()` must switch on the `.without_tstamp.type` discriminator to access the active union member. [F48]
- When adding or removing a `struct fw_descriptor` on `descriptor_list` under `card_mutex`, `config_rom_length` must be adjusted by `required_space(desc)`, `descriptor_count` by `1 + (desc->immediate > 0 ? 1 : 0)`, and `update_config_roms()` called so root directory offsets in `generate_config_rom()` stay consistent. [F59]
- Every removal of a `struct fw_transaction` from `card->transactions.list` (in `close_transaction()`, `split_transaction_timeout_callback()`, and `fw_core_handle_response()`) must clear `1ULL << t->tlabel` in `card->transactions.tlabel_mask` while holding `card->transactions.lock`. [F65]
- Whenever `card->split_timeout.hi` or `card->split_timeout.lo` is modified in `handle_registers()`, `update_split_timeout(card)` must be called under `card->split_timeout.lock` to clamp and recompute both `card->split_timeout.cycles` and `card->split_timeout.jiffies`. [F66]
- In `ohci_ar_context_work()`, when `end_buffer_index < ar_first_buffer_index(ctx)` indicates circular AR buffer wrap-around, `p` must be decremented by `AR_BUFFERS * PAGE_SIZE` after `handle_ar_packets(ctx, p, buffer_end)` reaches `buffer_end` so `ctx->pointer` wraps back into the base `ctx->buffer` range. [F70]

## Synchronization

- `contend_for_bm()` is called with `card->lock` held (`__must_hold(&card->lock)`) and temporarily drops `card->lock` around `fw_run_transaction()`, so it must re-acquire `spin_lock_irq(&card->lock)` before returning on every path. [F10]
- Writers updating `node_id` and `generation` on `struct fw_card` or `struct fw_device` must store `node_id` before `smp_wmb()` and `generation`, and lockless readers must load `generation` before `smp_rmb()` and `node_id` so that a current `generation` is never paired with a stale `node_id`. [F22]
- In `handle_selfid_complete_event()`, `ohci->self_id[0]` must be read before an `rmb()`, followed by copying `ohci->self_id[]` to `ohci->self_id_buffer[]`, a second `rmb()`, and a recheck that `OHCI1394_SelfIDCount` still reports the same generation before using the Self-IDs. [F25]
- When appending or linking DMA descriptors in `ar_context_link_page()` and `context_append()`, all descriptor fields must be written before a `wmb()` that precedes setting the previous descriptor's `branch_address`. [F27]
- In `ar_search_last_active_buffer()`, `READ_ONCE()` reads of `ctx->descriptors[i].res_count` across consecutive descriptors must be separated by `rmb()`, and a final `rmb()` must be executed after the loop before reading the received DMA buffer data. [F28]
- `fw_iso_context_flush_completions()`, `fw_iso_context_stop()`, `at_context_flush()`, and `ohci_cancel_packet()` must check `current_work() == &ctx->work` and return early before calling `disable_work_sync(&ctx->work)` or `cancel_work_sync(&ctx->work)`. [F29]
- Replacing `device->config_rom` and `device->config_rom_length` in `read_config_rom()` must be done under `down_write(&fw_device_rwsem)` before freeing `old_rom`, and readers outside `fw_unit` lifetime (such as sysfs attributes, `ioctl_get_info()`, and `compare_configuration_rom()`) must hold `fw_device_rwsem` for read. [F34]
- In `drivers/firewire/nosy.c`, `packet_buffer_get()` must copy the packet to userspace and advance `buffer->head` before calling `atomic_sub(..., &buffer->size)`, and `packet_buffer_put()` must copy the packet and advance `buffer->tail` before calling `atomic_add(..., &buffer->size)`. [F38]

## Object Lifetimes

- In `create_units()`, the parent reference `fw_device_get(device)` must be acquired before `device_register(&unit->device)`, and registration failure must call `put_device(&unit->device)` rather than `kfree(unit)` so `fw_unit_release()` drops the parent reference and frees `unit`. [F4]
- A `struct fw_device` allocated in `fw_node_event()` does not call `device_initialize(&device->device)` until `fw_device_init()` finishes reading the Config ROM, so `fw_device_get()`/`put_device()` cannot be used before that point and early failure paths in `fw_device_init()` must call `fw_device_release(&device->device)` directly. [F5]
- When `fw_device_init()` revives a rediscovered `reused` device, it must swap `device->node` and `reused->node` via `fw_node_set_device()` under `card->lock` before calling `fw_device_release(&device->device)`, so `fw_device_release()` clears `obsolete_node->device` and drops `obsolete_node` rather than `current_node`. [F6]
- In `fw_core_remove_card()`, the card must be unlinked from `card_list` under `card_mutex` before binding `dummy_driver` (which preserves `free_iso_context` and `stop_iso`), and `isoc_wq`/`async_wq` must only be destroyed after `fw_destroy_nodes()`, `fw_card_put()`, and `wait_for_completion(&card->done)` finish. [F7]
- In `fw_card_add()`, `isoc_wq` and `async_wq` are managed by `__free(workqueue_destroy)`; if `card->driver->enable()` fails, `card->isoc_wq` and `card->async_wq` must be reset to `NULL` before returning, and on success `retain_and_null_ptr()` must be called on both local pointers. [F8]
- `fw_schedule_bus_reset()`, `fw_schedule_bm_work()`, and `schedule_iso_resource()` take a reference (`fw_card_get()` or `client_get()`) before queueing delayed work and drop it immediately if queueing returns `false`; `br_work()` reuses its reference when postponing and drops it only if re-queueing returns `false` or work finishes. [F9]
- In `fw_device_op_release()`, `client->iso_context` must be destroyed before `client->buffer`, and `client->in_shutdown = true` must be set under `client->lock` before waiting on `client->tx_flush_wait` and iterating `client->resource_xa` and `client->event_list`. [F12]
- In `fw_iso_resource_manage()`, when `allocate` is true and channel allocation succeeds (`c >= 0`) but `manage_bandwidth()` fails (`ret < 0`), the allocated channel must be rolled back via `deallocate_channel(card, irm_id, generation, c)` and `*channel` set to `ret`. [F14]

## API Contracts

- When `release_client_resource()` is called with a non-NULL `return_resource` out-parameter, it erases the handle from `client->resource_xa` and drops the XArray's `client` reference, but skips `resource->release()` and transfers ownership of the `client_resource` and its held references to the caller. [F3]
- `fw_iso_resource_manage()` returns `void` and reports outcomes via its out-parameters: `*channel` is set to the allocated/deallocated channel (`0..63`) or a negative errno (`-EINVAL`, `-EBUSY`, `-EAGAIN`, `-EIO`), and `*bandwidth` is overwritten with `0` if no bandwidth was allocated or deallocated. [F43]
- `show_immediate()` and `show_text_leaf()` in `drivers/firewire/core-device.c` are invoked by `init_fw_attribute_group()` with `buf == NULL` to probe whether a Config ROM attribute exists, so both functions must guard against `buf == NULL` before calling `sysfs_emit()` or writing into `buf`. [F44]
- `ohci_enable()` in `drivers/firewire/ohci.c` is called with a non-`NULL` `config_rom` from `fw_card_add()` and with `config_rom == NULL` from `pci_resume()`, so `ohci_enable()` must check `if (config_rom)` and reuse `ohci->config_rom` and `ohci->config_rom_bus` when `config_rom` is `NULL`. [F49]
- When initiating a lock transaction via `__fw_send_request()`, `fw_send_request()`, `fw_send_request_with_tstamp()`, or `fw_run_transaction()`, the caller must pass a firewire-core extended lock tcode (`TCODE_LOCK_MASK_SWAP`..`TCODE_LOCK_VENDOR_DEPENDENT`, i.e. `0x10 | EXTCODE_*`) rather than `TCODE_LOCK_REQUEST` (`0x9`). [F53]
- When calling `__fw_send_request()` or `fw_send_request()` with `tcode == TCODE_STREAM_DATA`, the caller must encode `tag`, `channel`, and `sy` into `destination_id` using `fw_stream_packet_destination_id(tag, channel, sy)` because `fw_fill_request()` stores `destination_id` directly into `packet->header[0]`. [F54]
- When calling `__fw_send_request()` with `tcode == TCODE_WRITE_QUADLET_REQUEST`, `payload` must point to at least 4 bytes of valid memory because `fw_fill_request()` unconditionally dereferences `*(u32 *)payload` to populate the quadlet data header field. [F55]

## Error Handling

- In `drivers/firewire/ohci.c`, `read_phy_reg()`, `write_phy_reg()`, `update_phy_reg()`, and `read_paged_phy_reg()` return a negative errno (`-ENODEV` or `-EBUSY`) on failure, so callers such as `detect_initiated_reset()` and `get_status_for_port()` must store the result in a signed `int` and check `< 0` before bitmasking or converting to `bool`. [F39]
- `fw_iso_context_create()` and `fw_card_driver.allocate_iso_context()` return an `ERR_PTR` on failure and never `NULL`, so callers (`ioctl_create_iso_context()`, `fwnet_broadcast_start()`, `fw_iso_mc_context_create()`) must test `IS_ERR()` and must not store a failed pointer into `client->iso_context` or `dev->broadcast_rcv_context`. [F40]
- `fw_run_transaction()`, `read_rom()`, `reread_config_rom()`, and `read_config_rom()` return `RCODE_COMPLETE` (`0`) on success and positive `RCODE_*` constants (or negative errnos in `read_config_rom()`) on failure, so callers (`fw_device_init()`, `fw_device_refresh()`) must check `!= RCODE_COMPLETE` rather than `< 0`. [F42]
- `fw_iso_buffer_destroy(buffer, card)` unmaps `buffer->page_count_mapped` pages via `card->device` and frees `buffer->page_count` pages, so `fw_iso_buffer_alloc()` and `fw_iso_buffer_map_dma()` must set `page_count` and `page_count_mapped` to the exact number of completed loop iterations before calling `fw_iso_buffer_destroy()`. [F50]
- `fw_card_read_cycle_time()` returns `-ENODEV` without modifying `*cycle_time` when `card->driver->read_csr == dummy_read_csr`, so callers that ignore its return value or copy the output to userspace (`fw_cancel_transaction()`, `__fw_send_request()`, `ioctl_get_cycle_timer2()`) must zero-initialize the `u32` target variable before calling it. [F51]

## External Contracts

- When introducing a new `/dev/fw*` UAPI feature or event gated by a `FW_CDEV_VERSION_*` constant in `drivers/firewire/core-cdev.c`, `FW_CDEV_KERNEL_VERSION` must be incremented in lockstep so `ioctl_get_info()` advertises the new ABI version to userspace. [F67]
- In `copy_iso_headers()`, the OHCI IR DMA buffer places the little-endian timestamp in `dma_hdr[0]` and the little-endian isochronous header in `dma_hdr[1]`, so `copy_iso_headers()` must swap their order and byte-swap both via `swab32()` while copying any payload quadlets at `dma_hdr[2..]` unchanged. [F91]
- When completing a `FW_CDEV_EVENT_RESPONSE` event where `rsp->length <= sizeof(*rsp) - offsetof(typeof(*rsp), data)` (4 bytes on 64-bit systems), `complete_transaction()` must queue `rsp->data` as a second iovec after `sizeof(*rsp)` so both 32-bit (`offsetof`) and pre-2.6.27 64-bit (`sizeof`) userspace readers find the payload. [F93]
- `fw_iso_resource_manage()` and `deallocate_channel()` in `drivers/firewire/core-iso.c` must split 64-bit `channels_mask` into 32-bit halves (`channels < 32` for `CSR_CHANNELS_AVAILABLE_HI` and `channels - 32` for `CSR_CHANNELS_AVAILABLE_LO`), and `manage_channel()` must map `channel` `0..31` to `cpu_to_be32(1 << (31 - channel))`. [F119]
- `dispatch_ioctl()` must validate `_IOC_SIZE(cmd) <= sizeof(union ioctl_arg)` and zero-initialize `union ioctl_arg buffer` with `memset(&buffer, 0, sizeof(buffer))` before `copy_from_user()` so that structure padding and any trailing fields omitted by older-ABI callers are zeroed before handler execution and `copy_to_user()`. [F186]
- In `core-cdev.c`, all `__u64` user pointers in UAPI structs must be converted with `u64_to_uptr()` and `uptr_to_u64()`, and `ioctl_get_info()` must copy exactly 36 bytes (not `sizeof(struct fw_cdev_event_bus_reset)`) to `a->bus_reset` so 32-bit compat callers using `compat_ptr_ioctl` do not suffer a 4-byte buffer overflow. [F187]
- In `core-cdev.c`, `ioctl_add_descriptor()`, `ioctl_send_phy_packet()`, and `ioctl_receive_phy_packets()` must reject non-local device files (`!client->device->is_local`) with `-ENOSYS`, and `ioctl_send_broadcast_request()` must reject offsets below `CSR_REGISTER_BASE + CSR_CONFIG_ROM_END` with `-EACCES`. [F189]

## Known Pitfalls

- During `update_tree()`, because each temporary `node1` from `build_tree()` is freed by `fw_node_put(node1)`, `card->root_node` and `card->irm_node` must be repointed from `node1` to the persistent `node0` whenever they match, and `move_tree()` must update the moved child's parent port pointer from `node1` to `node0`. [F61]
- In `iso_resource_work()`, when `ISO_RES_ALLOC` succeeds with `channel >= 0`, `r->todo` must transition to `ISO_RES_REALLOC` and `r->channels` must be narrowed to `1ULL << channel`, and when `r->e_alloc` or `r->e_dealloc` is passed to `queue_event()`, that pointer on `r` must be cleared to `NULL` before `if (free)` cleanup. [F68]
- When `update_phy_reg()` modifies PHY register 5 (`addr == 5`), it must OR `PHY_INT_STATUS_BITS` into `clear_bits` before writing `(ret & ~clear_bits) | set_bits` so that write-1-to-clear interrupt status bits read back as 1 are not inadvertently cleared. [F69]
- Because `fw_csr_iterator_next()` post-increments `ci->p` before returning, callers resolving a relative quadlet offset `value` from the current directory entry (such as `search_directory()`, `search_leaf()`, `units_show()`, and `create_units()`) must compute `ci.p - 1 + value` rather than `ci.p + value`. [F85]
- Because `union fwnet_hwaddr` is `__packed` with an 8-byte `uniq_id` at offset 0 and a 6-byte `fifo` address at offset 10 (`include/net/firewire.h`), `fwnet_tx()` and `fwnet_probe()` must use `get_unaligned(&ha->uc.uniq_id)` and `get_unaligned_be48()` / `put_unaligned_be48()` for `ha->uc.fifo`. [F97]
- In `build_tree()`, when a port has status `PHY_PACKET_SELF_ID_PORT_STATUS_PARENT`, `node->color` must be assigned the port loop variable `port_index` (not the outer stack-walk variable `i`) so the parent node later links itself into `child->ports[child->color]` at the matching port slot. [F101]
- In `complete_transaction()`, each `switch` case that declares a local response pointer (`FW_CDEV_EVENT_RESPONSE` and `FW_CDEV_EVENT_RESPONSE2`) must close its compound block `{ ... }` before the next `case` or `default` label. [F105]
