# MELLANOX MLX5 core VPI driver — drivers/net/ethernet/mellanox/mlx5/core/lib

Provides shared hardware abstraction libraries across the mlx5 core, Ethernet (`mlx5e`), E-Switch, and RDMA (`mlx5_ib`) drivers: PTP clock/PPS (`clock.c`), cross-function communication (`devcom.c`), Socket-Direct grouping (`sd.c`), multi-table flow steering and TTC (`fs_chains.c`, `fs_ttc.c`, `smfs.c`), MACsec/RoCE IPsec steering (`macsec_fs.c`, `ipsec_fs_roce.c`), bulk DEK pools (`crypto.c`), ASO WQEs (`aso.c`), ICM (`dm.c`), L2 MPFS (`mpfs.c`), tunnel ports (`vxlan.c`, `geneve.c`), PCI VSC (`pci_vsc.c`), and NVRAM parameters (`nv_param.c`).

## Architecture & Data Flow
- Any change to `struct mlx5_crypto_dek_bulk` counts (`num_deks`, `avail_deks`, `in_use_deks`) must update `struct mlx5_crypto_dek_pool` counters by the same delta under `pool->lock`. A freed DEK bit in `bulk->need_sync` stays set when `mlx5_crypto_dek_free_locked` clears `bulk->in_use` and is cleared only after `mlx5_crypto_cmd_sync_crypto` succeeds in `mlx5_crypto_dek_sync_work_fn`. [F1478, F1479]
- In `struct mlx5_crypto_dek_bulk`, bits `>= bulk->num_deks` in `need_sync` and `in_use` must remain zero for `hweight_long((*need_sync) ^ (*in_use))` in `mlx5_crypto_dek_bulk_reset_synced`, and list transitions/revalidations must set `bulk->avail_start` `<=` the lowest zero bit in `need_sync`. `mlx5_crypto_dek_pool_reset_synced` must iterate `partial_list`, `full_list`, and `sync_list` with `list_for_each_entry_safe` before calling `mlx5_crypto_dek_pool_free_wait_keys(pool)`. [F1481, F1521, F1542]
- In `mlx5_crypto_dek_fill_key`, a 128-bit key (`sz_bytes == 16`) must be copied to `MLX5_ADDR_OF(encryption_key_obj, key_obj, key[1])` because `key[0]` is reserved. [F1503]
- Hardware real-time timestamps pack 32-bit seconds above 32-bit nsec: `mlx5_ptp_settime_real_time` and `mlx5_perout_configure` must reject seconds `> U32_MAX`, and `mlx5_ptp_freq_adj_real_time` must fall back to PPB when `scaled_ppm` is outside `[S32_MIN, S32_MAX]`. Combining 32-bit words in `mlx5_read_time`, `perout_conf_real_time`, and `REAL_TIME_TO_NS` requires casting to `u64` before `<< 32` or `* NSEC_PER_SEC`. [F1510, F1531]
- 64-bit divisions in `clock.c` (`find_target_cycles`, `mlx5_init_overflow_period`) and `dm.c` (`mlx5_dm_sw_icm_alloc`, `mlx5_dm_sw_icm_dealloc`) must use `div64_u64`/`div_u64`/`do_div`/`DIV_ROUND_UP_ULL` instead of `/`. In `mlx5_dm_sw_icm_alloc`, `block_idx` must be `u64` so `block_idx << MLX5_LOG_SW_ICM_BLOCK_SIZE(dev)` does not truncate above 4 GiB. [F1533, F1538]
- In `mlx5_aso_poll_cq`, `aso->cc` is updated only after `mlx5_cqwq_pop(&cq->wq)`, `mlx5_cqwq_update_db_record(&cq->wq)`, and `wmb()`, by a `with_data` step (`MLX5_ASO_WQEBBS_DATA` vs `MLX5_ASO_WQEBBS`) matching `aso->pc` in `mlx5_aso_post_wqe`. [F1484]
- `MLX5_MACEC_RX_FS_ID_MAX` (`0xffff`) is both the inclusive max RX `fs_id` and `MLX5_MACSEC_RX_FS_ID_MASK` in `MLX5_MACSEC_RX_METADAT_HANDLE`, so it must be `2^N - 1`. In `macsec_fs_rx_setup_fte`, big-endian `attrs->sci` needs `be32_to_cpu()` on its 32-bit words for `MLX5_SET` when `sci_present` is true, or raw copy of `ETH_ALEN` bytes into `outer_headers.smac_47_16` when false. [F1512, F1513]
- In `fs_ttc.c`, `ttc_rules[]` is sized only up to `MLX5_TT_ANY`, so `0 <= tt < MLX5_NUM_TT` loops in `mlx5_generate_ttc_table_rules` and `mlx5_generate_inner_ttc_table_rules` must skip `mlx5_ttc_is_decrypted_esp_tt(tt)`. [F1514]
- `mlx5_set_port_tun_entropy_calc` and `mlx5_set_port_gre_tun_entropy_calc` must query `MLX5_REG_PCMR` via `mlx5_query_ports_check` before modifying bits. In `mlx5_set_entropy`, disabling global `entropy_calc` is rejected when `tun_entropy->num_enabling_entries > 0`, and `entropy_flags.gre_calc_supported && reformat_type == MLX5_REFORMAT_TYPE_L2_TO_NVGRE` must precede `entropy_flags.calc_supported`. [F1489, F1525]
- In `struct mlx5_sd`, `sd->primary` and the union (`secondaries`/`tx_ft` vs `primary_dev`/`alias_obj_id`) are valid only when `mlx5_devcom_comp_is_ready(sd->devcom)` is true, and `mlx5_sd_primary_get_peer` must only be called on the primary `mlx5_core_dev`. [F1467]
- `mlx5_core_reserve_gids` and `mlx5_core_unreserve_gids` (`gid.c`) must adjust `dev->roce.reserved_gids.start` and `count` in opposite directions by the same delta. In `set_l2table_entry_cmd` (`mpfs.c`), copy the MAC to `&in_mac_addr[2]` (skipping the 2-byte reserved prefix). In `st.c`, TPH index 0 is reserved, so `mlx5_st_create` requires `num_entries >= 2` and restricts `st->index_limit` to `[1, num_entries - 1]`. New `enum mlx5_timeouts_types` entries (`tout.h`) require a matching slot in `tout_def_sw_val` (`tout.c`). [F1497, F1500, F1507, F1508]

## Synchronization
- Updates to `clock->timer.tc`, `clock->timer.cycles.mult`, and `clock->pps_info.start` require `write_seqlock_irqsave(&clock->lock, flags)` (paired with `read_seqbegin`/`read_seqretry` in `mlx5_timecounter_cyc2time`). `mlx5_update_clock_info_page` must run under `write_seqlock_irqsave(&clock->lock, flags)` and bracket `mdev->clock_info` writes with `smp_store_mb` (`MLX5_IB_CLOCK_INFO_KERNEL_UPDATING`) and `smp_store_release` on `clock_info->sign`. [F1444, F1445]
- When `clock->shared` is true, `mlx5_clock_mdev_get(clock)` and accesses to `clock_priv(clock)->mdev` and `event_mdev` require `mlx5_clock_lock(clock)`, which nests inside `mlx5_devcom_comp_lock(mdev->clock_state->compdev)` and outside `clock->lock`. [F1446]
- `mlx5_devcom_for_each_peer_begin` returns `true` with `comp->sem` read-locked and unlocks it before returning `false` (`!READ_ONCE(comp->ready)`), so `mlx5_devcom_for_each_peer_end` must be called on every exit after `true` and never after `false`. `mlx5_devcom_comp_set_ready`, `mlx5_devcom_get_next_peer_data`, and `mlx5_devcom_for_each_peer_entry` require `devcom->comp->sem`, while `mlx5_devcom_get_next_peer_data_rcu` and `mlx5_devcom_for_each_peer_entry_rcu` require `rcu_read_lock()`. When `attr->flags & MLX5_DEVCOM_MATCH_FLAGS_NS` is set, `devcom_component_equal` matches `attr->net` via `net_eq`. [F1425, F1448, F1449, F1596]
- Access to `pool->destroy_list` between `mlx5_crypto_dek_pool_reset_synced` (holding `pool->lock`) and `mlx5_crypto_dek_destroy_work_fn` must be serialized by `pool->destroy_lock` via `mlx5_crypto_dek_pool_splice_destroy_list`. [F1453]
- `mlx5_vsc_gw_lock` takes `pci_cfg_access_lock(dev->pdev)` before polling `VSC_SEMAPHORE_OFFSET` (unlocking on all error paths), and `mlx5_vsc_gw_unlock` writes `MLX5_VSC_UNLOCK` to `VSC_SEMAPHORE_OFFSET` before `pci_cfg_access_unlock(dev->pdev)`. [F1461]
- In `mlx5_st_alloc_index` and `mlx5_st_dealloc_index`, `st->idx_xa` lookups, `usecount` updates, and `pcie_tph_set_st_entry` must run under `st->lock`, with `xa_erase` and `kfree(idx_data)` before unlocking if `pcie_tph_set_st_entry` fails. [F1462]
- In `mlx5_aso_post_wqe`, `dma_wmb()` must precede `*aso->wq.db = cpu_to_be32(aso->pc)`, and `wmb()` must precede `mlx5_write64((__be32 *)doorbell_cseg, aso->uar_map)`. In `eq_update_ci`, `__raw_writel` to `eq->doorbell + (arm ? 0 : 2)` must be followed by `wmb()`. [F1549, F1552]

## Object Lifetimes
- In `mlx5_chains_get_table`, `level > 0` must recursively get levels `0 .. level - 1` before locking `level` and put them in reverse on error, matching `mlx5_chains_put_table`. `mlx5_chains_create_prio` gets `chain_s` (`mlx5_chains_get_chain`), creates `ft`, `miss_group`, and `miss_rule`, inserts `prio_s`, and calls `mlx5_chains_update_prio_prevs`; error paths and `mlx5_chains_destroy_prio` must tear these down in reverse ending with `mlx5_chains_put_chain`. [F1418, F1420]
- `destroy_chain_restore` gates all cleanup on `if (!chain->miss_modify_hdr) return;`, so `create_chain_restore` must roll back `chain->restore_rule` and `chain->id` if `mlx5_modify_header_alloc` fails. [F1421]
- `mlx5_devcom_register_component` gets `comp->ref` before `devcom_alloc_comp_dev` (which gets `devc->ref`) and must call `kref_put(&comp->ref, mlx5_devcom_comp_release)` if `devcom_alloc_comp_dev` fails; `devcom_free_comp_dev` drops both. [F1424]
- `mlx5_dm_sw_icm_alloc` sets `block_map` bits under `dm->lock` before `mlx5_cmd_exec` and clears them on error, whereas `mlx5_dm_sw_icm_dealloc` runs `MLX5_CMD_OP_DESTROY_GENERAL_OBJECT` first and clears `block_map` only if `mlx5_cmd_exec` succeeds. [F1427]
- `macsec_fs_tx_add_rule` and `macsec_fs_rx_add_rule` must balance `macsec_fs_tx_ft_get` / `macsec_fs_rx_ft_get` on every error path so `tables->refcnt` reaches zero for cleanup. In `macsec_fs_id_del`, when `refcount_dec_and_test(&fs_id_found->refcnt)` holds, remove `fs_id_found->hash` from `hash_table` and zero `fs_id_found->id` under `xa_lock(fs_id_xa)` before unlocking, calling `xa_erase`, freeing `fs_id_found`, and freeing `macsec_device` if `macsec_fs_is_macsec_device_empty` holds. [F1430, F1431]
- `mlx5_macsec_fs_add_rule` fires `MLX5_DRIVER_EVENT_MACSEC_SA_ADDED` on `mdev->macsec_nh` only after rule creation succeeds, while `mlx5_macsec_fs_del_rule` fires `MLX5_DRIVER_EVENT_MACSEC_SA_DELETED` before deleting the rule; callbacks must not retain the stack-allocated `struct mlx5_macsec_event_data *`. [F1460, F1547]
- When `!MLX5_CAP_GEN(mdev, device_frequency_khz)`, `mdev->clock` is `&null_clock` and `clock_state` is NULL, so `mlx5_clock_load`, `mlx5_clock_unload`, and `mlx5_cleanup_clock` must return early. In `mlx5_clock_unload` and `mlx5_shared_clock_unregister`, disarm/migrate PPS-in via `mlx5_clock_arm_pps_in_event` and unregister `pps_nb` via `mlx5_eq_notifier_unregister` before `cancel_work_sync(&mdev->clock_state->out_work)`; for `clock->shared`, migrate `cpriv->event_mdev` and `cpriv->mdev` under `compdev` and `clock` locks to a surviving peer, calling `mlx5_clock_free(mdev)` only if none remains. [F1436, F1437, F1557]
- In `mlx5_crypto_dek_pool_destroy`, `cancel_work_sync(&pool->sync_work)` must precede `cancel_work_sync(&pool->destroy_work)`, and both must finish before draining `wait_for_free`, removing bulks, or freeing `destroy_list`. [F1452]
- `mlx5_hv_vhca_agent_create` must initialize all `agent` fields before setting `hv_vhca->agents[type] = agent` under `hv_vhca->agents_lock`; `mlx5_hv_vhca_agent_destroy` clears `hv_vhca->agents[agent->type]` under `agents_lock` before `agent->cleanup(agent)` and `kfree(agent)`, and both must call `mlx5_hv_vhca_agents_update(hv_vhca)`. `mlx5_hv_vhca_cleanup` must destroy the control agent and call `mlx5_hv_unregister_invalidate` before `mlx5_hv_vhca_destroy` destroys `work_queue` and frees `hv_vhca`. [F1455, F1498, F1568]
- When `mlx5_core_is_sf(dev)` is true, `mlx5_st_create` borrows `parent_mdev->st`, so `mlx5_st_destroy` must return early. `mlx5_vxlan_del_port` must call `hash_del_rcu` and `synchronize_rcu()` before freeing `vxlanp` under `vxlan->sync_lock`, and `mlx5_vxlan_reset_to_default` must skip `IANA_VXLAN_UDP_PORT`. `mlx5_aso_create` creates `aso->cq` before the SQ, and `mlx5_aso_destroy` destroys the SQ before `aso->cq`. `mlx5_uplink_netdev_get(mdev)` must be paired with `mlx5_uplink_netdev_put(mdev, netdev)` (not plain `dev_put`). [F1435, F1438, F1439, F1597]

## API Contracts
- `mlx5_crypto_dek_pool_push` takes ownership of `dek` on all paths, so callers (`mlx5_crypto_dek_create`) must never `kfree(dek)` after calling it. `mlx5_crypto_dek_init` returns `NULL` when bulk DEKs are unsupported and `ERR_PTR` on error; callers must check `IS_ERR` and reset `mdev->mlx5e_res.dek_priv` to `NULL` so `mlx5_crypto_dek_create`/`destroy` can test `!dek_priv` for fallback mode. [F1422, F1463]
- Callers sharing a `struct mlx5_aso` must externally lock the entire `mlx5_aso_get_wqe` / `mlx5_aso_build_wqe` / `mlx5_aso_post_wqe` / `mlx5_aso_poll_cq` cycle. `mlx5_aso_get_wqe` zeroes only `sizeof(struct mlx5_aso_wqe)` (64 bytes), so `with_data == true` callers must zero the trailing `aso_data` segment, call `mlx5_aso_build_wqe` before `mlx5_aso_post_wqe`, and pass matching `with_data` to `post_wqe` and `poll_cq`. [F1443, F1473]
- `mlx5_vsc_gw_read`/`write` require address bits 30–31 to be zero; `write` writes `VSC_DATA_OFFSET` before `VSC_ADDR_OFFSET` (bit 31 = 1) and polls `mlx5_vsc_wait_on_flag(dev, 0)`, while `read` writes `VSC_ADDR_OFFSET` (bit 31 = 0), waits via `mlx5_vsc_wait_on_flag(dev, 1)`, and reads `VSC_DATA_OFFSET`. `mlx5_vsc_gw_read_fast` requires `*next_read_addr > read_addr`, and `mlx5_vsc_gw_read_block_fast` returns bytes read so far (`0` or `< length`) on failure, so callers must check `ret != length`. [F1464, F1506, F1554]
- `mlx5_macsec_fs_add_rule` and `mlx5_macsec_fs_del_rule` select `tx_rule` vs `rx_rule` and whether `sa_fs_id` is dereferenced via `action == MLX5_ACCEL_MACSEC_ACTION_ENCRYPT`, requiring non-NULL `sa_fs_id` for decrypt and matching `action` on delete. [F1466]
- `mlx5_dm_sw_icm_alloc` requires `length` to be a non-zero power-of-two multiple of `MLX5_SW_ICM_BLOCK_SIZE(dev)` and `log_alignment` to be `ilog2` of byte alignment. `mlx5_create_ttc_table` and `mlx5_create_inner_ttc_table` require `params->ns_type` in `{MLX5_FLOW_NAMESPACE_PORT_SEL, MLX5_FLOW_NAMESPACE_KERNEL}` and `params->ft_attr.max_fte == 0`. `mlx5_hv_read_config`/`write_config` require `len == HV_CONFIG_BLOCK_SIZE_MAX` and aligned `offset`; `mlx5_hv_vhca_invalidate` must stay atomic (`GFP_ATOMIC`) and defer locking/execution to `hv_vhca->work_queue`. [F1474, F1475, F1477, F1584]

## Error Handling
- `mlx5_chains_update_prio_prevs` must allocate all replacement `miss_rules[n]` via `mlx5_chains_add_miss_rule` across the reverse walk of `chain->prios_list` before deleting any existing `pos->miss_rule`. [F1419]
- On handler failure at peer `pos` in `mlx5_devcom_send_event`, `rollback` must step back with `pos = list_prev_entry(pos, list)` and use `list_for_each_entry_from_reverse` under `comp->sem`. When `sd_cmd_set_secondary(pos, ...)` fails in `mlx5_sd_init`, `err_unset_secondaries` must set `to = pos` and use `mlx5_sd_for_each_secondary_to` before `sd_cmd_unset_primary`. [F1426, F1434]
- `mlx5_macsec_add_roce_rule` must call `mlx5_macsec_del_roce_rule` on error to roll back rules already added for `gid_idx`. Teardown helpers in `macsec_fs.c` check pointers only for non-`NULL`, so creation functions must check `IS_ERR` before storing pointers into structs. [F1432, F1470]
- `mlx5_geneve_tlv_option_create` returns `< 0` on error and a 16-bit `obj_id` on success, so callers must store it in a signed `int` and test `< 0`. `mlx5_crypto_modify_dek_key` and `mlx5_crypto_create_dek_key` must call `memzero_explicit(in, sizeof(in))` after `mlx5_cmd_exec`. `mlx5_nv_param_read`/`write` use `WARN_ON` only for caller bugs (`len > MLX5_ST_SZ_BYTES(mnvda_reg)` or `MLX5_GET_CFG_HDR_LEN(mnvda) == 0`), not firmware register errors. [F1465, F1471, F1598]

## External Contracts
- `mlx5_devlink_enable_sriov_set` and `mlx5_devlink_total_vfs_set` must verify `per_pf_total_vf_supported` in `nv_global_pci_cap` (returning `-EOPNOTSUPP` if false) before setting `per_pf_total_vf = 1` in `nv_global_pci_conf` and writing `nv_pf_pci_conf`. [F1492]
- `mlx5_extts_configure` must test `(rq->extts.flags & PTP_EXTTS_EDGES) == PTP_EXTTS_EDGES` to reject both-edge requests, and `mlx5_ptp_verify` must invert the capability bit check (`!(clock->pps_info.pin_caps[pin] & ...)`). [F1528]

## Known Pitfalls
- Reusing an `mnvda` buffer across `mlx5_nv_param_read_*` calls in `nv_param.c` requires `memset(mnvda, 0, sizeof(mnvda))` first. Reusing `create_flow_group_in` across `mlx5_create_flow_group` calls in `fs_ttc.c` requires zeroing any match criteria set in `mc` for the previous group. [F1472, F1487]
- `mlx5_devcom_get_next_peer_data` and `mlx5_devcom_get_next_peer_data_rcu` must check `list_entry_is_head(tmp, &comp->comp_dev_list_head, list)` and return `NULL` before setting `*pos = tmp`. In `mlx5_vsc_gw_lock`, the `if (lock_val)` branch that sleeps and executes `continue` must increment `retries` first. [F1516, F1520]

## Other
- `mlx5_read_time` must read the 32-bit MMIO registers (`real_time_h`/`l` or `internal_timer_h`/`l`) via `ioread32be` as high, low, high (`timer_h1`), and re-read low if `timer_h != timer_h1`. [F1555]
