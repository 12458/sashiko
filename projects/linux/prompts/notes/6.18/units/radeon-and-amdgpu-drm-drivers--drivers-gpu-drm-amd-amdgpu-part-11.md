# RADEON and AMDGPU DRM DRIVERS — drivers/gpu/drm/amd/amdgpu (part 11)

Hardware IP block driver (`gfx_v10_0.c`) for GFX v10.0 (`gc_10_1` / Navi1x and `gc_10_3` / Sienna Cichlid families), managing graphics and compute rings, MEC/PFP/CE/ME/RLC microcode loading, MQD initialization, KIQ, clockgating/powergating, cleaner shaders, and GFX interrupt handling.

## Architecture & Data Flow

- In `gfx_v10_0_hw_init`: when `adev->firmware.load_type == AMDGPU_FW_LOAD_DIRECT`, `amdgpu_pm_load_smu_firmware` and `gfx_v10_0_disable_gpa_mode` must precede `gfx_v10_0_rlc_resume`; on GC 10.1.10, 10.1.1, and 10.1.2, `gfx_v10_0_tcp_harvest` must run after both `gfx_v10_0_init_golden_registers` and `gfx_v10_0_rlc_resume`, which would otherwise overwrite harvested TCP/SQC disable registers. [F1437, F1490]
- In `gfx_v10_0_tcp_harvest`, updates to `mmUTCL1_UTCL0_INVREQ_DISABLE` and `mmGCRD_SA_TARGETS_DISABLE` must preserve upper SQG/RMI/GL1C bits by masking existing values with `(0xffffffffU << (4 * max_wgp_per_sh))` and `(0xffffffffU << (3 * max_wgp_per_sh))` before ORing disable bitmasks. [F1436]
- In `gfx_v10_0_sw_init`, `gfx_v10_0_mec_init` must complete before `gfx_v10_0_compute_ring_init` because compute rings derive `ring->eop_gpu_addr` from `adev->gfx.mec.hpd_eop_gpu_addr`. [F1492]
- On non-reset, non-resume initialization in `gfx_v10_0_kgq_init_queue`, `gfx_v10_0_kiq_init_queue`, and `gfx_v10_0_kcq_init_queue`, `ring->mqd_ptr` must be zeroed with `memset` before `amdgpu_ring_init_mqd(ring)`, and `mqd_backup` must be checked for non-NULL before `memcpy_fromio`/`memcpy_toio`. In `gfx_v10_0_kgq_init_queue`, `gfx_v10_0_cp_gfx_set_doorbell` must only run for the first GFX ring (`ring->doorbell_index == adev->doorbell_index.gfx_ring0 << 1`) so initializing a second ring does not overwrite `mmCP_RB_DOORBELL_RANGE_LOWER`. [F1426, F1440]
- `gfx_v10_0_get_cpc_int_cntl` and `gfx_v10_0_set_compute_eop_interrupt_state` must only program interrupt control registers for MEC1 (`me == 1`), leaving all other MEC pipes to `amdkfd`. [F1439]
- When `gfx_v10_0_cp_compute_enable` halts MEC engines (`enable == false`), it must set `adev->gfx.kiq[0].ring.sched.ready = false` in lockstep. [F1442]
- PM4 packet sizes and ring allocations must match emitted DWord counts: `gfx_v10_0_kiq_pm4_funcs` (`set_resources_size` = 8, `map_queues_size` = 7, `unmap_queues_size` = 6, `query_status_size` = 7, `invalidate_tlbs_size` = 2) must match the `gfx10_kiq_*` callbacks; `emit_frame_size` and `emit_ib_size` in `gfx_v10_0_ring_funcs_{gfx,compute,kiq}` must track their callbacks; and `gfx_v10_0_get_csb_size` must match `gfx_v10_0_get_csb_buffer`, with `gfx_v10_0_cp_gfx_start` allocating `gfx_v10_0_get_csb_size(adev) + 4` DWords on `gfx_ring[0]` for the trailing `PACKET3_SET_BASE`. [F1450, F1451, F1460]
- In `gfx_v10_0_ring_emit_vm_flush`, emitting a GPU TLB flush on `AMDGPU_RING_TYPE_GFX` must be followed by `PACKET3_PFP_SYNC_ME`. [F1446]
- In `gfx_v10_0_ring_preempt_ib`, `amdgpu_ring_set_preempt_cond_exec(ring, false)` before `PREEMPT_QUEUES_NO_UNMAP` must be paired with `amdgpu_ring_set_preempt_cond_exec(ring, true)` after polling the trailing fence, even on timeout. [F1447]
- `gfx_v10_ring_insert_nop` must handle `num_nop == 1` before computing `min(num_nop - 2, 0x3ffe)` for `PACKET3_NOP` and must never be called with `num_nop == 0`. [F1459]
- `gfx_v10_0_rlc_backdoor_autoload_copy_ucode` must verify `id > FIRMWARE_ID_INVALID && id < FIRMWARE_ID_MAX`, clamp `fw_size` to `rlc_autoload_info[id].size`, and zero-fill trailing bytes up to `rlc_autoload_info[id].size` in `adev->gfx.rlc.rlc_autoload_ptr`. [F1454]
- `gfx_v10_0_init_gds_vmid` must start its loop at `vmid = 1` (never clearing VMID 0), and all per-VMID GDS accesses (`gfx_v10_0_init_gds_vmid`, `gfx_v10_0_init_compute_vmid`, `gfx_v10_0_ring_emit_gds_switch`) must index `mmGDS_VMID0_BASE` and `mmGDS_VMID0_SIZE` by `2 * vmid` while indexing `mmGDS_GWS_VMID0` and `mmGDS_OA_VMID0` by `vmid`. [F1456]
- `gfx_v10_0_check_grbm_cam_remapping` must save and restore `mmVGT_ESGS_RING_SIZE` (or `mmVGT_ESGS_RING_SIZE_Sienna_Cichlid`) around writing the `0xDEADBEEF` probe to `mmVGT_ESGS_RING_SIZE_UMD` on both remapped and non-remapped paths. [F1448]

## Synchronization

- Any caller of `gfx_v10_0_select_se_sh` (`gfx_v10_0_setup_rb`, `gfx_v10_0_tcp_harvest`, `gfx_v10_0_get_cu_info`) must hold `adev->grbm_idx_mutex` and restore broadcast mode via `gfx_v10_0_select_se_sh(adev, 0xffffffff, 0xffffffff, 0xffffffff, 0)` before unlocking. [F1404]
- Any path calling `nv_grbm_select` must hold `adev->srbm_mutex` and reset selection via `nv_grbm_select(adev, 0, 0, 0, 0)` before unlocking; in `gfx_v10_0_cp_gfx_resume`, `gfx_v10_0_cp_gfx_switch_pipe` must also be protected by `adev->srbm_mutex` and restored to `PIPE_ID0` after configuring `gfx_ring[1]` on `PIPE_ID1` before `gfx_v10_0_cp_gfx_start`. [F1405, F1407]
- When acquiring both RLC safe mode and `adev->srbm_mutex` (`gfx_v10_0_kiq_reset_hw_queue`, `gfx_v10_0_reset_kcq`), `amdgpu_gfx_rlc_enter_safe_mode` must precede `mutex_lock(&adev->srbm_mutex)` and `amdgpu_gfx_rlc_exit_safe_mode` must follow `mutex_unlock(&adev->srbm_mutex)`. [F1406]
- In `gfx_v10_0_ring_preempt_ib`, `gfx_v10_0_reset_kgq`, and `gfx_v10_0_reset_kcq`, KIQ ring allocation and packet emission must hold `spin_lock_irqsave(&kiq->ring_lock, flags)`, unlocking both on `amdgpu_ring_alloc` failure and after `amdgpu_ring_commit`. [F1412]
- In `gfx_v10_0_ring_set_wptr_gfx` and `gfx_v10_0_ring_set_wptr_compute`, when `ring->use_doorbell` is true, `atomic64_set((atomic64_t *)ring->wptr_cpu_addr, ring->wptr)` must precede `WDOORBELL64(ring->doorbell_index, ring->wptr)`. [F1420]
- In `gfx_v10_0_get_gpu_clock_counter`, reading the 64-bit Golden TSC counter across upper/lower SMUIO registers must occur under `preempt_disable()` / `preempt_enable()` using `RREG32_SOC15_NO_KIQ` with an upper-register carry-over recheck (`hi_check != clock_hi`). [F1419]
- IRQ `.process` callbacks (`gfx_v10_0_eop_irq`, `gfx_v10_0_priv_reg_irq`, `gfx_v10_0_bad_op_irq`, `gfx_v10_0_priv_inst_irq`, `gfx_v10_0_kiq_irq`, and `gfx_v10_0_handle_priv_fault`) run in atomic context and must never acquire sleeping locks (`srbm_mutex`, `grbm_idx_mutex`) or perform KIQ register reads. [F1519]

## Object Lifetimes

- In `gfx_v10_0_ring_test_ib`, resources from `amdgpu_device_wb_get`, `amdgpu_ib_get`, and `amdgpu_ib_schedule` must be freed in reverse order at `err2` (`amdgpu_ib_free` and `dma_fence_put(f)`, with `f` initialized to `NULL`) and `err1` (`amdgpu_device_wb_free`). [F1400]
- In `gfx_v10_0_mec_init`, `hpd_eop_obj` and `mec_fw_obj` created via `amdgpu_bo_create_reserved` must be unmapped and unreserved (`amdgpu_bo_kunmap`, `amdgpu_bo_unreserve`) after CPU initialization, and any error path must call `gfx_v10_0_mec_fini(adev)`. [F1402]
- In `gfx_v10_0_sw_fini`, `amdgpu_gfx_kiq_free_ring(&adev->gfx.kiq[0].ring)` must precede `amdgpu_gfx_kiq_fini(adev, 0)`, and all unmanaged kernel BOs (`pfp_fw_obj`, `ce_fw_obj`, `me_fw_obj`, `clear_state_obj`, `cp_table_obj`, `hpd_eop_obj`, `mec_fw_obj`, `rlc_toc_bo`, `rlc_autoload_bo`), firmware blobs, and `kcalloc` IP dump buffers must be explicitly freed. [F1403, F1494]
- In `gfx_v10_0_hw_fini`: `cancel_delayed_work_sync(&adev->gfx.idle_work)` and `amdgpu_irq_put` for `priv_reg_irq`, `priv_inst_irq`, and `bad_op_irq` (matching `gfx_v10_0_late_init`) must run before disabling KGQ/KCQ/CP; on `IP_VERSION(10, 3, 1)` (VanGogh), `gfx_v10_0_set_powergating_state(ip_block, AMD_PG_STATE_UNGATE)` must also precede queue/CP teardown; and when `amdgpu_sriov_vf(adev)` is true, it must only call `gfx_v10_0_cp_gfx_enable(adev, false)` and return early without halting MEC or clearing KIQ. [F1409, F1510, F1511]
- In `gfx_v10_0_update_gfx_clock_gating`, clockgating must be enabled in order FGCG, MGCG/MGLS, 3D CGCG/CGLS, then CGCG/CGLS, and disabled in exact reverse order, all bracketed by `amdgpu_gfx_rlc_enter_safe_mode` and `amdgpu_gfx_rlc_exit_safe_mode`. [F1410]
- In `gfx_v10_0_set_powergating_state` on GC 10.3.1, 10.3.3, 10.3.6, and 10.3.7, `amdgpu_gfx_off_ctrl(adev, false)` must precede `gfx_v10_cntl_pg(adev, false)` when ungating, whereas `amdgpu_gfx_off_ctrl(adev, true)` must follow `gfx_v10_cntl_pg(adev, true)` when gating. [F1411]

## API Contracts

- `gfx_v10_0_compute_ring_init` takes a 0-based `mec` index and sets `ring->me = mec + 1`, whereas `gfx_v10_0_get_cpc_int_cntl` and `gfx_v10_0_set_compute_eop_interrupt_state` take a 1-based `me` index (`1` for MEC1) and `gfx10_kiq_map_queues` encodes `PACKET3_MAP_QUEUES_ME` as `ring->me == 1 ? 0 : 1`. [F1427]
- `ring->mqd_ptr` and `ring->mqd_obj` hold `struct v10_gfx_mqd` for GFX rings (`gfx_v10_0_gfx_mqd_init`, `gfx_v10_0_kgq_init_queue`, `gfx_v10_0_reset_kgq`) and `struct v10_compute_mqd` for compute and KIQ rings (`gfx_v10_0_compute_mqd_init`, `gfx_v10_0_kcq_init_queue`, `gfx_v10_0_kiq_init_queue`). [F1483]
- `gfx_v10_0_select_se_sh` uses `0xffffffff` as the broadcast sentinel for `se_num`, `sh_num`, and `instance`, and on GFX10 the SIMD ID must be encoded into the `instance` argument of `gfx_v10_0_select_se_sh` while passing `simd == 0` to `gfx_v10_0_read_wave_data` and `gfx_v10_0_read_wave_sgprs`. [F1458]
- In `gfx_v10_0_wait_reg_mem`, when `mem_space != 0` (memory wait), `addr0` must be 4-byte aligned (`BUG_ON(addr0 & 0x3)`). [F1432]
- `amdgpu_ring_write_multiple` takes a 32-bit DWord count, so `gfx_v10_0_ring_emit_ce_meta` and `gfx_v10_0_ring_emit_de_meta` must pass `sizeof(ce_payload) >> 2` and `sizeof(de_payload) >> 2`. [F1482]
- `gfx_v10_0_me_init` and `gfx_v10_0_mec_init` must pass bit counts `AMDGPU_MAX_GFX_QUEUES` and `AMDGPU_MAX_COMPUTE_QUEUES` (not `sizeof`) to `bitmap_zero` on `adev->gfx.me.queue_bitmap` and `adev->gfx.mec_bitmap[0].queue_bitmap`. [F1489]
- `gfx_v10_0_ring_emit_init_cond_exec` must capture and return `ring->wptr & ring->buf_mask` before writing the `0` placeholder DWord via `amdgpu_ring_write(ring, 0)`. [F1524]
- `gfx_v10_0_reset_kgq` and `gfx_v10_0_reset_kcq` must call `amdgpu_ring_reset_helper_begin(ring, timedout_fence)` before unmapping/resetting the queue and clearing the ring, and return `amdgpu_ring_reset_helper_end(ring, timedout_fence)` after remapping. [F1527]

## Error Handling

- `gfx_v10_0_get_cpg_int_cntl` and `gfx_v10_0_get_cpc_int_cntl` return `0` for unsupported `me` or `pipe` indices (`me != 0` for CPG, `me != 1` for CPC); callers must check that the returned offset is non-zero before passing it to `RREG32_SOC15_IP` or `WREG32_SOC15_IP`. [F1422]
- `gfx_v10_0_alloc_ip_dump` treats allocation failures of `ip_dump_core`, `ip_dump_compute_queues`, and `ip_dump_gfx_queues` as non-fatal by setting the pointer to `NULL`; `gfx_v10_ip_dump` and `gfx_v10_ip_print` must check each pointer for `NULL` before use (and before calling `amdgpu_gfx_off_ctrl(adev, false)` in `gfx_v10_ip_dump`, which must always pair with `amdgpu_gfx_off_ctrl(adev, true)` outside `adev->srbm_mutex`), and buffer sizes, loop nesting, and MEC2 header substitutions must stay synchronized across `gc_reg_list_10_1`, `gc_cp_reg_list_10`, and `gc_gfx_queue_reg_list_10`. [F1413, F1424, F1449]

## External Contracts

- In `gfx_v10_0_ring_emit_fence`, `addr` must be 8-byte aligned when `AMDGPU_FENCE_FLAG_64BIT` is set and 4-byte aligned otherwise, whereas `gfx_v10_0_ring_emit_fence_kiq` forbids `AMDGPU_FENCE_FLAG_64BIT` (`BUG_ON(flags & AMDGPU_FENCE_FLAG_64BIT)`). [F1429]
- HQD ring bases (`cp_gfx_hqd_base`, `cp_hqd_pq_base_lo`, `mmCP_RB0_BASE`, `mmCP_RB1_BASE`), EOP base (`cp_hqd_eop_base_addr_lo`), and KIQ `PACKET3_SET_RESOURCES` cleaner shader addresses take 256-byte-shifted GPU addresses (`>> 8`), whereas MQD base, RPTR, and WPTR poll addresses take unshifted byte addresses masked with `0xfffffffc`. [F1431]

## Known Pitfalls

- Although GFX10 rings set `support_64bit_ptrs = true` and use 64-bit write pointers (`atomic64_read`/`atomic64_set` on `ring->wptr_cpu_addr`, `WDOORBELL64`, and casting `RREG32_SOC15` of `mmCP_RB*_WPTR_HI` to `u64` before `<< 32` in `gfx_v10_0_ring_get_wptr_gfx`), hardware writes a 32-bit read pointer, so `gfx_v10_0_ring_get_rptr_gfx` and `gfx_v10_0_ring_get_rptr_compute` must read `ring->rptr_cpu_addr` as `uint32_t`. [F1462, F1477]
- Writeback slot offsets from `amdgpu_device_wb_get` (`index`, `reg_val_offs`) are DWord indices that index `uint32_t *adev->wb.wb` directly in `gfx_v10_0_ring_test_ib`, but must be multiplied by 4 when added to `adev->wb.gpu_addr` in `gfx_v10_0_ring_test_ib` and `gfx_v10_0_ring_emit_rreg`. [F1485]
- In `gfx_v10_0_sw_init`, the GFX and compute ring loops iterate `j` over queues and `k` over pipes to allocate horizontally across pipes, so `k` must be passed as `pipe` and `j` as `queue` (`(adev, ..., i, k, j)`) to `amdgpu_gfx_is_me_queue_enabled`, `gfx_v10_0_gfx_ring_init`, `amdgpu_gfx_is_mec_queue_enabled`, and `gfx_v10_0_compute_ring_init`. [F1465]
- In `gfx_v10_0_get_cu_info`, `bitmap` holds the linear SA index `i * adev->gfx.config.max_sh_per_se + j` for `gfx_v10_3_get_disabled_sa` before being overwritten with `gfx_v10_0_get_cu_active_bitmap_per_sh`; `mask = 1`, `ao_bitmap = 0`, and `counter = 0` must be reset on each `(i, j)` iteration; indexing `disable_masks[i * 2 + j]` requires `i < 4 && j < 2`; and `ao_bitmap << (i * 16 + j * 8)` requires `i < 2 && j < 2`. [F1457, F1468]
- In `struct gfx_firmware_header_v1_0` and `struct sdma_firmware_header_v1_0`, `ucode_array_offset_bytes` and `ucode_size_bytes` are in bytes while `jt_offset` and `jt_size` are in DWords (multiply by 4 for byte math or add `jt_offset` to a 32-bit pointer); and because `gfx_v10_0_parse_rlc_toc` page-aligns CP firmware offsets via `ALIGN(rlc_toc->offset * 4, PAGE_SIZE)`, `gfx_v10_0_calc_toc_total_size` must bound `total_size` by `rlc_autoload_info[FIRMWARE_ID_MAX-1].offset + rlc_autoload_info[FIRMWARE_ID_MAX-1].size`. [F1479, F1481]
- In `gfx_v10_0_sw_init`, `adev->gfx.cleaner_shader_size` must be `sizeof(gfx_10_*_cleaner_shader_hex)` in bytes (not pointer `sizeof` or `ARRAY_SIZE`), and enabling the cleaner shader must check both GC_HWIP version and minimum ME/PFP/MEC firmware versions, resetting `enable_cleaner_shader = false` if `amdgpu_gfx_cleaner_shader_sw_init` fails. [F1484, F1496]
- In `gfx_v10_0_ring_emit_reg_write_reg_wait`, `gfx_v10_0_wait_reg_mem` with `opt = 1` must only be used when `adev->gfx.cp_fw_write_wait` is true, falling back to `amdgpu_ring_emit_reg_write_reg_wait_helper` otherwise. [F1497]
- Hardware-specific workarounds that must not be dropped: on `IP_VERSION(10, 1, 10)` (Navi10), `gfx_v10_0_check_gfxoff_flag` must clear `PP_GFXOFF_MASK` unless `adev->pdev->revision` is `0xc2` or `0xc3`; on `IP_VERSION(10, 1, 2)`, writes to `mmRLC_CSIB_ADDR_HI/LO`, `mmRLC_CSIB_LENGTH`, and `mmCP_ME_CNTL` in `gfx_v10_0_init_csb` and `gfx_v10_0_cp_gfx_enable` must use `WREG32_SOC15_RLC`; and `SOC15_REG_GOLDEN_VALUE(GC, 0, mmLDS_CONFIG, 0x00000020, 0x00000020)` must remain in `golden_settings_gc_10_3_2` and `golden_settings_gc_10_3_vangogh`. [F1498, F1499, F1507]
