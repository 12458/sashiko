# DRM DRIVER FOR NVIDIA GEFORCE/QUADRO GPUS — drivers/gpu/drm/nouveau/include

This component provides the internal headers for the Nouveau driver across three layers: `nvhw` (hardware register/class definitions and DRF bitfield macros), `nvif` (the intermediate client/object/pushbuffer/ioctl interface between DRM and the backend), and `nvkm` (the core hardware abstraction for devices, subdevices, engines, VBIOS tables, MMU/VMM, and GSP firmware).

## Architecture & Data Flow

- `NVKM_LAYOUT_ONCE` and `NVKM_LAYOUT_INST(type, data, ptr, cnt)` order in `core/layout.h` defines the exact forward construction/`preinit`/`init` order of `struct nvkm_device::subdev` and reverse `fini`/destruction order. `cnt` in `NVKM_LAYOUT_INST` must exceed the highest bit index in any chip's `nvkm_device_chip.<ptr>.inst` mask, and `NVKM_LAYOUT_ONCE` subdevices must only set `.inst = 1` (`BIT(0)`). [F49, F85]
- `struct nvkm_gsp_object.client` tracks whether a GSP-RM handle is live: `nvkm_gsp_rm_alloc_get()` sets it and clears it to `NULL` on failure (as does `nvkm_gsp_rm_alloc_push()`), while `nvkm_gsp_rm_free()`, `nvkm_gsp_device_dtor()`, and `nvkm_gsp_client_dtor()` gate teardown on `object->client != NULL` and clear it. Broken by: manually setting `object->client` or calling `rm->api->alloc->free(object)` directly without clearing `object->client = NULL`. [F6]
- `PUSH_WAIT(push, size)` sets `push->seg = push->cur + size` (under `CONFIG_NOUVEAU_DEBUG_PUSH`) and may call `push->wait` to wrap the ring, resetting `push->bgn`, `cur`, and `end`; `PUSH_KICK(push)` calls `push->kick(push)` when `cur != bgn` and sets `bgn = cur`. Since `PUSH_DATA__`/`PUSH_DATAp` assert `_p->cur < _p->seg` and `_p->cur < _p->end`, callers must reserve all emitted `u32` words via `PUSH_WAIT` and never cache `push->cur` or `push->bgn` across `PUSH_WAIT`. [F35, F37]
- Descriptor tables must end with sentinels: `struct nvkm_intr_data` arrays for `nvkm_intr_add()` require `.mask == 0`, and `struct nvkm_enum` / `struct nvkm_bitfield` arrays for `nvkm_enum_find()` / `nvkm_snprintbf()` require `.name == NULL`. [F46, F47]

## Synchronization

- `nvkm_chan_get_chid()` and `nvkm_chan_get_inst()` return non-NULL `struct nvkm_chan *` with `chan->cgrp->lock` held and IRQs disabled in `*irqflags`, and `nvkm_fifo_pause(fifo, &flags)` acquires `spin_lock_irqsave(&fifo->lock, flags)`. Callers must not sleep and must release the lock on every path via `nvkm_chan_put(&chan, irqflags)` or `nvkm_fifo_start(fifo, &flags)`. [F16, F17]
- `nvkm_event_func` (`nvkm_event_ntfy::func`) and `struct nvkm_event_func::init`/`fini` run in atomic context under `read_lock_irqsave(&event->list_lock)` and `spin_lock_irqsave(&event->refs_lock)` respectively; callbacks must not sleep, and `nvkm_event_ntfy::func` must not call `nvkm_event_ntfy_add()`/`del()` on the same `nvkm_event`. When registered with `wait == true` (`nvkm_event_ntfy_add()`/`nvif_event_ctor()`), `nvkm_event_ntfy_allow()`, `block()`, and `del()` acquire `write_lock_irq(&event->list_lock)` and must never be called inside a callback. [F18, F93]
- GSP callbacks (`nvkm_gsp_msg_ntfy_func`, `nvkm_gsp_event_func`) run under `gsp->cmdq.mutex` (and `gsp->client_id.mutex` for `nvkm_gsp_event_func`), so they must not synchronously issue GSP RPCs (`nvkm_gsp_rpc_*`, `nvkm_gsp_rm_ctrl_*`, `nvkm_gsp_rm_alloc_*`, `nvkm_gsp_rm_free`) or mutate `client->events` (e.g., `nvkm_gsp_event_dtor()`). [F19]
- Every `nvkm_inth_func` callback (including `nvkm_subdev_func::intr` via `nvkm_intr_subdev`) runs in hardirq context under `device->intr.lock`, so it must not sleep or call `nvkm_inth_allow()`, `nvkm_intr_allow()`, `nvkm_intr_block()`, `nvkm_intr_rearm()`, or `nvkm_intr_unarm()` on the same `struct nvkm_device`. [F92]
- On `struct nvkm_vmm` and `struct nvkm_mmu`, lock order is `vmm->mutex.vmm` -> `vmm->mutex.ref` / `vmm->mutex.map` -> `vmm->mmu->mutex`. Callers that look up or split a non-raw `struct nvkm_vma` under `vmm->mutex.vmm` before `nvkm_memory_map()`/`nvkm_vmm_map()` must set `vma->busy = true` and unlock `vmm->mutex.vmm` first, and on error relock `vmm->mutex.vmm` to clear `vma->busy = false`. [F20, F95]
- `nvkm_event_init()` (initializing `event->refs_lock` and `list_lock` before `__nvkm_event_init()`) and `nvkm_subdev_ctor()` (initializing `subdev->use.mutex` before `__nvkm_subdev_ctor()`) must be used rather than calling the `__`-prefixed functions directly, giving each call site a distinct lockdep class. [F13, F14]
- `nvkm_mask` and `nvif_mask` perform unserialized 32-bit MMIO read-modify-writes (`nvkm_rd32`/`wr32`, `nvif_rd32`/`wr32`); concurrent callers modifying shared registers must provide external locking. [F88]

## Object Lifetimes

- `nvkm_kmap()` and `nvkm_done()` must bracket all `nvkm_ro32()`, `nvkm_wo32()`, `nvkm_mo32()`, `nvkm_wo64()`, `nvkm_robj()`, and `nvkm_wobj()` calls on `struct nvkm_memory` or `struct nvkm_gpuobj` to set up `ptrs`/`func` and flush writes on release. [F1]
- Every `struct nvkm_gsp_mem` initialized by `nvkm_gsp_mem_ctor()` holds a coherent DMA allocation and a `get_device()` ref in `nvkm_gsp_mem.dev`, and must be freed via `nvkm_gsp_mem_dtor()` (never by freeing `mem->data` directly). [F2]
- When `nvkm_gsp_rpc_push()` or `nvkm_gsp_rpc_rd()` succeeds with `NVKM_GSP_RPC_REPLY_RECV` and `repc > 0`, it returns a reply buffer that must be freed with `nvkm_gsp_rpc_done()`, whereas `NVKM_GSP_RPC_REPLY_NOWAIT`, `NVKM_GSP_RPC_REPLY_POLL`, and `nvkm_gsp_rpc_wr()` consume or discard the reply internally. When a GSP RPC reply is only an empty header in the message queue (e.g., `NV_VGPU_MSG_FUNCTION_ALLOC_MEMORY`), callers of `nvkm_gsp_rpc_push`/`wr` must pass `NVKM_GSP_RPC_REPLY_POLL` instead of `NVKM_GSP_RPC_REPLY_RECV`. [F3, F80]
- Every `struct nvif_log.shutdown` callback on `struct nvif_logs` must free all debugfs dentries, buffers, and the `struct nvif_log` container itself when called by `nvif_log_shutdown()`. In `struct nvkm_gsp`, `blob_init`, `blob_intr`, `blob_rm`, and `blob_pmu` (`struct debugfs_blob_wrapper`) and their buffers must outlive `debugfs_remove()` on `gsp->debugfs.{init,intr,rm,pmu}`. [F7, F8]
- When `nvif_object_sclass_get()` returns `>= 0` (including `0`), it allocates `*psclass` via `kcalloc()`, which the caller must free with `nvif_object_sclass_put()`. [F10]
- `nvkm_engine_ref()` can return an `ERR_PTR()` if lazy subdevice init (`nvkm_subdev_init_()`) fails on `0 -> 1`, so callers must check `IS_ERR()` before dereferencing or calling `nvkm_engine_unref()` (unlike `nvkm_memory_ref()` and `nvkm_vmm_ref()`, which unconditionally increment a `kref`). [F12]
- Falcon firmware needed during preinit/teardown/shutdown (e.g., `struct nvkm_fb::vpr_scrubber` in `nvkm_fb_mem_unlock`) must be cached during `nvkm_subdev_func::oneinit` in a persistent `struct nvkm_falcon_fw` rather than loaded on demand during shutdown. Instance memory allocated via `nvkm_memory_new` with `NVKM_MEM_TARGET_INST_SR_LOST` is lost across suspend/resume; use `NVKM_MEM_TARGET_INST` if not reconstructed on resume. [F79, F84]

## API Contracts

- `nvkm_object_func.dtor`, `nvkm_subdev_func.dtor`, `nvkm_engine_func.dtor`, `nvkm_device_func.dtor`, and `nvkm_memory_func.dtor` must return the outer heap pointer for the core to `kfree()` (or `NULL` if embedded) and must not `kfree()` it while returning non-NULL or return an embedded struct pointer at a non-zero offset. [F11]
- `nvif_unpack(r, d, s, m, vl, vh, x)` and `nvif_unvers(r, d, s, m)` only inspect the payload when `r == -ENOSYS`, so callers must initialize `ret = -ENOSYS`. `x = false` requires `*s == sizeof(m)` (returning `-E2BIG` on trailing bytes) and zeroes `*d`/`*s`, while `x = true` advances `*d` and decrements `*s` by `sizeof(m)` for trailing data. `nvif_unvers` evaluates `sizeof(m)`, so pass the dereferenced struct (`args->vn` or `*args`), not pointer `args`. [F25, F43, F74]
- `nvkm_mask`, `nvif_mask`, and `DRF_MR`/`NVIF_MR32` take pre-shifted mask and value (`DRF_SMASK`, `NVVAL`/`NVDEF`) and return the old 32-bit register value, whereas `DRF_MV`/`NVIF_MV32` take an unshifted field value and return the old unshifted field value. Unlike `DRF_MV`/`NVIF_MV32` and `DRF_MD`/`NVIF_MD32` (read-modify-write), `DRF_WV`/`NVIF_WV32` and `DRF_WD`/`NVIF_WD32` overwrite the whole register, clearing other bits. [F32, F33]
- In `nvkm/core/memory.h`, `nvkm_mo32`, `nvkm_robj(o, a, p, s)`, and `nvkm_wobj(o, a, p, s)` store byte offset `a` in `u32 _addr` and `nvkm_robj`/`wobj` take `s` as a 4-byte-multiple byte size (`_size = (s) >> 2`, `a + s` fitting in `u32`), whereas `nvkm_fo32(o, a, d, c)` and `nvkm_fo64(o, a, d, c)` take `a` as a 4/8-byte aligned offset (`_o = _a >> s`) and `c` as a 32/64-bit word count (`_s = _c << s` bytes). [F67, F73]
- `nvkm_mm_addr(node)` requires `nvkm_mm_contiguous(node)` (`!node->next`); on discontiguous nodes (`size_min < size_max`, `node->next != NULL`), it triggers `WARN_ON` and returns `0`. [F34]
- Emitting a pre-reserved word at the end of a pushbuffer segment (e.g., wrap-around `PUSH_JUMP` in `push->wait`) must be wrapped in `PUSH_RSVD(p, d)` so `__p->seg` and `__p->end` advance together before `PUSH_DATA__` checks. Addressing modes `o` for `PUSH_1`..`PUSH_10`/`PUSH_DATAp` must define `PUSH_<o>_INC` as an unparenthesized `first_inc:subsequent_inc` pair. [F36, F54]
- Callers of `nvkm_list_find(p, h, m, c)` and `nvkm_list_find_next` must assign and test the return value (`p = nvkm_list_find(...)`), as no match returns `NULL` while leaving `p` at `container_of(h, ...)`. `nvkm_list_foreach` (and `nvkm_runl_foreach_cond`/`engn_cond`) bodies must not `list_del` or `kfree` cursor `p` without breaking out. [F55, F56]
- `struct nvif_outp_dp_train_v0::dpcd` in `nvif/if0012.h` and `dpcd` in `nvif_outp_dp_train()` (`nvif/outp.h`) must be sized `DP_RECEIVER_CAP_SIZE` (15 bytes, not 16) since `sizeof(args.dpcd)` bytes are copied. [F70]
- Callers of `nvkm_object_search(client, handle, func)` that downcast via `container_of` must pass the target's `const struct nvkm_object_func *` as `func` (not `NULL`) to verify `object->func == func`. [F77]
- Before `NV507D_GET_CAPABILITIES`, clear the generation-specific notifier bit (`NV_DISP_CORE_NOTIFIER_1_CAPABILITIES_1_DONE` pre-GF110 or `NV907D_CORE_NOTIFIER_3_CAPABILITIES_4_DONE` on GF110+), enable `NV507D_SET_NOTIFIER_CONTROL` before `GET_CAPABILITIES`, disable it after, and poll for `DONE_TRUE`. [F83]
- `nvkm_device_tegra_func::iommu_bit` must be the GPU address bit triggering IOMMU translation (and `DMA_BIT_MASK`), or `0` if unused; hold `nvkm_device_tegra::iommu.mutex` when accessing `iommu.mm`. [F89]
- `nvkm_memory_page(p)` returns a log2 page shift, and `nvkm_vmm_get()`/`nvif_vmm_get()` take `page` and `align` as log2 shifts (`size` in bytes), whereas `struct nvkm_vma::page` and `refd` store 3-bit indices into `vmm->func->page[]` (or `NVKM_VMA_PAGE_NONE`). [F100]

## Error Handling

- Pass `&ctrl` (pointer address) to `nvkm_gsp_rm_ctrl_push(obj, &ctrl, repc)` because `rm->api->ctrl->push` updates `*params` in-place to the reply buffer (unlike `nvkm_gsp_rm_ctrl_wr(obj, ctrl)` and `nvkm_gsp_rm_ctrl_done(obj, ctrl)`, which take `ctrl` by value). When `repc > 0`, `r535_gsp_rpc_rm_ctrl_push()` stores the reply in `*argv` without freeing the RPC message even when `rpc->status != 0`, so callers must call `nvkm_gsp_rm_ctrl_done(obj, ctrl)` on both success and error paths. [F4, F71]
- Polling loops (`nvkm_nsec`/`usec`/`msec`, `nvkm_wait_nsec`/`usec`/`msec`, `nvif_nsec`/`usec`/`msec`) must exit via `break` on success (or pass `NVKM_DELAY` in `nvkm_nsec`), and return signed `s64` elapsed ns on `break` or `-ETIMEDOUT` on timeout; check failure with `< 0`, not truthiness. `nvif_usec`/`msec` and `nvkm_wait_usec`/`msec` multiply by signed `int` `1000` (unlike `nvkm_usec`/`msec` which use `1000ULL`), so timeouts >= 2148 ms (or >= 2,147,484 us) must be `u64` to avoid 32-bit overflow. [F27, F59, F66]
- `nvkm_firmware_load(s, l, o, p...)` requires descriptor array `l` to end with `.load == NULL` and returns an `ERR_PTR` on failure (never `NULL`); check with `IS_ERR()`. `nvkm_rdi2cr` and `nv_rd16i2cr` return the 8/16-bit value in `int` or `-EIO`; test `< 0` in a signed `int` before narrowing to `u8`/`u16`. [F28, F30]

## External Contracts

- Emitting `NVC36F_MEM_OP_D` (e.g., `MMU_TLB_INVALIDATE` or `MEMBAR`) into a channel pushbuffer must always be preceded by `NVC36F_MEM_OP_A`, `NVC36F_MEM_OP_B`, and `NVC36F_MEM_OP_C`. [F21]
- `struct nvif_ioctl_v0`, `nvif_ioctl_new_v0`, `nvif_ioctl_mthd_v0`, and `nvif_ioctl_sclass_v0` (`nvif/ioctl.h`) are copied from userspace in `nouveau_abi16_ioctl`; preserve binary layout and add any new header fields in `nvif_ioctl_v0` or `nvif_ioctl_mthd_v0` inside `struct_group_tagged` before `data[]`. [F99]

## Known Pitfalls

- `nvhw/drf.h` bitfield macros must be unparenthesized `HI:LO` pairs with `HI >= LO` (`DRF_HI`/`DRF_LO` expand to `(1 ? drf)`/`(0 ? drf)`). Single-word `DRF_MASK`, `DRF_SMASK`, `NVVAL*`, and `NVDEF*` shift `~0ULL` by `64 - DRF_BITS(drf)` and `DRF_LO(drf)` and require `0 <= LO <= HI < 64`; `NVVAL_GET_X(o, drf)` (`NVVAL_GET`, `NVVAL_TEST`, `NVDEF_TEST`) shifts `(o) >> DRF_LO(drf)` before masking, so `o` must be 64-bit when `DRF_LO(drf) >= 32`. [F53, F63, F64]
- Multi-word bitfields for `NVVAL_MW_GET`, `NVVAL_MW_SET`, and `NVDEF_MW_SET` must use `MW(hi:lo)` (`hi >= lo`) and span at most two adjacent elements of `o` (`DRF_HW_IDX <= DRF_LW_IDX + 1`), where `o` has the exact hardware word type (`sizeof((o)[0]) * 8`) and is narrower than 64 bits (e.g., `u32[]`) if `DRF_LW_BITS` can reach 64 (`DRF_HW_VAL` shifts `(long long)(v) >> DRF_LW_BITS`). Since `NVVAL_MW_SET_X` overwrites `(o)[DRF_LW_IDX]` before evaluating `DRF_HW_SET(o, drf, v)`, `v` must not read `(o)[DRF_LW_IDX]` or have side effects. [F41, F50, F65, F75]
- In `nvif/object.h`, the `m` array for `nvif_mclass(o, m)` and `nvif_sclass(o, m, u)` must be ordered most-preferred to fallback and end with `.oclass == 0`, and `nvif_mclass` arguments must not use identifiers `object`, `sclass`, or `mclass`. Nested macros in `nvif/push.h` (`__p`/`__d`, `_pp`/`_dd`, `_p`/`_d`, `_ppp`/`__o`) and `nvkm/core/memory.h` (`_a`/`_d` in `nvkm_fill`, `__a`/`__d` in `nvkm_wo64`) must keep distinct local names across expansion levels. [F61, F62]
- On GK104-GP10x (`NV917D`), format `HEAD_SET_CONTROL_CURSOR` with `NV917D_HEAD_SET_CONTROL_CURSOR_SIZE` (`27:26`, `cl917d.h`), not `NV907D_HEAD_SET_CONTROL_CURSOR_SIZE` (`26:26`, `cl907d.h`), which masks out bit 1 for 128x128/256x256 cursors. [F82]
