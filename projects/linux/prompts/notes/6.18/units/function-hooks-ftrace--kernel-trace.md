# FUNCTION HOOKS (FTRACE) — kernel/trace

Implements the core function tracer (`kernel/trace/ftrace.c`) and function graph tracer (`kernel/trace/fgraph.c`) infrastructure, managing all mcount/fentry callsite records, `ftrace_ops` and `fgraph_ops` registration, per-ops filter/notrace hashes, direct calls, and function profiling. It also provides the per-task shadow return stack (`ret_stack`) with embedded bitmap/data frames for function return hooking, and exposes tracefs control files and sysctls for filtering functions and PIDs.

## Architecture & Data Flow

- `ftrace_startup_subops()` must canonicalize any `NULL` `filter_hash` or `notrace_hash` in `ops->func_hash` and `subops->func_hash` to `EMPTY_HASH` before calling `add_next_hash()`, because `add_next_hash()` unconditionally dereferences `ops_hash->notrace_hash->size_bits` and `subops_hash->notrace_hash->size_bits` when `*filter_hash` is empty. [F190]
- In `ftrace_regex_open()` and `__ftrace_graph_open()`, `file->private_data` holds a `struct seq_file *` (whose `m->private` holds the iterator) only when `file->f_mode & FMODE_READ` is set, and points directly to `struct ftrace_iterator *` or `struct ftrace_graph_data *` when opened write-only. [F195]
- Before assigning a shadow stack pointer to `t->ret_stack` in `alloc_retstack_tasklist()` or `graph_init_task()`, `ret_stack_init_task_vars()` must zero the `SHADOW_STACK_TASK_VARS` region, `t->curr_ret_stack` must be set to `0`, and `t->curr_ret_depth` must be set to `-1` prior to `smp_wmb()`. [F199]
- Whenever `ftrace_update_pid_func` or `__register_ftrace_function` updates `op->func` between `ftrace_pid_func` and `op->saved_func` for an `ftrace_ops` with `FTRACE_OPS_FL_PID`, it must call `ftrace_update_trampoline` and `update_ftrace_function` in lockstep so the ops trampoline and global trace function invoke the updated callback. [F203]
- Whenever `fgraph_update_pid_func` updates `gops->entryfunc` between `fgraph_pid_func` and `gops->saved_func` for a subop on `graph_ops.subop_list`, it must also call `static_call_update(fgraph_func, gops->entryfunc)` if `ftrace_graph_active == 1` so the direct static call fast path invokes the updated entry callback. [F204]
- `register_ftrace_graph` and `unregister_ftrace_graph` must keep `fgraph_array`, `fgraph_array_bitmask`, `ftrace_graph_active`, `fgraph_direct_gops`, `fgraph_func`, `fgraph_retfunc`, and `fgraph_do_direct` synchronized via `ftrace_graph_enable_direct` and `ftrace_graph_disable_direct` as `ftrace_graph_active` transitions between 0, 1, and >=2. [F205]
- When `ftrace_hash_rec_update_modify` or `ftrace_ops_update_code` modifies an `ftrace_ops` whose `func_hash` is `&global_ops.local_hash`, it must walk `ftrace_ops_list` to update all other enabled `ftrace_ops` sharing `&global_ops.local_hash`. [F206]
- When `ftrace_hash_move_and_update_ops` updates a hash on an `ftrace_ops` that has `FTRACE_OPS_FL_SUBOP` set or is an unenabled `ftrace_ops` whose `func_hash` is shared by an enabled subop on `op->subop_list`, it must route the update through `ftrace_hash_move_and_update_subops` so the manager `ops` rebuilds its hashes via `rebuild_hashes`. [F208]

## Synchronization

- The seq_file .start callbacks t_start(), g_start(), fpid_start(), and fnpid_start() unconditionally acquire their locks (ftrace_lock, graph_lock, or ftrace_lock plus rcu_read_lock_sched()) before any return—including NULL or sentinel returns—so only their corresponding .stop callbacks (t_stop(), g_stop(), fpid_stop()) may release them. [F159]
- `register_ftrace_graph()` must not store `gops` into `fgraph_array[i]` until `ftrace_startup_subops(&graph_ops, &gops->ops, command)` has initialized `gops->ops.func_hash` and returned 0, because `fgraph_lru_alloc_index()` already set bit `i` in `fgraph_array_bitmask`. [F164]
- Lockless readers of `fgraph_array[]` in `function_graph_enter_regs()` and `__ftrace_return_to_handler()` must load each slot once with `READ_ONCE(fgraph_array[i])` and test against `&fgraph_stub` before dereferencing `gops`. [F165]
- In `ftrace_push_return_trace()` and `fgraph_reserve_data()`, the descriptor word `val` must be stored at the new top of `current->ret_stack`, ordered by `barrier()`, before advancing `current->curr_ret_stack`, and stored a second time after `barrier()` to recover if an interrupt clobbered the pre-advance write. [F167]
- In `__ftrace_return_to_handler()`, `current->curr_ret_stack` must not be decremented until after all `retfunc` callbacks have completed, with a `barrier()` preventing the compiler from hoisting the `curr_ret_stack` update across `retfunc`. [F168]
- `direct_mutex` ranks outside `ftrace_lock`: paths acquiring both must take `direct_mutex` before `ftrace_lock`, and `unregister_ftrace_function()` must release `ftrace_lock` before calling `cleanup_direct_functions_after_ipmodify()`. [F171]
- `prepare_direct_functions_for_ipmodify()` and `cleanup_direct_functions_after_ipmodify()` must release `ftrace_lock` (while retaining `direct_mutex`) before invoking `op->ops_func()`, because the callback may call `modify_ftrace_direct_nolock()` which acquires `ftrace_lock`. [F172]
- The lock hierarchy is `trace_types_lock` -> `ops->func_hash->regex_lock` -> `ftrace_lock`; therefore `ftrace_release_mod()` and `ftrace_free_mem()` must unlock `ftrace_lock` before calling `clear_mod_from_hashes()` or `clear_func_from_hashes()`, and `process_mod_list()` must drop `ftrace_lock` around `match_records()`. [F173]

## Object Lifetimes

- register_ftrace_graph() registers ftrace_suspend_notifier only when ftrace_graph_active transitions to 1, so both its error rollback path and unregister_ftrace_graph() must call unregister_pm_notifier(&ftrace_suspend_notifier) if and only if decrementing ftrace_graph_active brings it back to 0. [F145]
- register_ftrace_graph() must release the slot from fgraph_lru_alloc_index() via fgraph_lru_release_index() and clear gops->saved_func = NULL on failure, and unregister_ftrace_graph() must replace fgraph_array[gops->idx] with &fgraph_stub (never NULL) when releasing gops->idx. [F146]
- ftrace_graph_init_task() must clear t->ret_stack = NULL before any conditional allocation so a child task never shares its parent's shadow stack, ftrace_graph_exit_task() must clear t->ret_stack = NULL and issue barrier() before kmem_cache_free(), and idle task stacks in per_cpu(idle_ret_stack, cpu) are persistent and never freed. [F148]
- Because EMPTY_HASH points to the static read-only empty_hash sentinel, ftrace_hash structures must only be freed through free_ftrace_hash() or free_ftrace_hash_rcu() (which ignore NULL and EMPTY_HASH), and freeing an ops filter_hash or notrace_hash in ftrace_free_filter() must reset the pointer to EMPTY_HASH. [F150]
- When rebuilding or updating manager ops->func_hash in ftrace_startup_subops(), rebuild_hashes(), ftrace_shutdown_subops(), and ftrace_hash_move_and_update_subops(), intermediate and replaced filter_hash/notrace_hash instances must be freed via free_ftrace_hash() or free_ftrace_hash_rcu(), and subops->list changes must be rolled back on error. [F152]
- When ftrace_hash_ipmodify_enable() fails in ftrace_startup(), it must roll back __unregister_ftrace_function(), ftrace_start_up--, FTRACE_OPS_FL_ENABLED, and ftrace_trampoline_free(), and ftrace_shutdown() on a FTRACE_OPS_FL_DYNAMIC ops must run both synchronize_rcu_tasks_rude() and synchronize_rcu_tasks() before ftrace_trampoline_free(). [F153]
- For FTRACE_OPS_FL_ALLOC_TRAMP, ftrace_update_trampoline() calls ftrace_add_trampoline_to_kallsyms() before perf_event_ksymbol() and perf_event_text_poke(), and ftrace_trampoline_free() must reverse this by emitting unregister perf events and calling ftrace_remove_trampoline_from_kallsyms() before arch_ftrace_trampoline_free(). [F154]
- register_ftrace_direct() must free an unapplied new_hash via free_ftrace_hash() on error or retire the replaced direct_functions hash via call_rcu_tasks() after rcu_assign_pointer(), and unregister_ftrace_direct() must clear ops->func = NULL and ops->trampoline = 0 so ops can be re-registered. [F156]

## API Contracts

- __ftrace_hash_move() moves all ftrace_func_entry items out of @src into a newly allocated ftrace_hash while leaving the empty @src struct and its bucket array allocated, so callers of __ftrace_hash_move() or ftrace_hash_move() must always call free_ftrace_hash(src) regardless of whether the move succeeded or failed. [F151]
- Because struct ftrace_func_mapper embeds struct ftrace_hash as its first field and free_ftrace_func_mapper() invokes @free_func(map) on each entry before calling free_ftrace_hash(&mapper->hash) to kfree() each entry and mapper itself, @free_func must only free resources in map->data and must never kfree(map). [F161]
- In `append_hash()`, `*hash == NULL` indicates that no accumulator hash has been allocated yet (triggering `alloc_ftrace_hash(size_bits)`), whereas a non-NULL `*hash` for which `ftrace_hash_empty(*hash)` is true (such as `EMPTY_HASH`) means trace all functions and causes `append_hash()` to return 0 immediately. [F184]
- `__ftrace_hash_update_ipmodify()` treats a `NULL` `old_hash` or `new_hash` as matching all functions (returning `-EINVAL`) and `EMPTY_HASH` as matching none, so callers (`ftrace_hash_ipmodify_enable`, `ftrace_hash_ipmodify_disable`, `ftrace_hash_ipmodify_update`) must map any `ftrace_hash_empty()` filter hash to `NULL` before calling it. [F185]
- `alloc_ftrace_hash(size_bits)` takes a bit-shift exponent (`size = 1 << size_bits`), so callers computing `size_bits` from an entry count (`__move_hash()`, `register_ftrace_direct()`) must compute `fls()` first and then clamp the shift exponent to `FTRACE_HASH_MAX_BITS`. [F191]
- Because `ops->private` is `NULL` for global/standalone filter files not bound to a `trace_array` (such as `stack_trace_filter`), `ftrace_func_command` callbacks (`ftrace_mod_callback`), `ftrace_set_regex()`, and `ftrace_regex_open()`/`ftrace_regex_release()` must check `if (!tr)` before dereferencing `struct trace_array *tr`. [F192]
- `match_records()` and `ftrace_match_records()` return a tri-state `int`: `1` if at least one function record matched, `0` if no records matched, or a negative errno (`-ENOMEM`) on hash insertion failure, so callers must distinguish `ret == 0` from `ret < 0` and must not return `1` as an error or errno. [F194]

## Error Handling

- In function_graph_enter_regs(), current->curr_ret_stack must be saved before each entryfunc call and restored if that callback returns 0 to discard any fgraph_reserve_data() allocation, and if bitmap remains 0 after all callbacks, both the pushed frame (FGRAPH_FRAME_OFFSET + 1) and current->curr_ret_depth must be rolled back. [F147]
- When storing an allocation result into a `struct ftrace_hash **` out-parameter in `add_first_hash()`, `add_next_hash()`, or `ftrace_hash_move_and_update_subops()`, the NULL check must dereference the parameter (`!*filter_hash`, `!*notrace_hash`, `!*orig_subhash`) rather than testing the parameter address. [F188]
- Local `struct ftrace_hash *` variables (`filter_hash`, `notrace_hash`) passed by address to `add_first_hash()`, `add_next_hash()`, or `rebuild_hashes()` in `ftrace_startup_subops()` and `ftrace_shutdown_subops()` must be initialized to `EMPTY_HASH`, because `add_next_hash()` leaves `*notrace_hash` untouched when `*filter_hash` is non-empty. [F189]
- In `__ftrace_hash_update_ipmodify()`, if a conflict with an existing `FTRACE_FL_IPMODIFY` record occurs while `is_ipmodify` is true, the `rollback` loop must record `end = rec`, apply the identical `FTRACE_FL_DISABLED` and `in_old == in_new` skip conditions, and stop at `if (rec == end) return -EBUSY;` before modifying `end`. [F245]
- In `function_stat_show()`, the full evaluated variance denominator `stddev_denom = rec->counter * (rec->counter - 1) * 1000` must be checked for non-zero before passing it to `div64_ul()`, rather than only checking `rec->counter <= 1`. [F250]
- `FTRACE_WARN_ON` and `FTRACE_WARN_ON_ONCE` invoke `ftrace_kill()` to permanently disable ftrace and kprobe-ftrace (`ftrace_disabled = 1`), so they must only be used for unrecoverable internal accounting or code-patching bugs, never for recoverable user/registration errors or non-fatal imbalances. [F308]
- If `ftrace_disabled` becomes set while `ftrace_startup` is enabling calls, `ftrace_startup` must only remove `ops` from `ftrace_ops_list` via `__unregister_ftrace_function(ops)` and return `-ENODEV` without freeing the trampoline (`ftrace_trampoline_free`) or rolling back record flags. [F309]

## External Contracts

- In add_rec_by_index(), numeric function filter indices written by userspace are 1-based and must be decremented and checked for < 0 before indexing pg->records across ftrace_pages_start. [F235]
- In show_ftrace_seq_ops, t_next() must capture the current position l = *pos before incrementing *pos so that when t_func_next() or FTRACE_ITER_PRINTALL transitions to t_mod_start(m, &l), t_mod_start() and t_probe_start() compute the relative offset (*pos - iter->func_pos and *pos - iter->mod_pos) without skipping the first module or probe entry. [F237]
- Opening tracefs function listing or filter files (`ftrace_avail_open`, `ftrace_avail_addrs_open`, `__ftrace_graph_open`, and via `tracing_check_open_get_tr` in `ftrace_regex_open` and `pid_open`) must check `security_locked_down(LOCKDOWN_TRACEFS)`, whereas `ftrace_enabled_open` and `ftrace_touched_open` intentionally omit it. [F304]
- `ftrace_regex_release` and `ftrace_graph_release` must check `trace_parser_loaded(parser)` before freeing `parser` and process any buffered trailing token (`ftrace_process_regex` or `ftrace_graph_set_hash`) before moving the staged hash into the active filter. [F305]
- When `ftrace_ops` with `FTRACE_OPS_FL_PERMANENT` is registered (`is_permanent_ops_registered()`), `ftrace_enable_sysctl` must refuse to disable `ftrace_enabled` by restoring `ftrace_enabled = true` and returning `-EBUSY`, and `__register_ftrace_function` must reject registering `FTRACE_OPS_FL_PERMANENT` ops with `-EBUSY` when `!ftrace_enabled`. [F307]

## Known Pitfalls

- `ftrace_ops_set_global_filter(ops)` returns early without binding `ops->func_hash` to `&global_ops.local_hash` if `FTRACE_OPS_FL_INITIALIZED` is already set in `ops->flags`, so it must be called before `ftrace_ops_init(ops)` or any registration/filter call on `ops`, and `ops` must not statically set `FTRACE_OPS_FL_INITIALIZED`. [F193]
- In `t_start`, because `ftrace_lock` is released in `t_stop` and `ftrace_pages_start` or page linkages can change while unlocked, `iter->pg` must be reset to `ftrace_pages_start` with `iter->idx = 0` and re-advanced via `t_func_next` from 0 to `*pos` on every `t_start` call that scans function records. [F211]
- `__ftrace_graph_open` must set `fgd->hash = NULL` before `graph_lock` is released, and `g_start` must re-dereference `ftrace_graph_hash` or `ftrace_graph_notrace_hash` under `graph_lock` while resetting `fgd->idx = 0` and `fgd->entry = NULL` before calling `__g_next`. [F212]
- Because `do_for_each_ftrace_rec(pg, rec)` and `while_for_each_ftrace_rec()` expand to a nested `for` loop over `ftrace_pages_start` pages and `pg->records`, a `break` statement inside the body only skips the remaining records on the current `ftrace_page`, so early termination of the full scan must use `goto` or `return`. [F238]
- In `ftrace_free_mem()`, removing a matched `dyn_ftrace` record from a non-empty `ftrace_page` must `memmove()` the trailing records and `goto again` to re-run `bsearch()` on the same page, whereas emptying `pg->index` must unlink `pg` via `*last_pg = pg->next` and rewind `pg = container_of(last_pg, struct ftrace_page, next)` before `continue`. [F246]
- In `function_stat_show()`, `rec->counter` must be verified non-zero under `ftrace_profile_lock` before computing `avg`, and 64-bit `rec->time` and `stddev` dividends must be divided using `div64_ul()` rather than `/`. [F251]
- `ftrace_hash_key()` must check `hash->size_bits > 0` and return `0` when `size_bits == 0` before calling `hash_long(ip, hash->size_bits)`. [F253]
