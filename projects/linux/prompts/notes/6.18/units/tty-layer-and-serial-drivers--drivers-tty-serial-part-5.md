# TTY LAYER AND SERIAL DRIVERS — drivers/tty/serial (part 5)

This component contains the Linux Serial Core framework (`serial_core.c`, `serial_ctrl.c`, `serial_port.c`) and the GPIO modem-control helper library (`serial_mctrl_gpio.c`, `serial_mctrl_gpio.h`), alongside five hardware UART drivers: Toshiba TXx9 (`serial_txx9.c`), Renesas SuperH/RZ/R-Car SCI/SCIF/HSCIF (`sh-sci.c`, `sh-sci.h`, `sh-sci-common.h`), SiFive UART (`sifive.c`), Spreadtrum UART (`sprd_serial.c`), and STMicroelectronics STM32 USART (`stm32-usart.c`, `stm32-usart.h`). The Serial Core bridges the high-level TTY layer (`struct tty_operations uart_ops` and `struct tty_port_operations uart_port_ops`) with low-level `struct uart_ops` hardware drivers, managing port lifecycles, runtime PM, RS485, consoles, and line settings.

## Architecture & Data Flow

- In `sprd_serial.c`, `dma_request_chan()` stores an `ERR_PTR` directly in `sp->tx_dma.chn` and `sp->rx_dma.chn` on failure, so code must check `sp->tx_dma.enable` or `sp->rx_dma.enable` (never `sp->tx_dma.chn != NULL` or `sp->rx_dma.chn != NULL`) to determine whether DMA is active or to release channels. [F213]
- After invoking `uport->ops->set_termios()`, `uart_change_line_settings()` must hold `uport->lock` to synchronize `UPSTAT_CTS_ENABLE` and `UPSTAT_DCD_ENABLE` in `uport->status` with `termios->c_cflag`, recompute `uport->hw_stopped` via `uart_softcts_mode(uport)` and `get_mctrl()`, and call `stop_tx()` or `__uart_start()` if `hw_stopped` changed. [F226]
- When `uart_get_rs485_mode()` acquires a non-NULL `port->rs485_term_gpio` or `port->rs485_rx_during_tx_gpio` descriptor, it must set `SER_RS485_TERMINATE_BUS` or `SER_RS485_RX_DURING_TX` respectively in `port->rs485_supported.flags`. [F228]
- While `uport->rs485.flags & SER_RS485_ENABLED` is set, `uart_update_mctrl()`, `uart_suspend_port()`, `uart_resume_port()`, and `uart_configure_port()` must not call `uport->ops->set_mctrl()`, and when `uart_set_rs485_config()` clears `SER_RS485_ENABLED`, it must call `port->ops->set_mctrl(port, port->mctrl)` under `port->lock`. [F230]
- When `uart_port_startup()` opens a console port with non-zero `uport->cons->cflag`, it must transfer `cflag`, `ispeed`, and `ospeed` into `tty->termios` and zero `uport->cons->{cflag,ispeed,ospeed}`, and `uart_shutdown()` must save `tty->termios.{c_cflag,c_ispeed,c_ospeed}` back into `uport->cons`. [F231]
- Both `uart_shutdown()` and `uart_tty_port_shutdown()` must clear the port's suspended flag via `tty_port_set_suspended(port, false)` so `uart_resume_port()` does not re-initialize and restart a port that was shut down (e.g., due to a DCD hangup) after being suspended. [F232]
- During `uart_suspend_port()` of an initialized port, `uport->mctrl` must be saved to a local variable before being zeroed under `uport->lock` across `ops->shutdown(uport)`, and then restored to `uport->mctrl` so `uart_resume_port()` can re-apply the pre-suspend modem control state. [F233]
- Because `scix_early_console_setup()` uses `sci_ports[0]` and sets `sci_uart_earlycon = true`, `sci_probe()` must return `-EBUSY` if a port with `sp->port.mapbase != res->start` probes into `sci_ports[0]` while `sci_uart_earlycon` is true, and `early_console_exit()` must zero `sci_ports[0]` unless `sci_uart_earlycon_dev_probing` is true. [F239]
- In `sh-sci.c`, `sci_flush_buffer()` must reset `s->tx_dma_len = 0` and (when `s->chan_tx` is set) terminate TX DMA and set `s->cookie_tx = -EINVAL`, while `sci_dma_rx_chan_invalidate()` under `uart_port_lock` must clear `s->chan_rx = NULL`, `s->cookie_rx[] = -EINVAL`, and `s->active_rx = 0` together. [F240]

## Synchronization

- `uart_port_unlock_deref()` must release `uport->lock` via `uart_port_unlock_irqrestore()` before calling `uart_port_deref(uport)`, because dropping the final `state->refcount` reference allows `serial_core_unregister_port()` to proceed and invalidate `struct uart_port`. [F173]
- `uart_alloc_xmit_buf()` and `uart_free_xmit_buf()` must never call `free_page()` while holding `uport->lock` (acquired via `uart_port_ref_lock()`), and `uart_free_xmit_buf()` must detach `port->xmit_buf = NULL` and reset `port->xmit_fifo` under the lock before freeing the page after `uart_port_unlock_deref()`. [F174]
- In `serial_core.c`, functions that dereference `state->uart_port` without holding `state->port.mutex` must pin the port via `uart_port_ref()` (or `uart_port_ref_lock()`) and release it via `uart_port_deref()` (or `uart_port_unlock_deref()`), whereas `uart_port_check()` may only be called while holding `state->port.mutex`. [F193]
- In `serial_core.c`, locks must be nested in the order `port_mutex` -> `state->port.mutex` -> `uport->lock`, and any path that also acquires `tty->termios_rwsem` (`uart_ioctl()`, `uart_set_info_user()`) must acquire `tty->termios_rwsem` before `state->port.mutex`. [F196]
- In `uart_configure_port()`, when `uart_console(port)` is true, calls into the driver before console registration (`port->ops->config_port()`, `uart_change_pm()`, `port->ops->set_mctrl()`, and `uart_rs485_config()`) must be wrapped in `console_lock()` and `console_unlock()`. [F197]
- Callers of `uart_set_options()` must hold `console_list_lock` so early initialization of `port->lock` via `uart_port_spin_lock_init()` is serialized, and `serial_core_add_one_port()` must not call `uart_port_spin_lock_init(uport)` when `uart_console_registered(uport)` is true. [F198]
- Drivers calling `uart_update_timeout()` must hold `port->lock` while updating `port->frame_time`, and lockless readers such as `uart_fifo_timeout()` must read `port->frame_time` using `READ_ONCE()`. [F201]
- `serial_base_port_startup()` and `serial_base_port_shutdown()` must update `port_dev->tx_enabled` under `uart_port_lock_irqsave()`, and `uart_shutdown()` and `uart_tty_port_shutdown()` must call `serial_base_port_shutdown()` before `uart_port_shutdown()` and `uart_free_xmit_buf()`. [F202]
- In `drivers/tty/serial/sifive.c`, modifications to `ssp->ier` and the `SIFIVE_SERIAL_IE_OFFS` register in `sifive_serial_startup()` and `sifive_serial_shutdown()` must be serialized under `uart_port_lock_irqsave(&ssp->port, &flags)`. [F206]

## Object Lifetimes

- In `__uart_start()`, `pm_runtime_get(&port_dev->dev)` unconditionally increments the runtime PM usage counter, so an error return (`err < 0 && err != -EINPROGRESS`) must call `pm_runtime_put_noidle(&port_dev->dev)` before returning, while the non-error path pairs it with `pm_runtime_put_autosuspend(&port_dev->dev)`. [F175]
- `serial_core_register_port()` must pass `new_ctrl_dev` (which is `NULL` when `serial_core_ctrl_find()` reused an existing controller) to `serial_base_ctrl_device_remove()` on error, and `serial_core_unregister_port()` must remove `ctrl_dev` only when `!serial_core_ctrl_find(drv, phys_dev, ctrl_id)`. [F177]
- `serial_core_unregister_port()` must read `port->dev`, `port->port_dev`, `ctrl_dev`, and `port->ctrl_id` before calling `serial_core_remove_one_port(drv, port)` and must not dereference `port` afterward, because `serial_core_remove_one_port()` clears `uport->port_dev = NULL` and drops the port reference. [F178]
- In `uart_change_port()`, if `uport->ops->request_port(uport)` fails for the new configuration, the previous `iobase`, `type`, `hub6`, `iotype`, `regshift`, and `mapbase` must be restored and re-requested via `uport->ops->request_port(uport)` (setting `uport->type = PORT_UNKNOWN` if that re-request also fails). [F179]
- `uart_wait_modem_status()` must restore `__set_current_state(TASK_RUNNING)`, call `remove_wait_queue(&port->delta_msr_wait, &wait)`, and call `uart_port_deref(uport)` on every exit path from its wait loop. [F180]
- `uart_suspend_port()` and `uart_resume_port()` acquire a `struct device *` reference via `device_find_child(&uport->port_dev->dev, &match, serial_match_port)` and must release it with `put_device(tty_dev)` on both the early wakeup return path and the normal path. [F181]
- `uart_rs485_config()` and `uart_set_rs485_config()` drive `port->rs485_term_gpio` and `port->rs485_rx_during_tx_gpio` before invoking `port->rs485_config()`, and if `port->rs485_config()` fails they must roll back both GPIO output states (to 0 in `uart_rs485_config()`, or to the prior `port->rs485.flags` state in `uart_set_rs485_config()`). [F182]
- `uart_line_info()` and `uart_poll_init()` must save `state->pm_state` before calling `uart_change_pm(state, UART_PM_STATE_ON)` and restore `uart_change_pm(state, pm_state)` (always after `get_mctrl()` in `uart_line_info()`, and on error in `uart_poll_init()`). [F183]
- In `drivers/tty/serial/sh-sci.c`, runtime PIO fallback (`sci_dma_tx_work_fn()`, `sci_dma_rx_complete()`, `sci_dma_rx_submit()`) clears `s->chan_tx` or `s->chan_rx` to `NULL` while preserving `s->chan_tx_saved` and `s->chan_rx_saved`, which `sci_free_dma()` must use to unmap/free DMA buffers and release the channels. [F185]

## API Contracts

- Callers of `uart_handle_dcd_change()`, `uart_handle_cts_change()`, and `uart_write_wakeup()` must hold `uport->lock`. [F200]
- `uart_port_startup()` and `uart_startup()` return `1` when `uport->type == PORT_UNKNOWN` or when `uport->ops->startup()` fails for a `CAP_SYS_ADMIN` caller; callers (`uart_set_info`, `uart_do_autoconfig`, `uart_port_activate`, `uart_open`) must only mark the port initialized on `0` and must translate `> 0` to `0` for userspace. [F210]
- `mctrl_gpio_init()` and `mctrl_gpio_init_noauto()` return an `ERR_PTR` on failure when `CONFIG_GPIOLIB` is enabled but return `NULL` when `CONFIG_GPIOLIB` is disabled, and all `mctrl_gpio_*` helpers treat `NULL` (not `ERR_PTR`) as a no-op; callers must check `IS_ERR()` rather than `!gpios` or `IS_ERR_OR_NULL()`. [F211]
- In `__uart_read_properties()`, `port->iotype` must always be assigned (including setting `port->iotype = UPIO_UNKNOWN` on an unsupported `reg-io-width` property) before returning `-EINVAL` when `use_defaults` is `false`. [F214]
- In `sh-sci.c`, `offset` in `sci_serial_in()`, `sci_serial_out()`, and `sci_getreg()` is a register enum index into `params->regs[]` (not a byte offset), and optional registers that may have `reg->size == 0` must be guarded with `sci_getreg(port, REG)->size` before calling `sci_serial_in()` or `sci_serial_out()`. [F222]
- In `uart_get_info()` and `uart_set_info()`, `tty_port` stores `close_delay` and `closing_wait` in jiffies while `serial_struct` stores them in centiseconds (10 ms), requiring conversion via `jiffies_to_msecs(...) / 10` and `msecs_to_jiffies(... * 10)` while preserving `ASYNC_CLOSING_WAIT_NONE`. [F224]
- In `__uart_read_properties()`, when the `reg-io-width` property is absent, `port->iotype` must be set to `UPIO_PORT` if `port->iobase` is non-zero and `UPIO_MEM` otherwise; and when `use_defaults` is false, `port->mapsize < value` must be checked before mutating `port->mapbase` and `port->mapsize` by `reg-offset`. [F236]
- Changes to `enum mctrl_gpio_idx` or `mctrl_gpio_*` functions must update `mctrl_gpios_desc[]` and the `!CONFIG_GPIOLIB` stubs in `serial_mctrl_gpio.h` in lockstep, keeping `mctrl_gpio_get()` and `mctrl_gpio_get_outputs()` returning `*mctrl` unchanged when `gpios` is NULL or `CONFIG_GPIOLIB` is disabled. [F238]

## Error Handling

- In `stm32_usart_serial_probe()`, when `dma_request_chan()` returns a non-deferral `ERR_PTR` or when `stm32_usart_of_dma_rx_probe()` / `stm32_usart_of_dma_tx_probe()` fails, `stm32port->rx_ch` and `stm32port->tx_ch` must be reset to `NULL` before continuing in PIO mode. [F212]
- Multi-condition UART interrupt handlers (`stm32_usart_interrupt()`, `sci_mpxed_interrupt()`, `serial_txx9_interrupt()`) must initialize their status to `IRQ_NONE` and only return `IRQ_HANDLED` when at least one interrupt condition is actually serviced. [F217]
- In `uart_set_info()`, if `!(uport->flags & UPF_FIXED_PORT)`, `unsigned int uartclk = new_info->baud_base * 16` must be checked for `0` before modifying port state, and privileged (`CAP_SYS_ADMIN`) updates must reject `new_info->irq < 0`, `new_info->irq >= irq_get_nr_irqs()`, or `new_info->baud_base < 9600` with `-EINVAL`. [F255]
- `serial_port_runtime_suspend()` must return `0` immediately when `!pm_runtime_enabled(dev)` so that system suspend via `pm_runtime_force_suspend()` is not aborted with `-EBUSY` when TX bytes are pending in `xmit_fifo`. [F307]

## External Contracts

- Any fields added to `struct serial_rs485` must be carved out of `padding0`/`padding1` inside the `padding[5]` union without altering the offsets of `padding` or `padding1` or `sizeof(struct serial_rs485)`, and `uart_sanitize_serial_rs485()` must zero `padding0` and `padding1` before returning the structure to userspace. [F251]
- When translating between `uport->iobase` (`unsigned long`) and `struct serial_struct` (`unsigned int port` and `unsigned int port_high`), `uart_get_info()`, `uart_set_info()`, and `port_show()` must split or combine the upper bits using `HIGH_BITS_OFFSET` (`(sizeof(long)-sizeof(int))*8`) when `HIGH_BITS_OFFSET` is non-zero. [F254]
- In `uart_set_info()`, callers without `capable(CAP_SYS_ADMIN)` may only change `uport->flags` bits in `UPF_USR_MASK` and `uport->custom_divisor` (returning `-EPERM` otherwise), and even with `CAP_SYS_ADMIN`, changing IRQ or port I/O resources (`change_irq || change_port`) requires `security_locked_down(LOCKDOWN_TIOCSSERIAL)` to pass. [F347]
- In `uart_line_info()` (`/proc/tty/driver/<driver_name>`), powering on the port via `uart_change_pm()`, reading hardware modem status via `uport->ops->get_mctrl()`, and emitting `uport->icount` traffic/error counters and modem line flags are restricted to callers with `capable(CAP_SYS_ADMIN)`. [F348]
- In `uart_set_iso7816_config()` (`TIOCSISO7816`), every element of `struct serial_iso7816::reserved` must be verified to be zero after `copy_from_user()`, returning `-EINVAL` before calling `port->iso7816_config(port, &iso7816)` if any reserved word is non-zero. [F350]

## Known Pitfalls

- In `uart_set_termios()`, `cflag` must be reloaded from `tty->termios.c_cflag` after `uart_change_line_settings()` returns before evaluating `CBAUD == B0` transitions, because the low-level driver's `.set_termios()` callback may have overridden unsupported `c_cflag` bits. [F227]
- In `sh-sci.c`, for `PORT_SCI`, `SCSCR_TE` (transmit enable) must not be set in `sci_set_termios()` before `SCSCR_TIE` is enabled, and must instead be set in the same write as or after `SCSCR_TIE` in `sci_start_tx()`; additionally, in `sci_set_termios()`, modifying `SCFCR` after `sci_reset()` must mask out `~(SCFCR_RFRST | SCFCR_TFRST)`. [F241]
- In `stm32_usart_receive_chars_pio()`, when `sr & USART_SR_ERR_MASK` is non-zero and `ofs->icr != UNDEF_REG`, the error flags in `ofs->icr` must be cleared before reading `ofs->rdr` via `stm32_usart_get_char_pio(port)`. [F245]
- In `serial_txx9.c`, `serial_txx9_pm()` must not call `serial_txx9_initialize(port)` when `oldstate == -1`, and on a console port (`up->line == up->cons->index`), `serial_txx9_config_port()` must skip `serial_txx9_initialize(up)` and `serial_txx9_shutdown()` must skip FIFO reset and RX/TX disable. [F247]
- `uart_get_info()` must zero `*retinfo` at function entry before checking whether `uport` is non-NULL, because the sysfs attribute `.show` callbacks (`uartclk_show`, `type_show`, `line_show`, `port_show`, `irq_show`, `flags_show`, etc.) ignore `uart_get_info()`'s return value and format `tmp` directly from the stack. [F253]
- In `sci_txfill()` and `sci_rxfill()`, the FIFO byte-count mask must be `(s->params->fifosize << 1) - 1` rather than `s->params->fifosize - 1`, because a full FIFO of `fifosize` bytes is represented by the value `fifosize` in `SCTFDR`, `SCRFDR`, and `SCFDR`. [F260]
- In `sci_request_irq()`, `SCIx_MUX_IRQ` equals `SCIx_NR_IRQS` (one past `port->irqs[SCIx_NR_IRQS]` and `port->irqstr[SCIx_NR_IRQS]`), so when `SCIx_IRQ_IS_MUXED(port)` sets `i = SCIx_MUX_IRQ` for `sci_irq_desc[i]`, `port->irqstr` must be indexed by `j` and `irq` taken from `up->irq` rather than indexing `port->irqs[i]` or `port->irqstr[i]`. [F261]
- In `stm32_usart_receive_chars_pio()`, `sr` must be ORed with `USART_SR_DUMMY_RX` on every received byte before calling `uart_insert_char()`, because `stm32_usart_set_termios()` sets `USART_SR_DUMMY_RX` in `port->ignore_status_mask` to drop all received bytes when `CREAD` is cleared. [F267]
